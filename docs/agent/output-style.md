# 输出表述纪律（对用户回复的语言要求）

> 正本条文。常驻层指针：`my-rules/agents-md.md`（四 IDE alwaysApply 规则摘要，因 AGENTS.md 常驻预算已满而未设行）。
> 本文件非常驻，按需局部读。

## 适用范围

对用户的所有输出一律适用：日常回复、会话总结、向用户提问、呈现选项。

## 三条硬要求

1. **易懂的书面中文**：用普通人不需要回查仓库文档就能直接看懂的自然语言描述，避免口语碎片与电报式简写；先说清楚事物本身是什么、涉及什么范围、后果或收益，再谈代号。
2. **内部代号只作回查线索**：任务号（WXG-T-…）、常量名、条目编号（K-0NN）、门编号（G1–G4）、标签代码等内部符号，**不得**当句子主语堆砌；只能放在括号里附注，供需要核对的人回查原始条目。
3. **引用必附出处链接**：凡引用设计裁定、规则条文、判据或代码依据，都要给出可点击的文件引用链接（Markdown 链接或 `file:///` 路径，尽量带行号范围），让用户不用自己检索仓库就能定位依据。

## 会话总结的额外口径（参考 Cursor 表述风格）

- 结构化逐项说明「做了什么、改在哪里、为什么改、遗留什么」，每一条用完整短句表达实际含义，而非内部代号堆砌。
- 涉及代码改动时，必须列出修改的代码文件清单，并对每个文件把修改前后的对比说清楚：原来是什么行为/写法、改成了什么、为什么改；不能只写「更新了某文件」这类笼统表述。

## 为什么放在共享层而不是单个 IDE 的私有记忆

`my-rules/agents-md.md` 是 Cursor / CodeBuddy / WorkBuddy / Qoder 四家规则文件的符号链接正本（alwaysApply，每次会话自动注入）；写进这处的短指针 + 本文件细节，能保证任何 IDE 的新会话都受同一约束，而某一家 IDE 的私有记忆只有它自己看得见。`AGENTS.md` 因常驻预算已顶满（上限 2000 tokens）未加行，以四 IDE 强制注入的 my-rules 层为准。
