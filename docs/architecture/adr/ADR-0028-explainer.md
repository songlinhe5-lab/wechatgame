## 第 0 层 · 一句话

**把「每个颜色烘一张纹理」改成「每个风格烘一张无色 mask，颜色在绘制时乘上去」**——若验证成立，烘焙管线最难的两笔账（内存 DEC-7、包体 DEC-6）不是缓解，是**整题消失**。

## 第 2 层 · 问题本质（为什么"逐色"是三份 ADR 共同的痛）

现行设计：纹理 key = `styleId | colorIdx | size` ⇒ 颜色进纹理内容。连锁：

- **内存**：35 色 × 双张 ≈ **4.7 MB** GPU 常驻候选（DEC-7，预算 [待定]，低端机 `onMemoryWarning` 压力）；
- **包体**：投放档按"色数"计价 ⇒ P2（145 色 290 张）顶穿主包、P3（2104 色）连分包 ≤30 MB 都穿 ⇒ **数学否掉**（DEC-6 上限登记）；
- **工艺**：每色都要烘/校验/失效管理；`bakeSchemaVersion` 失效半径 = 风格×色全笛卡尔积；
- **观感**：换机/清缓存 ⇒ 冷烘；studio 预烘与玩家设备两份真源。

而珠面颜色其实**没有自由度**——全族只有 4 个端点 + 2 个表外系数（第 3 层），"逐色烘"等于把一个一维参数（base hex）的内容物化成了 N 张图。**tint = 把这个参数还给参数。**

→ 正本 §1、§2.2 表。

## 第 3 层 · 关键前提：端点族（为什么颜色"可以"是参数）

真源 `palette.ts`：

```ts
mix(hex, amount)   // amount∈[−1,+1]：−1→黑，0→不变，+1→白
                   // 实现：c + (target − c)·t，target = 255 或 0
endpoints = { base, edge: mix(base,−0.30), pit: mix(base,−0.44), lit: mix(base,+0.38) }
```

facet-4 现役六层逐层核对（`facet-4.ts` + `tuning.ts` 实读真数）：

| 层 | 色公式 | 归一化 | 属于 |
|---|---|---|---|
| #1 plate 底 rect | `mix(base, −0.44)`（`FACET4_PLATE_MIX`） | `base × 0.56` | 暗端 |
| #2 上刻面 | `lit` = `mix(base, +0.38)` | `base + 0.38×(1−base)` | 亮端 |
| #3 左刻面 | `base` | `base × 1` | 中性（d=1, l=0） |
| #4 右刻面 | `mix(base, −0.16)`（`FACET4_FACET_RIGHT_MIX`） | `base × 0.84` | 暗端 |
| #5 下刻面 | `edge` = `mix(base, −0.30)` | `base × 0.70` | 暗端 |
| （孔内壁/坑底） | `pit`（**target 色**系） | — | **不入 mask**：孔 live（ADR-0025 DEC-3 原样） |

两条纪律让 tint 有土壤：**C3 色源唯一**（只走端点/mix，无裸 hex）、**黑白轴**（`mixWith` 双色轴族外风格本案不覆盖，见第 6 层边界）。

→ 正本 §2.1「实层核对」。

## 第 4 层 · 数学原理（本案心脏，四步推导）

以下均归一化（通道值 ∈ [0,1]），`b` = base 通道值。

**① 暗端 = 乘法恒等**
`mix(b, −k) = b + (0 − b)·k = b(1−k)` ⇒ 令 `d = 1−k`：**`b·d` 就是 multiply（源灰 = d）**。零近似。

**② 亮端 = screen 恒等**
`mix(b, +k) = b + (1 − b)·k`；screen 定义 `S(b, s) = b + s − b·s = b + s(1−b)` ⇒ 令 `s = k`：**逐通道精确**。零近似。
（这正是当年否因——"向白仿射，纯乘法不可表达"——的正面解：**乘法不行不等于合成不行，screen 就是向白仿射的硬件原生形式**。）

**③ 双通道为什么无交叉误差（两路串行的封闭性）**
mask 每像素带 `(d, l)`。两路 = 先 multiply 后 screen：
`result = b·d + l·(1 − b·d)`。
一般 `d<1 且 l>0` 时它 ≠ 理想式 `b·d + l(1−b)`（差项 `l·b·(1−d)`）。但第 3 层表 ⇒ **facet-4 每个像素恰好只落一类**：
- 暗层（l=0）：result = `b·d` ✓ 精确；
- 亮层（d=1）：result = `b + l(1−b)` ✓ 精确；
- 中性层（d=1, l=0）：`b` ✓。
⇒ **对在册配方，两路合成逐层精确，唯一误差 = mask 存 8-bit 的量化**（d/l 存储 ≤0.5/255 ⇒ 色误差 ≤0.5/255/通道，ΔE≈0.2 量级 [待 T1' 实证]）。

**④ shader 单 pass 版（Cocos 载体②）**
`out = b·d + (1−b)·l`：对暗层（l=0）同①、亮层（d=1）同②，且**对假想的 d·l 共存像素也输出理想式** ⇒ 更通用、1 blit。Canvas2D 无 shader ⇒ 只能两路（本案主验证对象 = 两路版，shader 版随 Cocos blit 立项复评）。
**Cocos 支持面（2026-09-28 调研回写）**：官方 API 已给足通道——`Sprite`/UIRenderer 的 `customMaterial`（自定义材质 = 官方最佳实践，可采样 `cc_spriteTexture`）+ `BlendState`；而本案需要的只是 fragment 里三行代数（uniform 传 base），连 blend factor 都不碰；硬件因子写法（multiply=`dst_color/zero`、screen=`one/one_minus_src_color`）另有社区标准实现备用。真正的 Cocos 阻塞不在 tint，在 `Graphics` 不能画 image（blit 载体另立，第 5 站既有负面）。

→ 正本 §2.1。

## 第 5 层 · 工程形态（如果做，长什么样）

### 5.1 mask 怎么烘
同一份层集配方（DEC-4 同源纪律不变），把每层 fill 从"端点色"换成"**通道值**"：暗层画 `rgb(d,d,d) α=覆盖`、亮层画 `rgb(0,0,0, α=l)`（l 走 alpha 通道）……一张纹理同时携带 d（RGB）与 l（A）。每风格仅 **1 张珠面 mask + 1 张格面 mask**，`colorIdx` 从 key 里删除。

### 5.2 每格绘制序（Canvas2D 两路版）

```
已填格：
  ① rect  B0 底图                    （1 命令，不变）
  ② fillRect base 色（珠面包络）      ┐
  ③ blit  mask  composite=multiply   ├ ②+③ 合成 = tint
  ④ blit  mask  composite=screen     ┘
  ⑤ circle 孔（live，不变）
空格： ① 整格底 blit（mask 版同样 per-格面一张）
```

已填格命令 3 → **4–5**（DEC-8 #7 四帧账须按此重算 = T3'）。

### 5.3 失效/版本
`BAKE_SCHEMA_VERSION` bump 1 次（与 **inset=0 修复**、**1 dp 边线批**同批，⛔ 拆三次 bump 三次重烘——正本 §4 负面明文）。

### 5.4 与格内标准的关系
`cell-standard.md` 的 26 dp 轮廓、⌀12/⌀10、1 dp 边线全是 **dp 几何**口径 ⇒ mask 化的只是"颜色怎么来"，**几何口径一个都不动**；边线在 mask 里就是另一档固定灰阶（plate 系墨除外——孔 shadow 墨 `BEAD_SHADOW_HEX` 是端点族外唯一放行墨，留 live 臂，不入 mask）。

### 5.5 不动的东西（边界清晰）
运行时烘框架（bake-key/lru/surface）、blit kind（ADR-0026）、三层读序（DEC-3，只是读序里"每色文件"变"每风格文件"）、矢量回退臂、门禁跑配方层（DEC-8 #2）。

→ 正本 §2.4、§4。

## 第 7 层 · 风险明细（每条：怕什么 / 怎么验 / 验不过怎么办）

1. **H-FILL 翻倍**（最怕）：怕的是命令减半收益被两次全珠面混合吃掉还倒贴（低端机 fill 主导，K 族在案教训）；验 = T4' 沿 C ≥ A×1.5；**不过 ⇒ 两路版否决**，只留 shader 单 pass 分支随 Cocos 立项（决策树第 2 枝）。
2. **wx composite 支持面（2026-09-28 调研后已收窄，风险从「可能不支持」降为「支持但质量未知」）**：浏览器稳定（harness 无险）；wx 官方无支持清单页，间接证据可用（Mars 项目 iOS/Android 真机在案）但同文提醒高效模式优先；**仓内在役用量 = 0，自家零证据**；验 = T2'（正确性+开销双测，三台真机含 HarmonyOS 档）；**不过 ⇒ 同 1**（两路版死，Cocos 单 pass 分支不受此影响——它走 GL 不走 canvas composite）。
3. **AA fringe**：怕 mask 半透明边界在两路合成下出现暗边/亮边，逐像素与矢量臂不等；验 = T1' ΔE 容差 + 与既有 §13.11 解剖样张同帧对照；**不过 ⇒ 需预乘/coverage 通道方案，复杂度重估**。
4. **效果包络**：非黑白轴风格（`mixWith` 族）tint 不可达——**这是边界不是风险**，在册无需求，出现时走 LUT 另立 ADR（决策树第 3 枝）。
5. **量化 ΔE**：8-bit d/l 存储误差理论 ≤0.2 量级——若 T1' 实测超限，mask 改 16-bit 或分区存储（次要，有解）。
