# ADR-0027 — beads 预烘位图皮肤资产（brand 集进主包 + 关卡色集进分包）

> ⛔ **状态变更（2026-09-28 · WXG-T-221 八裁 · 用户拍板 B 案「历史归档」）**：本 ADR 的**运行时烘兜底轨**随 ADR-0025 一并转历史归档（复活须走新 ADR）。**预烘臂本身不废**：S3-lite 四张 dev 产物保留为解剖样张与工艺验证（ADR-0028 §2.4 原话成立）；若 tint（ADR-0028）验证通过，投放内容从「逐色 PNG」变「风格 mask PNG」，生成器链路（`bake-recipes.ts` / `bake:check`）**直接复用**。P1/P2/P3 逐色投放档位随八裁冻结，不再演进。

> 关联任务号 **WXG-T-219** · 用户 2026-09-27 三裁定：**乙（位图皮肤资产）／单珠 + 空格凹槽一起烘／文档与落码方案一并**。
> ⚠ **同批二批裁定（DEC-6 收口）**：「实时烘焙如果能达到效果就这么办，否则 B」⇒ 预烘臂转为**条件式备用路线**（口径 = P1），详见 §3 DEC-6。
> ⚠ **三批裁定（2026-09-28 用户拍板，WXG-T-221）**：**DEC-6 条件裁定推翻** ⇒ 预烘臂开工；但**范围收窄** = 本批只出「当前关」缺色集（非 brand 集全量），产物**只落 `games/beads/assets/**/levels/`** 供 dev 读，**不进 game.json / 不入主包 / 不入分包** ⇒ S0 包体守卫前置**本批不触发**（保留至放量批）；运行时烘臂**不删**（DEC-3 三层读序原样）。对应实施路线 = §6 表 **S3-lite** 行。

## 1. 上下文（Context）

- **本仓渲染基线是刻意立的可验证性锚**：`docs/architecture/architecture.md §5` 写明「首屏图片资源为 0 …
  这不是偷懒，而是刻意把包体基线压到最低，验证主包 ≤4MB 且不含任何图片是可行的」，并预留出口
  「后续游戏若要接入位图美术，预算表按上表逐项扣减」。⇒ 本 ADR 走的正是那条**预留出口**，不是违约。
- **玩家侧预热存在真空洞**（本提案的真实动因）：§13.5 的「beads-studio 预热」写的是烘进 **L2**，而 L2 =
  `wx.USER_DATA_PATH` / IndexedDB = **运行设备本地**。开发者机器上 studio 烘出的字节**传不到玩家设备**
  ⇒ 该裁定只兑现「设计预览一致」，对玩家首屏零收益。要让预热触达玩家，**只能以文件形式分发**（包内或分包）。
- **色板已有同族先例**：品牌色板真源 = `games/beads/art/<slug>.json` → `tools/scripts/sync-palettes.mjs` 生成
  `src/config/palettes-data.ts`（文件头 `GENERATED FILE — DO NOT EDIT BY HAND` + `palettes:check` 漂移守卫进 verify）。
  ⇒ 「离线从真源生成、入库到游戏目录、机械守卫防漂移」这条工艺链**已在役**，本 ADR 是它的位图版。
- **色板规模实测**（决定包体可行性，非估算）：`games/beads/art/` 16 份品牌 JSON 合计 **2104 色**
  （artkal-a 145／c 174／m 220／r 89／s 210／diamond-dotz 461／mard 291／hama-maxi 25 …）。
  `BEAD_COLOR_MAX = 35` 是**单关**色数上限，**不是**品牌集规模 ⇒ 「brand 用到的颜色」口径未钉，见 §3 DEC-6。
- **包体余量的两处失真**（诚实前置）：① `build:wx` 与分包配置未打通，`check:size` 在 `pnpm run verify` 内为
  **SKIP** ⇒ 主包真实余量今天测不出；② §3.9 内部目标 v1.51 已与 4096 KB 平台红线**合流**，而
  `check-bundle-size.mjs` 仍硬编码 `mainTargetKb: 2000` 且 A7 断言钉 2000（属知情豁免）⇒ **WARN 永不触发 = 守卫无牙齿**。

## 2. 备选方案（Alternatives）

| 方案 | 事实性对比 | 结论 |
|---|---|---|
| 甲｜纹理 = 缓存的分发形式 | 真源仍是层集，包内/分包文件 = 「提前烘好的 L2」，读不到即回矢量臂；不推翻 2026-09-25 A 案 | 否（用户选乙）：工程风险最低，但**视觉真源仍单一**，与「位图皮肤资产」的诉求不等价 |
| **乙｜位图皮肤资产（本 ADR）** | 包内 PNG 成为独立视觉真源之一 ⇒ 须明文推翻 A 案禁令，并重审 C3／C12／双指标门禁的适用面 | **采纳** |
| 维持 B2 原判（纯运行时烘，零包体） | 玩家首屏必付一次批量烘焙（低端机 ≤100 ms [暂定]，T6 待实测）；换机／清缓存后冷；studio 预览与玩家首启观感差不可消除 | 否：正是本提案要修的空洞 |
| 全量 2104 色进主包 | 112² PNG 单张字节 **[待实测]**；即便按乐观 5 KB/张量级 ⇒ 2104 张 ≈ 10 MB 级，**主包 4096 KB 连零头都放不下** | 否：数学不成立 ⇒ **DEC-6 条件裁定只允许 P1 档**（P3 不得采纳） |

## 3. 决定（Decision）

- **DEC-1 推翻清单（本 ADR 的核心义务，逐条留痕）**：
  | 被推翻者 | 原文要点 | 处置 |
  |---|---|---|
  | 用户 2026-09-25 皮肤系统三案裁定（记忆库正本） | 选 A 全程序化，**明令禁用纹理与位图皮肤**；混合方案「不得再作为例外通道引用；重提须走 ADR」 | **本 ADR = 那次重提**；禁令解除范围 = 预烘皮肤纹理资产，**AI 参考图仍不进仓不进包**（不作资产源） |
  | `§13.1 B2` | 否决设计期预产纹理资产（包体 + 任意 `paletteHex` 没皮） | **作废**；其「任意色」否因由 DEC-3 三层读序承接 |
  | `§13.1 B5` / `ADR-0025 DEC-1` | 只烘单珠，整格平面**本轮不采纳** | **作废**；平面扩为「单珠 + 整格底（B0 底图 + B1 凹槽）」= 原 §13.8 **N2 生效** |
  | `ADR-0025 §2` 备选 D | 设计期预产纹理 = 否（「烘焙必须是运行时能力」） | 改判：运行时能力**保留为兜底**，不再独占 |
- **DEC-2 门禁体系换轨（承认判别力变化，不假装仍有效）**：位图皮肤下每格命令数恒为 `blit` 级 ⇒
  **双指标门禁（珠体命令 ≤7 且真 α ≤2）对预烘资产出图的风格不再具有判别力**。处置 = 门禁继续跑在
  **烘焙输入（层集配方）**上，语义从「运行时开销上限」**降级为「配方复杂度上限」**；风格池历史移出记录中
  **因性能超门被拒者**（02 亮漆／07 复古像素／11／12／17 铜版排线…）自此**具备翻案资格**，但须逐套走
  「细线 2.0× 降采样实机质量验证」；因**语义/合规**被拒者（16／19 破坏 C12、珍珠虹彩不可达）**不在翻案范围**。
- **DEC-3 三层读序（正确性恒不依赖文件）**：
  `① 主包 brand 集` → `② 分包关卡色集` → `③ L2 运行时烘` → `④ 矢量臂（现役 facet-4）`。
  四者键统一 = `styleId | colorIdx | bakeSchemaVersion`（⛔ 禁止另发明第二套键）。
  miss / 文件解码失败 / 分包未到达 ⇒ **落到下一层**，首帧允许矢量出画，纹理到达后灌 L1（⛔ 不得为等文件而空帧）。
  ⇒ B4 三条硬约束（矢量回退恒在／零新 hex 于缓存本体／可整体丢弃重建）**原样保留**，本 ADR 只扩「字节从哪来」。
- **DEC-4 生成工艺 = 复用色板先例，禁手写源文件**：预烘纹理只准由构建期生成器产出（`beads-bake-assets`，
  与 `sync-palettes.mjs` 同族），**必须 import 游戏侧同一份层集模块与同一 `bakeSchemaVersion`**
  （⛔ studio 侧另写一份绘制实现 ⇒ 会烘出两个形态，「唯一配方真源」当场作废）。
  配套：产物目录头部生成说明 + 新增 `pnpm run bake:check`（漂移守卫，语义对 `palettes:check`）入 verify。
- **DEC-5 落位与分包**：主包目录 = 仅 brand 集（口径见 DEC-6）；新关色集随**该关**进分包，
  与关卡 manifest 版本号**耦合发布**（`bakeSchemaVersion` 变 ⇒ 相关分包全量重出，不做增量纹理补丁）。
  现状登记：分包基建**未打通**（`sync-levels-data.mjs` 仍限制每游戏 1 JSON；`check-bundle-size` 分包判定自标 G7 未实测）。
- **DEC-6 「brand 使用到的颜色」口径 = 条件裁定（用户 2026-09-27 二批：「实时烘焙如果能达到效果，那就这么办，否则 B」）**：
  预烘臂（L0 层）**不得先于运行时烘臂的实测开工**。

  | 分支 | 前提（全部须为**实测**证据，⛔ 纸面判） | 后果 |
  |---|---|---|
  | **主路｜运行时烘达标 ⇒ 不投放预烘资产** | `§13.13` 六项验证义务中的 **T1（静态等价 ΔE）/ T4（低端机帧时间 p95，C ≥ A×1.5）/ T5（内存）/ T6（首屏烘齐耗时与兜底）** 逐项 PASS，且画质/手感无退化 | brand 集**不进主包**（包内零位图基线保持）；**§13.5 L0 层 = 备用路线不开工**；ADR-0027 降为「已采纳但挂起的备用案」；**ADR-0025 仍为现行唯一实施路线** |
  | **兜底｜任一不达标 ⇒ 走 P1 档** | 上述任一项实测不达 | 主包只放**首屏/教学关必用色人工小集**（≈16 色 → 双张 32 张，⚠ 体量仍 [待实测]）；新关色集进**分包**；其余走运行时烘 ⇒ DEC-5 仍成立、但 brand 集**不得按整张品牌色板全量预烘** |

  口径上限登记（不得忘）：**P2 单品牌整张色板**（145 色 = 290 张 ≈1.5–3.5 MB）已顶穿主包余量 ⇒ 若因「品牌色全覆盖」需求要进 P2，
  **本 ADR 的「主包」落位本身需重开**；**P3 全量 2104 色**（4208 张 ≈20–50 MB）主包不可能、分包亦顶穿 ≤30 MB 总红线 ⇒ **数学否掉**。
  另：本裁定只解「预烘臂开不开工」；**DEC-7（N2 生效 ⇒ L1 双张 ≈4.7 MB）不随之消失**，因为两分支下运行时烘都是主路径 ⇒ 预算仍 [待定]。
  ⚠ **追记（2026-09-28 行业调研，正文 = ADR-0028）两条修正本表竞争力评估的事实**：
  ① 兜底分支（P1 投放）持有一张主路没有的牌——**压缩纹理**（wx 基础库 2.5.0+ iOS pvr / Android etc1，官方工具实测降运行时内存 50–70%；运行时烘产物为 RGBA8888 吃不到）⇒ 若因 T5 内存进入 P1，除包体代价外还应计 VRAM 收益；
  ② 更根本的候选路线 = **灰度 mask × 着色（tint）**：纹理粒度从 `style×color` 降到 `style`，DEC-6/DEC-7 的逐色张数问题（含 P2/P3 包体数学否因）在 tint 成立时**整体消解**⇒ 评估中（ADR-0028，未采纳未否决），⛔ 引用本 DEC 时不得再当作「逐色纹理是唯一形态」。
- **DEC-7 L1 内存预算必须重算（N2 生效的连锁）**：单珠基准 ≈112 px ⇒ 66.8 KB/色（含 mip ×4/3）。
  扩为「单珠 + 整格底」**双张** ⇒ 同基准下 **≈133.6 KB/色 ⇒ 35 色 ≈ 4.7 MB**，`§13.5` 的 **[暂定 2.5 MB] 不再成立**。
  两条出路（**待裁，本 ADR 不代拍**）：① 抬 B1 预算至 ≈5 MB（撞低端机 `onMemoryWarning`）；
  ② 给整格底单独设更低烘焙基准（底图无高频细节）—— ⚠ 该做法在 `zoom > 1` 段进入**放大区**，
  违反 §13.3 缩放红线，须先实测软化不可察才准采纳（⛔ 纸面判）。
- **DEC-8 珠面烘焙八条纪律（v0.7.1 自 `control-manifest §19` 外移 ⇒ 本列为正本；控制清单只留指针，原因 = 该文件越 ctx B 门 8000）**：
  1. **入格四判据**：静态 / 随珠体刚性运动 / 不越格 / 最小尺寸 ≥1px（或按消失点去层）——四条同时满足才进纹理（逐项分配正本 = `§13.11`）。
  2. **门禁跑矢量配方**：C3／C12／C7 一律审**配方层**，⛔ 以「烘出来看不出」绕过；α 只按 `isRealAlphaLayer` **两支式**计，⛔ 写「0 次半透明混合」（只可写「命令级 0 α」）。
     ⚠ 位图皮肤下双指标**降级为「配方复杂度上限」**，C12「统计域 = 珠面族图元」不再可执行 ⇒ 需重设计（DEC-2）。
  3. **失效纪律**：矢量配方任何视觉变更必须同批递增 `bakeSchemaVersion`（封箱测试同批断言），漏改 = 线上旧皮，按假绿论处。
  4. **缩放红线**：基准 = 珠体边长 × `CAMERA_ZOOM_MAX` × dpr cap + 1dip ⇒ 运行时恒 ≤1:1 或缩小；⛔ 运行时放大烘焙纹理（mip 档数待验，归 `zoom-bake-mip-validation`）。
  5. **孔径裁定收窄**：「整数孔径」只适用基准尺寸烘焙；运行时连续半径 + 0.5px 盖缝 ⇒ 连带 `cell-standard` J4 判据改写 + 封箱腿 3 复评归因（`§13.11 L-1…L-6`），⛔ 当微改动。
  6. **平台 IO 分层**：L2 磁盘 / offscreen canvas 差异只准住 `adapters/`；`core` 保持禁 `cc`/`wx`/DOM（L2/L3 铁律同生效）。
  7. **帧数口径**：命令收益只准引 `§13.12` 四帧账（⚠ v0.7：旧「空盘帧零改善」随 N2 生效作废，空格行 **[待落码实测]**）；⛔ 只报满盘帧，⛔ 纸面当性能结论，⛔ 把未落码的目标态当已得数字引。
  8. **预烘资产纪律**：纹理文件只准由**构建期生成器**从层集产出且**同源 import**（同一份层集模块 + 同一 `bakeSchemaVersion`，⛔ studio 另写一份绘制）；
     新挂 `bake:check` 漂移守卫入 verify；手画位图与 AI 参考图**仍不得入仓入包**；包体守卫（`check:size` 实跑 + 主包目标值留告警牙齿）未归位前**禁止向主包投放位图**（= S0，§5-2）。

## 4. 后果（Consequences）

### 4.1 正面
- **预热真正到达玩家**：brand 集恒在主包 ⇒ 任意关卡首屏零下载命中，消除「低端机首屏批量烘焙抖动」与
  「studio 预览 ≠ 玩家首启观感」两条原空洞。
- **空格帧首次获得收益**（N2 生效）：空格 5 → 2 命令（`blit` 整格底 1 + 孔无关）或 → 1（若底与槽合一张），
  ⇒ **开局空盘帧 5,120 条自此才有下降杠杆**（v0.6 的「空盘帧零改善」声明随本 ADR 作废）。
- **资产可审计**：纹理是文件 ⇒ 可截图对比、可入库留证、可由 `bake:check` 守漂移（运行时烘的缓存做不到）。
- **解锁风格池**：DEC-2 给出翻案资格（性能型移出者），美术路线不再被命令数上限死锁。

### 4.2 负面（已知成本，非风险）
- **视觉真源从「一处」变「两处」**：层集 + 包内 PNG。⇒ 任何层集改动若忘重出资产，游戏读到旧纹理 =
  **线上旧皮**。守卫义务 = `bakeSchemaVersion` 同批递增 + `bake:check` + 封箱断言，**三道都要新写**。
- **二进制进 git**：纹理是生成物 ⇒ 不可 diff 审、每次配方微调全量重烘重提交（体量 = DEC-6 档位 × 单张字节）。
  处置待定：生成物**不入库**（由 CI 构建期产出、产物目录只进包）vs 入库（可回溯但仓库膨胀）—— **本 ADR 不代拍**。
- **包体守卫当前无牙齿**：DEC-1 落地即向主包加位图，而 `check:size` 在 verify 里 SKIP、A7 恒不触发 ⇒
  **等于在没有度量的前提下加重物**。⇒ 本项是 DEC-1 的**前置义务**（S0 步），不是可选项。
- **C12 主体色不变式统计域失效**：判据 = 「珠面 pixel 数占比最大的端点色，统计域 = 珠面族**图元**」⇒
  位图皮肤下「图元」概念消失。须重设计为对纹理像素做 argmax（或显式指定主体色通道），⛔ 沿用旧式当已验。
- **双指标门禁降级**（DEC-2 明写）：命令数上限不再约束运行时开销 ⇒ 过去靠它挡住的「层数爆炸」类风险
  转移到了**烘焙耗时与纹理张数**上，风险没有消失，只是换维。
- **「有豆/无豆 = 同一张图」（P7）从结构保证降为工艺保证**：底图与珠体分属两张纹理 ⇒ 缝宽／色档一致性
  不再由「同一个 B0 rect 恒画」自动成立，须靠新机检（DEC-6 档位定案后设计）。§13.8 N1 的原否因自此**长期在场**。
- **Cocos 端仍不覆盖**：`Graphics` 不能画 image（ADR-0025 §4.2 原样成立）⇒ 位图皮肤在 Cocos 端要等 Sprite 池立项，
  在此之前**双端观感不一致**（wx/harness 出位图，Cocos 出矢量）。
- **验证义务扩容**：原 6 项（T1–T6）之上，新增 ①预烘与运行时烘**同源性**测试 ②分包未到达期矢量帧与到达后位图帧的
  **观感一致**测试 ③底图/凹槽机检重设 ④包体实测。正本 = `zoom-bake-mip-validation.md v0.3`。

### 4.3 中性 / 待观察
- 底图（B0）本身是**一枚纯色 `rect` = 1 命令** ⇒ 把它烘进整格纹理的净收益只有「省 1 条 rect」，
  代价是纹理张数翻倍（DEC-7）。是否值得，取决于 T3/T4 实测把「rect 提交开销」量出来 —— 可能测完发现不该合张。
- 每日挑战／照片转拼豆关的自定义色板：走 ③ 运行时烘 ⇒ 同一关内可能混用「文件纹理」与「运行时烘纹理」两种来源，
  观感差异须由 DEC-4 同源性保证（同一份层集代码 + 同一基准公式）。

## 5. 复评触发条件（Review Triggers）

0. **预烘臂开工前置（v0.7.1 改为条件式）**：`§13.13` 的 T1／T4／T5／T6 **未出实测结果** ⇒ 预烘臂（生成器 / 资产入包 / 三层读序）
   不得开工；运行时烘实测全绿 ⇒ 本 ADR 转「备用案」，**仅**按 P1 档保留。口径已钉（用户 2026-09-27 二批），⛔ 不得再拿
   「先投资产后补测」当顺序（判据正本 = 本 ADR DEC-6 分支表）。
1. **T-215 层集归位未完成 ⇒ 不得烘任何资产**（承 ADR-0025 §5-0；配方真源只在
   `temp/bead-relief-compare/wip-215-full-backup.patch`，先烘 = 把已判不合格的形态固化进包）。
2. `check:size` 仍 SKIP 或 A7 仍钉 2000 ⇒ 禁止向主包投放位图（先修守卫，再放重物）。

7. Cocos 端 Sprite 池立项 ⇒ 复评双端口径与 `blit` 落位（与 ADR-0025 §5-6 同步复评）。
8. **ADR-0028（tint）验证批出结果** ⇒ 本 ADR 的 DEC-6/DEC-7 按「纹理粒度 style×color → style」重算；若 tint 采纳，预烘投放体量口径（P1 ≈16 色双张）同步作废重开。
9. **离屏烘焙物理像素口径实测（追记）**：wx 生态在案陷阱「离屏画布 = 物理像素尺寸，blit 必须显式指定逻辑尺寸，否则整图放大 dpr 倍发糊」⇒ S3-lite/S5 接线时逐处断言 blit 目标 = dp 口径（已列入 ADR-0025 §6-3 / T6 批）。
