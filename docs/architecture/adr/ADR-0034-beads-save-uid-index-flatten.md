| 案 | 内容 | 动因 | 代价（实测/推算） | 裁定 |
|---|---|---|---|---|
| **A** | **存档按 uid 记账 + 运行时保持下标展平视图**：产物每条关卡记录带身份；读档展平成 `number[]`、写档收拢成 `Record` | 让档内容与「关表怎么排」解耦 | 生成物 +210 B 源 / +130 B 包；save-schema 换形；**29 处测试夹具换形**（§4.2 表） | ✅ **采纳** |

## 3. 决定（Decision）

> 一句话：**存档以关卡稳定身份记账（`Record<uidKey, 历史最高星>`），运行时仍是下标稠密数组；身份↔下标的换算只发生在读档/写档两个既有边界点，各恰一次。**

### DEC-1 存档键形态

- 新字段 **`starsByUid: Record<string, number>`**，键 = 关卡身份 token，值 = 该关历史最高星 ∈ `[0, STAR_MAX]`（`tuning.ts:889`，= 3）。
- **v5 文档内 ⛔ 不再并存 `starsByLevel`**（用户明令 ⛔ 留两套并存；两套并存 = 第二真源，`normalizeBeadsSave` 的 `changed` 判定将无法自洽）。
- 身份 token 规则（**manifest uid 的纯函数派生，⛔ 不是第二真源**）：
  - `single` / `boss` → uid 原样，如 `L00001`；
  - `plate` 的第 c 格（c ≥ 2）→ `L000NN#c`（c = entry 展开内 **1-based 格序**，首格不加后缀）。
  - 理由（F5 + `expandEntriesWithIds`）：一个 plate entry 占**多个装配槽**（64×64 盘 = 4 格），纯 uid 无法「一格一星」；复合键把「槽身份」而非「文件身份」作为记账粒度，而它仍完全由 `uid` + 展开序决定，生成期可机械复算。
- 归一化（逐条对齐 S8 §2.4「逐字段降级、不弃整档」与 §8-12「字段级隔离」判例）：非对象 ⇒ 全槽 0；值非有限数 ⇒ 该键 0；小数 ⇒ 向下取整；越界 ⇒ 钳 `[0,STAR_MAX]`；**未知键 ⇒ 丢弃 + 一次性 `console.warn` 计数**（不抛、不弃整档）。

### DEC-2 桥接表（数据通道）——取「关卡对象各自带身份」

见 §3.1 对比表。**裁定：`BeadsLevelRaw` 增一条身份字段（沿用上面 token 规则），`ArcEntry` 零改动。**

展平/收拢因此只需要一条既有数组：**LEVELS 的下标即槽位**（F4 的 `levels[i].id === i+1` 不变量已是生成期硬断言），`LEVELS[i].<uid>` 就是「第 i 格是哪个身份」。章维信息（本章含哪些槽）继续走 `ARCS[k].levelRefs`——它是**每次构建由章的 uid 列表重新生成**的派生物，天然与当前关表一致，⛔ 不需要进档。

### DEC-3 展平/收拢时机与三条铁律

| 转换 | 唯一落点 | 频次 | 是否热路径 |
|---|---|---|---|
| 展平（uid 账 → 下标数组） | `normalizeBeadsSave(raw, levelCount, levelKeys)` ← 由 BOOT 的 `beads-game.ts:818-825` 调用 | **每启动 ≤1 次** | ❌ 否（§2 例外明文：存档读写、初始化） |
| 收拢（下标数组 → uid 账） | `_persistProgress()`（`beads-game.ts:2269`）内一次线性扫描 | **每局 ≤1 次**（S8 §2.5「结算写」） | ❌ 否 |

- **签名扩展**：`normalizeBeadsSave(raw, levelCount, levelKeys: readonly string[])`。`levelKeys` 由 `BeadsGame` 在 BOOT 装配关卡表时构造一次并存为只读镜像 `this._levelKeys`（与 `_levels` 同生命周期）；⛔ 视图/结算不得再构造。
- **L3**：转换函数是纯 TS（无 `cc` / DOM / `wx`），身份轴来自生成产物 ⇒ 纯 Node 可单测（§11）。
- **L5**：不新增状态持有者。`_levelKeys` 是关卡表的只读派生镜像，不是游戏状态；视图侧继续只拿 `starsByLevelRaw` 只读引用（`beads-shell.ts:747`、`meta-view.ts:1199` 零改动）。
- **热路径零分配**：⛔ 不在 `update` / `step` / `buildRenderModel` 内做任何 uid↔index 转换；7 处按下标取数位点继续走整数下标。归一化内为孤儿键判定**允许一次函数局部 `Map` 建表**（读档一次性、随调用回收），不构成常驻分配。
- **ES5 契约（§15）**：产物遍历一律 `for` / `Array.from`；⛔ 对 `Object.keys` 结果之外的可迭代对象用展开。

### DEC-4 迁移 = v4→v5 一次性换制，**bump `SAVE_VERSION` 4→5**

- **bump 结论 = 要 bump**。判例对表：v1→v2（`reduceMotion`/`largeText`）、v2→v3（`onboarded`）、v3→v4（`vibrate`）都是「**新增可选字段 + 逐字段降级**」，因此 `debugInfo`/`beadStyle`/`skinId` 甚至明文不 bump（S8 §8-12「version 无需为此 bump」）。本批不同：**同一语义换键形态**，旧字段在新代码里无对应物 ⇒ 属 `control-manifest §5`「每次 schema 变更：升版本 + 写迁移」，不属「加字段」档。不 bump 会让「version 仍写 4、形态已是 5」的档在开发期多包共存时**无法判别**。
- `migrations[4] = migrateV4ToV5`：**只做版本标记 + 旧字段原样透传**（沿 v1→v2 判例）。⛔ 不在迁移函数里做 uid 换算——`Migration` 签名是 `Record → Record`（`packages/framework/src/core/save/save-manager.ts:22`），**拿不到关表轴**。
- **真正的换算落在 normalize**（唯一持有关表轴的层，DEC-3）。这不只是整洁性问题，而是**必须**：见 DEC-5 的短路事实。

### DEC-5 形态探测 = 唯一裁定（与 WXG-T-342 的关系）

实测：`migrateV1ToV2` 等三条既有迁移均返回 `version: SAVE_VERSION`（常量，**不是 n+1**），而 `SaveManager.load()` 每步后重读 `doc['version']`（`save-manager.ts:97-101`）⇒ **一条迁移即跳到当前版，其后所有迁移被跳过**；v1/v2/v3 老档根本不会流经 `migrations[4]`。因此换算必须由 normalize 的形态探测兜住：

1. `isRecord(raw['starsByUid'])` ⇒ 走 v5 路径；
2. 否则 `Array.isArray(raw['starsByLevel'])` ⇒ 走 **v4 换算**：旧第 i 位 = 写档那一刻关表第 i 关 ⇒ 在「当前关表 = v4 唯一真相源」假设下搬运成 `levelKeys[i]`（F9：未上架 + v1.22 刚把轴对齐到当前 10 关 ⇒ 假设成立）；
3. 两者皆非 ⇒ 全槽 0（沿「非数组 ⇒ 全 0」臂语义）；
4. 换算后写回的文档**只含 `starsByUid`**，`changed = true` 恰一次；二次读同一档 `changed = false`（幂等臂，沿 §8-14 ④）。

⇒ **WXG-T-342 的前缀搬运不与之并存**：它升为「按 uid 轴搬运」的**输入侧兼容分支**，只服务于 v4→v5 这一次；v5 之后不再有位置型字段，§8-14 的「长度不符」触发器随之作废（作废声明归 T-1 在 S8 落文，⛔ 我代写）。

### DEC-6 「当前关表 = v4 唯一真相源」假设的边界与上架后的正确做法

- **本批可一次性做的理由** = §1.3 窗口（F9）。
- **上架后此假设失效**，正确做法三条：① 迁移只按当时仍有效的 uid 轴换算，未知/退役 uid **保留为孤儿键**（不删，删 = 玩家曾通关的事实消失）；② 需真实档样本做灰度验证（playtest 读数 + `production/qa` 镜像用例），⛔ 不能在 CI 里自我宣布无损；③ 若两个**已上架**版本之间关表重排过，则不存在唯一真相源 ⇒ 必须按版本分支各配一套轴快照，即档内需留「这档是在哪张关表上写的」的凭证。
- ⇒ 工程侧本批就为 ③ 预留出口：v5 文档增**只作取证、不参与任何判定**的 `contentVersion: number`（真源 = `manifest.contentVersion`，现 35）。字节 = 档体 +约 22 B，包体零增。⛔ 不得把它接进任何逻辑（否则成第二真源）。

### DEC-8 门票归约与橱窗三态**判据源隔离**（已按 `meta-ui v0.5 §2.7` / `§8-10` 对齐）

- 新增纯函数 `systems/arc-ticket.ts`（暂名，落码批复核）：输入 = 章内每槽的历史最高星（DEC-3 展平视图）+ 章的 `levelRefs`；输出 = **至少两值**：`satisfied: boolean`（每槽 `== STAR_MAX`）**与 `fullStarCount / total`（= 告知件「满星 n/N」的派生量，`ux v1.10 §4.1` 甲臂；N = 本章清单长度，⛔ 不是 `DEMO_LEVEL_COUNT`）**。归约为纯函数：⛔ 副作用、⛔ 读第二真源（= `I1`）。**⚠ T-1R 后本 DEC 的两条边界已由正本锁死**：`§2.6.1-3` 裁「归约集合 = 本章清单内的**每一个槽，⛔ 无豁免**（boss 收尾关也是小关之一、教学关不特判）」；`§8-18` v1.3-R 另开**静态臂：⛔ 门票归约的输入集合里出现章 id**（判据源只允许 = 关身份账 ∩ 当前章清单槽位集）⇒ 落码批须同时交这两臂（本文 §6.1 **M-17 / M-16**）。
- **⛔ 门票布尔不落档**（`I5`，遵 S8 §2.3「可派生的值不入档」）；档内不存在「已开票」标记。
- ⛔ 不复用 `_arcState` 内的 `allCleared`（`beads-shell.ts:692-712`，判据 = `stars[lv-1] > 0`），⛔ 不被其调用，⛔ 不共用布尔中间量；反之 **三态归约一字不动**（Q16 = 甲，仍按 ≥1★），门票只在**跳章那一刻**作闸门。
- **⛔ 不得做成运行期活锁**（`I7` 棘轮）：不得每帧重算门票并据此收回已得入口。强制用例（T-1 明文「必须写成用例」）：给一已推平且玩家已进入过下一章的章**追加一关（0 星）**⇒ 实时归约重新为假，但已获得入口**不得消失**。
- 反例臂（必须两栏同时成立才叫隔离住了，= `meta-ui §8-10` 三臂的 ②）：章内一关 2★、其余 3★ ⇒ `_arcState == 'cleared'` **且** `arcTicketSatisfied == false`。**空清单臂**：两层都为假，⛔ 真空判成「已满星 ⇒ 可进下一章」（`§8-15-③` 同口径），进度件 `N=0` 时**不创建**（⛔ 显示 `0/0`）。

### DEC-9 身份失效的降级与可观测性（**已按 `I3` / §2.6.4 / §8-17、§8-18 定稿**）

- T-1 已裁 = 本文初稿默认项的**同一档**：`§2.4 v1.3 新行`「存档引用的关身份在当前关表里不存在 ⇒ **该条记录单独作废**，其余能对位的**逐条无损**；⛔ 不得把作废记录挪给别的关；不弹错、不中断启动」+ `I3`「孤儿记录**可枚举**」+ `§8-17`「⛔ 把孤儿当类型错而走全档出厂默认 ⇒ 本条红」。⇒ **不阻塞 S-2**（原列 Q2 已答）。
- **写侧裁定（属工程域，本文明确取「裁剪丢弃」）**：孤儿键在**写回时物理丢弃**。理由不是省事，而是它恰好关掉一条污染通道：若长期保留孤儿键，则同一 uid 被**复用为新内容**时，玩家凭旧内容拿到的星会直接替新内容开门——`save-progress v1.3 §2.6.3`「复用身份 = ❌ 最危险，禁止」与 `§8-18` 静态臂「⛔ 存在身份复用放行路径」正好要咬住这个形状。丢弃把污染窗口收敛到单次会话内。
- **诚实边界**：丢弃 ⇒ 「被删关的星」不可逆。这比「保留孤儿」信息更少，但语义正本已明文选了「逐条作废、不迁移、不挪用」（且 §2.6.3 删关行裁定「若删掉的恰是唯一未满星关，门票自然达成 = 允许」）⇒ 本文跟随，⛔ 自行改语义。
- 可观测性（= 把 `I3` 的「可枚举」做出来）：`console.warn('[beads] save uid unmatched: dropped=N, missing=M')`（仓内既有渠道，`beads-game.ts:1070/1657` 同形态），⛔ 不新增玩家可见反馈（S8 §4「降级静默」）。测试臂用**注入桩捕获该 warn**（行为测试，非源码正则——§17 教训）。

## 4. 后果（Consequences）

### 4.1 正面

1. **插 / 删 / 调序 / 移章 / 整体重编号对历史星账免疫**（星随身份走），直接消掉 K-151 的能力边界⑤ 与 `levels-spec §11.7` 那条「须另开迁移单」的欠账——本批就是那张单。
2. 门票有**可归约的充分信息**：章内每关历史最高星（R7 的判据源），不再依赖「下标恰好对上」。
3. 改动收口在 **2 个既有边界点**（F8），运行时 7 处下标位点与视图契约零改动 ⇒ 回归面小、可全在纯 Node 验。
4. `arcs.ts` / `ArcEntry` 不动 ⇒ EP13-S1/S2 已入库的表侧不变式与 6 个消费点不重写。
5. 为上架后的扩池/换盘预留了唯一正确形态（DEC-6 ③ 的 `contentVersion` 取证位）。

其余已知成本：

1. **关表产物耦合面 +1 字段**：`BeadsLevelRaw` 多一条身份字段 ⇒ 凡「记录键集合全等」形态的断言需复核（实测无此类断言，`levels.test.ts` / `level-import.ts` / `config/levels.ts::validateBeadsLevel` 均不吃键集合；但落码批仍须跑全套件确认）。
2. **档体增、篡改面增**：星账从 ~30 B（10 个数字）升到 ~130 B（10 个键值对）。⛔ 不占包体（写 `wx` storage，域配额 10 MB）；白名单裁剪已覆盖（S8 §6「存档超长」条）。
3. **迁移链短路是既存缺陷**（DEC-5）：`migrations[n]` 返回 `SAVE_VERSION` 而非 `n+1` ⇒ 一条跳到底、后续迁移被跳过。今天无害（v1–v4 全是加字段 + 逐字段降级），**但本批是第一条结构迁移**，缺陷首次变成必须绕开的事实。本 ADR 用 normalize 形态探测绕开，缺陷本身另立小单改严（S-7）。
4. **换制期回滚代价 = 清档**：v5 档被 v4 代码读到 ⇒ `version > current` 分支直接 reset（`save-manager.ts:84-89` 实测）。⇒ 本批开发期内**真机扫码档会清至少一次**，须提前告知 QA，⛔ 不得说「无损」。
5. **plate 复合键的含义绑定格序**：同 uid 从 4 格改成 6 格时，`uid#c` 所指代的槽含义漂移 ⇒ 属能力边界（R-3，触发即需再迁移）。
6. **一次性成本集中**：29 处夹具换形 + save-schema 换形必须在同一批内完成，否则中间态测试不可信（K-152 同族的「批量假红淹没真信号」）。

### 4.3 中性 / 待观察

- 包内的 `description` 中文串（≈500 B UTF-8）是既有可瘦身项，与本批无关，登记以免日后误记账。
- `_levelKeys` 与 `_levels` 同生命周期 ⇒ 若日后关卡表改成惰性/分包装载，镜像需随之改（现池 10 关，全量常驻）。
