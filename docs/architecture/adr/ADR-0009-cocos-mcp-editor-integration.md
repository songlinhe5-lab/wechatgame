# ADR-0009 — Cocos MCP 编辑器接入（智能体 ↔ Cocos Creator 验证闭环）

- **状态**：已决定（Accepted）
- **日期**：2026-09-12
- **作者**：程基岩（技术 + 引擎负责人）
- **关联决策**：ADR-0001（引擎选型，钉定 Cocos Creator 3.8 LTS / 3.8.8）/ ADR-0003（空场景代码驱动）/ ADR-0005（程序化渲染）
- **关联文档**：`docs/engine-reference/cocos/VERSION.md`（知识缺口清单 G1–G9）、`docs/architecture/control-manifest.md`（L1 铁律）、`docs/architecture/architecture-beads.md`（EP-10 真机步）、`memory/MEMORY.md`（build:wx 已知限制）

## 1. 上下文（Context）

### 1.1 环境事实

- 智能体（四 IDE：Cursor / CodeBuddy / WorkBuddy / Qoder + 终端）**没有 GUI**，Cocos Creator 编辑器只能运行在用户本机（macOS）。
- 编辑器侧的验证、构建、资源管理此前**完全依赖人工**：智能体写完代码只能停在"Node 侧全绿"，编辑器内发生什么不可知（architecture.md §6 构建链"诚实说明"）。
- MCP 的 HTTP transport（`http://127.0.0.1:3000/mcp`）与具体 IDE 无关，是四 IDE + 终端**一套配置通吃**的接入方式——与 `.githooks` 全 IDE 共用是同一个设计逻辑。

### 1.2 既有缺口（引用真源，不转述）

| 缺口 | 真源 | 现状 |
| --- | --- | --- |
| **G1–G9 知识缺口清单**（G1 框架包引用【阻塞工程搭建】/ G2 Graphics 签名 / G3 Label 行为 / G4 触摸坐标系 / G5 帧驱动 / G6 装饰器注册 / G7 构建与包体 / G8 wx 适配 / G9 `.meta` 与资源） | `docs/engine-reference/cocos/VERSION.md` §3 | `bindings.ts` **已写但未验证**（§4 验证矩阵 ❌）；需要"编辑器就绪后按序验证并回填结论" |
| **EP-10 真机步** | `docs/architecture/architecture-beads.md` 风险登记册 R1/R5（"bindings.ts 未验证（矩阵级 G1–G9 沿用）……EP-10 首步验证"）；ADR-0005/0006 §5 均挂 EP-10 | Cocos 侧一切真机验证的前置步 |
| **`.meta` 必须由编辑器生成** | `control-manifest.md` L1（禁止手工编辑 `.scene`/`.prefab`/`.meta`）；`VERSION.md` G9（手工新增 assets 文件依赖编辑器自动补 `.meta`；资源目录移动只能通过编辑器） | 目前只是**纪律**：智能体新增资产后没有任何手段触发编辑器刷新，闭环靠人肉开编辑器 |
| **`build:wx` 未接入** | `memory/MEMORY.md` 已知限制（"小游戏真机构建 `build:wx` 尚未接入 Cocos Creator CLI，目前由浏览器 harness 覆盖游戏逻辑与渲染验证"）；`architecture.md` §6（Cocos 构建需要编辑器 ⚠，CI 无法产出安装包） | 微信小游戏最终构建链断在编辑器这一环 |

### 1.3 边界红线

架构纪律 **L1 禁止手工编辑 `.scene` / `.prefab` / `.meta`**。因此本决策的接入定位从一开始就限定为：

> **验证 / 构建 / 资源刷新闭环**——不是"用 AI 搭场景"。

MCP 的场景/节点修改类工具不得用于绕过 L1（工具级防线见 §3.3 与控制清单增量）。

### 1.4 运行时影响

MCP 插件安装在编辑器侧（`extensions/`），**不进入微信小游戏构建产物**，对主包 ≤ 4 MB 红线零影响（ADR-0001 包体约束不受扰动）。

## 2. 备选方案（Alternatives）

> 版本号、许可、维护状态为 2026-09-12 核实值（GitHub `DaxianLee/cocos-mcp-server` 公开页）。

| 维度 | **A：DaxianLee 开源版** | **B：VberAI Pro 版** | **C：自研最小 MCP 插件** | **D：不接入（维持人工开编辑器）** |
| --- | --- | --- | --- | --- |
| 版本 | v1.5.4（50 个核心工具，由 150+ 精简重构而来） | 1.7.8（16 个意图级工具 / 231 项操作 / 12 模块） | — | — |
| 能力覆盖 | 场景/节点/组件/预制体/资源/构建/调试等 13 类前缀，编辑器控制面广 | 覆盖面更广：Streamable HTTP、UI 模板一键建场景、动画/Spine（39 项）、内置知识库 | 只做三件事：**构建 + 控制台回读 + 资源刷新** | 零覆盖 |
| 许可与商用 | **自定义许可：禁止任何商用、转售**；源码可学习、可二开，商用需联系作者授权 | 商用合规，但**价格未公开**（`vberai.com/pricing`，需询价/联系 `support@vberai.com`） | 自有代码，MIT/自定，**零许可风险** | 无 |
| 维护风险 | **社区单点**（个人项目，~1.4k stars / 32 commits，无 SLA） | 商业公司（VberAI）维护，存续绑定其商业意愿 | 维护成本自担（三件事范围小，可控） | 无 |
| 接入成本 | **低**：插件装 `extensions/`、编辑器内启动；HTTP 端点四 IDE 一套配置 | 低（提供主流客户端一键配置），加询价/采购流程 | **中–高**：需自研并长期维护，占用工程带宽 | 零（但每次验证/构建循环都挂人工） |
| 与 L1 的兼容性 | 50 个工具**含场景/节点写操作**——必须靠其编辑器插件自带的工具管理面板做白名单禁用 | 同样含建场景/UI 模板类工具，同样需禁用 | **天然兼容**（根本不实现写场景工具） | 天然兼容 |
| 版本兼容 | **存在歧义**：页面简介称 3.8.0+，系统要求 3.8.6+；本仓钉定 3.8.8 理论满足，待实测 | 要求 Cocos Creator **3.8.6+**（3.8.8 满足） | 自控版本 | 无 |
| 协议 | HTTP（`127.0.0.1:3000/mcp`，端口可配，无鉴权） | Streamable HTTP | 自定 | — |

**排除理由**：

- **D**：不解决 1.2 的任何缺口；G1–G9 与 EP-10 的解锁被无限期挂在"人什么时候开编辑器"上，与"多成员 / 多 AI 会话并行同一仓库"的协作方式（architecture.md §1.2）冲突。
- **B**：能力溢出——我们需要的是验证/构建/资源刷新，不是一键建场景与 Spine 动画；且价格不透明，在商业化尚未启动时先付费不符合成本纪律。保留为商业化启动后的候选。
- **C**：三件事的工具面小，但自研意味着协议适配、编辑器 API 探索（恰好撞在 G1–G9 未验证的同一片雷区上）与长期维护全部自担——**用社区方案先验证闭环价值，再决定是否值得自研**，是更小的赌注。

## 3. 决定（Decision）

### 3.1 一句话

> **接入方案 A（DaxianLee/cocos-mcp-server 开源版 v1.5.4，HTTP 本机模式 `127.0.0.1:3000/mcp`），通过其编辑器插件的工具管理面板默认禁用全部场景/节点写操作类工具，仅保留验证/构建/资源/调试类工具——接入定位是"验证/构建/资源刷新闭环"，不是"用 AI 搭场景"。**

### 3.2 用例分层

| 层级 | 用例 | 关闭的缺口 | 说明 |
| --- | --- | --- | --- |
| **P0** | `bindings.ts` 首编译验证：MCP 触发构建 + `debug_console` 回读编译/运行错误，按 `VERSION.md` §3 依赖顺序逐条验证并回填结论 | **直接关闭 G1–G6**；G7 的构建基线部分顺带启动 | G1（框架包引用）最高优先级——它阻塞整个 Cocos 工程搭建 |
| **P1** | `.meta` 合规闭环：智能体新增资产文件后，经 MCP 资源工具触发编辑器刷新/重导入，由**编辑器生成** `.meta` 后提交 | **G9 落地为工具闭环**；L1 中".meta 由编辑器生成"从纪律升级为可执行流程 | 资源目录调整仍然只能走编辑器（G9 红色感叹号问题不变） |
| **P2** | 微信小游戏构建驱动：经 MCP 的 `project_build_system` 类工具从命令行驱动编辑器构建，产物接 `check-bundle-size.mjs` | **G7 全量关闭**；缩小 `build:wx` 缺口（距离"CLI 无人值守构建"仍差一步） | G8（wx 适配真机行为）与 EP-10 的**真机**部分不归 MCP——真机步仍需人工，MCP 只负责把"编辑器内构建+回读"自动化 |

> 诚实修正：G8 与 EP-10 真机帧率/安全区验证**不在本决策能力范围内**（MCP 到编辑器为止，不到真机）。EP-10 的解锁 = P0（编辑器内验证）+ 人工真机步。

### 3.3 工具白名单 / 禁用清单

以插件编辑器内的**工具管理面板**为准（默认禁用声明如下，实测后按 v1.5.4 实际工具名回填微调）：

| 状态 | 工具前缀 | 理由 |
| --- | --- | --- |
| ✅ 白名单 | `project_*`（运行/构建/项目信息） | P0/P2 构建驱动 |
| ✅ 白名单 | `debug_*`（控制台日志/日志分析） | P0 回读编译与运行错误 |
| ✅ 白名单 | `asset_*`（导入/刷新/重导入/依赖分析） | P1 `.meta` 合规闭环 |
| ✅ 白名单 | `validation_*`（场景完整性/资源引用验证） | 替代部分目视检查 |
| ✅ 白名单 | `server_*` / `broadcast_*` | 连接状态与消息监听 |
| ❌ 默认禁用 | `scene_*` 写操作（新建/保存场景）、`node_*` 写操作（创建/删除/变换/层级）、`component_*` 写操作（增删改/挂载）、`prefab_*` 写操作（创建/实例化/同步） | **L1 工具级防线**：这些动作的全部产出 = 手编 `.scene`/`.prefab`，正是 ADR-0003 否决的路径 |
| ❌ 默认禁用 | `sceneView_*` / `referenceImage_*` / `preferences_*` | 纯编辑器视图/偏好操作，与本决策定位无关 |

执行纪律（对 v1.5.4 统一"类别_操作 + action 参数"模式的落地）：

- 按**前缀整体禁用** `scene_*` / `node_*` / `component_*` / `prefab_*`；若 P0 验证确需只读查询（如层级确认），可临时开启对应工具并在 ADR 复评记录中登记，**严禁开启其写 action**。
- 任何经 MCP 发生的场景/节点变更，**视同手编 `.scene`，违反 L1**，评审打回。

### 3.4 四 IDE 接入方式

HTTP transport 与 IDE 无关：四个 IDE 与终端的 MCP 配置统一指向同一个 URL（`http://127.0.0.1:3000/mcp`），与 `.githooks` 共用是同一设计逻辑——**一份配置，四处生效**，不产生 IDE 专属配置分叉。插件本体装编辑器 `extensions/`，在编辑器内启动。

## 4. 后果（Consequences）

### 4.1 正面

- **G1–G6 从"人肉目视验证"变为"智能体可驱动"**：构建触发 + `debug_console` 回读错误，`bindings.ts` 未验证缺口有了确定的关闭路径，`VERSION.md` 的回填工作流可以由智能体推进。
- **`.meta` 合规从纪律升级为工具闭环**：智能体新增资产 → MCP 触发刷新 → 编辑器生成 `.meta` → 提交。L1 的".meta 由编辑器生成"从"靠自觉"变为"有流程"。
- **P2 为构建自动化铺路**：微信小游戏构建从"必须有人开编辑器点构建"向"命令行可触发"移动，直接缩小 `build:wx` 与 architecture.md §6"CI 无法产出安装包"的缺口。
- **运行时包体零影响**：插件在编辑器侧，不进构建产物（§1.4）。
- **四 IDE 一套配置**：HTTP 端点统一接入，无 IDE 分叉。
- **L1 有了工具级防线**：白名单禁用写在插件面板里，比"prompt 里写纪律"多一层机械约束。

### 4.2 负面（已知成本，不是风险——白纸黑字）

1. **非商用许可直接阻塞商业化**：开源版自定义许可**禁止任何商用、转售**。本项目一旦启动商业化或对外发布，必须（a）联系作者获得授权，或（b）切换方案 B 付费，或（c）按方案 C 自研替换——迁移成本在那时才暴露，且届时 P1/P2 用例可能已依赖此工具链。
2. **编辑器必须开机的单点依赖**：MCP 服务跑在编辑器进程内，编辑器未启动 = 智能体验证链路整体不可用；且编辑器只在用户本机（macOS）运行，**没有 CI 形态**，headless 流水线（`docs/agent/headless-ci-pr-review.md`）仍然吃不到这一环。
3. **HTTP 无鉴权，安全性建立在"仅本机"这一前提上**：`127.0.0.1:3000/mcp` 无任何认证，本机任意进程都能触发构建/资源操作。端点**禁止暴露到非回环地址**（列入控制清单红线）。
4. **社区单点断维护风险**：DaxianLee 个人项目（~1.4k stars / 32 commits），无 SLA、无承诺维护周期。断维护时 P1/P2 用例没有官方替代，只能转方案 B/C。
5. **升级流程负担**：插件升级需要删除编辑器 settings 中两个配置文件再重来，多一步人工操作；且升级可能改变工具清单，白名单映射需随之重核。
6. **版本兼容歧义悬置**：README 简介"3.8.0+"与系统要求"3.8.6+"不一致。本仓钉定 3.8.8 理论上满足较严标准，但在 P0 实测前不定论——实测失败则本决策的能力承诺全部落空。

### 4.3 中性 / 待观察

- 3.8.8 上的实际兼容性：待 P0 实测回填（`VERSION.md` 验证矩阵同步更新）。
- 50 个工具中实际可用比例、`debug_console` 回读错误的信噪比：待 P0 实测。
- Pro 版价格未公开：商业化启动时再询价，当前不做采购决策。
- 自研最小插件（方案 C）的真实成本：待 P1/P2 跑通后再评估"值不值得替换掉非商用许可"。

## 5. 复评触发条件（Review Triggers）

出现以下任一情况，**重新评估本决策**：

1. **项目启动商业化**（对外发布 / 产生收入）→ 复评许可红线：作者授权 / 方案 B 采购 / 方案 C 自研，三选一必须落地后才能进入商业发布流程。
2. **插件停止维护**（连续 ≥ 6 个月无更新，或 Cocos 3.8.x 新补丁版本不再兼容）**或 Cocos 升级 4.x** → 复评方案 C 自研接管三件核心能力（构建/控制台/资源刷新）。
3. **需要 Streamable HTTP、意图级工具或动画/Spine 操作**（如后续游戏引入骨骼动画资产）→ 复评方案 B。
4. **P0 实测发现版本兼容失败，或白名单不足以支撑验证闭环**（只读查询被连带禁用导致 G2–G6 无法验证）→ 复评工具粒度或方案 C。
