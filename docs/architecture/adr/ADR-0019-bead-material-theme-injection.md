# ADR-0019 — 珠材质主题的参数化注入与运行时切换

- 状态：**Proposed**（待用户批准落码；本文件只记录决策，不含实现）
- 日期：2026-09-23 · 任务号 **WXG-T-203 续作** · 执笔：程基岩（engineering-lead）
- 关联：`ADR-0016`（照片转拼豆色板/品牌引用制）、`ADR-0017`（zoom 自适应 LOD）、
  `assets-spec §1.9.7`（换肤面裁定）、`bead-visual-style-spec 附录 A`（17 套材质参考图）、

## 1. 上下文（Context）

需求：**运行时平滑切换不同风格的拼豆珠效果，且不影响玩法。**

### 1.1 现状事实（读码所得，非推测）

| 项 | 事实 | 位置 |
|---|---|---|
已有的注入通道 | `buildBeadsView(builder, snap, palette, inks)` —— UI token 层 `BeadsPalette` 与珠色墨水 `BeadInks` **已经是外部传入**，game 侧按当前关卡解析后传入，热路径零分配 | `view/view-model.ts:204` |
同上（空槽侧） | `drawEmptySocket(builder, cx, cy, palette, size, colorIdx?, inks, tilePainted)` —— 材质相关系数仍来自模块级常量 | `view/bead-render.ts:425` |
**缺失的通道** | `drawFilledBead(builder, cx, cy, colorIdx, options)` 的 `options` 里**没有任何材质形参**；珠体全部材质系数硬绑在模块级 `Object.freeze` 的 `BEAD_CARD`（radius / contact* / bevel* / softHighlight / shadowDy / **§5 抬起四通道增益** / hole* / wall*）与 `palette.ts` 的 `BEAD_BEVEL_DARK_MIX` / `BEAD_BEVEL_LIGHT_MIX` / `BEAD_RIM_MIX` / `BEAD_SOFT_HIGHLIGHT_ALPHAS` / `BEAD_SHADOW_ALPHA` / `BEAD_CONTACT_SHADOW_ALPHA` | `view/bead-render.ts:56`、`view/palette.ts` |
已有裁定 | `assets-spec §1.9.7` 早已判定「珠体十层对主题化**零参数通道** ⇒ 需工程最小重构」，并划定换肤面：`base` 色**锁死**、软高光 α **只可下调**、投影 α **不得降为 0**、倒角三系数**可自由换**；且「换肤只能是**材质主题**，不能是**配色主题**」 | 美术侧既有裁定（本 ADR 不重开） |
要切换的对象 | `bead-visual-style-spec 附录 A` 的 17 套材质参考图中，**只有 01 哑光注塑已被实现**（就是当前线上模型）；02/06/11/12/13… 均为设计参照，15 自否、05/07/08 移出候选 | `design/proposals/bead-visual-style-spec.md` |

### 1.2 为什么现在必须决定架构而非先写代码

若不先定注入形态，落地"第二套材质"（最可能的首个候选是 02 亮面烤漆或 06 珐琅金属）时，
最省事的写法就是往 `drawFilledBead` 里塞 `if (style === 'glossy') …`。一旦如此：

1. 渲染函数长出**风格枚举分支** ⇒ 17 套 = 17 组分支，逐层交叠（侧壁 × 高光 × 孔 × 虹彩带）⇒ 组合爆炸；
2. 违背 `assets-spec` 「新参数一律归 `tuning` 呈现层」与美术侧「材质系数是规格、不是代码」；
3. **ADR-0017 的降档通道失效** —— 降档集 `WAVE_LOD_LAYERS` 是"层数"概念，风格分支各自决定层数后，
   每帧图元上界变得不可静态推算，`§1.8` 图元基线（现测值 **1587/帧，+1/已填格**）失去可核对性；
4. 判据体系（`bead-render.test` 已钉住 12 条图元逐 kind 序列、§1.2 selected 语义、§5 三通道）
   会随分支膨胀而逐个失焦。

### 1.3 约束（引用，不发明新数值）

- **L5** 视图不持状态：材质 id 若被 view 自己记住即违规。
- **L4** 禁 `Math.random()`：任何风格的"颗间微抖动/开片"必须由**格坐标派生的确定性哈希**给出，
  且**不得消耗 `services.rng` 的 draw 序列**（否则换关/重开跳变，破坏可回放）。
- **§2** 热路径零分配：材质对象必须是模块级 frozen 单例，渲染中禁止 `new`/`spread` 合成。
- **§5** 存档：新增字段须 `version++` + 写迁移 + `validate`，不直接改默认值。
- **§8** 渲染：只产 `rect / circle / line / text / polygon` **五种**既有原语。
- **§3 冻结常量不动**：`BEAD_CELL=50`、`BEAD_PITCH=52`、`TOUCH_MIN`、各相位时长与本决策无关。
- `ADR-0017` 降档与 `bead-visual-style-spec §6` 图元预算纪律：**增量必须可静态核算**。

## 2. 备选方案（Alternatives）

| 方案 | 做法 | 事实性评估 |
|---|---|---|
**甲** 每风格一个绘制函数 | `drawGlossyBead()` / `drawEnamelBead()` … 17 个导出 | 上手最快，但层组合（侧壁×高光×孔×虹彩×描边）会以**分支数相乘**复制；判据矩阵与 `§1.8` 基线各自维护一份；`view-model` 需持有风格→函数的分派表（= 把规格搬进代码）。**否决** |
**乙** 单一 `BeadMaterial` 参数记录 + 表驱动注册表 | 材质 = 一份 frozen 数值表；渲染函数**只有一条代码路径**，读表取值；差异层由受限枚举声明 | 与 `assets-spec §1.9.7` 给的换肤面**天然同构**（该裁定本来就只允许改光泽/倒角/rim/投影 α 这几类系数）；图元数可按材质静态求和；不传材质 ⇒ 缺省即现值，**零行为变更**；成本 = 一次性把常量拆成参数 |
**丙** 材质表由服务端/JSON 运行时下发（可热更） | 乙 之上把表外置成数据 | 多一层解析/校验/失败兜底与包体；且材质表是**美术规格**，改动必须走 `assets-spec` 与判据更新，热更有意义吗？—— 不需要（改材质=发版）。**否决**（留作复评项） |
**丁** 真实贴图（sprite sheet） | 直接画珠的预制位图 | 视觉上限最高，但**直接违反本仓库支柱**：demo 阶段零外部美术文件 + 主包 ≤4MB；且 17 风格 × 10 色 × 缩放档 = 图集爆炸；亦使 `§1.8` 图元口径与 ADR-0017 失效。**否决** |

## 3. 决定（Decision）

**采乙**：引入**材质参数记录 `BeadMaterial`**，经 `options.material` 注入 `drawFilledBead` /
`drawEmptySocket`；材质注册表 `BEAD_MATERIALS` 为模块级 frozen 单例；当前线上模型原样成为
注册表里的 `MATTE_INJECTED`（**缺省值，不传即逐字等价现行为**）。

### 3.1 材质记录的形状（字段 = `assets-spec §1.9.7` 允许的换肤面 + 本仓已有参数，**不新造维度**）

```
BeadMaterial {
  id
  // —— 系数族（全部对应现有常量位） ——
  radiusRatio, contactX/Y/W/H, contactRadiusScale, shadowDy, shadowAlpha,
  contactShadowAlpha, bevelDarkMix, bevelLightMix, rimMix, highlightAlphas[3],
  liftScaleGain, liftShadowDyGain, liftShadowFade, liftContactShrink, wallRatio, wallLiftGain,
  holeRatio, holeShadeOffset, holeShadeAlpha,
  // —— 受限的"层集合"差异（不新增原语，只声明既有层的开关/复用次数） ——
  layers: { sideWall, hole, outline, iridescentBand, twoToneBand }   // 每个 = 既有 5 原语之一
}
```

**硬约束（写进类型与判据，不靠自觉）**：
1. `highlightAlphas` 各值 **≤ 现值**（§1.9.7「只可下调」）；
2. `shadowAlpha > 0` 且 `contactShadowAlpha > 0`（§1.9.4 五通道之第 3 条不得归零）；
3. `bevelDarkMix < 0 < bevelLightMix`、`radiusRatio` 落在 `[0.22, 0.36]`（保证圆角方读感，不回正圆也不回方角）；
4. `layers` 只允许既有 5 原语，**禁止申请新原语**（如 ellipse）——需要新原语即视为对本 ADR 的复评触发（§5）。

### 3.2 切换与"不影响玩法"的边界

- **持有者**：材质 id 属**元游戏/设置**，存 `meta` 侧车存档（`BeadsMeta`，`version 1 → 2` +
  `migrations` + `normalize`，未知 id 回落 `MATTE_INJECTED`，永不抛异常）。**不进** run 存档
  （`save-schema`），**不进** `BeadsSnapshot`。
- **读取路径**：`beads-shell` 解析一次 → 随 `inks` 一起作为**参数**传给 `buildBeadsView`。
  ⇒ 与既有 `palette`/`inks` 注入完全同构，**L5 不破**（view 不持状态，game 不感知材质）。
- **玩法隔离**（四条守卫判据，见 §6.2）：命中测试、格几何、`hitGridCell`、关卡 `pattern`、
  `BEAD_PITCH`、时序与状态机**一律不读材质**。材质只影响 `RenderModel` 里图元的**数值与条数**。
- **生效时机**：下一帧自然生效（渲染每帧重建）。**不做**跨帧插值过渡。

### 3.3 图元预算与 LOD（与 ADR-0017 的关系必须显式化）

- 每个材质提供 `layerCost(beadCount)`（= `layers` 开关的静态求和），并在注册表里声明上限
  `MAX_EXTRA_LAYERS_PER_BEAD`。`§1.8` 基线表**按材质分列**，不再只有一个数。
- `ADR-0017` 的降档集扩展为「**降档集 = f(基础层集, 材质 layers)**」：新增的红线集合
  （底图 + 空格凹陷 + 中心孔，见 `bead-visual-style-spec §6`）对所有材质一致不砍。
- 反例警戒：**17 版画（hatch）**每珠 +4~8 条 ⇒ 156 格 ≈ **+624~1248 条/帧**，
  会**吞掉 ADR-0017 全部收益（现基线 1587/帧）** ⇒ 该风格在预算上归入"需先解降档才可考虑"，
  本架构不给它开例外。

## 4. 后果（Consequences）

### 4.1 正面

1. 新风格 = **加一行数据表**，`drawFilledBead` 单一代码路径不分支 ⇒ 17 套是 O(表数)，不是 O(分支积)。
2. **缺省即现状**：不传 `material` 时逐字等价 `BEAD_CARD`/`palette` 常量 ⇒ 引入过程可做到零视觉回归（可 diff 验证）。
3. 图元数可按材质静态求和 ⇒ `check:size` / `§1.8` / ADR-0017 三处口径继续可机检。
4. 材质与配色彻底解耦，兑现 §1.9.7「只能是材质主题、不能是配色主题」——**由类型与守卫判据保证**，
   而不是靠"大家记得别改 base"。
5. 与 `ADR-0016` 的品牌色板引用制无冲突：材质只碰系数，色仍来自关卡 `palette` + `paletteCodes`。

### 4.2 负面后果（**已知成本，不是风险**）

1. **一次性重构面不小**：要把 `BEAD_CARD` 约 20 个系数 + `palette.ts` 6 个混合常量从"模块级常量"
   变成"默认材质的字段"。所有引用点（含 `view-model` 的 `TRAY_BEAD_SIZE` 路径、scene-vfx 波浪/
   解环器、`denied-press`）都要跟着走参数 ⇒ **触碰现有 4 个测试文件的全部层序判据**。
2. **判据矩阵从 1 涨到 N**：`bead-render.test` 现在钉的是"12 条图元逐 kind 序列"这种**唯一真值**；
   材质可变后必须拆成两轨 —— ①对 `MATTE_INJECTED` 逐字相等（回归锁），②对其他材质满足**不变式**
   （红线层存在、层数 ≤ 声明上限、A5 不越格）。**第二类断言要新写**，不写就等于失去保护。
3. **可访问性实算每材质重跑**：软高光 α 下调与倒角对比变化会移动 B2「图形对珠面 ≥3:1」的实算值。
   现仓内**没有**这个实算工具（历史上靠 `temp/v15r3-theme.mjs` 一次性算过并发现 4 色打穿）。
   ⇒ 每加一个材质都得重跑，否则"只可下调"的护栏会在无声中打穿对比度地板。**这是真实欠账**。
4. **切换瞬间的视觉断裂**：不做过渡插值 ⇒ 结算/波浪进行中切材质会出现"半屏旧材质"一帧。
   选了简单，代价是小瑕疵。（若不可接受 → §5 触发项。）
5. **热路径分配预算收紧**：材质必须 frozen 单例查表；任何"运行期合成材质"（spread/merge）
   都违反 §2 ⇒ 以后想支持"用户自调滑块"级别的微调，本方案**不给免费路径**，需另立 ADR。
6. **meta 存档升版本**：`version 1→2` + 迁移 + 判据；老玩家存档需验证不破。
7. **`layers` 开关会诱导"新原语申请"**（珠光/玻璃的椭圆反射带最自然的表达是 ellipse）。
   本 ADR 禁止 ⇒ 只能用 `rect`+大圆角近似 ⇒ **部分风格的还原度被架构上限压住**（11 珠光、12 彩窗
   首当其冲）。这是有意的取舍：宁缺风格，不破"零资产 + 五原语"的地基。
8. **17 这个数字不可达**：按 §1.9.7 与预算约束，参数空间能表达的只有约 8–10 套
   （01/02/06/11/12/13/14/16/18/19 中经判据与预算过关者）。**"17 套可切换"是错误预期**，
   需要主理人向用户重新对齐（见 §7 未决问题 Q1）。

### 4.3 中性 / 待观察

- 真机帧率对不同 `layerCost` 的敏感度（`ADR-0017` 的 7403→5187 结论只在旧层集下测得）。
- 微抖动类风格（K7）在本架构下天然归 `layers` 之外的"坐标派生参数"，其确定性哈希成本待测。

## 5. 复评触发条件（Review Triggers）

1. 需要**新渲染原语**（真 ellipse / 渐变 / 模糊）才能表达某风格 ⇒ 触发框架层复评（连带 `§8` 渲染契约）。
2. 要做**用户可调的材质滑块**（非离散主题）⇒ §4.2-5 的免费路径不存在，需重新设计（含热路径分配）。
3. 任一材质实测使每帧图元超 `§1.8` 声明上限或真机掉帧 ⇒ 回到 ADR-0017 重谈降档集。
4. B2/对比度实算出现任何材质打穿 ⇒ 触发美术 + QA 联合复评，必要时收紧"只可下调"的界。
5. 要支持**配色主题**（换 base）⇒ 与本 ADR 边界冲突，须另立 ADR 并同时重开 A1 色相通道与 §1.9.2 十色间距判据。
6. 决定引入外部贴图 ⇒ 直接推翻 §1.2 前提，`ADR-0004` 包体口径需复评。

## 6. 实现边界与测试脚手架（工程侧，不含美术/UX 文档）

### 6.1 框架已有 vs 增量

| 能力 | 已有 | 需新增 |
|---|---|---|
参数注入到渲染 | ✅ `palette` / `inks` 已按参传入 | `material` 同一路加一个形参（含 `drawEmptySocket`） |
默认值=现状 | ✅ 常量俱在 | 把常量搬进 `MATTE_INJECTED` 记录，**不改任何数值** |
切换入口与持久化 | ✅ `SaveManager` + `meta` 侧车 | `BeadsMeta.materialId` + 版本迁移；shell 层一个选择入口（UX 待位） |
图元预算 | ✅ `§1.8` 表 + `check:size` | `layerCost()` 与按材质分列基线 |
LOD | ✅ ADR-0017 两态通道 | 降档集 = f(基础层, 材质 layers) |
确定性哈希（微抖动风格） | ✅ `createRng(seed)` | **格坐标纯哈希**（不消耗 rng draw 序列）——若启用 K7 |

### 6.2 "不影响玩法"的可验证定义（必须落为判据，不接受口头保证）

1. **几何不变**：同一关卡、同一材质下，`hitGridCell` / `gridLayoutFor` / `TOUCH_MIN` 判定结果全等；
   材质的 `radiusRatio`/`layers` **不参与**任何命中与格尺寸计算。
2. **状态机不变**：材质 id 变更前后，`phase`、`snapshot` 除渲染无关字段外逐字段相等。
3. **时序不变**：`SELECT_LIFT_MS`、`FILL_POP_*`、`SOLVER_*` 等与材质无耦合（类型上材质不含时长字段）。
4. **确定性与 L4 合规**：全仓 `Math.random` 零命中；同 seed 同关卡 ⇒ `RenderModel` 字节级稳定。
5. **L5 合规**：材质在 game/状态层**只读**，`buildRenderModel` 不写它。
6. **回归锁**：`MATTE_INJECTED` 与重构前的 `RenderModel` **逐条图元相等**（一次性对拍，可留作永久判据）。

### 6.3 Story 拆分草案（垂直切片；验收只引 GDD/规格 §8，此处不写验收正文）

- **S1｜材质通道打通（零视觉变更）**：`BeadMaterial` 类型 + `MATTE_INJECTED` = 现值 + 注入形参 +
  §6.2-6 回归锁判据。**交付即"什么都没变"**，把重构风险与风格风险分离。
- **S2｜注册表 + 持久化 + 切换生效**：`BEAD_MATERIALS`、`BeadsMeta.materialId`（v1→2 迁移 + 回落）、
  shell 读取并逐帧传入。此步只做"能换"，不做第二套材质。
- **S3｜首个第二材质落地（候选 02 亮面烤漆 或 06 珐琅金属）**：一张参数表 + `layerCost` +
  `§1.8` 分列基线 + a11y 实算重跑。
- **S4｜LOD 与预算联动**：降档集 f(基础层, layers) + 上限守卫 + 真机帧率验证（依赖 ADR-0017 复验）。

> ⚠ 环境阻塞（如实登记）：`build:wx` / Cocos 真机构建链**尚未接入**，S4 的"真机帧率"这一半
> 当前**无法验证**；本 ADR 接受以 `check:size` + 帧内图元计数 + 浏览器 harness 作为代理指标，
> 真机数据到位前 S4 不得宣布完成。

## 7. 未决问题（交主理人 → 用户拍板）

- **Q1** 「17 套」的期望需重对齐：本架构在既有裁定与预算下现实可表达约 **8–10 套**（§4.2-8）。
  选项：**(a)** 接受 8–10 套目标；**(b)** 放宽 §1.9.7 允许新原语（动框架契约）；
  **(c)** 允许外部贴图（动零资产支柱与包体）。**我建议 (a)**。
