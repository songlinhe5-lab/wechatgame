## 1. 上下文（Context）

- facet-4 现役 **珠体 6 命令 + B0 底图 1 = 每格 7 / 命令级 0 α**；若美术按参考图风格把效果加满
  （估算约 17 层 / 6 α，**无承载代码 ⇒ 属估算，需先有配方实现才准出数**），32×32 满盘全矢量
  ≈ 17,400 命令 —— 低端机不可行；且 C7 命令上限（7）使矢量路线与美术层扩展根本对立。
- 缩放已上线**连续捏合**（非离散档，`CAMERA_ZOOM_MIN/MAX` = 0.2/2.0 绝对倍率），矢量每帧全量重算路径；
  位图放大软化需工程对策。低倍段靠 `view-model::drawGrid` 的**格心可视窗剔除**（丁-3 免 clip）保证 1024 格
  全量只在低 zoom 段发生 —— 那里每格面积极小、成本重心在命令提交/展平，正对 H-CPU 项。
- 珠色真源 = 关卡数据 `paletteHex`（任意 hex，beads-studio 入关写入）⇒ 设计期无法枚举全部颜色。
- 平台：wx 小游戏（Canvas2D 渲染器）+ 浏览器 harness；Cocos 端 `Graphics` **不支持绘制 image**。

## 2. 备选方案（Alternatives）

| 方案 | 事实性对比 | 结论 |
|---|---|---|
| A 全矢量 + 抬 C7 上限 | 16 层风格 ≈ 17 cmd/珠；1024 格 ≈ 17,400 cmd/帧；低端机 >33ms（估算，待测试 7 实证） | 否：成本与美术层数线性绑定，路线死锁 |
| B 引擎层 clip 图元 | Canvas2D 有 `clip()`；Cocos `Graphics` **无裁剪能力**（stencil 或回几何）⇒ 两端口径必分裂 | 否：破坏 ADR-0002 渲染器可替换契约 |
| C 灰度模板 + 运行时 tint | 暗端 `mix(base,−k)` = 乘法可精确复刻；亮端 `mix(base,+k)` **向白仿射**，纯乘法 tint 不可表达 ⇒ 需双通道模板或自定义 shader | `~~否：色彩语义（§1.9 端点族）无法单 tint 复刻，复杂度最高~~` ⇒ **2026-09-28 重开**：否因中的出路「双通道模板」经调研有封闭解（out = base·d + (1−base)·l 对端点族逐层精确），另立 **ADR-0028** 评估；本表按当时口径留档 |
| D 设计期预产纹理资产 | 任意 paletteHex 无法穷举；全量预产 ≈ 1–2MB PNG 吃主包 ≤4MB 红线大半 | `~~否：色板运行时性决定了烘焙必须是运行时能力~~` ⇒ **v0.7 改判（ADR-0027）**：预产资产**与**运行时能力**共存**（brand 集走文件、任意色走运行时烘）；全量穷举仍不可行，故运行时臂⛔ 不得删除 |
| **E 运行时烘焙 + 两级 LRU（本 ADR）** | 命令数与美术层数**解耦**（烘什么都 1 命令/格）；静止态精确尺寸零重采样 | **采纳** |

## 3. 决定（Decision）

采用**运行时烘焙**：矢量风格代码（facet-4 系层集）保持唯一真源，作为烘焙配方；运行时按 key
首次命中时用 offscreen canvas 复用 Canvas2D 矢量回放器烘成纹理，进 L1 内存 LRU → L2 磁盘 LRU
（wx `USER_DATA_PATH` + manifest + `bakeSchemaVersion` 整体失效）。渲染层新增 **`blit` 命令**
（v0.6 定名，`~~image~~` 已改齐；框架接口改造另立 **ADR-0026**，未立 ⇒ 开工前置未满足），
未命中/烘焙中一律走现有矢量回放（逐字节 = 现役 facet-4）。

含四项子决议（详细规则正本 = §13 v0.6）：

- **DEC-1 纹理平面（v0.6 收窄 → v0.7 扩类）**：✅ ~~**只烘「单珠」一类**~~ ⇒ **两类：单珠 + 整格底（B0 底图 + B1 凹槽）**（key 另需带**目标色**维 ⇒ 整格底 per-color）
  ⇒ 原「五类」中的**锁定与 `(c,t)` 与单关图集仍不做**（N3）；接触阴影仍不烘（N4）。
  ⇒ 逐格代价：已填格 **7 → 3**（整格底 1 + `blit` 1 + 孔底 1）；空格 **5 → 1/2**（[待落码实测]）；**v0.6 的「空盘帧零改善」声明作废**。
  ⚠ 副作用（正面）：单珠平面下动画期**不需切分层**——落座回弹/波浪的 `scale` 只动珠体族（B0 不参与 = 既有层序
  死结论），blit 尺寸随包络即可，原「就位整格在 fill_pop 期强制走分层」那套机制随 N1 一并作废。
  ⚠ **小豆档 `hideHole` 走矢量臂**（不另立无孔变体 ⇒ 零内存增量；可否决，触发条件见 §5-6）。
- **DEC-2 缩放策略**：烘焙基准 = **珠体边长** × `CAMERA_ZOOM_MAX`(2.0) × min(物理/设计比例, `BAKE_DPR_CAP`) +
  1dip 外圈防截边 ⇒ 满豆恒等档 `26×2.0×2 + 外圈 ≈ 112 px/纹理`；恒 **≥ 显示尺寸** ⇒ 运行时恒 ≤1:1 或缩小；
  捏合中用最近档 + 运动掩蔽。**mip 链档数与「每档矢量重烘」本 ADR 不定案**（归
  `beads/design/proposals/zoom-bake-mip-validation.md` 的 V/S1/S2/M/M+ 五路径，⛔ 预测当已验）。
- **DEC-3 孔径裁定收窄**（v0.6 采纳，因用户裁定③「烘孔内壁 + live 孔底」而成立；⛔ 八裁随整案转历史归档——tint 制下对应物 = 孔边线入 mask、pit 仍 live，见 ADR-0028 / §13.1 B15）：「孔径整数、2 的倍数」
  （2026-09-26 拍板）**适用范围收窄至基准尺寸烘焙**（设计档恒等语义保留）；连续缩放路径孔半径连续缩放，
  程序化孔底圆半径 = 烘焙孔径 × 当前缩放 + 0.5px 盖缝余量（修 T2 的跳变露底）。
  ⚠ **这不是纯代码改动**：连带 `games/beads/art/cell-standard.md` J4 及其 §4 变更纪律五件套、
  `tests/bead-cell-standard.test.ts`（原「两档通式」）断言改写、`bead-render`/`bead-style-ledger`/`scene-vfx`
  三处孔半径期望同步、**封箱腿 3（珠体族三键）必红 ⇒ 走 `§K.5.1` 复评归因（⛔ 禁自更新，K-082）**。
  清单正本 = `§13.11 L-1…L-6`。若 T2 修不掉 ⇒ 本条整体作废、退回「孔整枚 live」并重开裁定。
- **DEC-4 分辨率分档（v0.6 作废）**：`~~高端 32dip×2 = 64px/格；低端 23dip/格~~` ⇒ **与 DEC-2 公式互斥、废弃**。
  废因：两者在物理/设计比例 >1 的机型（1080p ≈1.44、iPhone dpr3 ≈1.56）于 zoom>1 段进入**放大区**，
  直接违反 §4 缩放红线（⛔ 运行时放大烘焙纹理）；其「运行时恒 ≤1:1 至 zoom 2.0」的断言仅在比例 ≤1 的机器上成立。
  低端机的内存控制改由 **`BAKE_DPR_CAP` 实测自适应降档（2 → 1.5）** 表达。
  保留的两条仍有用的口径：**孔——取整孔径向内 1dip 做孔内投影**（落孔径内）；**珠——纹理向外多烘 1dip**
  （兼防截边的透明边）。

## 4. 后果（Consequences）

### 4.1 正面
- 命令数与美术层数**解耦**：美术 6 层或 20 层，运行时**已填格固定 3 命令**（底图 + `blit` + 孔底）。
- 32×32 满盘（1024 可填格，全在带内上界）**四帧账**（正本 = `§13.12`；⛔ 不得只报好看那一帧）：
  空盘 5,120 → ~~**5,120（零改善，烘焙不覆盖空格）**~~ ⇒ **v0.7：N2 生效后本帧首次有杠杆，真数 [待落码实测]**；
  半盘 6,144 → 4,096（−33%）；终局满盘 7,168 → **3,072（−57%）**；
  错位为主与终局同价 + 逐抬起格 1 条（连通组实测最大 62 颗）。
- 动画帧（落座回弹/波浪）在单珠平面下**与静止同价**（blit 尺寸随包络，前提 `zoom × scale ≤ CAMERA_ZOOM_MAX`）。
- 缩放画质：静止态精确尺寸零重采样；放大路径被基准尺寸封死；缩小段的 mip 方案待验（不列入正面收益）。
- 门禁兼容：C3/C12/C7 继续跑在**矢量配方**上（烘焙只是配料的编译产物），风格门禁体系零改动。
  ⚠ **v0.7 修正**：「零改动」仅对**运行时烘**成立；改为位图皮肤资产后，**双指标门禁降级为「配方复杂度上限」**，
  且 **C12「统计域 = 珠面族图元」在位图下不再可执行**（需重设计）⇒ 详见 ADR-0027 DEC-2 / §4.2。
- α 口径：已填格 = **命令级 0 α**；⛔ 不得写成「0 次半透明混合」（Canvas2D `drawImage` 仍走 source-over，
  GPU 端是否真关混合由 T4 帧时间实测判，同 K-037 家族）。

### 4.2 负面（已知成本，非风险）
- **Cocos 端本期不覆盖**：`Graphics` 不能画 image ⇒ Sprite 节点池改造是独立立项（约 1–2 story）；
  本 ADR 范围 = wx Canvas 渲染器 + harness SVG 导出。Cocos 端在改造完成前维持矢量路径。
- **L1 内存（v0.6 随平面重算 → v0.7 再重算）**：单珠纹理 112²×4 B ≈ 50 KB，含逐档 mip ×4/3 ≈ **66.8 KB/色**
  ⇒ 16 色 ≈ 1.1 MB、**35 色 ≈ 2.3 MB** ⇒ 预算 `~~8 MB~~`（属整格平面，本平面不成立）改定 `~~[暂定 2.5 MB]~~`。
  ⚠ **v0.7：平面扩为双张（单珠 + 整格底）⇒ 同基准 ≈133.6 KB/色 ⇒ 35 色 ≈ 4.7 MB**，预算真数回到 **[待定]**
  （ADR-0027 DEC-7 两条出路）；2.5/2.3/8 三个旧数⛔ 不得再被引用。
  并保留 `wx.onMemoryWarning` → 降 `BAKE_DPR_CAP` 1.5 的自适应降档（⇒ 字节 ×0.56）。低端机（720p，
  比例 ≈0.96）实测仍为 T5 验证项，⛔ 纸面判。
- **新增失效纪律**：矢量配方任何视觉变更必须同步 `bakeSchemaVersion` 递增（封箱测试同批断言），
  漏改 = 线上旧皮——这是对现有封箱流程的新增义务。
- **6 项验证义务**（v0.6 从 12 项收缩；正本 = `§13.13`，载体归 `zoom-bake-mip-validation.md` 一份）：
  T1 静态等价 ΔE、T2 孔对齐、T3 分层路径开销（含**空盘帧零改善声明**）、T4 帧时间 p95（C ≥ A×1.5 否则整体
  回退）、T5 内存、T6 失效与兜底 + 烘焙耗时。**随整格平面作废的四条**：路径切换跳变、拼缝、
  `(c,t)` 组合数、孔底挖空；接触阴影未烘 ⇒ 阴影 α 上限也退出本轮。
- **孔径收窄的判据连锁**（新登记）：`cell-standard.md` J4 需走 §4 变更纪律五件套 + `bead-cell-standard.test.ts`
  断言改写 + 三处孔半径期望同步 + **封箱腿 3 必红（走 `§K.5.1` 复评归因）** ⇒ 这条成本不写在代码里、
  只写在标准与 QA 档，⛔ 不得归入「微改动」（正本 = `§13.11 L-1…L-6`）。
- **烘焙配方依赖未归位的层集**：现役工作树 = `facet-4` 6 命令且**零描边**（T-215 三轮改动只活在
  `temp/bead-relief-compare/wip-215-full-backup.patch`，主表已写「已落」）⇒ 先烘后归位 = 把用户看图
  已判不合格的形态烘进缓存，且每次命中都在复现。
- **回退栈深度**：烘焙失败 → 矢量回退 → 若 T4 整体不通过 → 全量回退矢量并限美术层 ≤7
  （判定顺序正本 = `bead-visual-style-spec §13.13`；`~~§13 六~~` 的旧指针随 v0.6 换源）。

### 4.3 中性 / 待观察

## 6. 追记（2026-09-28 · WXG-T-221 三批 · 行业调研 + ADR-0028 开题）

三条增量登记（调研正文 = ADR-0028 §1–§2，不在此重复）：

1. **备选 C 重开**：行业对「平涂参数化变体」的标准解是灰度 mask × 着色（Unity 官方移动指南原话背书灰度+tint；Phaser v4 GradientMap / GameMaker LUT shader / Defold gradient map 均为在役先例）。本 ADR §2 备选 C 的否因（单 tint 不可表达亮端）已被「双通道模板」的数学封闭解推翻（暗端 multiply 精确 = mix(−k)；亮端 screen 精确 = mix(+k)；且每层只居其一 ⇒ 两路合成无交叉误差）⇒ 见 **ADR-0028**。
2. **预烘文件路线的独占红利 = 压缩纹理**（影响 §2 备选 D / DEC-1 读序的竞争力评估）：运行时烘出来的是 RGBA8888，吃不到微信基础库 2.5.0+ 压缩纹理（iOS pvr / Android etc1，官方工具实测降运行时内存 50–70%）⇒ 若 T5 内存不达而回退投放档，投放侧还有一张本 ADR 未计分的牌（补记入 ADR-0027 DEC-6 兜底分支）。
3. **离屏 canvas 物理像素陷阱**（wx 生态在案多发，社区原话「离屏画布是物理像素尺寸，blit 回主画布必须显式指定逻辑尺寸，否则整图被放大 dpr 倍发糊」）⇒ DEC-2 基准公式落地时必验：blit 目标尺寸 = **dp 口径**，⛔ 拿 texel 当 CSS px；此坑与本 ADR WXG-T-220 实施进展注中的烘焙臂直接相关，列入 T6 验证批断言。
