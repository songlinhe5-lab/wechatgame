# ADR-0017 — 大盘 zoom 自适应 LOD：按视图缩放降珠层（通道与红线；层集由 art 冻结）

- **状态**：**Proposed（草案待裁）** —— 本文只立**工程通道、触发策略与不可降红线**；**具体砍哪几层由 art 冻结**（`art-bible`/`assets-spec` 是美术真源），阈值亦留 `[待确认]`（待真机）。
- **日期**：2026-09-20
- **关联**：`systems-index §3.3` v1.34（盘面上限 13/12 → 29/29，风险 1 由此而来）/ ADR-0015（缩放平移，丁-3「布局即相机」）/ ADR-0016（调色板三重编码 —— 本 ADR 的红线与之同源）/ `assets-spec §1.1`（十层卡 + L11 垫）/ `assets-spec §1.6.9`（既有 LOD 判例）/ 任务 `WXG-T-181`
- **上位**：用户 2026-09-20「zoom 自适应 LOD 立项（风险 1）」+ 提出三种形态方向（standard29 / 小盘单图或 2×2 拼图 / 异形）。

## 1. 上下文（Context）

### 1.1 直接动因

`GRID_MAX_COLS/ROWS` 13/12 → **29/29**（`systems-index §3.3` v1.34，WXG-T-180）后，静态图元从 ≈1560 涨到 **≈8410（5.4×）**，并被 §3.3 v1.34 列为**风险 1（最大）**。该风险的处置**前置项就是本文**。

### 1.2 三种形态（用户提出；本 ADR 的验收场景）

| 模式 | 说明 | 格数 | 静态图元（×11 层/珠） |
|---|---|---|---|
| **A** | standard29 单盘 | 841 | **9251** |
| **B1** | small18 单图 | 324 | 3564 |
| **B2** | small18 **2×2 拼图**（4 盘） | 1296 | **14256** ⚠️ 比 standard29 还高 |
| **B3** | small16 单图 / 2×2 | 256 / 1024 | 2816 / 11264 |
| **B4** | small14 单图 / 2×2 | 196 / 784 | 2156 / 8624 |
| **C** | 异形（29 盘内，形状内 ~650~700） | ~650 | ~7150 |

**两条由表直接得出的结论（本文最重要的判断）**：

1. **小盘"单图"根本不需要 LOD**（2156~3564，与现 156 珠的 1810 同量级）—— LOD 只对 **standard29 / 异形 / 2×2 拼图**三种形态必需。
2. **2×2 拼图不是"更省"，而是更贵** —— small18 的 2×2 = 1296 格 > standard29 的 841 ⇒ **拼图模式对 LOD 的需求最高**，不能因为"每块小"就豁免。

### 1.3 现状：有 LOD 判例，但**没有本 ADR 要的通道**

- 已有：`DISSOLVE_LOD_ALPHA = 0.60` + `DISSOLVE_LOD_LAYERS = 4`（层集 = **L1 + L2 + L3 + L5**）—— 属**消除溶解动画**期降层（`assets-spec §1.6.9`，规格保留、**本轮不预埋**）；`WAVE_LOD_LAYERS = 7` 属过关波浪按列降层。
- **没有**：「按**视图缩放**降低**静态**珠层」的通道 —— 这正是 29×29 能装进去、却不一定能跑动的原因。

### 1.4 不可降红线（与 ADR-0016 丙案同源）

`filled` 珠是 **11 层**（十层卡 + **L11 目标色垫**）。其中两层**不得因性能砍掉**：

- **L11 目标色垫** = 谜面载体（B′ 垫色显缝；砍掉 ⇒ 玩家读不出"这格该是什么色" ⇒ **可解性受损**）；
- **L5 符号** = 可访问性**三重编码**（色 + 符号 + 明度）中的符号维（砍掉 ⇒ 色盲玩家失去唯一区分通道 ⇒ 与 `accessibility` D1/D2 及 ADR-0016 丙案的负面后果**同源**）。

> 一句话：**LOD 砍的是"质感层"，不是"信息层"**。

## 2. 备选方案（Alternatives）

### 2.1 甲：视图缩放驱动（zoom 档位 → 层集）—— **本文推荐为主干**

按当前 `camera.zoom` 落档：近看满层、远看降层。契合 ADR-0015 丁-3「布局即相机」—— 缩放本就是既有状态。

### 2.2 乙：视口裁剪（只画可见格）—— **正交且应先做（本文推荐先落地）**

大盘缩小后，屏幕外仍有大量格在被绘制 ⇒ 先做视口裁剪是**纯收益**（不改观感、所有模式都受益）。**与甲不冲突，应并列做。**

### 2.3 丙：整盘一律降（不按 zoom）

实现最简，但放大近看时也糊 ⇒ 牺牲大盘的核心价值（精细图案）。**不推荐单独用**，可作低端设备的回退阀。

### 2.4 丁：同色连通块合并绘制

把同色相连格合成单条 path ⇒ 图元可降一个量级。收益最大，但改动大、且会与"逐珠动画/选中"打架 ⇒ **记录为远期方向，本轮不做**。

## 3. 决定（Decision）

- **推荐组合 = 乙（视口裁剪，先落地）+ 甲（zoom 档位降层，主干）**；丙作为**低端设备/低帧率回退阀**；丁仅登记、不做。
- **层集由 art 冻结**，本文只给建议档（**均含 L11 + L5 两条红线**）：

| 建议档 | 触发（阈值 `[待确认]`） | 建议层集 | 每珠图元 |
|---|---|---|---|
| 满层 | zoom ≥ 0.9 | 11 层（现状） | 11 |
| 中档 | 0.5 ≤ zoom < 0.9 | L11 + L1 + L2 + L3 + L3b + L5 | 6 |
| 低档 | zoom < 0.5 | L11 + L1 + L2 + L3 + L5 | 5 |

- **回退阀**：`reduceMotion` 开启，或运行时帧率低于阈值 ⇒ 强制低档（不新增冻结值，阈值 `[待确认]`）。
- **滞回（hysteresis）必需**：档位切换要留死区，否则在阈值附近缩放会"跳变闪烁"（且可能触 `accessibility` D2 闪烁红线）。
- **本文不引入任何 `systems-index §3` 新冻结值**（阈值均为占位，待 art / playtest）。

## 4. 后果（Consequences）

### 4.1 正面

- 让 standard29 / 异形 / 2×2 拼图三种形态从"能装配"走向"**可能可玩**"（风险 1 的唯一处置路径）。
- 视口裁剪对所有形态都是纯收益，且风险极低。
- 红线明确 ⇒ 不会出现"为了帧率把符号/垫砍了"的静默退化。

### 4.2 负面（已知成本，白纸黑字）

- **近看/远看观感差异需 playtest**：降层后大盘"远看是色块、近看才出质感"，是否被玩家读作"变丑"未知。
- **切换跳变**：未做滞回会闪烁（§3 已列为必需项）。
- **层集未定 ⇒ 本文不能声称"性能已解决"**：图元降幅取决于 art 最终砍几层（建议档 11→5 ⇒ 841 珠从 9251 降到 ~4205，**仍未达小盘单图量级**）。

### 4.3 中性 / 待观察

- 2×2 拼图若采纳，其 1296 格**即使低档也有 ~6480 图元** ⇒ 可能仍需视口裁剪 + 分块绘制，需单独验证。

## 5. 复评触发条件（Review Triggers）

1. art 冻结层集 ⇒ 阈值可定档，本文建议档作废/更新。
2. **真机帧率实测**（29×29 + 三种形态）⇒ 若低档仍不达标 ⇒ 启动丁（合并绘制）评估。
3. playtest 反馈"远看变丑" ⇒ 上调触发阈值（更早满层）或改中档层集。
4. 若 2×2 拼图成为主玩法 ⇒ 需补"分块/分盘"的绘制与 LOD 策略（本文未覆盖）。
