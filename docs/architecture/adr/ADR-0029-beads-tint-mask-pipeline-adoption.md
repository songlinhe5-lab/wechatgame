## 1. 上下文（Context）

### 1.1 要解决的问题

WXG-T-226 的目标是把已定稿的 tint mask（有孔 v1.1 / 无孔 v1.0-holeless）接入**正式管线**：`drawFilledBead` / `drawEmptySocket` 走 tint 路径、`makeBeadRecipe` / `makeCellRecipe` 改产 **d/l mask**（非位图成品）。方案件给出三条工程事实：

1. **Cocos 侧无烘焙载体**：`Graphics` 不能画 image，框架 `blit` 在 Cocos 静默跳过（`cocos-renderer.ts` `case 'blit'`）；
2. **Canvas2D 两路合成不通**：`drawImage` 只吃 RGB，做不出 `base·d + (1−base)·l` 的两通道合成 ⇒ 必须 tint + mask 两张纹理；
3. **mask 生成须三层**：spec（资产规格）+ 场计算（层集 → d/l）+ adapter（按端口渲染）。

### 1.2 为什么载体不能一次拍死

方案件原推荐「整盘单图元 + effect」（+1 draw call）。**2026-09-29 的 Cocos 探针进展已推翻「无载体」前提**（`tint-mask.effect` / `bead-field.effect` + 4 张 128px 贴图 + `tint-probe.scene` 已接线，`Sprite` + `customMaterial` 通路实证成立），但**没有解决规模问题**：

| 载体形态 | draw call | 代价 |
|---|---|---|
| 整盘单图元（每帧 CPU 合成整盘一张） | +1 | 29×29 盘按 128px/格 = 3712² RGBA ≈ **55 MB 显存**（方案件未算此项） |
| Sprite 池（每格一枚 Sprite） | +N | 29×29 = **841 draw call** ⇒ 移动端不可接受 |
| 分块带状合成（每 8 行一条 128×1024） | ≈4 | 需新写运行时合成层，工作量最大 |

⚠ **本仓已有判据纪律**：`ADR-0028 §5` 的 **T3'（命令带宽账）/ T4'（低端机帧时间）本身就需要真机**，而 T2'–T4' 至今 `DEFERRED — 需真机`。⇒ **在没有真机帧时间与显存数据时选载体 = 无数据拍**（K-051 族：纸面推论须实测复算）。

## 3. 决定（Decision）

### DEC-1 · 载体：本批 = 命令层 + Canvas2D/harness；Cocos 生产仍走矢量
- 本批交付面：`bake-recipes` 改产 d/l mask（spec + 场计算）+ 运行时双臂注入（命中 ⇒ tint 路径；未命中 ⇒ 矢量臂**逐字节不变**）+ Canvas2D/harness 通道可跑。
- Cocos 生产通道**不接** tint（`Graphics` 无 image 能力，见 1.1 事实 1）。
- ⛔ **载体形态留待真机数据**：拿到 T3'（命令带宽）/ T4'（低端机帧时间）/ 显存实测后，再在 ① 整盘单图元（含降采样或分块策略）与 ③ 分块带状之间裁决；**不得在无数据时拍**。

### DEC-2 · 孔底：接受定稿 v1.1（与 studio 定稿同构）
- tint 臂下**孔区真透** ⇒ 透出下层 **B0 tile**（本格 `edge = mix(base, −0.30)` = 0.70×目标色），与 studio 定稿 v1.1 同构。
- 托盘珠的孔在 tint 臂下同样透明（不再有 live `pit` 圆）。
- **矢量臂保持不变**（`pit` circle 仍在）⇒ 这是**渲染臂差异**，**不是** §3 冻结常量变更，`systems-index §3` 本次不动。
- ⛔ **判据欠账（交 QA）**：K3「孔底透出目标色」的**现役判据文本**在 tint 臂下不再逐字成立（透出的是 B0 tile 的 `edge` 而非 `pit`）⇒ 由 WXG-T-230 / T-228 判据族改写，**本 ADR 不代改判据**。

### DEC-3 · 生成器真源：丙·渐进（不放弃 DEC-4 同源）
- 现状：studio 服务端**跑定稿 py** 出图（单一真源、零移植）——保留该链路用于**资产产出**。
- 玩家端 mask 生成走 **TS 场计算**（spec 化后），并加 `mask:diff` 对拍门禁（py vs TS 逐字节 / 容差内一致）；**对拍绿之前 TS 不得成为唯一真源**。
- ⛔ 禁止「手写第二份系数」：mask 系数只有一处真源（定稿 py 的冻结口径块），TS 侧为 spec 化实现。

### DEC-4 · 档位与 dpr：128px 定档 + 高倍段回矢量（⛔ 仍禁运行时放大）
- 128px 是**当前唯一**烘焙档（`BAKE_CANONICAL_SIZE` / 定稿脚本 128 输出）。
- 高倍段（`zoom > LOD 回矢量阈值`）**回退矢量臂** ⇒ 满足 `control-manifest §19`「⛔ 运行时不得放大烘焙纹理」。
- 阈值 `[待真机]`：需真机测出「128px 在何 zoom 以上肉眼可辨糊」再定值 ⇒ **本批不落数值**，先落「回退机制存在 + 阈值可配」。
- 192/256 档**待真机数据**后再议（不是本批范围）。

### DEC-5 · 白名单与回退：未命中一律矢量回退
- `maskId = 白名单(kind, gauge, styleId)` 返回 `undefined` ⇒ 矢量臂（逐字节 = 今日）。
- 白名单**显式化**：当前只有 `facet-4` 有 mask；⛔ 不得给未定稿风格偷烘 mask（同屏 tint/矢量混用观感由美术评，`[待真机]`）。

### DEC-6 · 灰度 mask 编码沿用 ADR-0028 §2.1（WXG-T-229 已落盘的实测定稿）
- `R = d / G = l / B = 形状 / A = 255`（A 恒满幅免疫 Trim）；合成 `rgb = base·d + (1−base)·l`、`a = B/255`，预乘 α。
- 本 ADR 只承载**接入决策**，不重开编码之争；若编码变更须新 ADR。

## 4. 后果（Consequences）

**正面**
- P0 关键路径（T-226）**解除 Q1 阻塞**：命令层与 Canvas2D 侧可立即落码，T1'（静态等价）可在 harness 逼近。
- 载体决策被推到**有数据**的位置，避免 55 MB 显存或 841 draw call 这类未实测的坑。

**负面 / 代价（诚实登记）**
- **生产通道（Cocos）本批无收益** ⇒ tint 的性能/包体收益在玩家侧 = 0，直到载体落地。
- 本批**不解决** `check:size` SKIP 与包体守卫无牙齿（K-089）⇒ 仍不得向主包投放 mask 资产。
- Q2 ①使 tint 臂与矢量臂在**孔底**上产生**观感差异**（真透 vs live 坑底）⇒ 两臂观感一致性待 T1' 与真机评。
- `TC-TINT` 族在 tint 臂落码前多为「待执行（预期红基线）」⇒ G 门在本批**不会转绿**。

**零影响**
- 矢量臂逐字节不变（V-5）⇒ 未注入 tint 运行时时的行为与产物**完全不变**（sealing 腿 1/3 期望成立）。
- 冻结常量与 `systems-index §3` **本次不动**（DEC-2 已说明为何不动）。

## 6. 复评触发条件（Review Triggers）

1. **T3'/T4' 真机数据到位**（命令带宽账 / 低端机帧时间）或**显存实测** ⇒ 触发 DEC-1 载体形态裁决（① vs ③）。
2. **T1' 静态等价不过**（整珠平均 ΔE ≥ 2 或孔边高光 ΔE ≥ 5）⇒ 回到 §2 重开编码/档位。
3. **真机测出 128px 可接受上限 zoom** ⇒ 触发 DEC-4 阈值定值；若上限低于 `ZOOM_TIP_MIN` 一档 ⇒ 重开档位（192/256）。
4. **palette 注入需求出现**（品牌盘 > 10 色）⇒ 触发白名单与 mask 体积预算重算。
5. **`blit` 在 Cocos 获得 image 能力**（引擎升级或改用 Sprite 承载）⇒ 触发 DEC-1 重开。
