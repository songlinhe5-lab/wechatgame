## 1. 目标

用一份**版本化本地存档**承载"进度 + 成绩 + 设置"三类状态：下次启动直接续进、星级与冲刺最佳分留痕、音乐音效记忆；任何损坏/越界/高版本数据都**安全降级、绝不中断启动**。

## 2. 机制

### 2.1 键与版本（代码所有权，本篇只提案语义）

- 键名：`wxgame.beads.save.v1`（architecture-beads §2 已定；**归代码**，`v1` 后缀即版本号——版本演进通过新键 + 一次性迁移实现，不改旧键）。
- 版本纪律：`version` 字段为**存档自描述**；SaveManager 加载时：`version ≤ 当前` → 逐级迁移至当前；`version > 当前`（来自更高版本 App）→ **降级处理**（见 §2.4）；校验失败/解析异常 → 降级，**零异常外泄**（core-loop §2.1 BOOT 降级边界）。

### 2.4 降级矩阵（沿用 S1 §8-10 判据，逐条落字段）

| 异常 | 处理 |
|---|---|
| 解析失败 / 非对象 / `version` 缺失 | 全档弃用 → 出厂默认（runs=0 → 进 L1） |
| `version > 1`（或未来 >1.1） | 保留可读字段、未知字段丢弃 → 按当前版本默认补齐 → **照常启动**（高版本档不锁死旧包） |
| `unlockedLevel` 越界（<1 或 >`DEMO_LEVEL_COUNT`） | 钳到 1（沿 breakout 判例"安全降级优先于报错"） |
| `stars` 长度不符 / 含非 1–3 值 | 逐项钳正：**按前缀搬运**（见下方 v1.2 条）——短于关卡数则缺位补 0，长于关卡数则截断；**非数组**（缺失 / 类型错）仍重置全 0；单值越界钳 0。**⚠ v1.3 起本行适用域收窄 = 仅 §2.6.5「无身份旧档一次性入口」那一趟**；终态读档不再有「长度不符」这个概念（新档不靠长度对位），失配走下方 v1.3 四行；非数字单值钳 0 的口径**逐字不变** |
| `settings` 缺字段 | 单字段默认 false，不弃整档 |

#### 2.6.1 玩家可见语义（四条，逐条可转 QA 陈述）

1. **每个大关各自持有其全部小关的历史最高星**——「这一关是几星」的答案只取决于「它是哪一关」，⛔ 取决于「它是全表第几关 / 数组第几位」。
2. **推进位是两层结构**：玩家走到**哪个大关**（章间）+ 该大关内**走到哪一关**（章内）。两个轴各自都不可省：只有章内序 ⇒ 跨章歧义；只有章 ⇒ 无法表达「本章推平到第几关」。
3. **推进门票 = 本章全通关（每关 ≥1★）∧ 累计星 ≥ 门槛**（§3.7 v1.79 改判 / R7 v0.5）：~~推进门票 = 本大关全部小关 3★~~（**⚠ v1.3-R5 改判（WXG-T-346，用户 2026-10-22 拍板 A）**；旧句按 **K-053** 留档）。门槛 = **满星容量 − floor(关数 × 2 / 3)**，关数派生、⛔ 落档：9 关 ⇒ **21★**、6 关 ⇒ 14★、3 关 ⇒ 7★；**1–2 关短章 ⇒ 门槛 = 关数**（= 只要求全通关）。判据源的寻址轴不变（章内每关身份引用，不再是「下标 ∩ 区间」）；大关内小关解锁仍线性（过一开一）。**三条不变量**：① **全通关是独立前提**（累计星够但有一关 0★ ⇒ 不开；专防「7 关满星 + 2 关没打 = 21★」跳关）；② **逐章判定**（开第 N 大关只看第 N−1 章，⛔ 跨章累计总分，与 `unlockedLevel` 的位置语义无冲突）；③ 门票达成态**不落档**（I5，纯函数实时归约）。**v1.3 同批补裁（答工程侧 ADR-0034 §7-Q5，逐字保留）：归约集合 = 本章清单内的每一个槽，⛔ 无豁免——boss 收尾关也是小关之一（定义源 = `meta-ui §2.7` 「大关 = 一组题材关卡 + boss 关收尾」）；教学关不特判**（同向判例 = §3.7 v1.78 已把选档闸门的「首关豁免」整条退役）。若 `star-collect-rule §6-T2`（教学关专项）后续裁出豁免 ⇒ 属语义变更，**必回设计轨复批**，可豁免时亦需先出 §3 变更单（豁免 = 判据集合改动），⛔ 实现自行特判。
4. **通关 ≠ 门票达成，两层各算各的**：同一份存档必须能同时回答两个不同问题——「本章是否全通」（每关星 ≥ 1，显示层，喂橱窗三态的 `cleared`）与「本章是否**全通关 ∧ 累计星 ≥ 门槛**」（推进层，喂门票；~~每关星 = 3~~，**⚠ v1.3-R5 改判（WXG-T-346）**）。两层**共享「每关 ≥1★」这一子条件，但仍须各自归约** ⇒ ⛔ 一处回答两问、⛔ 不得合并成一个布尔、⛔ 复用 `_arcState` 的 `allCleared`（C3 拆分；消费侧规格 = `meta-ui.md §2.7` + `ux/arc-level-select-spec.md` v1.11）。

| 存档被外部篡改 | ✅ 不受本批影响 | 沿用 §6「非法输入」条逐字段钳正 + §2.4 全档无效则出厂默认，口径逐字不变 |

#### 2.6.4 降级默认（身份视角）

沿用两条既有判例：**安全降级优先于报错**（core-loop §2.1 / breakout）与**逐字段降级不弃整档**（§2.4 / §8-12 字段级隔离）。新增三条硬口径：**⛔ 弃整档、⛔ 中断启动、⛔ 因身份失配而清零星数**。逐场景的默认值已逐行写入 §2.4 矩阵（v1.3 四行），本节点出三条**边界原则**：

1. **作废只发生在「对不上」的那一条上**，不做整批回滚——整批回滚等价于清档，违反既有判例。
2. **降级不得让玩家看到错误**：静默钳正、照常启动、无「存档异常」弹窗（§4「降级静默」行逐字适用）；如需排查走 logger。
3. **棘轮优先于闸门**：无法判定时取「让玩家少玩一关」，⛔ 取「让玩家丢进度」（与 §6「丢失容忍 > 中断」同一价值序）。
4. **「作废」是语义判定 = 不参与任何计算**，而非必然的物理删除；⛔ 不得把作废记录挪给别的关。具体写回是否裁剪属工程裁（ADR-0034 DEC-9 取「写回时丢弃孤儿键」，本文**接受该形态**，因为它收敛了「身份被复用则旧星替新内容开门」的污染窗口）；**但退役关不适用本条**（见 §2.6.3 补行：身份仍在 ⇒ 记录仍在）。
5. **可观测性属必需而非可选**：失配必须可枚举（I3），渠道 = 内部日志计数，⛔ 玩家可见反馈（§4「降级静默」）。

#### 2.6.4.1 身份指不回时的降级档（**v1.3-R3 追加裁定 · 答工程侧 ADR-0034 §7-Q8**；⛔ 改本节既有五条）

> **唯一触发器**：档内两根进度指针（**推进位** = 续玩点；**解锁位** = 已获准推进的最远边界）之一所记的**关身份**在当前关表里 resolve 不出（该关被物理删、身份从关表消失）。⛔ 不适用：章改名 / 删章 / 拆章重分（章维变更对关身份账无损，见 §2.6.3 与 §8-18）；「身份表整体换掉」属结构换制，必须走 §2.6.6 迁移腿，⛔ 指望运行时兜底。

**三档对比**（同一夹具 = 两指针指向的关已不在当前关表）：

| 档 | 做法 | 玩家可感后果 | 回滚代价 | 是否符合 I7（已得入口不回收）与本节现口径 |
|---|---|---|---|---|
| **甲** | 整档回落第 1 关（全档出厂默认） | 星、通行、设置全清，从零开始 | **不可回滚**（星账一并清） | ❌ 撞本节第 1 条「作废只发生在对不上的那一条」与 I7；也撞 §2.6.3「退役关记录不得作废」的精神 |
| **乙** | **只**把两根指针回落第 1 关，星账无损 | 星还在，但玩家被送回第 1 关；已解锁的章内 / 跨章边界清零，已推平的章要重走 | 字段级可回滚；但玩家已感知的进度回退不可撤销；开发期测试档的推进 / 解锁类用例需重跑 | ❌ 撞本节第 3 条「棘轮优先于闸门：取让玩家少玩一关，⛔ 取让玩家丢进度」；也撞 §2.4「推进位 / 解锁位无法对位」行「⛔ 不得回退到比玩家实际已进入过的位置更小」 |
| **丙（裁定）** | 两根指针**各自**回落到「**另一根仍可解析的指针所指的那一关**」= 最近仍存在的有效关；星账逐条无损（⚠ **v1.3-R4 收窄**：~~当前关表中、存档仍能指认的、装配序最靠后的那一关~~ ⇒ 锚源只剩另一根指针，理由见定义 1；结论／档位不变） | 最坏 = 回到「**另一根指针所指的那一关**」（~~最后一关有记录 / 最后玩过的那一关~~ ⇒ 锚源收窄后只剩这一条证据），通常即失配关的前一关（**最多重玩一关**；连续多关被删则相应更多；两根都失配 ⇒ 首个开放章首关）；星、已通关记录、章级入口全保留 | 只改失配分支与工程侧降级变异臂的期望值；schema、版本号（留 5）、视图契约零改动；已降级的档不可还原，但星账无损 | ✅ 星账无损 ⇒ 章级入口按 I1 现算不回退；章内线性边界**只回退不前进**（保守方向 = 本节第 3 条的「少玩」一侧）；与 §2.4 该行逐字同向 |

**裁定 = 丙档**，理由三条：① 它是唯一同时守住「星账无损 + 章级入口不回退 + ⛔ 白送全章」的档位；② 它把「猜」限制在**存档自己还能指认的关**上——这正是 §2.6.2 **I4** 末句「指不回时按 §2.6.4 降级，⛔ 不得猜」要的降级，而不是新造一条寻址轴；③ 它与 §2.4「推进位 / 解锁位无法对位」行**同向**，本裁定只把该行从原则补成可执行定义（该行写了「可对位的最远已解锁位置」，未写「怎么求」）。

**被否档位的理由**：甲 = 弃整档，等于把一次内容变更升级为清档，撞既有判例且不可逆；乙 = 字段级清档，星虽在但玩家的**已得边界**被回收，正是 I7 明文要防的「因内容变更回收已得入口」（§8-20 同向）。另有两档已在工程侧实测排除、本批**不重开**：「夹到当前表末位」= 白送全章、越权动 `systems-index §3.7` 线性解锁行；「从 token 字面反解序数」= 第二位置读路径，被 §8-22-④ 拒收。

**可执行定义（工程照此落，⛔ 自行改档）**：

1. **锚集合** = **另一根仍可解析的指针所指的那一关**（单一候选）。⚠ **v1.3-R4 改判（2026-10-22 · WXG-T-345 · 设计轨 T-1Q2；旧句按 K-053 留档，⛔ 静默覆盖）**：~~锚集合 = 当前关表 ∩（另一根仍可解析的指针 ∪ 星账键集）~~ ⇒ 现口径 = **只认另一根指针；星账键集从锚集合中移除**。**移除理由（依据 = 已入库实现事实，非猜测）**：终态星账为**稠密物化**——`games/beads/src/game/save-schema.ts::normalizeStarLedger` 末尾有「稠密尾趟」（当前关表每个身份键都补 0），`collapseStars` 写档时对**每个槽位**都写值（含 0）⇒ 真实档里「星账键集」= **当前关表全集** ⇒ **键存在性对每一关恒真，不承载「玩家到过哪」的信息**；读星值又被本档第 ④ 条禁令封死 ⇒ **星账在本降级档里不提供有效证据**。旧句的后果不是理论风险：并集里恒有表末位 ⇒ 取「装配序最靠后」必落表末位 = 本档「⛔ 禁止的实现 ②」（夹到当前表末位 = 白送全章）；旧单测未抓到，是因为 Q8 夹具用了**稀疏**星账（`keyOnly`），与生产数据形状不一致 ⇒ 夹具须按稠密档重写（归工程批，⛔ 本批零落码）。**「可解析」的判据**：该指针在当前关表里 resolve 得出（身份命中 ⇒ 已在表内；v4 旧数值入口那一趟沿 §2.6.5，⛔ 本档另立）；指不回（含另一根也失配）= 不可作锚。章级门槛由门票另行把守（I1 / I5），⛔ 本降级档不代它判、也 ⛔ 借它过滤锚（否则玩家在「章维变更后暂时归约为假」的章里的既有记录会被挡在锚外，反而撞 I7）。⛔ 读星账——**键也不读**（键集恒真，读它只会把锚拖向表末位）；读**值**更被禁（成「由星数反推推进位」，撞 §8-19 反向断言与 I6）。
2. **取锚** = **锚集合的唯一元素**（= 另一根指针所指的那一关）；**不再有「装配序最靠后」的比较**。⚠ **v1.3-R4 简化（同上批；旧句按 K-053 留档）**：~~锚集合中沿当前关表装配序最靠后的一关（装配序 = 当前关表的下标序，是关表的事实，不是存档的位置轴）~~ ⇒ 锚集合恒为 **0 或 1** 个元素，「最靠后」退化为空操作。~~星账通常只含已通关记录，最后进入但未通关的那一关由另一根指针兜住 ⇒ 两者并集即「存档能指认的最远已进入位置」~~ ⇒ 该前提在稠密物化下**不成立**（星账键集 = 全表，并集恒为全表）⇒ 删除；现读 = 「存档能指认的最远已进入位置」**只由两根指针自己表达**（另一根 = 证据，失配的那根 = 待改写的值），⛔ 由星账提供。
3. **落点** = 失配的那一根指针改写成该锚的身份；两根**各自判定、各自降级**，⛔ 把一根的语义搬给另一根（锚可以是另一根指针所指的关，那只是位置证据）。
4. **最后兜底** = 锚集合为空（= **另一根也指不回**；~~连星账都无记录~~ ⇒ ⚠ v1.3-R4 括注订正：星账已退出锚源，见定义 1；**兜底结论不变**）⇒ 首个开放章的首关（本版 = 第 1 关；= §2.4 该行的「出厂默认」）。
5. **写回与幂等** = 降级结果**同批写回恰一次**，把两指针落成可解析态；第二次读 ⛔ 再降级（`changed = false`）。⛔ 为此 bump 版本号（ADR-0034 DEC-7 补充条款 ①：留 5）。
6. **静默与可观测** = 无弹窗、不中断启动（本节第 2 条）；失配次数进 logger 计数（本节第 5 条 / I3）。

**⛔ 禁止的实现（逐条 = 反例，命中即判红）**：① 按 token 字面（如 `L00012` 的数字段）比较或反解序数（= 第二位置读路径，§8-22-④）；② 夹到当前表末位（= 白送全章，越权动 §3.7）；③ 失配即回第 1 关（乙档，已否）；④ 用星值大小挑「最高星关」（撞 §8-19 反向断言）。

**射程边界（诚实登记）**：① 「身份表整体换掉」不在本档射程——必须走 §2.6.6 迁移腿（一次性映射），运行时 ⛔ 兜底；② 若失配的解锁位原本代表「已获准进入的下一章」，而锚集合里**没有任何一关落在该章**（玩家进章后一关未玩、且该章首关恰好被删）⇒ 章级棘轮无从判定，按统一规则回落并在日志标 `grant_chapter_unknown`；这是本档的**已知残余风险**，登记待观察（与 ADR-0034 §4.4 免疫矩阵同族的诚实口径，⛔ 粉饰成已闭合）；③ 本档 ⛔ 改变 §8-20 的夹具结论（追加一关不删身份 ⇒ 不触发降级）；④ **（v1.3-R4 新增 · 稠密星账下的已知残余风险）** 解锁位失配、而另一根（续玩位）仍可解析却**停在更早的关**时 ⇒ 回落落到**续玩位**，比玩家真实边界（原解锁位）**更保守**——方向 = 宁可多玩（玩家得多走几关）、**⛔ 白送**；代价 = 已获准进入的边界被拉到续玩位（仍守住 §2.4 该行「⛔ 不得回退到比玩家实际已进入过的位置更小」：续玩位 = 实际进入过的位置）。这是**收窄锚源换来的、稠密星账下无法消掉的代价**：星账本可在「另一根指针不在边界上」时提供位置证据，但其键集恒真、值又被禁读 ⇒ 该证据不存在 ⇒ 只能取续玩位。**登记待观察**（若日后星账改为**稀疏**记录、或另开第三根可解析的位置证据 ⇒ 回设计轨复批重开锚源，⛔ 实现自行放宽；⛔ 粉饰成已闭合）。

**对工程侧降级变异臂的固化**：ADR-0034 §6.1 的 **M-20** 期望值据此定为「失配 ⇒ 回落到最近仍存在的有效关；⛔ 静默回 1」，其**锚源 = 另一根仍可解析的指针**（v1.3-R4 收窄，见定义 1／2；~~另一根指针 ∪ 星账键集~~）；变异注入 = 把该分支改成回 1 ⇒ 本臂必红（该臂原文的「暂定基准」至此转为已裁）。

#### 2.6.5 旧口径处置（**唯一裁定，⛔ 留两套并存规则**）

**裁定：v1.2（WXG-T-342）的「长度不符 → 前缀搬运」被取代，其唯一残余身份 = 「无身份旧档（v4 及以前）的一次性迁移入口」。** 展开四条：

1. **迁移趟内**：旧档只有位置轴 ⇒ 按位置对位读入（**第 i 位读成「旧关表的第 i 关」，再按当时关表换算成身份**）；这是旧档唯一可能的合理解释，不是新制认可的寻址方式。旧档的「非数组 ⇒ 全 0」臂口径不变。
2. **迁移趟后**：读入即落成身份化终态并写回恰一次；此后终态读档 ⛔ 不再执行前缀搬运 ⇒「长度不符」不再是运行期概念。§2.4 该行与本节为唯一终态表述，任何文档/代码若仍把前缀搬运当常规规则陈述 ⇒ 属漂移。
3. **诚实代价（不粉饰）**：若旧档所在关表**已经历过中间插删**（本仓发生过：`chapter-store` 删除即整体重编号），位置对位本身就是错的，且迁移腿无法自我察觉 ⇒ 登记为**近似迁移**，处置 = 靠 §8-15～22 的镜像夹具覆盖 + 试玩抽样；⛔ 不得为了「看起来准」在存档层猜 uid 映射（那是第二真源）。
4. **本仓现状（⛔ 伪造）**：本作**未上架**（无 AppID / 无上传）⇒ 无外部玩家存档，本批改判**不涉历史玩家**；一次性入口真正服务的对象 = 开发期本地档、真机扫码档与单测/金样本夹具。「未上架所以可改结构」是**本批的窗口依据**，不是长期豁免（见 §2.6.6）。

#### 2.6.6 上架后再次变更存档结构的前置要求（流程判据，登记在册）

> 本批靠「未上架」这一窗口成立（§2.6.5-4）。**上架后同样的动作不再有窗口**，须同时满足以下四条方可立项（缺一 ⇒ 主理人不予排批）：

1. **迁移腿**：旧→新为纯函数 + 幂等（第二遍读同一档 ⇒ 不再改写），且**永不抛异常**（SaveManager 契约）；⛔ 禁止「读不认识的档就清档」。
2. **镜像用例**：QA 按本文 §8 引用式造用例（判据源 = §8，⛔ 现场另立），必含「喂旧档入新制 ⇒ 逐字段无损」正例与「身份失配 ⇒ 逐条作废不弃档」降级例两臂。
3. **灰度**：走 `wxgame-release-checklist` 口径（小流量先行、保留可回滚旧包、观测「进度回落 / 星数归零」类玩家反馈与日志计数）；回滚预案须写明**旧包读新档**的降级行为 = §2.4「高版本档」行（保留可读字段、照常启动），⛔ 锁死旧包。
4. **数值真源对账**：若变更牵到门票粒度 / 星数口径 ⇒ **必须先出 `systems-index §3` 变更单并等拍板**，⛔ 文档先行落码；本批零 §3 触达，故不涉。

- 存档超长（被外部塞入巨量字段）：加载时白名单字段裁剪，体积上限兜底，不崩溃。

- `meta.signin` 记录跨版本日历变更：按 `lastPlayDate` 字符串比较，解析失败视为未签到（不阻塞）。
- 写档时存储满（weapp storage 配额）：SaveManager 捕获失败 → 本局内内存态继续用，下次 BOOT 重试；**不向玩家报错**（解压定位，丢失容忍 > 中断）。

**并发 / 竞态**
- 同帧过关 + 失败（不可能同时，S1 cleared 优先裁决保证）——防御上仍按"后写覆盖、字段 max 保护星级"。
- 结算写与设置写同帧：合并为一次整档写入（§2.5 幂等）。
- BOOT 读档与 runs+1 写同帧：读完成后自增写回，无脏读（同步 API，architecture §2）。

**非法输入**
- 外部篡改（debugger 改 storage）：按 §2.4 降级矩阵逐字段钳正，全档无效则出厂默认——**玩家视角永远可玩**。
- `stars` 数组含小数：向下取整后钳 [0,3]。

## 7. 依赖

- **上游**：S1（读写时机与分流）、S7（sprint 成绩与星级终值）、S9（设置）、meta 提案层（冻结后接入）。
- **下游**：S1（BOOT 分流）、S9（设置回显）、S7（NEW BEST）、未来排行（开放数据域提交，meta-framework §3——提案层）。

## 8. 验收标准（可测试硬判据，QA 直接造用例）

1. 首启（无存档）→ runs=1、unlockedLevel=1、进 L1；二次启动 runs=2、续进 unlockedLevel 最远关。
2. 通过第 n 关（n<8）→ unlockedLevel=n+1 落档且重启保留；stars[n-1] = max(旧, 新)，历史最高星不被低星覆盖。
3. 存档篡改矩阵逐条复现 §2.4：解析失败→出厂默认进 L1；unlockedLevel=99→钳 8、=0→钳 1；stars 长度 3→**前 3 位搬运、其余补 0**（v1.2 起；v1.1 及以前为重置全 0，旧口径见 §2.4 注的留档）——全部**不中断启动**（联合 core-loop §8-10）。⚠ 本条「钳 8」与 §2.4 行「钳到 1」及代码 `levelIndex` 的「越界⇒回 1」不一致（既存漂移，本批只登记不改，K-053 留档；真源以 §2.4 行与代码为准）。**⚠ v1.3 适用域订正（WXG-T-343，⛔ 删本条）：本条里的「stars 长度 3 → 前 3 位搬运」自 v1.3 起仅在 §2.6.5 一次性迁移入口内成立**；终态读档的长度臂已作废（新档不靠长度对位），失配改按 §2.4 v1.3 四行逐条作废（新增判据 = 本 §8-17）。
4. 高版本档（version=2）→ 可读字段保留、照常启动，无异常抛出（SaveManager 永不抛异常契约）。
5. v1.1 字段冻结（2026-09-12）后：旧 v1 档直接升级读取，sprint/meta 字段取默认值，v1 字段值无损；新档写 v1.1 完整字段。
6. `sprint.bestScore`：构造新分 > 旧最佳 → 写入 + S7 NEW BEST 显示；≤ → 不写（联合 S7 §8-11）。
7. 连胜：连续过关 3 次 → winStreakCurrent=3、Best=3；第 4 关失败 → Current=0、Best 仍 3（v1.1 字段已冻结 2026-09-12，判据生效）。

9. PLAYING 全程（注入落子次数 = 关卡最大可构造量 `GRID_MAX_COLS×GRID_MAX_ROWS` = 156；旧「200 次」超出可构造上限不可验，BD-24，WXG-T-091 修正）写档次数 = 0；**过关结算帧（本判据取 `level:cleared` 帧——失败/sprint 帧的写档另依 §2.5 「每局 ≤1 次」口径、不属本条断言域，实测失败帧零写档与之一致，P18③）**写档恰 1 次。

11. **换肤两字段入档**（v1.1 / WXG-T-211-D；承 `proposals/bead-visual-style-spec.md §12` **C9**，口径面背 `ux-spec §3.3`「生效与存档口径」③／⑤）：暂停面板行4 两钮每完成一次点按 ⇒ 对应字段（`settings.beadStyle` 存 **registry 已注册的 `styleId` 单值**；豆径档字段存 **满豆/小豆枚举单值**。**字段名与结构终稿归代码**，本篇只定语义）随**即写**落盘（属 §2.5「即写」族，低频，与四开关同一写入通道）；**只存末值、不存历史栈**（连点 N 次 ⇒ 落档次数按 §2.5 幂等口径合并，档内**恒为末值一条**）；杀进程重启后两字段**回显与关前最后一帧一致**。**不新增事件名**（沿用四开关「即写 S8」判例）。
