## 1. 目标

在"槽位压力"逼近临界时给玩家一次**可控的泄压阀**：三道具只清理托盘珠、绝不回退网格进度，以"每关每道具 1 次免费 + 激励视频角标位"承接参考图的商业化位，而不改动 P0 核心循环。

## 2. 机制

### 2.1 作用域与线性索引

- 托盘槽按**行主序线性编号**：基线行索引从 0 起、长度 `TRAY_BASE_SLOTS`；扩展行（解锁后存在）紧接其后、长度 `TRAY_EXPAND_SLOTS`（来源：systems-index §3.4）。**未扩展时扩展行索引不存在**，任何落在其上的索引非法（§6）。
- 生效容量 = 未扩展为 `TRAY_BASE_SLOTS`；已扩展为 `TRAY_BASE_SLOTS` + `TRAY_EXPAND_SLOTS`（来源 §3.4）。
- 唯一作用对象 = **holding 槽中的托盘珠**。网格 `filled/empty/locked` 三态**不读不写**（来源 §3.6「道具目标：仅托盘珠」行 + concept 附录 A6 + 铁律 L5 精神）。

### 2.2 三道具效果与目标选取

| `type` | 名称 | 效果定义 | 目标选取规则 |
|---|---|---|---|
| `region` | 区域消除 | 清除托盘**连续 `REGION_CLEAR_SLOTS` 槽**内的全部持有珠（来源 §3.6） | 窗口锚点 = 当前 `selected` 槽；无选中时锚点 = 线性索引最小的 holding 槽。窗口以锚点为中心向两侧延展至 `REGION_CLEAR_SLOTS` 槽；越出生效容量边界时**整体钳制**（窗口恒长，不缩小、不越界）。「连续」按线性索引计，**跨基线行与扩展行合法**，不被行界截断。 |
| `clearAll` | 槽位清空 | 清除**生效容量内全部** holding 槽（概念 A6「清空托盘全部珠」） | 无瞄准：全槽命中，含 `selected` 槽（选中态随之清除，S4 §2.4）。实际清除数 = 当时持有珠数，上限随扩展态取 §3.4 两值之一；**本文不为其新造常量** `（已裁定 2026-09-12：由 §3.4 容量派生，不新造独立常量）` |
| `random` | 随机消除 | 随机移除至多 `RANDOM_CLEAR_COUNT` 颗持有珠（来源 §3.6） | 从当时的 holding 槽集合中用 `services.rng` **等概率、无放回**抽取（铁律 L4，禁 `Math.random`）；不区分颜色——不为"杂色优先"加策略（支柱 3 复刻优先）。持有数 < `RANDOM_CLEAR_COUNT` → 全部移除、不补抽（§6）。 |

### 2.3 结算时序（一次点击 = 一次原子结算，无瞄准中间态）

```
S2 道具卡点击（S2 §2.1 路由优先级 2，携带 type）
  → S6 校验 type ∈ POWERUP_TYPES 且 S1 状态 = PLAYING，否则忽略（§6）
  → 取本关该 type 的剩余免费次数（三计数器互相独立，§2.5）
     ├─ 次数 > 0：按 §2.2 用托盘只读镜像算 affectedSlots
     │    ├─ 非空 → 广播 powerup:used {type, affectedSlots} → 该 type 次数 −1
     │    └─ 空（窗口内 / 托盘内无持有珠）→ 不广播、零槽变化
     │         是否扣次 （已裁定 2026-09-12：拒用不扣，采纳默认——免费次数是唯一稀缺资源，
     │         不应被误触或空窗口吞掉，支柱 1）
     └─ 次数 = 0：不广播、不清槽、次数不变，仅 `ad_badge` 占位反馈（§2.6）
```

- **单步生效**：点击即结算，MVP 不引入"选窗"两步瞄准——因此不需新增 §4 事件，也不要求 S2 增加瞄准路由 `（已裁定 2026-09-12：MVP 单步自动锚点；两步瞄准列 Should）`。
- **道具不改时间**：不加时、不冻结、不延表；倒计时唯一真源仍是 S5（§3.5）。

### 2.4 与 S4 的事件契约

- S6 **不持有托盘真源**，只订阅 systems-index §4 既有事件维护**只读镜像**：`tray:spawned`（该槽置 holding）、`bead:placed`（回执 slot 置 free）、`tray:expanded`（生效容量扩大）。
- 清槽动作由 **S4 执行**（S4 §2.4 出口二）：S4 收到 `powerup:used` 后把 `affectedSlots` 逐槽置 `free`，含 `selected` 时同时清除选中。
- 一致性硬要求：payload 的 `affectedSlots` 必须与 S4 实际清空的槽一致（S4 §8.10）。事件总线串行送达，派发瞬间 S6 镜像与 S4 状态同帧一致；若发现某槽已 `free`（镜像漂移）→ S4 幂等跳过并记警告（§6 非法输入）。
- 本文**不新增事件**；扩展位所需的 `tray:expanded` 沿 §4 既有条目，其广播方为 S4（S4 §2.3），S6 只对扩展位的**角标占位反馈**负责 `（已消歧：§4 触发方统一为 S4，主理人裁定 2026-09-12）`。

### 2.5 免费次数计数模型

- 每 `type` 一个计数器，初值 `POWERUP_FREE_USES`（来源 §3.6），**三道具互不影响**（用掉 `region` 不动 `random`）。
- 扣减时机：仅当效果实际生效（`affectedSlots` 非空）后 −1；超限点击不产生次数变化。
- 复位时机：进入新关（BOOT→PLAYING 装配）与整关重置（失败重试 / 暂停重玩 / 换关）→ 三计数回初值（§3.5 重置第 5 项，S5 §2.4）。
- **不入存档、不跨关累积**（§3.5、§3.6；免费次数与扩展态同为关内态）。

### 2.6 激励视频位与 MVP 边界（诚实口径）

- `AD_PLACEMENTS` = 4 位（来源 §3.6）：3 道具卡 + `btn_expand`。S6 拥有 3 个道具位的"超限后再用"入口语义；扩展位的解锁效果归 S4（S4 §2.3）。
- **MVP 不做拉起与发奖**：§3.6 标 `[待用户确认]`，§5 工程确认 `createRewardedVideoAd` 不存在，ADR-0006 采方案 A。故超限点击的可交付口径 = **`ad_badge` 角标占位轻提示**（位置与形态见 `art/assets-spec.md` §1.4，贴卡右上），**零事件、零槽变化、零扣次、不调用任何 wx 广告 API**。
- 推论（不掩饰）：MVP 阶段玩家**拿不到第 2 次道具效果**，道具位只有免费那条路径成立；扩展位在 MVP 同样**没有解锁路径**（无免费次数概念，又无广告发奖），其扩容逻辑只能在单测/harness 注入验证 `[待确认：扩展位是否给"每关 1 次免费扩展"或明确"demo 永不可解锁、仅测试钩子"——涉及 S4 §2.3 与 §8.5，不由 S6 私定]`。
- 广告能力补齐后（另轮，非 MVP）：超限点击 → 拉起 → `onRewarded` 成功后才清槽并记一次使用；加载失败 / 中途关闭 → 不清槽、不扣次。

## 6. 边界条件

**极端值**
- 窗口 / 托盘内无持有珠时使用 → 零 `powerup:used`、零槽变化；扣次与否按 §2.3 已裁定**不扣**。
- 未扩展（容量 = `TRAY_BASE_SLOTS`）时 `region` 窗口恒可容纳（`REGION_CLEAR_SLOTS` 小于基线容量，来源 §3.6/§3.4），不出现"窗口放不下"。
- `clearAll` 于满槽时一次清掉生效容量内全部持有珠（含 `selected`）→ 下一供料 tick 恢复供料，**不补发**满槽期间跳过的次数（S4 §2.2/§6）。
- `random` 持有数 < `RANDOM_CLEAR_COUNT` → 全部移除、不补抽、事件仍恰 1 次。
- 同关内三道具各用 1 次 → 共 3 次成功效果（计数独立）；第 4 次任意道具点击进超限占位分支。

**并发 / 竞态**
- **与供料同帧**：按事件到达序串行（S4 §6）——清除先到则该槽可作为本帧供料目标；供料先到且新珠落入窗口/抽取集合则一并清除，否则不受影响。
- **与落子同帧争用同一颗珠**：以先到为准（core-loop §6）。道具先到 → 珠已离槽，S3 落子前向 S4 复核失败并忽略（bead-grid §6）；落子先到 → 该槽已 free，不进 `affectedSlots`。
- **`tray:expanded` 与道具请求同帧**：按容量变化的先到序解释窗口钳制边界；禁止用"旧容量"算出的越界索引生效。
- **`level:cleared` / `level:failed` 触发时（含假想的瞄准中）**：S1 一旦离开 PLAYING，其后到达的道具请求全部作废。本篇 §2.3 采单步结算，**不存在瞄准中间态**，故无"瞄准中被结算/暂停打断"问题；若裁定引入两步瞄准，则必须补「PAUSED / cleared / failed 打断即取消瞄准、不扣次」条目 `（§2.3 已裁定单步结算，无瞄准中间态，此条不适用）`。
- **PAUSED 中请求与 resumed 同帧**：请求作废，不缓存、不重放（S2 §2.3 门禁优先）。

**非法输入**
- `type` ∉ `POWERUP_TYPES`（含 undefined / 拼写错）：忽略 + 警告日志，零事件零扣次，不崩溃。
- 非 PLAYING 状态（BOOT / PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH）收到道具请求：S6 二次防御性忽略（S2 已在路由层拦）。
- 越界索引（< 0 或 ≥ 生效容量）出现在锚点或镜像中：钳制或丢弃该索引 + 警告；`affectedSlots` 只含合法且派发时确实 holding 的槽。
- 连点同一道具卡：帧内合并沿用 S2 §2.4 去抖窗口；跨帧第 2 次按 §2.5 计数规则处理（免费已尽 → 仅占位反馈）`（已裁定：MVP 不加独立冷却，沿用 S2 §2.4 去抖；§3 未冻结冷却值，不写）`。
- 镜像漂移（S6 认为 holding、S4 已 free）：S4 逐槽置 free 时跳过已 free 槽（幂等），记警告供回归排查。

- **下游**：S4（`powerup:used` 清槽执行）、S7（`powerup:used` 结算统计）、视觉层（溶解/生效动效、角标占位）、音频层（事件消费）。对齐 systems-index §2 拓扑：`S4 ─► S6`，S6 回指 S4 仅经事件，无反向调用。
- **明确边界**：**不依赖 S3 写入路径**——道具绝不改网格任何格态（`filled` 为终态，bead-grid §2.2 + §3.6）；**不改倒计时**——不加时、不冻结、不暂停 S5；不写 S8（免费次数与扩展态均关内态，不入档）。

## 8. 验收标准（可测试硬判据，QA 直接造用例；未标环境者均 `[Node]` vitest 可断言）

1. **region 窗口恒长与集合正确**：构造生效容量内含若干 free 槽后使用 `region` → 窗口为连续 `REGION_CLEAR_SLOTS` 个线性索引且完整落在容量内；`affectedSlots` 恰等于窗口内原 holding 槽集合；窗口外 holding 槽逐一不变；`powerup:used` 恰广播 1 次且 payload 与 S4 实际清空槽 1:1（联合 `S4§8-10`）。
2. **region 锚点规则**：存在 `selected` 槽时窗口以该槽为中心；无 `selected` 时锚点 = 线性索引最小的 holding 槽；两态各 1 例，逐槽断言 `affectedSlots`。
3. **region 钳制与跨行**：未扩展时锚点位于容量首槽 / 末槽两组 → 窗口整体钳制在容量内、长度恒 `REGION_CLEAR_SLOTS`、零越界索引；已扩展时构造锚点使窗口跨越基线行与扩展行边界 → 窗口内 `REGION_CLEAR_SLOTS` 槽照常清除，不因行界截断。
4. **random 唯一随机源**：同一 seed 重复运行结果逐槽相同；固定 seed 采样 200 次，各 holding 槽被清除频次与均匀分布偏差 ≤ ±20%；架构守卫断言 S6 代码零 `Math.random`（`pnpm run check:arch`，铁律 L4）。
5. **random 不足数不补抽**：holding 数分别为 3 与 1 时 → 全部移除、`affectedSlots` 长度 = holding 数、事件恰 1 次、不凭空生成或复活任何珠。
6. **clearAll 全容量清槽**：满槽两组（容量 = `TRAY_BASE_SLOTS` 与已扩展 = `TRAY_BASE_SLOTS`+`TRAY_EXPAND_SLOTS`）→ 全部 holding 槽置 `free` 且 `selected` 态随之清除；随后 ≤1 个 `SPAWN_INTERVAL` 供料恢复（联合 `S1§8-3`）。
7. **零网格写入**：三道具各用 1 次，使用前后 `filled`/`empty`/`locked` 三计数逐一相等，S3 侧 `bead:placed`+`bead:rejected` 计数增量 = 0（对齐 `S3§8-6`），且 S6 无对 S3 的直接调用（依赖/守卫断言）。
8. **免费次数、超限占位与重置**：三道具计数互相独立（各 1 次 = 3 次成功效果）；同一道具第 2 次点击 → 零 `powerup:used`、零槽变化、零扣次，仅 `ad_badge` 占位反馈，全程零 `wx` 广告 API 调用；失败重试（整关重置）后三计数回 `POWERUP_FREE_USES`，且扩展态复位使 region 钳制边界回到基线容量（联合 `S5§8-6`）。角标视觉项 `[DevTools]`。
9. **空作用 / 非法 type / 状态门禁**：窗口或托盘内无 holding 珠时使用 → 事件计数 = 0、槽态零变化，并按 §2.3 默认**不扣次**（改判后本条同步更新）；`type` 非 `POWERUP_TYPES` → 忽略 + 警告、不崩溃；BOOT/PAUSED/LEVEL_CLEAR/GAME_OVER/FINISH 五态各注入道具请求 → 事件计数 = 0 且计数不扣。
10. **同帧竞态守恒**：注入「道具 vs 供料同帧」「道具 vs 落子同帧争同一槽」「`tray:expanded` vs 道具同帧」三组 → 按到达序串行生效、后到者按最新槽态重新解释；无同槽二次清除（幂等）、`powerup:used` 与 `bead:placed` 计数与预期序列 1:1、无负计数、无异常抛出。
