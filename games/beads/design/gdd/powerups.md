## 1. 目标

在"错位僵局"卡住玩家时给一次**可控的破局**：三道具反转为**解环器**——自动把错位珠归位、推进解谜，绝不触碰托盘、绝不改倒计时，以"每关每道具 1 次免费 + 激励视频角标位"承接参考图的商业化位，而不改动 P0 核心循环的取回/归位规则。

## 2. 机制

### 2.1 作用域（v1.3 反转：棋盘错位珠；托盘零读写）

- **唯一作用对象 = 棋盘上的 `filled(错位)` 格**（`misplaced` 判定见 `bead-grid §2.1`、§3.6 v1.22 冻结变更）。`filled(就位)` 与 `locked` **不可触碰**。
- **托盘零读写（v1.3 硬边界）**：S6 不订阅、不写、不请求任何托盘状态；`tray:*` 事件对 S6 为零消费（v1.2 时代的「托盘只读镜像」**作废**）。`bead:placed`（解环器路径）payload 不带 `slot`（§4）。
- 网格写入唯一真源 = S3：S6 只**裁定**（选珠、算 `affectedCells`）并广播 `powerup:used {type, affectedCells}`，**S3 执行写入**并逐格发 `bead:placed`（无 `slot`）——完成判定自动随后（`core-loop §2.2.2` 输入段内序：道具裁决 → S3 写入 → placed 回执 → cleared 判定）。

### 2.2 三道具效果与目标选取（v1.3：解环器三型）

| `type` | 名称 | 效果定义 | 目标选取规则 |
|---|---|---|---|
| `solver` | 解环器 | 自动归位 **1** 颗错位珠 | 选**行主序最前**的 `filled(错位)` 格 X（确定性，无 RNG）。执行规则（按 X 的目标格 = 底色 = X.colorIdx 的格 T 状态分派）：① T 为 `empty` → **直移**：X 珠离原格（原格 → `empty`）、T → `filled(X.colorIdx)`；② T 被错位珠 Y 占 → **单次交换**：X、Y 互换格位（若互换后 Y 就位则双赢；Y 仍错位则留在原地，多环由玩家继续解）；③ T 被**就位珠**占 → 该局面不可构造（色数守恒，`bead-grid §6`），防御性走重选下一颗 + 警告日志。每次直移/交换产生的 `filled(就位)` 格各发 1 次 `bead:placed`（无 `slot`） |
| `solverPlus` | 解环器·强化 | 自动归位**至多 `SOLVER_PLUS_COUNT`(3)** 颗错位珠 | 按 `solver` 规则**迭代执行 3 次**（每次重选行主序最前剩余错位珠）；剩余错位珠 < 3 → 全归、不补（判例同原 `RANDOM_CLEAR_COUNT` 不足数不补抽）。一次性广播 1 条 `powerup:used`，`affectedCells` 含全部受影响格位 |
| `solverRandom` | 解环器·随机 | 自动归位 **`SOLVER_RANDOM_COUNT`(1)** 颗错位珠 | 从当时 `filled(错位)` 格集合用 `services.rng` **等概率**抽取 1 颗（铁律 L4，禁 `Math.random`），执行规则同 `solver` ①②。无错位珠时效果为空（§2.3 不扣次） |

### 2.3 结算时序（一次点击 = 一次原子结算，无瞄准中间态；v1.3 承接反转）

```
S2 道具卡点击（S2 §2.1 路由优先级 2，携带 type）
  → S6 校验 type ∈ POWERUP_TYPES 且 S1 状态 = PLAYING，否则忽略（§6）
  → 取本关该 type 的剩余免费次数（三计数器互相独立，§2.5）
     ├─ 次数 > 0：按 §2.2 用棋盘只读镜像算 affectedCells
     │    ├─ 非空 → 广播 powerup:used {type, affectedCells} → 该 type 次数 −1
     │    │         → S3 执行写入 → 逐格 bead:placed（无 slot）→ 完成判定
     │    └─ 空（棋盘无错位珠）→ 不广播、零格变化
     │         是否扣次 （沿用 2026-09-12 裁定：拒用不扣——免费次数是唯一稀缺资源，
     │         不应被误触或空目标吞掉，支柱 1）
     └─ 次数 = 0：不广播、零格变化、次数不变，仅 `ad_badge` 占位反馈（§2.6）
```

- **单步生效**：点击即结算，MVP 不引入"选珠"两步瞄准 `（沿用 2026-09-12 裁定：单步自动锚点；两步瞄准列 Should）`。
- **道具不改时间**：不加时、不冻结、不延表；倒计时唯一真源仍是 S5（§3.5）。

### 2.4 与 S3 的事件契约（v1.3 反转：S4 → S3）

- S6 **不持有网格真源**，只消费 S3 广播的 `bead:placed` / `tray:stored` 维护**棋盘错位只读镜像**（哪些格是 `filled(错位)`）；~~`tray:spawned` / `tray:expanded` 托盘镜像~~ **⛔ v1.3 作废**（托盘零读写）。
- **网格写入由 S3 执行**（S3 是唯一真源）：S3 收到 `powerup:used {type, affectedCells}` 后按 §2.2 规则逐格写入（直移/交换），每产生一个 `filled(就位)` 格发 1 次 `bead:placed`（无 `slot`），随后完成判定自动执行。
- 一致性硬要求：S3 实际写入的格集合必须与 payload `affectedCells` 逐格一致（§8-1 联合断言）；镜像漂移（S6 认为某格错位、S3 已就位）→ S3 重算目标并记警告（§6）。
- 本文**不新增事件**；`powerup:used` 为 §4 既有条目（v1.22 payload 变更：`affectedSlots` → `affectedCells`，消费方 S4 → S3）。

### 2.5 免费次数计数模型

- 每 `type` 一个计数器，初值 `POWERUP_FREE_USES`（来源 §3.6），**三道具互不影响**（用掉 `region` 不动 `random`）。
- 扣减时机：仅当效果实际生效（`affectedCells` 非空，v1.3 字段）后 −1；超限点击不产生次数变化。
- 复位时机：进入新关（BOOT→PLAYING 装配）与整关重置（失败重试 / 暂停重玩 / 换关）→ 三计数回初值（§3.5 重置第 5 项，S5 §2.4）。
- **不入存档、不跨关累积**（§3.5、§3.6；免费次数与扩展态同为关内态）。

### 2.6 激励视频位与 MVP 边界（诚实口径 · 布局 A）

- `AD_PLACEMENTS` = 4 位（来源 §3.6）：3 道具卡 + `btn_expand`。S6 拥有 3 个道具位的"超限后再用"入口语义；扩展位的解锁效果归 S4（S4 §2.3）。（v1.3：道具反转不改变本布局——3 卡位、3 计数器结构原样保留）
- **布局 A（WXG-T-057 已冻结）**：这 4 位本轮仍是 **`ad_badge` 角标占位**——超限点击 = 轻提示，**零事件、零槽变化、零扣次、不调用任何 wx 广告 API、不拉起视频**。唯一 live 激励位是失败页续时，归 **S5 / §3.11**，不是本系统的第 4 个道具。
- 推论（不掩饰）：玩家**拿不到第 2 次道具效果**；扩展位同样**没有解锁路径**（无免费次数概念，又无广告发奖），扩容逻辑只能在单测/harness 注入验证。扩展位是否给「每关 1 次免费」仍 `[待确认]`，不由 S6 私定。
- 局内超限将来若唤醒（须另立项，且失败续时转化已验证）：超限点击 → 拉起 → `onRewarded` 成功后才清槽并记一次使用；加载失败 / 中途关闭 → 不清槽、不扣次。**本轮不做。**

## 6. 边界条件

> **偶数窗口居中偏向**：WXG-T-060 曾以「实现约定」记于本节，**WXG-T-062 已升格为 §2.2 表格内的明文规定**（左 2 右 3）。本节不再复述，避免两处漂移——基准与规定一律以 §2.2 为准。

**极端值**
- 棋盘无错位珠时使用 → 零 `powerup:used`、零格变化；扣次与否按 §2.3 已裁定**不扣**。
- `solverPlus` 时错位珠 < `SOLVER_PLUS_COUNT` → 全归、不补、事件仍恰 1 次（`affectedCells` 含实际受影响格）。
- 解环器目标的 T 格被错位珠 Y 占 → 单次交换（§2.2）；交换后 Y 仍错位（多环）→ 留待玩家/后续道具处理，**解环器不做链式递归**（一次点击至多解决选取的珠，行为可预测）。
- 解环器把**最后一颗**错位珠归位 → 完成判定照常触发 `level:cleared`（S3 写入路径与玩家归位路径完全同构，`bead-grid §2.3` 路径 B）。
- 同关内三道具各用 1 次 → 共 3 次成功效果（计数独立）；第 4 次任意道具点击进超限占位分支。

**并发 / 竞态**
- **与取回/归位争用同一颗珠**：同属**输入段**且每帧最多 1 条输入指令 ⇒ **不可能同帧**。跨帧时后到者按最新格态解释：目标珠已归位则重选下一颗错位珠；目标格已被占则按 §2.2 交换规则或重选。
- **与供料同帧**：**⛔ v1.3 作废**（供料段恒空，`core-loop §2.2.2`）。
- **`tray:expanded` 与道具请求同帧**：**⛔ v1.3 作废**（托盘零读写，S6 不消费 `tray:expanded`）。
- **`level:cleared` / `level:failed` 触发时**：S1 一旦离开 PLAYING，其后到达的道具请求全部作废。§2.3 单步结算，无瞄准中间态。
- **PAUSED 中请求与 resumed 同帧**：请求作废，不缓存、不重放（S2 §2.3 门禁优先）。

**非法输入**
- `type` ∉ `POWERUP_TYPES`（含 undefined / 拼写错 / **旧类型名 `region`/`clearAll`/`random`**）：忽略 + 警告日志，零事件零扣次，不崩溃——旧类型名不得静默映射到新类型。
- 非 PLAYING 状态（BOOT / PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH）收到道具请求：S6 二次防御性忽略（S2 已在路由层拦）。
- `affectedCells` 含非法格（越界 / `locked` / `filled(就位)`）：S3 拒绝该格写入 + 警告；实际写入集合与 payload 不一致时记漂移警告。
- 连点同一道具卡：帧内合并沿用 S2 §2.4 去抖窗口；跨帧第 2 次按 §2.5 计数规则处理（免费已尽 → 仅占位反馈）`（已裁定：MVP 不加独立冷却，沿用 S2 §2.4 去抖；§3 未冻结冷却值，不写）`。
- 镜像漂移（S6 认为某格错位、S3 已就位）：S3 重算目标选取并记警告供回归排查（幂等，不重复写入）。

## 8. 验收标准（可测试硬判据，QA 直接造用例；v1.3 随解环器反转整体改写——旧判据 1–10 不得再用；未标环境者均 `[Node]` vitest 可断言）

1. **solver 直移正确性**：构造错位珠 X 且其目标格 `empty` → 使用 `solver` → X 原格变 `empty`、目标格变 `filled(X.colorIdx)`（就位）；`powerup:used` 恰 1 次且 `affectedCells` 与 S3 实际写入格 1:1；`bead:placed` 恰 1 次（payload **无 `slot` 字段**）；托盘槽态使用前后逐一相等、`tray:*` 事件增量 = 0。
2. **solver 交换正确性**：构造二环（X 在 Y 的目标格、Y 在 X 的目标格）→ 使用 `solver` → 两格互换且**双双重回就位**；`bead:placed` 恰 2 次；构造多环（3+ 珠轮转）→ 仅选中的 X 被解决、Y 留在原格且仍 `misplaced`（无链式递归）。
3. **solverPlus 迭代与不补抽**：错位珠数分别为 5 与 2 时使用 `solverPlus` → 前者恰归位 `SOLVER_PLUS_COUNT`(3) 颗、后者全部归位（`affectedCells` 长度 = 实际受影响格数）；单次点击 `powerup:used` 恰 1 次。
4. **solverRandom 唯一随机源**：同一 seed 重复运行选中格相同；固定 seed 采样 200 次，错位格选中频次经**卡方检验**（α=0.01）与均匀分布**无显著差异**；架构守卫断言 S6 代码零 `Math.random`（`pnpm run check:arch`，铁律 L4）。（判例沿用 v1.2 卡方修订理由。）
5. **无错位珠不扣次**：棋盘全就位时使用任一解环器 → 事件计数 = 0、格态零变化、**不扣次**（§2.3）。
6. **就位珠/锁定格不可触碰**：解环器目标集合恒 ⊆ `filled(错位)` 格——构造含就位珠与 `locked` 格的关卡使用三型解环器各 1 次 → 就位珠与锁定格逐一不变。
7. **零托盘写入（v1.3 镜像改写，原「零网格写入」作废）**：三型解环器各用 1 次，使用前后**托盘全部槽态逐一相等**（`free`/`holding`/`selected` 计数与逐槽 colorIdx），S4 侧 `tray:stored`/`tray:selected`/`tray:expanded` 计数增量 = 0，且 S6 无对 S4 的直接调用（依赖/守卫断言）——**镜像对象由网格反转为托盘**：v1.2 判据「网格三计数相等」**已作废**（解环器正是要写网格：`misplaced` 计数应减少、`bead:placed` 应非零；**QA 不得按旧文把网格变化判成缺陷**）。与 `bead-grid §8-6`（双向性）、`tray-spawner §8-10`（替代判据）同批镜像，不得只改一侧。
8. **免费次数、超限占位与重置**：三道具计数互相独立（各 1 次 = 3 次成功效果）；同一道具第 2 次点击 → 零 `powerup:used`、零格变化、零扣次，仅 `ad_badge` 占位反馈，全程零 `wx` 广告 API 调用；失败重试（整关重置）后三计数回 `POWERUP_FREE_USES`（联合 `S5§8-6`）。角标视觉项 `[DevTools]`。
9. **空作用 / 非法 type / 状态门禁**：`type` 为旧类型名（`region`/`clearAll`/`random`）或非法值 → 忽略 + 警告、**不静默映射到新类型**、不崩溃；BOOT/PAUSED/LEVEL_CLEAR/GAME_OVER/FINISH 五态各注入道具请求 → 事件计数 = 0 且计数不扣。
10. **同帧竞态守恒**：注入「道具 vs 取回/归位同帧争用同一颗珠」→ 按 `core-loop §2.2.2` 帧内序解释（同属输入段者每帧最多 1 条指令故不可能同帧），跨帧后到者按最新格态重解释；无重复写入（幂等）、`powerup:used` 与 `bead:placed` 计数与预期序列 1:1、无负计数、无异常抛出。（原「道具 vs 供料同帧」「`tray:expanded` vs 道具」两组 ⛔ 随供料关停与托盘零读写作废。）
