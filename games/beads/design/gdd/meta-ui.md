## 1. 目标（为什么存在）

把关卡组织成「一张画 = 若干部面」，让玩家以**完成整图**为单位获得成品感与收藏驱动；连同主菜单页族入口规则写成可验收正本。回应用户 2026-09-18 批评（盘面珠子太少、缺连续珠、要图鉴），**不碰玩法内核**（Q1=甲）。

## 2. 机制

### 2.1 三层对象与命名（借词指代，标识符归代码）

```
Album（图鉴）    = 页族中的一页；整图的列表与收集视图，不持有玩法状态
 └─ Plate（整图）= 一幅完整拼豆画作；N 个 Cell-Level 的组织单位，完成态 = 其全部子版面完成
     └─ Cell-Level（子版面）= 一个盘面关卡 = **S1 状态机里的一局 PLAYING**（Q1=甲）
```

- **Cell-Level = 现有 LevelDef 的一个成员**，与 demo 8 关同构：同份行字符串图案（§3.2）、同套 `swaps` 构造与 BOOT 校验（§3.13）、同份计时（§3.5）、同套星级/结算/解锁（§3.7 / S7）、同套取回-归位裁决（`bead-grid §2.3`）。**本系统对这些零改写、零读写。**
- **不新增完成判定**：整图「完成」= 其 Cell-Level 的 `level:cleared` 已满，是**派生量**，不得成第二真源（S8 §2.3「可派生的值不入档」+ L5）。
- **命名纪律**：Album/Plate/Cell-Level 是**设计语义词**；代码标识符、JSON 字段名、存档键名归代码（D9，命名空间 `wxgame.beads.*`）。

### 2.2 整图 / 子版面数据结构（提案形态，**不含数值**）

```
Plate : { plateId, cellRefs[]（有序，指向现有 LevelDef）,
          宫格形态 = [待确认 · Q1/Q2/Q3], 图案来源(独立/切块/混合) = [待确认 · Q11] }
Album : { plateRefs[] }
完成态: completed(plate) = cellRefs 全部 completed（派生，不落档）
显示量: 整图进度 = completedCount / totalCells（**Q5 = 甲** ⇒ 纯显示；不参与结算 / 解锁）
```

- 进度归属（**Q5 = 甲** ⇒ 只读派生，**不因发奖/解锁扩档**）：现码两条档线——**S8 主档**（`unlockedLevel`/`stars[]`/settings）与 **meta sidecar**（体力/币/签到/购心记账，**无收集字段**）。收集进度语义属「进度」（S8 域）不属「钱包」（§3.14 域）。**本文只提案归属，键名与 schema 归代码（D9）。**
- **关卡数据链前置**：内容正本仍是 `design/levels/*.json` → 生成 `levels-data.ts`（ADR-0004 行字符串形态），校验器在 `config/levels.ts`（报错格式 `levels-spec §8`）。新增「图→格→关卡」映射 ⇒ 校验器扩面，**属 §10 CH-5；本文不动数据、不动代码。**

## 4. 输出与反馈

### 4.1 三层 Screen Flow（ASCII，本单落本文而非 `ux-spec`，理由见文首分工）

```
        点击小程序图标 ── BOOT ──► 玩法·普通 L1（runs==0）/ unlockedLevel 最远关（runs>0）
        （启动直进玩法 = 首屏即玩红线，本系统零扰动；ux-spec §1 原则1 / §6.3）
                                     │ 齿轮 → 暂停面板次钮「回主菜单」（弃本局棋盘，v1.29）
                                     ▼
     ┌──────────────── 主菜单（shell 屏 · 非启动落地页）────────────────┐
     │ 设置 / 签到（批0 已落码）  图鉴（本系统拟建页 · Q4 入口形态待裁）│
     │ 主钮「开始游戏」恒 = 全新开当前关 + 扣 1 心（§3.14）             │
     └──────────────────────────────┬───────────────────────────────────┘
                                    ▼
     【第一层】图鉴 Album ── 整图列表（缩略图 + 每张整图完成度呈现）
                                    │ 点选一张整图；**不受解锁门槛约束**（Q5 = 甲）
                                    ▼
     【第二层】整图 Plate ── 一屏只见「当前格」（Q2=甲）+ 整图缩略进度呈现
                                    │ 「进入本格」= 一次新局（体力扣减口径 = Q7 [待确认]）
                                    │ 相机旁路（meta 页族不缩放，ADR-0015 §3.4）
                                    ▼
     【第三层】子版面 Cell-Level = S1 的一局（玩法屏）
        BOOT 校验（BEAD_CHARSET + swaps ∈ §3.13 区间）→ PLAYING 取回/归位 → 
        ├ 错位全归位 → LEVEL_CLEAR → S7 星级结算 → 该格落位 → 回【第二层】
        ├ 倒计时归零 → GAME_OVER → 续时(§3.11)/重试(扣心 §3.14) → 留第三层
        └ 退出（次钮）→ 回【第二层】/回主菜单     ← 棋盘去留语义 = Q7-b [待确认]
                                    │ 整图全部格落位
                                    ▼
                    整图完成 → 收入图鉴（呈现形态 Q5；发奖与否 Q7-三；灰态/点亮态归 art 轨）
```

- **一屏只见一格**是第二层的硬形态（Q2=甲）：缩略整图仅作**进度呈现**，不得做成「九宫格各自可放大」——那会反翻 §2.3-2 的单相机前提。
- 整图灰态、完成格点亮态 = **美术规格**（归 art 轨另单），本文不定义色值/材质。
- 反馈：**0 文字教学**红线维持（`ux-spec §1` 原则 3 / GAP-03 裁定）；页族内按钮标签与页标题不属教学文字。

## 6. 边界条件

- **对 S2/S3/S4/S5/S6 零读写**：盘面/托盘/计时状态不由本系统持有（L5）；「进格即开新局」全走 S1 既有 BOOT→PLAYING，**不得**为图鉴开绕过 BOOT 校验的装载路径（`core-loop §2.1` 不允许带病进 PLAYING）。
- **缩略图 ≠ 可玩面**：第二层缩略必须纯只读呈现；点击缩略格「跳关」的合法性 `[待确认]`（牵 §3.7 线性解锁与 Q5-丙）。
- **数据不一致**：Plate 声明格集合与实际可装载 LevelDef 不符（缺格/越界/字符集外/`swaps` 越界）→ BOOT 期**拒收该图并降级**（沿 `levels-spec §8` 格式与 S8 §2.4「安全降级优先于报错」），不允许整图半可玩。
- **档面异常**：收集字段缺失/越界/来自高版本 → 按 S8 §2.4 逐字段钳正、不弃整档、不中断启动；sidecar 与主档**字段级隔离**（现码 `meta-save-schema` 降级即钳 `STAMINA_MAX` 界的同型处理）。
- **换图 / 时间跳变**：跨图跳转不得把上一局事件带进新图（每帧最多 1 条输入指令、离开 PLAYING 后请求一律忽略，`core-loop §2.2.2/§6`）；体力离线恢复依赖 `wallClock`（§3.14），本系统不自建恢复 tick。
- **非法点击**：页族遮罩外的玩法热区一律不响应；页族内无玩法热区，故不存在「误取珠/误归位」面（**Q4 = 甲** 已裁 ⇒ 双入口不采纳，本结论成立；若日后复批双入口，需同批复评 `ux-spec §4` 矩阵）。
