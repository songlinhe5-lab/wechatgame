# GDD · S1 核心循环（Core Loop）· beads

- 项目：`games/beads` · 版本 v1.0 · 任务号 WXG-T-007
- 数值纪律：本文只引用 `gdd/systems-index.md` §3 常量名，不写死数值（标注处除外）。

---

## 1. 目标

定义游戏状态机与关内主循环时序，把"供料 → 选珠 → 填色 → 判定"串成一条可持续产生"治愈 + 轻紧张"体验的循环，并裁决胜负流转。

## 2. 机制

### 2.1 游戏级状态机（六状态，沿用 breakout 判例，无主菜单）

```
BOOT ──► PLAYING ⇄ PAUSED
           │  │
           │  ├─ 图案填满 ──► LEVEL_CLEAR ── 有下一关 ─► PLAYING
           │  │                                   └── 全通关 ───► FINISH
           │  └─ 倒计时归零 ─► GAME_OVER ── 重试/下一关重开 ─► PLAYING（整关重置）
           │
           └─（暂停冻结所有计时与供料，表现层不冻结）
```

| 状态 | 职责 | 进入条件 | 退出条件 |
|---|---|---|---|
| `BOOT` | 读存档、装配关卡数据、校验图案矩阵（`BEAD_CHARSET` 判例） | 冷启动 | 数据合法 → PLAYING |
| `PLAYING` | 关内循环主状态：计时、供料、接受输入 | 上表 | 图案填满 / 倒计时归零 / 玩家暂停 |
| `PAUSED` | 冻结 S5 计时与 S4 供料；面板含「重玩本关」 | PLAYING 中点暂停 | 继续 → PLAYING；重玩 → 整关重置 → PLAYING |
| `LEVEL_CLEAR` | 结算星级、庆祝表现 | S3 报告"可填格全满" | 下一关（若 `levelId < DEMO_LEVEL_COUNT`）→ PLAYING；否则 → FINISH |
| `GAME_OVER` | 失败提示 + 「重试本关」 | S5 报告归零 | 重试 → 整关重置 → PLAYING |
| `FINISH` | 通关画面（8 关全清） | 最后关 LEVEL_CLEAR 确认 | 重玩第 1 关 → PLAYING |

**BOOT 降级边界**：存档缺失/越界/版本不匹配 → 安全降级进第 1 关（沿用 breakout 判例）；关卡数据校验失败 → 走 BOOT 内置错误占位，**不允许带病进入 PLAYING**。

### 2.2 关内微循环（PLAYING 的每秒心跳）

1. **供料**：S4 按 `SPAWN_INTERVAL_DEFAULT`（关卡可覆盖）生成 1 颗珠入随机空闲槽；满槽则跳过并广播 `tray:full`。
2. **选珠**：玩家点击托盘珠 → `tray:selected`，珠进入 `selected` 态。
3. **落子**：玩家点击网格空位 → S3 校验：
   - 空位 且 颜色匹配 → `bead:placed`（落座动画），该珠离开托盘；
   - 空位 但 颜色不匹配 → `bead:rejected`（抖动），珠留托盘、无惩罚；
   - 非空位/锁定格 → 忽略（无反馈噪声）。
4. **判定**：S3 每次落座后检查可填格是否全满 → `level:cleared`；S5 每秒检查归零 → `level:failed`。
5. **道具介入（可选支路）**：玩家点道具卡 → S6 清除托盘珠（`powerup:used`），改变槽位占用但不改变网格进度。

**循环闭环**：供料制造"空间压力"，填色释放压力并推进图案，完成瞬间同时清空时间与空间压力 → 一个可无限重复的自洽循环。

### 2.3 冲刺模式补记（2026-09-12 用户拍板，C8 条款；细则见 `gdd/score-combo.md` 与 systems-index §3.10）

- 冲刺模式 = PLAYING 内的**模式标志**（`mode: 'sprint'`），本节六状态机**零改动**，全部裁决复用上文。
- **stage 切换不断连**：梯级小图案填满即换下一 stage（`sprint:stage`），连击 streak 与倍率**跨 stage 延续**，不结算不弹窗。
- **加时与归零同帧，stage 优先**：stage 填满瞬间单局倒计时同时归零 → 先结算 stage 加时（`STAGE_BONUS_TIME`）；加时后 remaining > 0 继续爬梯，仍 ≤ 0 才判负（§6 cleared 优先裁决的 sprint 变体）。

## 6. 边界条件

**极端值**
- 图案无可填格（全锁定/预填）：BOOT 校验拒绝该关（≥1 可填格为关卡硬约束，归关卡校验器）。
- 剩余时间极短 + 托盘满：满槽告警与告急脉冲叠加不闪烁超频（≤3Hz 红线）。
- 供料 tick 与暂停同帧：暂停先冻结计时器，本帧不再供料。

**并发 / 竞态**
- 落子瞬间触发 `level:cleared` 与 `level:failed` 同帧：**cleared 优先**（S1 收到双信号按 cleared 裁决）——通关 generosity 判例。
- 道具清除与落子同帧争用同一颗托盘珠：以先到事件为准，后到者操作失效（珠已不在槽）。
- 扩展行解锁动画期间供料 tick：新槽立即可用，动画纯表现层。

**非法输入**
- 点锁定格 / 已填格：忽略，不播错误反馈（避免反馈噪声，§2.2）。
- 连续快速双击托盘珠：视为重选同一颗（幂等）。
- PAUSED 中任何玩法点击（除面板按钮）：全部忽略。

## 8. 验收标准（可测试硬判据，QA 直接造用例）

1. 冷启动无存档 → 直接进入第 1 关 PLAYING，全程无主菜单；有存档 → 续进已解锁最远关。
2. PLAYING 中每 `SPAWN_INTERVAL_DEFAULT`（关卡未覆盖时）托盘恰新增 1 颗珠，60 秒误差 ≤ ±1 颗。
3. 托盘 12 槽全占时供料停止，广播 `tray:full`，且**不触发失败**；使用任一清槽道具后供料恢复。
4. 颜色匹配落子 → 珠离托盘、格变 `filled`、`bead:placed` 恰发 1 次；不匹配 → 珠留原槽、格保持 `empty`、`bead:rejected` 恰发 1 次。
5. 可填格全满瞬间无论剩余时间多少 → 必进 LEVEL_CLEAR（同帧归零场景以 cleared 优先，用例：设剩余 0.01s 时放最后一颗）。
6. 倒计时归零且未满图 → 必进 GAME_OVER；重试后：倒计时回满、图案全清、托盘全清、扩展行重置、道具免费次数重置。
7. PAUSED 期间：剩余时间数值不变、不供料；继续后从暂停值恢复。
8. 通过第 n 关（n<8）→ 第 n+1 关解锁并可进；第 8 关通过 → 进 FINISH；FINISH 可重玩第 1 关。
9. 关卡数据含 `BEAD_CHARSET` 之外字符或全锁定格 → BOOT 拒绝进入该关（校验器报错，错误含关卡 id + 行列）。
10. 存档损坏/越界（如 unlockedLevel=99、stars 非法）→ 安全降级进第 1 关，不崩溃、不中断启动。
