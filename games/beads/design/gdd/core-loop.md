## 1. 目标

定义游戏状态机与关内主循环时序，把"初始错位 → 取回 → 归位 → 判定"串成一条可持续产生"治愈 + 解谜轻紧张"体验的循环，并裁决胜负流转。

## 2. 机制

### 2.1 游戏级状态机（六状态，沿用 breakout 判例，无主菜单）

```
BOOT ──► PLAYING ⇄ PAUSED
           │  │
           │  ├─ 错位珠全部归位（可填格全满）──► LEVEL_CLEAR ── 有下一关 ─► PLAYING
           │  │                                   └── 全通关 ───► FINISH
           │  └─ 倒计时归零 ─► GAME_OVER ── 重试/下一关重开 ─► PLAYING（整关重置 = 恢复初始错位布置）
           │
           └─（暂停冻结计时与输入裁决，表现层不冻结）
```

| 状态 | 职责 | 进入条件 | 退出条件 |
|---|---|---|---|
| `BOOT` | 读存档、装配关卡数据、校验图案矩阵（`BEAD_CHARSET` 判例）**与错位参数**（v2.0：`swaps` 合法性——坐标可填、每对珠色不同、对数 ∈ [`MISPLACED_PAIRS_MIN`, `MISPLACED_PAIRS_MAX`]，§3.13）并按序执行交换得初始布置 | 冷启动 | 数据合法 → PLAYING |
| `PLAYING` | 关内循环主状态：计时、接受输入（取回/归位/道具）、错位判定 | 上表 | 错位珠全部归位（可填格全满）/ 倒计时归零 / 玩家暂停 |
| `PAUSED` | 冻结 S5 计时与 S4 供料；面板含「重玩本关」 | PLAYING 中点暂停 | 继续 → PLAYING；重玩 → 整关重置 → PLAYING |
| `LEVEL_CLEAR` | 结算星级、庆祝表现 | S3 报告"可填格全满"（v2.0 语义 = **错位珠全部归位**，`filled` 数回到初始可填格总数） | 下一关（若 `levelId < DEMO_LEVEL_COUNT`）→ PLAYING；否则 → FINISH |
| `GAME_OVER` | 失败提示 + 「重试本关」 | S5 报告归零 | 重试 → 整关重置 → PLAYING |
| `FINISH` | 通关画面（8 关全清） | 最后关 LEVEL_CLEAR 确认 | 重玩第 1 关 → PLAYING；回主菜单 → 主菜单（shell 切屏，v2.3） |

**BOOT 降级边界**：存档缺失/越界/版本不匹配 → 安全降级进第 1 关（沿用 breakout 判例）；关卡数据校验失败 → 走 BOOT 内置错误占位，**不允许带病进入 PLAYING**。

### 2.2 关内微循环（PLAYING 的每秒心跳）

#### 2.2.1 玩法叙事序（**不是**执行序；v2.0 随「错位归位」核心循环重写，用户 2026-09-16 裁定）

0. **初始错位布置**（进关一次，非循环步）：BOOT 装配时棋盘**全满**——每格已有一颗珠，其中 **k 对**珠经 `swaps` 交换构造（§3.13）与底色错位（**错位珠**，颜色≠底色，**可选并高亮**）；**已就位珠**（颜色=底色）**不可选**；托盘初始为空。定时供料**关停**（案 A，§3.4 作废标注）——错位珠是珠子的唯一供给，托盘是纯缓冲。
1. **选错位珠（取回的起点）**：玩家点击错位珠 → `board:selected`，选择锚置 `board`（已就位珠/锁定格点击 = 极轻非惩罚反馈、零事件，裁定 4，`input-control §2.4`）。
2. **取回**：玩家点击托盘空槽 → 错位珠离格入槽：`tray:stored`（原格变 `empty`，槽变 `holding`）；**托盘满禁取珠**（无空槽 → 拒绝，极轻反馈零事件）。
3. **归位**：玩家点击托盘珠 → `tray:selected`（锚置 `tray`）；再点颜色匹配的空格 → `bead:placed`（落座动画），该珠离开托盘；颜色不匹配 → `bead:rejected`（抖动），珠留托盘、无惩罚。
4. **判定**：S3 每次 `bead:placed` 后检查可填格是否全满（= 错位珠全部归位）→ `level:cleared`；S5 每秒检查归零 → `level:failed`（失败条件**不变**）。
5. **道具介入（可选支路）**：玩家点道具卡 → S6 解环器自动归位错位珠（`powerup:used {type, affectedCells}`，S3 执行写入并逐格发 `bead:placed`），不触碰托盘。

> ⚠️ 本列表是**玩法叙事序**（玩家感知的因果链），**不是**固定步长循环里的执行顺序。两者混同会让判据不可测（曾致 Epic 文档把本列表直接读成「update 顺序」，见 `epics-beads.md §0` 更正注）。执行序见 §2.2.2。

**循环闭环**：错位珠制造"视觉失序"（颜色≠底色的冲突感即谜面），取回/归位恢复秩序并推进解谜，完成瞬间失序清零 → 一个可无限重复的自洽循环。空间压力由"托盘容量 vs 错位珠数"承载（k ≤ 8 ≪ `TRAY_BASE_SLOTS`，满槽禁取珠是软约束而非死锁——解环器与逆向归位始终可腾槽）。**v1.42 复注（WXG-T-203）**：§3.4 丙档扩容（12→24）后，小盘（≤18×18 部分错位）空间压力进一步松弛——压力主承载转向**时间预算（v1.41 规模闸）**与大盘取回节奏；满槽软约束性质不变（解环器/逆向归位仍可腾槽）。

#### 2.2.2 帧内执行序（**规范，唯一真源**；WXG-T-061 立、WXG-T-130 案 A 适配）

固定步长下每一帧的**执行顺序**如下。「同帧到达序」在单线程循环内**不可观测**——一帧内没有先后**事件**，只有代码**执行序**，因此凡是需要「同帧」裁决的条款，一律以本序为基准：

```
输入（段内序：状态指令 → 玩法事件）→ 连击窗（仅冲刺）→ 〔供料：案 A 关停后恒空段〕→ 计时
```

- **输入段内序**：**状态指令**（暂停/继续、扩展、选珠——`tray:selected` / `board:selected`、道具）→ **玩法事件**（**取回裁决** → `tray:stored`；**归位裁决** → `bead:placed` / `bead:rejected` → 完成判定 → `level:cleared`）。
- **取回归属（v2.0）**：`tray:stored` 是**输入段玩法事件**——S3 格态写入（`filled(错位)` → `empty`）与 S4 槽位写入（`free` → `holding`）在同一调用栈内原子完成，先广播后返回；与归位（`bead:placed`）**不可能同帧**（每帧最多 1 条输入指令）。取回**不触发完成判定**（错位珠离格只会减少 `filled`，不可能达成全满）。
- **v2.1 提交帧注（WXG-T-167；上位 `ADR-0015` §3.5 C-3 = (a)）**：**棋盘区**玩法事件（`board:selected` → 归位裁决 → `bead:placed` / `bead:rejected`）改在**抬起帧**进入输入段；**区外**（HUD / 托盘 / 道具卡 / 扩展钮 / 面板）仍在按下帧。段内序与段位**零改动**，仅棋盘区的投递时点后移一个「按下→抬起」区间 ⇒ 下游时长与判定帧的位移面见 §8 末「时基位移注」。
- **玩法事件段内序**（沿用）：**落子回执恒先于通关判定**（同一次归位调用栈内先 `bead:placed`、后 `level:cleared`）；而 **`level:failed` 属计时段**，故 `level:cleared`（输入段）**恒先于** `level:failed`（计时段）。
- **`cleared 优先` 的可观测机制**（§6）：输入段执行完若已离开 PLAYING，本帧**直接返回**，供料（恒空）与计时都不再执行 ⇒ 归零根本不会被判定。
- **供料段恒空（v2.0 案 A）**：定时供料关停（§3.4 作废标注）后 `_spawner.tick()` 为恒空段——**段位保留不删**，防止下游判据与帧内序基准漂移；供料复活须走 §6 变更 + 主理人确认。
- **每帧最多 1 条输入指令**（`input-control.md §2.4 / §8-10`）⇒ 同属输入段的两个**状态指令**不可能同帧发生；「同帧竞争」只可能发生在**不同段之间**（如输入段 vs 计时段）。
- **本序由实现承载**：`games/beads/src/game/beads-game.ts` 的 `_stepPlaying` 即此序（`_readInput()` → 冲刺连击窗 → `_spawner.tick()`〔关停后恒空〕→ `_timer.tick()`），并由 `games/beads/tests/frame-order.test.ts` 断言（WXG-T-061；v2.0 实现改造归工程后继，本条为规格承诺）。

**引用纪律**：其余 GDD 遇到「同帧」裁决时**引用本节**，不得各自复述——曾经的复述漂移（`pause-settings §6` 与 `timer-gameover §6` 表述不一致）已由 WXG-T-031 统一，本轮把剩余条款一并归口。

### 2.3 冲刺模式补记（2026-09-12 用户拍板，C8 条款；v2.0 案 A 适配；细则见 `gdd/score-combo.md` 与 systems-index §3.10）

- 冲刺模式 = PLAYING 内的**模式标志**（`mode: 'sprint'`），本节六状态机**零改动**，全部裁决复用上文。
- **stage 切换不断连**：梯级小图案错位全部归位即换下一 stage（`sprint:stage`），连击 streak 与倍率**跨 stage 延续**，不结算不弹窗。**取回不计分不断连**（`score-combo §2.4`，v2.0）。
- **stage 切换 = 新错位布置**（v2.0 案 A 适配）：换 stage 时托盘清空，新图案由 **`swaps` 交换构造**生成初始错位（不再有「新供料」——供料已关停，§3.10 C6 供料间隔段作废）。
- **加时与归零同帧，stage 优先**：stage 填满瞬间单局倒计时同时归零 → 先结算 stage 加时（`STAGE_BONUS_TIME`）；加时后 remaining > 0 继续爬梯，仍 ≤ 0 才判负（§6 cleared 优先裁决的 sprint 变体）。

## 6. 边界条件

**极端值**
- 图案无可填格（全锁定/预填）：BOOT 校验拒绝该关（≥1 可填格为关卡硬约束，归关卡校验器）。
- `swaps` 全部作废性非法（坐标不可填/同色对/对数越界）：BOOT 拒收该关（§3.13 校验规则）。
- 剩余时间极短 + 托盘满：托盘满只是**禁取回**（无告警事件）；告急脉冲不受影响（≤3Hz 红线内）。原「满槽告警叠加」随 `tray:full` 作废（§4）。
- 供料 tick 与暂停请求**同帧**：**该场景随供料关停不复存在**（供料段恒空，§2.2.2）；段位与裁决保留，供料复活时自动重新生效。

**并发 / 竞态**
- 取回与归位争用同一颗珠：**不可能同帧**——两者同属输入段、每帧最多 1 条输入指令（§2.2.2）。跨帧序：取回当帧生效（格变 `empty`、槽变 `holding`），下一帧归位请求携带最新状态。
- 归位瞬间 `level:cleared` 与 `level:failed` **同帧**：**cleared 优先**（通关 generosity 判例）。**机制**（§2.2.2）：`level:cleared` 属输入段玩法事件、`level:failed` 属计时段 ⇒ cleared 恒先；且输入段处理完已离开 PLAYING 时本帧**直接返回**，计时不再 tick。
- 取回的最后一颗错位珠：取回后棋盘 `filled` 减少，**不可能**触发 `level:cleared`（完成判定只挂在 `bead:placed` 后）；若玩家取回后倒计时归零，正常进 GAME_OVER（重开恢复初始错位布置）。
- 道具（解环器）与取回/归位争用：同属输入段 ⇒ 不可能同帧。跨帧时后到者按最新格态/槽态解释：目标珠已归位则解环器重选下一颗错位珠；目标格已被占则按 §3.6 交换规则或重选（`powerups §2.3`）。
- 扩展行解锁动画期间取回：新槽立即可作取回落点，动画纯表现层。

**非法输入**
- 点锁定格 / 已就位珠：极轻非惩罚反馈、**零事件**（裁定 4，复用 §8-5/G7 形态；不播错误反馈）。
- 托盘满时点空槽试图取回：**满槽禁取珠**——极轻反馈、零事件、格与槽零状态写（§3.13 取回前提）。
- 无 `board` 锚时点托盘空槽、无 `tray` 锚时点空格：无效落点轻提示、零事件（`input-control §2.4`）。
- 连续快速双击同一错位珠：视为重选同一颗（幂等）。
- PAUSED 中任何玩法点击（除面板按钮）：全部忽略。

## 8. 验收标准（可测试硬判据，QA 直接造用例）

1. 冷启动无存档 → 直接进入第 1 关 PLAYING，全程无主菜单；有存档 → 续进已解锁最远关。
2. **初始错位布置（v2.0 改写，原 16 颗供料判据作废）**：进 PLAYING 后棋盘 `filled` 总数 === 可填格总数、托盘全 `free`；`misplaced` 计数 === 2 × `swaps.length`（每对交换恰产生 2 颗错位珠，同色对已被 BOOT 拒绝）；已就位珠全部满足 `colorIdx === pattern(row,col)`。全关 60 秒内 `tray:spawned` 事件计数 === **0**（供料关停的可测反证；原「16 颗 ±0」判据随案 A 作废，**QA 不得按旧文把「零供料」判成缺陷**）。
3. **满槽禁取珠（v2.0 改写，原满槽跳供判据作废）**：托盘无空槽时点错位珠并点托盘任意槽 → **零事件**（`tray:stored` 计数 =0）、格保持 `filled(错位)`、槽态零变化、有极轻非惩罚反馈帧（复用 G7 判例形态，`input-control §8-5`）；腾出 ≥1 槽后同样操作 → 取回成功。**不触发失败**（D7 维持）。**v2.1 时基注（WXG-T-167）**：第一步「点错位珠」的 `board:selected` 现于**抬起帧**发出（棋盘区抬起才提交），第二步「点托盘槽」属区外、仍在按下帧 ⇒ 两步分属两个时基；本条主体（零事件）**不变**，仅用例需补 `up`（详 `input-control §8-11`）。
4. **取回与归位（v2.0 改写，覆盖原「落子」判据语义）**：取回（`board` 锚 + 点空槽）→ 原格变 `empty`、目标槽变 `holding(colorIdx)`、`tray:stored` 恰发 1 次（payload 含 slot/fromRow/fromCol/colorIdx）；归位（`tray` 锚 + 点匹配空格）→ 珠离槽（槽 `free`）、格变 `filled` 且 colorIdx 与底色一致、`bead:placed` 恰发 1 次；颜色不匹配 → 珠留原槽、格保持 `empty`、`bead:rejected` 恰发 1 次。取回与归位事件计数全程互斥同帧（每帧 ≤1 条输入指令）。**v2.1 时基注**：归位（`bead:placed` / `bead:rejected`）与棋盘区选珠现于**抬起帧**提交，取回落点（托盘槽）仍在按下帧；「事件恰发 1 次」的断言主体不变，发射手时基已后移 ⇒ 真链用例必须 `down` → 原地 `up`（位移 < 阈值 `[待确认]`）后才能断言事件已发。
5. 错位珠全部归位瞬间（可填格全满）无论剩余时间多少 → 必进 LEVEL_CLEAR（同帧归零场景以 cleared 优先，用例：设剩余 0.01s 时放最后一颗）。
6. 倒计时归零且未全部归位 → 必进 GAME_OVER；重试后：倒计时回满、**恢复初始错位布置**（错位珠逐格回到关卡 `swaps` 装配态，非全空）、托盘全清、扩展行重置、道具免费次数重置。
7. PAUSED 期间：剩余时间数值不变、零取回零归位；继续后从暂停值恢复。
8. 通过第 n 关（n<8）→ 第 n+1 关解锁并可进；第 8 关通过 → 进 FINISH；FINISH 可重玩第 1 关、可回主菜单（v2.3：上报意图、切屏归 shell，同暂停面板 go-menu 判例）。
9. 关卡数据含 `BEAD_CHARSET` 之外字符、全锁定格、或 `swaps` 非法（坐标不可填 / 同色对 / 对数 ∉ [`MISPLACED_PAIRS_MIN`, `MISPLACED_PAIRS_MAX`]）→ BOOT 拒绝进入该关（校验器报错，错误含关卡 id + 行列）。
10. 存档损坏/越界（如 unlockedLevel=99、stars 非法）→ 安全降级进第 1 关，不崩溃、不中断启动。
