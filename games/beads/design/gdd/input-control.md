# GDD · S2 输入与操控（Input Control）· beads

- 项目：`games/beads` · 版本 v2.2 · 任务号 WXG-T-141（v2.2 = 多点触控条款修订：双指捏合缩放列 Should——仅手势、无滑轨控件；v2.1 = `swap` 格间直换由「Should 待冻结」改**裁定永不实现**；v2.0 = 统一选择锚 + 取回/归位路由；v1.0–v1.2 见 §9）
- 数值纪律：只引用 `systems-index §3` 常量名（本篇主要 §3.8 热区、§3.1 布局带）。
- 依赖锚点：`core-loop.md` §2.2 第 2/3 步（选珠与落子）；非法输入清单沿用 core-loop §6。

---

## 1. 目标

把触摸输入路由为六类游戏指令（选归位珠 / 选错位珠 / 取回 / 归位 / 道具 / 扩展 / 暂停——归并为「选择类 + 落点类 + 面板类」三族），执行热区命中与状态门禁，保证"点哪是哪、错点无害"。

## 2. 机制

### 2.1 触摸路由表（单指点击，无拖拽/长按；v2.0 = 统一选择锚）

**统一选择锚（v2.0 核心机制）**：`selection ∈ {tray, board, none}`——`tray` = 托盘珠选中（`tray:selected`）、`board` = 错位珠选中（`board:selected`）、`none` = 无选中。**三值互斥**：任何一次成功选择都会清除另一侧的选中（换选即转移，不叠选）。带级次序（下表优先级 1–5）**不变**。

| 优先级 | 命中区 | PLAYING 行为（按 `selection` 分支） | 出口 |
|---|---|---|---|
| 1 | 暂停按钮（HUD 带，避开 `CAPSULE_AVOID`） | 请求 S9 暂停 | S9 |
| 2 | 道具卡 ×3（`POWERUP_BAND`） | 请求使用对应道具（解环器，`powerups §2.2`） | S6 |
| 3 | `btn_expand`（`TRAY_BAND`） | 请求扩展托盘 | S4/S6 |
| 4 | **托盘区**（`TRAY_BAND`）——**内部分支**：4a `holding` 槽（珠）；4b 空槽（`free`） | **4a**：选中/换选该珠 → 锚置 `tray`（若原锚 `board`，同时清除错位珠选中）。**4b**：锚 = `board` 且托盘有空槽 → **取回**（S3/S4，`tray:stored`）；锚 = `board` 且**满槽** → 拒绝（极轻反馈，零事件，§3.13）；锚 ∈ {`tray`, `none`} → 无效落点轻提示（零事件） | S4 / S3+S4 |
| 5 | **网格区**（`PUZZLE_BAND`）——**内部分支**：5a `filled(错位)` 格；5b `empty` 格；5c `locked` / `filled(就位)` 格 | **5a**：选中/换选该错位珠 → 锚置 `board`（`board:selected`；若原锚 `tray`，同时清除托盘珠选中）。**5b**：锚 = `tray` → 归位请求（S3 裁决 placed/rejected）；锚 ∈ {`board`, `none`} → 无效落点轻提示（零事件——`board` 锚的合法落点是托盘空槽，不是网格）。**5c**：极轻非惩罚反馈（零事件，裁定 4，§2.4） | S4（选中）/ S3（裁决） |

- 路由**自上而下短路**：一次触摸只命中优先级最高的一区；面板/弹窗（PAUSED、结算）打开时，2–5 全部屏蔽。
- 优先级 3 的出口列按 `powerups.md §2.6` 布局 A 当前**降级**为「命中即吞 + 一次性占位轻提示」，不发 `tray:expanded`；冲突登记与裁决见 §8-1（BD-37），几何与热区见 §2.2。
- **格间不直换（v2.0 立，v2.1 裁定冻结）**：错位珠与空格之间**必经托盘**（取回 → 归位两步）。**`swap`（格间直换）= 永不实现**（v2.1，WXG-T-138，提案 `proposals/v1.23-bold-remake.md` Q2，用户拍板）：「过一道手」= 手作拼豆的触感本体；且直接交换是环谜题的作弊器——托盘 2 槽即可滚窗解任意置换（提案 §5 诚实修正），**必经托盘 + 小托盘滚窗（`TRAY_BASE_SLOTS`=6）才是操作深度所在**。S3 不接受任何格间转移请求，工程无需为 swap 预留接口。

### 2.2 热区规则（来源 §3.8）

- 最小热区 `TOUCH_MIN` = 88px（≈44pt）。
- 网格珠名义尺寸 `BEAD_CELL` < 88 → 命中区**外扩 8px**（即 66×66），相邻外扩区重叠时按格中心最近者命中；仍不足 88 的极端小格不再扩大（防止跨格误触，66px 为 demo 接受值，QQ 验收以 §8 判据 4 为准）。
- 托盘珠名义 `TRAY_SLOT` < 88 → 同规则外扩 8px（62×62）。
- 按钮类（暂停/道具卡/扩展）实际尺寸 ≥ 88 直接用名义框。
- **`btn_expand` 是本条的反例（WXG-T-097/BD-15，依 `art/accessibility.md` C1）**：视觉 **132×48**（`assets-spec §1.3`）高 48 < `TOUCH_MIN` ⇒ **热区扩至 132×88、视觉不变**（同心，视觉 y∈[250,298] / 热区 y∈[230,318]）。落位与尺寸的唯一真源 = `systems-index §3.4`（v1.20：`TRAY_BAND` 上沿 420→450、托盘面板改**贴带上沿**，腾出带下沿），渲染与命中同源 `tuning.ts::expandButtonLayout()`，不存在「画出的框 ≠ 点击落点」漂移（WXG-T-062 判例）。热区与扩展态最上排槽热区实测净空 **11px** ⇒ 不与判据 2 的「重叠区最近格心」仲裁冲突，无需加例外条。

### 2.3 状态门禁（什么状态下点什么有效）

| 状态 | 有效输入 |
|---|---|
| `PLAYING` | 上表全部 |
| `PAUSED` | 仅暂停面板按钮（继续/重玩本关/音量开关） |
| `LEVEL_CLEAR` / `GAME_OVER` / `FINISH` | 仅**各自面板**的按钮——过关：下一关 / 去冲刺；失败：续时 / 重试本关；通关：去冲刺 / 重玩第 1 关（**面板外零响应**；逐相位独立可测判据见 §8-8b/8c/8d） |
| `BOOT` | 全部忽略 |

- **归位前置条件（v2.0）**：锚 = `tray`（存在 `selected` 托盘珠）；锚 ∈ {`board`, `none`} 时点空格 → 轻提示（视觉层），**不发归位请求**。
- **取回前置条件（v2.0）**：锚 = `board`（存在 `selected` 错位珠）**且托盘有空槽**；两条件缺一时点托盘空槽 → 极轻反馈或轻提示（见 §2.1 路由 4b），**不发取回请求**。

### 2.4 非法输入处理（对齐 core-loop §6）

- 锁定格 / **已就位珠**（v2.0：`filled` 且珠色=底色；**错位珠不适用本条**，错位珠可选中）点击：路由到 S3 但 S3 静默忽略——**零事件、零扣次、零状态写**；S2 层播**极轻非惩罚反馈**（WXG-T-128，2026-09-16 用户裁定；WXG-T-130 v2.0 维持同形态、对象由「已填格」收窄为「已就位珠」）：被点格 scale 1.00→0.96→1.00（120ms）+ 极轻闷「哒」（`sfx_denied`，待原子落码）；**零位移、零红、零色变**，`reduceMotion` 开 ⇒ 退为 1px `slot_border` 静态描边环。视觉规格 = `art-bible §7.3.7` / `assets-spec §1.6.7`；矩阵行 = `ux-spec §4`；毫秒真源 = `ux-spec §5`「不可填格轻压」。**与「放错拒绝」（`bead:rejected`）严格区分**：本条不发事件 ⇒ 不占 `systems-index §3.8`「错误反馈 ≤2 次/秒」预算；a11y 口径 = `accessibility` D1/D2/A5⑦/A6。**零噪声原则的适用边界**：仍适用于**自动事件**，不再否决**玩家主动点击**的确认反馈。
- **满槽取回（v2.0 新增）**：锚 = `board` 且托盘无空槽时点托盘任意槽 → **拒绝**：零事件（`tray:stored` 计数 =0）、零状态写 + 极轻非惩罚反馈（同上形态；用户 2026-09-16 确认「托盘满禁取珠」）。判据见 §8-11。
- 连续快速双击同托盘珠/同错位珠：幂等，第二次不产生新指令（对 S4/S3 的去抖窗口 = 1 帧内合并；此处「帧」= **固定步**，见 §8-3 时基口径）。
- 多点触控：MVP 只取第一触点，其余忽略；不缩放、不旋转。**v2.2（Should，未冻结未实现）**：棋盘若引入缩放/平移，**只做双指捏合手势**，不提供滑轨/按钮控件（用户 2026-09-17 对参考竞品「放大镜 + 竖滑轨」的裁定：仅手势即可）；实现前 §8-9 判据与本文路由不变。

## 4. 输出与反馈

| 指令/事件 | 条件 | 对齐 |
|---|---|---|
| `tray:selected {slot, colorIdx}` | 点 holding 槽（4a） | `selected` 态表现 assets-spec §1.2；锚置 `tray` |
| `board:selected {row, col, colorIdx}` | 点错位珠（5a；v2.0 新增） | 错位珠高亮（`ux-spec §5`「错位珠选中」行）；锚置 `board` |
| 取回请求 `(row, col, targetSlot)` → S3/S4 | 锚 = `board` 且点空槽且有空槽（4b） | S3/S4 同帧原子写入，`tray:stored` |
| 归位请求 `(row, col, colorIdx, slot)` → S3 | 锚 = `tray` 且点 `empty` 可判格（5b） | S3 裁决后反馈（placed/rejected） |
| 无前置点空格 / 点托盘空槽 | — | 轻提示（视觉层定义，不进 S3/S4；v2.0：`board` 锚点空槽属取回前置缺口，同走轻提示） |
| 满槽取回拒绝 | 锚 = `board`、满槽（4b） | 极轻非惩罚反馈，零事件（§2.4） |
| 暂停/道具/扩展请求 | 各归 S9/S6/S4 | — |

## 6. 边界条件

**极端值**
- 外扩命中区重叠（网格高密度区）：按"格中心欧氏距离最近"裁决，平局取 row 小者。
- 触摸点落在布局带间隙（如托盘与道具卡之间）：无命中，静默忽略。
- 连续极速点击（>10 次/秒）：每帧最多处理 1 条指令（「帧」= **固定步**，见 §8-3 时基口径），其余丢弃（防指令洪泛）。

**并发 / 竞态**
- 同帧先选珠后点落点「双事件」：**不可能同帧** —— 每帧最多 1 条输入指令（「帧」= **固定步**，见 §8-3；§2.4 / §8-10），选择与落点分属相邻两帧；跨帧时选择当帧生效、下一帧落点请求携带新锚态（S3/S4 收到时序仍串行）。WXG-T-061 换基准。v2.0：选错位珠（5a）与取回（4b）、选托盘珠（4a）与归位（5b）同此口径。
- 道具请求与暂停请求同帧：**不可能同帧**（同属输入段）。同帧内按 `core-loop §2.2.2` 输入段内序——齿轮（**状态指令**）先于道具（**玩法事件**）⇒ 等效结论仍是暂停优先、道具请求作废。
- `level:cleared` 与其后的取回/归位请求：两者同属输入段 ⇒ 本帧内不可能先后发生；跨帧时 cleared 之后的请求由 S3/S1 状态机忽略（对齐 `core-loop §6`）。

**非法输入**
- PAUSED 中点击玩法区：全忽略（含误触网格/托盘）。
- 越界坐标（<0 或 >750/1334）：忽略。
- `BOOT` 期任何触摸：忽略。

## 8. 验收标准（可测试硬判据，QA 直接造用例）

1. **6 类指令逐一验证路由正确（v2.0 扩充）**：点暂停→PAUSED；点道具卡→S6 收请求；点扩展→S4 收请求；点托盘珠→`tray:selected`（锚=`tray`）；点错位珠→`board:selected`（锚=`board`）；托盘空槽（锚=`board`）→S3/S4 收取回请求；空格（锚=`tray`）→S3 收归位请求。**判据冲突登记（BD-37，WXG-T-097/BD-15）**：本条的「点扩展→S4 收请求」在当前产品形态下**不可达**——`powerups.md §2.6` 布局 A 与 `ux-spec §4` 矩阵「点扩展 | 角标占位（MVP 无解锁路径）」写定本轮**无扩展解锁路径**，⇒ 实装行为是「命中即吞掉 + 一次性占位轻提示，零事件、零槽变化、零扣次、不调 wx 广告 API」，S4 收请求属**扩展解锁上线后**的行为。裁决：`§2.6` 布局 A 为当前有效产品决策，本条**不降格为已验**，QA 对「点扩展→S4 收请求」记 ⛔ 不可验（不得因占位实装而打 PASS）；解锁路径落地时同批改写本条与 `ux-spec §4` 该行。
2. 热区：在格中心偏移 ≤ 外扩边界内点击必命中该格；命中区外点击（带间隙处）零事件。**重叠优先级裁定（BD-23，WXG-T-091）：因 `BEAD_PITCH`(52) `<` 命中区(66)，网格内部外扩区必然重叠，此时一律以判据 4「最近格心」裁决为准——本条「偏移 ≤ 外扩边界内必命中本格」只在无重叠区成立；网格内部不存在带间隙处，「零事件」仅在网格外围验证。**
3. 一次触摸仅触发一条指令（监听计数器总和 =1），面板打开时玩法区点击计数 =0。**时基口径（WXG-T-115；与 WXG-T-113 修法对齐）**：本条「一次触摸」与 §8-10「一帧」的时基 = 游戏循环的**固定步**（`GameLoop.fixedDt`，即「**一个固定步 = 一次输入帧**」），**非渲染 tick**；§2.4 / §6 所述「帧」（输入帧）同义。⇒ **丢帧 / 卡顿使一个 tick 承载 N 个固定步（N>1）时，同一次物理触摸仍只准投递一条指令，不得因子步重放而重复触发**（一次性输入标志的生命周期绑定固定步，同一 tick 的后续子步不得二次读到同一次按下）。本条同时覆盖**相位切换落穿**：面板按钮一次点击只准触发该按钮的**一条**指令，不得在同 tick 后续子步于新相位里再触发第二条（如点「继续」不得顺手落子）。该口径由框架 `App._fixedUpdate`（每固定子步一次 `beginFrame`/`endFrame`）保证；**若实现在丢帧多子步下未达此口径，须如实登记为缺陷，不得放宽本条**。
4. 13 列满密度网格外扩命中区重叠时：点击点距哪格格心最近即命中哪格（构造相邻两格中点 ±1px 用例）。
5. 锁定格/**已就位珠**点击：S2 与 S3 **事件计数均为 0**（零事件、零扣次、零状态写）；**有极轻非惩罚反馈帧**——被点格自点击帧起 120ms 内出现 scale < 1.00 的绘制命令（`reduceMotion` 开 ⇒ 改为 1px `slot_border` 静态描边环、零形变）。**判据改写依据（WXG-T-128 v1.2，2026-09-16 用户裁定；WXG-T-130 v2.0 对象收窄）**：原文「**无任何视觉反馈帧**」已被推翻（原口径源自「零噪声原则」，用户裁定改为对齐竞品 pop-it「按下总有凹陷态」的极轻确认）⇒ **QA 不得再按旧文把 G7 轻压判成缺陷**；本条的硬判据主体从「零反馈」转为「**零事件**」（事件计数 =0 仍是不可放宽的红线：本交互绝不进 S3 状态机、绝不扣道具次数）。**v2.0 收窄注记**：v1.2 的「已填格」现拆为「已就位珠（零事件 + 轻压）」与「错位珠（可选中，走 `board:selected`）」两态——**QA 不得把错位珠的 `board:selected` 判成「对已填格产生了事件」的缺陷**。可测形式：`[Node]` 真链点击锁定/已就位珠 ⇒ 监听器事件增量 0 + `buildRenderModel()` 命令流中该格出现 scale 覆写（或 reduceMotion 分支下出现描边环命令）。
6. 双击同托盘珠：`tray:selected` 仅 1 次；双击不同珠（换选）：2 次，最终后者 selected。
7. 无 `tray` 锚点空格：不发归位请求（S3 请求计数 =0），有轻提示。**与判据 5 的交界（WXG-T-097/BD-16；WXG-T-128 v1.2 重述；WXG-T-130 v2.0 适配）**：本条只在被点格为「可落空格（empty）」时成立；锁定格 / 已就位珠走判据 5（**零事件 + 极轻非惩罚反馈**）；错位珠走路由 5a（`board:selected`）。两条**仍互斥于「被点格状态」这一个维度**，但反馈通道**不同**：本条 = 一次性**文字气泡**（告知「未选珠」这一前置缺口），判据 5 = 被点格**scale 形变**（确认「这格点不动」）。**轻提示不是「非法输入兼底」**：它只回答「未选珠」，不回答「格子不可填」。
8. PAUSED 状态点击托盘/网格/道具：全部忽略；仅面板按钮响应。

> **追加判据（WXG-T-115）**：以下 `8b` / `8c` / `8d` 补齐 `LEVEL_CLEAR` / `GAME_OVER` / `FINISH` 三相位的**独立可测门禁**——三相位此前仅有 §2.3 规范、§8 无可测条目（`PAUSED` 门禁见判据 8）。**编号采后缀、不整体重排判据 1–10**（同 `audio-events A05-09b` 判例，用户 2026-09-15 裁定 A）。每条含「判据原文 / 环境道次 / 可测形式 / 来源标注」四要素。

**8b（`LEVEL_CLEAR` 门禁）**
- **判据原文**：`LEVEL_CLEAR` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅结算（过关）面板上的按钮响应**（下一关 / 去冲刺）；面板外点击**零命中、不推进**（不误触「下一关」、不误开冲刺）。
- **环境道次**：`[Node]` / `[Probe]` 真链（✅ 可执行）＋ `[Harness]` 真指针（✅ 可执行）＋ `[Device]`/`[R]` 真机（**⛔ 无 AppID / 无真机**；解除条件 = 有 AppID → `build:cocos:wx` 出包 → 微信开发者工具 / 真机可跑 → 同一真链探针在 `wx` 宿主复取按钮命中）。
- **可测形式**：经 `InputManager` 真链（`beginFrame → push({phase:'down'}) → push({phase:'up'}) → update(dt) → endFrame(dt)`，与 `App._fixedUpdate` 同形）点「下一关」中心 ⇒ 相位 `level-clear → playing`、`levelIndex n → n+1`；点面板外（非任何按钮热区）⇒ 事件增量 **0**、相位与关卡号不变（**负向非平凡真**：点击确已到达 `_handleTap`）。
- **来源标注**：`§2.3` 状态门禁表第 3 行；`ux-spec §4` 流转表 `LEVEL_CLEAR` 行（＋`§3.3` 面板）；实现锚点 `games/beads/src/game/beads-game.ts` `case 'level-clear'`（**只读核对，不据以实现改判据**）。

**8c（`GAME_OVER` 门禁）**
- **判据原文**：`GAME_OVER` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅失败（结算）面板上的按钮响应**——普通局：**续时**「+N 秒继续本关」/ **重试本关**；冲刺局：**再来一局** / **返回关卡**；面板外点击**零命中、不重开**（不误触续时、不误触重试）。
- **环境道次**：同 8b（`[Node]`/`[Probe]` 真链 ✅ ＋ `[Harness]` 真指针 ✅ ＋ `[Device]`/`[R]` **⛔**，解除条件同 8b）。
- **可测形式**：真链点「重试本关」中心 ⇒ `game-over → playing`、`filled=0`（整关重置）；点面板外 ⇒ 事件增量 **0**、相位不变。**冲刺局子分支**（`_mode==='sprint'`）：真链点「再来一局 / 返回关卡」⇒ `playing`；面板外零响应。
- **来源标注**：`§2.3` 第 3 行；`timer-gameover §8-6`（失败页整关重置）；`ux-spec §4`（`GAME_OVER` 普通段 + 冲刺结算段）＋ `§3.5`；实现锚点 `beads-game.ts` `case 'game-over'`。

**8d（`FINISH` 门禁）**
- **判据原文**：`FINISH` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅通关面板上的按钮响应**（去冲刺 / 重玩第 1 关）；面板外点击**零命中、不误触**（不误开冲刺、不误触重玩）。
- **环境道次**：同 8b（**⛔ 真机解除条件同 8b**）。
- **可测形式**：真链点「重玩第 1 关」中心 ⇒ `finish → playing`、`levelIndex=0`；点面板外 ⇒ 事件增量 **0**、相位不变。
- **来源标注**：`§2.3` 第 3 行；`ux-spec §4` 矩阵行 `FINISH`（＋`§3.6` 通关画面）；实现锚点 `beads-game.ts` `case 'finish'`。

> **编号理由（为何采 `8b/8c/8d` 后缀，而非并入判据 8 或整体重排）**：判据 8 主体是 `PAUSED`，其按钮集（继续 / 重玩本关 / 音量开关）与三相位的「过关 / 失败 / 通关」按钮集**互不相同**，合并会丢失 **1:1 可测性**（一条用例无法同时断言四种相位迁移与四套按钮集）；整体重排会牵动台账与既有证据引用（成本更高）。⇒ 采后缀（同 `audio-events A05-09b` 判例）。

9. 多点触控（双指同帧）：仅第一触点生效，指令数 =1。
10. 每帧指令上限：注入 20 次触摸/帧（「帧」= **固定步**，同 §8-3 时基口径），仅 1 条进入路由，无崩溃、无事件错序。**多子步口径（WXG-T-115）**：在**一个 tick 的 N 个固定步**下注入 **1** 次触摸，路由计数仍 **=1**（**丢帧不得把同一次触摸放大为 N 条指令**）；在一个固定步内注入 20 次触摸，仅 1 条进入路由。

> **追加判据（WXG-T-130，v2.0）**：以下 `8-11` / `8-12` 补齐 v2.0 新交互（取回 / 选择锚互斥）的独立可测条目。编号采后缀式追加（同 `8b/8c/8d` 判例，不整体重排）。

**8-11（满槽禁取珠）**
- **判据原文**：锚 = `board`（错位珠已选中）且托盘无空槽时点击任意托盘槽 → **零事件**（`tray:stored` 计数 =0）、错位珠保持 `filled(错位)`、槽态零变化；有极轻非惩罚反馈帧（同判据 5 形态）。
- **环境道次**：`[Node]` / `[Probe]` 真链 ✅ ＋ `[Harness]` 真指针 ✅ ＋ `[Device]`/`[R]` ⛔（解除条件同 8b）。
- **可测形式**：构造托盘全 `holding` 局面 → 真链点错位珠（断言 `board:selected` 恰 1 次）→ 点任一槽 ⇒ 监听器事件增量 0、`buildRenderModel()` 中该格无离格命令、出现 scale 覆写或描边环命令；腾出 1 槽后重复 → `tray:stored` 恰 1 次。
- **来源标注**：`§2.1` 路由 4b / `§2.4` 满槽取回条；`systems-index §3.13` 取回前提行；`core-loop §8-3`；用户裁定「托盘满禁取珠」（2026-09-16）。

**8-12（选择锚互斥与转移）**
- **判据原文**：`selection ∈ {tray, board, none}` **恒互斥**——任意时刻至多一侧存在选中态；任何新选择清除旧锚（换选即转移）；带级次序不受锚态影响（锚 = `board` 时点托盘珠仍优先命中 4a、点道具卡仍命中 2）。
- **环境道次**：同 8-11。
- **可测形式**：真链点错位珠 A（`board:selected` 1 次）→ 点托盘珠 B ⇒ `tray:selected` 恰 1 次、且 A 的选中态绘制命令消失（`buildRenderModel()` 中 A 无 `selected` 参数）；反向序列对称断言。再注入「锚 = `board` 时点道具卡」⇒ S6 收请求、锚态不变。
- **来源标注**：`§2.1` 统一选择锚定义；`bead-grid §2.2`（`selected` 表现层态互斥）；`ux-spec §4` 新增三行（`tray:stored` / `board:selected` / 满槽拒取回）。
