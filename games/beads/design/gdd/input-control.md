## 1. 目标

把触摸输入路由为五类游戏指令（选珠 / 落子 / 道具 / 扩展 / 暂停），执行热区命中与状态门禁，保证"点哪是哪、错点无害"。

## 2. 机制

### 2.1 触摸路由表（单指点击，无拖拽/长按——复刻参考玩法）

| 优先级 | 命中区 | PLAYING 行为 | 出口 |
|---|---|---|---|
| 1 | 暂停按钮（HUD 带，避开 `CAPSULE_AVOID`） | 请求 S9 暂停 | S9 |
| 2 | 道具卡 ×3（`POWERUP_BAND`） | 请求使用对应道具 | S6 |
| 3 | `btn_expand`（`TRAY_BAND`） | 请求扩展托盘 | S4/S6 |
| 4 | 托盘珠（`TRAY_BAND`，holding 槽） | 选中/换选 | S4 |
| 5 | 网格格位（`PUZZLE_BAND`） | 落子请求（需当前有选中珠） | S3 |

- 路由**自上而下短路**：一次触摸只命中优先级最高的一区；面板/弹窗（PAUSED、结算）打开时，2–5 全部屏蔽。
- 优先级 3 的出口列按 `powerups.md §2.6` 布局 A 当前**降级**为「命中即吞 + 一次性占位轻提示」，不发 `tray:expanded`；冲突登记与裁决见 §8-1（BD-37），几何与热区见 §2.2。

### 2.2 热区规则（来源 §3.8）

- 最小热区 `TOUCH_MIN` = 88px（≈44pt）。
- 网格珠名义尺寸 `BEAD_CELL` < 88 → 命中区**外扩 8px**（即 66×66），相邻外扩区重叠时按格中心最近者命中；仍不足 88 的极端小格不再扩大（防止跨格误触，66px 为 demo 接受值，QQ 验收以 §8 判据 4 为准）。
- 托盘珠名义 `TRAY_SLOT` < 88 → 同规则外扩 8px（62×62）。
- 按钮类（暂停/道具卡/扩展）实际尺寸 ≥ 88 直接用名义框。
- **`btn_expand` 是本条的反例（WXG-T-097/BD-15，依 `art/accessibility.md` C1）**：视觉 **132×48**（`assets-spec §1.3`）高 48 < `TOUCH_MIN` ⇒ **热区扩至 132×88、视觉不变**（同心，视觉 y∈[250,298] / 热区 y∈[230,318]）。落位与尺寸的唯一真源 = `systems-index §3.4`（v1.20：`TRAY_BAND` 上沿 420→450、托盘面板改**贴带上沿**，腾出带下沿），渲染与命中同源 `tuning.ts::expandButtonLayout()`，不存在「画出的框 ≠ 点击落点」漂移（WXG-T-062 判例）。热区与扩展态最上排槽热区实测净空 **11px** ⇒ 不与判据 2 的「重叠区最近格心」仲裁冲突，无需加例外条。

### 2.3 状态门禁（什么状态下点什么有效）

| 状态 | 有效输入 |
|---|---|
| `PLAYING` | 上表全部 |
| `PAUSED` | 仅暂停面板按钮（继续/重玩本关/音量开关） |
| `LEVEL_CLEAR` / `GAME_OVER` / `FINISH` | 仅**各自面板**的按钮——过关：下一关 / 去冲刺；失败：续时 / 重试本关；通关：去冲刺 / 重玩第 1 关（**面板外零响应**；逐相位独立可测判据见 §8-8b/8c/8d） |
| `BOOT` | 全部忽略 |

- 落子前置条件：当前存在 `selected` 托盘珠；无选中时点网格 → 轻提示（视觉层），**不发落子请求**。

### 2.4 非法输入处理（对齐 core-loop §6）

- 锁定格 / 已填格点击：路由到 S3 但 S3 静默忽略——S2 层**同样不播任何反馈**（零噪声原则）。
- 连续快速双击同托盘珠：幂等，第二次不产生新指令（对 S4 的去抖窗口 = 1 帧内合并；此处「帧」= **固定步**，见 §8-3 时基口径）。
- 多点触控：只取第一触点，其余忽略；不缩放、不旋转。

## 6. 边界条件

**极端值**
- 外扩命中区重叠（网格高密度区）：按"格中心欧氏距离最近"裁决，平局取 row 小者。
- 触摸点落在布局带间隙（如托盘与道具卡之间）：无命中，静默忽略。
- 连续极速点击（>10 次/秒）：每帧最多处理 1 条指令（「帧」= **固定步**，见 §8-3 时基口径），其余丢弃（防指令洪泛）。

**并发 / 竞态**
- 同帧先选珠后点网格「双事件」：**不可能同帧** —— 每帧最多 1 条输入指令（「帧」= **固定步**，见 §8-3；§2.4 / §8-10），选珠与落子分属相邻两帧；跨帧时选珠当帧生效、下一帧落子请求携带新选中色（S3 收到时序仍串行）。WXG-T-061 换基准。
- 道具请求与暂停请求同帧：**不可能同帧**（同属输入段）。同帧内按 `core-loop §2.2.2` 输入段内序——齿轮（**状态指令**）先于道具（**玩法事件**）⇒ 等效结论仍是暂停优先、道具请求作废。
- `level:cleared` 与其后的落子请求：两者同属输入段 ⇒ 本帧内不可能先后发生；跨帧时 cleared 之后的落子请求由 S3/S1 状态机忽略（对齐 `core-loop §6`）。

**非法输入**
- PAUSED 中点击玩法区：全忽略（含误触网格/托盘）。
- 越界坐标（<0 或 >750/1334）：忽略。
- `BOOT` 期任何触摸：忽略。

## 8. 验收标准（可测试硬判据，QA 直接造用例）

1. 5 类指令逐一验证路由正确：点暂停→PAUSED；点道具卡→S6 收请求；点扩展→S4 收请求；点托盘珠→`tray:selected`；点空格（有选中）→S3 收落子请求。**判据冲突登记（BD-37，WXG-T-097/BD-15）**：本条的「点扩展→S4 收请求」在当前产品形态下**不可达**——`powerups.md §2.6` 布局 A 与 `ux-spec §4` 矩阵「点扩展 | 角标占位（MVP 无解锁路径）」写定本轮**无扩展解锁路径**，⇒ 实装行为是「命中即吞掉 + 一次性占位轻提示，零事件、零槽变化、零扣次、不调 wx 广告 API」，S4 收请求属**扩展解锁上线后**的行为。裁决：`§2.6` 布局 A 为当前有效产品决策，本条**不降格为已验**，QA 对「点扩展→S4 收请求」记 ⛔ 不可验（不得因占位实装而打 PASS）；解锁路径落地时同批改写本条与 `ux-spec §4` 该行。
2. 热区：在格中心偏移 ≤ 外扩边界内点击必命中该格；命中区外点击（带间隙处）零事件。**重叠优先级裁定（BD-23，WXG-T-091）：因 `BEAD_PITCH`(52) `<` 命中区(66)，网格内部外扩区必然重叠，此时一律以判据 4「最近格心」裁决为准——本条「偏移 ≤ 外扩边界内必命中本格」只在无重叠区成立；网格内部不存在带间隙处，「零事件」仅在网格外围验证。**
3. 一次触摸仅触发一条指令（监听计数器总和 =1），面板打开时玩法区点击计数 =0。**时基口径（WXG-T-115；与 WXG-T-113 修法对齐）**：本条「一次触摸」与 §8-10「一帧」的时基 = 游戏循环的**固定步**（`GameLoop.fixedDt`，即「**一个固定步 = 一次输入帧**」），**非渲染 tick**；§2.4 / §6 所述「帧」（输入帧）同义。⇒ **丢帧 / 卡顿使一个 tick 承载 N 个固定步（N>1）时，同一次物理触摸仍只准投递一条指令，不得因子步重放而重复触发**（一次性输入标志的生命周期绑定固定步，同一 tick 的后续子步不得二次读到同一次按下）。本条同时覆盖**相位切换落穿**：面板按钮一次点击只准触发该按钮的**一条**指令，不得在同 tick 后续子步于新相位里再触发第二条（如点「继续」不得顺手落子）。该口径由框架 `App._fixedUpdate`（每固定子步一次 `beginFrame`/`endFrame`）保证；**若实现在丢帧多子步下未达此口径，须如实登记为缺陷，不得放宽本条**。
4. 13 列满密度网格外扩命中区重叠时：点击点距哪格格心最近即命中哪格（构造相邻两格中点 ±1px 用例）。
5. 锁定格/已填格点击：S2 与 S3 事件计数均为 0，无任何视觉反馈帧。
6. 双击同托盘珠：`tray:selected` 仅 1 次；双击不同珠（换选）：2 次，最终后者 selected。
7. 无选中珠点网格：不发落子请求（S3 请求计数 =0），有轻提示。**与判据 5 的交界（WXG-T-097/BD-16）：本条只在被点格为「可落空格（empty）」时成立；锁定格 / 已填格仍按判据 5 走「零事件且无任何反馈帧」（否则两条判据互斥：本条要求的轻提示帧正是判据 5 禁止的那一帧）——即轻提示不是“非法输入兼底”，它是“未选珠”这一个前置缺口的告知。**
8. PAUSED 状态点击托盘/网格/道具：全部忽略；仅面板按钮响应。

> **追加判据（WXG-T-115）**：以下 `8b` / `8c` / `8d` 补齐 `LEVEL_CLEAR` / `GAME_OVER` / `FINISH` 三相位的**独立可测门禁**——三相位此前仅有 §2.3 规范、§8 无可测条目（`PAUSED` 门禁见判据 8）。**编号采后缀、不整体重排判据 1–10**（同 `audio-events A05-09b` 判例，用户 2026-09-15 裁定 A）。每条含「判据原文 / 环境道次 / 可测形式 / 来源标注」四要素。

**8b（`LEVEL_CLEAR` 门禁）**
- **判据原文**：`LEVEL_CLEAR` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅结算（过关）面板上的按钮响应**（下一关 / 去冲刺）；面板外点击**零命中、不推进**（不误触「下一关」、不误开冲刺）。
- **环境道次**：`[Node]` / `[Probe]` 真链（✅ 可执行）＋ `[Harness]` 真指针（✅ 可执行）＋ `[Device]`/`[R]` 真机（**⛔ 无 AppID / 无真机**；解除条件 = 有 AppID → `build:cocos:wx` 出包 → 微信开发者工具 / 真机可跑 → 同一真链探针在 `wx` 宿主复取按钮命中）。
- **可测形式**：经 `InputManager` 真链（`beginFrame → push({phase:'down'}) → push({phase:'up'}) → update(dt) → endFrame(dt)`，与 `App._fixedUpdate` 同形）点「下一关」中心 ⇒ 相位 `level-clear → playing`、`levelIndex n → n+1`；点面板外（非任何按钮热区）⇒ 事件增量 **0**、相位与关卡号不变（**负向非平凡真**：点击确已到达 `_handleTap`）。
- **来源标注**：`§2.3` 状态门禁表第 3 行；`ux-spec §4` 流转表 `LEVEL_CLEAR` 行（＋`§3.3` 面板）；实现锚点 `games/beads/src/game/beads-game.ts` `case 'level-clear'`（**只读核对，不据以实现改判据**）。

**8c（`GAME_OVER` 门禁）**
- **判据原文**：`GAME_OVER` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅失败（结算）面板上的按钮响应**——普通局：**续时**「+N 秒继续本关」/ **重试本关**；冲刺局：**再来一局** / **返回关卡**；面板外点击**零命中、不重开**（不误触续时、不误触重试）。
- **环境道次**：同 8b（`[Node]`/`[Probe]` 真链 ✅ ＋ `[Harness]` 真指针 ✅ ＋ `[Device]`/`[R]` **⛔**，解除条件同 8b）。
- **可测形式**：真链点「重试本关」中心 ⇒ `game-over → playing`、`filled=0`（整关重置）；点面板外 ⇒ 事件增量 **0**、相位不变。**冲刺局子分支**（`_mode==='sprint'`）：真链点「再来一局 / 返回关卡」⇒ `playing`；面板外零响应。
- **来源标注**：`§2.3` 第 3 行；`timer-gameover §8-6`（失败页整关重置）；`ux-spec §4`（`GAME_OVER` 普通段 + 冲刺结算段）＋ `§3.5`；实现锚点 `beads-game.ts` `case 'game-over'`。

**8d（`FINISH` 门禁）**
- **判据原文**：`FINISH` 状态点击棋盘 / 托盘 / 道具卡 / 齿轮：**全部忽略**；**仅通关面板上的按钮响应**（去冲刺 / 重玩第 1 关）；面板外点击**零命中、不误触**（不误开冲刺、不误触重玩）。
- **环境道次**：同 8b（**⛔ 真机解除条件同 8b**）。
- **可测形式**：真链点「重玩第 1 关」中心 ⇒ `finish → playing`、`levelIndex=0`；点面板外 ⇒ 事件增量 **0**、相位不变。
- **来源标注**：`§2.3` 第 3 行；`ux-spec §4` 矩阵行 `FINISH`（＋`§3.6` 通关画面）；实现锚点 `beads-game.ts` `case 'finish'`。

> **编号理由（为何采 `8b/8c/8d` 后缀，而非并入判据 8 或整体重排）**：判据 8 主体是 `PAUSED`，其按钮集（继续 / 重玩本关 / 音量开关）与三相位的「过关 / 失败 / 通关」按钮集**互不相同**，合并会丢失 **1:1 可测性**（一条用例无法同时断言四种相位迁移与四套按钮集）；整体重排会牵动台账与既有证据引用（成本更高）。⇒ 采后缀（同 `audio-events A05-09b` 判例）。

9. 多点触控（双指同帧）：仅第一触点生效，指令数 =1。
10. 每帧指令上限：注入 20 次触摸/帧（「帧」= **固定步**，同 §8-3 时基口径），仅 1 条进入路由，无崩溃、无事件错序。**多子步口径（WXG-T-115）**：在**一个 tick 的 N 个固定步**下注入 **1** 次触摸，路由计数仍 **=1**（**丢帧不得把同一次触摸放大为 N 条指令**）；在一个固定步内注入 20 次触摸，仅 1 条进入路由。
