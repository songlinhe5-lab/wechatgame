## 1. 目标

把触摸输入路由为六类游戏指令（选归位珠 / 选错位珠 / 取回 / 归位 / 道具 / 扩展 / 暂停——归并为「选择类 + 落点类 + 面板类」三族），执行热区命中与状态门禁，保证"点哪是哪、错点无害"。

## 2. 机制

### 2.1 触摸路由表（v2.5 = 分区提交时基：棋盘区抬起才提交 + 位移阈值分 tap/drag，区外仍按下即响应；v2.0 = 统一选择锚）

**提交时基（v2.5 新增，`ADR-0015` §3.5 C-3 = (a) 主理人已裁）**：路由入口从 v2.4 的「**单指点击，无拖拽/长按**」改为——**单指 / 双指**；**棋盘区（`PUZZLE_BAND` 网格区）tap = 按下到抬起且全程位移 < 阈值**，**棋盘区 drag = 按下到抬起且位移 ≥ 阈值 → 触发棋盘平移**；**双指 = 捏合缩放**。**HUD / 托盘 / 道具卡 / 扩展钮 / 各类面板不变，仍按下即响应。**

| 区域 · 手势 | 识别条件 | 提交帧 | 出口 |
|---|---|---|---|
| 棋盘区 **tap**（选珠 / 落点） | 按下 → 抬起，全程位移 **< `BOARD_TAP_MOVE_THRESHOLD`** `[待确认]` | **抬起帧** | 走下表路由 **5a/5b/5c**（错位珠组选 / 组归位 / 直填 / 不可填格轻压）——**指令语义与带级次序零改动**，只是提交帧从按下帧移到抬起帧 |
| 棋盘区 **drag**（单指平移） | 按下 → 抬起，位移 **≥ 阈值** `[待确认]` | 平移**逐帧连续**（相机态，非玩法指令）；抬起帧结算终点 | **触发棋盘平移**（事件名 `[待确认]`，本文不新造事件），**不发** 5a/5b/5c 任何指令、不计入「一次触摸 = 一条指令」的玩法指令数 |
| 棋盘区 **双指捏合** | 第二指落下即进捏合态，两指距离比驱动倍率 | — | **缩放**（**只做手势、无滑轨 / 按钮控件**，沿 `concept` D13 / v2.2 裁定）；**缩放档位与上下限范围** `[待确认]`（钳位口径见 ADR-0015 §3.4，数值归 §3 变更单） |
| HUD / 道具卡 / 扩展钮 / 托盘 / 面板 | 单指 tap | **按下帧（不变）** | 路由 **1–4** 与 §2.3 门禁、§8-8 / 8b / 8c / 8d 判据**逐条原样成立**，QA 不得因 v2.5 重开这些用例 |

- **阈值只钉形态、不钉数值**：`BOARD_TAP_MOVE_THRESHOLD`（切比雪夫位移判定，单位 px）**当前不冻结** `[待确认]`——ADR-0015 §4.2-8 明写「阈值是未冻结的 UX 参数」，归设计轨 playtest + 真机实测后走 `systems-index §3` 变更单。
- **旧文本作废留档（v2.4 及以前，比对用，不得据以实现）**：~~「§2.1 触摸路由表（单指点击，**无拖拽/长按**）」~~、~~「棋盘区指令在**按下帧**提交」的隐含口径~~（原文未写「抬起」，一律按按下帧读，v2.5 起以抬起帧结算）。

**统一选择锚（v2.0 核心机制）**：`selection ∈ {tray, board, none}`——`tray` = 托盘珠选中（`tray:selected`；**v2.2 tray-spawner 组选：同一时刻 = 至多一色组全部 `selected`**）、`board` = 错位珠选中（`board:selected`）、`none` = 无选中。**三值互斥**：任何一次成功选择都会清除另一侧的选中（换选即转移，不叠色）。带级次序（下表优先级 1–5）**不变**。

| 优先级 | 命中区 | PLAYING 行为（按 `selection` 分支） | 出口 |
|---|---|---|---|
| 1 | 暂停按钮（HUD 带，避开 `CAPSULE_AVOID`） | 请求 S9 暂停 | S9 |
| 2 | 道具卡 ×3（`POWERUP_BAND`） | 请求使用对应道具（解环器，`powerups §2.2`） | S6 |
| 3 | `btn_expand`（`TRAY_BAND`） | 请求扩展托盘 | S4/S6 |
| 4 | **托盘区**（`TRAY_BAND`）——**内部分支**：4a `holding` 槽（珠）；4b 空槽（`free`） | **4a（v2.3 组选）**：选中该珠**同色全组** → 锚置 `tray`（若原锚 `board`，同时清除错位珠选中）；换点他色 = 整组换选；**再点已选组任一颗 = 整组静默取消（零事件，锚回 `none`）**。**4b**：锚 = `board` 且托盘有空槽 → **取回**（S3/S4，`tray:stored`；**v2.6：落槽 = 玩家点槽定落位** —— 从被点空槽起**连续相邻**排布，容量不足 ⇒ **部分收纳**（收距锚珠最近者，余珠留格、锚改指剩余首颗可续点）；~~v2.3：系统自动归类、点击空槽仅作触发~~ ⛔ 作废）；锚 = `board` 且**满槽 / 起点零连续空槽** → 拒绝（极轻反馈，零事件，§3.13）；锚 ∈ {`tray`, `none`} → 无效落点轻提示（零事件） | S4 / S3+S4 |
| 5 | **网格区**（`PUZZLE_BAND`）——**内部分支**：5a `filled(错位)` 格；5b `empty` 格；5c `locked` / `filled(就位)` 格 | **5a（v2.4 组选）**：选中/换选该错位珠 → 组 = **锚起 8 向（含对角）连通、同色错位珠的完整连通块，不限步数**（「找相邻直到找不到，一起抬起」；就位珠/锁定/空格/异色均**阻断传播**）→ 锚置 `board`（`board:selected`；若原锚 `tray`，同时清除托盘珠选中）。**5b（v2.3 批量归位 + v2.4 直填放开）**：锚 = `tray` → **组归位请求**（S3 裁决 placed/rejected；匹配时沿 8 向连通同色空格批量填充，`bead-grid §2.3 路径 B`）；锚 = `board` → **直填**（点底色 = 组色的 `empty` 格，**不限距**，v2.4 删 ≤2 门 ⇒ 取组内离目标最近者同帧归位，`bead-grid §2.2 组语义`）；锚 = `none` 或底色不匹配 → 无效落点轻提示（零事件）。**5c**：极轻非惩罚反馈（零事件，裁定 4，§2.4） | S4（选中）/ S3（裁决） |

- 路由**自上而下短路**：一次触摸只命中优先级最高的一区；面板/弹窗（PAUSED、结算）打开时，2–5 全部屏蔽。**v2.5 补充**：棋盘区的「一次触摸」= **一次抬起提交的 tap**（上行表「提交时基」）；位移 ≥ 阈值的 **drag** 与**双指捏合**属相机态、**不进本表路由**（既不算命中某区，也不产任何一区指令）。
- 优先级 3 的出口列按 `powerups.md §2.6` 布局 A 当前**降级**为「命中即吞 + 一次性占位轻提示」，不发 `tray:expanded`；冲突登记与裁决见 §8-1（BD-37），几何与热区见 §2.2。
- **格间不直换（v2.0 立，v2.1 裁定冻结）**：错位珠与空格之间**必经托盘**（取回 → 归位两步）。**`swap`（格间直换）= 永不实现**（v2.1，WXG-T-138，提案 `proposals/v1.23-bold-remake.md` Q2，用户拍板）：「过一道手」= 手作拼豆的触感本体；且直接交换是环谜题的作弊器——托盘 2 槽即可滚窗解任意置换（提案 §5 诚实修正），**必经托盘 + 小托盘滚窗（`TRAY_BASE_SLOTS`=6）才是操作深度所在**。S3 不接受任何格间转移请求，工程无需为 swap 预留接口。

### 2.2 热区规则（来源 §3.8）

- 最小热区 `TOUCH_MIN` = 88px（≈44pt）。
- 网格珠名义尺寸 `BEAD_CELL` < 88 → 命中区**外扩 8px**（即 66×66），相邻外扩区重叠时按格中心最近者命中；仍不足 88 的极端小格不再扩大（防止跨格误触，66px 为 demo 接受值，QQ 验收以 §8 判据 4 为准）。
- 托盘珠名义 `TRAY_SLOT` < 88 → 同规则外扩 8px（62×62）。
- 按钮类（暂停/道具卡/扩展）实际尺寸 ≥ 88 直接用名义框。
- **`btn_expand` 是本条的反例（WXG-T-097/BD-15，依 `art/accessibility.md` C1）**：视觉 **132×48**（`assets-spec §1.3`）高 48 < `TOUCH_MIN` ⇒ **热区扩至 132×88、视觉不变**（同心，视觉 y∈[250,298] / 热区 y∈[230,318]）。落位与尺寸的唯一真源 = `systems-index §3.4`（v1.20：`TRAY_BAND` 上沿 420→450、托盘面板改**贴带上沿**，腾出带下沿），渲染与命中同源 `tuning.ts::expandButtonLayout()`，不存在「画出的框 ≠ 点击落点」漂移（WXG-T-062 判例）。热区与扩展态最上排槽热区实测净空 **11px** ⇒ 不与判据 2 的「重叠区最近格心」仲裁冲突，无需加例外条。

### 2.3 状态门禁（什么状态下点什么有效）

| 状态 | 有效输入 |
|---|---|
| `PLAYING` | 上表全部 |
| `PAUSED` | 仅暂停面板按钮（继续/重玩本关/音量开关） |
| `LEVEL_CLEAR` / `GAME_OVER` / `FINISH` | 仅**各自面板**的按钮——过关：下一关 / 去冲刺；失败：续时 / 重试本关；通关：去冲刺 / 重玩第 1 关（**面板外零响应**；逐相位独立可测判据见 §8-8b/8c/8d） |
| `BOOT` | 全部忽略 |

- **归位前置条件（v2.0）**：锚 = `tray`（存在 `selected` 托盘珠）；锚 ∈ {`board`, `none`} 时点空格 → 轻提示（视觉层），**不发归位请求**。
- **取回前置条件（v2.0）**：锚 = `board`（存在 `selected` 错位珠）**且托盘有空槽**；两条件缺一时点托盘空槽 → 极轻反馈或轻提示（见 §2.1 路由 4b），**不发取回请求**。**v2.6 补充（WXG-T-168）**：空槽数 < 组大小**不再整组拒** —— 只收「起点起连续空槽数」颗（距锚最近者优先），逐颗 `tray:stored`；起点**零连续空槽**（含满槽）才走拒绝分支。

### 2.4 非法输入处理（对齐 core-loop §6）

- 锁定格 / **已就位珠**（v2.0：`filled` 且珠色=底色；**错位珠不适用本条**，错位珠可选中）点击：路由到 S3 但 S3 静默忽略——**零事件、零扣次、零状态写**；S2 层播**极轻非惩罚反馈**（WXG-T-128，2026-09-16 用户裁定；WXG-T-130 v2.0 维持同形态、对象由「已填格」收窄为「已就位珠」）：被点格 scale 1.00→0.96→1.00（120ms）+ 极轻闷「哒」（`sfx_denied`，已随 WXG-T-152 原子批落码）；**零位移、零红、零色变**，`reduceMotion` 开 ⇒ 退为 1px `slot_border` 静态描边环。视觉规格 = `art-bible §7.3.7` / `assets-spec §1.6.7`；矩阵行 = `ux-spec §4`；毫秒真源 = `ux-spec §5`「不可填格轻压」。**与「放错拒绝」（`bead:rejected`）严格区分**：本条不发事件 ⇒ 不占 `systems-index §3.8`「错误反馈 ≤2 次/秒」预算；a11y 口径 = `accessibility` D1/D2/A5⑦/A6。**零噪声原则的适用边界**：仍适用于**自动事件**，不再否决**玩家主动点击**的确认反馈。
- **满槽取回（v2.0 新增）**：锚 = `board` 且托盘无空槽时点托盘任意槽 → **拒绝**：零事件（`tray:stored` 计数 =0）、零状态写 + 极轻非惩罚反馈（同上形态；用户 2026-09-16 确认「托盘满禁取珠」）。判据见 §8-11。
- 连续快速双击同错位珠：幂等，第二次不产生新指令（对 S3 的去抖窗口 = 1 帧内合并；此处「帧」= **固定步**，见 §8-3 时基口径）。**v2.3 例外的托盘侧（覆盖旧「同托盘珠双击幂等」条）**：再点已选同色组任一颗 = **整组取消**（静默零事件），非幂等保持（用户裁定②，`tray-spawner §6` 同批）。
- 多点触控：**v2.5 分区改写（ADR-0015 §3.5 C-3 = (a) 前置）**——**棋盘区**：双指 = 捏合缩放、单指位移 ≥ 阈值 = 平移，**两者都不产玩法指令**（次指落下**不产** `justDown`，框架侧口径见 ADR-0015 §3.2-2）；**区外（HUD / 道具卡 / 扩展钮 / 托盘 / 面板）**：仍「只取第一触点，其余忽略」，逐条不变。缩放**只做手势、无滑轨 / 按钮控件**（D13 沿袭，v2.2 的 Should 随 ADR-0015 Accepted 转正为**已裁待施工**；本文仍不写实现）。**旧文本作废留档**：~~「多点触控：MVP 只取第一触点，其余忽略；不缩放、不旋转」~~、~~「实现前 §8-9 判据与本文路由不变」~~（路由与 §8-9 **已随 v2.5 改版**，该「不变」条款解除）。

## 6. 边界条件

**极端值**
- 外扩命中区重叠（网格高密度区）：按"格中心欧氏距离最近"裁决，平局取 row 小者。
- 触摸点落在布局带间隙（如托盘与道具卡之间）：无命中，静默忽略。
- 连续极速点击（>10 次/秒）：每帧最多处理 1 条指令（「帧」= **固定步**，见 §8-3 时基口径），其余丢弃（防指令洪泛）。

**并发 / 竞态**
- 同帧先选珠后点落点「双事件」：**不可能同帧** —— 每帧最多 1 条输入指令（「帧」= **固定步**，见 §8-3；§2.4 / §8-10），选择与落点分属相邻两帧；跨帧时选择当帧生效、下一帧落点请求携带新锚态（S3/S4 收到时序仍串行）。WXG-T-061 换基准。v2.0：选错位珠（5a）与取回（4b）、选托盘珠（4a）与归位（5b）同此口径。
- 道具请求与暂停请求同帧：**不可能同帧**（同属输入段）。同帧内按 `core-loop §2.2.2` 输入段内序——齿轮（**状态指令**）先于道具（**玩法事件**）⇒ 等效结论仍是暂停优先、道具请求作废。
- `level:cleared` 与其后的取回/归位请求：两者同属输入段 ⇒ 本帧内不可能先后发生；跨帧时 cleared 之后的请求由 S3/S1 状态机忽略（对齐 `core-loop §6`）。

**非法输入**
- PAUSED 中点击玩法区：全忽略（含误触网格/托盘）。
- 越界坐标（<0 或 >750/1334）：忽略。
- `BOOT` 期任何触摸：忽略。

**新增手势的边界（v2.5，只写形态、不写阈值与档位数值）**
- **drag 起手在棋盘区、抬起点在带外**（拖过 `PUZZLE_BAND` 上/下沿）：仍按 **drag** 结算（位移已 ≥ 阈值），**不得回退成 tap**、不得因「抬起点在托盘/HUD 区」而触发路由 1–4（带级次序只在**同一提交帧的一次 tap** 上生效）。
- **drag 起点在托盘 / 道具卡 / 齿轮热区**：那些区**语义不变（按下即响应）**，拖拽不从它们起手（ADR-0015 §4.2-8 登记的残余歧义归**阈值定值 + playtest**，本文不自裁）。
- **捏合中途抬起一指**：owner **不迁移**（两指均抬起后才复位，ADR-0015 §3.2-3）⇒ 不得把「捏合收尾」误读成单指 drag，也不得产 `board:selected`。
- **非 `PLAYING` 相位 / meta 页族**：相机旁路（平移与缩放不生效、不扰动 §2.3 门禁与判据 8/8b/8c/8d 的「面板外零响应」）。
- **换关 / 重试 / 回菜单**：相机归 **fit 初始**（`fit = min(1, 含边距适配)`；公式真源属工程侧 `board-camera.ts::computeFitZoom`，本文只引用不写取值。**小盘 `fit = 1` ⇒ 与旧「恒等」档逐位相同**，故本条属**口径命名更正、行为零改动**，T-169 真机反馈③「开局居中不贴边」已入库基线不拆）。**复位点数量与实际触发时机 = `ADR-0015` §3.4**（工程轨 WXG-T-172-E1 同批改写）；本行标签只登记**输入层可见事实**、不作复位点清单，数值与实现归工程与 §3 变更单。

2. **热区（v2.5 改写：与「抬起才提交」兼容）**：棋盘区在格中心偏移 ≤ 外扩边界内**按下并原地抬起**（全程位移 < `BOARD_TAP_MOVE_THRESHOLD` `[待确认]`）⇒ **抬起帧**必命中该格；命中区外**抬起**（带间隙处）零事件。**重叠优先级裁定（BD-23，WXG-T-091）原样保留**：因 `BEAD_PITCH`(52) `<` 命中区(66)，网格内部外扩区必然重叠，此时一律以判据 4「最近格心」裁决为准——本条「偏移 ≤ 外扩边界内必命中本格」只在无重叠区成立；网格内部不存在带间隙处，「零事件」仅在网格外围验证。**v2.5 追加两分支（drag 不得被读成两次 tap）**：① 按下点与抬起点分属两格且全程位移 ≥ 阈值 ⇒ 判为 **drag**，玩法指令计数 = **0**（不得「按下 A 格、抬起 B 格」各算一次命中）；② drag 途中跨过的格一律**不发** `board:selected` / 归位 / 直填请求，仅在抬起帧结算一次平移终点。**旧判据（v2.4，作废留档）**：~~「在格中心偏移 ≤ 外扩边界内点击必命中该格；命中区外点击（带间隙处）零事件」~~——旧「点击」按**按下帧**结算 ⇒ 真链探针在 `push({phase:'down'})` 后即断言命中的旧用例**不再构成证据**（K-035 假绿谱系），须补 `push({phase:'up'})` 且位移在阈值内。
3. 一次触摸仅触发一条指令（监听计数器总和 =1），面板打开时玩法区点击计数 =0。**时基口径（WXG-T-115；与 WXG-T-113 修法对齐）**：本条「一次触摸」与 §8-10「一帧」的时基 = 游戏循环的**固定步**（`GameLoop.fixedDt`，即「**一个固定步 = 一次输入帧**」），**非渲染 tick**；§2.4 / §6 所述「帧」（输入帧）同义。⇒ **丢帧 / 卡顿使一个 tick 承载 N 个固定步（N>1）时，同一次物理触摸仍只准投递一条指令，不得因子步重放而重复触发**（一次性输入标志的生命周期绑定固定步，同一 tick 的后续子步不得二次读到同一次按下）。**v2.5 追加（时基后移、本条口径不变）**：棋盘区「一次触摸」的**结算帧 = 抬起帧**（区外仍为按下帧）⇒ 固定步口径逐字沿用，只是棋盘区投递时点后移一个区间；**被吞掉的 down**（位移 ≥ 阈值的 drag / 双指捏合的第二指）**不计为指令**。本条同时覆盖**相位切换落穿**：面板按钮一次点击只准触发该按钮的**一条**指令，不得在同 tick 后续子步于新相位里再触发第二条（如点「继续」不得顺手落子）。该口径由框架 `App._fixedUpdate`（每固定子步一次 `beginFrame`/`endFrame`）保证；**若实现在丢帧多子步下未达此口径，须如实登记为缺陷，不得放宽本条**。

> **编号理由（为何采 `8b/8c/8d` 后缀，而非并入判据 8 或整体重排）**：判据 8 主体是 `PAUSED`，其按钮集（继续 / 重玩本关 / 音量开关）与三相位的「过关 / 失败 / 通关」按钮集**互不相同**，合并会丢失 **1:1 可测性**（一条用例无法同时断言四种相位迁移与四套按钮集）；整体重排会牵动台账与既有证据引用（成本更高）。⇒ 采后缀（同 `audio-events A05-09b` 判例）。

9. **多点触控（v2.5 按区分割，旧判据被翻）**：**棋盘区**双指同帧 ⇒ 进捏合缩放态，**玩法指令数 = 0**（`board:selected` / `tray:stored` / 归位 / 直填 / `bead:placed` 计数全为 0；次指落下不产 `justDown`，ADR-0015 §3.2-2）；单指位移 ≥ 阈值的 **drag** 同判（平移 = 相机态，不是指令）。**区外**（HUD / 道具卡 / 扩展钮 / 托盘 / 面板）双指同帧 ⇒ 仍**仅第一触点生效、指令数 =1**。**旧判据作废留档**：~~「多点触控（双指同帧）：仅第一触点生效，指令数 =1」的全域口径~~——v2.5 起该表述**只在棋盘区之外成立**（即 ADR-0015 §4.2-2 登记的「一条契约切成两段」）。
10. 每帧指令上限：注入 20 次触摸/帧（「帧」= **固定步**，同 §8-3 时基口径），仅 1 条进入路由，无崩溃、无事件错序。**多子步口径（WXG-T-115）**：在**一个 tick 的 N 个固定步**下注入 **1** 次触摸，路由计数仍 **=1**（**丢帧不得把同一次触摸放大为 N 条指令**）；在一个固定步内注入 20 次触摸，仅 1 条进入路由。**v2.5 计量单位改写**：棋盘区「一次触摸」= **一次完整的 down→up 序列（位移 < 阈值 `[待确认]`）** ⇒ 一个固定步内注入 20 次按下（无配对抬起）**路由计数 = 0**，注入 20 次按下+抬起配对**仍仅 1 条进入路由**；多子步口径同步后移：丢帧使一个 tick 承载 N 个固定步时，同一次**抬起**只准投递一条指令（旧「同一次按下」表述作废留档：~~「在一个固定步内注入 20 次触摸，仅 1 条进入路由」的按下帧计数口径~~）。平移 / 捏合属相机态，**不占**本条指令预算（见判据 9）。

> **追加判据（WXG-T-130，v2.0）**：以下 `8-11` / `8-12` 补齐 v2.0 新交互（取回 / 选择锚互斥）的独立可测条目。编号采后缀式追加（同 `8b/8c/8d` 判例，不整体重排）。

**8-11（满槽禁取珠）**
- **判据原文**：锚 = `board`（错位珠已选中）且托盘无空槽时点击任意托盘槽 → **零事件**（`tray:stored` 计数 =0）、错位珠保持 `filled(错位)`、槽态零变化；有极轻非惩罚反馈帧（同判据 5 形态）。
- **环境道次**：`[Node]` / `[Probe]` 真链 ✅ ＋ `[Harness]` 真指针 ✅ ＋ `[Device]`/`[R]` ⛔（解除条件同 8b）。
- **可测形式**：构造托盘全 `holding` 局面 → 真链点错位珠（**v2.5：`down` → 原地 `up` ⇒ 抬起帧才出 `board:selected` 恰 1 次**）→ 点任一槽（托盘 = 区外，**仍按下即响应**）⇒ 监听器事件增量 0、`buildRenderModel()` 中该格无离格命令、出现 scale 覆写或描边环命令；腾出足量槽（free 数 ≥ 组大小，T-147/T-157 整组收进口径）后重复 → `tray:stored` 计数 = 组大小（**v2.3：落位 = 自动归类插入位，非必为点击槽**）。**v2.5 两步时基注**：本条两步**分属两个时基**（棋盘区抬起提交 / 托盘按下提交）⇒ 用例天然至少跨一个固定步，「每帧 ≤1 条输入指令」仍成立；**不得**在只下发 `down` 的情况下断言「锚已 = `board`」。
- **来源标注**：`§2.1` 路由 4b / `§2.4` 满槽取回条；`systems-index §3.13` 取回前提行；`core-loop §8-3`；用户裁定「托盘满禁取珠」（2026-09-16）。

**8-12（选择锚互斥与转移）**
- **判据原文**：`selection ∈ {tray, board, none}` **恒互斥**——任意时刻至多一侧存在选中态；任何新选择清除旧锚（换选即转移）；带级次序不受锚态影响（锚 = `board` 时点托盘珠仍优先命中 4a、点道具卡仍命中 2）。
- **环境道次**：同 8-11。
- **可测形式**：真链点错位珠 A（**v2.5：`down` → 原地 `up`，`board:selected` 于抬起帧发 1 次**）→ 点托盘珠 B（区外，按下即响应）⇒ `tray:selected` 恰 1 次、且 A 的选中态绘制命令消失（`buildRenderModel()` 中 A 无 `selected` 参数）；反向序列对称断言。再注入「锚 = `board` 时点道具卡」⇒ S6 收请求、锚态不变。
- **来源标注**：`§2.1` 统一选择锚定义；`bead-grid §2.2`（`selected` 表现层态互斥）；`ux-spec §4` 新增三行（`tray:stored` / `board:selected` / 满槽拒取回）。
