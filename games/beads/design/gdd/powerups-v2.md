## 1. 目标

道具体系在核心循环里的职责 = **破局手段**，不是进度手段，也不是通关手段。

三条硬边界（沿用 v1.3 已裁定，本版不改）：

1. **不改倒计时**：不加时、不冻结、不降速；时间唯一真源仍是 S5（`systems-index §3.5`）。加时只走失败续时一条通道（§3.11）。
2. **不碰托盘**：S6 对托盘零读写、零订阅（`§3.6`「道具目标 = 棋盘错位珠」条）。托盘工作台的手感与容量压力是玩家的活，不被道具短路。
3. **不替代谜题本体**：「环追踪」是支柱 2 的谜题核心；道具只提供**有限、可数、可预测**的推进量，绝不出现「一键通关」（本版为此专门排除了环轮转式实现，见 §2.2「为什么不是环轮转」）。

与三支柱的关系：

| 支柱 | 本体系的兑现方式 |
|---|---|
| ① 一眼读懂的治愈 | 一次点击 = 一次原子结算，无瞄准中间态、无第二级面板；两件道具各自「点一下就见效」，反馈即时 |
| ② 托盘工作台的手感与环谜题 | 托盘零读写；道具只作用于棋盘；容量瓶颈与环结构仍是玩家的作业面 |
| ③ 复刻优先、不加戏 | **从三件收到两件**；不新增 HUD 元素、不新增计数显示、不新增事件名（沿用 `powerup:used`） |

一句话：**两件工具，一「片」一「串」——星引棒理一片，线引棒串几颗。**

## 2. 机制

### 2.1 作用域（唯一作用对象 = 棋盘 `filled(错位)` 格）

- **可作用**：仅 `filled(错位)` 格（判定式 `misplaced(cell) = filled ∧ colorIdx ≠ pattern(row,col)`，`§3.13`）。
- **不可作用**：`locked`（`.` / `x`）与 `filled(就位)` 格。v1.3 只把这条写成「硬边界」靠实现自觉；**本版升级为算法级保证**——两件道具的候选珠池只从 `filled(错位)` 集合里取（§2.2），就位珠与锁定格在数据结构上取不到，不存在「误伤」路径。
- **托盘零读写**：S6 不订阅 `tray:*`、不请求槽位变更、不读托盘状态。取回/归位仍走 S2 两段式。
- **网格写入唯一真源 = S3**：S6 只**裁定**（选窗口/选珠/算 `affectedCells`），广播 `powerup:used {type, affectedCells}`，由 **S3 执行写入**并逐格回执 `bead:placed`（无 `slot`）。

> 与支柱 2 的「格间直换永不实现（`concept` D11）」不冲突：该禁令针对**玩家操作**；道具作为「外部工具代劳」的例外自 v1.22 起成立（解环器本来就直接写网格）。

#### 2.2.1 星引棒（`windowRestore`）效果定义

一次点击走三步，**全程确定性、零随机**（本道具不消费 `services.rng`，调用计数恒 0；铁律 L4 天然满足）：

**第 1 步 · 定窗口尺寸**
`w = min(SIDE, cols)`、`h = min(SIDE, rows)`，`SIDE` = 窗口边长 `[待拍板]`（用户已给 6）。
窗口按**格位**取（含 `.` / `x` 空位），**不是**「6×6 颗豆」——盘面填充率不影响窗口尺寸与位置计算。

**第 2 步 · 定窗口位置（自动选「错位珠最密集」）**
在全部 `(cols−w+1) × (rows−h+1)` 个候选位置中取**窗口内错位珠数最多**者。
平票走**确定性五级 tie-break 链**（逐级收紧，必然收敛到唯一解；⛔ 禁止 `Math.random`，本步零随机）：

1. 窗口内**错位珠数最多**
2. 窗口内**就位珠数最少**（同等收益下少压在已完成的格上）
3. 窗口中心到盘面几何中心的**曼哈顿距离最小**，整数式：`|2r₀+h−1−(rows−1)| + |2c₀+w−1−(cols−1)|`（用整数式是为了避开偶数边窗口的 `.5` 浮点，判据可逐位比对）
4. 窗口左上角**行号最小**
5. 窗口左上角**列号最小**

> ⚠ 第 4/5 级只在「前三级完全同值」时才用到，实际是极罕见的角落对称情形。**第三级（就近盘心）不是装饰**：现池 boss 关有 345 / 729 个窗口并列为最密集（见核算表），若按行主序取最前，30×30 关会命中 **0 颗**——同一规则下差距 = 36 颗 vs 0 颗。

**第 3 步 · 执行归位（目标色拉取置换）**
对窗口内每个错位格（**行主序**）：
1. 若它此刻已就位（可能被上一次交换顺带修好）→ 跳过；
2. 否则取它的目标色 `need = pattern(cell)`，在「盘上所有 `filled(错位)` 格」中按**确定性候选序**找一颗珠色 = `need` 的珠，与它**两两交换**。

候选序（决定「换哪一颗」，也决定连带面）：
- **先窗口内**（行主序）；窗口内无可用同色错位珠时，才向窗外扩展；
- 窗外扩展 = **切比雪夫半径由小到大**（1, 2, 3, …），同半径内按**行主序**。

**硬承诺**：全部处理完 ⇒ **窗口内 100% 就位**（不做按比例截断）。这条在 10 关真实数据上逐一实测通过（§2.2.4「窗内残留」列恒为 0）。

**为什么必须交换、不能就地改色**（本节最重要的一条推导，不许省略）：
若直接把这几十格刷成目标色，盘上每色珠数就不再等于 `pattern` 每色格数 ⇒ 某些色过剩、某些色不足 ⇒ 缺色的那些格**永远拿不到珠** ⇒ 结构性死锁，只能重开。BOOT 的「每色珠数守恒」校验（`levels-spec §2` 表 ④）保证的是**初始盘**守恒；道具一旦破坏守恒，`levels-spec §2.2`「可解性由构造保证」这条根本性质就断了。**置换天然守恒**（不造珠、不灭珠），这是唯一安全实现。

**单调不变式（可作硬判据）**：每次交换的双方都是错位珠，其中窗口那一格必变就位 ⇒ 交换只会让错位总数**减少 1 或 2**，绝不增加 ⇒ `hits ≤ ΔM ≤ 2 × hits`（`hits` = 窗口内错位珠数、`ΔM` = 本次净归位颗数）。10 关实测全部落在区间内。

**为什么不是「环轮转」**（必须登记，否则后人会重新踩进来）：
把「归位」实现成「沿置换环整环轮转」在数学上同样守恒、同样优雅，但**会沿环把整盘染指**。对 10 关真实盘面做环闭包实测，一次使用将归位 `M` 的 **69.6% / 100% / 77.3% / 100% / 74.8% / 72.5% / 100% / 94.6% / 86.4% / 79.5%`（L00001→L00010）——**三关直接一键通关**。故本版明确**不做环轮转**，改用「有界的逐格拉取」：交换次数 ≤ 窗口错位格数，一次点击至多牵动 `2 × hits` 个格，**不沿环扩散、不递归**。

#### 2.2.2 线引棒（`quotaRestore`）效果定义

- **取量**：`k = clamp(ceil(剩余错位珠数 × Q), MIN, 剩余)`；`Q` = 比例 `[待拍板]`（推荐 0.05）、`MIN` = 下限 `[待拍板]`（推荐派生于 `TRAY_BASE_SLOTS`，语义 = 「一整托盘珠」）。
  基准取**当前剩余**（不是初始总数）⇒ 局内任何时点用，效果都按「此刻还剩多少」算；`clamp` 上限 = 剩余 ⇒ 永不超发。
- **选珠**：按**行主序最前的 `k` 个**错位格（确定性，零随机）。
- **执行**：与星引棒**同一套**「目标色拉取置换」算法（候选序起点 = 该格自身，向外切比雪夫半径扩展）。同样满足 `k ≤ ΔM ≤ 2k`。
- **小盘联动（用户「最后来不及补点击」的直接承接）**：`剩余 ≤ MIN` 时 `k = 剩余` ⇒ **一次全清**，玩家不必再算两次点击。

### 2.3 结算时序（一次点击 = 一次原子结算，无瞄准中间态）

沿用 2026-09-12 既定裁定，逐字不变：**点道具卡 = 当帧完成全部裁定**，不进入「选窗口 / 选珠」二级态，不缓存待定指令。

```
S2 道具卡点击（路由优先级 2，携带 type；区外按钮 = 按下登记、抬起提交，input-control §2.1 v2.13）
  → S6 校验 type ∈ POWERUP_TYPES 且 S1 状态 = PLAYING，否则忽略（§6）
  → 查额度（§2.5 优先级：引导 → 免费 → 额外〔购买 | 视频〕）
     ├─ 有额度：按 §2.2 用棋盘只读镜像算 affectedCells
     │    ├─ 非空（盘上有错位珠）→ 广播 powerup:used {type, affectedCells} → 额度 −1
     │    │        → S3 执行写入 → 逐格 bead:placed（无 slot）→ 完成判定
     │    └─ 空（盘上零错位珠）→ 不广播、零格变化、**不扣额度**（沿用 2026-09-12 裁定）
     └─ 无额度：不广播、零格变化，弹双通道面板（购买 / 看视频，§2.6）
```

- **单步生效**：MVP 不引入两步瞄准（两步瞄准列 Should，本版不排期）。
- **道具不改时间**：不加时、不冻结、不延表。倒计时唯一真源仍是 S5。
- **帧内位置**：道具属**输入段的「状态指令」子段**（先于玩法事件），见 `core-loop §2.2.2`；因此与取回/归位**不可能同帧**（每帧至多 1 条输入指令）。

### 2.4 与 S3 的事件契约（`powerup:used {type, affectedCells}`）

- **S6 不持有网格真源**：只消费 S3 广播的 `bead:placed` 维护**棋盘错位只读镜像**（哪些格是 `filled(错位)`）。
- **S3 是唯一写入方**：收到 `powerup:used` 后按 §2.2 的裁定逐格写入，每产生一个 `filled(就位)` 格发 1 次 `bead:placed`（payload **无 `slot`**）。
- **`affectedCells` 语义本版精确化**（v1.3 只写「受影响格位」，不够断言）：
  `affectedCells: [{row, col, colorIdx}]` = **结算后该格的新珠色**，覆盖**全部发生珠色变化的格**——既含窗口内被拉正的格，也含**窗外被换入/换出的格**（置换的另一端）。
  理由：置换必然动到窗外格；若只报窗口内格，S3 的写入与 payload 就 1:1 不上（违反 §8-7），表现层也画不出「珠子飞出去」的那一半。
  数量界：`|affectedCells| ≤ 2 × hits`（星引棒）/ `≤ 2k`（线引棒）。
- **一致性硬要求**：S3 实际写入的格集合必须与 payload 逐格一致（§8-7 联合断言）；镜像漂移（S6 认为错位、S3 已就位）→ S3 重算目标并记警告（§6）。
- **不新增事件**；`powerup:used` 为 `systems-index §4` 既有条目。窗口矩形（用于高亮表现）由 S6 的裁定结果对象交给视图（形态同既有 `selectBoardBead` 回执），**不进事件 payload**，避免 §4 事件表变更；若表现层确实需要跨系统拿窗口，再走 §4 可选字段变更单（见 §5 T-8）。

### 2.5 次数计数模型（四类额度）

四类额度，**互不挪用、分别记账**：

| 额度 | 值（常量） | 生命周期 | 是否入档 | 扣减时机 |
|---|---|---|---|---|
| **引导** | 每件 **1 次 / 账号**（`POWERUP_TUTORIAL_USES`，新） | 跨关跨局，永久 | **入档**（meta sidecar） | 仅当引导层确实调用并成功生效 |
| **免费** | 每件 **`POWERUP_FREE_USES`** 次 / 关 | 关内态，整关重置复位 | **不入档** | 效果实际生效后 −1 |
| **购买** | 受「每关额外上限」与「每型子限」约束 | 关内态，整关重置复位 | **不入档** | 扣豆成功且生效后 −1 |
| **视频** | 受「每关额外上限」「每型子限」「每日广告次数上限」三约束 | 关内态 + 日计次入档 | 日计次**入档** | `onRewarded` 且生效后 −1 |

- **消耗优先级**（玩家无感，纯系统序）：**引导 → 免费 → 额外**。额外内部玩家显式二选一（购买 / 视频），系统不代选。
- **复位时机**：进入新关（BOOT→PLAYING 装配）与整关重置（失败重试 / 暂停重玩 / 换关）⇒ 免费与额外额度回初值（`§3.5` 重置条目）。引导额度**不复位**（账号级）；日计次按**本地日**（`dateKey`，与签到 / `HEART_AD_DAILY_LIMIT` / `CLEAR_COIN_REPLAY_DAILY_CAP` 同口径）归零。
- **不入档原则不变**：免费与额外次数仍是关内态，不跨关累积、不进存档主结构（`§3.6`）。新增的两项（引导已用位、视频日计次）**必须入档** ⇒ 走 S8 存档变更单（见 §7）。
- **扣次唯一口径**：只有 `affectedCells` 非空（真的改了盘）才扣。零错位珠、非法 state、非法 type、豆子不足、视频未看完，一律**零扣次**。

### 5.3 推荐值与推导依据（供拍板直接读）

**T-2 每关额外次数（推荐「合计 2、每型 1」）**
依据 = §2.2.4 连续使用序列表：5 个普通关**第 3 次星引棒即清零**。把额外额度卡在 2 且每型限 1 ⇒ 单关星引棒最多用 **免费 1 + 额外 1 = 2 次**，序列读数落在「剩 **2–49 颗**（M 的 **1.6%–40%**）」⇒ 玩家**必须自己打完最后一段**，道具不构成买通关。
⚠ **一处例外必须写明**：L00007（14×8、M=60）2 次后只剩 2 颗 ⇒ 该关「免费 1 + 额外 1」已近乎打完。这是「定长 6×6 窗口在小盘上占比天然高」的固有代价（同 A 在最小档 6×5 = 整盘全清的极端属同一族），缓解只能靠「小盘不开放额外通道」或「小盘单价上抬」，属 playtest 后调价，⛔ 不得为此改 `SIDE`。
「每型 1」而非「只限合计」的理由：中/小盘上星引棒价值是线引棒的 **1.8–4.3 倍**（§2.2.3），若只限合计，玩家永远把额度花在星引棒上、线引棒变成纯摆设（退化策略）；每型 1 逼玩家在「再来一片」与「串几颗」之间做选择，两件都有人用。
**备选「合计 1」更严**：适合 playtest 判「道具仍太强」时收紧；代价是 B 的出场率会很低。

**T-4 每日赠送（推荐「乙：每天 1 次、跨关通用、不累积」）**
- 甲（不送）的问题：入门只给「引导 1 + 免费 1」，第二天起没有任何「不用豆子也能用道具」的理由 ⇒ 道具只剩付费触达，与「治愈向休闲」的玩家结构不符。
- 乙的依据：成本上限 = **1 次 / 天 × 1 件**（不累积 ⇒ 不能攒）；与签到（七日七份礼）、`HEART_AD_DAILY_LIMIT`（5 次/日）共用 `dateKey` 本地日口径，零新机制；留存侧它是「签到之外的第二条回访理由」，且**不引入新页面**（在道具卡上直接显示「今日 1 次」）。
- ⚠ **经济影响（不得隐去）**：按 20 豆/次的最低档折算，每日 1 次 ≈ **44% 的签到日均产出（45.7🪙）** 被绕开。若道具是主力豆子出口（`§3.14` v1.80），这会显著降低购买频次。**缓解**：只送**线引棒**（便宜那件）而非二选一，或只在「本关首次失败后」解锁当日赠送（丙的变体）。
- 丙的依据：星引棒在中/小盘上单次价值是线引棒的 **1.8–4.3 倍**（大盘上两者持平，见 §2.2.3），白送它等于每天白送一次「半关」，风险明显高于乙。

**T-5 定价（推荐 线引棒 20 / 星引棒 45）**
沿用**仍有效的**「20 豆 = 一局价值」定价基准（经济体提案 **§15.4**，该节其余内容已作废但此基准被明确继承）。
- 线引棒 = 20（= 1 局）：中/小盘净归位 12–23 颗，是「一次便宜的补点击」；
- 星引棒 = 45（≈ 2.25 局）：中/小盘净归位 29–61 颗（M 的 36%–64%），是「一次半关级推进」；
- ⛔ 两件不得同价：同价会让玩家永远买 A（§2.2.3 价值差证据）。
- ⚠ 更贵的选项（星引棒 60+）在 boss 关上不成立：L00009/L00010 上星引棒只推进 5.9%/6.8%，玩家会算出「60 豆买 6% 进度」而不买——**这正是「6×6 定长窗口」在大盘上的固有代价**，价格不宜再抬。

**T-10 / T-11 线引棒取量（推荐 Q=0.05、MIN=`TRAY_BASE_SLOTS`）**
现池 `M` 跨度 17 倍（60–1024），用户 2026-10-26 明确指出「如果只是限制珠子个数，可能不同小关道具使用价值差异较大」⇒ 必须**按当前剩余归一化**（这条推导链继承经济体提案 §15.2，该节其余数值已作废）。
- `MIN` 取 `TRAY_BASE_SLOTS`（不写死 12）的理由：语义可读——「一串 = 一整托盘珠」，玩家一眼懂；且 `§3.4` 改容量时本值自动跟随（托盘档位制改动零涟漪）。
- `Q = 0.05` 的理由：要让线引棒在大盘上落到与星引棒**同量级**（星引棒 5.9%–6.8%），5% 给出 5.1%–7.9% ⇒ 两件在同一水平，谁都不支配谁；取 10% 则大盘上 B 反超 A 一倍（52→102 颗），定价逻辑立刻失衡。
- 副作用（诚实）：因为 `0.05 × M ≤ MIN` 在 `M ≤ 240` 时恒成立，**现池 8 个普通关的取值全部落在下限 12**，即「比例式在普通关实际退化成了固定 12 颗」。这不是 bug，是「普通关规模相近」的事实；比例腿只在 boss 盘（30×30 / 32×32）才真正起作用。若日后普通关盘面拉大到 `M > 240`，比例腿自动接管，无需改码。

### 5.4 本体系**不**改动的量（防误伤清单）

`MISPLACED_PAIRS_MIN/MAX` · `misplaced` 判定式 · `TRAY_*` 全族 · `STAR_TIER_*` · `LEVEL_TIME_*` / `SEC_PER_STEP` · `REVIVE_*` · `STAMINA_*` / `HEART_AD_*` · `CLEAR_COIN_*` · `AUDIO_CLIP_TOTAL`（**不新增 clip**：两件道具复用 `sfx_powerup` + `sfx_dissolve`，因为 `audio-events §1` 的触发源是 `powerup:used` 事件本身，与 type 无关）。

## 6. 边界条件

**极端值 / 小盘**

- **盘面 < 6×6（贴边收缩）**：`w = min(SIDE, cols)`、`h = min(SIDE, rows)`；若某轴 < 6，该轴仅剩**唯一**候选位置（窗口 = 整条轴）⇒ 窗口自动等于全盘。`GRID_MIN_COLS/ROWS = 6/5` 的最小盘 6×5 ⇒ `w=6, h=5` ⇒ **窗口 = 整盘 ⇒ 一次点击即整盘全清 = 直接过关**。⚠ **这是已拍板的已知后果，不是缺陷**（用户 2026-10-26 明确接受）。当前关卡池**没有** ≤6×6 的盘（最小 14×8），该极端只由未来最小档关卡触发；届时应重新评估「免费 1 次即通关」的力度（缓解杠杆见 §5 T-2 / T-5，⛔ 但不得自行改 `SIDE`）。
- **窗口内 0 颗错位珠**：星引棒与线引棒都按「盘上零错位珠」处理 ⇒ **不广播、零格变化、零扣次**（沿用 2026-09-12 裁定：免费次数是稀缺资源，不应被误触或空目标吞掉）。若盘上仍有错位珠但最密集窗口恰好全就位——**不可能**（最密集窗口的命中数 ≥ 任一其他窗口；盘上有错位珠 ⇒ 存在含它的窗口 ⇒ 最密集窗口命中 ≥ 1），故无需为「有错位但窗口为零」单独设分支；该情形只可能由镜像漂移伪造，走漂移分支。
- **剩余错位珠 < `MIN`**：线引棒 `k = 剩余` ⇒ 一次全清（这就是设计意图）。
- **最后一颗被归位**：S3 写入路径与玩家归位路径**完全同构**（`bead-grid §2.3` 路径 B）⇒ 完成判定照常触发 `level:cleared`。道具不得自行判定通关。

**多环 / 递归**

- **区域内多环不链式递归**：本版**没有递归**。每次交换只动两个格，交换次数 ≤ 窗口错位格数（A）/ ≤ `k`（B）⇒ 一次点击至多牵动 `2 × hits` 个格。⛔ **不做环轮转**（理由与实测见 §2.2.1「为什么不是环轮转」：环闭包会归位 M 的 69.6%–100%）。
- **连带面必须有界且可测**：`affectedCells` 长度 ≤ `2 × hits`，且窗口内残留恒为 0（§8-3 断言）。

**并发 / 竞态**

- **与取回/归位争用同一颗珠**：同属**输入段**且每帧最多 1 条输入指令 ⇒ **不可能同帧**（`core-loop §2.2.2`）。跨帧时后到者按最新格态解释：目标珠已归位则重算候选序；镜像漂移则 S3 重算并记警告。
- **与 `level:cleared` / `level:failed`**：S1 一旦离开 PLAYING，其后到达的道具请求**全部作废**（零事件、零扣次）。§2.3 单步结算，无瞄准中间态可留。
- **PAUSED 中请求与 `game:resumed` 同帧**：请求**作废**，不缓存、不重放（S2 门禁优先）。
- **双通道面板打开期间**：其余输入被模态吞掉；面板期间 S1 若离开 PLAYING（如超时判负）⇒ 面板关闭且**不扣次、不扣豆、不发奖**；视频已拉起但页面被系统挂起 ⇒ 按 `skipped` 处理。
- **连点同一张卡**：帧内合并沿用 `input-control §2.4` 去抖窗口；跨帧第 2 次按额度规则处理（不设独立冷却，§3 未冻结冷却值，不写）。

**非法输入**

- **非法 `type`**：`type ∉ POWERUP_TYPES`（含 `undefined` / 拼写错 / **旧类型名 `solver` / `solverPlus` / `solverRandom` / `region` / `clearAll` / `random`**）⇒ 忽略 + 警告日志，零事件零扣次，不崩溃。⛔ **旧类型名不得静默映射到新类型**——两套体系语义完全不同（旧 = 1/3/随机 1 颗，新 = 6×6 窗口 / 定量），静默映射会造出「玩家点旧卡得到一片全清」这类事故。
- **非 PLAYING 状态**（BOOT / PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH）收到请求：S6 二次防御性忽略（S2 已在路由层拦）。
- **`affectedCells` 含非法格**（越界 / `locked` / `filled(就位)`）：S3 拒绝该格写入 + 警告；实际写入集合与 payload 不一致时记漂移警告。
- **豆子不足 / 达上限 / 视频未看完**：轻提示，零扣次、零扣豆、零格变化；不重复弹面板（同一帧内只弹一次）。
- **镜像漂移**（S6 认为某格错位、S3 已就位）：S3 重算目标并记警告（幂等，不重复写入）。

## 8. 验收标准（可纯 Node 断言的硬判据；未标环境者均 `[Node]` vitest 可断言）

> 记号：`hits` = 最密集窗口内错位珠数；`ΔM` = 一次使用前后的错位总数差；`affectedCells` = 事件 payload。

1. **窗口选取的确定性（同输入 ⇒ 逐位相同）**
   同一盘面快照连续调用两次裁定函数 ⇒ 窗口 `(r₀, c₀, w, h)` 与 `affectedCells` **逐字段相等**；且工具的 `services.rng` 调用计数 **= 0**（本版两件道具均不消费随机源）。对 10 关全量跑一遍，锚点必须与 §2.2.4 表的 `锚点` 列逐关一致：`(1,3) (3,2) (4,4) (3,3) (4,3) (3,4) (1,1) (3,2) (12,12) (13,13)`。
2. **tie-break 五级链各自生效**
   构造四个夹具分别只靠第 2 / 3 / 4 / 5 级分胜负：(a) 同级命中、就位数不同 ⇒ 取就位少者；(b) 前两级同 ⇒ 取整数曼哈顿距离小者；(c) 前三级同 ⇒ 取行号小者；(d) 前四级同 ⇒ 取列号小者。另断言 `L00009` 的 345 个并列窗口与 `L00010` 的 729 个并列窗口下**输出唯一**（不是任意一个）。
3. **贴边收缩正确性**
   (a) `6×5` 盘 ⇒ `w=6, h=5`、候选位置数 = 1、窗口 = 整盘；使用一次后 `M = 0`（整盘全清）。
   (b) `5×5` 盘 ⇒ `w=5, h=5`、窗口 = 整盘、一次全清。
   (c) `7×6` 盘 ⇒ `w=6, h=6`、`c₀ ∈ {0,1}` 两个候选，命中多者胜。
   (d) 任何盘面下 `w ≤ SIDE ∧ h ≤ SIDE ∧ r₀ ≥ 0 ∧ c₀ ≥ 0 ∧ r₀+h ≤ rows ∧ c₀+w ≤ cols`。
4. **区域内全归位（硬承诺）**
   10 关全量：一次星引棒后**窗口内错位格数 = 0**（§2.2.4「窗内残留」列逐关为 0）；抽样 30 个随机盘面（固定 seed 生成，只用于造夹具、不用于道具）同样为 0。
5. **单调不变式（守恒与不增错位）**
   `hits ≤ ΔM ≤ 2 × hits`（星引棒）；`k ≤ ΔM ≤ 2 × k`（线引棒）。10 关全量断言；并断言**每色珠数在前后完全相等**（置换、不造珠不灭珠）⇒ 盘面可解性未被破坏。
6. **就位珠与锁定格逐格不变**
   使用前后逐格比对：所有 `filled(就位)` 格的 `colorIdx` 一字节不变；所有 `locked` 格不变；`selection` 锚不变。
7. **托盘零写入**
   使用前后**托盘全部槽态逐一相等**（`free`/`holding`/`selected` 计数与逐槽 `colorIdx`），`tray:stored` / `tray:selected` / `tray:expanded` 计数增量 = 0，且 S6 无对 S4 的直接调用（依赖守卫断言）。
8. **S3 写入与 payload 1:1**
   `powerup:used` 恰 1 次；`affectedCells` 集合 ≡ S3 实际珠色变化的格集合（逐格 `row/col/colorIdx` 全等，含**窗外**被换位的格）；`|affectedCells| ≤ 2 × hits`；`bead:placed` 次数 = 本次新增 `filled(就位)` 格数，且每条 payload **无 `slot` 字段**。
9. **零错位珠不扣次**
   棋盘全就位时使用任一道具 ⇒ `powerup:used` 计数 = 0、格态零变化、**四类额度（引导/免费/购买/视频）全部不变**、豆子不变。
10. **次数模型与复位**
    (a) 消耗优先级 = 引导 → 免费 → 额外；引导额度先被吃掉时免费额度不变。
    (b) 每件免费额度用尽后，第 2 次点击进双通道分支（零 `powerup:used`、零格变化、零扣豆）。
    (c) 每关额外上限（T-2 建议 2）与每型子限（建议 1）各自独立生效：A 买 1 次后再买 A 被拒；A 买 1 + B 买 1 成功；第 3 次任一件被拒。
    (d) 失败重试 / 暂停重玩 / 换关 ⇒ 免费与额外次数回初值，**引导已用位不变**。
    (e) 免费与额外次数**不写存档主结构**（存档 diff 为零）；引导已用位与视频日计次**写档**。
11. **跨本地日复位**
    本地日 `dateKey` 变更后，视频日计次归零、可选日赠送额度回 1；同一本地日内不可重复领取赠送；跨日不累积（第二日仍是 1，不是 2）。
12. **非法输入与状态门禁**
    (a) `type` 为 `solver` / `solverPlus` / `solverRandom` / `region` / `clearAll` / `random` / `undefined` / 空串 ⇒ 忽略 + 警告、**不静默映射到新类型**、零事件零扣次、不抛异常（断言「旧名 → 新类型」映射表不存在）。
    (b) BOOT / PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH 五态各注入两件道具的请求 ⇒ 事件计数 = 0 且四类额度不扣。
    (c) PAUSED 期间的请求在 `game:resumed` 后**不被重放**（事件计数仍 0）。
13. **同帧竞态与幂等**
    注入「道具 vs 取回/归位同帧争用同一颗珠」⇒ 按 `core-loop §2.2.2` 帧内序解释（同属输入段者每帧至多 1 条指令 ⇒ 不可能同帧）；跨帧后到者按最新格态重解释；无重复写入（同输入连调两次结果幂等）、无负计数、无异常抛出。
14. **视频腿失败不发奖**
    `onRewarded(skipped)` / `onError` ⇒ 零扣次、零扣豆、零格变化、日计次不变；开发期「失败即照发」降级分支**必须由开关显式控制且带删除标记**，测试断言该分支在 release 配置下关闭。
15. **架构守卫**
    S6 与两件道具的裁定实现**零 `Math.random`**（`pnpm run check:arch`，铁律 L4）；`src/**` 零 `import 'cc'`（L3）；裁定函数纯函数、无副作用、热路径零分配。
