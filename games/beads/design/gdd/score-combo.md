## 1. 目标

给两类模式各配一条"进度可感"的计分线：普通关以**星级**承载成就型驱动（零局内 HUD 负荷，支柱 1）；冲刺模式以**连击倍率 + 单局分**承载节奏感与长时沉浸（用户六目标），并产出可排行、可存档的最佳分。

## 2. 机制

### 2.1 双模式总览

| | 普通模式（现有 8 关） | 冲刺模式（本篇新增，2026-09-12 用户拍板冻结） |
|---|---|---|
| 目标 | 填满图案 → 星级 | 无尽爬梯：连续完成小图案冲分 |
| 局内 HUD 计分 | **无**（决策 D6 维持） | 有：分数 + 当前倍率 + 连击数 |
| 计时 | `LEVEL_TIME`（§3.5，180–420s） | `SPRINT_TIME_DEFAULT` 单局时长（附录 C1） |
| 失败 | 倒计时归零（唯一，D7） | 倒计时归零（唯一；托盘满仍只告警不判负，与 D7 一致） |

### 2.2 普通模式：星级（冻结）与结算分（提案）

- 星级 = **档内按实际用时判星**（§3.7 **v1.78 新制**，用户 2026-10-17 拍板；正本 `proposals/star-collect-rule.md` R1–R5）：本局倒计时 = 进场档位线（`tierSecondsFor(level.time, 档)`，三线共用 `STAR_TIER_K=[1.00,0.85,0.70]`，⛔ 不另存数）；倒计时内完成 ⇒ 用时 ≤3★线→3★／≤2★线→2★／其余→1★（首次 1★ 档进场也可当场跳 3★）；超时看广告续时后完成 ⇒ **保底 = 进场档位星**（不看用时、不可能跳档）；失败不续时 ⇒ 本局无星、不动历史最高。下次主动进场档 = 本关历史最高 +1（封顶 3★）。总星数（皮肤货币/主界面显示）= Σ 各关历史最高（`starsByLevel` 零改动）。`level:cleared` payload 的 `stars` 由 S7 计算后随事件分发（§4 既有事件，零新增）。⚠ **漂移自白（K-046）**：本行旧文仍写 v1.0 制 `ratio ≥ STAR3_RATIO(0.32)/STAR2_RATIO(0.12)` 与 `starRemaining`——两常量已分别于 v1.50/v1.78 删除或划史证，本批顺带订正；`ratio` 仍计算并上报，但**只供 C7 结算分展示**。
- 结算分（用于未来排行/段位，**局内不显示**）：`settleScore = stars×1000 + round(ratio×1000) − powerupsUsed×50 + (未用扩展 ? 200 : 0)`——全部系数列附录 C7（已冻结，2026-09-12 用户拍板）。

### 2.2.1 星级时间计算规则链（**v1.2 新增 · WXG-T-394 合订**）

> **一句话**：星级不是「玩家打得多快」，而是**先算这关最少要几步，再把步数装进某一档时钟**。
> 本节 = 可读版规则链；数值真源 = `systems-index §3.5`/§3.7，公式正本 = `levels-spec §5.0`——一律**引用**，⛔ 不复制常量。

```
① S    = bot 在「基础档 12 槽」按固定策略跑出的批量动作数（直填+取回+落子，选锚并入被服务的动作）
         锁死 = branchOrder 'ACB'（归位→直填→取回）+ retrieve:'max' 真降序 + 只计返回 true 的成功动作
         ⛔ 不得改回 'BAC'：取回优先会囤货 ⇒ 步数随容量递增（L5 三档 64/68/110），容量轴失效（v1.85）
② need = ceil(S × SEC_PER_STEP)                          ← 2★ 档「至少要给的秒数」，§3.5
③ T₁   = clamp(ceil(need ÷ STAR_TIER_K[1]), LEVEL_TIME_MIN, LEVEL_TIME_MAX)   ← 1★ 时钟，§3.5/§3.7
④ 三档 = tierSecondsFor(time, tier) = clamp(round(time × K[tier]), STAR_TIER_FLOOR[tier], …)
⑤ 判星 = 档内按实际用时（§2.2，v1.78 R3/R4），非「剩余 ÷ 总时长」
```
⚠ **两级 `ceil` 不可省**：只做一次会被 `tierSecondsFor` 的 round 吞 1 秒（实测 `S=109`：217s → 预算 108 < 109，须 218s）。

**单关系数通道 `level.starTierK`**（§3.7 v1.86）：只改「`time` × 系数」的**系数**，⛔ 不存三个绝对秒数（`time` 仍是 1★ 时钟单一真源）；形态 = 长度 3 / `[0]===1` / 严格递减，生成期 `assertStarTierK` 硬拦。

**算例（L9 boss）**：最省 12/24/48 = **110/71/50** 步 → 3★ 预算 **55** 步 → `ceil(55×4.14)=228s` → 系数 `228÷546=0.4176`（覆盖全局 0.70）。自洽：24 槽最省 71 > 55（差 16 步）⇒「必须 48 槽」是实测结论；余量 `55−50=5` 步 =「很赶但可及」。

**为什么基准档是 2★**：`T₁` 由 `S@12` 反解 ⇒ 2★ 秒数**恰好**等于基础档最优解 = 「不看广告的满分线正好压在最优解上」（紧平衡）。代价照实说：人类多花 2–3 动作就掉 1★（调法 C9 #1，⛔ 别改 `STAR_TIER_K`）。

**容量-星级判据**：`tierStepBudget(T₁, tier) = floor(tierSecondsFor(T₁, tier) ÷ SEC_PER_STEP)`

| 判据 | 不过时 |
|---|---|
| `S@12 ≤ tierStepBudget(T₁, 2)` | **硬拦**：基础档拿不到 2★ = 定价自相矛盾 |
| `min(最省@24, 最省@48) ≤ tierStepBudget(T₁, 3)` | **告警**：判据出自 ±29% 残差单价 × bot 贪心，⛔ 不得据此判死关卡 |

钳位关跳过两条（地板把档秒数与步数解耦）。

### 2.2.2 两种「步数」口径（⛔ 混用会把「够」误报成「不够」）

| 口径 | 取法 | 用途 | ⛔ |
|---|---|---|---|
| **定价口径** `pricing.stepsByCap` | 一条固定策略（`ACB` + `max` + 不复用锚）在 12/24/48 各跑一次 | 跨关可比定价 | **不可判可达性**：大容量下偏松——L9 48 槽 **76** vs 最省 **50**（差 52%）⇒ 会误报「拿不到 3★」 |
| **最省解** | `BEST_EFFORT_POLICIES` 6 策略（`ACB/ABC/CAB/CBA/BAC/BCA` × `max/min` × 锚复用）取最小 | 可达性判定（该开几槽） | **不可定价**：换口径 = 历史全部 `time` 失效 |

**铁律**：定价只用单一口径；可达性只读最省解且带**自洽核验**（输出「低档最省仍差 N 步 ⇒ 必须 X 槽」，低档本就够时该结论必须**不成立**）。推论：`stepsByCap` 在 24/48 槽是**上界**，容量真实收益比表上更大。

### 2.2.3 余量判读（「很赶」的量化定义）

`余量 = tierStepBudget(T₁, 3) − 最省解(拿到 3★ 的那一档)`

| 余量 | 读法 | 处置 |
|---|---|---|
| < 0 | **拿不到** 3★ | 扩容，或改该关 `starTierK[2]` |
| 0 | 零容错（紧平衡下沿） | 设计裁定，不属调参 |
| 1–8 | 很赶（**4–8 = 很赶但可及**，现池 L9 = **5**） | 观察；过紧调 `starTierK[2]`，过松收系数 |
| > 8 | 偏松 | 收系数（⛔ 不动全局） |
| 带宽内 | ⛔ 不判 | 既不算超线、也不据此放宽门限 |

> ⚠ **留余量 ≠ 放宽门限**：调余量走「改关系数 / `slack`」（C9 #1/#2）；⛔ 为读数过线而改门限 = 改安全余量设计，须设计侧单独裁定。

### 2.3 冲刺模式：无尽爬梯

- 单局结构：1 局 = `SPRINT_TIME_DEFAULT` 秒倒计时（附录 C1）＋ 串行小图案阶梯。每梯级（stage）装载一个小图案（复用 S3/S4/S3 全套机制，参数按梯级公式生成，附录 C6——公式为**预算口径**：色数/格数是该 stage 的上限预算（用于选池与校验），实际棋盘取池图案本身，见 §9 C6 设计说明）；**stage 填满 → 立即换下一 stage**（广播 `sprint:stage`，见 §2.5），不结算不弹窗，节奏不断；**换 stage 时托盘清空**（新图新供料，裁定依据见 §9 C8 补记）、连击不断（C8 例外条款）。
- 难度爬梯（附录 C6 公式，已冻结 2026-09-12）：梯级 n 的 色数 = min(3+⌊n/2⌋, `BEAD_COLOR_MAX`)；格数 = min(6×5+…) 上限 13×12（§3.3）；供料间隔 = max(6.0−0.5n, 2.0)（区间端点对齐 §3.4）。图案库从 levels-spec 8 关图案池循环取用（原创图案，规避 IP 风险——参考分析 §8）。
- stage 完成奖励：加时 `STAGE_BONUS_TIME` 秒（附录 C5）+ 固定分（附录 C5），倒计时与爬梯双向形成"越玩越紧"的心流坡。

### 2.4 冲刺模式：连击系统

- **连击窗口**：两次正确落子间隔 ≤ `COMBO_WINDOW_S` 秒（附录 C2）保持连击；超窗 = "犹豫断连"（用户目标明示）。
- **倍率阶梯**：连续正确落子数（streak）达 `COMBO_STREAK_TIERS` 阈值（附录 C3，推荐 2/4/7）→ 倍率 ×2/×3/×5，上限 `COMBO_MULT_MAX=×5`。
- **断连条件**（三选一即断，streak 清零、倍率回 ×1）：
  1. 放错（`bead:rejected`）——立刻断连；
  2. 窗口超时（正确落子间隔 > `COMBO_WINDOW_S`）；
  3. stage 切换**不断连**（跨 stage 连击延续——连续挑战的核心爽点，附录 C8 例外条款，已冻结 2026-09-12）。
- **取回不计分不断连（v1.1 新增，WXG-T-130 用户裁定）**：`tray:stored`（取回）**不产生分数**（非落子）、**不重置连击窗口**、**不推进也不打断 streak**——连击唯一计数进 = `bead:placed`、唯一断出 = 上两条。理由：取回是解谜周转步而非「正确落子」，若取回续窗则玩家可借无限取回白嫖窗口，破坏「犹豫断连」的节奏张力；若取回断连则惩罚了必要操作，违背 A4 零惩罚精神。同理，**取回不计入 stage 完成判定**（完成只看错位珠全部归位）。
- 计分：每次正确落子 = `SCORE_PER_BEAD × 当前倍率`（附录 C4）。普通模式**完全不走本节**（连击系统仅存在于 sprint 模式）。
- 断连不扣分、不扣时（惩罚 = 倍率归零的机会成本本身；与普通模式 A4"放错无惩罚"精神一致，冲刺模式因有倍率增益故惩罚已有）。

## 6. 边界条件

**极端值**
- sprint 开局即连续超窗：streak 恒 0、倍率 ×1，仅基础分累计，无死局。
- stage 填满瞬间单局时间同时归零：**stage 优先结算再加时**——若加时后 >0 则继续爬梯，仍 ≤0 才判负（cleared 优先精神的 sprint 变体，附录 C8 已冻结 2026-09-12）。
- 连击窗口计时与 PAUSED：窗口计时随 PAUSED 冻结（复用 S5 冻结语义），恢复不追溯断连。
- `SPRINT_TIME` 覆盖值越界（<90 或 >120）：BOOT 拒绝该配置，回退默认（对齐 S5 §6 防御口径）。

**并发 / 竞态**
- `bead:placed` 与 `bead:rejected` 同帧：**不可能同帧** —— 两者都由一次落子裁决产生，而每帧最多 1 条输入指令（`input-control §2.4`）；产生哪个只取决于该次落子的颜色是否匹配。原「按到达序处理——先 placed 后 rejected…」两种分支**均不可达**，随「到达序」基准一并作废（WXG-T-061）。
- 连击窗口到期与正确落子同帧：**落子判有效**。基准改为 `core-loop §2.2.2` 帧内序——落子属**输入段**、连击窗 tick 属**连击窗段**（紧接输入段之后）⇒ 落子当帧已重置窗口，本帧窗口不会再穿透判定。结论与旧表述一致，基准由「事件到达时序」改为帧内序。
- `sprint:ended` 与 `combo:up` 同帧：`sprint:ended` 由归零判定产生（**计时段**），`combo:up` 由落子产生（**输入段**）⇒ 按帧内序 combo 先、ending 后；S1 一旦离开 PLAYING，其后到达的 combo 事件被丢弃（`core-loop §2.2.2` + §6 同款裁决）。
- stage 切换与道具请求同帧：**不可能同帧** —— 两者同属输入段且每帧最多 1 条指令。跨帧按帧内序：stage 切换（含**托盘清空**，裁定见 §2.3 / §9 C8 补记）先于其后帧的道具请求；S6 单步结算无中间态（S6 §2.3），无叠加风险。

**非法输入**
- sprint 模式收到普通模式 `level:cleared`（stage 完成不走该事件，走 `sprint:stage`）：防御忽略 + 警告。
- 倍率计算收到 streak < 0 或非整数：钳 0 + 警告。
- 普通模式误开连击计数（mode 标志丢失）：mode 从 S1 单向读取，S7 不自持模式态，杜绝漂移。

## 7. 依赖

- **上游**：S1（模式标志、状态门禁、cleared/failed）、S3（placed/rejected）、S5（sprint 倒计时真源）、S6（结算统计）、S8（最佳分读写）。
- **下游**：S8（冲刺最佳分/连胜写入——v1.1 字段已冻结 2026-09-12）、视觉/音频层（特效三档、音效）、未来排行（meta-framework 提案消费 settleScore/sprint 分）。

## 8. 验收标准（可测试硬判据，QA 直接造用例；附录 C1–C8 已于 2026-09-12 冻结（systems-index §3.10），全部判据可执行）

1. 普通模式局内全程零分数 HUD 元素；过关后 `level:cleared` payload 的 stars 与 §3.7 **v1.78 判星线**逐一吻合（**判据族沿 `star-collect-rule.md` R3/R4/R5**：进场档三线两侧采样〔含 1★ 档当场跳 3★ 正例〕 + 续时保底 = 档位星臂 + 失败无星臂 + 下次进场档 = 最高+1 臂；旧 ratio 四点采样腿随 v1.50/v1.78 作废，⛔ 不得按已删常量建用例，EP14-S1 落码验收线）。
2. 普通模式结算分 = 附录 C7 公式逐项可复算（构造 stars/ratio/powerupsUsed/扩展四因子组合各 1 例）。
3. sprint 单局时长 = `SPRINT_TIME_DEFAULT`（未覆盖时），误差 ≤ ±0.5s（联合 S5§8-1）。
4. streak 达 C3 各阈值瞬间倍率切换为 ×2/×3/×5，`combo:up` 恰各 1 次；超过最高档 streak 继续增长但倍率封顶 ×5。
5. 断连三分支各 1 例：放错（rejected 后 streak=0、`combo:break{reason:'wrong'}`）、窗口超时（> `COMBO_WINDOW_S` 无落子，reason='timeout'）、无第三分支误触发。
6. stage 填满 → `sprint:stage{stageIndex}` 恰 1 次（`stageIndex` = 新 stage 索引，即已完成 stage 索引 + 1）、新图案 ≤1 帧装载、**连击跨 stage 延续**（streak 值不变）。
7. stage 完成加时后 remaining = 原值 + `STAGE_BONUS_TIME`（钳单局上限）；加时与归零同帧按 C8 裁决。
8. sprint 单局得分 = Σ(SCORE_PER_BEAD×倍率) + Σ stage 奖励，注入 20 次落子序列逐分可复算。
9. 特效档位与倍率档一一对应（×2 粒子/×3 伪震屏/×5 全屏爆发），全程无 >3Hz 闪烁、无真位移震屏（§3.8 红线，DevTools 帧检）。
10. PAUSED 期间连击窗口计时冻结（恢复后窗口从暂停值续算）；普通/冲刺模式互窜注入（sprint 中发 level:cleared）→ 防御忽略 + 警告。
11. 破纪录：sprint 结算分 > S8 最佳 → NEW BEST 显示且 S8 写入新值；≤ 最佳 → 不写不显示。（"sprint 结算分"即 `sprint:ended.settleScore`，与 §8.8 的单局分同值）
12. **取回不计分不断连（v1.1 新增）**：注入「归位 → 取回 → 归位」序列（取回间隔 > 0 且 < `COMBO_WINDOW_S`）→ streak 连续递增、`combo:up` 按阈值正常触发、`combo:break` 计数 =0；单局分只随两次 `bead:placed` 增长（`tray:stored` 前后分数差 = 0）；取回与下一归位间隔 > `COMBO_WINDOW_S` 时**仍断连**（取回不续窗）。解环器归位（`bead:placed` 无 `slot`）**正常计分**（它是一次真实落子，仅非托盘来源）。
13. **定价链可复算（v1.2）**：由 `S@12` 独立复算 `T₁ = clamp(ceil(ceil(S×SEC_PER_STEP)÷STAR_TIER_K[1]), MIN, MAX)`，与关表 `time` 逐关相等（钳位关断言钳位前后），且全关 `S@12 ≤ tierStepBudget(T₁, 2)`。
14. **可达性只读最省解（v1.2）**：带 `starTierK` 的关，报告须并出定价口径与最省解两列；「必须 X 槽」仅当「低档最省仍差 N 步」成立时出现；反例锁 = 低档本就够的关该结论不得出现（防退化为无条件输出）。
