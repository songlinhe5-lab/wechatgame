# ── 直填是必需路径（bot 策略反证）─────────────────────────────────────────────
# 假设「玩家只走批量取回+批量填充 ⇒ taps 远低于 bot」被实测推翻：
# 令 runBot(allowDirectFill:false) 后 **10/10 盘全数死锁**（taps 2–28，通关=N），
# 卡死态形如 `no-move tray=111111111111 holes=12 misplaced=…`：
#   全错位初盘空格数 = 0；取回一组同色珠 ⇒ 托盘被单色占满，而留下的洞底色 ≠ 该色
#   ⇒ A 路径（托盘珠→同色底洞）无合法目标，B 路径满槽禁取 ⇒ 无步可走。
# 直填（T-162 board 锚 + T-180 一次点击整片归位）不吃托盘容量，是唯一能开出洞的路径。
# 因此 taps 口径与 runBot 的贪心策略（A 归位 → C 直填 → B 取回）绑定：改 bot 策略须重锚 SEC_PER_TAP。
