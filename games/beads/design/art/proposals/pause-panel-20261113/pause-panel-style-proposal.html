暂停面板：按功能分区重做视觉层级

同一个面板同时承担「暂停」「设置」「退出」三件事。现在的 12 个次级按钮全部是同一副纸面， 玩家只能逐字读文案才能分辨功能。本方案不增加任何功能、不改面板尺寸，只把按钮按职责分成 主操作、设置、辅助、外观、本局五个区，并让每类控件拥有各自的形态与状态语言。

依据：ux-spec §3.3 暂停面板 · art-bible T1 纸 / T3 木 / chip 矩阵 · 现有 palette.ts token（零新增色值）。本稿只出方案，不改代码。

01现状诊断

截图对应当前实现（五行共 12 个按钮 + 木主钮）。问题不在材质，而在「功能」没有进入视觉。

  • 层级缺失。除了「继续」，其余 12 个按钮全部是纸面同一形态，主操作、设置、退出三类职责没有分界。
  • 状态太弱。开关只靠文案尾缀「开 / 关」表达状态；全关时 7 个开关与选择器、动作按钮几乎同款。
  • 选择器没有切换暗示。标签与当前值同字号、同颜色、同一行排开，既挤又读不出「点按可循环」。
  • 高风险动作不设防。「重玩本关」「回主菜单」与音量开关同权重，误触代价完全不对等。
  • 没有扫读路径。五行三列密铺、无分区标题，视觉上更像调试面板而不是玩家设置页。

02功能分区

在不改变面板高度、行高、列宽与热区的前提下，把现有 30px 行间距用作分区标题带（28px 字面 + 1px 细线）， 按钮位置一格不动。行内容按职责重排如下（动作 id 与语义不变，仅换格位）：

分区按钮（左 → 右）控件族分区要传达的事
主操作继续T3 木主钮唯一的「回到对局」，保持全场最高权重
设置音乐 · 音效 · 震动开关 chip声音与触觉反馈，开关状态一眼可读
辅助减弱动效 · 大字号 · 幽灵符号开关 chip可访问性与显示辅助，同族同形
外观珠子风格 · 豆子尺寸 · 皮肤选择器卡片点按循环切档，值即状态
本局重玩本关 · 性能信息 · 回主菜单纸动作钮 / chip / 弱化退出钮会话级动作：重置、调试信息、离开

说明：「性能信息」本质是调试项，现落脚在「本局」行末段。若后续愿意把它移入菜单设置或仅在调试模式显示， 本方案无需改样式；这属于功能口径变更，不在本稿范围。

04关键数值与对比度

几何（全部沿用现值）

面板 560×718；内缩 20；列宽 160；列间 20；行高 88；行间 30；主钮 240×88。分区标题占据现有行间，不推按钮。

字档

标题 40 粗；主钮 / 纸动作钮 30 粗；chip 与选择器标签 22；选择器值 22 粗（新增语义键，字面复用现有 22 粗档）；分区标题 22。

状态双通道

开关同时用「底色 + 胶囊文字」两条通道表达开 / 关，不依赖色相；按下保留位移通道，减弱动效时由换面承担反馈。

文字 / 底色对比度用途
woodText / woodFace5.40 : 1木主钮、开态 chip 文字
text / panel13.06 : 1纸动作钮、选择器值
textDim / panel4.63 : 1chip 关态标签、分区标题（22px 正文门 4.5）
text / cardPressed11.21 : 1按下态切换后的文字

对比度按 WCAG 相对亮度公式实测；未引入任何新色值，全部读取现有 palette.ts token。

主要风险：① 22px 分区标题低于正文 28px 地板，但与面板内现有 22px 控件标签同档，属于控件字数而非正文； ② 四字标签 + 38px 胶囊在 160px 格内只剩约 10px 余量，落码时需按实测字宽验证； ③ 行序变化会改变老玩家的肌肉记忆，这是功能分区必须付的代价，可用分区标题补偿。

06待拍板

1. 行序重排

推荐按本稿重排（设置 / 辅助 / 外观 / 本局）。若想零重排，可保留现顺序，分区标题退化为「设置 / 体验 / 外观 / 系统」，但「本局」行仍会混入调试项。

2. 性能信息归属

本稿保留原位并按 chip 绘制。是否只在调试模式显示、或移入菜单设置，是功能口径问题，需另批决策。

3. 回主菜单确认

退出会丢弃本局。本稿只做视觉弱化；是否加二次确认属于交互功能变更，不在样式方案内。
