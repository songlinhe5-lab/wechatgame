## 2. 四条设计支柱的可判读定义（玩家看到什么算达标）

> **⚠ v2 改判据（2026-10-13）**：下表是 v1 判读，**三条已被新风格推翻**，不改则 QA 逐帧假红。旧文**留档不删**，冲突以本注记为准：
>
> 1. **治愈②「阴影只有柔投影一种、无硬边描边阴影」→ 作废**。位图场景件**自带烘焙光影**（木纹渐变 / 内阴影 / 外投影画在图内），不受运行时叠层条款约束。新判据：**每个图元 ≤1 层运行时叠层投影**（只作用于程序化件），且**全场景光向一致**——定稿图光源在橱窗顶部射灯 ⇒ 位图内投影一律向下、高光一律朝上；出现与光向矛盾的烘焙阴影 ⇒ 不达标。
> 2. **明快②「UI 强调色只有 2 个（木棕 + 交互蓝）」→ 放宽为 3 个**：新增 **CTA 粉**（实测 `#FDB7BB`，兼蝴蝶结 / 绶带同族）。判据「第一眼先看到珠」保留，但量化口径改为**可执行测法**：截图逐簇 HSV 饱和度直方图，场景件饱和度须 ≤ 珠色最低档的某比例——**阈值 `[待实测]`，本文不预支伪数值**（v1 未给数值，v2 同样不给，只把测法定下来）。
> 3. **UI 辨识度①「木 = 可按」材质语义 → 作废**。新风格里木框橱窗、木招牌、木铭牌底板**都不可按**，材质不再等于交互性。替换为**形态三通道**：① **凸起实体 + 顶高光 = 可按**（钮 / 牌）② **围合凹陷 = 陈列，不可按**（橱窗 / 框 / 槽）③ **描边环 = 状态**。灰度可辨要求不变（去色后仍能指认「哪个能按」），但承担辨识的通道从「材质色阶」换成「**轮廓形态 + 明度**」。
>
> 未动项：**休闲支柱全部**（每屏 1 主钮 / 圆角 ≥12 / 红色只在告急与失败 / 正文 ≥28px）、**E1 floor**、**色盲三重编码纪律**（只是换了通道载体）。

| 层级 | 交付形态 | 用于 | 纪律（逐条可判） |
|---|---|---|---|
| **T7 场景件（位图）** | **PNG / WebP 透明底**，走 `ADR-0031` 静态位图腿 | **只有「身份件」准入**：招牌总成（含麻绳 + 蝴蝶结 + 珠字）、橱窗木框、玻璃高光层、射灯、木铭牌底板、CTA 胶囊、绶带、金章、主题作品图 | ① **@2x 交付**，显示尺寸 = 交付尺寸 ÷2，⛔ 无 9-slice ⇒ 按最终 footprint 1:1，不得指望拉伸；② **透明底必须带抗锯齿**（alpha 不得二值；实测 `sprite-00` 半透像素 **0.00%** ⇒ 不合规，须补 1px 羽化）；③ **状态变体不预出图**——按下 = y+2 位移、禁用 = 运行时 tint（与顶栏圆钮已裁的分层法同源）；④ 光影须与 §2 改判据 1 的光向一致；⑤ 单张预算与格式见 §8；⑥ 文字**一律不烤进图**（铭牌名 / CTA 文案 / 版本号全走 `font_label`），否则违反零字体文件纪律且不可本地化 |

## 7. ⛔ 不动项清单 + 与「干净几何珠面」的共存策略

> **⚠ v2 边界澄清（2026-10-13）**：本次改政**只动 UI 容器族（T7 场景件）与支柱判读**，**珠面 / 格面 / 托盘 / 盘面色值 / 冻结常量 / 毫秒值一律不动**（下列五条原文有效）。⚠ **待用户显式确认的一件事**：新风格是手绘场景，是否要把**珠子本身**也改手绘（即翻掉 WXG-T-263「手绘蜡笔质感不实施」裁定）？——**本文按「不翻」写**，因为翻它要牵动珠面十层体系、风格池四套裁定与封箱基线，属独立 ADR 射程，⛔ 不得由美术圣经改政顺带通过。

**不动项（逐条，落码与评审都不得触碰）：**

1. 珠子绘制全部层集与系数（现行默认皮肤 = 复刻·四棱刻面；风格池/bead-visual-style-spec §12 体系零涉）。
2. B0 连续目标色底图、空格凹陷坑 S1–S4、locked X 斜纹、hint/wrong/selected 状态语言与毫秒。
3. **托盘里的格子与珠子**：`TRAY_SLOT 48 / TRAY_GAP 6` 几何、槽底 `traySlot #4A5060`（2026-10-06 用户刚定稿）、托盘珠等比内缩口径。
4. 盘面格底/坑底一切色值；`BEAD_PITCH 32 / BEAD_CELL 30 / BEAD_GAP 2`。
5. `systems-index §3` 全部冻结值、`ux-spec §5` 全部毫秒值、`TOUCH_MIN 88`、字号 floor 28。

**共存策略（为什么暖纸底不会和干净几何珠打架）：**

- **对撞轴保住了**：铁律 1「珠子先于背景」的机制 = 底低饱和、珠高饱和。暖纸底与冷紫灰底饱和度同级（≤12%），对撞轴从「色温」平移为「材质温度」——几何硬边珠面在软纸底上读作「整洁的手工材料」，干净感不降反升。
- **几何语言不混**：UI 容器圆角 ≥16 且全部带 1px 暖描边；珠面保持现行无外描边、靠倒角明暗的语言。两族（「描边容器」vs「无描边珠」）互不模仿 ⇒ 不会互相读混。
- **唯一风险点如实登记**：奶白珠 `#FDF6E9` 对 `#F1E8D8` ΔL ≈ 5.4%，是 10 色中最弱对（靠珠自身暗倒角 L2 与 L0 投影补分离）⇒ `[待真机]`；若真机判糊，回退杠杆 = `bg_base` 加深至 `#EDE2CC`（ΔL ≈ 7.7%），单 token 改动。

## 8. 包体承诺

> **⚠ v2 改政（2026-10-13）**：本节 v1 的「零位图 ⇒ 美术位图 +0 KB」**不再成立**（下方 v1 原文留档）。v2 承诺改为**有预算、有格式路线、有前置**：
>
> **① 实测（用户交付招牌总成 707×459 RGBA，382.5 KB 入包）**
>
> | 处理档 | 体积 | 判定 |
> |---|---|---|
> | PNG 真彩（原尺寸 / @2x 908×590） | 382.5 / **578.4 KB** | ⛔ 单张即超整批预算 |
> | PNG-8 256 色 | 158.6 KB | ⚠ 仍超，且木纹起色带（图内 top12 色各占 0.3–0.6%，量化余量小） |
> | **WebP 有损 q=80**（q=75 / q=90 / 无损） | **28.4**（24.1 / 43.4 / 214.9）KB | ✅ 唯一能让整批塞进预算的路线；q=80 恰好落在 v1 给 logo 定的 ≤30 KB 口径内 |
>
> **② 格式路线**：默认 **WebP 有损 q=80**（带 alpha）。⚠ **风险如实登记**：微信真机的**带透明 WebP 解码本仓未证**（harness 浏览器可先验，真机须上传开发版扫码 ⇒ `[待真机]`）；若真机不通过，回退 = PNG-8 并把整批预算从 300 KB 抬到 ~1.2 MB ⇒ 主包 2979 + 1200 ≈ **4.2 MB，越 4096 平台红线** ⇒ 届时必须砍元素或走分包，不在本文预先解。
>
> **③ 预算**：以正本 `menu-showcase-asset-spec §6` 为口径——**固定切图 ≈ 15 组（含状态帧 ×2~3）+ 9 张 boss 缩略 256²**（单张实测 ~38 KB）；本机 `check:size` 已有牙，主包 release 实测 **2979.0 KB**（基线 2939.8，boss 缩略净 +39.2）⇒ 平台红线 4096 余 **1117 KB**，内部目标 **2000 KB 已越**（既存，非本批造成，但本批继续推高，需用户认这个数）。本改政另提**整批硬顶 ≤300 KB** 作为建议值（≈ 正本余量的 27%）， **属新增约束、非已裁项**，需与正本 §6 合并后生效。
>
> **④ 前置（未被本改政解除）**：`control-manifest §19`「⛔ 包体守卫未归位前向主包投放位图」+「未命中一律矢量回退」仍生效 ⇒ 须另走 **§3.9 变更单**回改 §19 正文，并把守卫的射程从「包体」扩到「**包体 + 层序**」（`ADR-0031 §6` 的裁定）。在册位图例外目前仅 boss 缩略一张。
