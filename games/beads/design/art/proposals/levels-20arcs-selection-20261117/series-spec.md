## 1. 风格口径判断：平涂大色块矢量剪影母版

**结论**：180 张母版统一为「**单一主体 · 圆润平涂矢量剪影 · 硬边闭合轮廓 · 有限色板 · 纯黑作采样排除信号**」的风格画。不是照片、不是 3D 渲染、不是厚涂、不是像素图、不是写实渐变插画。

> 注意「风格画」只描述**主体**怎么画；纯黑区域不参与风格判断，它是给 studio 的排除标记，不是画面的一部分（§3）。

**为什么是这个口径（四条来自本仓管线的硬理由，不是审美偏好）**：

1. **量化管线吃不下渐变与纹理**。studio 的生成链是「源图 RGBA → 区域平均缩放 → Median Cut（RGB+色相四通道）→ Dominant Color → 品牌色板最近邻 ΔE76 → 门 B/C 过滤 → 分布质量评分 → 背景去格 → 包围盒裁剪 → 配色平衡 → 错位打乱 → rowstring」。渐变会被中位切分切成大量近色，随后被「近似族互斥」（`NEARFAM_BAND_MAX=10`、`NEARFAM_BASE_MAX=22`）合并或剔除，成品色数不可控且色块碎裂。依据 [`palette-quantize.mjs`](../../../../../../tools/scripts/palette-quantize.mjs#L171) 与 [`beads-gen.mjs`](../../../../../../tools/scripts/beads-gen.mjs#L37)。
2. **可读性门禁反推「大色块、少碎块、单连通」**。`pattern-legibility` 的 T1（珠/块 ≥9，最小识别单元 3×3）、T2（块/色 ≤2.0）、T3（孤点 ≤1%）、T4（1 格宽细丝 ≤1）、T5（珠/色 ≥25）、T6（主体 4 连通分量 =1）、T7（短边 ≥11/14/16）。现池实测就是反证：`L00003` 色 1 被切成 16 块、`L00007` 60 珠装 6 色退化成点状噪声。依据 [`pattern-legibility.md`](../../../levels/pattern-legibility.md#L23) §2、§4。
3. **配色质量评分要求明度跨度与色相覆盖**。评分看色相扇区覆盖、明度跨度 `QUALITY_LUMA_SPAN_MIN=40`、两两最小 bandΔE ≥15。⇒ 每套配色必须**至少含 1 个亮色 + 1 个暗色，并跨 ≥3 个色相扇区**；整幅粉彩或整幅深色都会刷不出质量分。依据 [`palette-quantize.mjs`](../../../../../../tools/scripts/palette-quantize.mjs#L181)。
4. **行业通行做法同向**。拼豆 / perler bead 的「图 → 珠阵」转译，通用流程就是先扁平化、限色、去纹理、放大主特征，再按网格采样；儿童向休闲拼图的图案母版普遍是居中单主体 + 闭合轮廓 + 3–6 色。本仓的 `pattern-legibility` 与 studio 量化门只是把这套经验写成了可计算的判据。

### 1.1 与美术身份的关系（别混两件东西）

[`art-bible.md`](../../specs/art-bible.md#L28) §1–§2 的「冷调静底 + 糖果 3D 珠 + 柔和投影」是**游戏画面**的视觉身份，不是母版插画的身份。母版只需在**取色**上归 §3.2 十色珠板，让量化后贴得住品牌色；珠子的圆角、高光、投影由游戏侧程序化绘制，母版里**不许画珠子、不许画 3D 高光**。art-bible §1 列的反面参照（硬边像素风、重描边卡通、拟物厚涂、金属质感）在母版上同样适用，但「硬边像素风」此处指的是**不要预先像素化**——格子由 studio 采样生成，母版保持圆润矢量轮廓。

## 3. 纯黑 = 采样排除信号：studio 的代码边界与处置

> **本节只回答一件事**：怎么做到「让 studio 不参与采样」。纯黑不是要被 studio 看到的颜色，而是要在 studio 看到之前就被本地翻成透明的标记。

### 3.1 studio 里「不参与采样」只有一个入口，且是采样**之前**

1. **唯一入口 = `alpha < 128`**。studio 收的是 RGBA 像素（[`generate.html`](../../../../../../apps/beads-studio/public/generate.html#L544) 用 `getImageData` 传出）。[`beads-gen.mjs`](../../../../../../tools/scripts/beads-gen.mjs#L1081) 在**区域平均缩放阶段**就跳过透明像素（`if (buf[o+3] < 128) continue`），整格透明标记 `A=0`；随后 [`buildGrid`](../../../../../../tools/scripts/beads-gen.mjs#L1222) 投票时再跳过 `A=0` 的采样点，[`if (!nn) continue`](../../../../../../tools/scripts/beads-gen.mjs#L1228) 把整格透明格直接判成空位 `void`。⇒ 这些像素**根本没进过** Median Cut、色板映射、限色、配色平衡、错位构造，也就没有色号、不占 4–16 色预算、不会变成珠子。这才叫「不参与采样」。
2. **studio 自带的「四边框去背景」不算不参与采样**。[`beads-gen.mjs`](../../../../../../tools/scripts/beads-gen.mjs#L1252) 那步发生在**量化完成之后**：取四边框最常见的已量化色号，再从这个色号里 4 连通 flood fill 删成 `void`，另有「背景残留清洗」删孤立同色号格。也就是说纯黑若作为画面颜色留在图里，会**先被量化成一个色号、吃掉一格用色预算**，然后才被删掉，还会在边缘留下混色黑珠。仓内历史证据：苹果黑底占全图 53%、花盘边缘出现黑珠、绿叶边缘采样到黑底混色被映射回纯黑；[`generate.html`](../../../../../../apps/beads-studio/public/generate.html#L347) 的「铺满整盘（不扣背景）」提示也明说背景会吃掉大半用色预算。⇒ 这条是「采样完再删」，不满足本批目的，不能拿它当排除手段。
3. **因此纯黑必须先在本地翻成 `alpha=0`**。模型画不出真 alpha（§0.1），所以纯黑是「模型能稳定产出、本地 floodfill 能确定性识别」的代用信号；studio 从头到尾看不到纯黑，只看到透明。⇒ 主体禁近黑（G8）的理由也随之改变：不是怕颜色跟炭黑撞，而是**近黑主体像素会被 floodfill 判进排除区、连同身体一起抠掉**。
4. **十色板里本来就没有纯黑**（佐证，不是主论点）。[`art-bible.md`](../../specs/art-bible.md#L109) §3.2 十色最暗为炭黑 `#33333D`（≈0.05）与深棕 `#6B3E1E`（≈0.12）；`#000000` 不在其中，UI 的 `shadow_ink` 是 `#3D2E1E`。[`palette-quantize.mjs`](../../../../../../tools/scripts/palette-quantize.mjs#L174) 里的 `BLACK='#000000'` 只是门 B 的历史错误参照（现已改为 `ΔE(c, mix(c,−0.44)) < 8`），与可用珠色无关。⇒ 纯黑从来就不是珠色，让它承担「排除」而不是「配色」是顺理成章的。
5. **主体不触边的第二个理由**。四边框全是透明格时，`grid` 里这些格是 `0`，[`bg` 取到 0](../../../../../../tools/scripts/beads-gen.mjs#L1281) 使 `if (bg > 0)` 不成立 ⇒ 四边框去背景自动空转，不会误删任何主体色。若主体触边，边框上会出现主体色号，flood fill 就可能把连到边框的主体边缘一起删掉。⇒ G7 的「四边留白 ≥8%」不只是给 floodfill 留连通路径，也是让 studio 那步安全地空转。✅ 实测佐证：第 0 张探路图上送 studio 后 `report.voidCells=0`（去背景零删除），而 136 个空位全部由「整格透明」直接产生，逐格复算差 0，见 [`studio-verify.json`](probe-2048/studio-verify.json)。
6. **用户口径在仓内早有裁定**。[`ai-workflows/README.md`](../../../ai-workflows/README.md#L99) 的 v6b（2026-10-09 用户换政）原文：「**纯黑底**——主体剪影与黑底对比最强，**转化时按黑底抠图去除（生豆阶段黑底不参与选色）**。旧『纯白底』规作废」；同段另定「线条禁纯黑（与黑底抠图/选色避黑冲突）」「选色避开纯黑（黑只当背景用），主体内不得出现黑/深色」「每色区单一精确平涂色、边界干净，否则拆珠出现孤立杂色豆」。⇒ 本批 §2 G1/G2/G8 的约束不是新发明，是把既有产线口径从本地 ComfyUI 线移植到云端 Token Plan 线；探路张的实测也顺带验证这条移植是否成立。

### 3.2 处置（三段式：标记 → 翻译 → 交付）

| 段 | 做什么 | 验收 |
|---|---|---|
| **A 出图：标排除区** | 提示词写「纯黑 `#000000` 纯色背景、无渐变、无暗角、无阴影」，用纯黑把**不参与采样的区域**标出来；主体按 G8 禁近黑、按 G2 硬边，保证排除区与主体边界互不混淆 | ⚠ **四角取样按近黑 `max(RGB)≤24`，不是精确 `#000000`**——第 0 张探路实测模型画的是 0–24 近黑噪点，精确纯黑只占 21.04%；按精确纯黑判会假 FAIL。另查四边环带无渐变（p99≤2）；主体最暗像素与 `#000000` 的 ΔE ≥25 |
| **B 本地：翻成透明** | 确定性 floodfill（四角种子点）把纯黑连通域转 `alpha=0`，向内收紧 1–2px 吃掉抗锯齿过渡边；**不调用任何分割模型、不让 studio 做这一步** | 查 alpha 分布：`alpha=0` 占比、四角全透明、主体内 `alpha=255` 连成一片；主体区 RGB 逐像素原值不变（⛔ 只改 alpha） |
| **C 交付：studio 看不到纯黑** | 交 RGBA PNG。[`generate.html`](../../../../../../apps/beads-studio/public/generate.html#L544) 传 RGBA，[`beads-gen.mjs`](../../../../../../tools/scripts/beads-gen.mjs#L1081) 的 `alpha<128` 在缩放阶段即跳过、[`buildGrid`](../../../../../../tools/scripts/beads-gen.mjs#L1228) 整格透明判空位 ⇒ 排除区**从未进入量化**；四边框去背景因 `bg=0` 自动空转（§3.1 第 5 条） | 生成的 `pattern` 主体 4 连通分量 =1、无游离黑点；用色数不含任何由背景贡献的色号 |

## 4. 2048 母版 → 量化 → rowstring 的口径

- **2048 是母版像素分辨率，不是珠面格数**。studio 生成时按请求的 `cols×rows` 把 2048 区域平均降采样，每格约 `2048/cols` 像素。按 [`pattern-legibility.md`](../../../levels/pattern-legibility.md#L38) §2 的最小豆面经验线（3–4 色 ≥12×12、5–6 色 ≥15×15、7–8 色 ≥17×17）与用户裁定的选图下限 10×10，入关盘面大概率落在 12×12–17×17，2048 母版每格仍有 120–170px，对平涂大色块是充足冗余。
- **不必走组合图切块**。[`level-content-pipeline.md`](../../../proposals/level-content-pipeline.md#L63) §0.6 记录 2048@32px/颗 = 64×64 母版、1024@32px = 32×32 单图档；本批用户裁定单图硬顶 32→64，故 2048 母版按 16×16 或 32×32 采样入关均属单图，不触发 Plate 切块。该口径已随 `36c4d492` 入库（v2.00 推翻 v1.45 组合图切块语义：任一维 >64 的关卡 JSON 一律 BOOT 拒收、不再自动切块）。
- **大盘可玩性不在本规范里设闸**。按用户此前裁定，「不可发布」不设在 studio，交由真机运行体验验证；studio 只做导入工具行为。
- **4096 上限**：`generate.html` 对源图有 4096 解像上限，2048 在范围内。
- **珠面基准分档（用户 2026-11-18 首裁 32×32；2026-11-24 二次裁定分档）**：
  - **普通关 = 32×32**（沿用 2026-11-18 令）：量化/预览/效果确认 `cols=rows=32`（cell=64px）；格级预算按 64px（G2 轮廓 ≥2 格=128px、G4 点缀 ≥3×3 格=192px）；16×16 产物留档作对照不作基准。
  - **BOSS 关 = 48×48（2026-11-24 用户裁定，A03 起生效）**：动机 = BOSS 难度不足——32×32 下受 G9「主体占画布 70–82%」约束，实际豆面仅 ≈25×25，P9 步数仅 84（门禁 68，余量过小）。48×48 下主体 ≈37×37、可填格 ≈2.2 倍、步数约翻倍到 ~190。**技术边值**：`GRID_MAX_COLS/ROWS = 64` 已放开（v2.00，2026-11-17），48 合规；`fit = 666/(48×32−2) ≈ 0.43`、珠绘制边长 ≈11.3px（仍 >8px 命中下限）；**不选 64**：fit 0.33、珠边 8.5px、4096 格 ≈4.4 万图元，性能/触控未经真机验证且 LOD 未立项（systems-index 已登记）。已入库 A01/A02 BOSS 不回溯（用户 2026-11-24 裁定「仅后续大关」）；BOSS 母版须按 48 盘重算主体占比（G9 70–82% 不变），2048 母版每格 42.7px 冗余充足；大盘可玩性仍交真机验证（§8）。
