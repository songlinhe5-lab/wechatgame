# 豆面可读性（Pattern Legibility）· WXG-T-357

> **一句话**：`DI`（`level-difficulty.md`）管「难度排序与工量」，本文管「**看不看得清**」——
> 稀不稀碎、轮廓断不断、盘面够不够装下这个色数。⛔ 本文指标**不参与难度定价**，也不得用于估工。

- 版本：**v1.0**（2026-10-23 立，WXG-T-357）；实现 = `tools/scripts/lib/pattern-legibility.mjs`
- 门禁：**⑧**（`tools/scripts/sync-levels-data.mjs::checkLegibility`，默认 WARN / `BEADS_LEGIBILITY_STRICT=1` 硬红）
- studio 落点：`apps/beads-studio/server.mjs::legibilityFix()` —— **生成后二次优化修复**
- 自测：`tools/scripts/pattern-legibility.test.mjs`（6 例，`node --test`）

---

## 1. 为什么需要它（与既有两个判据的分工）

| 判据 | 回答什么 | 不能回答什么 |
|---|---|---|
| `DI`（§3 公式） | 这关**难不难**、能否排出严格序 | 图案是否碎成噪点（`DI` 只看 `N/M/C/A`，不看块结构） |
| 门禁⑦ `steps` | 工量是否落档 | 同样的步数，可以是一整块色也可以是一堆 1 格点 |
| **本文 T1–T7** | **一眼能否看清、轮廓是否完整、盘面是否够** | 难度、工量、定价 |

现池已暴露的真问题（2026-10-23 实测）：`L00003` 只有 3 色却把色 1 切成 **16 块**、`L00007` 60 珠装 6 色（每色 10 格）退化成点状噪声 —— 两者 `DI` 与 `steps` 都「正常」，**只有本文判据能抓到**。

## 2. 七项指标与门限（全部可从格点直接算，4 连通）

| # | 指标 | 定义 | 门限 | 锚（为什么是这个值） |
|---|---|---|---|---|
| **T1** | 珠/块 | `N / 同色连通块数` | **≥ 9** | 图案最小识别单元 = 3×3 格；1 格=噪点、2×2=只见「有色块」、3×3 才见「是什么形状」 |
| **T2** | 块/色 | `同色块数 / 用色数` | **≤ 2.0** | 同色最多「1 主块 + 1 点缀块」；再多就是颜色被切碎（最直白的「稀碎」定义） |
| **T3** | 孤点/N | `面积=1 的块数 / N` | **≤ 1%** | 单格点=纯噪点；分母用 `N` 不用块数（块数少时率会虚高） |
| **T4** | 细丝块 | `最短边=1 且面积≥2` 的块数 | **≤ 1** | 1 格宽笔画在豆面上读作毛刺/断线 |
| **T5** | 珠/色 | `N / 用色数` | **≥ 25** | 每色 ≈ 5×5 才够「一整块 + 一圈干净轮廓」 |
| **T6** | 主体分量 | 全部珠的 4 连通分量数 | **= 1** | > 1 = 图案漂了孤岛（如现池 `L00002` 底部 5 格小岛） |
| **T7** | 短边 | `min(cols, rows)` | **≥ 11 / 14 / 16**（C≤4 / C≥5 / C≥7） | 防「超长条盘」把图案挤扁 |
| 参考 | `P/√N` | 比周长 | `[4.0, 6.5]` 出带**只提示不拦** | 偏低=团块糊成一坨，偏高=毛边锯齿 |

> ⚠ **T1/T5 是设计锚定值，不是回归拟合**（同 `level-difficulty §3.3` 口径）：⛔ 不允许为了「让某关过」去调门限（判例 K-012 第二把尺子）。

**最小豆面经验线**（由 T5 反推，填充率取现池实测中位 0.66）：

```text
盘面格数 ≥ 38 × 用色数      短边下限 ≈ 3.5 × 用色数
3–4 色 → 12×12（≥152 格，短边 ≥11）
5–6 色 → 15×15（≥228 格，短边 ≥14）
7–8 色 → 17×17（≥304 格，短边 ≥16）
```

## 3. 判读分型（决定用什么药）

- **`sizing`**（命中 T5/T6/T7）⇒ 盘/色数不足：**放大盘面或减色**。修图案无用。
- **`structure`**（只命中 T1–T4）⇒ 盘够但图案碎：**合并色块 / 降纹理**，盘面不用动。

## 5. studio：生成后二次优化修复（行为契约）

**落点** = `apps/beads-studio/server.mjs::legibilityFix(pattern)`，在**新入关**两条路径调用（一键入关 single / 新建大关的首关 boss）。`renumber` 等纯重写路径**不调**（不改既有真源）。

**自动修三件事**（只做确定性、不引入新颜色、不改盘尺寸、不碰 `x` 锁定格）：

| 操作 | 规则 | 说明 |
|---|---|---|
| 吞孤点 | 面积=1 且四邻有珠 → 涂成邻色多数；四邻全空 → 删为 `.` | 直接消 T3 |
| 并细丝 | 1 格宽块，且**该色另有主块（≥9 格）** → 涂成邻色多数 | 只并入，不扩张；该色唯一形体时保留 |
| 填小孔 | 面积 ≤ 4 的内孔 → 填邻色多数 | 消「针眼」，T6/视觉断裂 |

**守恒配套（硬约束，v1.1 补）**：`levels-data.ts:56` 要求 `misplaced` 与 `pattern` **每色珠数守恒 + 可填轮廓逐格匹配 + 错位格 ≥1**（现池 9 关实测全部严格相等）。⇒ **只改 `pattern` 必破约**，故落码走 `repairLevel({pattern, misplaced})`：先 `repair(pattern, { noDelete:true })`（关卡级不许删格，删格会改可填轮廓），再把 `misplaced` 的盈余色配平到短缺色，并断言三条契约；`swaps` 型（无 `misplaced`）**直接拒修**并给原因。

**修不动的不假装修**：`sizing` 类（T5/T7 不足）只回报，回执明写「须重生成/减色」。
**回执**：写入 studio 既有 `log` 通道（前端零改动），形如
`已入关 L00012（single 16×16，实测 88s）｜豆面修复 吞孤点 7 格、并细丝 2 格；残留 T2（结构类）`。

## 6. 门禁⑧ 使用

```bash
pnpm run levels:check                              # 默认 WARN：打印未过关清单，不拦提交
BEADS_LEGIBILITY_STRICT=1 pnpm run levels:check    # 硬红：新关不达标直接失败（CI 灰度收紧用）
node tools/scripts/lib/pattern-legibility.mjs --report   # 人读表
```

**为什么默认 WARN**：现池 legacy 有 6 关（含 `L00010` 照片冒烟盘）不达标，硬门会当场打红全部提交 ⇒ 与「门禁必须先绿」冲突。
**转硬红的条件**：第 4 节表里 non-`sizing` 项清零（或逐关登记「设计意图豁免」并写进 §7）。
