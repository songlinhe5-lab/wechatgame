**色板口径扩展（§3.2 `BEAD_COLOR_MAX` 10→35，**v1.55 已生效**；提案 = 正本 v1.10/§6 v1.54）**：字符集由 `.x1-9A` 扩为 **`.x1-9A-Z`**，色索引 = **1–35**（`1-9`=1–9、`A-Z`=10–35）。这是**单字符 rowstring 形态下的硬天花板**（9 + 26 = 35），不是保守取值：在当前数据形态下 35 即「不限制」，>35 需换编码格式（另案，正本 §8）。两条消歧硬规定：① **只收大写**（小写 `a-z` 与 `0` 仍非法，防 `a`/`A` 二义）；② **`X` 是色索引 33（`Y`=34、`Z`=35）、`x` 是锁定符** ⇒ 校验器/任何正则**不得大小写不敏感**（❗正本 §2.1 与原提案注均写「`X`=34」，**工程落码时实测为 33**，本文按实测订正）。解码表**实测 7 份**（正本记 4 份），**v1.55 已一次收干**为两份同源件：游戏侧 `config/bead-charset.ts`、工具侧 `tools/scripts/lib/bead-charset.mjs`，由判据 **X1** 逐字符钉死（`tests/bead-charset.test.ts`，含「不得再出现第二份表字面量」扫描）。

### 2.1 交换构造法（v1.2 新增；可解性的构造保证）

**错位布置 = pattern 全满 → 按 `swaps` 顺序对可填格珠两两交换。**

- **可解性由构造保证（关键性质）**：交换是**可逆置换**——玩家对任意错位珠执行「取回（进托盘）→ 归位到其目标格」的周转，等价于逐步还原该置换；交换构造不存在「结构性不可还原」的布置（对比：任意涂改式错位可能造成色数不守恒型死局）。**可解性校验因此免于运行时搜索**，仅需 §2 表 ③ 的静态规则。
- **错位珠计数恒等式**（校验器可断言）：`misplaced 总数 === 2 × swaps.length`——每次合法交换（两格珠色不同）恰产生 2 颗错位珠；链式交换逐对累加，恒等式在任意 `swaps` 下成立。
- **底色不动**：pattern 永远是底色真源；珠的初始归属 = 交换结果。运行时 `misplaced(cell) = filled 且 colorIdx ≠ pattern(row,col)`（§3.13）。
- **authoring 建议**（关卡作者侧，非校验项）：优先构造「同排近距交换」（视觉冲突易读，符合支柱 1）；L1 教学关用 1 对同排相邻交换。

### 2.2 全错位初盘（v1.3 新增；成片错豆）

`swaps` 封顶 8 对 ⇒ 最多 16 颗错豆，**无法表达「成片错豆」**。MVP 大盘（14×14 / 18×18）改用 `misplaced` 初盘：关卡直接携带**整盘初始珠色**（rowstring），引擎 `assembleFromMisplaced` 逐格解码写入，不经任何随机 ⇒ **输出逐帧确定**。

- **成片错豆来源**：`misplaced` 由生成器按色循环移位产出（同色连续游程整体移到下一色 ⇒ 整块区域统一错色），故错豆呈大片连通而非散点。
- **可解性**：靠 §2「每色珠数守恒」保证——初盘与目标盘同色同数，玩家经取回/归位（大盘依赖直填 T-162）即可还原，无需运行时搜索。
- **与 swaps 互斥**：`misplaced` 存在即忽略 `swaps`（数据侧 `swaps` 置空数组占位）；`MISPLACED_PAIRS_MAX` 仅继续管辖 swaps 型关卡。
- **作者侧**：全错位大盘的通关时长/难度另经 playtest 调（`time` 不再套 §3.5 的 k 定价）。

### 2.3 错位档位与「最大化错位」（**v1.12 生效** = §3.2 批2 已落码；本文口径由「提案」改「生效」）

**生效前的现行行为（登记作历史对照，已被 v1.12 推翻）**：`beads-gen --mis full` 是 **all-or-nothing** —— 主导色 `m > ⌊N/2⌋`（或色太少）⇒ `derange()` 直接 `ok:false` → 自检 `exit 1` → `levelDraft=null` → studio 判「无关卡草案」而拒产。用户 2026-09-24 裁定：**别判不可解，能错多少错多少** ⇒ 现由 **`max` 档承载**（`full` 的 all-or-nothing 语义**保留不动**，两档并存、由调用方选）。Plate 逐宫路径 `buildCellInitial` 现为 甲 / **甲max** / 乙 / 丙 四阶（乙 = 退成 ≤8 对 swaps、丙 = 整盘 422 拒收）。

**新档 `max`（已落码：`--mis max` / studio 错位密度选「最大化错位」，值 `max`）的硬口径**（记号：`N` = 该域内可填格数，`m` = 主导色珠数）：

1. **两条不可破硬约束**（= §2 表 ③④，本档不放宽任一条）：可填轮廓逐格匹配 + **每色珠数守恒**。⇒ 「最大化错位」= **同一多重集内部重排**，**不是把某些格改成别的颜色**；改判格色只允许发生在生成期的 `pattern` 侧（`balance()`），`misplaced` 侧永远不得改色。
2. **极值**：`M_max = min(N, 2(N−m))`，强制就位格数 `F = N − M_max = max(0, 2m−N)`；全错位可行 ⇔ `m ≤ ⌊N/2⌋`（即现 `full` 的前提）。⇒ `m ≤ N/2` 时 `max` **等价于 `full`（不打折）**；`m > N/2` 时给出的是**守恒下的最优结果**，不是「退让」。✅ **已由 X2 穷举实测复核（不再是手算）**：`level-derange.test.mjs::X2` 对 3×4 轮廓（含 1 枚 `x` + 3 枚 `.` 不可填位）穷举 **3⁸ = 6561 个色分布**，逐例断言固定点数 **恰等于** `max(0, 2m−N)`、`M = min(N, 2(N−m))`、每色守恒、且 `m ≤ ⌊N/2⌋` 时 `max` 与 `full` 输出**逐格相同**（等价性）⇒ 全绿；§3.3 三例实测亦吻合（`N=10[7,3]→F=4,M=6`、`N=9[5,2,2]→F=1,M=8`、`N=12[6,3,3]→F=0,M=12`）。真管线抽样：13×11=143 格、`m=88` ⇒ `M=110`、`F=33`（studio 生成实测）。
3. **唯一仍不可解的退化情形**：`M_max = 0 ⇔ N < 2`（可填格不足 2）**或 `m = N`**（整盘单色 ⇒ 无任何异色可交换）。⚠️ 且二者**在合法关面内不可达**：§2 色数 ≥3 ⇒ `N ≥ 3` 且 `m ≤ N−2` ⇒ `M_max ≥ 4`。⇒ **本档下不存在「合法但不可解」的关**（这是可证结论，不靠兜底）；`exit(1)` 只可能出现在生成端中间态（`--colors 1`、shape 掩码后 `N<2`），那种输入本来就该失败。✅ 该结论已由 **X3** 穷举钉死（不再是手算）：`level-derange.test.mjs::X3` 在穷举域（N=8）内对**所有恰用 ≥3 色**的赋值（**5796 例** = 3⁸ − 3·2⁸ + 3，即满射数；已用独立脚本实测确认该例数）逐例断言 `M_max ≥ 1` 且 `buildCellInitial` 必返 甲 / 甲max（**不落乙、不落丙**），实测分层 = 甲 4620 例、甲max 1176 例；**实测最小 `M = 4`**，与本文推出的下界 `M_max ≥ 4` 吻合且**取下（tight）**——即该下界不是余量，若 §2 色数下限再放宽（如 ≥2 色）此断言即失效。
4. **与 P2b（Plate 切块）的关系**：`sliceBoard` 是**纯几何裁剪且故意不接 `misplaced`**（`server.mjs:301` 只传 pattern），每宫初盘由 `buildCellInitial` 在切块后**逐宫重建** ⇒ **本档的 `N`/`m` 一律是「该宫」的量**，每宫各自守恒、各自取极值。⚠️ **不得为救观感而跨宫搬珠**（跨宫搬 = 破每宫守恒 = 破可解性）；已知代价：某宫 `m_g` 极高时该宫观感上「几乎没错位」（整盘能 full 不代表逐宫能 full）。
5. **不放宽任何既有闸**：宫错位密度 ≤60% 且需「整区域就位」构造（§10 v1.7；32×32 全错位宫 176–178 taps 两轮 bot 复现 ⇒ 结构性不可入关）、§3.13 规模闸（`steps × SEC_PER_STEP ≤ LEVEL_TIME_MAX` ≈1479 批量动作 ∧ bot cleared）、BOOT「错位 ≥1」均照旧。与密度档的关系 = **取 `min(目标密度, M_max)`**：密度是**作者想要的**，`max` 是**够不着 full 时的能力上界**，两者不同层。
6. **输出义务**（已落码）：`max` 使 `M` 成为**可变输出** ⇒ 报告与草案必须携带并打印 `M`/`N`/`F`（现只报「错位/不错位」），否则 `time` 定价与规模闸无法追溯（定价链已按 `M×0.8` 估 steps，`level-import.ts:119,144`，天然兼容）。落地形态 = `pattern.json` 新增 `report.mis = {mode,N,m,M,F,M_max}`（beads-gen `derange()` 返回值同步携带；studio 侧读该单一真源，不另存副本）。

## 5. 难度与时长预估（**v1.4 实测口径**，2026-09-21；公式 v0.2 = 真引擎实测点击数 × `SEC_PER_TAP`；**v0.3 起 `time` 正源 = 逐关人工实测 `t_act`；v0.4 起自变量 = BAC 批量动作数 × `SEC_PER_STEP`，本公式仅作新关先验**，见 §5.0 版本表）

> **重推前提（WXG-T-130 案 A）**：核心循环 = 「错位归位」，玩家只处理错位珠；定时供料不存在。

### 5.0 难度估算公式（正本；实现 = `level-import.ts measuredLevelTime`，**全仓唯一**）

```text
T₁ = clamp( steps × SEC_PER_STEP , LEVEL_TIME_MIN , LEVEL_TIME_MAX )  （秒；现 [30, 2500]）
T₂ = T₁ × 0.85      T₃ = T₁ × 0.70      ← §3.7 v1.50 三档时钟（`tuning.tierSecondsFor`）
D  = round( 100 × T₁ / LEVEL_TIME_MAX )   难度分 0–100（占满档时长比例）

⚠️ 分母不可跨档比较（顶值 420 → 2500 后 D 缩水 ≈6×），且现值下八关 D 全落 2–12 ⇒ 已无分辨力。

steps        = **BAC 尝试序下的批量动作数** = `直填 + 取回 + 落子`（选锚并入被它服务的动作；
               `tools/scripts/beads-bot.ts` 实测）。一个动作 = 一次玩家可感知的批量操作。
SEC_PER_STEP = 1.69s（`tuning.ts`；旧名 `SEC_PER_TAP=3.6`，**量纲由「每点击」改为「每批量动作」**）

⚠ 优先级：**已人工试玩过的关 = 直接用实测 `t_act` 定 T₁**（`pricing.source='playtest'`），
   本公式只作**未试玩新关的先验**（八关残差仍 ±29%，不够直接进玩家体验）。
```

`taps` 的取法（**不复刻任何判定逻辑**，同 g3 取证铁律）：装盘走生产 BOOT
（`pattern` + `misplaced` → `applyMisplacedToGrid`），每一步只经 `BeadsGame` 四个公开命令
（`tapGridCell` / `selectBoardBead` / `selectTraySlot` / `retrieveSelectedGroup`），
包一层计数（**只计返回 true 的成功命令**）。

> ⚠️ **bot 的适用边界（2026-09-23 playtest 实测修正，见 §5.0.1 回流读数）**：旧文声称
> 「bot `taps` 是人类点击数的下界、比拟合静态代理都便宜且准」——**已被证伪**：① L8 实测人类 104 击 >
> bot 84 击（计量件含误点，小盘上反而更多）；② `t_act ÷ bot_taps` 跨 0.72–1.27，**不能用来推人类用时**
> （bot 在小而碎的盘上退化到接近「1 击 1 颗」，L7 `bot_taps = 1.88 × M`）。
> ⇒ **bot 保留的职能 = 可解性证明（`cleared`）+ 规模闸的保守剪枝**；**时长定价改以逐关实测为准**（公式 v0.3）。

- **取值锚（`SEC_PER_TAP = 3.6`，用户 2026-09-21 拍板冻结）**：= L1–L8 已入库关的
  `time / 实测 taps` **中位数**。这 8 关的 time 是 playtest 校准过的真值（非公式产物），
  实测反推区间 3.01–5.71、中位 3.60 ⇒ 本值语义 = 「与已校准的 8 关同节奏」。
- **为何不按盘面结构量算**：v0.1 三维度公式（f_N/f_C/g_A）已作废，实测证伪见 §5.0.1 v0.2 行。
  真实批量由「托盘占用动态 + 同色空格连通域几何」支配，而全错位初盘**空格数为 0**、
  连通域随玩法演化 ⇒ 静态盘面根本看不见这两个量。
- **入关接线**：`time` 的唯一正源 = 实测。生成期 `beads-gen.mjs` spawn bot（`--patch` 回填
  `report.difficulty` + `levelDraft.time`）；入关期 Studio `ingestLevel` 再测一次并取实测值，
  **不采信草案自报 `time`**（同 `cycleProfile` 纪律）。
  `draftToLevel`（游戏内一键导入，客户端无引擎）走静态兜底 `estimateLevelTime` = `ceil(M/2)` taps。
- **Studio report 字段**：`difficulty {score, timeEst, misplaced, taps, bMed, split, cleared, secPerTap, blockers, formula}`
  —— 前四项是前端旧契约（名字不变、值源换成实测），其余为 v0.2 新增取证字段。
- **压力性质（v1.2 结论沿用）**：倒计时对熟练玩家几乎不构成失败风险，难度主承载是解谜本身；
  但 `time` 同时是**倒计时预算**，高估会白给 3★（`STAR3_RATIO=0.32`）、并让失败页与续时激励位永不开张。

#### 5.0.0 硬拦闸（§3.13 v1.41 · 用户 2026-09-21 拍板「生成期拒产 + 入关期拒收」）

**只用真值，不用静态代理量**：

| 判据 | 生成期（`beads-gen`） | 入关期（`ingestLevel`） |
|---|---|---|
| `taps × SEC_PER_TAP > LEVEL_TIME_MAX` | 打印完整报告后 `exit 4`（拒产） | 422 拒收 |
| bot 未通关（可解性未证实） | 同上 | 422 拒收 |
| bot 不可用（容器无引擎） | 写 `difficulty.error`，不给假数 | 500 拒收（**不回落静态估算**） |

> **为何不设 M / B_med 静态闸**（曾拟定 `M ≤ 280 ∧ B_med ≥ 8`，已入库 10 关实测**证伪并删除**）：
> 甜心 B_med=6 而 44 taps 轻松通关、猫咪脸 B_med 同为 6 而 134 taps 超预算 ⇒ 静态量**无分辨力**，

### 5.0.2 动作数区间与定价溯源（**dev-only**，WXG-T-203 续作 2026-09-23）

**为何要落盘**：v0.2 把 `time = taps × SEC_PER_TAP` 算完就扔 `taps`，导致 `time` 成为**孤儿数字**
—— 谁改了 `pattern` 都没人能发现 `time` 已过期。现在把定价依据随关卡真源存下，使溯源可校。

**关于「最小动作数」（直接回答，避免后人重新踩）**：真最小**算不出**。它 = 「选锚 → 整组取回或盘上直填
→ 空格集变化 → 下一批能多大」的自适应排序问题（M≈150 时状态空间指数级）；且**直填绕过托盘**
（`_tryDirectFillFromBoard`，`retrieve` + `fill` 同帧两写）⇒ 常见的 `2·⌈M/托盘容量⌉` 下界
**前提不成立**。因此只存两个端点，**不存任何单点「最小值」**：

| 字段 | 定义 | 性质 |
|---|---|---|
`actionsLB` | 初始盘「同色 8 向连通错位块」个数（走玩家同一个 `collectMisplacedGroup`） | **可证明下界**：一次消费只能动一个连通组内的珠 ⇒ 消费数 ≥ 组数 |
`actions` | 真引擎 bot 实测成功命令数 | **可达上界**（贪心、非最优）；亦即旧称的 `taps` |

⚠️ **两者比值不能当预估用**：v1.46 关表 8 关实测 `actionsLB ÷ actions` = **0.13–0.20**（L5 33/236、
L8 17/84）—— 差 5–8 倍且比值随盘形飘。与 §5.0.1 同一结论：**静态/机算量预测不了人类用时**。
本区间的真作限 = ① `time` 溯源可校；② 异常盘哨兵（`actions < actionsLB` ⇒ 必错）。

**`pricing` 块（写在 `design/levels/singles/*.json` 的 `time` 之后）**：

```jsonc
{ "time": 850,
  "pricing": { "source": "bot", "actions": 236, "actionsLB": 33,
               "actionsSplit": { "moves":118, "places":33, "directFills":65, "retrieves":20 },
               "secPerTap": 3.6, "clamped": false, "cleared": true } }
// 人工试玩后改写（§5.0 公式 v0.3）：
{ "time": 259,
  "pricing": { "source": "playtest", "actions": 212, "tAct": 288, "k": 0.9, "measuredAt": "2026-09-23" } }
```

三条纪律：
1. **dev-only**：`sync-levels-data.mjs::DEV_ONLY_FIELDS` 在装配时整块剔除 ⇒ **不进** `LEVELS_DATA` /
   cocos 镜像 / 包体（运行期无人读；实测产物含 `pricing` 数 = 0）。
2. **不变式**（`assertPricing`，由 `levels:check` 在写盘与校验两条路径上都跑）：
   `source=bot` ⇒ `time == round(actions × secPerTap)`（除非 `clamped`）且 `actionsLB ≤ actions` 且 `cleared`；
   `source=playtest` ⇒ `time == round(tAct × k)`。**语义是溯源记录不是活公式** —— `secPerTap` 随当时写定，
   后续回调 `SEC_PER_TAP` 不致旧关集体报红。单测：`node --test tools/scripts/sync-levels-data.test.mjs`（7 例）。
3. **写盘入口唯一** = `beads-bot.ts::pricingOf`（studio 一键入关直接透传 bot stdout 的 `pricing`，
   不在 `server.mjs` 重拼 ⇒ 避免第二份构造式漂移）。

### 5.0.3 关卡数据不做客户端加密（威胁模型登记，WXG-T-203 续作）

结论：**客户端加解密不实现**，已评估并否推。理由：密钥必须在包内（否则运行期解不开）⇒ `unzip` 搜密钥
或 devtools 断点即得明文；且真正有商业价值的不是 `pattern`（玩家过关时本来就会看到，属内容不属秘密）
而是**定价逻辑**（`SEC_PER_TAP` / `k` / `STAR3_RATIO` / 广告缺口），它们在 `tuning.ts`，
同样在包里 —— 只加密关卡 = 白做。量级参照：8 关真源 JSON 合计仅 **8.8 KB**，包体不构成理由。

**接链时必做的最低限（现在无落点：`build:wx` 尚不存在，`settings/v2/packages/builder.json` 为空）**：
构建档 **开 minify / 关 sourcemap**（别把可读变量名与源码映射送进包），并将本小节当作验收项。
真要保护定价数据只有一条路：把 `time`/难度/广告参数**移出包体、改为服务端下发**（代价：失去离线可玩 +
需后端）—— 与本节 v0.3「`time` 应来自实测/运营而非玩家资产」方向一致，待发布阶段单独裁定。

### 5.1 尾盘满槽（GAP-06）交叉校验 —— ⛔ v1.2 整体作废（WXG-T-130 案 A）

> **⛔ 作废声明**：本节全部前提（定时供料、供料冗余、满槽跳供、死珠棘轮）随供料关停消失——托盘珠唯一来源是玩家取回、必有可周转路径（`core-loop §6`、`tray-spawner §2.4` GAP-06 闭合声明）。原文保留于 git 历史，此处不复制。3★ 与满槽的交叉约束由 §5 重推口径取代。

<!-- 原供料侧定性分析（WXG-T-081）随 v1.2 作废删除；作废原因见上。 -->

**供给冗余（派生自 §3 表与 §3.4/§3.5 常量）**

| 关 | 可填格 | 供料上限 = time ÷ spawnInterval | 对需求的冗余 | 本节手速假设（2–3s/珠，取中 2.5s）vs 供料节律 |
|---|---|---|---|---|
| L7 | 79 | 380 ÷ 3.0 ≈ **126 颗** | ≈ **+60%** | 2.5s/珠 **快于** 3.0s/颗 ⇒ 名义上不因总量堆积 |
| L8 | 65 | 280 ÷ 2.5 = **112 颗** | ≈ **+72%（八关最高）** | 2.5s/珠 **恰等于** 2.5s/颗供料节律（**零余量**）；手速落在假设下沿（3s/珠）或更慢时，**供料快于手速** ⇒ 托盘常驻高位 |

**定性结论**

1. L7/L8 的风险**不在总量而在颜色构成的棘轮效应**：零杂色不等于零死珠——供料按「网格仍需数」加权、不扣「托盘已持有同色数」（见 `gdd/tray-spawner.md` §2.4 缺口登记第 2 条），故某色需求归零后仍持有的珠不可落子且**不可逆累积**，有效容量单调下降。
2. 尾盘（剩余需求 < 剩余供料量）窗口越长，棘轮越可能触顶 12 槽；L8 时限最短（280s）+ 冗余最高（+72%）+ 供料最快（2.5s）⇒ **尾盘窗口占比八关最大**。故：**L7/L8 尾盘软锁死属「高可能」而非「小概率」，L8 > L7**。
3. **3★ 交叉（派生自本节既有硬上限口径 + `STAR3_RATIO`=0.32）**：L8 供料受限通关下限 = 65 × 2.5 = 162.5s，3★ 线 = 280 × 0.68 = 190s ⇒ 余量 27.5s；而满槽跳过供料「不排队、不补发」（S4 §2.2 第 4 步）⇒ 每次跳过永久吃掉 2.5s，**L8 的 3★ 只容得下 ≤ 11 次满槽跳过**（(190 ÷ 2.5) − 65）。L7 同法：下限 237s、3★ 线 258s ⇒ 余量 21s ≈ **≤ 7 次跳过**。即：L7/L8 的 3★ 实质上是「**零死珠 + 几乎零满槽**」的熟练挑战。

**建议（按优先序，均不新增数值）**

1. **首选：先落泄压阀 A′**（供料侧维持 `held ≤ demand` 不变量，见 `ux/ux-spec.md` §8 U8）。落地后 L7/L8 **无需调 `spawnInterval`、无需扩容**：每颗珠恒可落子 ⇒ 满槽不再等于死锁，上述 3★ 余量从「死锁风险」降为「纯节奏挑战」。**修可玩性优于调参**，调参只会把死锁概率往下压、不会归零。
2. 若用户选 B / C / D（三者均**不解决「过度供给产死珠」**：D 只去杂色、C 只清杂色、B 靠玩家手动补救），则 L8 需二选一：① 把 `spawnInterval` 由 2.5s **上调至 3.0s**（= L7 值，仍在 §3.4 合法区间 [2.0, 6.0] 内，且等于本节手速假设上沿）；或 ② 给 `TRAY_EXPAND_SLOTS` 一条**免广告解锁路径**（该常量已在 §3.4 冻结但 `powerups` §2.6 自认无解锁路径 = 惰性常量）。**推荐 ①**：改 1 个关卡字段 vs 造一条新解锁通道（新事件 + 新 UI + 新常量，且与 A1「激励视频解锁」用户裁定相冲）。
3. **不推荐**把扩容当首选：参考作确实随棋盘规模扩容（L1=12 / L2=24，参考分析 §2.2/§5），但 beads 的扩容绑定激励视频（A1 用户拍板），本轮无 AppID / 广告 SDK ⇒ 扩容是「纸面容量」，救不了实战死锁。
4. **playtest 触发线**：本节既有口径与预估法不改；**观测项**交 QA 的 playtest 计划定义（建议观测：尾盘是否出现「满槽且不可恢复」、以及 L7/L8 实测满槽跳过次数是否超过上述 3★ 余量），**阈值不在本策划文档内发明**。

## 7. 关卡设计约束（新增关卡必须遵守）

1. 字符集限定 `BEAD_CHARSET=".x1-9A-Z"`（**§3.2 v1.55 生效**，旧值 `.x1-9A`），其余字符均为错误——校验器报错到 id+行+列。**仍非法**：空格、`0`、**全部小写**（`x` 除外，它是锁定符）。⚠️ 大写 `X` 已从「非法」变为「**索引 33 合法**」（`Y`=34、`Z`=35）⇒ 任何 `toUpperCase()` / 正则 `i` flag 都是契约破坏（正本 §2.1 误写 34，已按实测订正）。
2. 每关只引入一个主新变量（支柱 3；对照 §3 表"新变量"列）。
3. 色数 ∈ [3, **35**] 且 ≤ `BEAD_COLOR_MAX`（**§3.2 v1.55 生效**：用户 2026-09-24 改判放开上限，**推翻 v1.36 的 ≤10**；35 = 单字符 rowstring 的编码天花板 ⇒ 该形态下的「不限制」；**>35 需换编码格式 = 另案**，本变更不覆盖）；索引 9/A（深棕/炭黑）**v1.36 起启用**；索引 **11–35 = `B`–`Z`** 无 demo 色 ⇒ **必携品牌引用**（见 §2 色板引用行与 §1 注；BOOT 硬校已落码 = 正本 §5-B1）；**demo 旧关仍 3–8 色不变**。
4. decoys 恒为空数组（惰性）。
5. 图案原创；异形轮廓靠 `.` 空位塑形，`x` 仅作视觉收边/教学，≤8 枚/关。
6. time ∈ [180,420] 越界即 BOOT 拒绝；~~spawnInterval ∈ [2.0,6.0]~~ **⛔ v1.2 作废**。
7. **swaps 遵守 §2 错位约束 + §2.1 恒等式**（对数 ∈ [1,8]、坐标可填、异色对）；可解性由交换构造保证（§2.1），无需运行时搜索。
8. 可填格 ≥1 且预估清关时长 ≤ time×0.85（防结构性不可通关；v1.2 预估法见 §5——错位玩法下该约束在八关建议值下自动满足）。

### 11.3 空大关「敬请期待」页的语义边界

**它是什么**：走马灯**最后一页**，表达「还有大关没投放」。**页数恒 = `ARC_OPEN_MAX` + 1**（`ui/main-menu-presenter.ts::_pages`）：前 `ARC_OPEN_MAX` 页 = 已开放章实体，末页 = **唯一**空橱窗。**即使所有章都 `open:true`，这一页仍在**（公式不随投放量变）——它是**投放状态**的固定出口，不是「内容没了」的占位。

**三条否定（防误用）**：
- ⛔ **不是「每个未开放章一页」**：`open` 必须前缀（无洞），未开放章不各自成页（否则玩家看到多个一模一样的「敬请期待」，且泄漏未投放章数量）。
- ⛔ **不是「空章」的表达手段**：章 `levels: []` = **非法数据**（生成期 throw）；要让一章暂不开放就用 `open:false`。判据：**空章 = 数据缺陷；空橱窗 = 正常投放态**。
- ⛔ **不是可点入口**：不做「预约 / 提醒我」、不做二次跳转、不加解释文案。

**呈现（照现码写、零新增）**：中间**置灰花**（`drawComingSoonMark`：`palette.locked` 填充 + `textDim` 描边，`SOON_CORE_R` / `SOON_RING` / `SOON_PETAL_R` 既有常量）+ 木牌文字 `ARC_COMING_SOON` =「敬请期待」；**无** boss 图、**无**缩略图、**无**三态戳（`carouselLevel = undefined`）。⛔ 不给该页配大关名/序号。

**交互**：点图 = **零事件**（`beads-shell.ts`：`offset >= ARC_OPEN_MAX ⇒ return false`；presenter 松手返回 `'none'`）⇒ 不开列表、不切 overlay、不扣心、无音效；翻页可达（◀▶ 边界可见性不变）。

|---|---|---|

### 11.5 向后兼容：单关还允许自带展示名吗？

**结论：不允许。** 玩家可见名的**唯一来源 = 所属 chapter 的 `title`**；单关 JSON ⛔ 再写 `title`（生成期断言 8 拒收，`pipeline §11.5`）。

**三条例据**：
1. **双真源必漂**：同一关既在 `singles/*.json` 写 `title`、又在 chapter 写 `title`，改一处漏一处，且运行期没有任何机制能判谁对。
2. **玩家面已无处显示单关名**：木牌 = 章名、页头 = 章名、玩法屏 = 零文字、选关格 = 缩略 + 星带（无文字）⇒ 单关名是**没有出口的字段**，留着只会诱使后来者误用。
3. **工程侧已定形**：`BeadsLevelRaw.title` 降级为**生成期派生字段**（保留字段名与 `?: string`），值由 sync 从章注入（`pipeline §11.7`）。

**现状登记（诚实口径，⛔ 不写「已达标」）**：工作树 `singles/L00009.json:4` 仍为 `"title": "曼陀罗"` ⇒ **CH-S3 落地前存在短窗双真源**；本节写的是**目标态**，验收 A1 在 CH-S3 前**预期红**。另：`design/levels/levels-data.header.txt` 与 `src/config/levels-data.ts:19` 的 `title` 注释仍写「木牌**第二行**」「缺省只显关序」⇒ 与现码（单行；有 title 即隐关序，2026-10-21 裁）漂移，随 CH-S3 同批订正（本文不碰源码/模板）。

**唯一窄例外：章收尾关（boss）的 `BeadsLevelRaw.title`** —— 允许存在，但须同时满足 4 条：

| # | 判据 |
|---|---|
| ① | 该关 `manifest.entries[].kind === "boss"` |
| ② | 它是所属章 `levels[]` 的**末项**（boss 收尾） |
| ③ | 值**逐字等于**该章 `title`（生成期注入，⛔ 非人手写） |
| ④ | 消费面**仅** `drawPlateTitle` 一处；将来任何第二消费面（含页头）必须走 shell → ViewModel，⛔ 不得复用 `lv.title` |

> 为什么保留字段而不是删：`drawPlateTitle` 只读 `lv.title`，删字段须改视图 + 改测试（K-053 换形代价），而当前没有第二消费面（`pipeline §11.7` 同判据）。该例外**不是**「单关可带名」的复活口——源 JSON 手写即被断言 8 拦下。

**`name` 不算例外**：`BeadsLevelRaw.name` 是 studio 生成串（`levels-data.ts:16` 注释「内部名 ⛔ 不上屏」）⇒ 非玩家可见名，本节不涉及，也⛔ 不得拿它兜底显示。
