## 0. 要解决什么

四条目标，各自给**可验收判据**（否则"有质感"无法收口）：

| 目标 | 判据（真机 / harness 可查） |
|---|---|
| **质感** | 单颗珠在 1× 缩放下能看出：穹顶偏心高光、孔的内壁明暗、侧壁厚度。不允许出现"纯色圆角方块贴纸"观感 |
| **空间感** | ① 珠与底板有可辨的高度关系（接触阴影 + 侧壁）；② `lift` 抬升时高度语言连续（见 §5），不允许"平移 6px 其他什么都不变" |
| **辨识度** | ① 一眼认定是拼豆 = **中心孔存在且在 fit 档最小珠径下仍可见**；② 相邻异色可分 = 生成侧 ΔE 约束（§8）+ 孔底透出目标色（§4/§7） |
| **与实物神似** | 对照参考图逐条核（§2 表）。已知主动放弃项 = 表面微颗粒（P5），须在验收时知情 |

## 1. 分层模型（自上而下）

```
B0  连续目标色底图   ← 每可填格一格，pitch 满铺、方角、恒画（与格内有无豆无关）
B1  空格凹陷层        ← 仅 empty：pit 内缩块 + 上暗缘 + 下受光（画在 B0 之上）
L0b 投影              ← 仅 filled
L0a 接触阴影          ← 仅 filled
L1  珠主体            ← 圆角方轮廓
L2' 侧壁（新）        ← 主体下缘一条暗带，高度随 lift 增长
L2  暗倒角 ×2
L3  亮倒角 ×2 / L3b rim 光
L1c 中心孔（新）      ← 孔底 + 内壁上暗弧 + 内壁下亮弧
L4' 偏心椭圆高光（并档）
```

**沿用不变量（死结论，改动即回归）**：

- ⛔ **B0/B1 不参与 `lift`、不参与 `scale`** —— 恒锁格心恒画（§1.6.1 P0 陷阱 #2 同源；旧 bug 是"抬珠把垫一起抬走 ⇒ 读数被自身抹除"）。本模型把底图独立成层，从结构上隔离该风险。
- ⛔ `scale` 只作用珠体族（L0a…L4'），**不作用 B0/B1**。
- 渲染序固定 B0 → B1 → 珠 → 孔 → 高光。

### P5 主动放弃项（须知情）

程序化颗粒只有两条路，都不划算：① 噪声位图 → 违反零外部资产 + 占包体；② 逐颗撒小图元 → 图元爆量。
**替代** = 靠倒角/高光塑形给"哑光塑料"的读感。**代价**：放大到珠径 >60px 的特写会显得比实物干净。

## 4. 「有豆 / 无豆 = 同一张图」的论证与代价

**现状**（实测数值）：`empty` 最外层 = 亮 `base` + 内缩 6% 的 `pit`(−0.44) + 圆角 r=11 + 格间 `BEAD_GAP=2`；
`filled` 可见底 = `edge`(−0.30) + 方角 pitch 52（上批所改）。⇒ **色档与几何双重不一致**。

**目标**：B0 对**每一格**都画 `edge` 方角 pitch 满铺；`empty` 与 `filled` 的差别只出现在 B0 **之上**画什么。

**"空 vs 珠"仍可辨的依据**（沿用 `accessibility.md` A3 ③ 的既有量化）：同色下坑底 S2 与珠体 L1 的 ΔL = `0.14 × L_base`（活力橙 23.7/255），且坑的暗缘在上、珠的暗倒角在下 —— **明暗方向相反** ⇒ 凹陷/凸起可分。

**代价与风险（不掩饰）**：

1. 现方案里"空格外圈是亮 `base`"这一条**顺带**承担了"哪些格可填"的读数。改成统一 `edge` 后，该读数只剩 B1 的凹陷线 ⇒ **可填轮廓的辨识度可能下降**。若真机判定不足，回退 = 给 `empty` 的 pit 再加一档深度（**不新增 hex**，只调 mix 系数）。
2. `filled` 侧不再单独画垫 ⇒ **−1 图元/格**；`empty` 侧 base 被 B0 承担、坑层保留 ⇒ ≈0。净 **−156**（156 格盘）。
3. 色盲相关：见 §7。

## 6. 图元预算与 LOD（必须一起裁，不能事后补）

- 孔 = **+2~3 条/格**，侧壁 **+1**，椭圆高光并档 **−2**，垫并入底图 **−1** ⇒ 净 **约 +1~2/格**；156 格 ≈ **+156~312**。
- 按仓内纪律（`important_decision_experience`：图元/包体增量类规格值**必须落码后差分复算**）：本表**不给基线数字**，落码后跑 `check:size` 与 §1.8 基线表复算并回填。
- ⚠️ 量级上这会**重新逼出 ADR-0017 的降档通道需求**。且上批实现的 LOD 红线原文是「**L11 垫与 L5 符号任何档不砍**」，现 L5 已随符号删除作废 ⇒ 红线段须重写为：
  **B0 底图 + B1 空格凹陷 + L1c 中心孔 = 任何档不砍**（孔是识别特征，砍了立刻退回"贴纸"）；质感族（倒角/rim/高光/接触阴影）= 降档可砍集。

## 7. 可访问性连锁（改规格必须一起改的账）

- 上批已把 **A1 从「色相+符号+明度」三重降为二重**（符号层整层删除），并把 B2「符号对珠面 ≥3:1」判为 ⛔ 作废。`check:a11y` 锚点门已对齐（A1 锚改指 `padColorIdx`、B2 锚 `-`）。
- **K3 若采纳「孔底透目标色」**：等于给每颗珠自带一个"我该变成什么色"的对照物，且孔是**几何特征**，在 fit 档珠径 ~19px 时仍在 —— 而上批实测证明 **6px 垫缝在那个尺度上恰好消失**（那才是"分不清"的真凶）。这条对本仓当前唯一可行的非色相通道有实质价值。
- **但 K3 不是色盲等价替代品**：孔只回答"这一格要什么色"，**不回答"这两颗珠哪个是哪个色"**。后者在符号删除后只剩色相 + 明度，而 `accessibility.md` A3 ① 早已量化：**明度单独不足以分开 10 色**（玫红/湖蓝、湖蓝/赭棕相邻差 <4%）。⇒ 用户 2026-09-16「暂不支持色盲」的裁定继续成立，本规格不偷偷宣称已修复。

## 8. 色板与相邻格 ΔE（生成侧，与视觉规格耦合）

- 真机取证 + 一次纠错：上一轮我报的 `红↔粉 ΔE76 = 29.8` 来自**错误的色彩转换**（sRGB→XYZ 多做了一次逆伽马）。**正确值 = 41.9**；同批色盲模拟四列**全部作废**，不得引用。
- 八关实测（正确管线）：L1 最小相邻 ΔE 41.9（相邻 88 对红/粉）⇒ **L1 的问题不在色相，在"目标色只有 6px 缝能表达"**（本规格 §4 治它）。真实低分盘是 L5 14.1 / L6 13.9 / L8 18.0。
- 已落码：`beads-gen.mjs::separateAdjacent()` + `adjacentConflicts()`，`--minadj` 默认 **20**，跑在 `balance()` **之后**（链路最后一步），改不到就保持原色（色彩保真优先），`report.adjacency` 上报 `changed`/`conflicts`。
- 建议 K9 与 B0 底图**一起看真机效果**再定阈值：底图统一后缝变连续、可读性上升，20 可能偏松或偏紧，**不要现在猜**。

### 11.5 §5 抬起三通道（v1.5-r9，2026-09-23）

单一高度参量 `liftT = clamp(lift) / liftRef`（`liftRef = 6` = 选中/锚组抬起量；波浪 `WAVE_LIFT_PX = 3` ⇒ liftT 0.5），四通道同向：

| 通道 | 规则 | 满抬起值（静息 → 抬起） |
|---|---|---|
珠体放大 | `size × (1 + 0.04·liftT)` | 38 → 39.52px（仍 ≪ 格宽 50，A5 零重叠前提不变） |
投影偏移 | `shadowDy × (1 + 1.5·liftT)` | 1.78 → 4.63px |
投影浓度 | `shadowAlpha × (1 − 0.4·liftT)` | 0.15 → 0.12（仅未覆写时） |
接触面宽度 | `contactW × (1 − 0.35·liftT)` | 33.4 → 21.7px |
侧壁长度 | `wallH × (1 + 0.9·liftT)` | 3.8 → 7.2px |

**两条被现成判据拦下、改代码而非改判据的坑（重要，别踩第三次）**：

1. **α 越界**：初版把 L0a 接触阴影的 **α 也随 lift 淡掉**，而 `§1.2 lift and shadow α` 判据明写「L0a 固定 α 不受影响」——那是 art 已定的语义。⇒ 改为**只收窄、不动 α**；"离地 ⇒ 接触面变小"由宽度传达已足够。
2. **覆写与 lift 打架**：`selected` 传 `SELECTED_SHADOW_ALPHA`（"抬起 + 阴影更深 = 重量/强调"），而 lift 的物理结论是"抬高 ⇒ 影子变淡"；两者同现时上一版得到 0.183 而非 0.25 ⇒ **会静默推翻 §1.2 的选中语义**。现规则 = **显式覆写优先，lift 只调制未被覆写的默认值**（G1 落座包络与选中态逐字不变；G4 波浪期吃 lift 衰减）。

另：位移类判据（`§1.2 bodyY`、`scene-vfx lift`）**从「比底边」改为「比珠心」** —— 珠体现在随 lift 放大，底边比心多下移 half-growth，拿底边量会得到 178.33 而非 179。**那不是位移错，是尺子错了**；珠心才是与缩放无关的正确基准。

图元数：本批**只改数值、不加图元** ⇒ §11.2 基线不变（仍 1587，+1/已填格）。

**仍缺一步：ease-out 斜坡。** 本批只建立「通道 ↔ 高度」的静态映射；选中态的 `lift` 仍是 0 直接跳到位（无时域缓动），所以选中瞬间仍会偏硬。要补需要：① game 侧给锚组一个抬起进度（类 `placeProgress`，目前无此状态）；② `ux-spec §5` 新增一行时长 —— 建议**复用 `FILL_POP_MS = 120` 不新增毫秒值**，属 ux 口径变更，需拍板后再动。

⚠ D1（`reduceMotion`）本批无需特批：没有自发动画与 α 往复（不触 D2）；斜坡落地时再按 §5 注记处理（曲线退化为线性、放大归零）。

- **证据分层（不混称）**：fit 档 = 编译产物 e2e（`temp/beads-lift-shadow/`，8 关全档间隙占格径 **0.0787、极差 0**；L6 `gridCell 29.65 ⇒ lift 5.93`）；
  胀档 0.75×/1.5×/3× = 单测 `scene-vfx §5 抬起量走等比`（含第③条「孔径/格径 恒定」）；真码变异自证 = 把 `liftT` 分母退回静息值 ⇒ 判据报
  `expected 0.16617 to be close to 0.16779`（红）。**两者都是几何口径，帧率仍 `[待真机]`。**

**追记后仍未做**：① 侧壁（吃 C7 最后 1 命令余量）；
③ **大组错峰**——实测 L2/L4 的选中连通块达 **24 / 18 颗**（本次重测 L2 最大组 = **55 颗**），全组共用一个 `liftProgress` ⇒ 同帧齐起齐停，
读感可能是「整片闪」而非「从指尖揭开」；相位可由视图从 `(i,j)` 距锚派生（L5 安全，参 `SOLVER_STAGGER_MS` 语言）。
⇒ **③ 已完成，见 §11.6-b**（改用快照消费序的**序号**作相位源，比距锚派生更准且零重算）。

### 11.6-b 追记③：独立时长 + 一次回弹 + 组内错峰（v1.5-r16，2026-09-26）

**用户要求**：「下一个做 ③，增加一个回弹的效果，ease in out」。

| 项 | 现口径 | 真源 |
|---|---|---|
| 时长 | ~~120ms（= `FILL_POP_MS`）~~ → **200ms 独立值** | `tuning.SELECT_LIFT_MS`；毫秒表 = `ux-spec §5` v1.20 两行 |
| 曲线 | ease-out → **ease-in-out 升到 `1+REBOUND` 再落回 1**（`scene-vfx::liftEase`，复用本模块已有 smoothstep） | `SELECT_LIFT_PEAK_T 0.7` / `SELECT_LIFT_REBOUND 0.12` |
| 错峰 | 板锚组按**快照消费序序号**逐颗相位偏移；`SELECT_LIFT_STAGGER 0.35` ⇒ 组尾晚起 70ms | `scene-vfx::liftStaggerPhase` |
| 预算影响 | 错峰走**同窗口相位偏移** ⇒ 不拉长总时长 ⇒ **零新增第二个毫秒值**；曲线两端精确 ⇒ **稳态 6px 不变**（现有 Δy 类判据不漂） | — |

**裁定解除（必须记牢）**：v1.5-r10 用户裁定「斜坡按 120ms 复用做」在本批被**解除**——理由：回弹需要一个「过冲→回落」的完整周期，120ms 内两阶段各 40ms 不可读。**顺带收口一处既存漂移**：`ux-spec §5` 旧值 100ms 与代码实际 120ms 不等，且没有任何判据会为此变红（K-035 同族）。

**错峰为何用序号而不是距锚**：`snap.boardGroupRows/Cols` 由 game 侧按 `planConsumeOrder` 填（锚恒在序首，WXG-T-186）⇒ 序号就是现成的“揭开序”，**视图零重算**（L5：不在视图跑 BFS）、且与玩法消费序天然同序（取回/直填也是这个序）。

**逐帧实测（编译产物，L2 最大组 55 颗；`temp/beads-lift-shadow/curve-trace.mjs`）**：

| 帧 | elapsed | 锚 lift | 组尾 lift |
|---|---|---|---|
| 1 | 17ms | 3.86 | 0.00 |
| 4 | 67ms | **6.62**（过冲） | 1.71 |
| 6 | 100ms | 6.00（落定） | 5.23 |
| 8 | 133ms | 6.00 | **6.68**（过冲） |
| 10 | 167ms | 6.00 | 6.00 |

⇒ 锚与组尾各自“升→过冲→落定”，时间上错开 ~70ms = 从锚揭开的一片；**峰值不越 6.72px**（恒等档）。

**判据**（`tests/scene-vfx.test.ts` · §5 抬起曲线与错峰，四例）：曲线两端精确 / 峰值 = `1+REBOUND` 且不越 / 全程不下穿底面 / 起手斜率 < 0.25（ease-in 起步，钉住“非旧 ease-out 即跳”）；相位单调（`p=0` 全 0、`p=1` 全到位）；**帧级** = 2 颗组中途帧锚珠严格高于组尾珠、满帧两者 `toBe(SELECT_LIFT_PX)`；D1 不走曲线与错峰。
**真码变异自证**（三型各判红，含数字诊断而非「找不到」）：`liftT` 分母退回静息值 ⇒ `expected 0.16617 to be close to 0.16779`；`SELECT_LIFT_REBOUND → 0` 与 `SELECT_LIFT_STAGGER → 0` ⇒ 帧级例报 `expected 5.56 to be greater than 5.56`。

**未做（承前）**：① 侧壁；④ 过冲量 0.12 与错峰占比 0.35 均为**起始值**，`[待真机/playtest]`（55 颗大组是否偏扰属观感，不由纸面判）。

### 12.7 α 上限的证据边界与回改触发器（四批补录）

**上限定为 α ≤ 2 的理由（不是“2 层便宜”）**：

- **2 是实测分布的空档区**：入选池（六批后 = 4 套）= **0 / 0 / 0 / 1**（四棱 / 13 / 06 / 18），移出组 = 3（彩玻）/5（亮漆）/6（珍珠）/7（夜光）/16（磨砂）/20（毛毡）⇒ **无任何现有样本落在 2**。故 1 → 2 **不改变任何现有池单决策**，只是为未来「一层软阴影 + 一层高光」这个最小质感配方留出余量；放到 3 就会放进实测脏组（12 彩玻）。
- **成本口径**：α 混合 = 每像素 read-modify-write（需读回 framebuffer），是带宽操作；因 A5 零重叠前提，同像素 α 叠加 ≈ 单颗珠内部层数（邻珠投影偶外拓 1 层）。**计数式与测量单对齐**：本门 α 层数 = `alphaCmds`（`alpha < 1` 的命令数，见测量单 §3.2），`styles.mjs` 的 `probe()` 用的是同一式。
- ⚠ **四口径不得互相代替**（测量单 §0 消歧）：**层级 / 命令数 / α 次数 / fill 面积** 是四个不同量——本门只盖住后二中的**一项**（见下项 5）。

**诚实边界（必读）**：

1. **α ≤ 1 还是 ≤ 2 对帧率的影响，本仓当前不可证** —— 真机帧率从未测过（`ADR-0022 DR-1` 明文；D7 只有桌面档 WebGL2 / 1024 uniform / Apple M4）；H-FILL 仍是**待真机裁判的假设**（该 ADR 自述「不预设结论」）。**执行载体已在位**：`production/qa/beads/render-perf-device-baseline.md` v1.0（2026-09-25，严守真）只出了**测量规程**，所有数据列均 `[待填]` ⇒ 不得把它当已有结论引用。
2. **回改触发器**：`ADR-0022 §7` 的 **D1**（真机基线 fps p10/p50 + 每帧真 α 命令计数）与 **D2**（12命令/4α vs 3–7命令/0α，再加“命令减半但保留 4α”的构造档分离两变量）跑完后，**本上限必须回头复核一次**：D2 判为「α 不敏感」（差异 <15%）⇒ 上限可放宽、重心改盯命令数；判为「α 敏感」⇒ 收紧回 ≤ 1 甚至 ≤ 0。
3. **解除条件（已收窄）**：不再等「真机链路可用」（构建链已通、**低端真机用户 2026-09-25 确认在手** ⇒ D1/D2/D7 已由「⛔ 不可测」转「待执行」）。**具体解除门** = 该测量单 §12 checklist 第 6/7/8 步跑完（D1 基线表 + D2 臂矩阵 + 两机同向判读）⇒ 按其 §6.3 六态表裁 H-FILL / H-CPU 后回头改本上限。⚠ 敏感线 **S=15%** 在测量单里仍标 `[待主理人拍]`（未冻结），且其 §10.1 禁令 6 禁止把建议值当已冻结值判绿。
4. **未验前不得引用的说法**：“2 层安全”“4 层仍安全”均无数据支撑；现状十层带 4 α 也只是「未被否证」，不是「已验证可行」。
5. **本门已知盲区：α 覆盖面积（FI 指数）未入门**——测量单 §6.1 的 **E4 臂**专门拆「被混像素数」与「混合次数」两个变量，而本门只卡 α **层数** ⇒ 理论上存在“命令 ≤7、α ≤2 但单层面积极大（如满幅柔光）”的风格能混过门禁。**暂不补第三指标**（无真机数据定面积阈值），登记为缺口：D1 埋点读数出来后，随该单 **DG-4**（纸面口径 vs 真机口径差值表）一并评估是否加面积门。

### 13.3 缓存 key 与烘焙内容

- **key = `styleId | colorIdx | bakeSchemaVersion`**（⚠ 单烘焙口径下 **sizeTier 已移出 key**，见下）。
  v0.6 平面收窄为单珠 ⇒ **key 无需新增维度**：豆径与格径差异由 blit 的绘制尺寸表达（层集全比率制），
  托盘珠与网格珠同 key 复用成立（珠色相同时）。
- **孔 = 烘内壁 + live 孔底（v0.6 更动 v0.5 的「盖帽」口径）**：孔框/孔内壁属静态层（只取决于风格与珠色，
  合 §13.11 四条）⇒ **进纹理**；孔底 `circle` 逐帧 live 画，理由不变——① K3 孔透目标色语义保留；
  ② `targetColorIdx` 不进 key（否则 key 空间 ×35）。
  ⚠ **接缝机制随之从「盖帽」改为「贴边盖底」**：live 孔底半径 = `烘焙孔径 × 当前缩放 + 0.5 设计 px`，
  0.5px 余量用于盖住纹理内壁与 live 圆之间的缝（ADR-0025 DEC-3；= §13.13 T4「孔对齐」的确诊对象）。
  ⇒ **孔径整数裁定必须收窄**：现码 `facet-4.ts::HOLE.r = Math.round(size × holeRatio / 2)` 是**逐帧**取整，
  连续缩放下半径一跳一跳，且与烘好的内壁对不上 ⇒ 取整只在**基准尺寸烘焙**时生效，运行时路径连续缩放。
  ⚠ 附带好处仍在：孔底按最终分辨率画，纹理缩放时孔沿不糊。
  ⚠ **小豆档 `hideHole` ⇒ 走矢量臂**（v0.6 裁定，可否决项）：纹理已含内壁，小豆档若复用同纹理会剩一圈
  没有孔底的暗纹；另立「无孔」变体 = 每色纹理 ×2 ⇒ 改由矢量臂出画，零内存增量、零第二变体。
  托盘珠无目标色 ⇒ 按既有契约回落本格 `pit`，同样 live。
- **烘焙内容边界 = 珠体层集（plate 描边 + 9 刻面）**。**格级抬起影不烘**（用户 2026-09-27 问，三理由）：
  ① 影钉在格面静息足迹、不随 `lift` 平移 ⇒ 与珠体**不同变换**，合不进同一纹理；
  ② 影色 = 本格**目标色** `pit` ⇒ 烘进去就把 `targetColorIdx` 拖进 key（×35，同孔的理由）；
  ③ 本身 1 枚 rect / 0 α，不是 fill rate 瓶颈。B0 底图全风格共享（S4），同理不烘。
  ⚠ **术语消歧（用户 2026-09-27 问「一份还是两份」）：当前默认皮肤下是一份**——现役唯一
  实现 = `drawLiftGroundShadow`（格级分离影）；「投影 L0b / 接触阴影 L0a」四通道
  （`shadowAlpha`/`contactAlpha`/`contactWidth`/`shadowDy`）**只在 `legacy-ten` 对照臂活着**
  （facet-4 无承载体，`drawFilledBead` 如实不透传），随十层回退阀退役同批退役，
  不入烘焙范围。**影的实现路线裁定（用户 2026-09-27 追问「程序化 vs 纹理」，判据经 §13.10
  调研修正）= 维持程序化**：按 §13.10 双项收益式，影两项收益 ≈ 0（H-CPU 项：1 命令/1 展平；
  H-FILL 项：0 α 实色 1 pass；实例仅选中组），纹理版逐维度不省反贵：① 软本影 = 逐像素
  α 混合（带宽）比实色 rect 贵且破「0 真 α」不变式；② key 族多一套（影色 = 目标色 pit ⇒
  key = `targetColorIdx`，×35）或灰模+tint（撞 C 案色彩语义问题）；③ fade 动效需命令 α；
  ④ 双 renderer 采样差异 = seal 新漂移源。业界同代引擎明文反例（Laya cacheAs 文档）：
  「对象非常简单（一个字/一张图），缓存不但不提高性能反而损失」。
  **纹理版唯一实质优势 = 表达上限（软本影/羽化）**，故后备路径触发条件钉为「**美术要软
  阴影**」（性能理由对它不成立）；届时需先登记三项代价（带宽 α 混合 / key 族 / 破 0 α 门）
  再拍板。投影（legacy-ten L0b）同理且退役在即，不单独裁。
- **烘焙基准 = 2.0× 珠体边长（v0.6 按 B6 改写）**（用户 2026-09-27 裁定：「烘焙直接用 2.0 倍的纹理，
  不再烘 1.0 倍」⇒ 每 (style, color) 一张覆盖全部尺寸档）。分辨率算式 =
  `珠体边长 × CAMERA_ZOOM_MAX(2.0) × min(物理px/设计px, BAKE_DPR_CAP[暂定 2])` + **1dip 外圈**（防边缘截断）
  ⇒ 满豆恒等档实算 `26 × 2.0 × 2 = 104` + 外圈 ≈ **112 px/纹理**。
  `~~BEAD_CELL × CAMERA_ZOOM_MAX(2.0) × dprCap~~`（v0.5 原式，按格边长）随 B5 作废：平面只剩单珠，
  基准的承载体是**珠体绘制边长**（`BEAD_CELL − 2×BEAD_DRAW_INSET`，等比后随 zoom 与豆径档变）。
  基准倍率仍直接引 `CAMERA_ZOOM_MAX`、不设第二常量（§13.9 v1.59 注原文有效）。
  正确性论证：绝对档 ⇒ 全盘最大绘制珠径 `珠边长 × zoom ≤ 珠边长 × CAMERA_ZOOM_MAX` ⇒ **「只下采、不上采」恒成立**
  （旧论证走的 `fit ≤ 1` 通道随 `zoom ≤ fit × SPAN` 口径退役；新论证更强——与盘的 fit 无关）；
  请求尺寸 > 缓存分辨率的 miss 分支降为防御性保留，逐档判定与 settle 重烘机制整体删除。
  ⚠ 本节此前否决过「单档最大烘焙」——那是针对「逐盘最大档」（fit 逐盘变、无统一上限）的反对；
  用户口径按固定基准 2.0× 烘，该前提不成立，**采纳**。
- **mip 链：本轮不定案**。逐档减半到 ≈8 px 的档位方案、以及「有细线/星光的风格每档要用矢量配方重烘」
  （= M+ 路径）均属 `proposals/zoom-bake-mip-validation.md` 的 **V/S1/S2/M/M+ 五路径裁决面**，
  该档明文「⛔ 任何预测不得被读作已验」⇒ 本章只写接口一条：缩小跨度 = `CAMERA_ZOOM_MAX / CAMERA_ZOOM_MIN` =
  **10 倍**且与机型无关，故低倍段画质与闪烁**必检**；⛔ 在本章把档数或「每档重烘」写成既定（= 重走
  §13.10 检讨过的「先裁定后调研」）。
- **zoom 手势期走矢量臂保留**（§12 S2「矢量无损」在交互期逐字兑现；settle 防抖
  **[暂定 150ms]** 不再承担「定档重烘」职责，纯作纹理⇄矢量切换时机）。
- ⚠ **单烘焙口径的代价（诚实登记）**：① 静息档 ≈ 2× 降采，2D canvas 无 mipmap，
  2px 线族（plate 描边、孔边线 = T-215 新增）可能变糊/走样 **[待真机 A/B]**；**回退阀** = 实测静息档读数劣化
  ⇒ 退回逐档烘（sizeTier 加回 key，其余结构不动）；② 内存按 (2×)² = 4× 于静息档单烘，
  预算见 §13.5 B1 算式；③ v0.6 新增：孔内壁入纹理 ⇒ 低 mip 档内壁糊化后与 live 孔底的 0.5px 盖缝余量
  是否仍够用，属 §13.13 T4 的实测项，⛔ 纸面判。
- **`bakeSchemaVersion` = `tuning.ts` 命名常量**：层集几何 / inks 端点表 / 烘焙径口径
  （SPAN、dprCap）任一变更 ⇒ 手工 bump ⇒ 全缓存作废重烘；⛔ 不做细粒度失效（无微妙 stale 态，ponytail：一把全冷最简）。

### 13.4 烘焙时机与回退（miss 永不阻塞）

1. **关卡加载预热**：关卡 JSON 色集已知 ⇒ 加载屏内同步烘齐本关色集（单口径无档位概念；
   ≤35 色 × ~10 命令 offscreen 回放，毫秒量级；托盘色 ⊂ 关卡色集 ⇒ 同批覆盖）。
2. **懒烘**：加载后新出现的颜色（如自定义色板关 / 每日图案）⇒ 当帧矢量臂出画 + 烘焙入队，
   下一帧起命中；⛔ 烘焙不得发生在 `buildRenderModel` 热路径内（热路径零分配纪律）。
3. **回退恒在**：任何 miss / 预算驱逐 / 适配层不可用（如 headless 单测）⇒ 矢量臂，
   输出与今日逐字节同构 ⇒ **正确性从不依赖缓存**，缓存只买 fill rate。
