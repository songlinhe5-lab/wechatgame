## 3. 豆子出口①：道具卡超限再买一次

### 3.1 交互

1. 某型道具本关免费次数（1 次）用完后，再点该卡 ⇒ 卡片显示**豆子价角标**（替代现 `ad_badge`），点击弹出「用 N 豆子再用一次？」；
2. 确认 → 扣豆 → 效果照常生效（与免费次完全同路径：`powerup:used`）；
3. 豆子不足 / 本关购买次数达上限 ⇒ 角标置灰，点击轻提示（零扣款、零事件）。

### 3.2 次数与价格（v0.3 按行业锚重定价）

| 项 | 建议值 | 依据 |
| --- | --- | --- |
| 每型每关可买次数 | **1 次** | 与免费 1 次对称；防「无限买同型」把单关变成付费直线 |
| 每关总购买上限 | **2 次**（3 型合计，最贵组合 ≤ 90 豆 ≈ 2 天签到） | 品类惯例：一关可买的付费道具上限 **1–2 次**，防「付费即通关」；2 次已够救一次失手 + 一次推图 |
| 单价 | `solver` **20** / `solverRandom` **30** / `solverPlus` **45** | 按影响格数（1 / 1 随机 / 3）分档，并按**「最低档 ≤ 0.5 天免费产出」**定标：45.7 豆/天 ⇒ 20 = **0.44 天**，保证「每天用一次不心疼」；v0.2 的 30/40/60 占 0.66–1.31 天，属高估 —— 道具只在卡关时有价值，价格越接近一天收入，玩家越会「宁可重开也不买」，出口形同虚设 |
| 关内重置 | 购买计数与免费次数同源复位（新关 / 重试 / 换关） | 沿用 `powerups.md §2.5`，**不入存档** |

### 3.3 与布局 A 的关系

- 改判点：3 个道具位的 `ad_badge` 从「广告占位」改为「豆子价角标」——**不拉起广告**，只读豆子余额；
- 扩展位（`btn_expand`）**本批不动**（仍角标占位），后续可另批决定「广告解锁 / 豆子买」；
- 需登记：`powerups.md §2.6` 布局 A 的 3 道具位口径变更（留痕，不静默改）。

## 4. 心：自然回复（现状不动）+ 广告固定恢复（限次）

### 4.1 你的四条裁定 → 与代码逐条对照

| # | 要求 | 现状 | 差距 |
| --- | --- | --- | --- |
| ① | 固定时间恢复 **1 心** | **已实现**：`STAMINA_REGEN_MIN_MS = 8 分钟/心`，`MetaState.refresh()` 每帧按 wallClock 算 `floor(Δt / regen)`，离线同样计（`staminaAnchorMs`） | **无 —— 零改动** |
| ② | 恢复到上限**不再恢复** | **已实现**：`refresh()` 里 `cur >= STAMINA_MAX` 时锚点跟随 `now`、不累积，且写档值恒钳 `STAMINA_MAX = 8` | **无 —— 零改动** |
| ③ | 看广告**固定恢复数量** | 现在是**回满**：`refillStamina()` 直接置 `STAMINA_MAX`（play 侧 `onStaminaRefill`、菜单侧 `onRewarded` 两处调用） | **要改**：回满 → 固定 `+HEART_AD_GAIN` |
| ④ | **每日限制**广告次数 | **完全缺失**：`refillStamina()` 不计数、无日期键、无上限 | **要新增**：计数 + 日期键 + 常量 |

> 结论：你 ①② 要的行为**生产代码今天就是对的**，本提案不改它；真正要动的是 ③④，且 ③ 是把「回满 8」降级为「固定 N」，属于**收紧**，须走 §3.14 / §3.11 变更单留痕。

### 4.2 落法（最小改动面）

1. **新常量**（`tuning.ts`）：
   - `HEART_AD_GAIN = 3` —— 上限 8、8 分钟/心 ⇒ 等效 24 分钟自然回复（§8 #1 依据）；取 8 就退回旧「回满」口径，取 1 则广告几乎无感；
   - `HEART_AD_DAILY_LIMIT = 5` —— 日上限 5 次 × +3 = 日广告得心 ≤ 15（§8 #2 依据）。
2. **`MetaState` 新增 `grantAdHearts()`**：`addStamina(HEART_AD_GAIN)`（已有语义：钳上限、溢出即弃）+ 日限计数；`refillStamina()` 保留但 **UI 不接**（与 `buyHeart()` 同样标注「不接 UI / 待下线」）。
   - ⚠ **已知损耗**：`addStamina` 会把 `staminaAnchorMs` 重锚到 `now` ⇒ 丢弃当前未满一档的进度（最多 8 分钟）。签到已走同一路径，属既有口径；若要严格公平需另立「保留锚点」的 `grantAdHearts` 实现（**是否需要，待你拍板**）。
3. **存档新增 2 字段**（`meta-save-schema.ts`，`version` 仍 `1`，**老档零迁移**）：
   - `heartAdToday: number`（缺省 `0`）、`heartAdDate: string`（缺省 `''`），与既有 `heartBuysToday / heartBuysDate` 同型；
   - `normalizeBeadsMeta` 补默认值 + 纳入 `changed` 判定（坏值降级，不抛）。
4. **入口与闸门**：
   - 满心（`stamina >= STAMINA_MAX`）⇒ **不拉起广告、不计次**（避免玩家白看一次）；
   - 日限用尽 ⇒ 入口置灰 + 轻提示（零加心、零计次）；
   - **0 心 retry/restart 被拒**仍走同一入口（`'stamina-refill'` 位），只是奖励从「回满」变「+N」，够 1 局即可重试。
5. **文案**：「看广告回满体力」→「看广告 +3 心」；走 `copy-tokens`，[待裁] 措辞。
6. **豆子买心下线**：`buyHeart()` 保留（测试仍用），头注标「不接 UI / 待下线」；`HEART_PRICE_LADDER` 保留不删（避免无谓删码）。

### 4.3 语义与数值影响（须知）

- 0 心玩家的续航从「一次广告 8 局」降到「一次广告 3 局」（N=3）；配合日限 5 次 ⇒ 日广告得心上限 15，约等于「一日一条半满心」。
- 自然回复仍是**主供给**：8 分钟/心 ⇒ 理论 7.5 心/小时，受上限 8 截断 ⇒ **从 0 回满只需 64 分钟**。这意味着「心」本身几乎不稀缺，广告得心的边际价值偏低——`[待 playtest]` 观察项；若要让广告真正有杠杆，需拉长 regen 或降低上限，但**两者都动 §3.14 冻结值**，本提案不擅自改。
- 「回满 8」在数值上等价于「跳过 64 分钟自然回复」；改成 +3 = 跳过 24 分钟。**这是本批唯一实质削弱玩家收益的地方**，请确认这是你想要的方向（若不是，把 `HEART_AD_GAIN` 提到 5 即可）。

### 4.4 广告基础设施

- `services.rewardedAd` 已通（续时 + 回满两处 live）；
- **placement 沿用 `'stamina-refill'`**（零新增位、零框架枚举改动），语义由「回满」变为「+N」——须在同批变更单里登记该位的语义变更；
  - 备选：新开 `'heart-ad'` 位以便埋点区分；**代价**是要同步发布侧广告单元映射（`[待拍板]`）。

## 7. 判据（落码时必测）

### 7.1 豆子（道具出口）

1. 免费次数用尽后才出现豆子价角标；免费次数内**零扣豆**；
2. 豆子不足 / 达每关上限 ⇒ 零扣款、零事件、零清槽；
3. 购买成功 ⇒ 扣豆一次 + 效果生效一次（与免费路径同一事件）；
4. 豆子图标缺失 ⇒ 沿用现图标，**零崩溃、零空图**。

### 7.2 心（自然回复 + 广告）

1. 自然回复回归：距锚点满 8 分钟 +1 心；不足 8 分钟**零变化**；
2. 到上限即停：8 心时跨 24 小时**仍为 8**，锚点跟随 `now` 不累积；
3. 广告成功 ⇒ 心增量**恰为** `HEART_AD_GAIN`，且钳 8（例：7 心 +3 ⇒ 8，溢出即弃）；
4. 满心时入口不可用 ⇒ 不拉起广告、**不计次**；
5. 日限用尽 ⇒ 拒绝、零加心、零计次；跨日（本地 `YYYY-M-D` 变化）计数归零；
6. 老档（无 `heartAdToday/heartAdDate`）装载 ⇒ 默认 0 / `''`，**零迁移、零重置警告**；
7. 0 心 retry/restart 被拒 → 看完广告 ⇒ 加 `HEART_AD_GAIN` 后可重试（不再是「回满 8」）。

### 7.3 存档与安全

1. `coins` / `staminaCur` / 既有 `heartBuys*` 字段名与语义**逐字不变**。

## 8. 七项定值 + 依据（✅ 2026-10-22 用户「按建议值走」⇒ 全部生效，已落 §3 v1.80）

> **定值三条锚**：① **品类惯例区间**（F2P 手游体力/激励视频/消耗品的通用做法，不是精确统计）；② **本作内部自洽**（`STAMINA_MAX=8`、8 分钟/心、豆子日均 45.7 三个既有数才决定合理区间）；③ **出错代价对称性**（宁可保守，留 `[待 playtest]` 调参位，别一次定死）。

| # | 项 | 建议值 | 依据 | 取偏的代价 |
| --- | --- | --- | --- | --- |
| 1 | `HEART_AD_GAIN` | **3** | 惯例：单次激励奖励的「**时间等价**」多落在 **20–30 分钟**；本作 8 分钟/心 ⇒ 24 分钟 = **正好 3 心**，落在区间中位。内部：上限 8，取 8 等于「回满」（日限失效），取 1 一段 30 秒广告几乎不可感 | 取 5 偏慷慨（40 分钟等价），取 1 玩家无感、广告位空转 |

### 8.1 一句提醒（关于变现杠杆）

若你的目标是**加强变现**，最高杠杆不是调广告次数，而是 `§3.14` 的 `STAMINA_REGEN_MIN` / `STAMINA_MAX`：现在 8 分钟/心 + 上限 8 ⇒ **从 0 回满只要 64 分钟**，体力几乎不稀缺，广告加心的边际价值天然很低。要真正撬动，应把 regen 拉到 20–30 分钟/心、上限降到 5（对标品类常见「2.5 小时回满」）。但那属另一单冻结值变更，本提案**不擅自改**，仅登记为可选方向。
