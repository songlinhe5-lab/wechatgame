## 0. 一句话结论

在当前关卡数据形态（**每格一个字符**的行字符串，ADR-0004）下，「不限制」的**数学上限就是 35**（`1-9` 九枚 + `A-Z` 二十六枚）；故 §3.2 `BEAD_COLOR_MAX` 取 **35 = 该形态下等同「不限制」**，与生成端发符表、studio 输入框三处对齐。「品牌全色板（291/461 色）/ 完全不限制」不是改一个常量能到的，需换 rowstring 编码格式，**本单不覆盖，登记为另案**（§8）。错位侧：`max` 档的实现代价接近于零——**现有构造已经天然达到最大化极值**，要改的只是「不许全错就整盘失败」这条 all-or-nothing 判定（§3.4）。

### 2.2 为什么不是「品牌色板 291/461」，也不是「不设限」

- 用户原话给了两条路（「抬到品牌色板」**或**「干脆不限制」）。两条在当前形态下**都不可直接落**：品牌色板条目数是**候选池**规模（v1.40 后与关卡解耦，`levels.ts:179-183` 只校 `paletteCodes` 长度 ≥ pattern 最大索引、≤ `BEAD_COLOR_MAX`），而 pattern 的**索引**才是被字符集限死的那个量。
- 故 35 不是「保守取值」，是**该形态的天花板**：把 10 抬到 35 = 在不动编码的前提下把上限**去掉**。超过 35 只剩一条路 = 换编码（每格多字符 / 数字数组），即 §8 另案。

## 3. 变更 B：§3.13 新增「最大化错位」档

### 3.1 记号与硬约束（先定域，再谈极值）

- **求解域**：一张 `pattern`（Plate 情形 = **切块后的某一宫**，见 §3.5）。
- `N` = 该域内**可填格数**（`pattern` 非 `.`/`x` 的格）；`c` = 用色数；`m_i` = 第 i 色珠数；`m = max m_i`（主导色）。
- **两条不可破的硬约束**（均为既有 BOOT 契约，本单不放宽任何一条）：
  1. **可填轮廓逐格匹配**：`pattern` 可填 ⟺ `misplaced` 可填（`validateMisplacedGrid` ③）。
  2. **色珠数守恒**：`misplaced` 上每色计数 **== `pattern` 上每色计数**（④）。**守恒是「可解」的唯一依据**，最大化必须在守恒前提下做 ⇒ 「最大化错位」= **在同一多重集内部重排**，不是「把某些格改成别的颜色」。
  - 由此「每格新色 ≠ 原色」自动被表达为：**置换的固定点越少越好**；改色（= 改 `pattern`）不是错位档位能碰的东西。
- 生成阶段**允许**改判格色的只有 `balance()`（`beads-gen.mjs:377-431`），因为它改的是 **`pattern`（目标态）**，与 misplaced 守恒不冲突。⚠️ **关键区分，写进契约**：`pattern` 侧可改判（生成期），`misplaced` 侧不可改色（守恒）。

### 3.2 极值（Hall 型论证）

一色 i 的 `m_i` 颗珠最多只能填进 `N − m_i` 个**别的**格 ⇒ 错位格数 `M ≤ min_i (N − m_i) + (N − m) = 2(N − m)`（非主导珠最多错 `N−m` 格、主导珠最多填 `N−m` 个非己格），并与 `M ≤ N` 取小：

```
M_max = min( N , 2(N − m) )
强制就位格数 F_min = N − M_max = max( 0 , 2m − N )
全错位可行（M_max = N）⇔ m ≤ ⌊N/2⌋        ← 正是 balance()/derange() 现在的前提
```

- `m ≤ N/2` ⇒ `max` **等价于** `full`（不打折）。
- `m > N/2` ⇒ 错位 `2(N−m)` 颗、就位 `2m−N` 颗，**这是守恒下的最好结果**，不是「退让」。

### 3.3 唯一退化情形（仍不可产，且合法关面上不可达）

`M_max = 0 ⇔ N < 2 ∨ m = N`（可填格不足 2，或整盘单色 ⇒ 无任何异色可交换）。

⚠️ **可证：这两条在关卡合法面内不可能同时通过其它 BOOT 门**——`colors.length ≥ 3`（`levels.ts:157`）⇒ `N ≥ 3` 且 `m ≤ N − 2` ⇒ `N − m ≥ 2` ⇒ **`M_max ≥ 4 > 0`**。⇒ `max` 档下**不存在「合法但无解」的关**；`exit(1)` 只可能出现在生成端中间态（`--colors 1`、shape 掩码后 `N<2`），那种输入本来就该失败。**这条是本单最硬的正面结论**：用户要的「别判不可解」在契约上是可证的，不靠兜底。

### 3.4 构造零改动（现有算法已经是最优）

`derange()` / `derangeCell()` 现构造 = **按色排序后整体循环左移 `k = maxFreq`**（`beads-gen.mjs:453-459`、`level-derange.mjs:70-101`）。其固定点数恰为 `max(0, 2m − N)`（区间论证：唯主导色组长 = k，移位 k 必离自身区间；仅回绕可命中 ⇒ 命中数 = `2m − N`），**已手算三例核对**：

| 例（色分布） | `m` | `2m−N` | 实测固定点 | `M_max` |
|---|---|---|---|---|
| N=10，[7,3] | 7 | 4 | 4 | 6 = 2(N−m) ✓ |
| N=9，[5,2,2] | 5 | 1 | 1 | 8 ✓ |
| N=12，[6,3,3] | 6 | 0 | 0 | 12（全错）✓ |

⚠️ **诚实标注**：上表是**文档内推导 + 手算样例**，**未经代码实测**。⇒ 工程侧须以断言复核（判据 X2，§5），不采信本单的手算为「已验」。

⇒ `max` 档的施工实质只有三处：① 删「`maxFreq > ⌊N/2⌋` ⇒ `ok:false`」的 bail；② 把「无固定点」自检换成「固定点数 == `max(0,2m−N)`」；③ 报告/草案携带 `M` 与 `N`（现在只报「错位/不错位」）。**不改排序、不改移位量、不引入新构造。**

### 3.5 与 P2b（Plate 切块）、密度上限、规模闸的关系

- **与 P2b「错豆须在切块后逐宫重排」**：`sliceBoard` 是**纯几何裁剪**且**故意不接 `misplaced`**（`server.mjs:301` 只传 `pattern`），每宫初盘由 `buildCellInitial` 在裁剪后**重新构造**（`level-derange.mjs:149-171`，管线 P2b）。⇒ **`max` 档的 `N`/`m` 一律是「该宫」的量，不是整盘**；每宫各自守恒、各自取极值。⚠️ 已知代价（登记，不回避）：切块后某宫可能主导色极高 ⇒ 该宫 `F = 2m_g − N_g` 很大，观感上「这一宫几乎没错位」；整盘能 full 不代表逐宫能 full。**不得为救观感而跨宫搬珠**（跨宫搬 = 破每宫守恒 = 破可解性）。
- **与宫错位密度 ≤60% 上限**（`levels-spec §10 v1.7`；WXG-T-203 E1 两轮 bot：32×32 **全错位宫结构性不可入关**，176–178 taps）：**`max` 档不放宽这条，也不与它同层**。密度档 = 作者**想要**多少错位（目标），`max` = 够不着 full 时**最多能**给多少（能力上界）。先用密度档定目标，`max` 只在 `full` 不可行时兜底，**两者同时命中时取 `min(目标密度, M_max)`**。
- **与规模闸（`steps × SEC_PER_STEP ≤ LEVEL_TIME_MAX`，≈1479 批量动作 ∧ bot cleared，§3.13 v1.41/v1.50）**：闸**不放宽**。⇒ 新增一条必登记口径：`max` 档让 `M` 成为**可变输出**，所以**报告与草案必须打印 `M`/`N` 并按 `M` 走实测定价**（现 `measuredLevelTime` 已按 `misplaced × 0.8` 估 steps，`level-import.ts:119,142-144`，天然兼容），否则 time 与闸无法追溯。
- **与 `swaps` 型关卡**：`MISPLACED_PAIRS_MIN/MAX`（1/8）继续只管辖 swaps 型；`max` 属 misplaced 型，**不共用该区间**。⚠️ 顺带订正：Plate 的「乙」档（`level-derange.mjs:104-147`）现在把不可 full 的宫**退成 ≤8 对 swaps**——`max` 落地后乙档的**存在理由消失**（它是「all-or-nothing 之下的次优逃生口」），建议**降为 `max` 的次级 fallback 或删除**（未决 Q2，本单不擅删）。

| Q3 | §3.10 C6 冲刺色数预算 | **甲** 随 §3.2 自动抬到 35（高梯级难度失控）／**乙** 另冻 `SPRINT_COLORS_MAX = 10`（保持 v1.36 手感，新常量）／**丙** 挂账待冲刺功能重开（入口现三处隐藏，v1.32 裁定）。**推荐 丙**（冲刺不可达，不值得为它加冻结常量） |
| Q4 | §3 翻转的执行形态 | **甲** 本单（含 §5 施工清单）一次批完再翻值／**乙** 先翻值 + B1 缺口校验（解用户当下的墙），`max` 档第二批／**丙** 只翻值、其余全挂账。**推荐 乙**（B1 必须与翻值同批，`max` 可独立；`--minadj`/a11y 复评进 QA 轨） |
| Q5 | ADR-0004 §5 复评 | 需 **adr-arch** 落正式复评记录；顺带订正 §4.2 现文「色板被字符集硬编码上限锁死在 **16 语义**内」——与冻结真源不符（现 charset = 12 字符，提案后 = 37）。设计轨不写 ADR 本体，本单 §2/§8 即复评输入 |

## 8. 本单不覆盖（边界声明）

1. **>35 色 = 换 rowstring 编码格式，另案**。三条候选（各自都要动 ADR-0004 形态、体积、`sync-levels-data`、cocos 镜像、studio 导出）：**甲** 每格多字符（如 2 字符/格 ⇒ 容量 37²，行宽×2 = 体积翻倍、手工写关可读性崩）／**乙** 数字数组（`[0,3,7,…]` ⇒ JSON 体积 ×2–3，最直白）／**丙** 保留行字符串但**色索引改指向 `paletteCodes` 下标的压缩表**（体积不涨、容量 = 表长，需新增「索引→表位」映射与校验）。**本单不选型**；建议触发条件 = 真出现「一关需要 >35 色」的素材用例（现关表最大 8 色），在那之前 35 不是约束。
2. **不改代码、不改关卡 JSON、不动 cocos 镜像、不写 ADR 本体、不 commit**（任务单约束）。`games/beads/cocos/assets/...` 与 `src` 是同产物镜像（`framework:sync`），本单只在 §5 清单里登记为「随 A 批同步」，未逐文件展开（历史行号会漂，按 `framework:sync` 生成关系处理）。
3. **不做 a11y 设计**：§2.4 只做归因（依赖已搁置裁定），不复活 E4、不发明色盲判据、不提 `--minadj` 新阈值。
4. **不重烤现有关卡**：现 8 关最大 8 色 ⇒ 本变更对已入库内容零扰动（§2.6-③）。
