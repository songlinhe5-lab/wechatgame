## 1. D-01 现象复算

### 1.1 口径与假设（先于表）

供料实现（`tray-spawner.md` §2.2 / `Spawner.tick`）：`_acc` 从 0 累加，**第一次供料发生在 t = `spawnInterval`**，之后等间隔。S4 §8-1「60s / 4.0s → 15 颗」锁定此口径。

| 符号 | 定义 |
|---|---|
| `F` | 可填格（JSON 图案中 `1–8` 字符数；`x` / `.` 不计） |
| `T` | 关卡 `time`（秒） |
| `I` | 关卡 `spawnInterval`（秒） |
| `p` | 有效珠期望比：有 `decoys` 时 `NEEDED_WEIGHT:(NEEDED_WEIGHT+DECOY_WEIGHT)=3:4=0.75`；无杂色时 `p=1`（L7/L8） |
| 供料硬上限 | 每次供料都是可落子色（运气满分）。`t_hard_even = F × I`；`t_hard_imm = (F−1) × I` |
| 3:1 期望 | `t_31_even = (F / p) × I`；`t_31_imm = (F / p − 1) × I` |
| 手速叠加 | levels-spec §5 熟练手 2.5s/珠：`t_hand = max(t_31_even, F × 2.5)`（本表与 3:1 等间隔同值，后四关均仍是供料瓶颈） |
| 星级 | `ratio = remaining / T`；`≥ STAR3_RATIO(0.40) → 3★`；`≥ STAR2_RATIO(0.20) → 2★`；过关即 1★（§3.7 现行值） |
| 玩家 | 匹配珠 **立刻**落子、托盘永不因满槽跳过供料（理论最快；真实局只会更慢） |

**主判决列 = 等间隔 + 3:1 期望**（与实现一致、描述「熟练且运气正常」）。  
**天花板列 = 等间隔硬上限**（理论最高星）。  
「开局第 1 颗立刻」仅作敏感度，**不作为主口径**。

## 2. D-05 处置：`LEVEL_TIME_DEFAULT` 300s vs 竞品 180/209s

| 来源 | 时长 | 玩法瓶颈 |
|---|---|---|
| §3.5 现行 | `LEVEL_TIME_DEFAULT=300s`，关卡可覆盖 ∈[180, 420] | 供料心跳 + 托盘 12 槽 |
| concept §6 / D2 | 「单关恒定 ~5 分钟，与参考图 04:55 对齐」——**用户已拍板** | 同上 |
| 竞品实录（`popit-pindou-gameplay-ui-analysis.md` §5） | L1=180s / L2=209s | **错豆挪移 / 修复**，棋盘开局已有豆，不吃 spawn 硬上限 |

**不可对齐的理由**：

1. 竞品 L1 房子约 13×12，时长 180s——规模接近本作 L8，但玩家从棋盘取豆归位，**零等待供料**。本作 L1 仅 22 格，3:1 期望供料已要 176s；若把默认改成 180s，教学关 3★（须 ≤108s 完成）会立刻数学死亡。
2. JSON L1–L4 已显式写 `time: 300`，改默认常量 **不会**自动改这四关；D-05 真正冲突在「文档叙事 / 竞品对照」，不在运行时这四关。
3. 沉浸打关需要的是「钟够用、星可达」，不是把钟面数字做成竞品皮肤。后四关缺的是 **覆盖值偏紧**，不是默认 300 太大。

**处置（推荐）**：`LEVEL_TIME_DEFAULT` **维持 300s** `[待确认]`。合法区间 [180, 420] 不动。与竞品的差距写进 §6 变更记录作「不同循环、禁止对标秒数」。若用户坚持「开局钟面接近竞品」，那是另一场产品决策（须同时重做 L1–L4 的 `I` / `F`，超出本任务）。

不推荐把默认拉到 180/209：与 D2、与 L1 供料算术、与「减少打断流失」三者同时冲突。

### 3.5 T-B 续时预留口径（四组共用，不设计广告位）

现行星级 `ratio = remaining / T`。若 T-B 把续时加进同一条 `remaining`，**续命后 remaining 变大可直接把 1★ 做成 3★**。禁止。

预留接口（实现属 T-B，本文只锁口径）`[待确认]`：

| 字段 | 语义 |
|---|---|
| `reviveBonusSec` | 本局激励续时累加；HUD 倒计时可显示「钟 + 续时」 |
| `starRemaining` | `max(0, remaining − reviveBonusSec)` —— **星级与 C7 的 `ratio` 都用这个** |
| `revived` | 本局是否用过续时；`true` 时 `stars = min(stars, 2)`（3★ 只给一命局） |
| 扩展行 | 维持 A7：不扣星（与续时正交） |

这样「续时后 remaining 变大」只延长可玩窗口，**不改星、不改 C7 的 ratio 项**。广告意愿由「能继续打完这关」驱动，不由「买 3★」驱动。

**意图**：D6「按剩余时间比例给星」在 L7 这种 `T ≈ F×I` 的关上没有 3★ 带宽。把比较基准从「钟的全长」改成「相对供料硬上限的松弛」。

新口径 `[待确认]`（阈值可沿用 0.40/0.20，语义变了）：

```
parSec          = F × I                         // 等间隔硬上限
slackSec        = max(T − parSec, 1)
paceRatio       = starRemaining / slackSec      // 1.0 = 恰好按 par 清完
baseStars       = paceRatio ≥ STAR3_RATIO → 3
                ≥ STAR2_RATIO → 2
                过关 → 1
stars           = max(1, baseStars − ⌊rejects / 3⌋)   // 每 3 次放错降 1 星
if revived: stars = min(stars, 2)
```

`STAR3_RATIO` / `STAR2_RATIO` 本组 **数值不动** 0.40 / 0.20，但作用对象从 `remaining/T` 换成 `paceRatio`。

L5/L6 3:1 仍 `t > 现行 T`，**换口径不能让珠提前出现**，必须最低限度加时才能期望通关：

| L1 | 300 | 6.0 | 132.0 | 168.0 | 100% | 3★ | 176.0 | 73.8% | 3★ |
| L2 | 300 | 5.5 | 165.0 | 135.0 | 100% | 3★ | 220.0 | 59.3% | 3★ |
| L3 | 300 | 5.0 | 155.0 | 145.0 | 100% | 3★ | 206.7 | 64.4% | 3★ |
| L4 | 300 | 4.5 | 171.0 | 129.0 | 100% | 3★ | 228.0 | 55.8% | 3★ |
| L5 | 280→**320** | 4.0 | 224.0 | 96.0 | 100% | 3★ | 298.7 | 22.2% | **2★** |

失误项：放错无惩罚是 A4 冻结（不扣进度）；本组只在 **结算星** 上扣，不改局内。与「沉浸」兼容，但要改 D6 叙事（星 = 剩余时间比 → 星 = 相对 par 的松弛 − 失误）。

**C7 对账（必须改语义，不能只改 §3.7）**：

- `stars×1000` 仍用上面的 `stars`（已含失误与续命封顶）。
- `round(ratio×1000)` 的 `ratio` **改用 `starRemaining / T`（墙钟占比）**，不要用 `paceRatio`——否则 L7 满运局 `paceRatio=1` 会白送 +1000，与星档叠床架屋。
- 四点采样：星级改测 `paceRatio=0.40/0.399/0.20/0.199`；C7 的 ratio 项仍测墙钟四点。两套点必须在 QA 用例里写清，禁止再「注入一个 ratio 假绿」。
- 档序：最惨 3★=3170 量级仍压过最肥 2★（公式系数未改）。失误降星后 3★ 可能变成 2★，C7 跟随 stars 项 −1000，自洽。

**续时**：`starRemaining` 定义与 §3.5 相同；`paceRatio` 分子也走它，续时无法抬 pace。另保留 `revived → 2★ 封顶`。

**代价**：改 D6、改 S7 §2.2/§8.1、改 QA 双点采样；playtest 前玩家对「为什么只剩 20% 钟却是 3★」会困惑（L7 slack 短，墙钟占比低但 pace 高）。工程与教学成本高于 C。
