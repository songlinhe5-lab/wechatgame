## 3. 三条建议（优先级序）

### P1 · 营业章 = 签到（**信封实装**，用户已裁）

- **位置**：顶栏右上「信箱」位（`MENU_TOPBAR_X.mail = 648`，现禁用空圆）；
- **交互**：点一次开**既有** `signin` overlay（面板语义，零玩法事件）；
- **前置（硬）**：信箱图标切图（B2/B3）——未就绪前保持禁用空圆，⛔ 不自造程序化信封（头注禁令）；
- **验收**：热区注册 + 可达 `signin` overlay；未读态提示 = 至多 1 处「麻绳结」式小标（不铺红点）；
- **为什么排第一**：T-346 已把它列为 P0；零新机制，只补死链。

### P2 · 货架角 = 只读陈列

- **位置**：玻璃窗（橱窗）右下角一小格；
- **内容**：最近 1 件成品缩略 + 「已上架 N」（复用 `drawLevelThumb` 同族缩略能力）；
- **交互**：**零热区**（不注册任何 action）——守住「主钮 + 走马灯卡 = 唯二入口」；
- **验收**：`hitTestMeta` 在该格返回 null；
- **叙事**：通关一件，货架满一分（收集感回流首屏）。

### P3 · 今日订单 = 每日关（暂缓）

- **位置**：木牌板第二行槽位（与 `★ n/门槛` 天然互斥：仅门票未达成时出现）；
- **交互**：小票标签直进今日固定关，1 次交互，扣 1 ❤ 照 §3.14；
- **前置**：`daily-challenge.md` 提案立项 + §3 变更单（新常量/新机制）；
- **红线**：标签面积 ≤ 主钮 1/3，⛔ 不做第二枚大钮、不做红点铺屏、限时只写「本周」不写天数。

### P4 · 装扮馆（皮肤页）入口 —— 用户 2026-10-24 令「接入口 丙，请在主界面上设计入口位置」

- **前提（已核实，非推定）**：买断机制层已落码（WXG-T-360 · 提交 `09adcc7`）= 价目表 `SKIN_PRICES_COINS`（冷紫 150🪙，仍标 `[提案·Q3 待拍板]`）+ 落档事实 `ownedSkinIds` + 四个 API `ownsSkin / skinPrice / buySkin / ensureSkinOwnership`，**当前在源码里零消费者** ⇒ 玩家侧完全不可见（正本 `games/beads/src/game/meta-state.ts`）。皮肤池现 **2 款**（暖纸 = 默认、冷紫），注册序 = 循环序（`games/beads/src/config/skins/registry.ts:41`）；皮肤只换 **UI 令牌族**、珠色基色不入肤（同文件头注 D4）⇒ 页内预览必须画「界面色板样本」，⛔ 不是豆画。
- **硬约束（现网机械钉，改入口必先改它们）**：主菜单可点动作集 = 6 个，被 `games/beads/tests/meta-menu-wall.test.ts:408-423` 以「排序全等 + 16px 全域扫面」双重钉死 ⇒ **任何新增入口必须同批改这两条断言并重抓 menu 金样本**（`tests/ui-golden.test.ts` 的 `proof.screen` 含 menu）。顶栏元件已定档：热区 88（`TOUCH_MIN`）· 视觉圆 Ø80（`MENU_TOPBAR_VISUAL_D`）· 图标 40²（`MENU_TOPBAR_ICON_D`）· 三颗左缘 x `settings 24 / notice 560 / mail 648`（`games/beads/src/config/tuning.ts:143`）· 行顶深 = 胶囊底缘接口换算 + 4（兜底 124，真机逐机 116/137/164/176）。

| 案 | 位置 | 坐标与美术成本 | 首屏焦点影响 | 语义 | 主要代价 |
|---|---|---|---|---|---|
| **P4-甲（推荐）** | 顶栏**内颗** = 现公告预留位（x=560）升格 | 零新坐标推导（该档已在 §5.1b 落位表实测过避让与不互叠）· 元件全复用（白圆底 + 按下纹 + 40² 图标） | 顶栏属「工具/福利」层，不与主钮争焦 | 装扮与签到同层（收集/福利） | **占用公告语义位** + 需一枚皮肤图标 |
| P4-乙 | 顶栏新开**第四颗**（x=472，按 pitch 88 左推一档） | 公告位保留；但 472 档**从未做过背景占比实测** ⇒ 要重出坐标总图 | 右上挤成三颗，读屏成本上升 | 同上 | 视觉拥挤 + 实测欠账 |
| P4-丙 | 橱窗右下「货架角」升格为热区 | 要从 `open-levels` 那块整玻璃热区里切出一小格 ⇒ 橱窗热区几何重排 | **破「主钮 + 走马灯卡 = 唯二入口」**（本文 §0-4 与 P2 的立论基础） | 小铺衣架，语义最贴 | 与 P2「货架角零热区」裁定正面冲突 + 误触风险最高 |
| P4-丁 | 不设主界面钮，入口藏在设置弹窗的皮肤行「装扮馆 →」 | 零主菜单改动、零新美术（走文字纸钮） | 无稀释 | 藏在二级页里 | 发现性最差；且设置内已有免费换肤钮 ⇒ 变成「藏入口 + 旧入口」两不靠 |

- **裁定请求**：采 **P4-甲**。落地形态 = 新动作 `open-skins`；顶栏那颗现在画的是禁用态空圆（α 0.5、喇叭图标暂代、热区不注册，见 `games/beads/src/view/meta-view.ts:393-395` 与 `drawTopbar` 871-888），升格后与左上设置 / 右上信封三者同构同函数腿 ⇒ 零新画法。
- **硬前置（唯一的开工阻塞）**：图标 `ui_icon_skin`（源 80×80 @2x ⇒ 设计 40²）。⛔ 工程侧不自造图标（信封判例：形状归切图规格权威，`meta-view.ts:861` 注释）⇒ **切图未就绪期间该位保持禁用空圆**，入口不可见 = 本提案不闭合。备选 = 授权一枚最小程序化图标（属新画法，需美术裁定）。
- **提示纪律**：该位⛔ 不加红点、不加角标、不闪烁 —— 全局唯一提示位已归签到信封小圆点（`MENU_SIGNIN_DOT_R`，本文 §4「不铺红点」）。买得起 / 买不起只在页内读数体现，首屏不喊。
- **页面形态（丙路线本体）**：`skins` = **modal**（与 signin / settings 同族，复用 `overlayPlate()` 的 600×720 与 `dialogShiftY()` ⇒ 零新几何）；池 >4 款时再升整页（选关页 `levels` 先例）。版面（y 向上，板 x∈[75,675]、y∈[307,1027]）：标题基线 = 板顶 − 50 = 977（与设置标题同规则，字面 40 ⇒ 下缘 957），标题右侧挂 🪙 余额读数（读既有 `v.coins` 投影，⛔ 不造第二条数据通道）；卡区 = 2 卡横排 **248×300**、顶缘 945（净空 12，沿用 [WXG-T-339] 的避让实算口径），每卡上半 120 高 = 色板样本（3 条色带 + 1 颗圆钮样本 + 1 块面板样本，全部读 `skin.tokens` 既有字段 ⇒ 零新 hex）、下半 = 皮肤名（字号守 E1 地板 28）+ 状态行（`使用中` / `已拥有` / `150🪙`）；卡本体 = 热区（点已拥有卡 = 选用，写 `settings.skinId`），未拥有时卡右下「购买」小钮为禁用态 α0.5 但热区仍可命中空响（同 `studio-import` 判例）。返回钮 240×88 @ 板底 + 50 居中（与 signin 完全同形）。
- **入口唯一性待裁（决策点）**：皮肤页上线后，设置弹窗里那颗免费换肤钮 `cycle-skin` 是否退场?本文建议**退场**（装扮的唯一入口 = 皮肤页），对局内暂停面板那颗保留（局内换肤是另一场景）。两种走法都要动 `games/beads/tests/skin-system.test.ts:357` 的动作串白名单（该门现注释「无第四入口」）。
- **工程批次（拍板后才开工）**：B1 ux-spec 回写（`design/ux/ux-spec.md` §2 路由表加 `skins` 行 + §3 新线框节 + §4 输入响应矩阵）→ B2 落码（`open-skins` 热区注册 + `skins` overlay + 买断闭环），同批改 `meta-menu-wall` 两处集合断言 → B3 menu 金样本重抓 → B4 坐标总图重出（`design/ai-workflows/menu-proto-coords.py` 顶栏段，含新钮档）。

## 4. 元素手法（竞品 → 暖纸语言）

| 竞品做法 | 我们怎么改 |
|---|---|
| 居中大卡 + 高光 + 难度角标预览 | 玻璃窗框**不动**，只换玻璃内内容；完成度画成纸上「已拼格/留白格」，不做百分比数字 |
| 紫/黄高饱和飘带标签 | 换**红泥印章**（「今日订单」「新到」）；`danger` 系既有 token，零新 hex；字号守 E1 地板 28，对比 ≥4.5:1 |
| 全入口红点 + 红色 03:56 倒计时 | 全局同时至多 1 处「麻绳结」提示（只给签到）；❤ 未满只加小沙漏符号；**禁红色倒计时与闪烁**（≤3Hz 红线） |

## 5. 风险

- **稀释单主钮**：可点目标 >3 且视觉权重接近 ⇒ 首屏从「点哪」退化成「读什么」。本文三条里两条是只读/复活，今日订单一律小票形态；
- **图标自造风险**：信封切图未到位前若强行程序化，会破坏「零新画法」与切图规格权威——保持禁用空圆是正确稳态；
- **与 T-346 重叠**：签到/金币/每日均已被 T-346 覆盖，本文只补**入口形态与位置**，不重复定义数值。
