## 2. 三项裁定（含裁定 4 = 豁免形态）

### 裁定 A · 豆面实际用色数 [3,35] → [4,16]
- `BEAD_COLOR_MAX` 冻结值 **35 → 16**（语义 = 单关 `pattern` 出现的**不同色索引数**，非候选色板规模）。
- **编码天花板仍 35**：`BEAD_CHARSET=.x1-9A-Z`、色索引 1–35、解码容量全部不变；16 是**设计上单关用色上限**，与编码能力解耦。>16 在设计层违规（BOOT 拒收），**不是** v1.55 意义的「换编码另案」。
- 合法色数区间下限 **3 → 4**（承载在 `levels-spec §2` BOOT 校验面；本 §3 不另立下限常量）。
- **推翻** v1.55「35 = 当前数据形态下不限制」表述：如实登记改判，不静默改史（链：v1.36 ≤10 → v1.55 35 → v2.00 16）。

### 裁定 B · 单图硬顶 GRID_MAX_COLS/ROWS 32 → 64
- 单图导入硬顶 **32 → 64**；**推翻 v1.45（WXG-T-203）「单图上限 32、超 32 切组合图 Plate / `sliceBoard` k=ceil(n/32)」整条语义**。
- 新语义：**玩法无组合图逻辑**，任一维 >64 的关卡 JSON 一律 BOOT 拒收，**不再自动切块**。
- **连带由工程侧落实**（程基岩，`src/**` / `apps/**` 本批零落码）：`config/tuning/board.ts` 的 `GRID_MAX_COLS/ROWS` 32→64、`BEAD_COLOR_MAX` 35→16、`levels-spec §2` BOOT 校验器下限 3→4 + 豁免表、studio `sliceBoard` 切块阈值与 `importBlockers` 镜像同步 64。
- 内容分档（选图指导，非冻结）：16×16 简单 / 32×32 艰难 / >40×40 极难（不建议制作）/ 选图下限 10×10；登记于 `level-difficulty.md §2.1`，**不改 DI 公式本体与 §3.1 系数**。

### 裁定 C · 现池 3 色关 legacy 豁免形态 = **uid 白名单**（本执笔裁定）
- **裁定：按 uid 白名单**，不按 contentVersion 分层。
- 理由：① 豁免对象是**4 个确定的历史 uid**，白名单精确、封闭、可审计，不存在「同一 contentVersion 下新关误获豁免」的风险；② contentVersion 是关卡**结构版本**，用它承载「合法性豁免」会与换盘/重建流程（`--rebuild` 会 contentVersion++）耦合，语义错位、易误放；③ 白名单便于未来逐 uid 收口（改回 [4,16] 时删表项即可）。
- 约束：白名单**只对色数下限 3 放行**，上限 16 与其余所有校验（misplaced 守恒、字符集、尺寸、时限）一律照旧；**新关一律 [4,16]、无豁免**。
- ⛔ **不得给这 4 关升色规避**：`misplaced` 初盘按「每色珠数守恒 + 可填轮廓逐格匹配」构造（levels-spec §2 ④），改 `pattern` 色构成必破守恒 ⇒ 关卡不可解。豁免是唯一安全路径。
- 落码形态由工程侧裁定（建议 io/校验层按 uid 查表），设计真源只钉「白名单 + 仅下限放行 + 不得升色」三条。

## 5. 已知风险与缓解（可玩性/性能一律 `[待真机]`，禁止伪造实测）

1. **29×29 触控不可玩裁定**（用户任务单写作「AIDR-0018」，按仓库真源应为 **`ADR-0018`**，此处按笔误处理并留档）：该裁定**不因本次上限 32→64 而改变**——硬顶 64 只是导入合法性，不是可玩档位；`level-difficulty §2.1` 已明确「合法 ≠ 可玩/建议」。
2. **32×32 超预算在 64×64 下放大**：32×32 = 1024 格静态图元 ≈1.1 万、LOD 待立项；64×64 = 4096 格静态图元 ≈ **4.4 万**，性能压力约 4×。缓解：LOD 仍待立项；`[待真机]` 测 64×64 满载渲染帧率与内存；不得在实测前宣称可玩。
3. **E1 密度闸外推**：「全错位不可入关（须 ≤60% 整区域就位）」结论取证于 32×32（176–178 taps），64×64 下是否仍成立**待 playtest 重测**；内容指导已把 >40×40 标为「极难/不建议制作」作缓冲。
4. **16 色关无实测**：现池最高 6 色；16 色 × ≥608 格（pattern-legibility §2 外推）的可读性、成片错豆构造、可完成性均 `[待 playtest]`。
5. **工程侧同步未完成**：`board.ts` 三常量、BOOT 校验器、studio 切块阈值尚未落码（本批零落码）；在落码前，代码与 §3 处于**已登记漂移**状态，QA 不得据旧值造判据。
6. **无真机/无微信上传权限**（环境事实）：本环境无法验证真机触控、性能、包体；所有 `[待真机]` / `[待 playtest]` 项解除条件 = 具备真机与上传权限后由程基岩（落码）+ 严守真（QA）联合复验。
