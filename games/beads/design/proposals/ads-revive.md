## 1. 激励错配诊断

### 1.1 现行四位挂在哪

`AD_PLACEMENTS=4`（§3.6）= 3 张道具卡超限 + `btn_expand`。S6 §2.6 诚实口径：MVP 角标轻提示，零事件、零槽变化、零扣次、不调用任何 wx 广告 API。S6 尚未实现，四处点击只有「即将开放」。

这四位的**奖励语义全是槽位**：

| 位 | 假设发奖后得到什么 | 缓解的压力 |
|---|---|---|
| `region` / `clearAll` / `random` 超限 | 再清一次托盘珠 | 槽位空间 |
| `btn_expand` | 扩 +`TRAY_EXPAND_SLOTS` | 槽位空间 |

concept 支柱 2 把压力写成「时间 × 空间」。商业位只买了空间那一轴。

### 1.2 真正的死因是时间

S5 / 决策 D7 / §3.5：**失败唯一条件 = 倒计时归零**。托盘满只停供料并告警，不判负（core-loop §8-3）。

因此：

- 玩家被判负的瞬间，要的不是再清 6 槽，而是**再要几十秒把已填图案打完**。
- 失败页现行只有「重试本关」（ux-spec §3.5）→ 五项重置（图案清空、钟回满）。组 C 后单关仍是 ~5 分钟量级；**打断流失发生在「差一点点却必须重来」**，不是发生在「槽满了没广告」。
- 局内四位若在 PLAYING 拉起视频，还会打断沉浸（与「沉浸打关」对冲）；而失败时世界已停，本来就要看面板。

参考作商业化（`popit-pindou-gameplay-ui-analysis.md` §3.3）走的是**体力限流 → 广告补体力**。beads 已定 M5 生命/体力**永不采纳**（meta-framework v1.0）。把「看广告的理由」从体力挪到**失败续时**，才是本品类在无体力前提下的对应物：卖的是「保住这局进度」，不是「买进入资格」。

### 1.3 错配的产品后果

| 若维持四位为主商业位 | 后果 |
|---|---|
| 死因（时间）无挽回 | 失败 = 必重来 → 广告意愿低、打断流失高 |
| 压力源（槽位）可广告 | 玩家未死时被拉去看视频 → 沉浸被砍 |
| 组 C 后一命可通关 | 槽位广告更不是刚需；失败续时才是「差一点」的自愿点 |

**诊断句**：现行 4 位都在卖「槽位不足」；玩家死于「时间不足」。主位必须改挂失败页续时。

## 2. 主位重排（四组布局 + 1 组推荐）

约束：concept D5「激励视频位保留占位」已拍板；§3.6 `AD_PLACEMENTS=4` 已冻结；本提案**不改冻结值**，只给映射方案。S6 未实现 ≠ 可以假装局内广告已接通。

### 方案 A · 失败主位 live + 局内四位休眠（**推荐**）

| 位 | 本轮 | 之后 |
|---|---|---|
| 失败页 +N 秒 | **唯一 live 激励位**（待 ADR-0006 方案 B 真接） | 转化验证后再考虑唤醒局内 |
| 3 道具 `ad_badge` | **休眠**：视觉保留（D5），点击仍轻提示，不拉起 | S6 落地后仍先免费 1 次；超限是否拉起另立项 |
| `btn_expand` | **休眠**：无解锁路径维持 S6 §2.6 诚实口径 | 扩展免费 1 次 vs 广告解锁另拍（原挂起项） |

**理由**：主位对齐死因；局内不打断沉浸；不与未实现的 S6 抢工期；不偷偷改 `AD_PLACEMENTS`。微信侧只有一处「主动点按钮 → 明确 +N 秒」的激励，审核面最小。

代价：局内角标短期仍是「点了没功能」。用文案从「即将开放」改为「本关免费 1 次已用完」（S6 落地后）可减轻残缺感；扩展位保持原提示直到扩展路径拍板。

### 方案 B · 失败主位替换扩展位（4 位重映射）

live：失败续时 + 3 道具超限。扩展行改为**每关 1 次免费**（或 demo 永不可解锁、仅测试钩子——S6 §2.6 原挂起项一并裁）。

代价：PLAYING 中仍有 3 处拉起，沉浸风险高；S6 未实现，本轮仍接不满。拍板后才需要改 §3.6 映射说明（`AD_PLACEMENTS` 仍可以是 4，但 4 的身份变了）。

### 方案 C · 失败主位 + 道具超限作次位、扩展免费

与 B 接近，但明确**转化优先级**：失败页主 CTA；道具超限用小角标、文案「再看一次清槽」，不在 PLAYING 自动弹。扩展免费 1 次，去掉第 4 个局内广告。

代价：live 位变 1+3，审核与实现都比 A 重；须等 S6。适合「失败转化不够、再开次位」的第二阶段，不适合本轮。

### 方案 D · 只留失败页，删局内角标

与 D5「保留占位」、MVP 验收线「三道具均带角标占位」冲突。**不推荐**；仅作对照。

### 推荐

**方案 A**。唤醒局内三位的条件（写入复评，不写进 §3）：失败页续时上线后 playtest 转化仍显著低于预期，且 S6 已实现、框架 `RewardedAdProvider` 已接。在此之前局内四位继续 ADR-0006 方案 A。

## 3. 续时规则完整化（全标 `[待确认]`）

§3.7 已预留、本提案补齐。**任何数字都不是冻结令**；拍板后由主理人走 §6 变更记录再回写 §3。

### 3.1 常量提案（不进 §3）

| 名 | 推荐 | 备选 | 语义 |
|---|---|---|---|
| `REVIVE_BONUS_SEC` | **60** | 45 / 90 | 单次激励成功写入的秒数 |
| `REVIVE_MAX_PER_ATTEMPT` | **1** | 2 | 同一次尝试（从进关或重试起，到下一次五项重置）可成功续时的次数 |

**60 s 怎么来的（推导，非冻结）**：组 C 后一命期望可过关，续时只服务「差一点」。供料仍按关卡 `spawnInterval`：60s 大约等于 L5 约 15 次供料、L8 约 24 次供料；熟练手 ~2.5s/珠则约二十来格的收尾窗。45s 偏紧（L7 间隔 3.0s 时约 15 颗，十格以上收不完）；90s 接近 L8 全长 280s 的 1/3，会诱使「开局混到失败再看广告」——与「意愿点、非被迫点」冲突。

**1 次怎么来的**：失败页续时从 `remaining=0` 起跳，第二次只是把「没打完」再买一轮，把失败面板变成连续剧。1 次足够「救收尾」；用尽后只留重试，避免看三支视频打完 L8。`revived` 布尔与 1 次对齐；若拍 2 次，`reviveBonusSec` 累加、`revived` 仍在第一次成功后置 true。

### 3.2 记账（沿用星级返工 §3.5 接口）

| 字段 | 持有方 | 语义 |
|---|---|---|
| `remaining` | **S5 唯一真源** | 可玩倒计时。续时成功：`remaining += REVIVE_BONUS_SEC`（从 0 起则 `= N`） |
| `reviveBonusSec` | **S5** | 本尝试激励续时累加；初始 0 |
| `starRemaining` | **派生，不另存真源** | `max(0, remaining − reviveBonusSec)` |
| `revived` | **S5** | 本尝试是否至少成功续时 1 次 |
| `reviveCount` | S5（若拍 2 次才需要） | 成功次数；`>= REVIVE_MAX_PER_ATTEMPT` 后不再露出续时钮 |

现行未接续时：`reviveBonusSec=0`、`revived=false`，与 v1.9 / 组 C 行为逐字等价（§3.7 已写）。

**整关重置（S5 §2.4 五项）之外追加第 6 项记账复位** `[待确认]`：`reviveBonusSec=0`、`revived=false`、`reviveCount=0`。重试 / 暂停重玩 / 换关都走它。续时成功**不走**五项重置。

### 3.3 HUD `remaining` vs 星级 `starRemaining`

| 消费者 | 用哪条 | 为什么 |
|---|---|---|
| HUD 倒计时胶囊 | **`remaining`（可玩钟）** | 玩家要知道还能打多久；双钟会认知过载（支柱 1） |
| 告急 `TIMER_URGENT_T` | 同一条 `remaining` | 续时后若 N > 告急阈，告急解除；再降穿再告急 |
| 普通关星级 `ratio` | **`starRemaining / 关卡总时长`** | §3.7 T-B；禁止吃被续时放大的 HUD |
| 冲刺 C7 `ratio` 项 | 普通关结算才有星；冲刺本提案不续时 | 若未来冲刺也续时，C7 必须同样走 `starRemaining`，禁止用 HUD |
| 扩展行 | 不扣星（A7） | 与续时正交 |

**HUD 不显示 `starRemaining`。** 可选「续时」芯片（倒计时胶囊旁小标，热区不另占）`[待确认]`：仅 `revived==true` 时出现，三重编码用图标+文字「续时」，不单靠颜色。结算页可一行「本关使用了续时 · 最高 2★」——失败后打完往往 `starRemaining=0` → 1★，芯片防止「钟上还有 40 秒怎么只有 1★」的客诉。

**从 0 续时的算术（推荐路径）**：

```
死亡瞬间     remaining = 0, reviveBonusSec = 0, starRemaining = 0
onRewarded   remaining = 60, reviveBonusSec = 60, revived = true
             starRemaining = max(0, 60−60) = 0
收尾后过关   remaining 若残 40s → starRemaining = max(0, 40−60) = 0
             ratio = 0 → 1★；revived 封顶 min(1, 2) = 1★
```

若误用 HUD `remaining` 算星：残 40s / 300s ≈ 13% ≥ `STAR2_RATIO` → **2★，等于买星**。T-B 预留就是为堵这道门。

**2★ 封顶仍要**：失败页从 0 起跳时封顶通常不绑（分子已是 0）。它是（1）3★ 只给一命局的产品句；（2）万一将来加「未归零加时」或实现把 `remaining` 写成「回满一段」时的保险。`stars = min(computed, revived ? 2 : 3)`，3★ 阈值本身不改（仍引用 §3.7）。

### 3.4 失败面板动线（续打 ≠ 重试）

```
PLAYING  remaining 钳 0
  → S1 GAME_OVER，发 level:failed
  → 失败面板（世界停：非 PLAYING，S5 不计时，S4 不供料）
       ├─ 点「重试本关」
       │    → 五项重置 + 续时记账清零 → PLAYING（新尝试）
       ├─ 点「看视频 +N 秒继续本关」且本尝试未达次数上限
       │    → 玩家主动 show 激励视频（见 §3.6）
       │         ├─ onRewarded（看完）→ remaining += N；记账；关面板
       │         │    → S1 GAME_OVER → PLAYING（同一尝试，不重置）
       │         ├─ 中途关 / onError / 加载失败 → 不发奖，留在失败面板
       │         └─ 禁止：未看完当成功
       └─ 已用尽续时次数 → 不渲染续时主钮（或置灰+「本关已续时」）
            只留重试；零自动拉起
```

**续打保留**：网格 filled、托盘槽、选中、扩展态、道具免费次数、供料累加器、冲刺外的一切局内进度。只改 S5 的钟与续时记账。

**重试清掉**：S5 §2.4 五项 + 续时记账。

L1 是否隐藏续时 `[待确认，推荐不隐藏]`：续时是主动按钮，不是插屏；L1 组 C 后极少失败。隐藏会少一条审核面，但规则不统一。

### 3.5 与 S6「不加时、不冻结」纪律共存

S6 §2.3 / §7 硬边界：**道具不改时间——不加时、不冻结、不延表；倒计时唯一真源仍是 S5。**

本提案把这句话收成职责表，而不是开例外：

| 动作 | 谁做 | 谁不做 |
|---|---|---|
| 累加 / 暂停累计 dt | S5（仅 PLAYING 累计；GAME_OVER / PAUSED 不计） | S6 永不写 `remaining` |
| 加时（续时） | **仅 S5**，且仅激励 `onRewarded` 成功之后 | S6 三道具与扩展位永不加时 |
| 「看视频时世界停」 | 失败页：已在 GAME_OVER，本来就停 | 不是 S6 冻表 |
| 将来局内广告若唤醒 | 先走 S9 `game:paused`（与齿轮同通道），回来再 `resumed` | 仍禁止 S6 私自冻表或加时 |
| 超限清槽发奖 | S6 只在 `onRewarded` 后发 `powerup:used`（未来） | 与钟无关 |

**「续时是 S5 的唯一任务」**：加时通道唯一；失败续时不是第 4 个道具，不进 `POWERUP_TYPES`，不占 `POWERUP_BAND`，不消耗 `POWERUP_FREE_USES`。

S6 未实现的本轮：局内四位继续占位；工程不得借「续时任务」提前写道具广告拉起。

### 3.6 微信激励三条（失败页怎么满足）

| 审核要求 | 本方案落点 |
|---|---|
| 玩家**主动**触发 | 只响应失败面板按钮；零自动弹、零倒计时结束插屏、零切后台回来弹 |
| 奖励明确 | 按钮文案写死「+N 秒继续本关」（N 用拍板值）；禁止只写「看视频」 |
| 不强制观看 | 「重试本关」始终可点、热区 ≥ `TOUCH_MIN`、不藏在视频后面、不看也能重开关 |
| 未看完不发奖 | 仅 `onRewarded` 改钟；`onClose` 未奖励 / `onError` / 加载失败 → 零加时，面板不关 |

框架未接广告 API 期间：按钮可渲染，点击走与今日角标相同的轻提示（「即将开放」），**零 `wx` 调用**——与 ADR-0006 方案 A 一致。真接之前本条只约束文案与动线，不冒充已接入。

### 3.7 冲刺 / 其它边界

- **冲刺模式不续时** `[待确认，推荐]`：冲刺结束唯一原因 = 倒计时归零（score-combo §2.1）；续时会直接抬分。失败/结束走既有「再来一局 / 返回关卡」。
- 归零与最后一格同帧：仍 **cleared 优先**（S5 §6）。cleared 则根本不进失败面板，无续时。
- `onHide` 杀进程：续时记账若要进崩溃快照，归 T-055 提案字段，本篇不扩 S8。未拍快照前，杀进程 = 丢局内态（含未结算的续时尝试）。

## 4. UX 线框（失败面板）

设计分辨率 750×1334，y 向上，热区 ≥ `TOUCH_MIN`（88px）。遮罩与入出场沿用 ux-spec §3.3 / §5：遮罩 `rgba(42,46,67,0.5)`，面板入 200ms ease-out / 出 150ms ease-in。失败提示保持温和（非红闪、无屏震）——支柱 1。

### 4.1 现行（对照，ux-spec §3.5）

```
╔══════════════════════╗
║    ⏰ 时间到           ║
║  （温和提示，非红闪）    ║
║  ┌────────────────┐  ║
║  │   重试本关       │  ║  ← 唯一行动
║  └────────────────┘  ║
╚══════════════════════╝
```

### 4.2 推荐稿（方案 A：续时主钮 + 重试不抢、不强制）

主钮视觉更重（转化），**重试永不缺席、永不看视频才能点**——对齐 U1「副按钮不抢下一关」的反题：这里商业钮可以更大，但重试必须是完整热区，不能做成 12px 灰字。

```
╔══════════ 560×520 panel_dialog ══════════╗  垂直居中于 PUZZLE_BAND
║              ⏰ 时间到                    ║  text_primary，非 danger 闪
║         （温和提示，非红闪）               ║
║                                          ║
║      图案进度  ████████░░  还可续打        ║  可选；用 filled/可填格，不新造 §3
║                                          ║
║   ┌──────────────────────────────────┐   ║
║   │  ▶  +60秒 继续本关                 │   ║  主钮 480×88，绿胶囊
║   │     看完视频后从当前进度续打         │   ║  奖励一行写清；图标+文字
║   └──────────────────────────────────┘   ║
║                                          ║
║            重试本关                       ║  次钮 480×88 透明描边
║         （倒计时回满，图案清空）            ║  热区满 88；不看广告也可点
╚══════════════════════════════════════════╝
```

已用尽续时（`reviveCount` 达上限）时**不渲染**主钮，退回现行单钮，避免置灰主钮制造「你必须看广告」的残影：


## 7. 沉淀候选（0–3，交主理人汇编；ID 由 `kb:sync` 分配）

- **[流程] 激励视频主位应对齐「死因」而非「压力源」**（来源 WXG-T-057）  
  现象：beads 四处 `ad_badge` 全挂道具/扩槽，失败页只有重试。  
  根因：失败唯一条件是倒计时归零（槽满不判负），广告却买空间轴。  
  规避/做法：先挂「能挽回死亡」的主动激励（失败续时）；局内压力位可休眠到转化验证之后。

- **[流程] 续时加的是 HUD 钟，星级必须走扣掉 bonus 的分子**（来源 WXG-T-057 / T-B）  
  现象：若 `ratio = remaining/T` 且 `remaining` 含续时，残秒可把 1★ 做成 2★/3★。  
  根因：可玩钟与成就钟被合成一条。  
  规避/做法：HUD 用 `remaining`；星级与 C7 用 `starRemaining = remaining − reviveBonusSec`；续命局再 `min(*, 2)`。

- **[平台微信] 失败续时三条写进按钮，比 PLAYING 中拉起好过审**（来源 WXG-T-057）  
  现象：局内超限清槽要在 PLAYING 切出看视频，易被看成打断；失败时世界已停。  
  根因：激励政策要求主动触发、奖励明确、不强制、未看完不发奖。  
  规避/做法：只在失败面板用「+N 秒继续本关」主钮 + 始终可点的重试；`onRewarded` 才加时；未接 SDK 时零 `wx` 调用。
