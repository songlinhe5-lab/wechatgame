## 1. 我的理解复述（自然语言，先对齐再提问）

- 一张「**图**」= 一幅完整的**拼豆画作**（例如一只小猫、一枚徽章），它**不是一关**，而是**一组成品**。
- 每张图被切成 **3×3（9 宫格）** 或 **4×4（16 宫格）** 的**子拼图版面**；**每个子版面 = 一个可玩的拼豆关卡**（一张由不同颜色拼豆铺成的小盘面）。
- 玩家在子版面上完成一局 → 该格**点亮/落位**；**全部子版面完成 → 整图完成**；整图完成后**收入图鉴**（可回看、可展示收集进度）。
- 于是三层对象浮现：**图鉴（Album）→ 整图（Plate）→ 子版面（Cell-Level）**。这三层的**命名与数据归属尚未裁定**（§5），本文只借词指代。
- **尖锐的不确定点（不自我解答）**：子版面「完成」的定义**是否就是现有的「错位归位」核心循环**（满盘错位 → 取回 → 归位 → 可填格全满）？如果是，本提案主要是「内容组织 + 盘面扩容 + 元游戏页族」问题；如果不是（例如改成「看图填色」「自由填色不限制」「限时填色」），那是在**给游戏加第二个玩法内核**——它会冲击 `concept.md` **支柱 3「复刻优先，不加戏」**与**决策 D1「忠实复刻参考玩法，不做创新变体」**，也冲击 §7 Won't 里明写的「玩法创新变体」。**这是必须先裁的一条，本文按用户要求不自答。**

```
图鉴 Album（S10 页族内的一页，入口 = Q4）
  └─ 整图 Plate（一幅拼豆画作；宫格数 3×3 或 4×4 = Q1/Q2/Q3）
       └─ 子版面 Cell-Level（一个盘面关卡；尺寸 = Q3，玩法内核 = Q1）
            · 完成态 → 该格落位 → 全部落位 → 整图完成 → 收入图鉴（Q5）
```

## 4. 与缩放/相机的耦合点（只从设计角度标约束，**不重述 `ADR-0015`**）

1. **盘面尺寸的天花板是几何的，不是设计的**：`§3.3` 两行注释自证（13×52−2 ≤ 可用宽 690；12×52−2 ≤ `PUZZLE_BAND` 高 640）。⇒ **不解锁缩放，任何扩容都只能靠「把珠子画小」**，而珠子一画小就同时撞两样东西：`TOUCH_MIN=88` 的无障碍底线（棋盘已按 §3.8 例外降到 66²，无第二次例外可降），以及用户批评的**「看不清连续同色」**。→ 结论：**Q3/Q6 在缩放落地前不可能被好好回答**。
2. **「连续珠子」与「缩放」是同一枚硬币的两面**：密度上升 ⇒ 单珠视宽下降 ⇒ 必须能**放大局部**才点得准 ⇒ 又必须能**平移**才看得全。这就是为什么用户把它写成「需要在缩放以后，统一设计功能和架构」——**不是排期偏好，是依赖顺序**。
3. **Q2 决定相机的需求形态（设计侧后果）**：「同时可见 9/16 格」意味着**一屏 N 个独立可放大版面**，现有单相机方案的前提（一份相机配一张网格）在此形态下失效；「顺序解锁 / 点格放大」则退化成**单格内缩放**，现有方案够用。⇒ 本文只登记这条耦合，**不替工程裁**（复评触发条件见 `ADR-0015` §5-3）。
4. **扩容会把已验过的判据面重新打开**：`input-control §8-2/§8-4`（外扩重叠 + 最近格心）用例规模随格数增长；`bead-grid` 组选（8 向连通块）在大盘面上的搜索面积与观感同步变化；HUD/托盘/面板**不缩放**（用户已裁）⇒ 大盘面只放大玩法区需求，托盘容量与 k 的关系要一并重议（→ Q10）。**增量数字本文一律不估**（K-051：纸面推论须落码后差分复算）。
