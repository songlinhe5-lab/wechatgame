### 0.2 三域换算关系表 + 单一真源声明

```
[物理域] 5mm 豆径
   ↕ M1  成品边长(cm) = 格数 × 豆径(mm) ÷ 10        ← 真源：density-tiers §0.3/§1.2①
[格数域] cols × rows                                   ← 具式实测两处：beads-gen.mjs:1393-1396 + index.html:411
   ↕ M2  源图 px = 格数 × 32（最低 25）                ← 真源：levels-spec §3.1①（仅源图/做图域）
[源图域] PNG ≤ 4096²，每格 8×8 采样（= 每采样点 4 源像素）
   ⊥  ——（M2 与 M3 之间不存在换算，32=32 是数值巧合而非桥）——
[渲染域] 屏上 pitch = BEAD_PITCH × zoom，zoom ∈ [fit, fit×SPAN]   ← 真源：§3.3 + ADR-0015 丁-3
```

### 0.4 【P1 新发现】32 挂 `BEAD_CELL` 还是 `BEAD_PITCH`？—— 语义分叉，IMPACT 未列

「5mm ↔ 32」按实物读法存在歧义：真实拼豆板上 **peg 中心距 = 5mm**（豆坐在 peg 上，豆间几乎无缝），故「一颗 5mm 豆占 32」若取**格距**语义，应挂 `BEAD_PITCH = 32`；而 `ADR-0018 §3.4` 的槽位挂在 **`BEAD_CELL`（50）**。「1 格 = 5mm」与「珠径 = 5mm」在实物上近似同一，但在有 `BEAD_GAP` 的渲染模型里**不同一**。三条路的算术差异（`复算`，脚本见 §8）：

| 口径 | CELL / GAP / PITCH | zoom=1 顶格容纳 | HIT/PITCH | 与 `§3.3` 现结构 | 与 ADR-0018 槽位 |
|---|---|---|---|---|---|
| **乙-1**（改动最小，**本单默认建议**） | 32 / 2 / **34** | 20 列 / 17 行 | 66→**1.941**；48→1.412 | 只换数字，`PITCH = CELL+GAP` 公式不破 | 槽位在 CELL，逐字对齐 |
| 乙-2 | 32 / 1 / **33** | 21 / 17 | 66→2.000；48→1.455 | 同上（GAP 需另裁 = W2） | 同上 |
| 乙-3（字面「5mm = 一格」） | 32 / **0** / **32** | 21 / 18 | 66→2.063；48→1.500 | ⚠️ `GAP=0` ⇒ `BEAD_PITCH = BEAD_CELL + BEAD_GAP` 退化，缝宽全由 `inset` 承担，**破 §3.3 定义结构** | 槽位从 CELL 移到 PITCH，ADR-0018 处置面变大 |

⇒ **P1 必须用户先拍**（§6 第 2 条）。本件后续各节以 **乙-1（32/2/34）** 为算例基准，并在每处标注乙-3 的差异。

### 0.5 【P2 新发现】32 基下「等比参照」在常见手机上**不成立**，须真机量证

`ADR-0018` 当年选 50 的隐含算术（复算）：设计空间宽 750 ÷ `BEAD_CELL` 50 × 5 mm = **75.0 mm** —— 恰在一部手机可视宽度量级内，所以「zoom=1 = 实物等比」当时读起来可信。改成 32 基后：750 ÷ 32 × 5 = **117.2 mm**（乙-1 的 34 基 = 110.3 mm），**超出常见手机屏宽近 1.5 倍**。

- **结论（诚实）**：32 基能成立，但它的身份只能是「**命名基准 + 全部绝对阈值的搬家尺**」，不再是「屏上 = 实物比例」的自证。`ADR-0018 §3.4.1` 那句「zoom=1 呈现 5mm 真实比例」在 32 基下**按字面为假**，必须改写（§3.2 处置第 2 行）。
- **真·等比自证法**（交下游，本件不执行）：读 `viewport.fit.scale` → 设计 px→CSS px → 设备 ppi → mm，与实物卡尺量得的珠径比对。本环境无设备 ⇒ **`[需 真机]`**，不得据「应然」判绿（K-035 / K-040）。

### 0.6 【P3 新发现】小中盘在 32 基下**视觉上会变小**，除非同时推翻第二条 ADR-0018 条款

`computeFitZoom` 的 `Math.min(1, …)`（`board-camera.ts:92`）使「顶格带」内的盘恒为 zoom=1。两基顶格带与珠体（`复算`，固定 `BOARD_FIT_MARGIN=24`）：

| 盘面 | 52 基 fit / 珠体(设计px) / 占屏宽 | 34 基 fit / 珠体 / 占屏宽 |
|---|---|---|
| 6×5 | 1 / **38.0** / 41.3% | 1 / **20.0** / 26.9% |
| 13×12（旧顶格边界） | 0.9518 / 35.6 / 85.5% | 1 / 20.0 / 58.7% |
| **14×14（现关表最大）** | 0.8154 / **28.8** / 78.9% | **1** / **20.0** / **63.2%** |
| 14×18 / 18×18 | 0.6338 / **19.7** / 61.4% / 78.9% | 0.9705 / **19.1** / 61.3% / 78.9% |
| 29×29 / 32×32 | 0.3931 / 7.7 · 0.3562 / 5.8 | 0.6016 / 7.3 · 0.5451 / 5.4 |

两条结论：

1. **大盘（fit 档）几乎不变**（19.7 → 19.1），因为 `fit` 会自适应 —— 印证 `IMPACT-0020a §4.1`「改尺子不改变观感大小」。
2. **小到中盘显著变小**：52 基顶格带 = ≤13 列∧≤11 行，34 基扩到 ≤20 列∧≤17 行 ⇒ **现关表最大 14×14 从 fit 档掉进顶格档**，珠体 −30%（28.8→20）、盘面占屏 78.9%→63.2%。**观感判定 `[需 art/真机]`，本件不判。**

### 2.1 `BEAD_LOD_CELL = 45`（= 0.9×50）→ **[待 林绘澄 + 真机]**

- 现值 45 是「zoom 0.9 时的珠屏幕径」的**绝对快照**（`tuning.ts:840-844`；语义源 `ADR-0017 §3` 建议档「满层 zoom ≥ 0.9」）。32 基下保 45 ⇒ `45 > CELL=32`，**任何 zoom 下 `cell` 永不低于 45 于 fit=1 档**（`nextBeadLod` 判 `layout.cell < 45`）⇒ **默认视角恒降档**，且触发需 zoom 1.406 才回到满层，而顶格 = 1 ⇒ **结构性不可达**（`IMPACT §4.2`，复算 `45/32 = 1.406` 同意）。
- **建议（比例式，非数值）**：`BEAD_LOD_CELL = 0.9 × BEAD_CELL` ⇒ 32 基给 **28.8 ≈ 29**，与母值共命运（同 `IMPACT §7.2-1` 的守卫方向）。`BEAD_LOD_HYST = 2.5` 同理：52 基 = 母值 5.0% 带宽，32 基 = **7.8%** ⇒ 若意图是「5% 死区」则需 ≈**1.6**；若意图是「2.5 设计px」则不动。**意图未在册文档中写明**，须 art 裁定。
- 满层可见盘边界：`fit ≥ 0.9` 反解 ⇒ 52 基约 ≤12×11、34 基约 ≤**17×17**（`复算`）。**恒降档是否可接受、降档观感、以及 ADR-0017 一直欠的真机 FPS** ⇒ **`[需 art/真机]`**（`ADR-0017:4` 自陈「真机 FPS 未验」）。
- 红线不变（不受本单管辖，仅重申）：**L11 目标色垫与 L5 符号任何档不砍**（`ADR-0017 §1.4`）；`IMPACT L4` 提到的层集记号 `B0+B1+L1c` 是**新模型层名**，与 ADR-0017 旧十层卡层名并存 —— 属 art 域命名，本单不裁。
