## 2. 视觉语言（与我方现有方案的差异）

1. **底色与面板**：整体淡紫灰底 + 白面板 —— 与我方 v1.3 丙案「冷紫灰 `#ECEAF3` + 白板」**同族**，方向一致。
2. **文字**：关卡标题用**淡紫低对比**（估对比度 <2.5:1），我方已改用深藏青 `#2A2E43` + `text_secondary #6E7288`（4.74:1）⇒ **我方更优，不照抄**。
3. **珠子形态**：圆角方块（半径≈边长 20%）、顶亮底暗、底缘深色内缘线；**表面另有细密点状纹理**（同色相深浅点阵，像素级放大图 08 可见）`[待确认：程序化点阵 or 贴图]`。我方 v1.5 十层卡（倒角 + rim 光 + 三层软高光）**方向相同但更"糖果"**，参考的更"塑料/磨砂"。
4. **★ 空槽 = 目标色「淡色垫」（本次最重要的发现）**：
   - 空槽**不是纯白**，而是**目标色的浅淡版本**：湖蓝目标 → 淡青槽（帧 02/03 满屏淡青空槽）；奶白目标 → 近白槽（帧 08 猫脸白色区域）。
   - 更关键：**已放珠的格子周围同样能看到该格淡色垫的边**（珠与垫之间约 1px 的淡色缝，像素级放大图 08 中绿色珠之间的淡黄绿细线、粉珠周围的淡粉晕）。
   - ⇒ **参考游戏把「目标色」作为每一格始终可见的底色垫**，玩家靠「**珠色 vs 周围淡色**」判断是否放对。**这正是用户 2026-09-17 提出的问题（WXG-T-140 裁定 (b) 要解决的事）**，参考用的是「**垫色显缝**」路线，而非我方落盘的「**珠上描 2px 环**」路线。详 §6。
5. **非图案区**：直接露出背景色（不画格子），**未见我方设计的 X 纹「锁定格」**。
6. **完成态**：通关后棋盘显示**完整成品图案**（珠画本体），随即弹出结算。

## 5. 值得借鉴的（按优先级）

### 5.1 ★ 目标色垫的「始终可见」原则（最高优先，直接关联 L11）
参考游戏把目标色做成**长期垫色**，而不是「只在空槽显示」。我方 v1.22 之后 `filled` 格底色零露出是本次用户质疑的根源。**建议把 L11 的实现从"描边环"改为"垫色显缝"**（详见 §6 的 B′）。

### 5.2 结算屏「成品展示」仪式
参考：全屏 scrim + 缎带 + **白色面板展示玩家刚拼出的图案** + 金币 + 三按钮。我方结算目前是星级弹窗，**情绪峰值不足**。建议与我方 Q3-A（完成动画）+ Q3-B（收藏册）合并为「**作品展示面板**」：面板内放 renderModel 快照（我方已有 `buildRenderModel()`，**零新资产**），缎带用程序化图形。

### 5.3 托盘扩展按钮的**形态**
参考把「增加 2 行」做成**叠压在托盘下缘的胶囊**（▶ + 文案），非常聚焦。我方设计是「虚线行 + 按钮」，可保留虚线行（表达"未解锁容量"）**但把按钮做成同款叠压胶囊**，视觉更省空间。

### 5.4 道具的「圆盘 + 绿色 + 徽章」统一语汇
参考 3 枚道具形态语言完全一致（圆盘 + 描边 + 投影 + 右上绿 + 徽章），我方 §1.4 是卡片形态 + 深藏青角标。**建议保留我方卡片（信息量更大）但统一"可补次"徽章为绿色 +**，与「看视频补次」的语义绑定成一致语汇。

### 5.5 HUD 右上「重开 / 更多」双胶囊
参考在右上固定了「撤销·重开」+「•••（含暂停）」。我方 v1.23 HUD 只有齿轮 + 计时，**重开入口位置缺失**（ux-spec 需补），可直接采用该布局。

### 5.6 开场揭示动画
参考开场有「非图案珠飞离 → 图案成型」的 1–2 秒仪式。我方 v1.22 满盘错位开局**无仪式**，玩家第一眼看到的是"一坨错位珠"。建议加一个**1.5s 开场揭示**（错位珠轻微脉冲 / 目标色垫依次点亮），零玩法语义、纯表现层。

## 6. 与本轮 L11 裁定（WXG-T-140）的关系 —— 关键结论

**结论：参考录像印证了裁定的方向（目标色必须可见），但给出了一条更优的实现载体。**

| | 已落盘 L11（方案 b：描边环） | 建议变体 **B′（垫色显缝）** |
|---|---|---|
| 做法 | 每颗棋盘珠沿格缘描 `2px` 环，ink = `mix(pattern,#000,0.30)` | 把该格**淡色垫**（目标色浅版，即现有 `empty` 坑 S1/S2 的淡色同族）画在珠下，**露出格缝**（我方 `BEAD` 50 vs `pitch` 52 ⇒ 缝 2px 本就存在） |
| 视觉 | 156 条描边环，噪声偏高；环是"线"，易被读作独立物体 | 连续淡色带，噪声低；垫是"面"，与 `empty` 态语言同源，空/实过渡自然 |
| 与 §1.9.4「must not read as a bead」 | **对偶轻微打架**（已登记为已接受副作用） | **不打架**（垫是平面、无投影无高光） |
| 图元 | +1 层/格 ⇒ +156（基线 ④ 1828） | **同价** +1 层/格 ⇒ +156（**基线数字不变**） |
| 与参考录像的一致性 | 语义一致、载体不同 | **语义与载体都一致** |
| 实现门槛 | `tuning.ts` 加环宽常量 + view-model 需拿到 filled 格 pattern 色 | 同左（仍需 pattern 色），但可复用 `empty` 坑已有的垫色计算路径 |

**建议**：**L11 的语义名与 (b) 裁定不变**，把**实现载体改为 B′**（属实现选择、非重新裁定）；若用户希望保守，保持已落盘的描边环亦可（两者图元同价，切换成本集中在渲染层一处）。
**待确认项**：`view-model` 对 `filled` 格是否携带 `pattern colorIdx`（`empty` 侧已消费同值 ⇒ 源应存在）—— 两方案共同前置。

> 方法：scene 检测取 18 个切换点 → 22 张全景 + 8 组像素级裁切（neighbor 放大 10–16×）+ **raw RGB24 逐像素 run-length 扫描**

## 10.1 分辨率与屏幕（修正 §0 / §1）

- 1284×2778 = **iPhone Pro Max 档 @3x** ⇒ **逻辑分辨率 428×926 pt**。上一版按 220×480 归一化，**结论方向不变，绝对尺寸需按 3× 重标**。
- 实测尺寸：**珠子 ≈ 44px ≈ 14.7pt** ｜ **格距 ≈ 64px ≈ 21.3pt** ｜ **缝宽 ≈ 20px ≈ 6.7pt（≈ 1/3 格）**。上一版"单珠约 9×9 像素"作废。
- 120fps 录屏 ⇒ 动作可抽到亚帧级，缎带/淡出等动画过程可逐帧拆解（10.6 / 10.7）。

## 10.2 ★★★ 谜面可读性的行业答案（本节最重要，直接决定 B′ 是否采信）

逐像素取证（帧 `01` / `02`）：

| 取证位置 | 珠色 | 该格露出的「垫色」 | 判定 |
|---|---|---|---|
| 图案内绿珠区 | 黄绿 `#9BD84A` | **黄绿垫 `#E8EC78`** | **同色系 ⇒ 正确** |
| 图案内粉珠 | 粉 `#F0A8C0` | **米白垫 `#F5F0E8`** | 异色系 ⇒ **错位** |
| 图案内绿珠（另一格） | 黄绿 | **米白垫** | 异色系 ⇒ **错位** |
| 红区黄珠 | 金黄 `#F5D24E` | **珊瑚红垫 `#FF776E`** | 异色系 ⇒ **错位** |
| 白走廊青珠 | 青 `#7FD4E8` | **米白垫 `#EDE9E1`** | 异色系 ⇒ **错位** |

**三条结论（全部实证）**：

1. **每格铺「目标色垫」** = 该格目标色的**浅版**；**铺满整格、平底、无锥面、无描边**；
2. **珠子比格子小（≈2/3 格）**，放在垫上 ⇒ **四周露出约 1/3 格的垫色**；
3. **判据 = 珠色与垫色同色系 ⇒ 正确；异色系 ⇒ 错位。** 玩家**不需要记住图案**，只需比对「珠 vs 垫」。

**对 WXG-T-140 裁定的意义**：

- 上一版提出的 **B′（垫色显缝）获得行业实证** —— 参考游戏用的正是这条路，而非"在珠上描边"。
- 我方 (b) 是「珠上描 2px 环」，与行业做法**唯一差异在载体**：参考是"**铺满整格的色垫**"，我方是"**珠缘描边环**"。
- B′ 在**图元同价（+156）**前提下更优：噪声更低、与 `empty` 凹坑语言同源、不触碰「must not read as a bead」的对偶。
- ⇒ **建议采信 B′ 实现，替换 (b) 的描边环载体**（**语义不变，仅换实现**）。仍待用户拍板。

## 10.3 珠子造型（细化 §2）

- **造型 = 圆角方块 + 中央四棱锥**（"方钻"）：四条对角线自中心射向四角，锥面**上亮下暗**。
- **描边 = 深色同色系**（≈3px @3x ≈ 1pt），**不是黑描边**。
- 圆角半径 ≈ 珠边 × 0.22。
- **垫（目标色）无描边、无锥面** —— "立体珠 / 平面垫"的对照本身就是空与实的语义载体（与我方 `assets-spec §1.9.4` 同思路）。上一版"点状纹理"判断**作废**（见 §8 表第 4 项）。

## 10.4 托盘（**重大修正 §1 / §5.3**）

- **实为 3 实线行 + 1 虚线行 × 8 列** = **24 实槽 + 8 扩展槽**。上一版"3 行 × 11 列 ≈ 33 槽"作废。
- **空槽 = "素坯拼豆"造型**（米白圆角方块 + 描边 + 锥面），**不是凹坑** —— 托盘用"一颗未染色的珠子"表示空位。
  - 与我方"凹坑"路线是两种语言：素坯更直观（一眼是槽位）；凹坑与棋盘空槽同源、更"坑"。**二选一，属美术决策**。
- **托盘珠按色批量发放**（新发现，§3 未记）：

  | 时刻 | 托盘状态 |
  |---|---|
  | 第 3 关 t=8 / t=12 | **全空**（全素坯） |
  | 第 3 关 t=182 | 第 1 行 10 颗 + 第 2 行 5 颗，**全为黄珠**（单一颜色） |
  | 第 4 关 t=118 | **全空** |
  | 第 4 关 t=120 起 | **3 行 × 8 列全是深棕珠**（24 颗，单一颜色） |

  ⇒ **托盘一次只提供一种颜色**（推测 = 当前关卡"还没拼完的颜色"）。这是**降负/防错**设计。
  ⚠ **与我方 v1.23 语义冲突**：我方托盘 = "取回的错位珠暂存区"（颜色天然杂乱）；参考 = "按色发放的供给源"。**不照抄** —— 会把环谜题拆成"按色填空"。
