## 0. 阅读口径

### 0.1 符号

| 符号 | 含义 | 出处 |
|---|---|---|
| **mask** | 系数图：**R = d（暗系数）/ G = l（亮系数）/ B = 形状 / A = 255** | 定稿 py 头注 |
| **d / l** | 封闭解：暗端 `base·d`（`d = 1−k`）、亮端 `base + l(1−base)`（`l = k`）；`k` = 墨档（`mix(base, ·, k)`） | ADR-0028 §2.1 |
| **合成式** | `out = base·d + (1−base)·l`，逐通道仿射 ⇒ **亮度线性**：**`L_out = (d−l)·L_base + l`** | 本单推导（见 §5.1） |
| **kind** | `bead`（珠面）/ `cell`（格面 = 空槽凹槽 + 格外） | 方案件 §0.2 |
| **gauge** | `holed`（满豆档，珠面 **26**dp）/ `holeless`（小豆档，珠面 **24**dp） | `cell-standard-holed/holeless` |
| **`m = d−l`** | 本单引入的**明度斜率**指标：色间亮度差被压缩的系数（`ΔL_out = m·ΔL_base`） | 本单 |
| **芯区 / AA 带** | 芯区 = `B ≥ 250`（不透明）；AA 带 = `5 < B < 250`（边缘过渡） | 本单实测口径 |

### 1.1.1 base 移除裁定（2026-10-04 · WXG-T-237 v8.0 · 用户提问触发）

**结论：base 四件已从库中删除，透明度完全由 mask 的 B(shape) 通道承担。**

**移除依据（逐条核实，非推断）**：

| 核查点 | 读数 |
|---|---|
| `dev/harness/main.ts` 的 `MASK_FILE[gauge][kind]` | blit **只**加载 `*-mask.png` |
| `packages/framework/src/adapters/canvas2d/tint-blit-resolver.ts:36` | 有 `fx` 时走 `cache.get(cmd.textureId, base)` —— **只用 maskId + 着色基色** |
| 烘焙层 `bake-recipes.ts` / `bake-surface.ts` / `bake-key.ts` | **不涉及**任何 base PNG |
| `mask-diff.mjs` / `mask-diff.test.ts` | 门禁**只**比 4 个 mask 文件 |
| Cocos 侧 `games/beads/cocos/assets/scripts/` | **无** base 引用（原引用只在编辑器缓存 `cocos/temp` / `cocos/library`） |

**为什么透明度不需要 base**：

```
out = fx.base · d + (1 − fx.base) · l · shape        alpha = shape
```

- **`alpha = shape = mask 的 B 通道`** ⇒ 透明与否**只由 mask 决定**。
- 公式里的 `base` 是 **`fx.base` 着色基色（hex 字符串**，`colorIdx === undefined ? palette.slot : beadColorOf(inks, colorIdx)`**）**，
  ⛔ **与任何 `*_base.png` 文件无关**。
- 「−0.30 底色层」也不是 base.png，而是**代码画的 rect**（`drawTargetTile` 的 `edge`）。

**与本节原记载的一致性**：原文已把 base 标为「**条件交付**」并写明「走**整盘单图元**（Q1 选项①，推荐）
后 base 四件可省 ⇒ 回吐 KB 级」—— 本次是**执行该已写明的条件**，不是新决策。

⚠ **字节数更正**：原文写「4 base 小计 6 365 B」，**实测为 5 769 B**（bead holed 3 236 / bead holeless 1 753 /
grid holed 390 / grid holeless 390）⇒ 上表按实测填。

⚠ **若将来要回退**：真机侧若改走「**Sprite 池载体**」路径（Sprite 无 `spriteFrame` 不渲染 ⇒ 需占位图），
base 四件须重新生成 —— 代码在 git 历史（`8d7889a` 之前的 `export-cocos-textures*.py`）里，
或按本节规格重写（`bead` 占位 = A 通道取 `shape_b`；`grid` 占位 = 纯白 128²）。
- **口径**：mask 是**数据资产**（系数图，无颜色）⇒ **§2「未来真实资产替换提示词」对本分册不适用**；视觉资产的替换提示词仍住 `assets-spec §2`。

## 2. 编码规范与消费方式（**本分册核心**）

### 2.1 编码（冻结）

| 通道 | 含义 | 取值（本档实测） |
|---|---|---|
| **R** | `d` = 暗系数（`out ⊃ base·d`） | 珠面 0.396–0.867 · 格面 {0.32, 0.70} + 斜面渐变 |
| **G** | `l` = 亮系数（`out ⊃ (1−base)·l`） | 0 – 0.408（只在上扇与斜面受光段非零） |
| **B** | **形状 α**（自带，不依赖 `cc_spriteTexture`） | 珠面 = 圆角方 − 真透孔（含 0.5dp 羽化）；格面 = **满幅 255** |
| **A** | **恒 255 满幅**（**免疫 SpriteFrame Trim**） | ✅ 四件实测 **100.00%** |

> **A=255 的动机**（承定稿）：3.x 自定义 effect 下 `cc_spriteTexture` 不被引擎绑定（恒 white）⇒ **形状必须自带**（B 通道）。A 满幅是防 Trim 裁剪把 128² 裁到内容框。

### 2.2 消费方式（运行时必须照此）

1. **合成式**（唯一）：`rgb = base·d + (1−base)·l`、`a = B/255`，**预乘 α**。逐通道仿射 ⇒ **亮度线性**（§5.1）。
2. **tint 只吃「颜色字符串」**：`base` 由调用侧给（`palette.ts` 端点族的 `base`），mask 侧**零颜色**（V-1「mask-stable」红线）。
3. **⛔ 逐层覆盖 = 双通道同写**：mask 是「每个像素的**该层** (d,l)」，不是叠加层。烘焙器对任一层必须**同时写 R 与 G**；`d=1` 的层要**显式写 R=255**，不得「跳过」。**跳过 ⇒ 底层 d 渗漏**（现役缺陷，见 §7-D1）。
4. **⛔ 运行时不得放大烘焙纹理**（`control-manifest §19`）：128px 对应 30dp，放大即违规（§4.3 给了可用上界）。
5. **未命中一律矢量回退**：`maskId = 白名单(kind, gauge, styleId)` 返回 `undefined` ⇒ 矢量臂（逐字节 = 今日）。
6. **mask ≠ 贴图换皮**（与 `assets-spec §1.9.7` S2「禁纹理采样」的边界澄清）：mask 是**同一程序化层集的烘焙缓存**，不是外部位图替换风格；且**只在白名单命中时使用**，风格换皮仍是 S1/S2 双通道（穷举面）、不存在「贴图换皮」第三条。

## 4. 双档位与豆径档驱动的选用规则

### 4.1 驱动链（复用现役，⛔ 不新增第二把尺子）

```
BeadsSettings.beadSize (存档 S9)
  → snap.beadSize
  → view-model:  sizeSmall     = snap.beadSize === BEAD_SIZE_SMALL
```

| 对象 | gauge / 处置 | 依据 |
|---|---|---|
| 盘面已填格（珠） | 随档（`holed`/`holeless`） | — |
| 盘面空格（槽） | 随档（`holed`/`holeless`） | 槽底分叉 = 有意设计，⛔ **不得「顺手统一」** |
| **托盘珠** | **恒 `holed`** | 托盘不随档、恒满幅恒有孔 |
| 托盘空槽 / 锁定格 / 状态环 / 抬起影 / hint | **恒矢量** | 无 mask 档；live 层不满足「静态」判据 |
| 其余风格（`13`/`18`/…） | **矢量回退** | 白名单只含 facet-4（方案件 §7.1 `R-8`：同屏 tint/矢量混用的观感一致性风险，需美术评 `[待真机]`） |
| 切换语义 | **下一帧生效、零过渡** | 与风格切换同口径（`ux §5` 零新行） |

### 4.2 两档的不可混用点（落码逐条守）

见 §0.2 表；**槽底分叉**（holed 0.70 / holeless 0.32）与**孔径**（holed ⌀12 / holeless 无孔）是两条**不可互换**项。

### 4.3 128px 档位的可用上界（**换算，不给新数值**）

`128 px ÷ 30 dp = 4.267 device px/dp` ⇒ 成立条件 **`dpr × zoom ≤ 4.267`**：

| dpr | 可用上界 zoom | 是否覆盖 `CAMERA_ZOOM_MAX = 2.0` |
|---|---|---|
| 1 | 4.27 | ✅ 余量大 |
| 2 | **2.13** | ✅ 恰好覆盖 |
| **3** | **1.42** | ❌ **超出即被运行时放大 ⇒ 违 §19** |

⇒ **问题只在 dpr ≥ 3 且 zoom > 1.42 的设备上**（微信小游戏 dpr 无封顶）。三选项（承方案件 §6.2，**本单不代拍**）：
① 出 192 档（+10–30 KB，[估算]）；② 维持 128 + 显式豁免 §19（须实测观感）；③ **zoom LOD 在高倍段回矢量臂**。
**美术侧推荐 ③**（零包体、零放大模糊，高倍下矢量反而更清晰）；代价 = 阈值处 tint↔矢量切换的观感跳变 `[待真机]`；若跳变不可接受，退 ①。

## 5. 可访问性影响（**色相 + 明度二重编码在 tint 制下是否仍成立**）

> 口径：本节目的一切读数都是**定稿产物的逐像素实测 + 面积加权**（复算脚本见 §8），阈值一律用**本仓自己的判据**「ΔL ≤ 4% = 10.2/255 不可辨」（`art-bible §3.1` / `assets-spec §1.8`，与 `accessibility.md` A3② 同式）。**观感一律 `[待真机]`**。

### 5.1 关键推导：亮度在 tint 制下是**线性仿射**

`out_c = base_c·d + (1−base_c)·l = (d−l)·base_c + l`（逐通道同系数）
⇒ 亮度（`palette.ts::luminance` = Rec.601，通道线性）满足：

> **`L_out = m·L_base + l`，`m = d−l`**

⇒ 两条推论（本单 a11y 判定的全部依据）：
1. **色间亮度差被同一系数 `m` 压缩**：`ΔL_out = m·ΔL_base`（`m<1` 即压缩）⇒ **明度分档数只由 `m` 决定**。
2. **`l` 是加性灰底**：`(m, l) = (0.18, 0.38)` 这类组合会把任意色压向 `0.38` 中性灰（色相幅度只剩 18%）⇒ **色相通道同步塌陷**。

### 5.2 珠面（filled）实测

| 面域（面积加权，芯区 `B≥250`） | 面积 | `d` 均值 | `l` 均值 | **`m = d−l`** | 说明 |
|---|---|---|---|---|---|
| **珠体不透明区**（含外框环） | 482.4 dp² | 0.6283 | 0.0876 | **0.5407** | 定稿 mask 实测 |
| **四扇内域**（排外框 1dp 与孔环） | 360.4 dp² | 0.6580 | 0.0924 | **0.5656** | 定稿 mask 实测 |
| 同上 · **按层集应落值重建** | 360.4 dp² | 0.8800 | 0.0919 | **0.7881** | = 矢量臂同源（ADR-0028 §2.1 行 25） |
| 同上 · 现役语义重建（**对照组**） | 360.4 dp² | 0.6623 | 0.0941 | 0.5682 | ✅ **复现实测 0.5656** ⇒ 重建可信 |
| **纯本色区（`d=1` ∧ `l=0`）** | **0.0 dp²** | — | — | — | ⚠️ **珠面没有任何纯本色像素** |
| `m` 分档面积占比（定稿） | | | | | `m<0.25` **20.8%** · `[0.25,0.45)` 7.5% · `[0.45,0.60)` 32.4% · `[0.60,0.72)` 20.1% · `≥0.72` 19.2% |

### 5.3 明度可分档（单链聚类，阈 10.2/255；10 色降序）

| 面 / 口径 | `m` | `l` | **可分档** |
|---|---|---|---|
| 10 色本色平面（= `accessibility.md` A3① 的假设口径） | 1.000 | 0 | **8** |
| facet-4 珠面 · 层集应落值（= 矢量臂） | 0.788 | 0.092 | **6** |
| facet-4 珠面 · **定稿 mask 实落**（含 §7-D1 渗漏） | 0.566 | 0.092 | **6** |
| 上亮扇**单面** · 定稿（`m=0.18, l=0.38`） | 0.180 | 0.380 | **1**（10 色全并） |
| 上亮扇**单面** · 修正后（`m=0.62, l=0.38`） | 0.620 | 0.380 | **6** |
| 空槽 holed · 整格 | 0.656 | 0.009 | **6** |
| 空槽 holeless · 整格 | 0.517 | 0.008 | **5** |
| 空槽 holed · 坑底定值面（0.70） | 0.700 | 0 | **6** |
| 空槽 holeless · 坑底定值面（0.32） | 0.320 | 0 | **4** |
| 空槽 · **现役 live** 坑底 `pit`（−0.44 ⇒ 0.56） | 0.560 | 0 | **6** |

### 5.4 三条结论（照实写、不软化）

**① 色相通道：`m>0` 时「方向保持、饱和度被压缩」；`m` 塌到 0.18 的区域色相读法基本失效。**
`(d−l)>0` ⇒ 通道序保持（色相角不反转），但 `m` 越小色相幅度越小、而 `l` 是加性灰底 ⇒ 饱和度骤降。
**实测**：珠面上扇（占珠面 **20.8%** 面积，`m=0.18, l=0.38`）内 10 色亮度全距仅 **106.3 → 141.3 = 35/255**，且被抬向 0.38 灰 ⇒ **该区 10 色读作同一片灰**（预览图 `preview-combined-1024.png` 肉眼即见；深色珠上最显）。

**② 明度通道：珠面**没有**本色平面 ⇒ A3① 的「filled 侧」量化基准面已失效。**
- 默认皮肤 facet-4 的珠面 = 四扇（`m` = 0.62 / 1.00 / 0.84 / 0.70）+ plate 环 0.56 ⇒ 面积加权 `m ≈ 0.79` ⇒ **8 → 6 档**（`草绿/丁香紫`、`丁香紫/玫红` 落入不可分链）。
- 现役 mask 因 §7-D1 渗漏再降到 `m=0.57`（**档数同为 6，但临界对余量 −28%**：`草绿/丁香紫` 8.5→6.1、`丁香紫/玫红` 9.0→6.5）。
- ⇒ **`accessibility.md` A1/A3 的量化（基于「本色平面 = d=1」）在 facet-4 转正后已不成立**，且 A3 的「`filled` 侧 100% 可辨」口径须**按面域分列**（珠面面积加权 vs 单扇）。

**③ 空槽（empty）：holed 不变、holeless 再降一档。**
- holed 定稿槽底 0.70 比现役 live `pit` 0.56 **更亮 ⇒ 相邻色对 ΔL 放大 ≈1.17×**（整格面积加权 `m` 0.560 → 0.656），可分档同为 **6**（临界对余量增大、`深棕/炭黑` 11.0 → **12.9** 更稳）⇒ **a11y 中性偏正**。
- holeless 定稿槽底 **0.32** 比 0.86（`accessibility.md` A2b② 用的 `mix(base,#000,0.14)`）暗 2.7× ⇒ 整格 **5 档**（多并 `深棕/炭黑`）、坑底定值面 **4 档**（再并 `活力橙/草绿`）⇒ **小豆档的空槽明度可分档比满豆档少 1–2 档**（`accessibility.md` A3「小豆档不留孔 ⇒ 底盘可读改由 B0 缝隙单通道承担、**无冗余**」的欠账**加重**，需同批登记）。
