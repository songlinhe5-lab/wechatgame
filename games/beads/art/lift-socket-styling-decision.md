## §0 一句话现状

**2026-10-03 用户裁定「抬起态要影」并选型 C-3 ⇒ 已落码**：抬起格在槽内画一枚**正圆投影**，

## §2 七条逐项

### A · 定稿槽底缘亮线在小尺寸 + 抬起态下的薄带可辨性

- **现象**：抬起格下缘 1px 级亮带在屏上读作「一根横条」而非凹槽边缘。
- **同族已登记**：`tint-mask-asset-spec:279` 已有 `[待真机]` 薄带风险 —— 1dp 孔缘墨环 ≈ 2 device px（dpr2），环带面积 40.8dp² ≈ 珠轮廓 8%。**两者同一族**。
- **实测**：亮带 lum 175.5 vs 槽内 42.5 ⇒ ΔL **133/255**（对比极强，**不是「太弱」而是「太像一条独立的线」**）。
- **⛔ 待定标**：亮线在**小豆档 + 抬起态**下是否应减薄 / 减淡，以及减多少。定稿值 `SOCKET_LIT_MIX` 与线宽 `max(2, S×0.04)` 是否随档改。
- **候选**：甲 维持（保「凹槽最强线索」，靠上下文读）· 乙 随档递减线宽（`S×0.04` → `S×0.03`）· 丙 抬起态单独减淡（⛔ 需新增档态分支，违「层集不随态变」纪律）。
- **需美术给**：小豆档的**目标线宽设计px** 与抬起态允许的 ΔL 下限。

### B · 零对比坑底在暗 B0 上是否可接受 —— ⚠ 台账记法有误，以本条为准

- **⚠ 纠正**：v1.1 **不是**「0.70 一刀切」，而是**按档分叉**（`tint-mask-asset-spec:40`）：**holed 档槽底 = 格底色 0.70**（透色可辨 + 取放零跳变）· **holeless 档 = 0.32**（深坑保留）。判据 **I-5** 钉住「holed 0.70 / holeless 0.32」。
- **零对比问题只存在于 holed（满豆）档**：0.70 × 目标色 = **与 B0 tile `endpoints.edge`（−0.30）同色** ⇒ 槽底与格面**零跳变**。
- **⛔ 待定标**：(a) 维持 0.70（接受零对比，靠斜面环 + 亮线承载凹陷）· (b) 改 0.56（对齐矢量臂 `endpoint.pit` 实装 −0.44 族，**但取放会出现色跳变** 且判据 I-5 需改）。
- **⛔ 我曾建议 0.56 —— 该建议已撤回**（那是定稿决定，不是写错）。此处**只把争议摆回**，不预设倾向。
- **需美术给**：满豆档「取放零跳变」是否**必须保住**（它是 I-5 的立论前提）· 若不保，0.56 与 0.32 两档的 ΔL 目标值。

### C · `D1` 暗底坑底反读

- **现象**：共用坑底套依赖**近白底图**才读得出凹陷；落到生产 B0 暗底上**读作凸起**。
- **量化**（`assets-spec` §7.10 ⑧ / §7.11.7 D1）：四棱「暗底兼描边」在生产 B0 上**只剩 0.04 档差**；spike 样张底图 `plate = mix(base,+0.72)` 近白 ⇒ **一切观感结论不可迁移**。
- **⛔ 已发生的工程后果**：「抬起格露出真实槽图案」**本批不做**（工程暂定版由用户判）。
- **⛔ 待定标**：暗底（B0 −0.30）上**读凹陷**的最小可辨手段 —— 是加深 S1 暗缘 / 提亮 S4 亮线 / 坑底**偏离**目标色 / 换判据 I-5。
- **候选代价**：任何加深或提亮都**动判据 I-5 与取放跳变**，且需复评封箱（`frame78/0` 会变）。
- **需美术给**：暗底上「凹陷 vs 凸起」的**可接受混淆上限**（或一组正/负样张）。

### D · `D6` 光向唯一性

- **分歧**：`18` 风格投影 = **右下斜向** vs legacy `L0b` = **正下**；两套并存于池内，**光向不唯一**。
- **本批所做**：只保证**被删的格面影函数**符合 §6（左上顶光 ⇒ 影朝右下），⛔ **不代裁两风格的历史分歧**。
- **⚠ 现状使该争议暂时无载体**：生产网格**零影**（§1.1）⇒ 光向分歧**当前不可见**。
- **⛔ 待定标**：① 全池**统一光向**（选右下 or 正下）② 或明确「光向随风格」并登记为**风格属性**（则 §6 需增分叉条款）。
- **需美术给**：光向是**全局不变量**还是**风格属性** —— 这决定是改 1 处还是改 §6 条款。

### E · 阶梯段数 / 各段 α 与偏移 —— ✅ **已定案（2026-10-03）· C-3 正圆**

**用户裁定**：「抬起态**要影**」+ 选型 **C-3**（正圆，`r = 珠半径`，居中）⇒ **已落码**
（`bead-render::drawLiftSocketShadow`，参数 `tuning::LIFT_SHADOW_ALPHA 0.38` / `LIFT_SHADOW_SINK 0.10`）。

#### 选型否决链（逐条有实测依据，⛔ 不是审美偏好）

| 方案 | 否决理由 |
|---|---|
| **影投格面** | 被 tint cell mask（`shape` 全 255 完全不透明）与矢量 `PLATE` 满铺**完全遮住** —— 换绘制序前后画面**逐字节相同** ⇒ 结构上不可能 |
| **影投越格那 4dp** | 越格在**珠的上缘**（珠跨 `[格心−7, 格心+19]`、格跨 `[格心−15, 格心+15]`），而 §6 是**左上顶光 ⇒ 影朝右下** ⇒ 那是**背光面**，光学上错 |
| **影画在珠自身下缘**（珠内暗边） | 首版宽度 = 珠宽 ⇒ 落在珠自身已有的底缘暗边内 ⇒ **ΔL = 0，完全隐形**；加宽到 2.3× 半宽才可见，但**用户判「不像投影」** |
| **甲-1 Stadium 圆角条** | `radius = 高×0.5` 在 24×7 的 rect 上等于**药丸形** ⇒ **用户判「圆角轮廓不对」** |
| **甲-2 小圆角矩形** | 仍是「条」，不读作影 |
| **甲-3 正圆 `r=bandH×0.78`** | 半径取自**抬起量**（≈6）而非**珠半径**（≈13）⇒ 曲率只有珠的一半 ⇒ **用户判「圆角与珠子不一致」** |
| **甲-4/5 宽椭圆** | 影宽仅珠宽 67～77%，**曲率与珠对不齐** ⇒ 用户要求「投影要和珠子形状一致」 |
| **甲-6 圆角方 = 槽轮廓** | 严格贴槽，但读作「**整片槽底变暗**」（环境遮蔽）而非投影 |
| **C-2 正圆但居中** vs **C-3** | 用户选 **C-3（居中对称「碗影」）** |

#### 为什么 C-3 能同时满足「与珠同形」+「贴合槽轮廓」

盘面格 `beadInset > 0 ⇒ relief = 0` ⇒ `drawEmptySocket` 的坑外沿 **≡ 珠面轮廓** ⇒ **坑半宽 ≡ 珠半径**（几何恒等）。
故取 `r = 坑边长 / 2` 即**精确内接于槽**、不外溢 —— 不是凑数，是恒等式的推论。

#### 落码时修掉的两处偏差（预览 ≠ 正式，留档）

1. **半径大 1dp**：预览用 `(size − inset×1)/2`，`drawEmptySocket` 实为 `− inset×2` ⇒ 正式实现按 ×2（精确内接）。
2. **墨档出族**：预览用 `mix(base, −0.88)`（不在端点族内）⇒ 正式改用**族内** `shadeOuter −0.80` + `withAlpha 0.38`
   ⇒ **零新 hex / 零新 mix 系数**（纪律要求）。影会浅一档。

#### ⚠ 我自己的一处度量错误（已纠正）

预览期我用「差分包围盒内 `min(lum)` 差」报影深，得 **ΔL −4.4**，据此判「甲/丙/丁 读不出、很弱」。
**该度量错**：盒内 `min` 取到的是**珠自身底缘暗边**（≈27.8）而非影。正式实现同口径重测得 **ΔL −45.0**
（影区 19×16 设计px）⇒ **影的实际对比远强于我先前的报数**。教训与 K-091 同族：**测暗部必须限定在影的形状内**，
不能用「差分盒的全局 min」。

#### 两个连带项（用户未否 ⇒ 按默认落）

- **影压出槽下沿**：`r = 13` 而可见槽带仅 ≈5dp ⇒ 影必然盖到格外 B0 上（实测影区高 16 设计px）。默认**接受**（物理如此）。
- **影盖在槽的内阴影阶梯 + S4 受光亮线之上**：默认**接受**（物理如此）；用 `withAlpha` 而非实色，使那 3 层阶梯与亮线**透出**而不被整片盖掉。

### F · 接触影与坑底暗缘的层级关系 —— ✅ **已定案（同批随 C-3 落定）**

**层级已由实现钉定**：**影在坑底暗缘之上**（`drawLiftSocketShadow` 排在 `drawEmptySocket` **之后**）。
物理正确（影就压在槽面上），并用 `withAlpha` 保住内阴影阶梯与 S4 亮线的可读性。
⛔ 珠自身的接触影（L0a）**仍然不画** —— 用户判「不像投影」；生产网格珠自身零影这一事实不变（§1.1）。

### G · 封箱夹具无选中态 ⇒ 影层 / 选中态无封箱保护 —— ✅ **已裁：非美术域**（2026-10-03）

- **事实**：`bead-style-seal` 夹具（13×12 / 78 填 / 78 空）**从不调用** `selectBoardBead` / `selectTraySlot` ⇒ **选中态与影层不在封箱基线覆盖范围内**。
- **后果**：T-236 的影层增删**不需要复评**（已实测 `verify` PASS）；但**选中态的渲染变化无封箱保护**是真实边界。
- **✅ 用户裁定：不需美术定标**（工程/QA 域）。
- **本批的实证后果**：C-3 影只改**选中态**，而选中态不在封箱基线内 ⇒ **封箱腿 9/9 全过、零复评**（已实测）。
- **⛔ 仍未闭**：甲（补含选中态的封箱腿，撞腿 1 架构）/ 乙（显式登记为已知边界）**二选一仍待工程/QA 裁**；

## §3 共同阻塞

### 3.1 `丁`（抬高位移 6 → 11）撞封箱架构级阻塞 —— 用户 2026-10-03 已裁「暂不实施」

- **提案理由**（几何反推）：可见槽带 = `lift + 12 − 13` = `lift − 1` ⇒ 6dp 只有 5dp（读不出）；**11dp ⇒ 10dp** ≈ 槽内径 42% ⇒ 槽底缘着色完整露出；⛔ 上界 `11 < 半格 15` 珠不越格。
- **⛔ 阻塞**：`bead-style-seal` **腿 1** 断言「当前代码 ≡ `head.legacyFlow`(48 史证) ⊕ `head_liftShadowFade_r5`(48 现役存档)」逐字节相等；抬高位移影响**全部 96 例**（实测 `legacyFlow` **96/96 全变**、`frame78/0` **0 差** ⇒ 整帧不受影响）。
- **先例**：`927535c` 越界改 `head.legacyFlow` 48 例 ⇒ 处置 = 新建只读档案段 + 腿 1 改三段合并视图 ⇒ 那是**修改封箱核心断言结构**，按 K-082 属 **QA 复评**范围。
- **现值保持 6**；现态抓取件已备（`temp/wxg-t-211-s3/s3-seal.json`）。
- **⚠ 重启条件**：若美术在 A/C 裁出「槽必须更可读」，丁会复活 ⇒ **必须连同越格量（§1.3）一起交**，不得只裁「露出更多槽」。

### 3.2 「影物分离」当前不可行（E/F 的共同前置）

格 bead 26dp / 槽 24dp（mask `slotHalfDp 12`）/ 抬起 6dp 的几何下**没有可用表现空间**：格面被不透明 mask 全覆盖、槽内可见带仅 5dp 且已被槽自身着色占满、槽外余量仅 1.5dp。
⇒ **任何「把影画在珠外/槽外」的方案在当前几何下都不可实现**，须先改几何或改半透明基线。⛔ 二者都动冻结值 ⇒ 需独立立项。

## §5 纪律与边界

- ⛔ 本单**不代裁**；所有 `[待真机]` 项（薄带可辨性 / 观感 / CVD）**在有真机前不得判绿**。
- ⛔ **零新 hex / 零新系数**：所有墨档必须引用既有端点族（`shadeOuter −0.80 / shadeMid −0.68 / hole −0.58 / pit −0.44 / edge −0.30`）。
- ⛔ **图元数与包体增量不得沿用纸面值**，落码须差分复算（K-051）。
- ⚠ **旧文字一律 `~~划线~~` 留档、不静默删除**（K-053）。
- ⚠ 本单 §1.1 的「生产网格零影」是**代码实测**（`drawFilledBead` 内 `shadow` 0 次 + `drawLegacyTenBead` 无调用方），与台账「影层已删除」的记法**不冲突但更彻底** —— 台账只说删了格面影，实测发现**珠自身影在生产网格从未存在**。后续引用请以本条为准。
