## 1. 版面分区与层序

自上而下四带（关系不变式优先于具体 y 值，y 值 `[待实测]`）：

```
┌───────────────────────────────────────────┐
│  [招牌 logo 拼豆小铺]        [钮][钮][钮]   │  Z1 顶栏：logo 左 · 三 utility 钮右
├───────────────────────────────────────────┤
│        ┌───────────────────────┐           │
│   ◀    │   单主题橱窗 (Z2)      │    ▶      │  Z2 橱窗带：左/右切换钮贴橱窗两侧外缘
│        │  ┌─────────────────┐  │           │
│        │  │ 射灯光晕         │  │           │
│        │  │  [正在挑战绶带]   │  │           │  ← 仅「进行中」态出现
│        │  │  名牌 / boss成品  │  │           │  ← 内容随三态变（见 §2）
│        │  └─────────────────┘  │           │
│        └───────────────────────┘           │
├───────────────────────────────────────────┤
│            [ 开 始 游 戏 ]                  │  Z3 主 CTA：与当前主题绑定，通栏下方
└───────────────────────────────────────────┘
```

**层序 z（自底向上）**：`L0 纸底背景` → `L1 橱窗框+玻璃+射灯` → `L2 橱窗内容（名牌/boss成品/绶带/金章）` → `L3 ◀▶ 切换钮` → `L4 顶栏（logo + 三钮）` → `L5 主 CTA 开始游戏` → `L6 overlay`。

**关系不变式（判据，非 y 值）**：
- 橱窗**垂直填满** Z1 与 Z3 之间，无大片留白（本轮定稿要点：去进度链后放大橱窗补版面，见参考图 `00-hero-inprogress`）。
- ◀▶ 两钮**外切于橱窗左右缘**，热区 ≥ `TOUCH_MIN` 88；不压橱窗框。
- 主 CTA 与橱窗**同属"当前主题"语义组**（视觉上紧邻、间距 ≤ 一个 `space_band_pad`），表达"开始 = 开始这个主题"。
- logo 与顶栏三钮**共带不重叠**；三钮右对齐、等距。

## 2. 三态规格（核心交互语义）

橱窗一次只呈现**一个主题**，`◀ / ▶` 切换上/下一个主题；被呈现主题的状态决定橱窗内容与主 CTA 态：

| 态 | 触发 | 橱窗内容 | 当前标识 | 主 CTA「开始游戏」 | 参考图 |
|---|---|---|---|---|---|
| **未开始 / 锁定** | 尚未解锁（前一主题未推完） | **仅主题名牌**，整体**置灰/压暗**（灰字、暗柜） | 无 | **禁用**（灰态、不可点） | `03-state-locked.png` |
| **进行中（当前在推）** | 玩家正在推、未通关 | **仅主题名牌**（正常墨，**不显示 boss 成品图**——推完才揭晓） | **「正在挑战」绶带**（橱窗顶） | **可用**（正常态） | `01-state-inprogress.png` / `00-hero-inprogress.png` |
| **已通关** | 该主题全部关推完 | **boss 珠拼缩略成品（画框内）＋主题名牌** | **「已通关」金章**（橱窗角） | **可用**（可重玩该主题） | `02-state-cleared.png` |

**关键规则（用户口述，逐字对齐）**：
1. **没推完的主题 → 只显示名称**（进行中态橱窗内**不放** boss 图，保持悬念）。
2. **推完的主题 → 显示 boss 缩略图 + 名称**（成品是通关奖励的展示）。
3. **还没开始的主题 → 显示名称 + 置灰**。
4. 需一个**「当前正在推」的标识** → 采用橱窗顶「正在挑战」绶带（进行中态专属）。

> ⚠ **状态可辨不靠颜色**（见 §7）：三态用**形/文字/位**三重区分——锁定=灰化+暗柜、进行中=纯名牌+绶带、已通关=成品图+金章。

## 4. 文字与动态内容（切图设计的关键约束）

**能动态渲染的文字一律不烘焙进 PNG**，只切"底板"，文字叠在上层：

| 文字 | 处理 | 理由 |
|---|---|---|
| 主题名（D1 名牌内） | **动态**（系统字体/位图字体，叠 `_normal`/`_locked` 底板） | 9 主题各异、可改文案，烘焙=9 张死图 |
| 「开始游戏」（G1） | **动态**叠胶囊底板 | 文案可能 A/B 或本地化 |
| 「正在挑战」（D2） | 半固定；建议**动态**叠绶带底 | 状态词可能调整 |
| 「已通关」（D3） | 可**烘焙**（金章整体一枚） | 固定奖励章、无变量 |
| 「拼豆小铺」logo（A2） | **烘焙**（品牌字标） | 固定、含珠拼造型，程序化难复刻美术 |

> ⚠ **中文小字**：参考图里格内小名有错字（模型生成缺陷），**切图/字体侧的中文必须人工校对**，不得直接取参考图文字。

## 5. 图集 / 命名 / 分包

- **分包归属**：菜单 UI 位图（A2–G1）与 boss 缩略（E2）**统一进 `textures` Bundle**（ADR-0031 C′：复用现成 `textures`→主包，不新建分包）。
- **图集策略**：首版可**逐图入库**（同 demo 现状，未压图集）；量上来后并入 `atlas_ui_01`（1024²，padding 2px，`assets-spec §3`）。切图**导出留 2px 透明外边**防图集渗色。
- **命名**：严格 §4 规范（`ui_` 前缀 + 状态后缀）；`bitmap__boss_l{N}` 沿用 ADR-0031 既有 textureId 约定（双下划线前缀标位图族）。
- **`.meta` 纪律**：位图入 `cocos/assets` 由 **Cocos 编辑器/MCP 生成 `.meta`**，⛔ 禁手写（L1）；投放与构建受 §19 红线与 ADR-0031 时序约束（先规格→变更单→import→重建）。

### 5.1 工具与工作流（切图 → 入库）

环境事实：引擎 **Cocos Creator 3.8.8**，构建配置 `packAutoAtlas: true` 已开。

| 环节 | 用什么 | 要点 |
|---|---|---|
| 画元素 / 切图 / 导状态 | **Figma**（首选，免费）；备选 Photopea / Sketch | 矢量重画，**不从 AI 参考图硬裁**（非矢量、有错字）；组件 + 状态变体对应 §3 `_normal/_pressed/_disabled` |

| 9-slice 设定 | **Cocos 编辑器** Sprite Type = **SLICED** + 四边 border | ⛔ 不在切图工具里切九宫，在引擎侧设 |

| 拆件 mood（**初步自动切图规则·第一步**） | `design/ai-workflows/cut-sprites-local.py`（numpy+PIL，零外依） | 平背景洪水填充去底 → 连通域拆件 → 透明底单图；逐像素不重绘。`KEEP_SHADOW=1` 只键平背景保留投影（留档这套）/ `=0` 连投影一起吃。仅产**构图参照底稿**，非工程落库资产；换图调 `C`/阈值。产出见 §9 `sprites-v1-shadow/` |

## 6. 包体与红线（诚实登记，别当已达标）

- 本方案把主菜单从"0 位图程序化"改为"位图切图"，**主包位图从 0 KB 变正**：
  - 固定切图 ≈ 15 组（含状态帧）+ 9 张 boss 缩略 256²（单张实测 ~38 KB，见 ADR-0031）。
  - **红线**：主包 ≤ **4096 KB**（微信）；**内部目标** ≤ **2000 KB**（systems-index §3.9）。
  - **现状**：`check:size` 本机腿**已有牙**（beads 主包实测 **2979.0 KB** / 46 文件（2026-10-13 复核；旧记 2939.8 KB 已漂，划线留档：~~≈2939.8~~），超内部目标 **979 KB**、未越红线；>4096 会 FAIL。⚠ **口径注意**：`check:size` 报「无分包信息 → 全部计入主包（最严）」⇒ 此数含 `textures` 子包候选件）。 **余量仅 ~1.1 MB**——菜单切图 + 9 张 boss 缩略要**精打细算**（压缩、图集、必要时 boss 缩略走分包）。
  - **总包**：用户已裁「暂不开通体积扩展资质」⇒ 有效总包红线 **20 MB**（非 30 MB）；`systems-index §3.8` 现值 30720 待走 §3.9 变更单回改（本单不动正文）。
- **交付格式（2026-10-13 用户裁定：认 WebP）**：本清单以 `.webp` 为准（保留 α；实测招牌 960×622：PNG 558.3 KB → WebP q80 **55.5 KB**）。⚠ **未验证前提**：Cocos Creator 能否吃 `.webp` 作 ImageAsset 源**无先例**（`cocos/assets` 现 5 张全 PNG、0 webp）⇒ 落码前实测取证（本环境无编辑器 = 取证阻塞）；若不支持则回退「源 PNG + 构建侧转码」，收益改记构建侧。射灯/光晕等氛围层仍可后置或程序化。
