## 1. 视觉锚点

> **一句话锚点（v1.3 丙案）：冷调静底上唯一的高饱和暖珠子 —— 拼图区自带一圈极淡暖光，冷暖色温对撞让图案"浮"出画面；糖果 3D 珠以软高光与宽倒角立住质感。** `[v1.3·丙案]`

- 玩家 3 秒内应读到的画面：**冷紫灰画布 + 自带暖光晕的白板拼图容器 + 居中的彩色像素拼图 + 底部白色托盘与三个道具卡 + 顶部白胶囊倒计时**。 `[v1.3·F2/F3]`
- 关键词：**糖果质感、柔和投影、圆润、干净、无描边噪声**。
- 反面参照（明确不要）：硬边像素风（无倒角）、高饱和背景、重描边卡通、拟物厚涂、金属质感。

**四条铁律**：
1. **珠子先于背景**。背景与面板永远低饱和低明度差，保证珠子（画面唯一高饱和元素）第一眼被读到。
2. **三重编码不妥协**。珠子颜色必须同时有「颜色 + 符号 + 明度」三个通道（见 §3.3），符号为程序化矢量图形，不依赖字体。
3. **占位即规范**。3D 感全部由分层圆角矩形程序化合成（精确参数见 `assets-spec.md` §1.1 参数卡），未来可 1:1 换贴图。
4. **一屏一焦点**。拼图区是唯一视觉中心；托盘/HUD/道具栏均为"服务性"低对比 UI，不得抢焦点。

## 2. 情绪板（文字描述）

- **整体气质**：手工艺感 × 糖果质感。参考实物拼豆/串珠的手作温度 + 现代休闲游戏的干净 UI。
- **光照想象**：单一柔和顶光（略偏左上），物体有**柔和的短投影**（偏移小、透明度低），无硬阴影、无环境光遮蔽。
- **材质想象**：珠子 = 哑光糖果面 + 顶部高光条 + 四边倒角，**不透明、无反射、无渐变网格**；面板 = 纯白哑光 + 极浅描边。
- **色彩情绪**：背景淡紫灰（冷、低饱和）× 珠子暖橙棕（暖、高饱和），冷暖对比让拼图"浮"在画面上。
- **色温对撞（v1.3 丙案核心）**：整屏冷调低饱和为"静"，拼图容器外缘一圈**极淡暖光 band** 为"暖"，珠子为画面唯一高饱和暖元素——三级色温（冷底 → 暖晕 → 暖珠）建立独立辨识度；暖光只服务焦点区，不得扩散到 HUD/托盘/道具栏。 `[v1.3·丙案]`
- **动感想象（v1.4 改写，G8 根因对策）**：珠子是**有质量的物体**，不是贴图——放置会「落座」（携动量压下、被槽吸收、单调弹回），消除会「被吸走」（缩小 + 淡出，形态与符号保持到最后），道具生效有「一道斜向柔光扫过全场」的能量传递，过关有「整幅图案自左向右依次鼓起再落下」的余韵，连点不可填格会「按不动地轻颤一下」（极轻、非惩罚）。整体节奏仍**轻、软、不激烈**（与打砖块的街机爆点气质相反）：幅度上限刻意压得比竞品低（落座峰 1.06 / 庆祝峰 1.08 / 轻压谷 0.96）。**v1.3 的缺口**：以上除连击三档外全部只写在纸上、view 侧零消费（`bead:placed` 在视图里没有任何消费者）⇒ 最高频交互画面纹丝不动，质感断在「动」这一半。v1.4 的语言定义见 §7.2–§7.5，落码参数卡见 `assets-spec.md` §1.6。
- **与竞品的差异化（承丙案）**：竞品《奇妙拼豆》靠 pop-it **凹/凸两态**给按压解压感（`docs/reference/popit-pindou-gameplay-ui-analysis.md` §2.1/§4）；本作不做凹凸态切换（`filled` 是终态、网格不可回退，S6「绝不写网格」），改以**形变 + 接触阴影联动**表达同一件事——差异不在「动得更多」，而在**冷底静场里唯一会动的暖珠子**。

### 7.2 动态质感四要素（v1.4 新增，G8 根因对策）

> **G8 诊断**：v1.3 把**静态**质感做满了（十层珠卡、暖光 band、冷底 token），但**动态**质感四项（G1–G4）全欠账 ⇒ 珠子仍读作「贴图」而非「有质量的物体」。质感 ≠ 层数；质感 = **物体对力的反应方式**。以下四要素是本轮所有动效的共同判据，任何新增动画必须至少命中一条，否则不做。

| 要素 | 定义（观众读到什么） | 反面（贴图感） | 本作落点 |
|---|---|---|---|
| **重量 mass** | 形变分两段：先被力压下、再弹回，**不是瞬间到位** | 出现即终态（scale 恒定 1.00） | **G1** 落座（1.06→0.96→1.00）；**G7** 轻压（1.00→0.96→1.00） |
| **接触 contact** | 物体与被触面之间有**联动**（阴影随距离变深变浅） | 珠子浮在格子上，与槽无关系 | **G1** 的 L0a 接触阴影 α/宽随 scale 反向呼吸；L0b 投影随压下变浅 |
| **余韵 follow-through** | 主动作结束后有**衰减尾巴**，不硬切 | 到点即消失（α 阶跃） | **G2** 溶解（scale ease-in + α 线性 + 下沉，三通道不同缓动）；**G4** 逐列延迟造成的波浪尾 |
| **能量传递 propagation** | 一次操作的影响**沿空间扩散**，而非只在触点 | 反馈只发生在手指下那一格 | **G3** 斜向扫光（一次道具 → 全场）；**G4** 逐列波浪（一次完成 → 整幅图案）；**G6** 彩带（一次过关 → 全屏） |

- **气质不冲突声明**：四要素全部以「**幅度极小 + 时长极短**」实现（scale 振幅 ≤8%、单条 ≤800ms），与 §7 气质关键词「轻、软、落座感」不矛盾。本轮**不是加爆点**（那是打砖块的气质），而是把已有的静态质感「活过来」。
- **与竞品的质感路线差异**：竞品 pop-it 靠**凹/凸两态切换**给解压感（需可回退状态）；本作 `filled` 是终态、网格不可回退（S6「绝不写网格」），故走**形变 + 接触阴影联动**路线——同一件事（「这颗珠子是被我按进去的」）的不同物理表达。

### 7.3 逐条视觉语言（G1–G7）

> 通用约定：① 所有 `t` 为该动效自触发起的毫秒数，`p = t / 时长 ∈ [0,1]`；② 所有几何量为**设计空间 px**（750×1334，原点左下 y 向上）；③ **色来源一律为 §3 色板既有 token，本节零新色值**（约束 6）；④ 缓动只用 ease-out / ease-in / ease-in-out / linear 四种（渲染层无缓动库，逐帧公式在 `assets-spec.md` §1.6 给到可直接落码的形式）；⑤ 每条都给 **D1 退化口径**（减弱动效）与 **D2 频率核算**（闪烁 <3Hz），汇总见 §7.5 与 `accessibility.md` §2。

- **⚠️ 案 B 的三条未验风险（诚实登记，不得写成已解决）**：
  1. **跨 framework 域改动需全矩阵回归**：`RenderModel` 是公共接口，`games/breakout` 也消费同一模型 ⇒ 影响面 = **全矩阵**（beads + breakout + harness + 两 adapter），工程量与回归范围**需架构域报价**，美术侧无法估；须走 ADR / `control-manifest` 登记（不破 L2：core 无 `cc` 依赖，只有 adapter 碰引擎）。
  2. **`FIXED_WIDTH` 下整屏放大 1.015 可能露黑边，未验证**：1.015 倍放大 ⇒ 边缘图元被推出设计空间（750×1334）；`FIXED_WIDTH` 只保证宽度铺满、纵向由锚点吸收（高屏设备中段留白延展），故**上下（或高屏下的留白段）是否露出未填充区取决于相机/裁剪与背景层是否随变换**。**这是落码前置验证项**：工程单必须先给出「背景层是否参与全局变换 / 是否需外扩 1.5% 补边」的结论，再动接口；**真机未验**（Cocos 构建阻塞，ADR-0009 P2）⇒ 纸面无法闭合。
  3. **根因是视图侧 `_commands` 私有（WXG-T-074 已登记）**：本案要解的正是这个根因——`RenderModelBuilder` 只暴露逐图元 push，`build()` 产出冻结的 `{ background?, commands }`，**无任何变换语义位**，视图拿不到也造不出全局变换 ⇒ 才出现「规格有、实现空」的 G5 缺口。工程单须以**扩接口**（而非在视图侧 workaround）收口，否则同一缺口会在下一条整屏动效上复发。
- **D1 / D2 / A5 口径（不随选案变，裁定 2 明确 a11y 口径不变）**：**D1 = 整条关停**（`accessibility` D1 关停清单）；**D2** = scale 脉冲 1.00→1.015→1.00，每次连击一次、**非周期**、单峰 0 往复 ⇒ 折算频率 ≪ 3Hz；**A5** = 全局变换不改变图元间相对关系（1.015 ⇒ 珠径 50.75px < pitch 52 ⇒ **零重叠**，比 G1 的 1.06 更安全）。⚠️ **新增观察项（案 B 特有，真机待看）**：整屏缩放会使 HUD 文字与 1px 描边出现**亚像素抖动**——非闪烁（D2 不计），但属**可读性观感项**，落码后须真机复核 B1/E1 观感。

**回退阀降级顺序**（原则：**先砍动画期细节，最后才砍静态质感**；`[v1.4-r2·裁定 5]` **本轮只预埋 G4 的 6 层分支**，以下②③ 为**规格保留、本轮不落码**）：
1. **G4**（**本轮已预埋 6 层档**）：6 层 → 4 层（L1+L2+L3+L5），`936 → 624`；
2. **G2**（**规格保留、本轮不预埋**）：阀②的「启用」= 把「取消 α 阈值、**全窗口 4 层**」（= 主理人原建议）落码；本轮 G2 **十层全开**，故启用阀② 反而是一次**降配**（代码路径也更简）；
3. **G6**（**规格保留、本轮不预埋**）：`44 → 24` 枚，`+44 → +24`；
4. **最后**才动静态十层（§1.1 既有阀：合并 L4a+L4b 降 8 层）。

- **同帧叠加核算（绝对图元口径，防误读）**：动画期图元数必须与**静态基线**比，而不是单独累加——G2/G4 作用对象**就是**那些本来就要画的珠，降层后是**减法**：
  - **道具期**（G3+G2 同帧，最坏 clearAll 24 枚）：① **规格口径（G2 α 阈值 LOD 启用时）**= `+3`（扫光）`+ 96`（溶解珠 4 层）`− 240`（同批珠静态十层）⇒ 净 **−141**；② **本轮落码口径（裁定 5：G2 不预埋、十层全开）**= `+3`（扫光）`+ 0`⇒ 净 **+3**。**两口径不得混用**（`assets-spec §1.8` 末表同此注）；
  - **庆祝期**（G4+G6 接力）：`936`（156 珠 6 层，**取代**静态 1560）`+ 44`（彩带）⇒ 净 **−580**（G4 6 层档**本轮已预埋** ⇒ 此值本轮即成立；G6 44→24 的阀③ 不影响本行，只是启用后变 −600）；
  - **单珠期**（G1/G7）：净 **+0**；**G5（案 B 定案）**：净 **+0**（全局变换，图元数不变）。
  - ⇒ **结论：v1.4 六条动画在规格口径下最坏情况反而降低总图元数**（LOD 降层省下的 > 装饰层加的）；**本轮落码口径下为“基本持平”**（单珠 +0、道具期 +3、庆祝期 −580）。**真正的性能风险不在图元数，而在 CPU 几何重算路径**：G4 需对全场 ≤156 颗逐帧重算 scale 与 6 层坐标（静态珠本来也逐帧重建，增量 = 每颗多一次 scale 乘法族），G6 需 44×4 点旋转计算；**G5 走案 B 全局变换 ⇒ 零逐珠重算**（比已废的案 A 更便宜）。因此回退阀① 优先砍 G4 层数（直接减重算量）。逐条图元公式与绝对值表见 `assets-spec.md` §1.6.9。
- **热路径纪律**（`AGENTS.md` / `control-manifest`）：所有逐帧公式必须是**纯函数 + 零分配**（承 `wrongFlashAlpha(p)` / `comboParticleOffsets(progress)` 判例）；禁 `new`/`map`/`filter`/展开造集合；G6 彩带用**预分配 scratch**（44 枚 × 4 点 × 2 坐标 = **352 float**），不逐帧 new。
- **常量归位**：所有毫秒分段/幅度/层数常量 → `src/config/tuning.ts`（承 v1.3 判例注：「与 `WRONG_*` 判例同族：反馈/呈现层参数，**不进** `systems-index §3`」）；所有色值 → `src/view/palette.ts`（hex 只住 palette）。**美术规格本身零新增冻结常量**。⚠️ **一处跨域例外（裁定 3 连带，诚实登记）**：G7 新增 `sfx_denied` 会连带 `systems-index §3.12` `AUDIO_CLIP_TOTAL` **19→20** 的**冻结值变更单**（+ `systems-index-changelog` 新行）——属**音频/GDD 域**，随工程原子批走（`audio-events §5` Q-A05-5），**不在本美术单、本轮未改**。

## 8. 材质与光照

- **单光源假设**：左上顶光。全部物体的高光在左上、暗部在右下，**全局一致，不得出现反向受光珠子**。
- **珠子 3D 感 = 10 层程序化合成**（无贴图、无模糊、无真渐变；v1.3 质感升级 F4）：
  1. 接触阴影（紧贴珠底窄条，α0.12）
  2. 柔和投影（偏移 3px，α0.15）
  3. 主体基色圆角方
  4. 下/右暗倒角（`mix(base,#000,26%)`，5px@64）
  5. 上/左亮倒角（`mix(base,#FFF,20%)`，4px@64）
  6. 顶缘 rim 光（`mix(base,#FFF,38%)`，2px）
  7. 软高光·广（α0.08）
  8. 软高光·中（α0.16）
  9. 软高光·核（α0.30）——7→9 外扩递减、中心递增，叠层模拟柔光
  10. 符号（三重编码非色通道）
  - **精确参数卡见 `assets-spec.md` §1.1**，程序可直接落码。 `[v1.3·F4]`
- **暖光 band / 容器板 / 背景层次 = 同心圆角 rect 叠层 + 递减 α**（渲染原语无渐变/模糊下的唯一合规模拟法）；层序与每层 α 见 `assets-spec.md` §1.7/§1.8。 `[v1.3·丙案/F8]`
- **凹凸材质语言（v1.5，WXG-T-131）**：凸体（珠）与凹坑（空槽）共用同一几何骨架、**明暗方向互换**——凸 = 上亮下暗（L3/L2）+ 接触阴影 + 投影 + 三层软高光 + rim；凹 = **上暗下亮**（上内阴影线/下受光线）+ 暗缘框 + 内缩 6% + **零投影零高光**。E4 幽灵符号移除后，空/珠区分以**凹凸对比为主轴**（五形态通道复核成立，见 `assets-spec §1.9.4`）；错位珠（新玩法）压在同色坑上时，靠投影 + 满尺寸 + 高光三通道压过坑缘。
- **同色相渐变端点（v1.5）**：明端 `mix(base,#FFF,0.38)`（复用 `BEAD_RIM_MIX` 判例系数）、暗端 `mix(base,#000,0.26)`（复用 `BEAD_BEVEL_DARK_MIX`）、坑底 `mix(base,#000,0.14)`；**向纯黑/白线性混色只动明度轴、色相角不变** ⇒ 10 色渐变端点色相间距不塌（色相识别由 L0 主体承担，端点仅出现在 ≤5px 线/带）；`luminance(base) > 0.85` 的亮色（奶白）明端钳制为本色。10 色 × {L0, L+, L−, 坑底} 对照表与推导规则见 `assets-spec §1.9.2`；端点 hex 一律由 `palette.ts` **模块级预计算**（零每帧字符串分配，缓存建议见 `assets-spec §1.9.5`）。`[v1.5]`
- **动态质感 = 逐帧重算几何/α，不是加特效层**（v1.4，G8）：渲染原语面**无全局变换通道、无缓动库、无粒子系统**（约束 3）⇒ 所有动效只能靠四个手段：**scale（逐图元重算坐标）、α、叠层递减、位移**。因此「质感动起来」的正确做法是把十层卡的**层间参数做成时间函数**（如 G1：L0a 的 α 与宽比随 scale 反向呼吸、L0b 的 α 与 `shadowDy` 随压下变浅），而不是在十层之上**再叠一层光效**。后者既涨图元又读作「贴了个特效」，前者才读作「这颗珠子有质量」。逐帧公式见 §7.3 与 `assets-spec.md` §1.6。 `[v1.4·G8]`
- **面板/托盘**：纯白 + 1px 浅描边 + 半透明深色偏移矩形模拟投影；凹陷用"上亮下暗"双 1px 线反转表达。
- **禁止**：模糊贴图、法线、PBR、噪声、真渐变真模糊、外发光滥用；**允许**：多层图元 + 递减 α 的"伪渐变/伪光晕"（每处 ≤4 层、α 单调）。 `[v1.3]`
