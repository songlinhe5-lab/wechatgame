# 《拼豆》可访问性规范（Accessibility Spec）

> 项目：微信小游戏矩阵 · 第二款《拼豆填色消除》
> 版本：v1.0（demo 阶段）｜ 作者：林绘澄（可访问性）
> 配套：`art-bible.md`、`assets-spec.md`。方法论与分级体系：`my-skills/wxgame-art-spec-programmatic/SKILL.md`
> 设计分辨率 750×1334 / `FIXED_WIDTH` → **1 设计 px ≈ 0.5 pt**，88 设计 px ≈ 44pt。

---

## 1. 分级选择

三级承诺：Basic / Standard / Comprehensive。

| 分级 | 本 demo 目标 |
|---|---|
| Basic | ✅ 必须全部满足 |
| **Standard** | ✅ **本 demo 目标等级** |
| Comprehensive | 🔶 部分落地，其余延后（见 §3） |

> **结论：本 demo 承诺达到 Standard，并落地 Comprehensive 中成本低的若干项。**
> 与 breakout 一致：微信小游戏平台不支持屏幕阅读器，属平台限制，不计入本团队承诺范围。

## 2. 特性矩阵

| A2 | **色觉障碍友好 · 珠子状态** | `locked` X 斜纹 / `empty` 凹槽 / `hint` 蓝描边呼吸 / `wrong` 抖动+红描边 / `selected` 上浮+圆点——**每个状态都有非颜色通道** | ✅ **落地** |
| A3 | **灰度可辨** | 转黑白后 10 色 + 6 状态 100% 可区分（符号 + 明度 + 纹理保证） | ✅ **落地** |
| A4 | **色觉障碍友好 · 道具图标** | 3 个道具**以形状为唯一识别**（魔法棒/扫帚/磁铁）+ 文字标签并列，不靠颜色 | ✅ **落地** |

| B2 | **对比度 · 符号/图形** | 符号对珠面 ≥ 3:1（亮珠用 `mix(base,#000,55%)`，暗珠用 `#FFF@90%`，见 `assets-spec.md` §1.1 L5） | ✅ **落地** |

| C1 | **触控目标尺寸** | 交互元素 ≥ 44pt → **≥ 88 × 88 设计 px**。设置齿轮热区 88×88、道具卡 176×150、`btn_expand` 132×48 → **⚠️ 48 < 88，高度不足，须扩热区至 132×88（视觉不变、热区扩大）** | 🔶 **落地（含 1 处修正）** |

| D1 | **动效可减弱** | 设置提供「减弱动效」开关，**关停清单**：落座回弹（改直接落位）、消除溶解缩放（改直接淡出 120ms）、错误抖动（改静态红描边 300ms）、完成波浪弹跳（改静态高亮）、告急脉冲（改静态红字）；**保留清单**：珠子颜色/符号变化、面板淡入淡出、hint 静态描边 | ✅ **落地** |
| D2 | **闪烁安全（光敏）** | 任意闪烁 < 3Hz；`wrong` 描边闪 ≤2 次/秒；**禁止**全屏白闪 | ✅ **落地** |
| E1 | **文字可读性** | 最小 28 设计 px（≈14pt），正文 32px，倒计时 44px；系统字体随系统缩放 | ✅ **落地** |
| E2 | **文本缩放开关** | 「大字号」开关（正文 32→40px，面板自适应） | 🔶 部分（基础版落地，全界面自适应延后） |

| F2 | **输入精度要求** | 点按填色（无拖拽精度要求）；空位命中区域 = 珠位外扩 8px，降低误触 | ✅ **落地** |

| H1 | **符号显示开关** | 允许熟练玩家关闭珠面符号（纯色模式）——三重编码默认开启，此项为**可选减负** | ⏸ 延后（待用户拍板，见 §5） |

> **落地状态复核（2026-09-14，WXG-T-052）—— 三处 ✅ 曾与实现不符，现已补齐并留下偏差登记。**
>
> **A1 / A3 / B2 复核**：此前 `view-model.ts` 自述「the 10 vector symbols … deliberately deferred」，
> `view/symbols.ts` 与 `view/bead-render.ts` **并不存在** —— 珠子实际只画了**颜色 + 明度**两重通道，
> 而符号是三重编码中**唯一的非颜色通道**。即：A1「三重编码」实为两重、A3「灰度下 100% 可辨」在只有
> 明度 5 档时不成立、B2「符号对珠面对比度」当时**无对象**。
> 现两文件已落地（六层参数卡 L0–L5 + 10 符号矢量 path），并由 `tests/symbols.test.ts`、
> `tests/bead-render.test.ts` 断言：10 色 ↔ 10 符号一一映射、每颗满珠发射 L5 符号、
> 线宽 ≥ 2px、**10 色符号墨对珠面对比度全部 ≥ 3:1**。
>
> **偏差 1 · B2 与 `assets-spec.md` §1.1 L5 的阈值冲突（已处置）**：按 L5 的「亮度 > 0.6 → 深色墨」，
> 草绿 `#3FBF6B` 取 `#FFF@90%` 仅约 **2.4:1**，低于 B2 的 3:1 地板。处置：**以 B2 为硬地板**，
> 该色翻转为深色墨（约 3.7:1）。10 色中**仅此一色**需要翻转，测试中已显式钉住这条例外。
>
> **偏差 2 · `locked` 主体混色不可实现（待数据模型变更）**：`assets-spec.md` §1.2 规定 locked 主体为
> `mix(base, #B9B4CC, 0.60)`，但 `x`/`.` 两格在 `entities/grid.ts` 中 `colorIdx = 0`，**没有 base 可混**。
> 现按 `palette.locked` 平涂（无高光、无符号；非颜色通道由 45° 斜纹承担）。按规格混色须先给 locked 格
> 一个基色语义 —— 属数据模型变更，**不在此处发明**。
>
> **偏差 3 · locked 斜纹密度低于规格（登记待对齐）**：§1.2 要求「45° 斜纹，间距 10」，现实现为两条
> 对角 X 线。可辨性不受影响（非颜色通道仍在），但密度低于规格。

## 3. 落地范围小结

**本 demo 落地（13 项）**：A1 A2 A3 A4 B1 B2 B3 C2 D1 D2 E1 F1 F2

**落地含修正（1 项）**：C1 —— `btn_expand` 视觉 48px 高但**热区扩至 88px 高**（132×88），视觉不变。

**部分落地（1 项）**：E2（文本缩放基础版）

**延后（2 项）**：G2（屏幕阅读器，平台限制）、H1（符号显示开关，待用户拍板）

## 4. 与 UX 规格的接口（`[待 ux-spec 对齐]`）

UX 规格产出后须满足/引用：

1. 设置页含**「减弱动效」**开关（D1，关停/保留清单见 `assets-spec.md` §1.2/§1.6 的动效项）。
2. 可点元素 ≥ 88×88、间距 ≥ 96px（C1、C2）。
3. 倒计时告急须"变色 + 脉冲"双通道（B3）。
4. 填色命中区域外扩 8px（F2）。
5. 暂停必须**冻结倒计时**（F1）。
