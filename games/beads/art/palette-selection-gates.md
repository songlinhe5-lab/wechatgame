## 0. 要解决什么

品牌色板（15 板 2104 色）里存在大量在**刻面渲染**下不可分辨或不可显示的配色：
近白族互撞、近黑族元素消失、同族色阶被明暗带吞掉。选色若无门，产出的图纸玩家读不出目标色。

## 1. 三道门（正交并列）

### 1.1 门 A · 全深宪法（渲染侧约束，已生效）

珠体派生元素**恒比原色深**：底图 `mix(base,−0.30)`、框色/孔深 `mix(base,−0.44)`、
孔线 B14 影墨 `#1E2033`。

- **裁决记录**：条件描边律（深色珠换亮边）曾出七色三臂图例对比（2026-09-27 上午），
  被用户以「深珠×浅底错珠时亮边撞浅底」否决——边框职责 = 同时拉开珠体与背景，
  全深规则只在「深珠×深底」一格退化，且该格多数配对已被门 C 预先互斥（证据 §4-③）。

### 1.2 门 B · 单色下限（绝对门，逐色）

```
selectable(c) ⟺ ΔE76( c, mix(c, −0.44) ) ≥ PIT_VISIBLE_MIN(=8)
```

框色/孔深是最深派生元素，它与珠体的距离决定"三件套是否还存在"。向黑混合是乘法收缩，
`#000000` 处全等（ΔE=0）⇒ 黑珠在门 A 下**不可选是宪法的明确代价**，图纸要"黑"用
最暗深蓝/深棕（luma≈0.15 档）顶替。

**剔除名单（全量 2104 色仅 6 色）**：

| 板 | 色号 | hex | ΔE(base,pit) |
|---|---|---|---|
| artkal-m | MH7 | `#000000` | 0.0 |
| mard | H7 | `#000000` | 0.0 |
| yant | Y011 | `#000000` | 0.0 |
| hama-maxi/midi/mini | H18 | `#141315` | 3.2 |
| diamond-dotz | 8001 | `#1F1F24` | 7.0 |

其余 12 板 0 剔除。**注册表不剔色**（`palettes-data.ts` = 品牌实物镜像，studio 照片
映射需全量查色）；剔除只发生在选色交互层。

### 1.3 门 C · 近似族（相对门，两两，仅同品牌内）

```
confusable(A, B) ⟺  bandΔE76(A,B) < NEARFAM_BAND_MAX(=15)
                 ∧  baseΔE76(A,B) < NEARFAM_BASE_MAX(=22)
band(c) = { mix(c,−0.30), c, mix(c,+0.38) }   // edge/base/lit 三点带
```

- **选色规则**：选中 c ⇒ 同品牌内所有与 c confusable 的色置灰；等价实现 = 候选色与
  **每一个已选色**逐对判据。**不传递、不聚类**——连通块口径在 τ=12 时把 dotz 461 色并成
  一块 428 色，灾难性过锁，实证作废。
- **跨品牌不设限**（用户 2026-09-27 裁）：不同品牌同色号/同色值互不干涉。
- **为什么是双阈值合取**：纯色带最小距判据会误杀「淡黄 `#FFFBAA` ↔ 橄榄 `#8CA12A`」
  （band=12.0 但 base=40.4，肉眼可分）——band 门抓"刻面吞色"，base 门防"异色相误伤"。
- **τ_band=15 不取 12 的硬理由**：触发修正的实图黄对（`#F9F55D`↔`#E6C61E`，用户报难分）
  bandΔE=13.3，τ=12 连它都拦不住。

**四对代表性复核**（判据全过）：

| 色对 | band | base | 判定 |
|---|---|---|---|
| 截图两黄 `#F9F55D`↔`#E6C61E` | 13.3 | 20.2 | 锁 ✓ |
| 淡黄↔橄榄 `#FFFBAA`↔`#8CA12A` | 12.0 | 40.4 | 放行 ✓ |
| 粉↔紫红 `#E8649E`↔`#E970CC` | 12.0 | 20.8 | 锁 ✓ |
| 灰↔棕 `#99ABAC`↔`#B39D88` | 12.0 | 20.0 | 锁 ✓ |

## 2. 定标数据（2026-09-27，全量 15 板）

- 逐板最近带距分位：密集板（artkal-*/mard/dotz/yant）p50 = 2.4–6.5，稀疏板（hama/perler/nabbi）p50 ≥ 6.5；
- 合取门下锁色规模：选 8 颗 artkal-m 仅锁 78/220（35%），剩 142 可选；
- **可用性验证（贪心独立集 = 互分色上限）**：mard 52、artkal-m 47、artkal-c/dotz 42、
  hama-midi/mini 37–38、perler 35……15 板全部 ≥18——对上关卡颜色上限 35 的口径，
  密集板挑 35 色无压力，规则不会锁死色板。

## 5. Studio 实现方式 **[TODO·未裁]**

门在 studio 生成/选色时执行，**烘焙 vs 程序化待用户确认**：

| 方案 | 内容 | 代价 |
|---|---|---|
| 烘焙 | 生成期预计算逐品牌邻接表（色号→近似族名单 + 下限标记）随 `palettes-data` 或独立 JSON 出，运行时查表 | 数据量：2104 色邻接表（dotz 461 色最密）；色板更新须重烘 |
| 程序化 | 选色事件现算 ΔE（Lab 转换 ~20 行，O(已选数)，≤35 色） | 无预计算物；studio server 与游戏侧若共用需一份公共实现 |

判据计算量极小且只在选色事件触发（非热路径，无 C2 顾虑），两案皆可；
差异点 = **色板漂移时邻接表失效**要不要防（烘焙案需把 `sync-palettes` 门接上，程序化案天然免疫）。

## 6. 诚实声明

1. ΔE76 在蓝色区略钝（已知非均匀性）——真机复核若蓝族误放，升级 CIEDE2000 重定标；
2. 三点带（edge/base/lit）是四刻面（含 −0.16 右面）的近似，误差在阈值余量内；
3. 「深珠×深底」残余风险以示意 PNG 判定，真机错珠场景（含 L0a 接触影、珠间隙）待 T-215 归位后复核；
4. 定标用的七色测试板（黑白橙绿蓝青紫）非生产十色，结论以本文 §2 全量数据为准；
5. 本文初稿落 `design/art/`（用户指定），同日正式合并至 `games/beads/art/`（用户裁「合并」），与 art-bible / assets-spec 等姊妹文档同层；`design/art/` 目录已删。
