## 1. 基准口径（先读这个，防止算错）

> **单位纪律（v1.0-r3 · 2026-09-28 用户裁定）**：本文所有距离一律以 **dp** 计（与分辨率无关的逻辑格点 = 750 设计网格；旧写法「设计 px」自本批统一为 dp）。「px」只用于**设备物理像素**或**资产纹理像素（texel）**两种含义，其换算随设备 DPR 变化，⛔ 不得用来记录任何与设备无关的维度。

| 量 | 值 | 说明 |
|---|---|---|
| 格径 `BEAD_PITCH` | **32** dp | 格心距（§3.3 冻结）；B0 底图按 32 dp **满铺、方角**（K8 连续马赛克 ⇒ 格间**无可见缝**） |
| 格 `BEAD_CELL` | **30** dp = 32 − `BEAD_GAP 2` | **珠体边长基准**（不是格径！）⇒ 珠面 = `30 − 2×inset` |
| dp → CSS | ×0.5（750→375 CSS） | 1 dp = 0.5 CSS px |
| dp → 设备物理 px | **×0.5·dpr** | 1 dp = dpr1 → 0.5 物理 px ／ dpr2 → 1 ／ dpr3 → 1.5（线宽实际形态在此，见下适配口径） |
| 物理尺寸参照 | ≈0.08 mm/dp（~160 dpi，观看距 30 cm ⇒ 1° 视角 ≈ 65.9 dp） | 仅感知口径引用（§5），不是本标准判据 |

> **美术资源 × 设备适配口径（2026-09-28 用户问，登记留档）**：
> - 烘焙资产源密度 = **4 texel/dp**（128 texel ÷ 32 dp 格径，`BAKE_CANONICAL_SIZE`；覆盖 dpr2 cap × 满 zoom 2.0）。「1 dp ↔ 2 px」的诉求**已满足且有余量**（4 ≥ 2），mip 链 L1 档（64 texel）即 2 texel/dp 层级，⛔ 无需另做 2x 资产；反向降档（改烘 64px）= 满 zoom 时上采样发糊，不采。
> - **不按设备出资产分档版本**：1x/2x/3x 设备对 4 texel/dp 源都是**向下采样**（永不上采样），分辨率差异由采样器吸收，资产侧与设备无关。
> - 差异发生在**显示端而非资产端**：1 dp 描边的物理宽 = 0.5 px（dpr1，近乎消失）／1 px（dpr2，发丝）／1.5 px（dpr3）——此为低档机可读性问题，解法 = 描边 **dp 档位提升/地板**（实现批 ② 真机 A/B），换更高分辨率资产救不了。
> - ⚠ 未实测项：若 Cocos 小游戏 framebuffer 在 dpr3 设备不钳 2×，满 zoom 需求 = 6 物理 px/dp > 4 texel/dp ⇒ 3x 旗舰满 zoom 细节反而弱于 2x 档。**[待实测 FB scale 口径]**，实测前不得引用为结论。

## 4. 变更纪律（⛔ 本节是硬约束）

**任何 J1–J7 的值或门槛修改，必须同批提供：**

1. **调研数据**：改前/改后对照图（`temp/` 出图，标注孔径/环/坑，同帧同源）+ 面积账（按 §1 口径计算，方角近似**不认**，须含圆角修正）；

3. **判据与文档同批更新**：`bead-cell-standard.test.ts` 钉值 + 本文 §2/§3 同步，⛔ 只改代码不改文档 = 判红即假绿；
4. **台账登记**：`production/TASKS.md` 任务行 + 影响面（封箱腿 1/3 属珠体族，须走 `§K.5.1` 复评归因通道，⛔ 禁自更新基准）。

## 5. 明确不在本标准内（防越界）

- **颜色区分辨识度**（等亮度色对、色觉障碍、WCAG 3:1 对比度门）：**单开话题调研**，结论出来前不在本文件立门；
- **相邻格可辨**（跨格的色块/图案可读性）：同上；
- 感知类门槛（视角/mm）：本标准只有 J2 一条**代理指标**，面积 ≠ 感知——单颗珠面 0.39° 视角低于 ~0.5° 小视野辨色可靠区，**孤立辨色不可靠、同色连片 ≥3×3 格（1.46°）才够**，此结论供后续调研引用，不是本标准的门。
