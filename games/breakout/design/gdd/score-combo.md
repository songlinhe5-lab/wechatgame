# GDD · S5 计分与连击（Score & Combo）

> 版本 v1.0 · 依赖：S4（砖块破碎事件）· 被依赖：S8（最高分）

---

## 1. 目标
用"连击倍率"奖励精准操作，制造"越打越爽"的正反馈；同时通过"接球即重置连击"的规则防止无限滚雪球，保持分数系统的**可读性与公平性**。

## 2. 机制

### 2.1 得分结算
```
获取砖块基础分 base（见 S4 类型表）
destroyScore = base × comboMult
score += destroyScore
```

### 2.2 连击（Combo）
- `combo` 计数：**球不碰挡板期间**每破碎一块砖 +1。
- **重置条件**（任一）：
  - 球碰到挡板（`ball:hitPaddle`）
  - 球丢失（`ball:lost`）
  - 关卡切换 / 重开
- **倍率公式**：
```
comboMult = min(COMBO_MULT_MAX, 1 + floor(combo / COMBO_STEP))
// COMBO_STEP = 3，COMBO_MULT_MAX = 5
```
| combo 计数 | 倍率 |
|---|---|
| 0–2 | ×1 |
| 3–5 | ×2 |
| 6–8 | ×3 |
| 9–11 | ×4 |
| ≥12 | ×5 |

> 设计意图：需要连续 12 次不碰挡板才能吃满 ×5，这个门槛既给"神操作"留了空间，又不至于让普通玩家轻易滚雪球。炸弹砖连锁能快速拉高 combo，是刻意设计的"爽点爆发"。

### 2.3 最高分
- 每局结束（GameOver / Finish）时，`if score > bestScore → bestScore = score`，写入存档（S8）。

## 3. 输入
- `brick:destroyed`（来自 S4）→ 累加 combo、结算分数。
- `ball:hitPaddle`、`ball:lost`（来自 S3）→ 重置 combo。

## 4. 输出与反馈
| 时机 | 表现 |
|---|---|
| 每次计分 | 砖块位置弹出分数飘字（`+100`），600ms 上浮淡出 |
| 倍率提升 | HUD 连击数放大脉冲 1.3×(120ms) + 音阶上扬一级 |
| combo 归零 | 连击数字淡出 200ms（不做惩罚动画，避免挫败） |
| 最高分刷新 | 结算面板金色"NEW BEST"标签 |
| HUD 常驻 | `分数` 左上大字；`×N 连击` 紧随其下（combo≥3 才显示） |

## 5. 数值
| 参数 | 值 |
|---|---|
| 基础分（N/T/S/B/G） | 100 / 250 / 0 / 150 / 500 |
| `COMBO_STEP` | 3 |
| `COMBO_MULT_MAX` | 5 |
| 分数飘字时长 | 600 ms |
| 倍率脉冲 | 1.3×，120ms |
| 连击显示阈值 | combo ≥ 3 |
| 分数上限 | 无（int32 足够：单关最多 60 砖 × 500 × 5 ≈ 150k） |

## 6. 边界条件
1. **同一帧多砖破碎**（炸弹连锁）：按**事件到达顺序**逐块计 combo（先 +1 再算倍率），因此连锁中越靠后的砖享受越高倍率——这是有意设计。
2. **倍率跨越临界**：combo 从 2→3 时，第 3 块砖本身享受 ×2（先自增 combo 再算倍率）。
3. **球撞挡板同帧破砖**：按 S1 顺序，先处理砖块计分，再处理撞板重置 —— 该砖仍计入连击。
4. **排行榜/最高分为 0**：首次游戏 bestScore 初始 0，不做特殊展示。
5. **分数溢出**：使用整数，上限远高于实际，无需处理。
6. **连击数字位数变化**：HUD 布局需容纳 `×5` 且不换行、不挤压生命图标。

## 7. 依赖
- **上游**：S4（砖块破碎）、S3（撞板/失球事件）。
- **下游**：S8（最高分持久化）、S1（HUD 更新）。
- **框架假设**：事件总线、"可暂停计时器"（飘字动画在暂停时冻结）。

## 8. 验收标准
- [ ] 破碎一块砖得分 = 基础分 × 当前倍率，且倍率阶梯完全符合上表。
- [ ] 球撞挡板后 combo 归零、倍率回到 ×1。
- [ ] 炸弹连锁 10 连能正确逐级升到 ×5。
- [ ] 倍率提升有可感知的音阶与视觉脉冲。
- [ ] 最高分在同局结束写盘，重启后仍在。
- [ ] 不出现"接球后倍率不重置"或"跨关连击残留"的 bug。
