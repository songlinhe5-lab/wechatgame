# GDD · S1 核心循环（Core Loop）

> 版本 v1.0 · 依赖：无（编排层）· 被依赖：全部

---

## 1. 目标
定义游戏的**状态机**与**主循环时序**，把所有系统按正确顺序串起来，并规定固定的 `update` 顺序，保证物理与判定不抖动。

## 2. 机制（状态机）

```
                        ┌────────┐   读存档，决定入口（无菜单）
                        │  BOOT  │
                        └───┬────┘
        ┌───────────────────┼────────────────────────┐
   首次  │          有未完成进度│            5 关全通关 │
   (stats.runs==0)         │                        │
        ▼                   ▼                        ▼
 ┌──────────────┐   ┌──────────────────┐    ┌──────────────┐
 │PLAYING · 第1关│   │PLAYING · 续进     │    │ FINISH 通关  │
 │  (READY)     │   │「上次未通关的那关」│    │   画面       │
 └──────┬───────┘   └────────┬─────────┘    └──────┬───────┘
        └──────────┬─────────┘                     │
                   ▼                    「重新挑战」│
        ┌─────────────────────┐                    │
        │ PLAYING（含 READY   │◄───────────────────┘
        │  子状态的主循环）    │
        └──┬────────┬─────┬───┘
    「暂停」│   清关  │     │命尽（最后一命且失球）
           ▼        ▼     ▼
     ┌──────────┐ ┌─────────────┐ ┌────────────┐
     │  PAUSED  │ │ LEVEL_CLEAR │ │ GAME_OVER  │
     └────┬─────┘ └──────┬──────┘ └─────┬──────┘
          │               │              │
   ┌──────┼──────┐        │下一关/1.2s自动 │「重新挑战」
   │继续   │重玩本关│      │ 或(末关)→FINISH │
   │重玩第1关│设置⚙ │     ▼              ▼
   └──────┴──────┘   PLAYING(下一关)  PLAYING(第1关)
          └──► 回 PLAYING / READY（「继续」原样恢复）
```

- **主菜单（MENU）状态已移除**（用户裁定）：启动直接进入游戏，全流程**只有 2 条路径**（直接进入 / 通关画面）。
- **READY 是 PLAYING 的子状态**：球吸附在挡板上，玩家可移动挡板，点击或 1.5s 后发球。
- `LEVEL_CLEAR` 若已是最后一关 → 进入 `FINISH`（通关画面）。
- **暂停不改变当前局状态**，仅冻结 `update`。
- **退出小游戏**由微信胶囊 / 系统返回承担，游戏内无「返回菜单」。

## 3. 输入
- `BOOT`：无输入，自动按存档决定入口（首次→L1；有进度→续进；全通关→FINISH）。
- `PLAYING`：见 S2。
- `PAUSED`：点击「继续」/「重玩本关」/「重玩第 1 关」/「设置」。
- `LEVEL_CLEAR`：点击「下一关」；1.2s 后自动进入。
- `GAME_OVER` / `FINISH`：点击「重新挑战」（回第 1 关）。

## 4. 输出与反馈
- 状态切换时对应 UI 面板的淡入淡出（见 `ux/ux-spec.md`）。
- HUD 常驻显示：分数、连击倍率、生命、关卡号、暂停按钮。

## 5. 数值（固定 update 顺序）

每帧 `dt`（秒，建议上限 clamp 到 0.05 防卡顿穿墙）按以下**固定顺序**执行：

```
1. dt = min(rawDt, 0.05)          // 防止切后台回来的大 dt 导致穿模
2. S2 读取输入 → 设置 paddle.targetX
3. S3 更新挡板位置（指数平滑趋近 targetX）
4. S3 更新每颗球位置（子步进，见下）
5. S3 碰撞检测：墙 → 挡板 → 砖块（顺序固定，避免同帧双触发）
6. S4 处理砖块命中/破碎 → 派发 brick:destroyed
7. S7 更新掉落道具位置 + 拾取判定
8. S5 结算分数/连击
9. S6 检查失球/生命/清关
10. S1 检查状态迁移
```

**子步进（防穿模）**：单帧位移 `v*dt` 若 > `BALL_R`（12px），则拆成 `ceil(v*dt / BALL_R)` 个子步，每步重新做碰撞检测。

| 参数 | 值 |
|---|---|
| 最大 dt clamp | 0.05 s |
| 物理子步阈值 | 单帧位移 ≤ BALL_R(12px) |
| 目标帧率 | 60 fps（30fps 亦须正确，靠子步保证） |

## 6. 边界条件
1. **切后台/息屏**：微信 `onHide` 自动暂停，`onShow` 回到 `PAUSED`（不自动继续，防玩家丢命）。
2. **大 dt 卡顿**：单帧 dt clamp 0.05s + 子步进，避免球穿过挡板/砖块。
3. **状态竞争**：同一帧内球既碰砖又碰墙时，**按固定顺序**（墙→挡板→砖）只结算一次，避免重复扣血/重复计分。
4. **清关与失球同帧**：若最后一块砖破碎的同帧球出界，**清关优先**（玩家不会因已清空的关卡丢命）。
5. **READY 期间输入**：允许移动挡板，但不得移动球；发球方向取挡板中心正上方。
6. **BOOT 存档异常降级**：存档越界/非法、或版本高于当前支持版本/无法识别时 → **安全降级为"首次"（进 L1）**，**降级优先于报错**，不得抛异常中断启动（细则见 `save-progress.md` §6.3 / §6.8 / §6.9）。

## 7. 依赖
- **上游**：无。
- **下游**：S2~S9 全部由本状态机调起。
- **框架假设**：需要通用 `StateMachine` 与统一 `update(dt)`（见 `systems-index.md` §5）。

## 8. 验收标准
- [ ] 能进入并用任意路径遍历全部 **6 个状态**（BOOT / PLAYING / PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH），无死状态、无卡死。
- [ ] **不存在 MENU 状态**；BOOT 依据存档正确分流入 3 个入口（首次→L1 / 有进度→续进 / 全通关→FINISH）。
- [ ] 60fps 下球速 720px/s 时**不发生穿模**（球不会穿墙/穿挡板/穿砖）。
- [ ] 从后台切回必定处于 `PAUSED`。
- [ ] 清关与失球同帧时判定为清关。
- [ ] 主循环 update 顺序固定且单元可测（可注入固定 dt 复现）。
