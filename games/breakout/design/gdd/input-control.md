# GDD · S2 输入与操控（Input & Control）

> 版本 v1.0 · 依赖：S3（需要挡板 `targetX` 接口）· 被依赖：S1

---

## 1. 目标
把"单指拖拽"转成挡板的水平目标位置，做到**0 文字教学、3 秒上手**；同时提供键盘回退方案供 PC 调试。

## 2. 机制
- **绝对跟随（主方案）**：手指在屏幕上水平移动时，挡板目标 x = 手指 x 在场地内的映射值。**不要求手指落在挡板上**——触摸屏幕任意位置即可拖动（避免"手指挡住挡板"）。
  - 落点映射：`targetX = clamp(touchX, WALL_LEFT_X + PADDLE_W/2, WALL_RIGHT_X − PADDLE_W/2)`
  - 为减少手指遮挡，手指的 y 坐标不参与运算，只取 x。
- **相对拖动（备选，设置项）**：挡板按手指位移 `Δx` 平移。默认关闭；作为可访问性选项（手指不便跨屏移动者）。
- **发球**：
  - `READY` 状态点击屏幕 → 发球。
  - 或等待 **1.5s 自动发球**（降低首次门槛）。
  - 出射方向：竖直向上 ± 随机抖动 ≤ 10°（避免完全垂直导致节奏单调）。
- **键盘回退（仅开发/PC）**：`←/→` 或 `A/D` 以 **900 px/s** 移动挡板；`空格` = 发球/暂停。

## 3. 输入
| 输入 | 触发状态 | 行为 |
|---|---|---|
| `touchStart` (按下) | READY | 发球 |
| `touchStart` (按下) | PLAYING | 开始拖拽（记录起点，用于相对模式） |
| `touchMove` | PLAYING | 更新 `paddle.targetX` |
| `touchEnd` | PLAYING | 停止更新（挡板停在原位） |
| 点击暂停按钮 | PLAYING | → PAUSED |
| `←/→`, `A/D` | PLAYING | 键盘移动（回退） |
| `Space` | PLAYING/READY | 发球 / 暂停 |

**防误触**：暂停按钮区域 `HUD_BAND` 内点击**不**触发发球；只有 `y < HUD_BAND_Y(1240)` 的点击才视为发球/拖拽。

## 4. 输出与反馈
- 拖拽中：挡板轻微跟随延迟（见 S3），产生"重量感"。
- 手指 x 与挡板目标 x 用**同一套 clamp**，手指越界时挡板贴墙（不再跟随），松开后回中无跳变。
- 发球瞬间：球体放出 80ms 拖尾 + "咻"音效。

## 5. 数值
| 参数 | 值 |
|---|---|
| 拖拽模式默认 | 绝对跟随 |
| 键盘移动速度 | 900 px/s |
| 自动发球延迟 | 1.5 s |
| 发球随机抖动 | ≤ ±10° |
| 触摸采样 | 直接使用事件回调，不插值（挡板侧做平滑） |
| HUD 禁触带 | y ≥ HUD_BAND_Y(1240) |

## 6. 边界条件
1. **多点触摸**：只取**第一个触点**（`touchStart` 的 `id`），后续触点忽略，防止多指打架。
2. **手指滑出屏幕**：`touchEnd` 未见时（如滑出），按最后一次有效 `touchMove` 的 x 定格，并停止跟随。
3. **拖拽中切后台**：进入 PAUSED，清空拖拽状态；回到前台后不自动继续拖拽。
4. **点击发球 vs 拖拽冲突**：`READY` 点击既可能发球又可能开始拖拽 → 规则为"发球优先，且该次触摸同时作为拖拽起点"。
5. **键盘与触摸同时**：以**最后发生的输入源**为准（不做叠加）。
6. **横屏/异常宽高比**：触摸坐标须先经画布坐标转换（`convertToNodeSpaceAR`），再套 clamp。

## 7. 依赖
- **上游**：S3 必须暴露 `paddle.setTargetX(x)` 与 `paddle.getX()`。
- **下游**：S1 状态机。
- **框架假设**：`onTouchStart/Move/End` 已统一封装鼠标与触摸。

## 8. 验收标准
- [ ] 单指在屏幕任意位置水平拖动，挡板都能跟手，且**手指不遮挡挡板**。
- [ ] 挡板不会超出左右墙（clamp 生效）。
- [ ] 首次进入 READY，1.5s 内无操作会自动发球。
- [ ] 双指操作时只有一指生效，无抖动。
- [ ] 手指拖出屏幕后挡板停止跟随，不出现"粘滞"或跳变。
