# GDD · S6 生命与失败重开（Life / Game Over / Retry）

> 版本 v1.0 · 依赖：S3（失球事件）、S4（清关事件）· 被依赖：S8

---

## 1. 目标
提供**低挫败、快重开**的失败体验：失球只扣 1 命并立即回到可玩状态，GameOver 一键重开且进度不丢。契合微信场景"随时能走、回来能继续"。

## 2. 机制

### 2.1 生命
- 进入第 1 关 `lives = START_LIVES = 3`。
- 每次 `ball:lost` 且**该球是最后一颗在场球**时：`lives -= 1`。
- `lives == 0` → 进入 `GAME_OVER`。
- 生命上限 `MAX_LIVES = 5`（加命道具不可突破）。

### 2.2 失球 → 复位流程
```
ball:lost
  ├─ 若场上还有其他球在飞 → 不扣命，继续（多球机制）
  └─ 若这是最后一颗球：
        lives -= 1；combo 重置
        若 lives > 0 → 回到 READY（球重新吸附挡板，1.5s 后自动发球）
        若 lives == 0 → GAME_OVER
```

### 2.3 失败与结束
- **GAME_OVER**：显示本局分数、最高分、**「重新挑战」按钮**（回第 1 关）。**无「返回菜单」**（主菜单已移除）。
- **重新挑战（Retry）**：从**第 1 关**重新开始（本局分数清零）——注意"本局"与"解锁进度"是两回事。
- **FINISH（通关）**：打完第 5 关 → **通关画面**（总得分 + 最高分 + 「重新挑战」），与 GAME_OVER 共用同一面板组件、标题不同。

### 2.4 进度保持
- 失球、重新挑战、GameOver **都不清除**已解锁关卡与最高分（仅清除本局分数与连击）。

## 3. 输入
- `ball:lost`（S3）
- `level:cleared`（S1）
- UI：重新挑战（GAME_OVER / FINISH）；「下一关」在 LEVEL_CLEAR 面板（见 S1 / `ux/ux-spec.md` §2）

## 4. 输出与反馈
| 时机 | 表现 |
|---|---|
| 失球 | 底部红线闪 300ms + 球体碎裂粒子 + "剩余球数"从 HUD 球点序列消失（200ms） |
| 剩 1 命 | HUD 生命图标变红 + 微弱红晕呼吸（提醒风险） |
| 最后一次失球 | 球速瞬时慢放 0.3×，持续 400ms，再切入 GameOver（强化"终点感"） |
| GameOver | 面板从底部滑入 300ms；最高分刷新时金色"NEW BEST" |
| 重开 | 立即开始，无加载、无二次确认（低挫败） |

## 5. 数值
| 参数 | 值 |
|---|---|
| `START_LIVES` | 3 |
| `MAX_LIVES` | 5 |
| 失球红线闪烁 | 300 ms |
| 终局慢放 | 0.3×，400 ms |
| GameOver 面板入场 | 300 ms 上滑 |
| 命点消失动画 | 200 ms |

## 6. 边界条件
1. **多球同帧全失**：按"最后一颗球"规则只扣 1 命（不可能一帧扣多命）。
2. **失球同帧破最后一块砖**：清关优先（S1 §6.4），不扣命，直接 LEVEL_CLEAR。
3. **加命已达上限**：捡到加命道具但 `lives == MAX_LIVES` → 转化为 **+500 分**（不浪费道具，且不破坏上限）。
4. **终局慢放期间暂停**：慢放属于表现层，必须随暂停一起冻结，不得在暂停时继续倒计时。
5. **重开时长按/连点**：重开按钮加 300ms 去抖，防一次点击触发多次重置。
6. **READY 状态下反复失球**：READY 不产生失球（球固定在挡板上）；自动发球 1.5s 从 `PAUSED→PLAYING` 返回时重新计时。

## 7. 依赖
- **上游**：S3（失球）、S4/S1（清关）。
- **下游**：S8（记录最高解锁关卡）。
- **框架假设**：可暂停/可变速率（慢放）的 `update`。

## 8. 验收标准
- [ ] 单球丢失扣 1 命；多球时丢一球不扣命。
- [ ] 3 命耗尽准确触发 GameOver，不早不晚。
- [ ] GameOver 后点重开从第 1 关开始，本局分数清零、最高分保留。
- [ ] 加命到 5 后再捡加命转为 +500 分。
- [ ] 终局慢放不早于失球、不晚于 GameOver，且暂停时冻结。
- [ ] 清关与失球同帧时判定为清关（不扣命）。
