## 2. 依赖排序（Dependency Order）

依赖 = 箭头指向的对象必须先存在。**实现顺序即此拓扑序。**

```
S1 核心循环（状态机骨架）
      │
      ├─► S3 挡板与球物理 ──► S2 输入与操控（输入驱动挡板）
      │            │
      │            └─► S4 砖块与命中 ──► S7 道具系统（砖块破碎触发掉落）
      │                        │
      │                        └─► S5 计分与连击（砖块破碎触发计分）
      │                                    │
      └─► S6 生命与失败重开（依赖球越界判定）  │
                  │                          │
                  └──────────► S8 存档与进度（记录进度/最高分）◄─ S5
                                          │
                              S9 暂停与设置（控制 S1 状态 + 写 S8）
```

**关键依赖约束**
- S2 依赖 S3：挡板必须先有 `setTargetX()` 接口，输入才有意义。
- S4 依赖 S3：命中判定需要球的圆与砖块的矩形做 AABB / 圆-矩形检测。
- S5 依赖 S4：计分事件的触发源是"砖块破碎"事件。
- S7 依赖 S4：道具掉落由"砖块破碎"事件概率触发。
- S8 依赖 S5 + S6：存档内容含最高分（S5）与最高解锁关卡（S6 通关事件）。
- S9 依赖 S1 + S8：暂停是 S1 的一个状态；设置项持久化走 S8。

## 3. 全局数值基线（Global Constants）· ❄️ 冻结令

> **全工作室唯一真源**（Single Source of Truth）——**适用范围：游戏数值与常量**（分辨率 / 场地 / 砖块 / 球 / 挡板 / 道具 / 规则量 / 包体）。任何策划文档、美术文档或工程代码引用这些常量时，**只引用常量名，不重复定义数值**；发现不一致以本节为准并回写。
> **刻意例外（不属本真源）**：**存档键名与存档数据结构**归**代码**（`save-schema.ts`）定义——因为键名需带平台命名空间（`wxgame.`），由代码侧统一管理更安全。详见 `gdd/save-progress.md` §5。**此为例外，而非真源失效。**
> **冻结状态**：2026-09-11 经主理人确认冻结。设计分辨率锁定 **750 × 1334**（曾评估改 720×1280，因美术/工程/策划三方已自洽于 750×1334 而**否决**；判例见 `design/design-review.md` §11）。
> 单位：px（设计逻辑像素）/ 秒 / 度 / 倍率。
>
> **使用约定（强制）**：
> 1. **后续各 GDD / UX / 关卡文档章节一律引用本节常量名，禁止重复写死数值**；确需展示数值时须标注"来源：`systems-index §3`"。
> 2. 发现任何文档或代码与本节不一致 → **以本节为准**，并回写对应文档（经主理人中转）。
> 3. 修改本节须经主理人确认，并在 §6 变更记录登记。

### 3.3 砖块网格（Brick Grid）
| 常量 | 值 | 说明 |
|---|---|---|
| `BRICK_COLS` | 10 | 列数 |
| `BRICK_MAX_ROWS` | 6 | 最大行数 |
| `BRICK_W` | 62 | 砖块宽 |
| `BRICK_H` | 34 | 砖块高 |
| `BRICK_GAP_X` | 6 | 列间距 |
| `BRICK_GAP_Y` | 6 | 行间距 |
| `BRICK_START_X` | 38 | 第 0 列砖块**左边缘** x |
| `BRICK_TOP_Y` | 1200 | 第 0 行砖块**上边缘** y |
| 砖块 pitch | **68 × 40** | 列 pitch = BRICK_W + BRICK_GAP_X = 62+6 = 68；行 pitch = BRICK_H + BRICK_GAP_Y = 34+6 = 40 |
| `BRICK_ROW_PITCH` | 40 | 行间距 = BRICK_H + BRICK_GAP_Y |

**派生公式**
- 列中心：`colCenterX(j) = 69 + 68 * j`（j=0..9；69 = 38 + 62/2，68 = 62+6）
- 行中心：`rowCenterY(i) = 1183 − 40 * i`（i=0..5；1183 = 1200 − 34/2）
- 校验：最右砖右边缘 = `colCenterX(9) + 31 = 712 ≤ WALL_RIGHT_X(720)` ✓

### 3.8 包体预算（⚠️ 区分「平台红线」与「内部目标」，勿混用）

**① 平台红线（微信硬约束，不可越）**
| 项 | 上限 |
|---|---|
| 主包 | **≤ 4096 KB（4 MB）** |
| 主包 + 分包合计 | ≤ 30720 KB（30 MB） |

**② 内部目标（我们自设，比红线更严 → 程序侧按此做，勿以红线当目标）**
| 项 | 目标 / 上限 | 说明 |
|---|---|---|
| **demo 主包合计** | **≤ 2000 KB** | 留 ≥2000 KB 安全余量 |
| ├ 引擎运行时（裁剪后） | ≤ 1800 KB | 仅勾选 2D / Graphics / Tween / Label |
| ├ 业务代码（不含引擎） | ≤ 400 KB | — |
| ├ 美术位图 | **0 KB** | 全程序化绘制，不占主包 |
| └ 其他（配置/字体等） | ≤ 100 KB | 系统字体，无字体文件 |
| 权威来源 | `art/assets-spec.md` §5 | |

> **口径提醒**：**4096 KB 是红线、2000 KB 是我们的目标**——两个数字都对但层级不同。分项（引擎/业务/…）为**预算上限**，加总可高于 2000 KB，实际以**合计 ≤ 2000 KB** 为准。程序侧请按 2000 KB 目标做，红线仅作最后兜底。

## 4. 事件总线约定（供程序落码参考）

系统间通过事件解耦，建议事件名（字符串常量）：

| 事件 | 载荷 | 发出者 → 订阅者 |
|---|---|---|
| `ball:hitPaddle` | `{ x: number }` | S3 → S5（重置连击）、S9（音效） |
| `ball:hitBrick` | `{ brickId, hpAfter }` | S4 → S5（若非破碎则不计分）。**实现口径（G4 回归裁定 2026-09-11）**：拆分为 `steel:hit`（钢砖）/ `brick:damaged`（扣血未碎）/ `brick:destroyed`（破碎）三事件，语义全覆盖本行——代码不改，文档按实现回写 |
| `brick:destroyed` | `{ brickId, type, x, y }` | S4 → S5（计分）、S7（掉落）、S1（检查清关） |
| `ball:lost` | `{ ballId }` | S3 → S6 |
| `life:changed` | `{ lives }` | S6 → S1（HUD） |
| `score:changed` | `{ score, combo, mult }` | S5 → S1（HUD） |
| `level:cleared` | `{ levelId, score }` | S1 → S6、S8 |
| `game:over` | `{ finalScore }` | S6 → S1、S8 |
| `powerup:picked` | `{ type }` | S7 → S3/S5/S6 |

> 事件名与载荷为**建议**，最终以程基岩的框架实现为准；若框架事件命名不同，需回写本文档对齐（经主理人中转）。

## 5. 与框架层的接口假设（待程基岩确认）

本设计**假设**框架（`@wxg/framework`）提供以下能力，若不成立需调整设计：

1. **输入抽象**：`onTouchMove/onTouchStart/onTouchEnd` 统一封装鼠标与触摸（PC 调试用）。
2. **存档抽象**：`Storage.get/set(key, value)` 封装 `wx.setStorageSync` / localStorage。
3. **状态机**：`StateMachine` 通用实现（用于 S1）。
4. **计时**：统一的 `update(dt)` 驱动 + 可暂停的计时器（用于道具倒计时，暂停时冻结）。
5. **音频**：`Audio.play(id)` 走平台封装（用于反馈音效）。
6. **资源释放**：多球/道具频繁创建销毁需要对象池（性能）。

> 上述 6 条为**设计侧依赖清单**，第 6 条（对象池）为性能红线，建议 MVP 即纳入。
