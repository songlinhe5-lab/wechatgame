# GDD · S4 砖块类型与命中规则（Bricks）

> 版本 v1.0 · 依赖：S3（球圆数据）· 被依赖：S5（计分）、S7（掉落）、S1（清关）

---

## 1. 目标
用**数据驱动**的方式定义砖块：类型 → 生命值 / 得分 / 特殊行为，全部来自关卡 JSON，程序无需为每关写逻辑。命中反馈须即时可读（血量为 2 的砖块要"看得出来还差一下"）。

## 2. 机制

### 2.1 砖块类型
| 代码 | 名称 | HP | 破碎得分 | 不可破坏 | 特殊行为 |
|---|---|---|---|---|---|
| `N` | 普通砖 | 1 | 100 | 否 | — |
| `T` | 硬砖 | 2 | 250 | 否 | 命中 1 次后变为"受损态"（颜色变暗/裂纹） |
| `S` | 钢砖 | — | 0 | **是** | 永不破碎，只反弹；不计入清关条件 |
| `B` | 炸弹砖 | 1 | 150 | 否 | 破碎时引爆：对中心半径 `EXPLODE_R` 内其他砖块造成 1 点伤害 |
| `G` | 金砖 | 1 | 500 | 否 | 高分，掉落道具概率 ×3 |

> **5 类砖块（N / T / S / B / G）全部属 MVP，均已实装**（用户裁定；关卡数据 `levels-01-05.json` 的 L3/L4/L5 已实际使用 `S` / `B` / `G`）。**砖块不存在"应有/降级"层** —— demo 中唯一降级的是**道具**（6 定义 / MVP 实装 3 种，见 `gdd/powerups.md` §2.2）。类型定义见 `levels/levels.schema.ts` 的 `BrickTypeDef`。

### 2.2 命中判定（圆–矩形）
```
最近点 = clamp(ball.pos, rect.left, rect.right) × clamp(ball.pos, rect.top, rect.bottom)
if distance(ball.pos, 最近点) ≤ BALL_R  → 命中
```
**反弹轴向**：取球心到最近点的**最小穿透轴**（|penX| vs |penY|），翻转该轴方向分量，并把球推回到矩形外。避免"角碰撞双轴翻转"导致方向错乱。

### 2.3 命中结算
```
brick.hp -= 1（S 类型的 hp 记为 Infinity，不减）
if brick.hp ≤ 0:
    移除砖块 → 派发 brick:destroyed { type, x, y }
else:
    进入受损态 → 派发 ball:hitBrick { hpAfter }（不计分、不掉落）
```

### 2.4 炸弹连锁
- 炸弹破碎时，对 `EXPLODE_R` 范围内其他砖块各扣 1 HP，**递归**触发其破碎判定（连锁炸弹）。
- 递归深度上限 **8 层**（防死循环/性能雪崩），超出则忽略。
- 连锁破碎的砖块**计入连击与计分**（炸弹是"制造连击"的核心机制）。

### 2.5 清关条件
- **可破坏砖块全清** → 派发 `level:cleared`。
- 钢砖（`S`）**不计入**清关条件（否则无法通关）。

### 2.6 特殊砖块逐类定义（`N` / `T` / `S` / `B` / `G`）

> 每类给出：**血量 / 分值 / 行为 / 边界条件**。数值与 `levels/levels-01-05.json` 的 `brickTypes` 一一对应，属全局冻结常量。

#### `N` 普通砖（Normal）
| 项 | 定义 |
|---|---|
| 血量 | 1 |
| 分值 | 100（× 连击倍率） |
| 行为 | 命中 1 次即破碎；标准反弹（见 S3 §2.3） |
| 边界条件 | ① 破碎计入连击；② 破碎触发掉落判定；③ 空位 `'.'` 不生成节点 |

#### `T` 硬砖（Tough）
| 项 | 定义 |
|---|---|
| 血量 | **2** |
| 分值 | 250（**仅在破碎时结算**，第一次命中不计分） |
| 行为 | 第一次命中 → HP 2→1，进入**受损态**（亮度 −30%、裂纹加深），不计分、不掉落、不触发 `brick:destroyed`；第二次命中 → 破碎、计分、掉落判定 |
| 边界条件 | ① 受损态必须**视觉可辨**（不靠颜色，靠裂纹）；② 重开关卡须完整重置 HP 与裂纹视觉；③ 炸弹爆炸每砖仅扣 1 点 HP（硬砖需被波及 2 次才碎） |

#### `S` 钢砖（Steel）· 不可破坏
| 项 | 定义 |
|---|---|
| 血量 | **∞**（不可破坏；内部建议用 `hp = Infinity` 或 `-1` 哨兵，`indestructible: true`） |
| 分值 | **0**（命中不加分、不计连击） |
| 行为 | 受球撞击 → 镜面反弹、砖块**不消失**；播放火花粒子 + 金属音（区别于普通砖） |
| **是否计入通关条件** | **否**。清关仅由"可破坏砖全清"触发；钢砖残留不影响通关 |
| **是否受道具影响** | **完全免疫**：① 炸弹爆炸不对钢砖造成伤害、不破碎、不触发二次爆炸；② 激光（若实装）对钢砖无效；③ 不因任何道具被移除 |
| 事件 | 被撞时派发 `ball:hitBrick`（仅供音效/火花），**永不派发 `brick:destroyed`** |
| 边界条件 | ① 炸弹连锁波及钢砖 → 免疫；② 可破坏砖清空而钢砖仍在 → **立即判清关**（S4 §6.7 兜底）；③ 钢砖总量须 ≤ 全关 20%（设计约束） |

#### `B` 炸弹砖（Bomb）
| 项 | 定义 |
|---|---|
| 血量 | 1 |
| 分值 | 150（**自身破碎**计入连击与倍率） |
| 行为 | 被击中 1 次即破碎；破碎瞬间**引爆**，对范围内其他砖块造成 1 点伤害并递归触发其破碎判定 |
| **爆炸范围** | 半径 **68 px**，按**砖块中心**欧氏距离判定（约覆盖相邻 1 圈砖块） |
| **连锁规则** | 范围内砖块受伤 → 若因此破碎且其本身也是炸弹 → 继续引爆；**递归深度上限 8 层**，超出忽略 |
| **是否伤及己方砖块** | **会波及同场其他砖块**（普通/硬砖/炸弹/金砖均可被炸）；**不伤及**：钢砖（免疫）、玩家（挡板 / 球 / 生命 / 分数均无直接影响） |
| **连锁计分** | 连锁破碎的砖块**正常计分并计入连击**（按事件到达顺序逐块累加 combo）→ 炸弹是"制造连击爆发"的核心机制 |
| 边界条件 | ① 连锁引爆最后一块可破坏砖 → 触发清关；② 递归 8 层即止（防性能雪崩/死循环）；③ 范围判定以砖块中心为准，非矩形相交；④ 炸弹被另一炸弹波及同样引爆（可连环） |

#### `G` 金砖（Gold）· 高价值
| 项 | 定义 |
|---|---|
| 血量 | 1 |
| 分值 | **500**（普通砖的 5 倍）× 连击倍率 |
| 额外收益规则 | 掉落率 = `powerupDropRate × 3`（**封顶 1.0**）。例：L2/L4 基础 0.14 → 金砖 0.42 |
| **是否必掉道具** | **否 —— 已裁定维持"非必掉（×3 倍率）"，不改 JSON**。裁定理由（2026-09-11 主理人）：① 金砖已有 500 分的明确即时奖励，再叠加"必掉道具"会成为**双重奖励**，反而削弱其余砖块的策略价值（玩家会无脑只盯金砖）；② ×3 倍率保留了"掉了是惊喜"的随机张力，与支柱 3「一关一节奏」一致；③ 不动 JSON 即少一个改动面，避免再次触发跨文档核对。**此结论为终裁，勿反复** |
| 行为 | 命中 1 次即破碎；作为高价值目标，鼓励优先瞄准 |
| 边界条件 | ① 破碎计入连击与倍率；② 可被炸弹连锁引爆（**引爆亦按金砖倍率判定掉落**）；③ 场上道具已达上限 3 时，判定掉落也不生成（丢弃）；④ 黑白/色盲下靠**星标图标**区分（不靠金色） |

## 3. 输入
- 关卡加载：读取 `level.rows` + `level.brickTypes`，按网格常量实例化砖块。
- 球碰撞事件（来自 S3）。
- 炸弹连锁（内部）。

## 4. 输出与反馈
| 事件 | 表现 |
|---|---|
| 命中但未破碎（硬砖） | 砖块 80ms 白闪 + 轻微缩放 1.06；碎裂纹路叠加 |
| 破碎 | 同色粒子爆发（8~12 粒）+ 砖块 160ms 缩放淡出 + 分数飘字 |
| 钢砖被撞 | 金属音 + 火花粒子（区别于普通砖）+ 砖块不消失 |
| 炸弹爆炸 | 400ms 冲击波圆环 + 屏震 120ms + 低沉爆炸音 |
| 金砖破碎 | 金色粒子 + 特殊音效 |

## 5. 数值
| 参数 | 值 |
|---|---|
| `BRICK_W × BRICK_H` | 62 × 34 px |
| `EXPLODE_R`（炸弹） | 68 px（约覆盖相邻 1 圈砖块） |
| 爆炸伤害 | 1 HP / 每砖 |
| 连锁递归上限 | 8 层 |
| 金砖掉落倍率 | ×3 |
| 受损态视觉变化 | 亮度 −30%，叠加裂纹 |
| 破碎粒子数 | 8~12 粒，寿命 300ms |

## 6. 边界条件
1. **球同时命中两块砖**（正好落在砖缝）：只结算**最近**的一块（按球心距离），另一块下帧再判（因为球已反弹离开）。
2. **炸弹连锁引爆钢砖**：钢砖不受爆炸伤害（HP=Infinity）。
3. **炸弹连锁把最后一块砖炸掉** → 正常触发 `level:cleared`；同帧球出界 → 清关优先（S1 §6.4）。
4. **空行/空列**：JSON 中 `.` 表示空位，实例化时跳过，不生成节点。
5. **行列数越界**：布局行长度必须 = `cols`；不足处补 `.`，超出报错（开发期断言）。
6. **受损硬砖中途重开**：重开关卡必须**完整重置砖块 HP 与视觉**（不能残留裂纹）。
7. **钢砖围死可破坏砖**：关卡设计阶段禁止（见 `levels-spec.md` 设计约束），运行时若检测到"仅剩钢砖+无可破坏砖但未清关"→ 强制判清关（兜底）。

## 7. 依赖
- **上游**：S3（球圆与位置）、关卡数据。
- **下游**：S5（`brick:destroyed` → 计分）、S7（`brick:destroyed` → 掉落）、S1（清关检查）。

## 8. 验收标准
- [ ] 5 关 JSON 能被加载并正确还原布局（行列、空位、类型都对）。
- [ ] 硬砖需 2 次命中才破碎，且第一次命中后**视觉可辨**。
- [ ] 钢砖永不破碎，且不计入清关。
- [ ] 炸弹砖能连锁引爆相邻砖（含嵌套炸弹），连锁上限 8 层生效。
- [ ] 可破坏砖清空即派发 `level:cleared`；只剩钢砖时也能正确清关。
- [ ] 重开关卡后所有砖块 HP 与视觉完全重置。
