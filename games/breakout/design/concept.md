## 1. 一句话定位

> 一根手指拖住挡板，让弹球在霓虹墙上撞出连击——单关约 45~90 秒、随时可放下的微信小游戏打砖块。

## 2. 为什么是它（Demo 验证价值）

打砖块在**一款游戏内**同时覆盖框架的全部关键能力，是性价比最高的"框架验收器"：

| 框架能力 | 在打砖块中的落点 |
|---|---|
| 输入 | 触摸拖拽（挡板）+ 点击（发球/暂停/道具） |
| 碰撞 | 球-墙、球-挡板、球-砖（含角度反弹） |
| 数据驱动 | 关卡以 JSON 描述，改数据即改关卡 |
| 计分/连击 | 分数 + 连击倍率 + 最高分 |
| 生命/失败/重开 | 3 命 → GameOver → 一键重开 |
| 存档 | 解锁进度、最高分、设置本地持久化 |
| 暂停 | 任意时刻暂停/继续、重玩本关、重玩第 1 关 |

这决定了本 Demo 的验收标准是**"一天内手感成型"**，而非商业完成度。

## 3. 设计支柱（Design Pillars）

> 支柱 = 一切设计取舍的裁决标准。冲突时按序号优先。

1. **一指可得（Instant Control）**：单指拖拽即可完成全部核心操控，**0 文字教学、3 秒上手**。任何需要第二根手指或阅读说明书的设计一律砍掉。
2. **一击有回响（Juicy Feedback）**：每一次碰撞都必须有即时、可读的视听反馈（缩放/粒子/音效/分数飘字），连击时反馈强度递增，把"打中"变成"爽"。
3. **一关一节奏（Readable Ramp）**：关卡完全数据驱动，难度可读、可调、可回归；**每关只引入一个新变量**，玩家不需要同时学两件事。

## 4. MDA 分析（Mechanics → Dynamics → Aesthetics）

### Mechanics（机制 · 系统做了什么）
- 挡板沿一维（水平）移动；球与挡板/墙/砖发生镜面反弹。
- 砖块有生命值（1~2 点），命中扣血，归零破碎并计分。
- 破碎砖块按概率掉落道具（加宽挡板 / 三球 / 加命）。
- 连击计数：球不碰挡板期间连续破砖累积连击，倍率随连击递增。
- 生命 3 点，球落出底部即扣 1 命，归零结束。

### Dynamics（动态 · 玩家实际产生的行为）
- **角度控制（English/Spin）**：球撞挡板时出射角由落点决定 → 玩家从"被动接球"变成"主动瞄准"，这是技巧上限的来源。
- **风险决策**：接住球会**重置连击**，但保命；玩家在"追连击"与"保命"间持续权衡。
- **道具改写节奏**：加宽=容错、三球=混乱高收益、加命=续航；三者为 MVP 实装，让每局体验有可控的变奏。（Should：减速球可进一步强化「掌控感」，本期不承诺。）
- **资源管理**：有限生命 = 天然难度旋钮，无需硬性失败墙。

### Aesthetics（美学 · 玩家获得的情感）
- **Sensation（感觉）**：撞砖的顿帧、粒子、音效 → 纯粹的手感快感（首要）。
- **Challenge（挑战）**：角度控制与连击风险 → 技巧成长空间。
- **Discovery（发现）**：道具与关卡新砖型 → 每关一点点新鲜感。
- **Submission（沉浸/放空）**：单关约 45~90 秒、无需投入 → 微信场景下的"随手一局"。

> 自洽性检查：三条支柱分别对应 Sensation / Challenge / Discovery 三个主美学，Submission 由短局形式承载，无支柱打架（详见 `design-review.md`）。

## 5. 目标玩家（Bartle 类型）

- **首要：Achiever（成就型）** —— 驱动来自"推关 + 刷新最高分"，故必须有清晰的关卡进度、分数与最高分展示。
- **次要：Explorer（探索型）** —— 驱动来自"发现道具组合与关卡花样"，故每关引入新变量。
- **非目标：Killer / Socializer** —— 无 PVP、无强社交。**明确不做**：排行榜社交、好友对战、公会。

场景画像：微信里被分享/推荐点进来的**碎片时间玩家**，单手竖屏，期望"点开即玩、不注册、随时能走"。

## 6. 心流与难度曲线思路

- **心流通道**：难度 ≈ 技能。前 3 关刻意简单（教学 + 建立信心），第 4 关起引入真实威胁。
- **难度旋钮（按优先级）**：
  1. 基础球速：`BALL_SPEED_BASE` = 480 px/s（来源：`systems-index` §3.4）；关卡/概念层递进目标约为每关 +20 px/s 至约 560（**非 §3 新冻结**，以关卡 JSON 覆盖为准）
  2. 砖块总数与总血量（清关工作量）
  3. 新砖型（硬砖/钢砖/炸弹/金砖，一次一个）
  4. 道具掉落率（随机性调味）
- **单关时长目标**：45~90 秒（低于 45s 太空，高于 90s 挫败）。此为**概念层体验目标**，**非** `systems-index` §3 冻结常量。
- **失败成本**：极低——重开 1 次点击、进度不丢。**不做**扣分惩罚。
- **连击正反馈**：连击倍率给"操作好"的正向奖励，但接球即重置，避免无限滚雪球导致失衡。

> L4 硬砖约 40%、L5 硬砖约 29% 等比例为关卡设计口径（见决策表与 `design-review.md`），**非** §3 全局常量。

## 7. 范围分层（Scope Layering）

### MVP（必须，Demo 验收线）
- 5 关，数据驱动（`levels/levels-01-05.json`）
- 单球 + 挡板拖拽操控（含键盘方向键供 PC 调试）
- **砖块 5 类全部实装**：`N` 普通 / `T` 硬砖（2 血）/ `S` 钢砖（不可破坏）/ `B` 炸弹砖（连锁）/ `G` 金砖（高分）——定义与数值见 `gdd/bricks.md` §2.6 与 `gdd/systems-index.md` §3
- 计分 + 连击倍率 + 最高分
- 3 命 / 失球 / GameOver / 重新挑战
- 暂停（含重玩本关、重玩第 1 关、设置）
- 本地存档（解锁进度 + 最高分 + 设置）
- **道具：6 种定义 / MVP 实装 3 种**（加宽挡板 / 三球 / 加命）

> **口径澄清**：MVP 降级的**只有道具**（6 定义中实装 3 种）。**5 类砖块全部属 MVP**——因为关卡数据 `levels-01-05.json` 已实际使用 `S/B/G`，且 L4/L5 硬砖比例（关卡层，非 §3 全局常量）的难度设计正是靠 `T`/`S` 承载；降级声明会与数据自相矛盾。

### 应有（Should，时间允许则做）
- 未实装的道具：减速球 / 磁吸球（`slow` / `sticky`）
- 关卡选择与关卡解锁展示
- 设置项：音效/音乐/震动开关（**注**：设置项本身属 MVP，此处指"关卡选择"扩展）
- 连击音效音阶递增

### 可选（Could，锦上添花）
- 激光道具、屏震、过关彩带粒子、每日挑战、皮肤/主题切换

### 明确砍掉（Won't · 本期不做，附理由）
| 砍掉项 | 理由 |
|---|---|
| 在线排行榜 / 微信开放数据域排行 | 需后端与登录，超出 Demo 范围 |
| 账号 / 云存档 | Demo 无账号体系，框架层未就绪 |
| 内购 / 激励视频广告 | 商业化不在本轮验证目标内 |
| 多人 / 好友对战 | 与"随手一局"定位冲突，成本高 |
| 关卡编辑器 / 程序化生成 | 5 关手写数据足够验证数据驱动能力 |
| 皮肤商店 / 成就系统 | 认知与实现成本高，收益低 |
| 体力/能量系统 | 与"随时能玩"支柱直接冲突 |

## 8. 视觉锚点（一句话）

> **"霓虹街机"**：深空蓝紫底色，砖块为高饱和发光色块（按砖型区分色相），碰撞瞬间爆出同色粒子——冷背景 + 暖爆炸的强对比。

> 具体色彩、字号、动效曲线由林绘澄（美术）在 `games/breakout/art/art-bible.md` 落地；本概念仅提供方向锚点与"碰撞必须爆彩"的表达性要求。
