## 1. 去网格纹理 / 底衬降噪（差距 #2）★ 优先

**现状**：盘面每格画 B0 目标色底图（`view-model::drawTargetTile`，:106/:802；
WXG-T-242 裁定 B0 用 `cx` 不吃 `dx`），空格另有凹槽纹理；珠体经
`BEAD_DRAW_INSET` 等比内缩（`bead-render::drawFilledBead`，WXG-T-169 比例制裁定，
替 ADR-0015 C-5「保持绝对」）露出底图 ⇒ 珠缝全是蓝虚线网格。

**目标**：`handdrawn` 档下珠缝露**干净底色**（参考图），其余风格逐字节不变。

**实现路径（最小档）**：
1. view-model 按 `beadStyle` 分流：`handdrawn` 档**跳过槽纹理**、B0 底图降为
   「仅空格显示」（有珠格不画底图边饰）；
2. `handdrawn` 档的珠体 `drawInset` 传小值或 0（通道已存在：
   `FilledBeadOptions.drawInset`，EP11-S5 豆径档覆写口）⇒ 严丝合缝由风格侧达成，
   ⛔ 不动全局 `BEAD_DRAW_INSET` 常量。

**牵动判据**：
- ⚠ **目标色可读性**是本仓盘面设计承重（B0 底图 = 「这格该放什么色」的主通道，
  K3 孔透目标色是满豆档底盘可读唯一通道）。有珠格去底图不影响（珠即已放对/放错的
  答案）；**空格**的底图必须保留，否则玩法信息丢失。此条要在美术侧（art-director）
  过审后才动码。
- 「按风格覆写底衬」无在册先例 ⇒ 属新决策，需 ADR 或至少 systems-index 登记；
  L5（UI 不持有状态）不破——纯渲染分流。
- 测试面：`bead-size-tier` 矩阵腿自动覆盖新档；封箱类「1 点击=1 珠」不受渲染侧影响。

**量级 M**：view-model 分流 + 一条风格档表 + 测试钉值；不动玩法层。

## 2. 盘面剪影描边（差距 #1）

**现状**：void 格（关卡数据 `.`，`grid.ts`）全链「不存在」语义：不画、不命中、
不消费、不触发波浪（§1.6.7 判例五处拦截）；盘面外缘 = 有效格的阶梯边。

**目标**：沿「有效格连通域外边界」画一条**连续手绘风描边**（粗黑、微歪）。

**实现路径**：
1. 边界折线提取 = 逐有效格查 4 邻，缺邻边收进边集，串成有序环（单遍 O(cells)，
   关卡加载期算一次进渲染缓存 ⇒ 热路径零分配可守）；
2. 渲染 = 若干 `line`/stroke polygon 命令画在 B0 之下或盘框之上（层次要定：
   描边压在珠下最干净）；
3. 手绘感 = 顶点沿边界法线加**静态整数偏移表**（同 `handdrawn.ts` 纪律：⛔ rng，
   L4 不破）；
4. 多连通域/带洞（树干与树冠相连、心形无洞，但数据上可能出洞）⇒ 边界提取必须
   支持内洞（洞沿反向环），或首版声明「仅外轮廓」。

**牵动判据**：
- void「不存在」语义只约束**玩法层**；渲染层画一条经过格缘的装饰线不违 §1.6.7，
  但**不得产生可点热区**（命中仍走 `hitGridCell` 格心制，零变）；
- 描边伸出 bbox ⇒ 与 fit 档（WXG-T-262 `BOARD_FIT_MARGIN=24`、`clampCamera` 操作
  窗口）的关系要核：描边宽 ≤ margin 则夹取账不动；
- 命令增量按 K-051 落码差分复算，别沿用推论值。

**量级 M**：一个纯函数（边界提取，可 Node 单测）+ view-model 一条画线腿 + 单测。

## 3. 大块连通色区底图（差距 #3/#7）

**现状**：关卡数据逐格 `colorIdx`；同色相邻格已天然连片，但 B0 仍逐格画 ⇒ 缝可见。
参考图的「树冠一整片绿」= 底衬按**连通同色区**铺，珠缝透出大区色，且区内有明暗
变体（= 限色数据侧的深浅色号）。

**路径**：§1 做完后本条收益减半（缝里已是干净色）；剩余 = 连通区找边界 + 区域级
铺色（可复用 §2 的边界提取）+ 关卡数据侧变体色语法（限色架构 k-means 上游）。

**牵动判据**：目标色真源 = 逐格数据 ⇒ 区域铺色只是**渲染聚合**，⛔ 不得反向成为
命中/消费依据（L5/数据驱动）；改关卡数据格式 = 管线级（manifest/封箱/逐分复现
测试全链，前例：替换关卡数据击穿「1 点击=1 珠」测试的在册教训）。

**量级 L**：跨数据 + 渲染两层，建议独立批次、排在 §1/§2 实测观感之后。

## 4. 孔径与内环（差距 #4）

- 内环收窄：`HANDDRAWN_RING_RATIO/_RING_W` 是本风格私有 tuning ⇒ **随时可调**，
  建议并入 §5 小批；
- **孔径 ⛔ 风格私有**：`BEAD_CARD.holeRatio` 全池真源（K-042 同族纪律：真源单一
  化后不得逐风格开值），改孔径 = 全池决策 + 六裁/七裁在册账重算 ⇒ 本单**不做**，
  如参考图小孔是硬需求，单开全池议题。

## 5. 珠面体积渐变 + 轮廓线宽（差距 #5/#6）

- 体积 = 加一枚 `lit` 亮带（rect/arc 皆可，色源仍 `endpointOf` 四端点 ⇒ C3 不破；
  facet-18 亮带先例）：命令 4→5，C7 上限 ≤7 内；C12 facet 域统计会 +plate 层，
  门禁重跑即可；A5 账不动（亮带在珠面内）；
- 轮廓加粗 = `HANDDRAWN_OUTLINE_W` 0.05→0.07 档，A5 账重算（外沿 0.90+0.07=0.97，
  ×1.04=1.009 **越 1** ⇒ 需 FACE 让到 0.78 或抬起腿单独裁，⚠ 不是白拿的）；
- 两项合并 = 「handdrawn v3 风格收尾小批」，半小时级。

## 6. 选中/提示双语言（差距 #8）

参考图：红框 = 选中错位珠、黄框 = 目标提示格。现状：单色高亮 + 恒亮白环
（T-148）+ 抬起态。**这是交互语义决策不是美术决策**：
- 黄框「目标提示」若= 系统主动指路 ⇒ 涉及玩法（提示是否消耗/难度曲线）→ GDD 侧裁；
- 红/黄 = 新色源 ⇒ palette 在册色板与色盲三重编码（a11y-anchors）要过；
- 建议：先出 wxgame-ux-spec 侧的语义对照，再谈落码。本单只登记不展开。

## 7. UI 主题白底化（差距 #9）

整屏白底 + 线框槽 + 具象道具图标 = **第二套全局皮肤**（palette 档切换 + 托盘/HUD/
道具卡全套），与珠子换肤系统是两回事；道具图标是**资产问题**（程序化绘制 or
ImageGen 定调后落码，前例：主界面概念图三版待选）。建议独立立项，勿混进盘面批。

## 8. 可行性结论（2026-10-07 用户问「能否做到效果图/90% 接近」，同轮裁定存档）

**结论：能。90% 接近不需任何新机制，全在现有架构射程内；是工程量/批次问题，
不是可行性问题。**逐块判定：珠体（已 ~85%，余为参数级）/ §1 去网格 / §2 剪影描边 /
§3 色区底 / §6 双语言框（技术无碍，语义待产品裁）/ §7 白底主题（同属已验证路子）
= 全部 ✅。

**到不了 100% 的三处（诚实账）**：
1. 笔触级手绘感：L4（禁随机）+ 像素封箱 ⇒ 歪斜 = 静态表，「每颗独一无二」做不到
   （除非逐珠烘焙纹理，吃包体），观感差约 5–8%；
2. 珠面颗粒/纸纹噪点：需 tint-mask 烘焙纹理路线（在册管线可接，属额外批）；
3. 效果图是静态稿非游戏帧：「动起来像不像」只能 harness 实测背书，纸面不承诺。

**最短路径**：§1+§2+§5 三批完 = 盘面区 90%；含整屏再加 §7 一批。全程程序化、
零新外部资产、不碰包体红线。
