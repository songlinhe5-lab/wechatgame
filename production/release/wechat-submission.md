## 1. 账号主体类型：个人 vs 企业（差异）

在 mp.weixin.qq.com 注册小游戏时，需先选择**主体类型**。常见差异（**性质描述，非条款引用**）：

| 维度 | 个人主体 | 企业主体 | 备注 |
|---|---|---|---|
| 注册材料 | 通常仅需个人身份信息 | 通常需营业执照等企业资料 | ⚠️ 待核实具体材料 |
| 可开通能力 | 通常受限较多（如支付、部分类目） | 通常可开通更多能力 | ⚠️ 待核实当前能力边界 |
| 游戏类目 | 部分游戏类目可能对个人主体不开放 | 通常更完整 | ⚠️ 待核实 |
| 变现（内购/广告） | 通常受限 | 通常更完整 | ⚠️ 待核实 |
| 审核严格度 | 视类目与内容 | 视类目与内容 | ⚠️ 待核实 |

**对本项目的含义**：本 demo **无内购、无广告、无账号、无排行榜**（`concept.md §7 Won't`）→ 商业变现能力**不需要**。
但**能否用个人主体上架一款"游戏"**，需在注册时按平台当前规则确认（游戏类目对主体的开放情况是变动项）。⚠️ 待核实。
→ **建议你（USER）先决定主体类型，再走注册**；如仅是内部体验验证，也可先用平台允许的最简主体。

## 2. 游戏类目选择

- 微信小游戏需选择**服务类目**（游戏类目下再分小类，如休闲/益智/动作等）。⚠️ 待核实当前可选类目清单与命名。
- 类目与实玩内容须一致，**选错类目是常见驳回原因**。
- 本项目属**休闲 / 益智（打砖块）**向；正式选类目时以平台当前类目表为准。
- 部分游戏类目可能触发额外的**资质要求**（见 §3）。⚠️ 待核实。

**本项目判定**：类目选择**必须由 USER 在 mp 后台完成**，不在本轮可自动化范围内。

## 3. 合规材料清单（逐项标注适用性）

> 下表"本项目是否适用"一列，是**基于本项目已冻结范围**（纯本地、无变现、无账号、无云）的判断；**材料本身的要求以官方为准**。⚠️ 待核实。

| 材料 | 是什么 | 本项目是否适用 | 备注 / 入口 |
|---|---|---|---|
| **《小程序用户隐私保护指引》** | 在 mp 后台填写/声明收集与使用用户信息的方式 | **很可能适用**（几乎所有小程序都需填写） | mp 后台 ⚠️ 待核实填写项 |
| **用户协议 / 隐私政策（游戏内可访问）** | 面向玩家的协议文本 | 视平台要求；休闲小游戏通常需可访问 | ⚠️ 待核实是否强制 |
| **计算机软件著作权（软著）** | 版权登记，非行政许可 | **可能被要求**（游戏类目/提审时） | 中国版权保护中心 ⚠️ 待核实是否强制 |
| **游戏版号（出版物号）** | 国家新闻出版署对网络游戏的审批 | ⚠️ **高度不确定**：与"是否商业化/是否小游戏纳入监管"相关 | 国家新闻出版署 ⚠️ **务必自行核实** |
| **游戏备案** | 部分地区/平台的游戏备案要求 | ⚠️ 待核实 | ⚠️ 待核实 |
| **实名认证 / 未成年人保护（防沉迷）** | 面向中国大陆用户的游戏需接入身份验证与时长限制 | ⚠️ 待核实平台是否提供统一能力 | 见开发者文档 ⚠️ 待核实 |
| **ICP 备案 / 服务器域名** | 有服务端时域名需备案 | **本项目无服务器** → 大概率不涉及 | ✅ 较稳定（无后端即无域名） |
| **增值电信业务许可（文网文/ICP 证）** | 经营性互联网文化/电信业务许可 | 与商业化/经营性相关；本项目无变现 | ⚠️ 待核实 |

> **关于软著与版号的关键提醒**：这是本项目**最需要你亲自核实**的两项。
> - 软著：是"版权登记"，一般自愿，但游戏类目提审时**可能被要求**提供。⚠️ 待核实。
> - 版号：是"出版审批"，历史上主要针对商业化运营的网络游戏。**"一款无内购、无广告、无变现的微信小游戏是否需要版号"——请以国家新闻出版署与微信平台的最新要求为准**，本文件**不敢给结论**。⚠️ **待核实（高优先）**。

## 4. 审核常见驳回原因与规避（自查表）

> 以下为**经验性倾向**，非条款引用；具体以平台《运营规范》与驳回通知为准。⚠️ 待核实。

| 常见驳回类型 | 典型表现 | 本项目规避动作 |
|---|---|---|
| 类目不符 | 选的类目与实玩内容不一致 | 按 §2 选"休闲/益智"并核对 ⚠️ |
| 游戏资质缺失 | 未提供软著/版号（若被要求） | 提审前按 §3 备齐 ⚠️ |
| 隐私指引缺失 | 未填写隐私保护指引 | mp 后台补填 ⚠️ |
| 诱导分享 / 强制分享 | 分享才能玩、弹窗诱导 | ✅ 本项目无社交/分享功能 |
| 涉及未开放内容 | 游戏内容触及敏感题材 | ✅ 本项目为纯几何打砖块，无叙事题材 |
| 名称/介绍违规 | 名称含违规词、夸大宣传 | 提审前自查名称与文案 |
| 功能不完整/不可玩 | 审核时白屏、崩溃、无法进入 | 🚦 提审前真机自测（见 release-checklist §3） |
| 外链/第三方跳转 | 跳转到非白名单域名 | ✅ 本项目无外链 |
| 广告违规 | 违规展示广告 | ✅ 本项目无广告 |

**本项目结构性优势**（✅ 较稳定，来自已冻结范围）：无社交、无支付、无广告、无外链、无账号、无 UGC → **规避了大量高风险驳回项**。

## 5. 包体与分包上传要求

| 项 | 要求 | 来源 |
|---|---|---|
| 主包上限 | **≤ 4096 KB（4 MB）**（⚠️ 待核实：平台可能调整，上传前到官方文档确认） | 项目 `systems-index.md §3.8` 记录的"平台红线"；官方文档复核 ⚠️ |
| 主包 + 分包合计 | **≤ 30720 KB（30 MB）** | 同上 ⚠️ |
| 本项目内部目标 | 主包 ≤ **2000 KB**（比红线更严） | `assets-spec.md §5` ✅ |
| 分包使用 | 本项目 demo **暂不启用分包**（单包已远低于目标） | ✅ 较稳定 |
| 上传方式 | 微信开发者工具「上传」；需在 mp 后台配置版本 | ⚠️ 待核实细节 |

> **注意区分**：4096 KB 是"平台红线"，2000 KB 是"我们自设目标"。本项目因**全程序化绘制、美术位图 0 KB、无音频**，主包体积压力极小 —— 包体**不是**本项目的主要风险。

## 7. 本项目「少掉的上架负担」（结论）

相比一款**普通商业小游戏**，本项目因范围冻结（`concept.md §7 Won't`）而**少掉**以下负担：

| 普通商业小游戏通常要做 | 本项目 |
|---|---|
| 内购 / 支付能力开通与对账 | ✅ 无需（无内购） |
| 广告接入与广告位合规 | ✅ 无需（无广告） |
| 账号体系 / 登录合规（个人信息收集告知） | ✅ 无需（无账号、无身份信息，存档仅游戏数据） |
| 排行榜 / 开放数据域（好友关系链） | ✅ 无需（无社交） |
| 云存档 / 服务端 → 域名 ICP 备案 | ✅ 无需（纯本地） |
| 多人联机 / 实时服务 | ✅ 无需 |
| UGC / 聊天 / 内容审核 | ✅ 无需 |
| 商业化相关的经营性资质 | ✅ 大概率无需（无变现）⚠️ 待核实 |

**仍然必须做的**（不能少）：主体注册、类目选择、隐私保护指引、提审、真机自测。
**最不确定、必须你去核实的**：**游戏版号 / 备案是否适用于本 demo**、**软著是否被要求**、**实名防沉迷是否需接入**。⚠️
