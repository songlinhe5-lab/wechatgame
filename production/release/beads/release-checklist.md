## 8. 分包 / 远程包选型（**发布批拍板，本清单不代裁**）

以 **2026-10-18 release 重建实测（主包 3188.2 KB / 108 文件）**为选型基线；**23:29 现包 = 3201.0 KB（余量 895.0 KB），B′ 仍未落码** ⇒ 本节 gzip 表保留 10-18 基线读数，A 方案现值按现包更新，B′ 预期按 **3201.0 − 469.2 = 2731.8 KB** 计。所有方案都保留现有「位图缺失 ⇒ 程序化腿」回退，因此菜单位图晚到或加载失败不会白屏（已在 Node 侧验证，真机需走查 D-69 复核）。

⚠ **v1.1 换掉选型动机**：初稿把分包/远程包当作「为了回到内部目标 2000 KB」；内部目标已抬到 4096 KB 且现值达标 ⇒ 那部分理由不成立。现在的**真实收益 = 主包余量 + 首屏下载体积**（主包越小，低端机首屏越快、后续可投放额度越大），代价 = 异步加载窗与一层运维。因此本表不是达标题，是权衡题。

📐 **两个口径必须分开看（v1.2 新加，实测 2026-10-19）**——包体门按**原始字节**判，而用户等的是**传输字节**（gzip）：

| 组成 | 原始 KB | gzip KB | 压得动吗 |
|---|---|---|---|
| 引擎 `cocos-js/cc.js` | 1356.9 | **355.5** | 能（−74%）⇒ 它对**包体判定**是大头，对**下载时长**是小头 |
| `assets/main`（脚本+关卡） | 527.2 | 191.4 | 能 |
| 菜单 BGM `audio/bgm_porch.mp3` | 469.2 | **462.6** | ❌ 压不动（已是有损格式）⇒ 每挪走 1 KB 就真省 1 KB 下载 |
| `assets/textures`（菜单位图 + boss 缩略） | 442.2 | **406.6** | ❌ 几乎压不动（PNG 已量化） |
| **主包合计（10-18 基线）** | **3188.2** | **1553.2** | — |

⇒ 结论：**挪走音频与位图对下载时长的收益远大于对包体数字的收益**（挪两项 = 包体 −28.6%，但传输 **−56%**）。

| 方案 | 做法 | 主包估算 | 工程成本 | 运维成本 / 风险 |
|---|---|---|---|---|

### 8.1 决策点（v1.2 收口，给 USER 拍板用）

包体已达标 ⇒ 本表只剩一个真问题：**低端机首屏要下多少字节，愿意为它付多少复杂度**。按「改动量 / 下载收益」排序：

| 选项 | 下载量（传输） | 要付的代价 | 适用前提 |
|---|---|---|---|
| **A 不动** | 1553.2 KB（10-18 基线；现包原始 +12.8 KB 未折入） | 零；但余量只剩 895.0 KB（≈ 3 批菜单切图） | 首发不引入任何异步窗；接受后续批次一到就顶线 |
| **B′ 只挪 BGM**（主理人建议） | **1090.6 KB（−30%）** | 一处配置；首帧到分包到位之间无 BGM（合成腿兜底，需 AUD 听）+ 真机验 `loadSubpackage`（新增 D-78） | 想要下载收益又不碰编辑器/位图时序 |
| **B 全挪** | **684.0 KB（−56%）** | B′ 全部代价 + 编辑器改 `.meta` + 菜单首帧「程序化→位图」跳变（需 ART 看）+ 位图晚到回退面（D-69） | 把首屏下载当硬指标；愿意先补真机取证再上 |
| **C 远程包** | ≈684.0 KB | B 的代价 + CDN + 合法域名 + 资源/代码版本绑定（推翻 `version-strategy §5`「无需热更」结论） | 有 CDN 运维能力且要做资源热更 |

**主理人建议 = B′ 首发，B 作为「菜单切图下批入库后重测」的升级路径**：因为① 包体不是问题，下载才是；② B′ 的 469.2 KB 是**唯一一块「零编辑器操作、零 `.meta` 风险、腿已写好」的肥肉**；③ B 多拿的 26% 要付首帧跳变与位图晚到的观感风险，而菜单位图本来就是首屏要看的东西（挪走反而拖慢首屏观感）。⛔ 本表不代裁：选 B′ 或 B ⇒ 必须先补真机走查项 **D-78（`wx.loadSubpackage` 成功/失败回退）**，并让 AUD 真听一次无 BGM 窗口。

#### ✅ 拍板结果（USER 2026-10-19）

- **路线 = B′（只把菜单 BGM 挑进分包）**；按 23:29 现包 **3201.0 → 2731.8 KB**（−469.2），首屏传输 1553.2 → **1090.6 KB**（−30%，传输按 10-18 基线推算）。**B′ 仍未落码** ⇒ 发布门控现读 **3201.0 / 余量 895.0**，不是 2719.0。
- **节奏 = 先登记、暂不落码**：等 Session 1 真机走查（含 D-77 位图屏幕层序）跑完再动代码。理由（拍板时记录）：一轮真机只引入一个变量，⛔ 不让分包改动污染本轮基线读数。
- **实施时的唯一改动点** = `games/beads/src/config/audio-voices.ts::assetFile`（`audio/bgm_porch.mp3` → `subpackages/audio/bgm_porch.mp3`）；装配目录 / `game.json` 的 `subpackages[]` / 运行时路径 / `check:size` 分包识别由 `build-cocos.mjs` 自动跟上，⛔ 不需手改产物文件。
- **实施前硬前置**（未满足不得开开关）：① 走查单新增项 **D-78** 已登记为 `⛔ BLOCKED`（解除条件 = B′ 落码），见 `production/qa/beads/device-walkthrough.md §4` 的 **X-09**；② AUD 真听一次「首帧到分包到位」的无 BGM 窗口（合成回退腿听感）；③ 重跑 `check:size` 确认分包后主包/总包两项均绿（分包**仍计入 20480 KB 总包红线**）。
