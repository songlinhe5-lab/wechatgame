### 3.2 α / fill 口径补全（本单要补的口径缺口）

现口径（`assets-spec §1.6.9 / §1.9.5`）只数**图元/层级/命令条数**，`α 层的每像素混合代价不可见`（ADR-0022 §1.3 对 H-FILL 的旁证之一）⇒ 本单在**宿主侧只读遍历** `RenderModel.commands`（`RenderModel` 暴露 readonly 数组，framework core **零改动**）补两个量：

> ✅ **v1.1 已核**：`packages/framework/src/core/render/render-model.ts:105` 确为 `readonly commands: readonly DrawCommand[]` 公开暴露 ⇒ 宿主只读遍历**无需改框架**，不触 `framework:sync:check` 漂移门（BD-20 安全）。

```
alphaCmds = count(cmd.alpha !== undefined && cmd.alpha < 1 || /rgba\(.*,[0-9.]*[0-9]\)/.test(cmd.fill))
FI(α overdraw index) = Σ_{α 命令} A_cover_designpx × zoom² × DPR²  /  (视口物理像素数)
```

- **每帧同时记**：`cmds`（总命令数）、`byKind{rect,circle,line,text,polygon}`、`curves`（带 `radius>0` 的 rect + 所有 circle = 曲线展平数）、`alphaCmds`、`alphaAreaPx`、`FI`。
- **对照 `assets-spec` 口径的位置**：ADR §1.1 现状 = **12 命令/珠 · 4 真 α 层 · 7 次曲线展平**（一格含 B0 底图 = 13 枚）⇒ 埋点首帧读数必须与该四元组对表；**对不上 ⇒ 先开缺陷单（口径漂移）再测**，不得静默用埋点数。

### 6.3 判读规则（读数用**帧时间中位数 ms**，fps 只作呈现）

- 敏感线 **S = 15%**（改善 = `(t_基准 − t_臂)/t_基准 ≥ S`）——⚠️ ADR §7-D2 原写「建议值，主理人可改」⇒ **未冻结，本单标 `[待主理人拍]`**；

```js
          (cc && cc.game && cc.game.canvas) || null;               // 引擎侧取法（[待核实]）
  out.canvas = !!c;
  if (c) {
    var g2 = null, g1 = null, gl = null, type = 'none';
    try { g2 = c.getContext('webgl2'); } catch (e) {}
    if (g2) { gl = g2; type = 'webgl2'; } else {
      try { g1 = c.getContext('webgl'); } catch (e) {}
      if (g1) { gl = g1; type = 'webgl1'; }
    }
    out.ctxType = type;
    if (gl) {
      var P = gl;
      out.VERSION = gl.getParameter(P.VERSION);                     // "WebGL 1.0 ..." / 2.0
      out.GLSL = gl.getParameter(P.SHADING_LANGUAGE_VERSION);       // "GLSL ES 1.00" / "3.00 es"
      out.MAX_FRAGMENT_UNIFORM_VECTORS = gl.getParameter(P.MAX_FRAGMENT_UNIFORM_VECTORS);
      out.MAX_VERTEX_UNIFORM_VECTORS = gl.getParameter(P.MAX_VERTEX_UNIFORM_VECTORS);
      out.MAX_TEXTURE_IMAGE_UNITS = gl.getParameter(P.MAX_TEXTURE_IMAGE_UNITS);
      out.MAX_COMBINED_TEXTURE_IMAGE_UNITS = gl.getParameter(P.MAX_COMBINED_TEXTURE_IMAGE_UNITS);
      out.MAX_RENDERBUFFER_SIZE = gl.getParameter(P.MAX_RENDERBUFFER_SIZE);
      out.MAX_VIEWPORT_DIMS = [].concat(gl.getParameter(P.MAX_VIEWPORT_DIMS));
      out.OES_standard_derivatives = !!gl.getExtension('OES_standard_derivatives');
      out.EXT_color_buffer_float = !!gl.getExtension('EXT_color_buffer_float'); // 加分项，ES100 下限不依赖
      var d = gl.getExtension('WEBGL_debug_renderer_info');
      out.renderer = d ? gl.getParameter(d.UNMASKED_RENDERER_WEBGL) : 'no-debug-info';
    }
  }
  console.log('[QA-PERF][GL] ' + JSON.stringify(out));
})();
```

⚠️ **口径分两层，必写清**：`getContext('webgl2')` 探的是「**runtime 此刻给不给 WebGL2**」；而「**引擎实际用的上下文**」须由 `cc.game.canvas` 已持有的上下文决定（Cocos 3.8 拿不到 webgl2 时按 WebGL1 降级，具体到 wechat 平台申请逻辑本仓**未验证** `[待核实 D3/D7]`）。两列分开记：`ctxType_probed` / `ctxType_engine`。

### 7.2 矩阵与判据

| 采集项 | 通过线（ADR 原文） | 取不到时的乙案降级动作 |
|---|---|---|
| WebGL2 有无 | 只登记，**首版不赌**（设计下限钉死 GLSL ES 100） | 拿不到 webgl2 ⇒ 正常（按 ES100 走，**不阻断**）；连 webgl1 都拿不到 ⇒ P0 阻断，先修通道 |
| GLSL ES 版本 | 记 `1.00` / `3.00 es` 分布 | 版本串缺失 ⇒ 用 `MAX_*` + 编译探测（最小 shader 编译一遍）替代，登记方法 |
| `MAX_FRAGMENT_UNIFORM_VECTORS` | **全部 ≥20 ⇒ 色板走 uniform 成立**，否则色板改纹理通道 | 取不到 ⇒ 该机不计入分母（并登记），**不得按 16 规范下限假定** |
| `MAX_TEXTURE_IMAGE_UNITS` | 登记分布（乙案盘面纹理 + 符号子纹理 ≥2 是硬需求） | <2 ⇒ 乙案纹理布局需重设计，登记为通道风险 |
| `OES_standard_derivatives` | 只登记可用性 | 不可用 ⇒ **无影响**（ADR §2.2 已裁「不依赖 `fwidth`，AA 宽度由布局 uniform 解析给出」）；⛔ 禁止因为「某些机可用」就引入导数 |
| 失败线 | 撑不住 ES 100 uniform 下限的机型占比 **>5%** ⇒ 乙案数据通道重设计 | 样本 <5 台 ⇒ **该占比不可判**，D7 标「未达线（样本不足）」而非通过 |

**四条读数（含不得越界的限定）**

1. **`platform` 在鸿蒙上报 `ohos`——既不是 `android` 也不是 `ios`** ⇒ 本单与工程侧**任何按 `platform==='android'` 分支的逻辑在鸿蒙上会静默走 else**。已知实例：`build/wechatgame/game.js` 尾部「Android 第二拍才能拿到正确屏幕尺寸」的初始化分支——**鸿蒙走了立即初始化那条**，游戏能跑但首屏尺寸/点击映射未验 ⇒ 已登记 **DG-8 缺陷候选**。
2. **`FRAG_UV = 4096` 不得读作「uniform 安全议题关闭」**——单台、且是 2026 新千元机；D7 通过线要的是 **≥5 台全部 ≥20**。本条只证明「鸿蒙新机 uniform 预算充裕」，低端分布仍未测。
3. **`ctxType = webgl1` 而底层是 OpenGL ES 3.2** ⇒ 「设备能力 ≠ 运行时暴露能力」的活教材，**反向坐实 ADR-0022「下限钉死 GLSL ES 100、不赌 WebGL2」**。`deriv: true` 只是可用性登记，**仍禁引入 `fwidth`**（原裁定不变）。
4. **`benchmark = -1` ⇒ 想用 `benchmarkLevel` 客观定档的路线在鸿蒙上失效**（本单 v1.1 曾推荐该字段）⇒ 定档依据改用 `renderer` + `model` + `memorySize` + `dpr` 四件组合，已登记 **DG-7**。

**额外收获（非判据，但改变 D1 做法）**：真机帧间隔最小值 **15ms（≈66.7Hz）** 而非 16.67ms ⇒ 限帧点不在 60 整，**120Hz 面板被运行时限制** ⇒ ① 本单「裁定一律用帧时间 ms」的口径得到实测支撑；② **D1 第一问（静息满盘是否已贴 vsync 天花板）必须正式回答**，否则 D2 的 fps 读数会撞天花板效应。
