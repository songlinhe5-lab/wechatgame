# B19 · 柜内木牌：本地大模型腿 vs 在线大模型腿

用户要求（B19）：**再用本地大模型和在线大模型各抠一次**，三条硬要求 —— **有透视 / 有阴影 / 外轮廓平整**。
本轮同时隐含拍板：要保留透视 ⇒ 走「原稿直抠」路线，B18 的 W4（inpaint 正视版）不再考虑。

## 生图数

| 腿 | 内容 | 次数 / 费用 |
|---|---|---|
| 本地 | ComfyUI SAM2 分割推理 | 1 次（0 元） |
| 云端 | `qwen-image-3.0-pro --ref` 白底指令出图 | 1 张 / 0.18 元（封顶 0.25） |

## 能力边界（先查再动手，"节点存在 ≠ 能力可用"）

- 本地 **没有 matting 权重**：`LoadBackgroundRemovalModel.bg_removal_name` 的 options = `[]`；
  `BRIA_RMBG_ModelLoader_Zho` 节点在但需联网下载；`SAM3_Detect` 在、权重不在。
  ⇒ 本地腿只能用 **SAM2**（已验证可脚本化：`ImageCrop` → `LoadImageMask(粗矩形先验, channel=red)` → `Sam2Segmentation`）。
- 云端 **没有通用物体抠图 API**：百炼只有人像分割 / 擦除补全 / 指令编辑；
  VIAPI `SegmentCommonImage` 需 AK/SK 且官方文档明写「不适用于卡通图」。
  ⇒ 云端腿 = 模型出**纯白底图** + 本地色键。模型只干它擅长的一件事：把影画出来。

外轮廓平整度比稿差 40 倍、牌面色漂 14 灰阶。

## 影层怎么定的（两条推翻初判的实测）

1. 牌顶外侧 249.1 vs 背板基线 250、牌左外侧同 ⇒ **顶/左无影**；牌底 y2095–2099 亮度
   165/174/183/197/215 vs 基线 227 ⇒ **牌底 5 px 接触影，峰值衰减 0.78**。光源在左上。
2. 初稿曾记「右侧 x[962,978] 暗 20 灰阶」——**不成立**（读数法有误，见文末 B20 订正）。
   沿右侧整条仍无投影：近牌 x969 = 217 vs 斜玻璃边前 x1089 = 220，只差 3 灰阶，与左侧对称。
   ⇒ 右侧不入**整条**影层；但牌**右下角**确有偏重的接触影，见 B20。
3. 影编码：`RGB = 纯黑`、`alpha = 1 − L/L_ref`。这样贴到任意底色上都按乘性变暗，
   不会把稿的暖底色一起搬走。同口径实测：纯黑 max 12.8 / mean 4.9 灰阶，
   手推暖棕 (97,41,0) max 20.7 / mean 7.1 ⇒ **取纯黑**。
   ⚠ 预先定的阈值是 max ≤ 12，**未达**（实测 13.0）。已定位：峰出在紧贴描边那一行，
   是影与描边抗锯齿混采，不是编码错；mean 4.1。

## 顺带修掉的资产缺陷

## 上一轮的判据法错在哪（重要，别再犯）

「同列/同行远场中位」当基线**不成立**：台面不是均匀背景，牌右侧远处有一条
**斜玻璃边**（x≈1093 处 10 灰阶台阶），牌下方有**层板前缘灰蓝带**（y≈2134，R−B 掉到 4–6）。
远场参考一旦跨过这两样，基线自己就跳变，影被基线吃掉。上一轮把污染原因归给「灰蓝带」
也只对了一半——右侧真正的污染源是那条斜玻璃边。

改测法：**不建模，直接打印 8 px 块栅格认形状**（`b19-probe-grid.py`），
再对底边做**逐列剖面**（`b19-probe-bottom.py`）。一阶平面拟合试过，远场残差 std 39 = 模型不成立，弃。

## 三处确诊与修法

| 问题 | 实测 | 修法 | 结果 |
|---|---|---|---|
| 边缘不平（v1） | 稿的抗锯齿只有 **1 px**（顶 249→222→163、右斜 250→198→131）；v1 二值化把它吃掉再用 0.6 px 高斯硬补 → 斜边阶梯 | 平整后的掩码 **上采 4x → 高斯 → BOX 下采**取真实次像素覆盖率；半透边**向内射线取色**去「牌色×白背板」二次混合 | 部分覆盖 3275 px，全部完成取色 |

⚠ **裙边是外推，稿上没有**（右边缘实测只差 3 灰阶）。依据是「底边影左弱右强」与光源在左上
一致，方向可信、范围是补的。所以出两档强度待拍板，且 `SKIRT_W / SKIRT_H / gain` 三个参数可关可调。

## 合成不能取 max（一处差点写进去的黑边 bug）

影与牌体抗锯齿环重叠时，`alpha = max(cov, shadow)` 会让影的黑色顶掉牌色 → 牌缘啃出一圈黑边。
必须走标准 over：`alpha = cov + (1−cov)·k`、`rgb = rgb·cov / alpha`（影色为纯黑故预乘项只剩一项）。
另：影做高斯模糊后会把 alpha 漏回牌体内侧，须再 `np.where(plate, 0, k)` 清零一次。

## ComfyUI 工作流报错 `tuple index out of range` 的真因（外部建议已逐条核）

报错源是 **节点 7**：`SaveImage.images ← Sam2Segmentation 输出 1`，那是 3 维 MASK（B,H,W），
SaveImage 要 4 维彩色张量 → 读第 4 维越界。**它不是缺节点**：我们真正消费的 mask 走的是
节点 5 `MaskToImage` → 节点 6 `SaveImage`（即 `6-b19_00001_.png`），节点 7 是一条冗余死分支，
报错时提示已写明 `Output will be ignored`，整条腿照常出图。
⇒ 修法就是**删掉节点 7**（temp 与服务端校验均已验：`/prompt` 返回 success，节点 6 存出 `b19_00002_.png`）。

外部建议的三个方案在本资产上**均为负收益**，实测依据：

| 建议 | 本机核验 | 结论 |
|---|---|---|
| 加 `JoinImageWithAlpha` 出透明 PNG | 节点存在，但它**只写 alpha、保留稿原 RGB** | 边界环 3275 px 实测均值 `[200.8,171.9,140.7]` vs 去污染后 `[198.0,153.5,103.9]` → 蓝通道偏亮 **36.8 灰阶 ≈ 每像素混入 20% 白背板**。杂边不会消失，只是从不透明白圈变成半透明白圈 |
| `MaskGrow grow=-2, blur=1` | 核心节点名是 `GrowMask`，**无 blur 参数**（羽化需另接 `FeatherMask`）；dzNodes 的 `LayerMask: MaskGrow` 确实带 grow+blur（B22 装好后核） | 收缩 2 px 实测啃掉 **2193 px（牌体 3.5%）**描边。该建议假设 mask 超出到背景；本资产 SAM2 mask 本来就**缺**顶 2 px / 底 2 px 描边，方向相反。B22 复测同参数 → IoU 掉到 0.946、牌面少 8.8%、黑底环带 p95 **210.8**（对照 v3a 165.0），负收益坐实 |
| dzNodes `LayerMask: MaskEdgeShrink` / `ImageDe-fringe` | 当时 1016 节点 `LayerMask` **0 命中**；用户装好后 1272 节点，`MaskEdgeShrink`/`MaskEdgeUltraDetail` 可用，但 **`ImageDe-fringe` 仍 0 命中**（去污类关键字 `decont`/`unpremul`/`matting`/`fringe` 全 0） | 见 **B22**：EdgeShrink 黑底环带 p95 190–192、半透环 30–33%，均劣于本地 v3a 的 165.0 / 7.5% |

分工维持不变：**ComfyUI 只出 SAM2 先验 mask**；平整化 / 直线拟合 / 次像素覆盖率 /
**去污染取色** / 影层 / 判据全在本地确定性脚本（`b19-local3.py`）。ComfyUI 核心没有
color decontamination 节点，这正是杂边的真正解法，所以那一步不能往图里搬。

| 不透明区内部偏移 | −0.0 / 0.0 / −0.0（差全在边环） |
| alpha 通道最大差 | 0（alpha 本身不受影响） |

1. **`[A]` 九条腿全部 = 0**：`JoinImageWithAlpha` 一字不改 RGB。这条路线**结构上不可能**

⇒ **本地腿 v3a 维持定稿**；大模型在这条管线里的实际贡献只有「给出牌体轮廓」，
而这一步 v3 的四边最小二乘 + 参数域圆角已经量得更准。云端/dzNodes 腿降级为对照物。

## v4 是什么（`b24-v4-shadow.py`）

B21 的 v3a 影层只取了「底边逐列 + 右下裙边」**两个一维剖面**，实测形状不对
（牌右只有 322 px，稿是 1003）。v4 改成逐像素二维：

```
k(x,y) = clip((干净底 − 稿) / 干净底, 0, 1)     # 直接取稿上投影足迹，>5 灰阶才算影
RGB ≡ 黑，alpha = k                            # 乘性编码 → 合成结果 = 底×(1−k)，任意底色都保持暗
牌体（含 2px 环）沿用 v3a 的 alpha/RGB；牌体外只留 k；k 单独羽化 σ0.6
```

羽化 σ A/B（`b24-readings.txt`）：σ0.6 之后每加一档，覆盖几乎不动而「多画」线性上升
（σ1.2 → 12.9%、σ2.0 → 22.8%、σ3.0 → 32.0%）→ **σ0.6 就够**，再柔就是凭空画影。

## 踩坑（本轮自造）

1. **全图坐标 vs crop 坐标混用**（本轮第三次）：`hole & ~GT` 直接 broadcast 报错；

## 一、切片线沿用 B18，尺子先自证

`nine_slice()` 逐字复现一遍再对表：

| W3（原稿直抠） | 9/7 · 9/7 · 9/7 | **9/7 ×3** ✓ |

## 二、三段式：影层增量 = 0

切片线与牌体**共用**（牌缘 ±END，END = 24 设计px = 48 @2x px），差别只在端帽要
把悬在牌体外的影整块带走（牌左 349 px / 牌右裙边 744 px 都悬在外面）。牌缘一律从
资产自己的不透明列量（alpha>230），不写死稿 GT —— 管线腿的牌缘与 GT 差 1 px。

| 腿 | 端帽左 / 中段 / 端帽右（@2x px） | 接缝 maxdiff RGB 左/右 | alpha 牌体带 | alpha 影带 |
|---|---|---|---|---|
| ⑫ v4 牌体+二维影 | 116 / 286 / 121 | **3 / 0** | 0 / 0 | **1 / 0** |
| ⑩ v3a 只有牌体（对照） | 116 / 286 / 121 | 3 / 0 | 0 / 0 | 1 / 0 |

三档牌宽（140 / 191.5 / 280 设计px）读数完全相同，判据 <12 → **影层对接缝的增量是 0**，
且与 B17 的 W4 基线（3/4）同级。

中段能不能拉（牌底接触影的列剖面）：首 1/8 均值 0.213 → 末 1/8 0.224，差 +0.011（+5.1%），
线性斜率 +0.005/100 列，而列间自然抖动 RMS 就有 0.0043 —— 趋势与噪声同量级，
×1.47 拉伸后首尾差摊到 0.007。**中段可拉，不产生可见的"影被抹平"。**

## 六、本轮新发现的坑：@2x 重采样会把影区染亮

`b25-checks.py` 第 ② 条断言「纯影区（离牌体 3 px 以上）RGB ≡ 0」在 @2x 资产上**先失败**：
30 px 的 RGB 高达 255（alpha 0.027–0.090）。根因是 **LANCZOS 的负瓣振铃**：牌体亮边
（242,195,139）被振进外侧 3–4 px 的预乘 RGB，再除以很小的 alpha 就放大成白点
（同口径统计：影区里 1151 px 带着非零预乘 RGB）。v3a 旧资产同位置 0 px，因为它的一维影
在牌底 3 px 外就没了，够不到振铃区。

修法（`b19-plate-final.py`）：用**牌体覆盖率的同口径重采样**当门，`cov_r < 0.01` 处预乘 RGB 直接抹零
—— 影区 RGB 本该是 0，这一步不改变任何正确像素。修完两条断言全 PASS。

这就是 B24 否掉 ④/⑤ 的同一条理由（把稿上背景带进影层），只是剂量小、且藏在
`resize` 里 —— **乘性编码的不变量必须写成断言，不能靠目检。**
