## 目标

把主观"手感/难度"变成**可判定**的观察项，用 **≥3 轮**分阶段验证，并给出**明确的通过/调参判定线**。Playtest 用**真机**进行（需编辑器构建后），本轮无真机 → 计划**就绪待执行**。

## 观察框架（每轮通用）

| 维度 | 观察什么 | 数据来源 |
|---|---|---|
| **首次上手（零教学可懂）** | 是否 0 文字说明即可理解"拖挡板→撞砖→得分" | 首次游玩录屏 + 追问 |
| **手感（Feel）** | 挡板跟手度、反弹角度可控性、球速压迫感 | 主观评分 + 问卷 |

| **留存意愿** | 是否愿意再来一局 | 问卷 |

## 第 1 轮 · 新玩家首次体验（First-Time User Experience）

**目标**：验证"**零教学、0 点击进入、首局即赢**"是否成立（微信首 10 秒留存）。
**样本**：4~6 名**未玩过本作**的玩家（含 1~2 名非游戏玩家）；每人只玩**前 2 关**。
**环境**：真机（微信小游戏），首次运行（清空存档）。

| 观察项 | 具体问法/埋点 | 判定线 |
|---|---|---|
| 进入摩擦 | 从点图标到可操作耗时 | **≤1.5s** 达者 ≥80%（来源 `ux-spec.md §6.1`） |
| 是否卡在 READY | 是否有人因不懂发球而干等 | 100% 玩家 ≤1.5s 内球离开挡板（自动发球兜底） |
| 零教学可懂 | 玩完 L1 后问"你觉得要做什么" | ≥80% 能正确复述"用挡板把球弹回去打砖" |
| 首局体验 | L1 是否拿到"第一次爽"（破砖/道具） | ≥80% 在 L1 触发过道具或连击飘字 |
| 挫败 | L1 是否有人失球/GameOver | L1 失球率 **≤1 次/人**（L1 球速最慢 480、无硬砖，来源 `ux-spec.md §6.2`） |
| 提示时机 | "拖动屏幕移动挡板"是否在首次拖动后淡出 | 100% 首次拖动后 ≤1.5s 淡出且不重复 |

**通过标准（本轮）**：以上 6 项**全部达线** → PASS；任一项未达 → 记录并进入第 2 轮前调参。
**需调参信号**：≥2 人问"怎么开始/发球" → 提示时机或自动发球需调；≥2 人在 L1 失球 → L1 球速/挡板宽需下调。

## 第 2 轮 · 中盘系统与难度曲线（Mid-game & Difficulty Curve）

**目标**：验证 L2~L5 的**难度单调性**与**单关时长落点**，并暴露"卡关点"。
**样本**：5~8 名玩家（可含第 1 轮回访者）；连续通关至 L5 或 GameOver。
**环境**：真机。

| 观察项 | 埋点 | 判定线 |
|---|---|---|
| **单关时长** | 每关开始→清关（或失败）计时 | L1~L3 落在 60~85s；**L4 ≤90s、L5 ≤90s**（上限，来源 `levels-spec.md §3` / `concept.md`） |
| **难度单调** | 各关失败次数 | 无"难度倒挂"（后关不应显著更易）；L3 允许因布局回落但不得低于 L1 |
| **卡关点** | 哪一关失命最多 | 单关失败率 >50% → 该关需调参 |
| **新变量引入** | 每关是否只加一个新概念 | 玩家能说出每关"新在哪"；"一关一节奏"（来源 `design/design-review.md §2/§3`） |
| **硬砖占比感知** | L4(40%)/L5(29%) 是否过难 | L4/L5 失败率 ≤ 60%（来源 `levels-spec.md §3`） |
| **炸弹"爽点"** | 是否观察到连锁爆发 | ≥50% 玩家在 L4 触发过连锁（炸弹是"制造连击"的核心，来源 `bricks.md §2.4`） |
| **金砖策略** | L5 是否有人优先瞄金砖 | 观察到"优先瞄准"行为 ≥1 次（设计意图：高价值目标，来源 `bricks.md §2.6 G`） |

**通过标准（本轮）**：时长带内 ≥4/5 关；无单关失败率 >60%；至少观察到 1 次炸弹连锁"爽点"与 1 次金砖优先行为。
**需调参信号（回给文策渊，非 QA 决定）**：
- L4/L5 实测 **>90s** → 需下调球速/减行/加炸弹密度（`design-review.md §9.1` 已给出备选旋钮）；
- L4/L5 失败率 >60% → 硬砖占比或球速需回调；
- 出现"难度倒挂" → 关卡参数需重排。

## 第 3 轮 · 韧性 / 中断恢复 / 可访问性（Resilience & Accessibility）

**目标**：验证"**随时能走、回来能继续**"与"减弱动效"承诺，覆盖弱网/中断/特殊需求场景。
**样本**：5~8 名玩家 + 1~2 名对动效敏感/色觉障碍玩家。
**环境**：真机（含低端机、刘海机）。

| 观察项 | 场景 | 判定线 |
|---|---|---|
| **中断续进** | 游戏中杀进程 → 重启 | 100% 续进"上次未通关关卡"，无菜单（来源 `save-progress.md §4`） |
| **切后台** | 游戏中切后台/来息屏 → 切回 | 100% 处于 PAUSED，不自动继续（来源 `pause-settings.md §2.2`） |
| **暂停冻结** | 暂停 30s 后继续 | 球/道具/计时完全一致，无"偷偷前进" |
| **减弱动效** | 开启后玩 L4（炸弹关） | 屏震/粒子/彩带/拖尾**关停**；白闪/飘字/受损态**保留**（来源 `assets-spec.md §6.1/§6.2`） |
| **色盲/黑白** | L5 灰度下 | 5 种砖 100% 可区分（靠形状不靠颜色，来源 `ux-spec.md §7`） |
| **低端机帧率** | 低端机玩 L4（炸弹连锁） | 稳定 ≥30fps，无卡顿掉命（来源 `core-loop.md §5`） |
| **触控** | 单手竖屏操作 | 暂停按钮/主按钮热区 ≥88×88px 可稳定点中（来源 `systems-index §3.7`） |

**通过标准（本轮）**：中断续进、切后台、暂停冻结、减弱动效四项 **100% PASS**；低端机 ≥30fps；灰度下 5 砖可辨。
**需调参信号**：任一"续进失败/暂停跑动"→ **P0 Bug**（见 `bug-severity.md`）；低端机 <30fps → 性能专项。

## 判定线汇总（"什么算通过 / 需调参"）

| 结果 | 判定 | 动作 |
|---|---|---|
| 全部观察项达线 | **PASS** | 进入发布流程 |
| 1~2 项轻度未达（不涉 P0/P1） | **CONCERNS** | 记录 + 快速调参后复测 |
| 时长超带（L4>90s / L5>90s） | **需调参** | 交文策渊调关卡旋钮（`design-review.md §9.1`） |
| 中断续进失败 / 暂停跑动 / 崩溃 | **FAIL** | 立即开 P0 Bug，阻断发布 |
| 难度倒挂 / 单关失败率 >60% | **需调参** | 交文策渊重排难度 |
| 减弱动效关停/保留不符 | **FAIL** | P1 Bug，修后可访性承诺 |
| 首关 >20% 玩家卡在 READY/不知干嘛 | **需调参** | 教学提示或自动发球时机 |
