## 1. 一句话风格定位

> **「暖米纸台上的拼豆工作台」：低饱和纸木容器衬托高饱和几何珠面——珠子是桌上唯一的糖果，UI 是安静的工作台。**
> （替代 art-bible v1.3 锚点「冷紫灰静底」；冷暖对撞退役，改为「暖纸静底 × 糖果珠」的对撞，对撞轴不变：**底静、珠艳**。）

### 1.1 游戏名「拼豆小铺」的命名语义 → 视觉呼应（2026-10-07 定名后新增）

- **语义拆解**：拼豆 = 玩法（品类词，利于微信搜索）；**小铺 = 陈列／收藏的扩展空间**——不是「森林」那种场景叙事，而是「作品被摆上架子」的**容器语义**。
- **视觉落点（一句话）**：**把「铺子」做成一只木框橱窗：招牌（珠拼游戏名）在上，货架格位（陈列已完成图案）在下**，玩家进游戏第一眼看到的不是风景，而是「我的作品会被摆在这里」。
- **两处呼应，形成闭环**（线框见 `screens.md` S0 / S5）：
  1. **boot 标题页 = 铺面**：珠拼招牌「拼豆小铺」（`beadText`）＋ 下方木框橱窗内 **3 格货架陈列**已完成的珠拼图案缩略（首次进入时为空槽 → 用既有「虚线槽」语言，与托盘扩展行同源，零新语言）⇒「小铺」= 一个等着被填满的陈列架。
  2. **finish 通关画面 = 上架**：通关时把已完成的图案**逐格摆进同一只橱窗**（8/9 关缩略上货架，未通关格 = 空槽）⇒ 玩家在最后一屏看见自己的作品「上架」，命名语义在此闭合。
- **为什么与甲案自洽**：橱窗 = 木框（木＝可按的材质语义延伸为「可打开的陈列」）+ 纸底（纸＝承载），**不新增第三族材质**；陈列内容用既有珠体绘制，零美术文件。
- ⚠ **本条为本轮新增建议，非用户已裁项**：替换的是初稿「珠拼大树」主视觉（大树与「小铺」无语义关联，且大树是「森林」命名的遗留物）。是否采纳请主理人转达用户；**不采纳则 boot 主视觉维持「珠拼大树」**，其余定名内容不变。珠面 recipe 在两种方案下均不动。

## 2. 四条设计支柱的可判读定义（玩家看到什么算达标）

| 支柱 | 可判读定义（验收时逐条可查） |
|---|---|
| **休闲** | ① 每屏最多 1 个木质主按钮；② 全部圆角 ≥12、无直角容器；③ 压迫性元素（红色）只允许出现在倒计时告急与失败页一处，不做红点/角标轰炸；④ 所有正文 ≥28px（E1 floor 不变）。**⑤ 验收判读（QA 可引用）**：玩家在任一屏**只需做一个决定**（该屏唯一木钮就是那一步）——抽 6 个相位的静态帧，若 `danger` 红出现在「倒计时告急 / game-over」以外的相位，或某屏出现 ≥2 个木钮 ⇒ **不达标**。 |
| **治愈** | ① 底色为低饱和暖米（`bg #F1E8D8`，饱和度 ≤12%）；② 阴影只有柔投影一种：偏移 ≤4px、α ≤0.14、无硬边描边阴影；③ 无闪烁装饰（全部动效复用 `ux-spec §5` 已冻结毫秒，零新增时长）；④ 失败页文案温和、不红闪（沿用 ux-spec §3.5）。**⑤ 验收判读（QA 可引用）**：玩家看完一屏**不觉得被催促**——逐元素数投影层数 >1、或出现硬边描边阴影、或背景像素饱和度实测 >12% ⇒ **不达标**（饱和度由脚本复算 `[待实测]`）。 |
| **明快** | ① 珠子 10 色是全屏唯一高饱和来源（铁律 1 平移到暖底：纸木全部低饱和，珠子第一眼被读到）；② UI 自身强调色只有 2 个：木棕（可交互）+ 交互蓝（hint/选中环）；③ 屏四边留白 ≥24px，带间净空按 §3.1 冻结带值，不另发明。**⑤ 验收判读（QA 可引用）**：玩家**第一眼先看到珠、第二眼才看到 UI**——截图转灰度后珠面簇与任一 UI 容器簇的明度差 <0.1，或全屏出现第 3 个 UI 强调色 ⇒ **不达标**。 |
| **UI 辨识度高** | ① 容器三档材质即语义：**木 = 可按、纸 = 承载、胶囊 = 状态**（材质+明度+形状三通道区分主次，不靠色相单通道——色盲三重编码纪律在 UI 侧的落实）；② 每个控件 4 态（正常/按下/禁用/聚焦）可视差异 ≥2 个通道（明度 + 位移/描边，见 `screens.md` 矩阵）；③ 图标主笔画 ∈ {3,6}px 纪律不变（F7③）。**⑤ 验收判读（QA 可引用）**：玩家**把截图去色后仍能指认「哪个能按」**——灰度帧下木钮与纸面板明度差须可辨（现值 0.13 vs 0.84，K-4）；去色后指认错误 ⇒ **不达标**（无真机，走查口径 `[待真机]`）。 |

## 5. 层级与阴影

- **z 序 5 层**（与现渲染序一致，不新造层）：背景（宿主铺单色）→ 盘面珠阵 → 控件带（HUD/缩放/托盘/道具）→ 遮罩+面板 → 顶层（横幅/彩带）。
- **阴影只有 1 种**：柔投影 = 同形圆角 rect 偏移 (0, 3px)、`shadow_ink` α0.10（纸面板）/0.08（纸卡）/0.14（浮起态）。**每元素 ≤1 层投影 + ≤1 层内高光/内阴影线**；禁止位图软阴影、禁止多层叠加阴影（渲染原语无 blur，叠层 α 模拟是唯一合法手段——与现行 `panel_shadow` 同法）。
- 托盘面板「微拱白瓷」内阴影 ink 由 `#1E2033` → `#3D2E1E`（暖化，几何/α 不变；`assets-spec §1.3` 同步行）。

## 7. ⛔ 不动项清单 + 与「干净几何珠面」的共存策略

**不动项（逐条，落码与评审都不得触碰）：**

1. 珠子绘制全部层集与系数（现行默认皮肤 = 复刻·四棱刻面；风格池/bead-visual-style-spec §12 体系零涉）。
2. B0 连续目标色底图、空格凹陷坑 S1–S4、locked X 斜纹、hint/wrong/selected 状态语言与毫秒。
3. **托盘里的格子与珠子**：`TRAY_SLOT 48 / TRAY_GAP 6` 几何、槽底 `traySlot #4A5060`（2026-10-06 用户刚定稿）、托盘珠等比内缩口径。
4. 盘面格底/坑底一切色值；`BEAD_PITCH 32 / BEAD_CELL 30 / BEAD_GAP 2`。
5. `systems-index §3` 全部冻结值、`ux-spec §5` 全部毫秒值、`TOUCH_MIN 88`、字号 floor 28。

**共存策略（为什么暖纸底不会和干净几何珠打架）：**

- **对撞轴保住了**：铁律 1「珠子先于背景」的机制 = 底低饱和、珠高饱和。暖纸底与冷紫灰底饱和度同级（≤12%），对撞轴从「色温」平移为「材质温度」——几何硬边珠面在软纸底上读作「整洁的手工材料」，干净感不降反升。
- **几何语言不混**：UI 容器圆角 ≥16 且全部带 1px 暖描边；珠面保持现行无外描边、靠倒角明暗的语言。两族（「描边容器」vs「无描边珠」）互不模仿 ⇒ 不会互相读混。
- **唯一风险点如实登记**：奶白珠 `#FDF6E9` 对 `#F1E8D8` ΔL ≈ 5.4%，是 10 色中最弱对（靠珠自身暗倒角 L2 与 L0 投影补分离）⇒ `[待真机]`；若真机判糊，回退杠杆 = `bg_base` 加深至 `#EDE2CC`（ΔL ≈ 7.7%），单 token 改动。

## 8. 包体承诺

零位图、零字体文件、零新图集 ⇒ **美术位图 +0 KB**；图元增量 = 木按钮 sheen/底缘线 +2/钮、木钉圆 0（本版无木钉）⇒ 全帧最坏 +≈20 图元 `[待实测]`（落码须按 K-051 差分复算，不沿用纸面值）。主包红线 4096 KB 不因本批移动。

**boot 页（D-3 采纳后新增）的包体口径**：珠拼标题 `beadText` 与橱窗陈列格**复用珠体绘制函数**，只新增「点阵字模」这一份**纯数据**（4 字 × 字模位图布尔表，字节级）⇒ 位图仍为 **+0 KB**；但**图元数按珠数线性增长**（标题 4 字 + 陈列格缩略），**必须落码时差分复算并走封箱复评**（`risks.md` §2），本轮**不预支数值、不给纸面估计**。
