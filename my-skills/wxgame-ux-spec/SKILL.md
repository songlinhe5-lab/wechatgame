# wxgame UX 规格法（微信小游戏竖屏向）

提炼自 Breakout demo 的 UX 规格（实例：`games/breakout/design/ux/ux-spec.md`），
适用于本仓库任何小游戏。核心立场：**反馈即语言、首屏即玩、随时可走**。

## 1. 设计原则先行（每款游戏定 3-4 条，本文四条可直接沿用）

1. **首屏即玩**：`点击 → 开始` ≤2 次交互，全程无登录/授权。
2. **拇指可达**：核心交互在屏幕下 1/3，控制区低、信息区高。
3. **反馈即语言**：用动效与音效替代文字说明，0 文字教学。
4. **随时可走**：任意状态 1 次操作暂停；进度自动保存，下次启动直接续进。

## 2. 界面流程（Screen Flow）

- 用 ASCII 画完整状态流转图：BOOT 加载分流（首次/有进度/已通关）→
  核心玩法态 → 暂停/结算/通关。
- **能删的界面全删**：主菜单、返回菜单这类"游戏壳"界面能省则省，
  退出交给平台级动作（微信胶囊/系统返回）——并注明"有意为之，非遗漏"。
- **设置入口只留一条通道**（如挂在暂停面板），避免双入口状态不一致。
- BOOT 降级规则必须写：存档非法/越界/版本不识别时**安全降级优先于报错**，
  绝不中断启动。

## 3. 关键界面线框（ASCII，逐屏）

- 每个界面一张 ASCII 线框，标注设计分辨率（如 750×1334）、
  关键元素坐标（对齐 systems-index 冻结常量）、按钮热区（≥88×88px）。
- HUD 注明信息分区：分数/生命/关卡号/暂停钮各在哪个角、显示条件
  （如"连击 ≥3 才显示倍率""刷新最高分才显示 NEW BEST"）。
- 面板类注明遮罩透明度与入出场动效参数。

## 4. 状态流转 × 输入响应矩阵（本 skill 的灵魂）

一张表穷举所有组合，**不留未定义状态**：

| 当前状态 | 可用输入 | 响应 | 下一状态 |
|---|---|---|---|

要求：
- 每行都可被 QA 直接转成测试用例（与 wxgame-qa-gates 的 §B 用例对接）。
- 被裁掉的状态（如 MENU）要显式写"已移除的行"，防止实现时复活。
- 超时兜底必须有（如 READY 1.5s 无操作自动发球——玩家永不卡死）。

## 5. 交互反馈与动效时长表

- 表格四列：事件 / 视觉 / 音效 / 时长（毫秒，精确到可直接落值）。
- 统一缓动约定：进入 ease-out、退出 ease-in。
- **动效红线**：反馈 ≤400ms（过关/结算除外）；关键反馈必须视觉+音效
  双通道（静音玩家不失去信息）；屏震类给硬上限（如 ≤120ms / ≤6px）
  且可在设置关闭。

## 6. 首屏留存策略（微信小游戏首 10 秒决定留存）

- 写**首 10 秒时间轴**（t=0s 点击图标 → 加载 ≤1.5s → 零点击进入 →
  首次"爽点"时刻 → 10s 玩家已理解玩法）。
- 新手引导原则：无菜单、单条提示自动消失永不重复、无强制引导遮罩、
  失败无惩罚（首关要"赢"）、即时奖励、可跳过。
- 启动路径表：玩家类型 × 落地页 × 提示，通常只有 2-3 行。

## 7. 可访问性（与美术规格对接口）

触控 ≥88×88px、对比度 ≥4.5:1、色盲三重编码（引用 art-bible）、
减弱动效开关、单手持握、高对比描边。逐项标注与 `art/accessibility.md` 的对齐关系。

## 8. 决策记录与待确认项

已裁定项（谁裁的、理由）与剩余待确认项（附建议）分列——
待确认项不超过个位数，实机验证后关闭。

## 纪律

一切坐标/时长/尺寸引用 `systems-index.md` §3 冻结常量；冲突以它为准。
实例参照：`games/breakout/design/ux/ux-spec.md`。
