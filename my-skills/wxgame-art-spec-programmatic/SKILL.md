# wxgame 程序化美术规格法（三件套）

提炼自 Breakout demo 的美术流程（实例见 `games/breakout/art/`），适用于本仓库任何游戏。
核心策略：**demo 阶段零外部美术文件，全部程序化绘制 / 纯色几何占位**
（Cocos 侧 Graphics 或纯色 Sprite，浏览器侧 Canvas2D）；规格先行，
程序据此落码；为未来替换真实资产预留提示词与图集策略。

## 1. 美术圣经（`<game>/art/art-bible.md`）

```
## 1. 视觉锚点（一句话，来自 concept.md §8）
## 2. 情绪板（文字描述即可，不依赖外部图片）
## 3. 配色系统（具体 HEX）
   3.1 基础色板  3.2 元素类型配色（核心）
   3.3 类型三重编码（色盲友好硬要求：颜色+形状+符号，不允许仅靠颜色区分）
   3.4 特殊元素视觉语义锚定（对齐对应 GDD 节）
## 4. 构图与布局
   4.1 设计分辨率（权威定义，对齐 systems-index §3.1）
   4.2 安全区（微信平台留边）
   4.3 场地布局（引用冻结常量，不抄写）
## 5. 形状语言   ## 6. 元素视觉语言（逐项）
## 7. 动效气质（毫秒值，对齐 ux-spec）
## 8. 材质与光照
```

## 2. 资产规格表（`assets-spec.md`）

- **前置约定**：程序落码直接引用本表，不再二次发明。
- **资产清单**：每个可见元素一张规格卡——尺寸、颜色、层次、
  动效参数（全部来自冻结常量）。
- **未来真实资产替换提示词**（AI 生成备用）：现在就写好，
  每条描述风格/尺寸/约束，替换时直接使用。
- **图集策略**：微信主包预算内规划；**命名规范**先定死。
- **包体预算表**：主包预算分配（如引擎 ≤1800KB / 业务 ≤400KB 的内部目标）、
  分包与未来资产预算、美术对包体的承诺（超出预算的方案不出）。

## 3. 可访问性分级（`accessibility.md`）

- **三级承诺**：Basic / Standard / Comprehensive，本项目声明达到哪级。
- **特性矩阵**：逐特性 ×（支持/不支持/部分），含减弱动效开关
  （关停清单 / 保留清单要具体）。
- 与 UX 规格的接口对齐（引用 ux-spec 对应节）。
- 明确"待用户审批项"——不替用户拍板。

## 纪律

- 一切尺寸/颜色/时长引用 `systems-index.md` §3 冻结常量，冲突以它为准。
- 色盲友好三重编码是硬要求，不是建议。
- 实例参照：`games/breakout/art/`（art-bible / assets-spec / accessibility）。
