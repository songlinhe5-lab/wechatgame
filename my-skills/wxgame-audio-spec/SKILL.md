# wxgame 音频规格法（五件套 · 框架版）

> **本 skill 是框架骨架**：源自专家团音频域职责结构 + Breakout UX 动效表的音效列，
> 项目专属数值（曲目、响度、格式预算）均标 `[TODO]`，首款游戏实做音频时由
> 音频负责人填充并回写本 skill。执行层工具：配乐用 `indie-game-ost-pack`，
> UI 语音用 `game-ui-voice-pack`。

## 1. 音频方向基调（Music Direction）`[TODO: 每款游戏定]`

- 一句话音乐气质（对齐 concept.md 视觉锚点与 MDA 美学层）。
- 参考风格与"不做什么"（负面清单，防止跑偏）。
- 情绪曲线：菜单/核心玩法/危机/胜利/失败 各段的音乐情绪档位。

## 2. 音频事件表（SFX Event Table）—— 本 skill 的灵魂

**来源纪律：每个音效事件必须能追溯到一个游戏事件，事件表与 UX 动效表
（`ux-spec.md` §5 音效列）逐行对齐，不发明表中不存在的音效。**

| 事件 ID | 触发源（UX §5 行 / GDD 节） | 音效描述 | 优先级 | 状态 |
|---|---|---|---|---|
| SFX-001 | （如：球撞挡板 40ms） | `[TODO]` | 核心/次要 | 待做/已做 |

规则：
- **双通道红线联动**：UX 动效红线要求"关键反馈必须视觉+音效双通道"，
  因此凡 UX §5 标了音效的事件，此处必须有对应条目——反过来也成立。
- 事件 ID 全局唯一，代码引用 ID 不引用文件名。
- 每条标优先级：核心（缺了体验崩）/ 次要 / 打磨。

## 3. 音乐结构（BGM Structure）`[TODO]`

- 场景-曲目映射表（哪个状态放什么曲子：如 PLAYING 循环曲、FINISH 胜利乐）。
- 循环设计要求：无缝 loop（进引擎前必须试听循环点）。
- 情绪分层策略：是否用分层音轨（stem）随游戏强度变化——demo 可不做，写明取舍。

## 4. 混音规范（Mix）`[TODO]`

- **Bus 结构**：Music / SFX / UI 三条总线起步，各自独立音量档。
- 响度目标：BGM 与 SFX 的相对平衡基准（如 SFX 略高于 BGM，具体 dB `[TODO]`）。
- Ducking 规则：关键 UI 音（按钮、结算）触发时 BGM 短暂压低。
- 全局静音降级：**静音状态下游戏必须完全可玩**（与 UX 双通道红线互为因果）。

## 5. 实现策略（Implementation）

- **平台**：微信小游戏音频 API 约束 + 浏览器 harness 双端行为一致（对齐框架 adapters 层）。
- **包体预算**：音频文件总量计入 systems-index §3.8 包体预算，格式/码率
  选型在此约束内定（`[TODO]`），超预算方案不出。
- **预加载策略**：BGM 预加载，SFX 按需 + 池化，避免首响延迟。
- **存档联动**：音量设置持久化（对齐存档系统 S8，字段进存档版本矩阵）。
- **可访问性**：与"减弱动效"开关联动的音频项（若有）逐条列出。

## 6. 交付与验收

- 每条音效/曲目交付物：文件 + 事件 ID 映射 + 循环点说明（BGM 必附）。
- 验收判据写进音频事件表"状态"列（待做/已做/已验收），不发明独立判据体系。
- 项目实做完成后：把实际数值回写本 skill 的 `[TODO]` 位，沉淀为该域完整方法。
