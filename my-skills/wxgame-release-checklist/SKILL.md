# wxgame 发布清单法（微信小游戏四件套）

提炼自 Breakout demo 的发布流程（实例见 `production/release/`），适用于本仓库任何游戏。
两条铁律：① **平台红线与内部目标分清**（红线=微信主包 ≤4MB、主包+分包 ≤30MB；
内部目标=项目自定的更紧预算）；② **诚实约定**——AI 只产出可核实的材料，
官方规则一律标注"以官方入口为准"并列出官方链接，不编造审核细节。

## 1. 发布清单（`release-checklist.md`）——六阶段 + Go/No-Go 门控

```
## 0. 使用说明 + ⛔前置声明（红线 vs 目标，先读）
## 1. 构建前 Pre-Build：版本与范围冻结 / 包体预算核对 / 依赖就绪
    / 漂移登记表（已知"设计 vs 代码"不一致逐条列出）
## 2. 构建 Build：构建命令、产物核对、包体实测 vs 预算
## 3. 自测 Self-Test：功能体验 / 真机适配 / 合规自测（提审前）
## 4. 提交审核 Submit：材料核对、提审信息填写
## 5. 上线 Release：发布方式（全量/灰度/体验版）
## 6. 上线后观察 Post-Launch：崩溃率、反馈渠道、观察期
## 7. 门控汇总（每阶段 Go / No-Go 条件）
## 8. 变更记录
```

## 2. 上架材料（`wechat-submission.md`）

- 账号主体（个人 vs 企业差异）、游戏类目选择、合规材料清单（逐项标注
  本项目适用性——demo 无内购/广告/排行榜时材料大幅减少，明确写"少掉的负担"）。
- **审核常见驳回原因自查表**（自行核实，标注官方入口）。
- 包体与分包上传要求、体验版与灰度流程。
- 明确边界：本轮 AI 能做的 vs 需用户实操的（如扫码、认证、付款）。

## 3. 版本策略（`version-strategy.md`）

- **三个版本号分清**：游戏内版本 / 微信后台版本 / 构建号。
- SemVer 规则 + 0.x 阶段特殊约定 + 预发布标识（-alpha/-beta/-rc）。
- 热更新边界：先回答"本项目是否需要热更"，不需要就写明结论与理由，
  需要时列出前置条件（备忘，不当期做）。
- 变更日志：Keep a Changelog 风格，面向对象分层（玩家看 / 开发者看），
  `[版本号] - YYYY-MM-DD` + Added / Changed / Fixed。

## 4. 回滚预案（`rollback.md`）

- **回滚的两种含义先分清**：版本回退 vs 功能开关降级。
- 触发条件：Blocker 级（立即升级决策）/ 非 Blocker（评估是否值得）。
- 微信小游戏回滚手段与**平台限制**（如实记录，哪些做不到）。
- **本地存档兼容性是最大风险**：版本矩阵 + 回滚场景存档推演 +
  发布纪律前置防线（新版本必须能读旧档）。
- 角色与流程（决策人、时效目标）、热修简化流程、
  **回滚预案模板（每次发版前填一次）**。
