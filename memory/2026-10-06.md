## 合成式三端统一 + 旧 effect 死件清（WXG-T-259 · 第廿刀）

- **用户裁定（原话）**：「旧 `assets/scripts/game/view/tint-mask.effect` 死文件清除 / GPU 为准 ⇒ CPU 去乘 shape / 提交」
  —— 对上一轮（WXG-T-258 D 项）一致性核查留下的三个待拍板问题逐条拍板。
- **式统一不是新口径，而是代码回归规约**：`tint-mask-asset-spec §5.1`、ADR-0028 §2.1、定标单 §7.2 本来写的都是
  `out = base·d + (1−base)·l`、`alpha = shape`；偏离者 = TS `compositeTintMask` 的 `ls = l·shape` 与
  `preview-combined.py::composite()`（后者头注自写「与 shader 结果一致」而代码不符 ⇒ 自相矛盾）。
  ⇒ 两处同时改，py 重烘 `preview-combined-{128,1024}.png`（这两张是**在册产物**，改式必须重跑生成器）。
- **影响面可静态预测**：shape 二值（0/255）时 `l·shape ≡ l` ⇒ **逐字节不变**；只有珠 mask 的 **1242/16384** 羽化像素变亮
  （旧式 base 0.56 臂差 40.7/255）。格 mask 纯二值 ⇒ 上一批的盘面/托盘读数不受影响。
- **新门比改式更值钱**：旧测试里 shape 全取 0/255 ⇒ **改错了也不会红**。补一条羽化带腿（`shape=128/200` 三点 ⇒
  RGB 与 shape 无关）；判别力已验：旧式算 `(68,68,71)` vs 新式 `(106,106,108)`，差 38/255。
- **删资产踩到的镜像树坑（本批最有用的一条）**：`cocos/assets/scripts/game/**` 是 `games/beads/src/**` 的
  **镜像拷贝件**，旧 effect 的**正本在 src 侧**。只删拷贝件 ⇒ `framework:sync:check` 报 `OUT … (missing)` ⇒
  `build:cocos` **前置检查直接拒绝构建**（「直接构建会编出旧代码」）。⇒ 镜像树删文件**必须两处成对删**，
  且「构建被拦」是好事：它正是防止「编辑器里看不见但源码还在」的那道门。
- **重建档位时又踩一次老坑**：`build:cocos` **默认 debug**（含 sourcemap 不压缩），我按上一批的命令重跑 ⇒
  `check:size` 报主包 6082 KB「超平台红线」+ 疑似 debug。⇒ 测基线 ⛔ 必须 `--release`（脚本尾部本就提示，别只看第一行）。
- **在册自纠**：WXG-T-258 的主表行与详情节都写了「定标单 **v10.0**」，但 `tray-neutral-slot-mask-spec.md` 当时只到 v7.0
  ⇒ 本批补写 **§8 v10.0**（a=258 环带 / b=259 式统一），并修正 §7.2 公式行与 §7.3「槽底不得透明」（现况 = 仅无孔档仍守）。
- **诚实边界**：本批只证「公式同式」，⛔ 不证「屏幕逐像素相等」——真机 S3 同帧对拍仍需 `[R]`（K-037）。

## 提交被 ctx B 门拦下 → 分片子切 + 四件豁免（WXG-T-260 · 第廿三刀）

- **现象**：`git commit -F` 被 pre-commit 的 `ctx:check` **B 项**拦下 7 件（ADR-0030 45088 / control-manifest 8549 /
  knowledge CHANGELOG 8153 / INDEX 8972 / lessons engine-cocos 8618 / process 8752 / testing 8722）。钩子尾部那句
  「暂存内容与刚重建的索引仍不一致」是**连带诊断文案**，不是独立原因（`--staged` 只改 C 项数据源，A/B/D/E 不变）。
- **定责法（比绕过门禁重要）**：`git show HEAD:<file>` + `estimateTokens` 实算 HEAD 侧 token ⇒ 六件在 HEAD **全部门下**
  ⇒ 越限归属本会话 257~259 三批沉淀，不是存量欠债。⚠ 别按文件字节数判：CJK 约 3.2 B/token，一行长条目可含 500~1100 tok。
- **政策硬约束决定分流**：`knowledge/INDEX.md §4` + `memory/MEMORY.md:17` + 指针页尾三处同口径 —— lessons 各分片
  **不得新增豁免**，越阈只能「标签内部再切」（取向同 WXG-T-041）；先例 WXG-T-221（criteria→criteria-render）/ WXG-T-235。
  所以只有非分片件（ADR / control-manifest / knowledge 入口两件）具备豁免资格。
- **直觉路走不通要实跑排除**：本想「归档一批条目同时降分片与 INDEX」，`kb:audit` 实跑 = **归档候选 0 条**（活跃 115 / 归档 0，
  阈值=闲置 ≥90 天且访问 ≤1）⇒ 诚实排除这条路，取证写进 260 详情节。
- **子切一律走脚本 + 三重自证**（判例 K-030「手工拼长文件必出错且看不出来」）：回拼≡原文逐字节 / 块数≡lib 解析条目数 /
  写后重解析行内标签≡新片。两处 bug 都在**写盘前**被自证拦下（① 回拼漏块间空行 ② `render()` 对已含 `## tag` 的前缀二次追加标题）

  ⚠ `knowledge:split` 是**一次性迁移工具**（片目录已存在即早退），不能拿来再切。
