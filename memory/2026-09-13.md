## G2 验收通过 + G4 输入链路三连修（22:30-23:05，主理会话）

- **挡板"不动"的真相**：不是链路断，是**命中区**——Cocos touch-start 必须落在监听节点 UITransform 矩形内，GameRoot 只有设计区 750×1334，宽屏下信箱区全死。铁证：pointerX=115.61 == screenToDesign(500)，分毫不差。
- **修复 1（bindings）**：触摸监听改挂 Canvas 节点（全可见区命中），回退 this.node。
- **修复 2（bindings）**：readTouch 弃用 getUILocation 改用 getLocation（画布相对 CSS px，符合 RawPointerInput 左上原点契约）；删 mapPoint 的 y 翻转（与 screenToDesign 双重翻转相消，y 轴反了）。
- **修复 3（bindings）**：launch 时 `_fitToGameCanvas()`——app.resize(canvas.clientWidth/Height)。实测 getLocation 是画布相对（页面 600 → 335），而 Web platform.getScreenSize 给整窗 1280×720，viewport 空间错位一个画布偏移。微信下画布=全屏，no-op。
- **修复 4（core/input-manager，真框架 bug）**：beginFrame 清 `_downThisFrame/_upThisFrame` → 事件驱动宿主（Cocos）帧间到达的 push('down') 在 game.update 读取前被清，**justDown 永远不可见，tap 发球从不触发**（harness 同步喂样本所以从未暴露）。改为 endFrame 独占一次性标志生命周期。226+40 测试全过，无测试锁死旧语义。
- **验证断点**：代码全部落库 + verify 全绿，但编辑器未自动拾取外部变更（fit 仍 1280×720 / imFixed=false），需用户聚焦 Cocos Creator 触发资产刷新后再 playwright 复测（拖挡板 350→750 + 300ms 按住点击发球）。
