44. **纯函数先行、实装另单的价值**：把换算做成纯函数后，四档逐机数值可以**在 Node 里钉死**（16 判据），等平台 API 接入时只剩「喂三个数」这一步 —— 迁移成本为零。反过来先接 `wx` 再抽函数，就得回头补测试。
45. **「不要写宏」这条质疑抓到了真 bug**：`safeEdgeInset` 里的 `max(floor, 接口换算)` 语义 = 「接口值超过宏才生效」⇒ 静态宏在真机上当家（非刘海 112→124、Pro Max 底部 59→72）。改成「接口 > 0 就只信接口」后差值只剩两个数，且都是宏本不该参与的场合。**教训**：`max(静态兜底, 运行时值)` 看着安全，实际把兜底升格成了下限依据；要写就写「运行时值有效 ⇒ 只用它」+「无效 ⇒ 兜底」。
46. **宏删不到零时必须引用外部权威说明理由**：微信官方 `getWindowInfo` 原文「部分机型没有安全区域概念，也不会返回 safeArea 字段，开发者需自行兼容」⇒ 这才是保留 `SAFE_TOP_H`/`SAFE_BOTTOM_H` 的正当理由，而不是「以防万一」。顺带发现同一触发条件能兜住 Android targetSdk 35/36 把 `safeArea.bottom` 报成 `screenHeight` 的社区实测 BUG （inset 算成 0 ⇒ 走兜底），该虚报登 `[待真机]`，不在纸面上加夹取逻辑。
47. **改语义要留一条「相等式」断言**：光有「结果 ≥ 胶囊底换算」的不变式挡不住旧 `max` 回潮——它同样满足 ≥。新增 `expect(topbar(56,375)).toBe(112 + MARGIN)` 且 `.not.toBe(SAFE_TOP_H + MARGIN)` 才把「宏不得参与」钉成可失败判据。
