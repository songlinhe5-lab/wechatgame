## 二十五批 · Cocos 生产通道同源绘制：ADR-0030 交付 + 用户四刀回话改写（WXG-T-247，⛔ 零实现代码）

  ⛔ 不得记 D1/D2「≥2 台低端同向」达线）。**教训：引用环境事实表前先跑三条 <1s 的命令复核。**

**2) zoom 的「两个正交分辨率源」（本批最有价值的一处分析修正）**
初稿把「每帧重量绘」当成保锐利的唯一解 ⟹ 不准确。丙′ 的纹理是**整幅盘面帧**（矢量底图 + 珠 blit 同一张 canvas），所以：
- **源 A = 帧纹理分辨率** → 决定**矢量部分**（格缝/底图/坑沿）锐不锐，这才是 Q2 三选项管的；
- **源 B = 珠子 mask 档位** → 决定**珠子本体**锐不锐，与 Q2 **无关**：`BEAD_CELL=30` ⇒ 满 zoom 物理边长 `30×2×3 = 180 px`
  vs `MASK_CANONICAL_SIZE=128` ⇒ **已 1.41× 放大**，且 `TINT_LOD_MAX_UPSCALE=null`（永不回退）⇒ **harness 今日就在这么糊**，
  选 (a) 也救不了珠子，选 (b) 也不会让珠子更糊。
⇒ 于是拆出**决策 II**：既然 mask 改走 PNG，加投 **256² 档**（180 < 256 ⇒ 转下采样，四张估 ≈ 77 KB）是顺手的事；
或给 `TINT_LOD_MAX_UPSCALE` 填真值让超阈帧回矢量臂（那几帧不再同源，但两端仍一致）。

**3) Q4 裁定的包体实测（不是"位图很小所以无所谓"）**
四张 128² mask = 8,750 + 4,210 + 3,395 + 2,872 = **19.2 KB**；`textures.meta` 无 bundle 标记 ⇒ 落 `assets/main` 计主包（正是所求）。
`check:size` 实测 beads 主包 **2866.8 KB / 32 文件**（gzip 1334.6 KB）⇒ 距平台红线 4096 KB 余 1229 KB，但 **已超内部目标 2000 KB**
（守卫仅 WARN，K-089「无牙齿」在数上成立）。⇒ DEC-4 改写为：投放位图命中 §19 硬前置，须先过 `TC-TINT-18` + `verify --strict`，
且须回写 `architecture.md §5.1`「首屏 0 图片」**例外**；换肤/增量替换的前置 = `textures` 改 bundle（**编辑器动作**，L1 禁手编 `.meta`），
当前 `game.json` 无 `subpackages`；两张 `holeless` 的 `.meta` 待导入 = (b) 路线今天唯一真阻塞。
