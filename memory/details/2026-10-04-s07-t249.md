## 二十九批 · 选型调研 + 甲″ 分层上界出数（2026-10-05 · WXG-T-249 · ADR-0030 §5.0.3）

**本批起源 = 两问一裁**（用户原话顺次）：「丙′ C　甲′ A 请调研，最佳实践推荐哪个？」→「甲」（= 我给的选项 A：开 甲″ 三层工程单）。

**1) 先答「两方案各自优势局限」（只算本仓实测账，不引外部）**：本质差别 = **成本落在哪一侧**。
丙′ 把命令重放搬到 Canvas2D ⇒ 换 GPU 侧几何/α 层（tris 182 vs 3354 vs 37k–55k），代价是**每脏帧一次满幅上传**；
甲′ 把珠子变成引擎原生节点 ⇒ **零每帧上传**，代价是层级/节点遍历回来。**门控改变了这笔账的形状**：静置期三臂都只剩 2–3 真脏帧，
而 beads 观感批几乎全是逐帧动画 ⇒ 动画期满载，**门控后换臂的增量收益需重算**（此句已写进 §5.0.2 末）。

**2) 外部最佳实践调研（4 组 WebSearch，逐条可源）**：离屏 canvas 每帧上传的行业读数全部是**负面**
（Babylon：`texSubImage2D` “same or worse”，解法是降到 32 ms 节流；Spine/Construct3：iPhone 每帧上传 ⇒ 60→30 fps；Android NDK：512² 上传 130–150 ms）；
微信官方虽推「单上屏 + 多离屏 canvas」，但同页写明「鸿蒙 OS 暂不支持外接纹理」与「避免过大宽高（安卓会 crash）」，
且**视频场景已改走 `wx.createVideoDecoder().getFrameData()` 直传**而非 canvas 上传 ⇒ 丙′ 押的是**两条未证平台能力**；
Cocos 侧三原则（图集统一 / 渲染序连续 / 统一材质）与「UI 单独一层做位置同步」= **正是甲″ 的形态**；
动态合图小游戏默认禁用需最外层 `macro.CLEANUP_IMAGE_CACHE=false`，入图条件 <512（我们 128 符合）。
⇒ **推荐：甲′（以甲″ 三层形态实施）为主选，丙′ 降为第二候选**（同源观感收益不变，变的是成本风险已拿到数）。

**3) 落位裁定（ponytail 阶梯，关键一条）**：DEC-1 未裁 ⇒ ⛔ **不碰生产**；而甲″ 的「真分层」必然要改生产接线。
⇒ 本批只在**取证面**加一个 `layers=full,beads` 档测**上界**（非珠层整体停用），拿不到精确值但能回答「值不值得做」。
⚠ 实现陷阱（已沉淀 **K-104**）：必须**关组件**（`enabled=false` / `active=false`），不能「不喂命令」——
`CocosRenderModelRenderer.draw()` 内部才 `g.clear()` ⇒ 不喂 = 上一帧内容继续提交 = 读数成一份**冻住的矢量层**（会得出「什么都不省」的假结论）。
显隐逻辑收敛成**单一 `_syncLayers()`**（`setArm` 与 `setAtlasLayers` 各写一遍必漂）；驱动脚本按臂展开（非 atlas 臂恒 `full`）。

**4) 读数（`[E]` Apple M4 · dpr2 · gate=on · frames=150 warmup=40 · zoom 0.6/1/2）**：`full` ⇒ dc **15** / tris 3354–3137 / draw 0.9–1.0 ms / GPU 2.15–2.26 / tick 1.3–1.4；
`beads` ⇒ dc **2** / tris **740（708）** / draw **0.10 ms** / GPU **0.42–0.81** / tick 0.7–0.9
⇒ **非珠层恒占 13 dc + ≈0.8 ms CPU + 1.3–1.8 ms GPU，且与 zoom 无关**（甲″ 三层的理由坐实）。
**两处归因修正**：① §5.0.1 结论 7 写的「`dc 16` = Sprite 与 Graphics 交错打断合批」**被推翻** —— 真因是**相加**（非珠层 13 + 珠池 2；280 个 Sprite 自己就合成 2 批 ⇒ 图集/合批**成立**，`ADR-0022` D6 的桌面部分怀疑可销）；
② 抖动如实登记（本次 dc 15 vs 上次 16，差在 HUD 文本批次）。

**5) 🔴 本批最重的意外 = 在册上限被实测推翻**：`render-model.ts` 的 `ponytail:` 注释原文理由是「含 blit 的载体每帧成本在上传不在命令重放 ⇒ **损失小**」；
实测两档 `drawn` 都是 **150/150**（而 `chg` 只 3–4）⇒ 门控对含 blit 模型**恒判脏** ⇒ **甲′/丙′ 完全吃不到 §5.0.2 的收益**，且「损失小」不成立（每帧照付 13 dc + 0.9 ms）。
⇒ 处置：① ADR 把它从「延后」升格为 **DEC-1 改裁 甲′ 的硬前置**；② K-102 就地追加追记（**先改注释理由再回写 ADR**，不得只加新注释不修旧理由）；
③ 框架代码**不在本批动**（零生产改动纪律），登为未闭环 ①/⑥。**下一口最小收益单 = `signature()` 逐键走 `fx`，收益上限 = 本表 `beads` 那行。**
