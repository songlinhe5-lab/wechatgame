## WXG-T-096：beads 音频后端落码（BD-05 / BD-05b，路线 ADR-0013）

- **架构裁定（ADR-0013 新建）**：合成引擎 `SynthAudioBackend` 住 `packages/framework/src/platform/audio-synth.ts` —— 不能进 `core/**`（L2 禁 DOM/`AudioContext`）、不能进 `games/*/src`（L3 + Node 可测）；**音色表归游戏侧** `Game.audioVoices` → `App` → `Platform.createAudioBackend({ voices })`；未登记 clip = **不发声 + 一次性 warn**（禁止引擎发明音色）；能力缺失 ⇒ `NullAudioBackend`（不谎称 iOS 能出声）。备选「引擎住游戏侧」「音色进框架」「weapp 用 InnerAudioContext 播文件」三条的否因都写进 ADR §2。
- **与旧政的关系**：`memory/2026-09-12.md:137` 曾裁「不动框架」，把双调度器缺口登记为未来项。本单任务书批准改 backend，但落地比旧注更保守（**只扩工厂入参**，没把 backend 交给 `GameServices`）⇒ 旧缺口**仍未关闭**，beads 继续「单调度器 + 双逻辑通道」。教训：**执行旧裁决的继任单，要在 ADR 里写清「哪一半没做」**，否则下一个人以为缺口已关。
- **autoplay 契约（§4.4）关键设计**：context 不在构造期建；`unlock()` 由平台首次手势触发并摘监听；解锁前一次性请求**丢弃**、loop 记 `_wantedLoops`（**期望态**与「正在播」的 `_loops` 分离）⇒ 退后台 `suspend()` 保期望态、回前台 `resume()` 补起，BOOT 期 `bgm_main` 不丢。
- **限流必须分档**：旧「统一 0.05 s」让 `sfx_reject` 达 20 次/秒，违反 §3.8「错误反馈 ≤2 次/秒」（冲突 C-A05-4）⇒ 改 reject 0.5 / urgent beat 0.9 / tray_full 1.0 / place·select 0.05 / 其余 0，常量落 §3.12 已冻结值。
- **`AudioScheduler` 实测语义（写测试必知）**：`flush(dt)` 先 `_time += dt` 再派发，`_lastPlayed` 在 flush 时写 ⇒ 「emit → tick」顺序会让 per-clip 间隔**恒为 0**（正确顺序：推时钟 → emit → flush）；`_pending` 无条件清空且按 clipId 去重 ⇒ 用例前必须先 `flush(0)` 排空再清记账数组，否则上一例的心跳/ BGM 会漏进本例。
- **顺手抓到一处伪实现**：`setVolume()` 原写 `playbackRate.value = 1`（与电平无关的空操作）⇒ 改 `ActiveLoop{src,env,base,voice}`，`_wantedLoops` 存**未乘 clipGain 的基准值**，`setVolume` 对正在播的循环曲当场改 `env.gain`；测试从「只断言不抛」升级为断言真实增益（1 → 夹 1 → 夹 EPS → 0.4）+ 不重启位置。**教训：`不抛异常` 型断言能长期掩盖空实现。**
- **QA 冲突 C2 核账**：`sfx_revive_ok` 我写成 `bus:'ui'`，而 `audio-events §0` 前缀派生规则与 `audio-spec §2.1` 两处都是 SFX 通道 ⇒ 改 `'sfx'`，并把「§0 前缀派生」写成可机检守卫（`audio-dispatch.test.ts busFromId()`）。同批入档的 ADR-0013 §4.2 补两条 QA 指出的行为限制：回前台 BGM **从循环起点重来**（一次性源不可复用）、循环/噪声 buffer **惰性渲染** ⇒ 首播那一帧多一次 CPU 峰值（均归 `[B]/[R]`，不自行判缺陷也不声称已验）。
- **BD-34（本轮附带发现，量级高于音频本体）**：`_readInput()` 唯一调用点在 `_stepPlaying` ⇒ **PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH 四个面板相位在真输入链上收不到点击**；`App.tick` 是 `beginFrame → game.update → endFrame`，一次性标志被 `endFrame` 清 ⇒ 是**丢弃**不是延后。harness 与 Cocos 都走 `input.push()` 这条真链 ⇒ **浏览器里点不动结算面板**，很可能就是用户最初「没法玩」剩下的那一半。为什么长期没被发现：所有面板单测与探针 P22 都用 `game.tapDesign()` 旁路。**建议立 WXG-T-100**（未擅自开工：改的是玩法输入，不属 T-096 范围）。
- **BD-20 复发的真实成因（不是工具 bug）**：严守真实跑 `framework:sync:check` EXIT=1（12 处 differs）为真，我此前报的「13 PASS」在当时为真、随后失效 ⇒ 成因是**改了 `packages/framework/src/**` 却没重跑 sync**。排查中一度怀疑「sync 会把 `{ }` 规范化成 `{}`」——**错的**：`transformSource()` 只做 `.js` 剥离等替换，仓内本来就有 `{ }` 样式件且镜像一致。**确诊法：先读工具源码 + 拿 HEAD 两侧取证，再谈「工具 bug」。** 预防：改框架源码后固定「sync → verify」连跑；建议给 pre-commit 加「暂存含 `packages/framework/src/**` 才跑 `sync:check`」条件步（**待拍板**）。
- **交付与验收数据**：framework **255** 例 / beads **225** 例（`audio-dispatch` 27 例、`audio-synth` 15 例）/ breakout 239 例；`pnpm run verify` = **PASS 13 ｜ SKIP 1（`check:size`，无 `wechatgame` 产物）｜ FAIL 0**，与镜像在同一状态下复取。严守真 P5 复跑（报告 **v1.2 §19**）：PASS 12 / PASS* 8 / FAIL 0 / ⛔ 8 ⇒ **G4 仍 CONCERNS**。
- **部分交付（不冒充）**：① weapp `InnerAudioContext` 池**未做**（与 §3.12「主包音频 0 KB」正面冲突，回退须主理人先解除余量冲突）；② `sfx_ui_tap` 40 ms 是占位（`ux-spec §5` 无该行，Q-A05-1 未裁）；③ 三总线增益一律 1.0（`AUDIO_BUS_GAIN_* = [TODO]`，伪 dB 比静音更糟）；④ A05-25 `[C]` 包体与 A05-27 `[R]` 真机**均未验**；⑤ BD-33 三个新镜像脚本缺 `.ts.meta`（**只能由编辑器生成**，本环境无编辑器 ⇒ 写明阻塞，不伪造）。
