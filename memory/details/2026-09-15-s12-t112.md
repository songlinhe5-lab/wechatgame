## WXG-T-112：装置自指类门禁缺陷评估（波次4 第九轮 · BD-38 关单）

**结论**：BD-38 与 `ctx/BUDGET.md` / `ctx/hot-files.md` 是**同一根因**——`ctx:build` 自己写盘的 .md 产物，
在提交索引里取的却是**改写前的旧字节**（`resolveContent` 的 committed / staged-blobs 分支：dirty → HEAD blob、
已暂存 → 暂存 blob），而钩子随后 `git add` 把新字节推进暂存区 ⇒ `ctx:check --staged` 必红 ⇒ 每次涉及它的提交
都要提交两遍。`memory/INDEX.md` 只是**漏登记**进 `lib/context-index.mjs::WORKTREE_AUTHORITATIVE`。

**取证（隔离 `git worktree`，基线 = `3fa3be4`，全程不动在飞工作树）**：改日记一行 → 只 `add` 该日记 → 跑真
`pre-commit`：**基线三种起手（A 只暂存自有改动 / B 手跑 build 并 add 四产物 / C 手跑 build 不 add 产物）第一遍
全部 exit 1，诊断只点名 `memory/INDEX.md`；把该路径加进集合后三起手第一遍全部 exit 0**。三方 sha 对账直接坐实：
`idx=e6c82d12 == head`，而 `staged == worktree == 694e63d8`（另两个产物 `idx == staged == worktree`）。

**两条推翻既有认知的实测**：① 我上一轮记的「不手跑 `ctx:build`、让钩子自建即一次通过」是**错的**——那次一次通过
是因为前两遍失败时钩子已经把产物 add 过了；干净提交照样第一遍红。② WXG-T-072 的「先写产物、后建索引」三步同源
注释在 committed / staged-blobs 模式下**并不成立**，顺序只是必要条件，取源分支才是决定项。

**三类形态判定（Deliverable ①）**：类①（`memory/INDEX.md` ↔ `ctx/BUDGET.md` / `hot-files.md`）同根因 ⇒ 收口；
类③（任务书假设 WXG-T-111 的 `knowledge/lessons.md` 指针页 + `knowledge/INDEX.md` 生成块属同一形态）**不成立**：
前者的写盘方是 `kb:sync`、后者的指针页出自一次性分片器，都不在 `ctx:build` 的写盘链内，其一致性由 `kb:check` ④
守护 ⇒ 不并入本收口（诚实订正任务书假设，不扩面）。

**落码**：`WORKTREE_AUTHORITATIVE` 补 `memory/INDEX.md` 并导出（连带 `BUDGET_MD_REL` / `HOT_FILES_MD_REL`，消掉
`check-context-budget.mjs` 里的重复字面量）；`ctx:check` 新增**装置自指对账** `C:` 级项（生成物 ⊆ 集合，漏登记
当场红并给出修法位置；实测撤掉登记即 `exit 1` 点名）；新增 `tools/scripts/worktree-authoritative-selftest.sh`
（`pnpm run ctx:selftest`，9/0：静态对账 + 三类 gate 取源 + **判别力对照**（普通 dirty → `head`、已暂存 → `staged`，
防空转）+ worktree 端到端红绿双向）；回写 `.githooks/pre-commit` ② 段与 `docs/agent/hooks-best-practices.md §7`。
沉淀 **K-048**。

**两处自查（自己犯的）**：① 注释里写「本门跑在 verify / CI / pre-commit 三处」——**verify 的 15 项里根本没有
`ctx:check`**（grep 零命中），真实覆盖 = CI（`ci.yml` 的 ctx:check 步）+ 本钩子兜底两处 ⇒ 三处措辞已全部订正并
注明本地需显式 `pnpm run ctx:check`（BD-39 同族）。② 自测初版有两处假绿风险：红测那遍漏了重新施加「缺项」源码
（`run_hook_once` 每遍从工作树拷回正确版就把补丁冲掉了）、`String.replace` 的替换串里以 `$` 开头的序列会被按
特殊含义解释 ⇒ 改函数型替换 + 红测显式传入缺项源。

**代价（如实）**：集合内产物的索引记录跟随工作树 ⇒ 钩子 `git add <产物>` 会把工作树里未暂存的产物改动一并纳入
本次提交（三产物同语义、且是既存行为）；`memory/INDEX.md` 标记块**外**允许手写协议正文 ⇒ 手写后须与改动同次暂存。
未削弱任何既有守卫（手改 + add 在基线与修法下都为绿，实测对照过）。
