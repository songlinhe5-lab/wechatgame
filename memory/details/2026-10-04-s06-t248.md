## 二十八批 · 脏帧门控落地 + A/B 出数（2026-10-05 · WXG-T-248 · ADR-0030 §5.0.2）

用户令：「**先开 WXG-T-248「脏帧门控」**」（采纳上一批四选一的 (A)）。领号已核：头注「下一可用号 248」且 248 仅以头注形式存在 ⇒ 可领（现已顶到 249）。

**1) 落点裁定（三条否决都得留档）**：门控落在 **`App._render` 跳过 `onRender`**。否决乙（游戏侧 revision——改动面大、**漏标即冻屏**）、
否决丙（把 `signature` 塞进 `RenderModel`）——关键事实：beads 有 `wxg-t-211-s3-seal.json` **整帧封箱基准**（判据就是 `JSON.stringify`），
加字段 ⇒ 基线漂移要走 QA 复评；**所以下一次给渲染链加优化，先查有没有封箱基线钉着返回值形状**。另核两事实：
两个渲染器都不消费 `alpha`（grep 实证）；`bindings.ts` 里的 `dbg.gfx.clear()` 属独立 `__wxgTouchDebug` 节点，不是生产 Graphics ⇒ 无外部清空者。

**2) 指纹与失效**：32 位 FNV（`Math.imul(h,16777619)`），数值量化 **1/64 设计 px**（业已写成契约），命令字段 `for...in` 按**插入序**混值（新字段自动纳入），
但 `polygon` 顶点得另走 arena（命令里只有 `offset/count`，不混就是伪绿判据）。`blit` 帧**不入门**：`fx` 袋不哈希 ⇒ 掺 `_frameSeq` 恒判脏（宁多画不漏画）。
失效口四处一律 `_lastSig = Number.NaN`（**NaN 永不自等**）：`_init` / `onShow`（回前台表面可能已释放）/ `resize` / `dirtyGate` 关→开。

**3) 契约变化 = 必须同步登记的那一半**：`onRender` 不再是逐帧钩子 ⇒ 登 `control-manifest §8` 两条 + `app.ts` 接口 jsdoc 警示；
本仓两条宿主均已核（`bindings.ts` 纯转发、`harness-runtime.mjs:236` 包 `onRender` 只为捕获 model）。
⚠ 这类「内部优化」最容易静默上，登记不是文档工而是**越权面清点**。

**4) A/B 取证（同一把尺 = `App.dirtyGate`）**：spike 包 `app.tick` 采整帧 CPU（`CocosLoopBridge` 每次**现取属性** ⇒ 可包），加 `drawnFrames`/`setGate`/`?gate=off`；
驱动器加 `--gates=off,on` 维度与 `tick/drawn` 列。重建 `build:cocos:web`（12.9 s）后跑静置档与 `--disturb` 最坏档各一轮。
**读数**：静置 tick `4.40/4.50/5.00 → 1.20/1.30/1.10 ms`（≈**3.6–4.5×**）、drawn `150 → 2–3`；**dc 14/15、tris、GPU p50 2.26–2.91 两档一致**
⇒ **省的是 JS/CPU，不省 GPU**（引擎每帧仍提交同一份 Graphics buffer）。最坏档 tick `+0.4–0.7 ms/帧` = 指纹代价。
**本轮最大的读数陷阱**：开档 `draw p50` 反而 5.2–7.3 ms——样本只剩 2–3 帧 ⇒ 无判别力，⛔ 不得与关档 3.0–3.9 比大小（这句话已写进驱动器头注，因为读数会脱离会话独立被引用）。
**剩 1.1–1.3 ms 全在「建」**（定步模拟 + `buildRenderModel` 每帧 2031 命令）⇒ 下一口收益 = 跳过「建」的 revision 通道，属新单。

**5) 截图差分归因（差点误报缺陷）**：两档截图 0.25–0.34% 非零像素。先 8×10 带直方图定位（差异只在 HUD 计时 + 托盘，**盘面中段逐像素为 0**），
再做**控制对照**：门控**前**的 `vector-z1.png` vs 今日 g-on（4823 px）/ g-off（3361 px）落在**同样的带** ⇒ 归因为运行间自然漂移（抽珠 RNG + 计时），非陈旧帧。
⛔ 不得写「逐像素相同」（那是不存在的事）。
