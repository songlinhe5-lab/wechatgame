## 构建自动化能力修正：**MCP 不可，但编辑器 CLI 可**（WXG-T-049）

- **本会话上轮结论被自己推翻**：我曾判定「微信构建**结构上不可自动化**」。那只对 **MCP 通道**成立。实测 **Cocos Creator 自带 CLI 可以构建**：
  `CocosCreator --project <proj> --build "platform=<p>;debug=true"`（官方手册《命令行发布项目》）+ 本机 `app-asar` 内含 `--project`/`--build`/`buildConfig`。
  实测 `platform=web-mobile` **3.9s 构建成功**，产物含 `index.html`/`cocos-js/`/`assets/`，日志 `build Task (web-mobile) Finished in (3 s)`，**编辑器实例同时开着也不冲突**。
  **教训：登记「能力不行」必须写明「失败的是哪条通道、哪一层」**——"MCP 不可"写成"构建不可"，会让 `build:wx` 类缺口看起来无解。
- **G1 语法那一半在 web-mobile 上关闭**：产物 `assets/main/index.js` 内命中 `BreakoutBootstrap`/`BreakoutGame`（我们的代码确实被编进去），日志**无** `Unexpected token`、无后缀解析报错 ⇒ `export * from …` 这类 ESM 语法被 Cocos 构建管线接受。wechatgame 平台未测（同一套 packer-driver，风险已大幅下降）。
- **构建产物落点与门禁静默跳过**：Cocos CLI 默认把产物写在**工程内** `games/<game>/cocos/build/<platform>/`，而 `architecture.md §1/§5` 约定的是 `games/<game>/build/`。`check:size` 原先只认后者 ⇒ **产物在、门禁说没有**（K-031 族）。已改为**两处都扫**。
- **落地**：`build-cocos.mjs` = 前置检查 + CLI 构建 + 产物校验；`pnpm run build:cocos`（wechatgame，需 AppID）/ `build:cocos:web`（web-mobile，免 AppID）。实测聚合调用 **12.5s 成功**。
- **我另一处操作失误**：第一次构建被我加的 `perl -e 'alarm 300'` 超时保护 SIGTERM 掉，产出"半成品产物"（只有 `assets/`+`src/`，缺 `index.html`+`cocos-js/`）。**构建类长任务不该套 alarm**；改用 `nohup … &` 后成功。注意：SIGTERM 在**成功的**构建日志里也出现（builder worker 收尾），**不可当失败信号**。
- **A 档 404 根因**：用户在 `cocos/extensions/` 目录下用相对路径 `serve` → 目录不存在 → 全 404。**手机与网络正常**（192.168.1.251 → Mac 192.168.1.248 已连通）。用绝对路径 `serve` 即解决。
- **仍待做**：`preview-template/` 已裁定**忽略**（已加 gitignore 规则）；手机端实玩验收；`build:cocos`（wechatgame）待 AppID 后首跑取**主包空体积基线**（G7）。
