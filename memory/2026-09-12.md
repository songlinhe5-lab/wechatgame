## 专家团 vs my-agents 跨平台复用评估（调研结论）
- 三 IDE 均原生支持项目级 subagent 目录：CodeBuddy `.codebuddy/agents/`（项目级优先级最高，字段 name/description/tools/model/permissionMode/skills/color）、Cursor `.cursor/agents/`（字段 name/description/model(fast|inherit)/readonly/is_background）、Qoder `.qoder/agents/`（name/description + 正文为系统提示；优先级 Built-in<User<Project<Plugin<--agents）。
- my-agents 现有 7 个 agent frontmatter 为 name/description/model: inherit/readonly，三平台均可识别；但缺 `tools` 白名单（Qoder 靠 tools 限权，readonly 未必生效）、CodeBuddy 的 `permissionMode`、以及 `skills:` 自动加载字段（目前只在正文写必读 skill）。
- 关键差异：插件专家团的 lead SOP 是"系统级注入主对话"；my-agents 的 studio-orchestrator 是"可被 spawn 的 subagent"。无插件环境下复现需把主理人纪律写进 AGENTS.md / alwaysApply 规则，否则主对话不会自动按九阶段 SOP 走。
- 待实测：四 IDE 对 `agents/` 内**符号链接**的识别率（Qoder 可 `qodercli agents list` 验证）；不识别则改为复制 + 同步脚本。
