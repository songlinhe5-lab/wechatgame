- **包体实测**：`--release` 主包 **2939.8 → 2979.0 KB**（+39.2 KB / +3 文件）；未越 4096 平台红线，仍越 2000 内部目标（**越线系既存**）。坑：默认构建是 **debug**（含 sourcemap），首次量出 6246 KB 不可作基线，必须 `-- --release`；且手工调 `build-cocos.mjs` 需 `--game=beads`，正确写法是 `pnpm --filter beads run build:cocos -- --release`。
- **推翻 ADR-0031 两条旧断言**（§4.2 条 4 已就地更正）：① CLI 真能构建 wechatgame（AppID 已在 `build/project.config.json`），与编辑器实例同开不冲突；② MCP `project_build_system` 确实**不能**触发构建（只有 get/open/check），但 `asset_system.refresh` 能完成导入——两条能力要分开说。
- **运行时取证（web-mobile 产物 + 浏览器）**：装载腿**全绿**（`masks=4/4`、bundle 腿命中、`ImageAsset 256²` 解出、`_bitmaps` 注册、选关墙帧内 1 条 `blit`、未就绨 warn 未出现）；**但屏上第 9 格空白**。A/B 互证定位：摘掉位图⇒程序化珠子缩略立刻可见；隐藏 `Graphics` 节点⇒曼陀罗显形。
- **根因 = 层序，不是资产也不是加载**：blit 恒挂 `BlitLayer`，而 `ADR-0030 S5′-3` 为「珠子不盖面板」定的序是 `Background → BlitLayer → Graphics → Labels`；选关墙卡片底与槽位矩形全由后置的 `Graphics` 画 ⇒ 本腿被盖。**「无 warn + 命令已发出」不能当「已上屏」证据**，位图腿验收须加视觉层序判据。
- 另一头缺口：`setLevelThumbBitmapResolver` 只有 Cocos host 调，**harness 未注入平行腿** ⇒ 日常验证环境里永远只能看到程序化缩略（§4.2 条 3 的双实现风险坐实）。
- 本轮 0 张 AI 图、0 元；证据截图在 `temp/evidence-0*.png`（不入库，待按用户裁留或重跑）。

## 层序修复：位图腿真上屏（同日第 9 批）

- 用户从三选项里点「修层序」→ 最小改：框架新增 `BlitLayerUI` 节点（插在 `Graphics` 后、`Labels` 前），`createBlitCarrier(layer, uiLayer)` 多一形参；beads 载体 `accept()` 按腿选父节点（tint→`BlitAtlas` 仍在珠层下，静态位图→UI 层）。池位共用，只在 `parent` 真变时 `setParent`⇒ 热路径仍零分配。
- **不再只靠「无 warn」**：装载成功补一行 `boss 位图 1/1 已装载 ⇒ 落 UI blit 层`。
- 改 `packages/framework/src/adapters/cocos/bindings.ts` 必须跑 `sync-framework-to-cocos.mjs`（否则 cocos 镜像的旧基类签名直接编译不过）；`framework:sync:check` 已 OK。
- 复测（重构建 web-mobile + 浏览器）：第 9 格由 `avg(247,246,251)/1 色桶` 变 **`avg(76,75,71)/79 色桶`**；同法测空白槽对照区仍精确复现旧失败签名⇒ 量法可信；A/B 可逆；珠层无回归（面板仍压珠，关 `Graphics` 则珠色回）。
- **保留意见两条**：① 取证时页面在后台（`visibilityState=hidden` ⇒ rAF 冻结、引擎不起），子代理靠手工泵帧 + 重跑 `cc.game.init/run` 才拿到数据，中途画布降半分辨率——**窗口置前复跑双证 + 真机扫码仍是待补项**；② 新层序必然推论：位图与面板同屏时会盖面板（当前不可达，已备案）。
