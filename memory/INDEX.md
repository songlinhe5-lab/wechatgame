# memory/ — 日志分级索引（WXG-T-068；二级详情层 WXG-T-106）

> `memory/` 是跨会话的**运行时记忆**，分四层：`MEMORY.md`（蒸馏后的常驻摘要）→
> `YYYY-MM-DD.md`（**当日骨架**：逐轮一节，摘要 + 指针）→
> `details/<日期>-<slug>.md`（**正文层**：长节逐字节外移）→ 本文件（索引入口）。
> 目标是「先读摘要，命中后再读那一节 / 那一个详情文件」，而不是整读日记（单篇 5.6k–12.6k tok ✗）。

## 1. 读取协议（分级加载）

**`MEMORY.md` 可常读**（1.3k tok，常驻层：约定 / 脚本 / 已知限制）。**过程账（日记 + 详情件）只在四种触发下查**
—— 它是「过程账」而非「结论库」，大部分会话**不需要**读它：

1. **改一个"已经定过的东西"之前**（冻结常量 / 协议 / 裁定 / 门禁阈值）⇒ 查它当初**为什么**这么定；
2. **接续未完成的工作**（跨会话接力、backlog 里带「上轮未闭环」的项）⇒ 查它**做到哪一步、卡在哪**；
3. **追溯用户的原话与裁定**（人的决定，知识库推导不出来）⇒ 这是本层**独有的**权威记录；
4. **排障时找「当初怎么确诊的」**（诊断法常比结论更值钱）。

**怎么查（别整读）**：先 `grep -n '<任务号或关键词>' memory/INDEX.md` 定位「哪一天 / 哪一节 / 行区间」，
再看表里「**详情**」列分流：

- 为 `—` ⇒ 正文仍在日记：`read_file('memory/YYYY-MM-DD.md', offset=行首, limit=行尾 − 行首 + 1)`；
- 非 `—` ⇒ 日记里只剩「摘要 + 指针」骨架，**正文按该列给的路径与行区间读**
  `memory/details/<日期>-<slug>.md`（已外移行的「摘要」列摘自详情件里的**原节首句**，不是骨架指针句）。

一次查询几百 tok，而非 3.2 万。

**例行用途（本层唯一的定时动作）**：日志满 30 天蒸馏时，**重读那一天的节**，决定哪几条进 `MEMORY.md`（见 §3）。

**与 `knowledge/` 的分工**：`knowledge/` 答「**该怎么做**」（可复用、跨任务的结论 ⇒ 任务开工前按域查）；
本目录答「**当初为什么这么做 / 做到哪一步 / 谁拍的板**」（时间序过程账 ⇒ 只在上面四种触发下查）。
判不准就问：**「下个月做别的功能，这条还用得上吗？」** 用得上 → `knowledge/`；只是这个仓的历史 → 本目录。

- **更细粒度**：`##` 以下的 `###` 子节在 `ctx/index.json` 里（同源数据，本表只列到 `##`）。

### 1.1 外移口径（本层机械规则，不靠人自觉）

- 触发（两个口径不得混）：**文件级**＝该日记越 B 门或余量不足才动手；**节级**＝只外移正文 **> 600 tok** 的 `##` 节（选择口径，不是独立触发器）。
  未越阈的历史日记（如 `09-11` 5617 / `09-13` 6645）**不预先切**。
  命令：`node tools/scripts/split-memory-detail.mjs --date=<YYYY-MM-DD>`（默认 dry-run、`--write` 才落盘；
  入口 `pnpm run memory:split`），写到该日记自然降回 8000 tok 以下为止。
- 去向：`memory/details/<YYYY-MM-DD>-<slug>.md`，**一节一文件**；正文**逐字节搬运**（不得改写 / 不得丢），
  日记原位只留「标题 + 指针」骨架且**保留原 `##` 标题行**（⇒ 锚点不失效）；原文由 git 保真。
- 反向声明（唯一真源）：详情文件 **H1 即隶属标记** `# 隶属 · <date> · §<日记节 anchor>`；本表「详情」列由它
  派生（同源），**不手维护第二份表**；缺标记 / 指不到现存节 ⇒ `ctx:check` C 项硬拦（不留静默）。
- 自带防再膨胀：详情文件天然进索引面 ⇒ 受同一道 B 门（8000 tok）约束，**不得为其新增豁免**。

## 2. 文件分工

| 文件 | 内容 | 读法 |
|---|---|---|
| `MEMORY.md` | 蒸馏后的**长期笔记**（约定 / 脚本 / 已知限制） | 常驻摘要层，直接读 |
| `YYYY-MM-DD.md` | 当日**骨架层**（逐轮一节：摘要 + 指针；长节已外移） | **按本表行区间读节**，勿整读 |
| `details/<日期>-<slug>.md` | **正文层**：自日记某节逐字节外移的长正文 | 只读命中的那一个（受同一道 B 门约束） |
| `INDEX.md` | 本文件：摘要层入口（生成块由 `ctx:build` 维护） | 先读这里 |
| `archive/` | 满 30 天蒸馏后的归档（`memory:distill --write`） | 不进索引面；`git` 永久可查 |

## 3. 生命周期（与 `docs/agent/memory-distill.md` 同一套）

- 日志满 **30 天** ⇒ `pnpm run memory:distill`（dry-run）⇒ **先把长期有效内容蒸馏进 `MEMORY.md`**
  ⇒ `pnpm run memory:distill --write` 归档。**蒸馏责任在人 / 会话**，脚本只做机械轮转。
- **连座归档（WXG-T-106）**：归档某天 ⇒ 该天的 `details/<日期>-*` 一同进 `memory/archive/details/`
  （否则留孤儿与本表悬空指针）；组内任一目标重名则**整组跳过**，日记与详情件必同进同退。
  逐字节搬运 ⇒ 隶属标记**故意不带目录前缀**，归档后仍成立。
- 生成表里每篇标注「蒸馏到期」＝ 文件名日期 + 30 天：**到期不得靠 B 门豁免硬扛**（T-041 裁决）。
- 全文归档后其摘要行会随索引自动消失（`memory/archive/` 命中 `SKIP_DIRS`）。
