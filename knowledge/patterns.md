# patterns.md — 模式库（本仓已验证可复用的做法，追加式）

## 数值与真源

- **[K-012] 冻结常量 SSOT 模式**（breakout/beads 双实例验证）
  `systems-index.md §3` 表格 = 唯一真源；代码 `src/config/tuning.ts` 只做镜像 + `as const`；
  其他文档一律引用**常量名**不抄值；改值走 §6 变更记录 + 全仓 grep 旧值残留。
  变体：`IMPLEMENTED_POWERUPS` 派生语义——数据里可存在未实装 ID，运行时 `pool ∩ IMPLEMENTED` 交集 + 权重重归一，裁剪不改数据。

- **[K-013] 关卡覆盖全局基线**：§3 常量是底线，per-level JSON 字段覆写调优；
  `validate-levels.mjs` 在 CI 里守卫（单调性/上限/字符集/行宽）。

## 代码结构

- **[K-014] 决策表模式**（breakout `src/systems/motion.ts` 实例）
  多开关 × 多效果的组合行为收敛成纯函数 `resolveMotionEffects()`（输入开关，输出逐项 bool），
  表驱动测试逐项断言，视图层只读结果不做条件散落。适用于 a11y/画质/难度分级类正交开关。

- **[K-015] 事件总线 payload 约定**：`<域>:<事件>` 命名、payload 一律带 `levelId`（beads 约定）、
  事件表即 `systems-index §4`（实现与文档一一对应，新增事件走 §6 变更）。

- **[K-016] 同帧冲突固定结算序**（breakout powerups 实例）：多来源同帧到达时按 `life→multi→expand`
  固定顺序结算——「写死并测试」（GDD 判据 + 实现常量 `PICKUP_SETTLE_ORDER` 同名对齐，
  测试 import 实现常量断言，勿在测试里自比较字面量）。

## 上下文与工程基建

- **[K-017] 章节级上下文索引（`ctx/` 体系，WXG-T-024）**
  生成器扫描全部 `.md` → 每节存「**标题路径为主键**（`§3.7 星级与结算`）+ 行号区间为辅 + 首句摘要 + token 估算 + 关键词」；
  生成物**不含时间戳、键序固定**才字节稳定，可入库做新鲜度守卫；读取协议 = 先查 `ctx/ROUTES.md` 路由表 → `read_file(offset, limit)` 只取命中节。
  实测收益：读单节比全文省 87%–98%；守卫 `ctx:check` 四重（常驻预算/单文件上限/索引新鲜度/ROUTES 锚点）。

- **[K-018] 导航表锚点必须被守卫校验**：`路径#锚点` 形式的引用会随标题改名**静默漂移**——
  把「锚点可命中」并入守卫脚本，以索引文件为唯一真源（与生成器共享模块，禁 shell 外调）；
  整文件引用用行级豁免语法（如 `<!-- no-anchor -->`）显式声明，不靠约定俗成。

- **[K-019] 新增 CI job 一律并入 `gate` 收口**：job 用 paths-filter 增量触发，`gate` 以 `needs` + 逐 job `success|skipped` 判定；
  分支保护**只挂 `gate` 一个 required check**——新增/调整 job 不必反复改保护名单。

- **[K-020] 指标分层治理：结构门硬、行为门软**（WXG-T-026 裁定）
  **结构类**指标（常驻预算 / 单文件上限 / 索引新鲜度 / 锚点可命中 / **基线回归**）→ 硬门（`FAIL` 阻断 CI）；
  **行为类**指标（节省率、抖动率、整文件读率）→ **报告项**（如实展示 ❌ 与数字 + `WARN`，`exit 0` 不阻断），
  理由：行为指标取决于历史会话分布，不该成为无关 PR 的合并门。
  配套纪律：报告标题与汇总行**必须同时**出现 `WARN` 与「未达标」，并保留 ❌ 与原始数字；
  桩自测加断言「未达标时 exit 0 且含 WARN / 劣化时 exit 1」，防止「报告项」被悄悄改成 PASS 或抹掉数字。

- **[K-021] 「纯查表门禁」模式**：重计算放在分析器、产出**稳定 JSON**（无时间戳、键序固定），门禁只做查表 + 阈值判定
  → CI 零安装、毫秒级、可复现；扩展一律**追加字段**，不动既有键，兼容旧版读取。

## 流程

- **[K-022] 八要素 spawn 模板**：角色声明 / Task ID / 项目上下文 / 环境事实（做不了的要明说）/ 权威来源清单
  （含 knowledge 相关条目路径）/ Deliverables 逐文件 / 精确 Output Path / 必读 skill 仓库路径。
  成员间不直连，产出经主理人中转。

- **[K-023] 双层验证**：实现者自验（跑全套测试）→ 独立成员复验（fresh eyes 读断言真实性 + 对照 §3 常量）。
  复验发现记缺陷台账（D-xxx 阻塞 / F-xx Minor），Minor 可随下次提交带上、不重开门。

- **[K-024] 裁决留痕**：用户/主理人的每次拍板落 §6 变更记录（豁免理由逐条照录 + 生效依据），
  commit message 与 §6 条目互相可追溯。

- **[K-027] 旁挂式生命周期层升级存量 md 沉淀层**（WXG-T-029）：
  给已有 markdown 沉淀层加「行内 ID `[K-xxx]` + 侧车 `ledger.json`（访问时间戳/次数/seen）+ `archive/` 归档区」——
  **不改正文顺序、不改读取协议**，只加标记块（`<!-- kb:active:start/end -->`，脚本只重写块内）与 `SKIP_DIRS` 排除；
  归档搬移用**双向可逆标记**（标题行下插 `> 归档于 …`，解析器把该行纳入条目、reactivate 时剥离还原）保证原文完整可逆。

- **[K-028] 访问计数「自动 + 显式」双通道**（WXG-T-029）：自动通道解析读入账本覆盖写转录的 IDE（零纪律成本），
  `kb:touch` 兜底其余 IDE / 手工补录；文档显式声明**「未观测 ≠ 未访问」**，故归档只出候选、**必须人工确认**——
  避免把采样盲区当业务结论。计数幂等靠持久化 `(主体, 条目)` 去重集，且**去重键不含观测日**（含日则退化为每日一次，仍膨胀）。

## 关卡与生成链

- **[K-068] 关卡生成链四段连锁模式**（WXG-T-203）：`manifest.json` → `sync-levels-data` 生成 `levels-data.ts`（**数据体内嵌 manifest 的 description，非仅头部注释**）→ `sync-framework-to-cocos` 同步镜像 → 测试快照（`bodyOf` 从生成物提取）。改 manifest（含 description 这类「看似纯文案」字段）后必须按链序走完四步：① sync-levels-data ② sync-framework-to-cocos ③ 从**最终生成物**重提取快照 ④ verify 一次看剩余缺口；跳过任一下游重生成就各出一处 FAIL，快照提前于生成物提取 = 给旧世界拍照。测试判据引 `DEMO_LEVEL_COUNT` 常量勿写死关数（v1.35 先例）。

- **[K-069] 部分错位「整区域就位 + 子集置换」构造模式**（WXG-T-203 E1 取证）：错位在子集 S 上循环移位构造（S 外恒等 ⇒ S 上仍是多重集置换），**绝不逐格改回 solved**（破坏守恒 ⇒ 盘填不满 NC 假象）；子集按块粒度（如 8×8）整块选取保连通——随机散点逐格挑错位格会打碎 8 向连通大组，实测反直觉地比全错位更难（mis60 taps > mis100），而真实关卡错位是成区域的，散点测的是不存在的难度形态。void 轮廓按块内可填格整体归属；判据线 = time ÷ SEC_PER_TAP（420s→116 taps），与 bot 贪心策略绑定。配套判据 K-028（结构正确 ≠ 可解，须 bot 实测 cleared）。
