# knowledge/ — 工作室知识库（WXG-T-023）

> 本目录是跨任务、跨会话、跨 IDE 的**长期知识沉淀层**：教训、模式、平台坑。
> 与其他载体的分工：GDD/design = 产品设计；ADR = 架构决策（为什么）；`production/qa/` = 判据与缺陷；
> 本目录 = **怎么避开已踩过的坑、怎么复用已验证的做法**。

## 1. 读取协议（开发前期）

- **任务开工前**：成员与主对话先读本 INDEX 与 `lessons.md` 中与本次任务**同域**的条目
  （spawn 八要素的「权威来源清单」应包含相关知识条目路径）。
- 触发词：看到「实现/修复/接入/发布」类任务时，先查 `lessons.md` 有无同域条目，有则列入任务单必读。

## 2. 写入协议（任务收尾）

- **每个 WXG 任务收尾时**，执行者随交付回传 0–3 条沉淀候选（没有可传「无」）；主理人汇编去重后入账。
- 触发判定：踩坑修复、非显而易见的做法、平台/工具反直觉行为、复用价值 > 一次性的经验。
- 条目格式（必须带任务号可追溯）：

```markdown
- **[类别] 一句话标题**（来源 WXG-T-xxx / commit abc1234，2026-09-12）
  现象：…
  根因：…
  规避/做法：…
```

- 类别：`构建` / `工具链` / `跨IDE` / `平台微信` / `引擎Cocos` / `测试` / `流程` / `环境`。

## 3. 文件分工

| 文件 | 内容 |
|---|---|
| `lessons.md` | 教训库：踩过的坑与规避（按类别排序，最新在后） |
| `patterns.md` | 模式库：本仓已验证可复用的实现/流程模式 |

## 4. 维护

- 主理人负责汇编与去重；条目不删改只追加，废弃条目标 `[已过时：原因]`。
- 新条目提交进 commit（带 Task ID，过 commit-msg 钩子）。
