## 测试守卫

- **[测试守卫][K-038] 自动化统一走「便捷旁路 API」，真输入链可以整段断链而全绿**（来源 WXG-T-096 附带发现 BD-34，2026-09-15）
  现象：beads 所有面板用例与 QA 探针 P22 都用 `game.tapDesign()` 驱动 ⇒ 225 例连绿；但 `_readInput()` 的唯一调用点在 `_stepPlaying` 内，`App.tick` 又是 `beginFrame → game.update → endFrame`（一次性标志每帧被清），于是 PAUSED / LEVEL_CLEAR / GAME_OVER / FINISH 四相位在**真链**（harness 鼠标、Cocos touch → `InputManager.push`）上收不到任何点击——面板按钮全绿地不存在。
  根因：测试入口与被测系统的入口不是同一条；旁路 API 为了便利绕过了状态机里唯一读输入的那一步，而没有任何断言约束「旁路与真链必须等效」。
  代价：这是用户最初「完全没法玩」里最后一块 P0/P1，靠 Node 侧回归三轮都没测到；若进真机才被发现，成本是整轮返工。
  规避：① 关键交互必须各有一条**经 `InputManager` 真链**的用例（旁路只用于装配前置），二者断言同一结果；② 给「相位 × 输入」建矩阵守卫（`input-control §2.3` 已有表，可机检：非 playing 相位也必须能命中面板按钮）；③ 评审时追问「这条绿走的是哪条入口」，凡便捷 API 都要问它是否等价于宿主接线。
  判例引用：`production/qa/beads/g4-regression-report.md` §15.2 BD-34、evidence/diag-p5-fixtures.mjs（同坐标同帧序：真链无派发 / 旁路生效）；同族 K-035、K-037。

- **[测试守卫][K-042] 几何单一真源化后测试失去自证能力，须另配不依赖该真源的不变量守卫**（来源 WXG-T-097/BD-15，2026-09-15）
  现象：把渲染与命中都改接同一份 `trayLayout()` 后做变异检验：把锚定改回旧行为（带内居中），整套测试仍然**全绿**；同时另一条自己重推「带中线」公式的测试在带加高后整组脱靶，变成永真断言（点了个空处，当然零响应）。
  根因：单一真源只保证**一处改、处处一致**，不保证那一处**对**；而任何在测试/探针里重推公式的地方都是静默漂移温床，一旦与真源分叉，断言对象从「不该有反应」退化为「什么都没点」。
  代价：错锚定可以无阻力入仓；真正靠它才成立的结论（可访问性热区、重叠仲裁）看起来已验收，实则从未被测定。
  规避：① 测试与探针内**禁止重推几何公式**，一律 import 真源；② 必须另写一条**不变量断言**（净空 / 不重叠 / 上下界关系），其预期值来自**规格字面值或另一条独立推导**而不共用于被测真源，让错锚定必红；③ 每条「零响应 / 零事件」类断言都要配一条**正向对照**（同坐标在应响应的相位下确实产生事件），否则永真无从发现；④ 真阳性判据选**事件**而不选函数返回值——返回值常只表「吞掉」分支，与「状态是否改变」不等价。
  判例引用：`games/beads/tests/feedback-vfx.test.ts` BD-15 几何净空条（M3 变异在此转红：`expected 309 to be greater than 318`）、`games/beads/tests/pause-settings.test.ts` 正向对照；同族 K-035（假绿谱系）。
  追记（2026-09-19，WXG-T-169 收口批·§A4c.2 落点补齐时重现）：规避③「零响应类断言必须配正向对照」**不只在旧测试里失效，新写的用例同样会当场中招**。本批新写「drag 途中跨格 ⇒ 零落子零选中」例，第一版把**抬起点选在拖拽终点**（该格与已备珠颜色不同 ⇒ 落子本就不合法）⇒ 对「阈值被改到 `drag` 永不成立」的变异**不红**：绿得完全没有信息量。把抬起点改回**已备珠的那个格心**（同点在单指 tap 下确实会落子 = 正向对照同位）后，同一变异立即转红，例子才真正锁住 drag 判定。**做法补一条**：写完零事件例子先不要登记「已验」，而是问「**同坐标同帧形下，它该红的那次会红吗**」——若答不出，就是把断言域选在了非法/无效位置上；先找共位正向对照，再跑变异。

- **[测试守卫][K-060] 变异自检里断言「方向」选错会留下伪绿：被测标量在变异下「冻结在旧非零值」而非归零时，存在性断言无判别力**（来源 WXG-T-128 / commit 61d2911，2026-09-19）
  现象：为「扫光不因状态切换中断」写判据，首版断言「过关帧 `sweepProgress > 0`」。按 K-036 做变异自检——给 `_stepSweepFx` 加 `playing` 门（**正是该断言要否定的那个实现**）——**判据仍然全绿**：变异下扫光并未归零，而是**冻结在 0.79**（离开 `playing` 后步进被 `return` 掉，旧值原样留着）⇒ `> 0` 恒真。改成「过关后**仍在推进**（`sweepProgress > pAtClear`）+ 越过窗口后归零」两条后，同一变异立即红于 `expected 0.79 to be greater than 0.79`。
  根因：变异自检只回答「**断言红了没有**」，不回答「**断言凭什么红**」。当被测量是**单调推进的时间/进度标量**时，`> 0` / `!= null` / `is defined` 这类**存在性断言**与「暂停 / 冻结 / 短路」型缺陷正交 —— 缺陷让标量**停在中间值**，存在性依然成立。判别力只能落在**差值或终态**上，不能落在「有没有值」。
  规避/做法：① 时间/进度类标量一律断言**单调增量**（下一帧 > 本帧）或**终态**（窗口过后归零 / 复位），存在性断言只作前置；② 选「**必然让被测行为偏离**」的注入点，并在跑之前先预测「这条断言会怎么红」——预测不出红法即说明断言形态选错；③ 变异后**看红在哪一条**：若红在无关的收尾断言、核心断言仍绿，等于没测（本例首版即「红的在④归零、②仍绿」）；④ 把「断言形态 + 变异实况」写进用例注释，防后人把弱断言当主体系。
  判例引用：`games/beads/tests/scene-vfx.test.ts`「裁定『恒播满』…」例（注释含两次失败记录）；同族 K-042 追记（断言域选错 ⇒ 变异不红）、K-036（变异自检方法论）、K-037（可证层级）。

- **[测试守卫][K-089] 守卫脚本硬编码的目标值与冻结真源脱钩 ⇒ 断言永不触发（假绿守卫）；投放重物前要先实测「守卫能不能红」**（来源 WXG-T-219 取证，2026-09-27）
  现象：准备向微信小游戏主包投放位图资产前核对包体守卫，发现 `tools/scripts/check-bundle-size.mjs` 仍写
  `mainTargetKb: 2000`、A7 断言同样钉 2000，而真源 `systems-index §3.9` v1.51 已把内部目标与平台红线 4096 KB **合流**
  （缓冲消失）⇒ 实测主包 ~1928 KB 时告警与断言都恒绿，**这条守卫事实上没有牙齿**；同批还发现 `check:size`
  在 `pnpm run verify` 里为 SKIP（构建链未打通）⇒ 主包真实余量今天测不出。两处若不当场戳穿，结论就会是「守卫通过」。
  根因：守卫里的阈值是**当年抄进脚本的常数**，冻结真源换版时无人回写；脚本层没有任何断言去比对「阈值 ↔ §3 现值」，
  所以脱钩只能靠人记得 —— 而「记得」正是不可复用的机制（同 K-042 的「同源一起错」家族）。
  规避：① 依赖某守卫做「可以加重物」的决策前，先做一次**破坏性自证**：临时把阈值调到当前实测值以下，看它是否真的 FAIL；
  不 FAIL 的守卫等于不存在，须在台账里改标「未覆盖」而不是「PASS」；② 守卫阈值只准从冻结真源读取（或加一条
  「脚本常数 ≠ §3 现值 ⇒ 红」的一致性断言），⛔ 手抄第二份常数；③ 把「先修守卫再投放」写成裁定项的**前置义务**
  （本例 = ADR-0027 S0），并在复评触发里明写「守卫仍 SKIP / 仍钉旧值 ⇒ 禁止投放」。
  判例引用：`tools/scripts/check-bundle-size.mjs`、`games/beads/design/gdd/systems-index.md §3.9`、
  `docs/architecture/adr/ADR-0027-beads-prebaked-bitmap-skin-assets.md` §1 与 §5-2；同族 K-037（全绿不等于宿主可证）、K-042（判据与被测面同源须另配守卫）。
  **追记（WXG-T-292，2026-10-18 · 总包红线 30720→20480 同批）**：规避 ② 的一致性断言落地时又踩到**它自己的盲区**——
  一致性断言钉字面（`totalRedlineKb === 20480`）是必要的（它就是「门 ↔ 文档」的牙），但同一自测里**构造越界样本**的那条
  也钉了字面 `30721 KB`：改值到 20480 后该条**仍绿**（30721 当然越 20480）⇒ 对新阈值零敏感性，即使忘改 LIMITS 也测不出。
  修法：① 样本数一律由被测常量派生（`L.totalRedlineKb + 1` 必红 ∧ `= L.totalRedlineKb` 必不红，同一条 assert 锁两个方向）；
  ② 字面钉值只留在「一致性断言」这一处，⛔ 不在构造数据里重复；③ 改完阈值跑一次**反事实**（把 LIMITS 改回旧值 ⇒ 自测必红，
  仍全绿即说明该断言没牙）。

- **[测试守卫][K-125] 语义从「取大」换到「优先」时，`≥` 型不变式没有判别力，必须补一条相等式**（来源 安全区接口优先批 / WXG-T-265 · commit 5703654，2026-10-13）
  现象：改写 `safeEdgeInset` 后既有测试「结果 ≥ 胶囊底换算值 + 余量」全绿——但**旧 `max` 写法同样满足它**；只留这条，旧语义回潮不会有任何一条红。
  根因：不变式只刻画「不低于」方向，而本批改的恰恰是「常量不得参与」这一侧；换算单一真源化之后，测试若再从同一份常量取期望值就等于用被测逻辑测被测逻辑（同 K-042）。
  规避/做法：① 换语义批必须新增**成对断言**——正向严格相等 `toBe(112 + MARGIN)` ∧ 反向排除 `not.toBe(SAFE_TOP_H + MARGIN)`，把「宏不得参与」钉成可失败判据；② 逐机档用**字面量**钉死（116/137/164/176/161、72/63/104），不许复写成被测同款公式；③ 单位换算方向另配单调性断言（同 dp 下屏越窄 ⇒ 设计 px 越大），防分子分母写反后数值仍「看着合理」。
  判例引用：K-042（真源化后判据失去自证，须另配不依赖该真源的守卫）、K-060（变异自检断言方向选错留伪绿）、K-089（守卫硬编码与真源脱钩 ⇒ 断言永不触发）。
- **[测试守卫][K-129] 往皮肤调色板加一枚字段在本仓是「三处联动」的改动，逐道修会逐道漏；台账那一道的修法只有一条**（来源 L4 门楣牌第十一批 / 无单，2026-10-13）
  现象：`BeadsPalette` 新增 3 枚令牌后，先只跑相关两套测试 ⇒ 红的是 K-6 图元族台账两条（菜单帧 total/sha 漂）；重跑捕获脚本顶版后再跑**全量**又冒出两道独立红：`skin-system.test.ts` 两肤字段键集恒等（`expected 29 to be 32`）与 `bead-render.test.ts` ④ 色表锁（条数 + sha1 前 12）。三道锁彼此不知道对方存在，所以「修到绿」得跳三次。
  根因：同一份调色板被三个不同侧面消费（绘制命令图元计数 / 两份肤的键集一致性 / 色表指纹），而没有任何一处能预告「你还要改另两个」；最危险的是台账那道的**诱因形状**长得像「改个期望值就绿」，手改 fixture JSON = 伪造证据（与 K-111 同一脉）。
  规避：① 开工前先列三处清单并**同批改完再跑全量**（逐道修逐道跑会把一次改动敲成三轮）；② 图元台账只允许走**捕获脚本**重取，然后逐键对预期（本例 playing 四键必须仍 MATCH，否则是渗漏不是漂移）；③ 新增字段必须**同批**给每份肤一个值，别名只能指向在册值（⛔ 为编译过而临时编一个新色相）；④ 色表锁的顶版数值用与测试同款的去注释实算给出，但要同时明白**它只防漂移不防错色**，数值对不对得靠另一条不依赖该表的判据（本例 = 对比度实算腿）。该锁的期望值是手钉字面量，⇒ 属 K-089 描述的「与真源脱钩」形状，顶版时把来源（哪个批次、哪三枚）写进注释行，否则下一个人无从判断这是真改动还是误改。
  判例引用：K-111（「顺手重建产物」覆盖基线）、K-089（守卫硬编码与真源脱钩）、K-042（判据与被测面同源）。
- **[测试守卫][K-143] 同一个「引用集」被生成器与门禁各写一份解析正则 ⇒ 一侧的「无条件保留」例外永不触发，规则形同虚设**（来源 WXG-T-293 / ctx 第二跳 D3，2026-10-18）
  现象：`ctx/hot-files.md` 的规则 R 写着「L3 若被 ROUTES 以 `路径#锚点` 引用则无条件保留」。实测该条件**只命中 8/85**：生成器用 `[^\s`)|，,。]+`（遇空格即断），而 ROUTES 的锚点绝大多数含空格（`§3.7 星级与结算`、`§A1 · 核心循环（S1）— 来源 …`）；门禁 D 项用的是另一套 `[^|\n]*` + `trim()`，所以 `ctx:check` 一直绿、没人发现例外分支已死。
  根因：一条规则的**判据输入**由两份代码各自解析同一份文本，二者不同源；被削掉的节不会让任何门变红（D2 只做文件级覆盖），于是「有规则、无门」= 永久静默失效（K-036 的「跑过 ≠ 检了」在这里的变体：写了 ≠ 生效）。
  规避：① 引用/解析口径**必须单一来源**——本批把正则与归一化提到 `lib/context-index.mjs::ROUTES_ANCHOR_REF` + `normalizeRouteAnchor()`，生成器与 D 项共同 import，⛔ 两侧各自维护副本；② 修完口径要**当场看见它变红**（本批 D3 落地时先报 6 条，再顺藤摸出解析器第二个坑：锚点名内含分隔符 ` · `，用 `split(' · ')` 会把一条锚点劈碎，导致除第一条外全部假不命中）；③ 任何「例外/保留/豁免」类规则都要配**反事实自测**：造一个「例外该救它」的合成样本，断言例外失效时门必红，且例外生效时不误报（本例 = `ctx:hotfiles:selftest` 的 U1/U2/U3 六正六反，已挂 fast 档）；④ 装置自测与被测装置**同源 import**，不复制逻辑，否则测的是副本。
  判例引用：`tools/scripts/lib/context-index.mjs`、`tools/scripts/check-context-budget.mjs`、`tools/scripts/context-hotfiles-selftest.mjs`；同族 K-089（守卫硬编码与真源脱钩，须先证能红）、K-036（全绿≠检了）、K-142（自陈与实测口径不同源 ⇒ 结论失真）。
- **[测试守卫][K-144] 同一个「零响应」结论由两条不同机制各自达成时，只写一例 ⇒ 变异只能拆掉一条，另一条恒绿**（来源 WXG-T-295，2026-10-19）

- **[测试守卫][K-157] 夹具手工拼出的「最小形状」若与生产装配形状不同，对数据形状敏感的边界分支就永远走不到，变异也不会红**（来源 WXG-T-345，2026-10-22）
  现象：存档「身份指不回时落到哪一根指针」的降级锚用例，首版夹具手搓「只含被点名关卡」的稀疏星账；而生产读档会把星账补成「每关都有键（缺者记 0）」的稠密形态。于是一个「取装配序最靠后那一关」的错误实现（设计正文明令禁止的「落表末位」）在稀疏夹具下每次都仍指向同一关，五条用例全绿；改用生产装配函数喂「全 3★ 稠密账」后，同一实现立刻变红。
