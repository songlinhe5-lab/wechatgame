## 判据实测取证

- **[判据实测取证][K-193] 截图工具回显「Saved」不等于我读过它；凭上一轮印象描述本轮画面 = 臆述**（来源 MVP 复验批 / 用户 2026-10-27 追问，2026-10-27）
  现象：同一轮里连出两次臆述。① 把失败面板说成「看视频续时 01:36 / 金币续时 / 重开本关 / 回主菜单」四项，实际把 PNG 读进上下文后只有「▶ +180秒 继续本关 / 重试本关」两项（与 `systems/fail-panel.ts` 的 `FailPanelAction = 'revive' | 'retry'` 逐字一致），据此得出的「第二腿文案缺失」缺陷整条作废；② 把暂停面板行5 说成「与源码反序」，实测行5 画面顺序 = 源码 `row5Ids` 顺序，真正错位的只有行4。两次都是**上一轮的读数形状被当成本轮的观测**写进结论。
  根因：`take_screenshot` 的成功回显只证明「文件落盘」，不携带任何像素信息；而旧会话摘要里存着同名面板的历史描述，脑内补全比重新读图便宜得多 ⇒ 描述会悄悄从「本轮观测」退化成「历史复述」。这与 K-036「跑过 ≠ 检到」同族，是它的取证侧变体：**存了 ≠ 看了**。
  规避/做法：① 任何「画面显示 X」的断言，其依据必须是本轮把该图（或 PIL 裁放后的子图）真正读进上下文的结果；只存证未读的图在报告里一律写「已存证待读」，⛔ 给描述。② 每条视觉结论后面挂**图名**，让「哪张图支撑这句话」可机械回查。③ 小图（≤300px）肉眼判版面必错 ⇒ 先 PIL 按已标定的设计↔像素映射反算裁剪框再放大 4–6x 读（本批用同一映射量出道具卡角标实为「金币价 100 + 拥有数 ×0」，把上一轮「角标语义存疑」整条撤掉）。④ 复述旧结论时显式标「待复验」，不要混进本轮读数。
  关联：K-036（跑过 ≠ 检到）、K-152（本版快照当不变式）、K-165（改判前先取证是否落码）。

- **[判据实测取证][K-194] 换宿主复验前先确认读回口装在哪；探针缺失时改用「逐格行为判别」而不是猜**（来源 MVP 复验批，2026-10-27）
  现象：想在 `dev/harness`（直接编译 `games/beads/src`，秒级重建、最贴近 HEAD）上复验 Cocos 产物里的三个疑点，随即发现 `__WXG_GAME_DEBUG / __WXG_HIT_DEBUG / __WXG_CELL_DEBUG / __WXG_GESTURE_DEBUG` 这组读回口**只由引擎侧启动器** `games/beads/cocos/assets/scripts/BeadsBootstrap.ts` 安装（且全部受 `globalThis.__WXG_TOUCH_DEBUG` 门控），harness 宿主不装 ⇒ 换宿主等于换量具，`tapActive`、格心、命中 round-trip 一类判据当场全丢，F2（带外行不可点）根本无法在同一口径下比对。
  根因：探针是「宿主适配层」的产物而不是游戏 src 的能力；同一份 src 在不同宿主下的可观测面不等价，而这层差异在代码里没有任何声明，只有实际换宿主时才暴露。
  规避/做法：① 复验开工前先列「本轮依赖哪些读数 → 哪个宿主提供 → 该宿主产物是否等于被测源码」，据此决定是重建产物还是换宿主；本批结论 = 重建 `build:cocos:web`（实测 ~27s）比换宿主更便宜且保住同一量具。② 探针拿不到的映射关系，用**可证伪的行为判别**替代：画面文案与热区的对应，逐格点一次、每次只 diff 一帧该行（本批据此把暂停面板行4 判成「整行循环错位一格」——⚠ **该判定已于同晚被引擎侧逐格对拍否证并撤回**，因为「逐格点」的格心仍是自己算的，见 K-195）。③ 合成点击要带按下时长（mousedown→~120ms→mouseup）；事件驱动宿主上零时长 down+up 可能整帧丢失，会被误读成「热区不存在」。④ 关卡计时在真实流逝：读源码/查文档期间页面仍在走时，长链条实验要么压进同一次调用，要么先续时再开工。
  关联：K-156（度量前先断言产物版本）、K-161（判方向前先列消费点）、K-037（取证层次与门禁可信度）。

- **[判据实测取证][K-195] 「UI 点了一下没反应」不能当规则判据；出口存在性要走引擎公开命令，道具类还须确认二次提交**（来源 MVP 复验批 / WXG-T-434，2026-10-27）
  现象：上一轮在浏览器里对 L00001 做「取回最大同色错位组 → 托盘 12 槽满 → 放回 / 满槽再取 / 扫豆刷三条出口逐个点、`filled` 全部 Δ=0」，据此判成 P0 死局。本轮在 Node 侧用**同一动作序**（生产 BOOT + `BeadsGame` 公开命令）复现，读数直接翻转：取回 `filled 102→90` ⇒ 盘面**多出 12 个空格**（不是我推的「仍 0 空格」）；族 C 直填 `(0,8)→(0,2)` 成功；`usePowerup('trayRestore')` 返回 accepted 且 `filled 90→102`（12 颗全部归位）；`expandTray()` 把容量 12→24 后有 2 条出口 ⇒ 死局不成立，降级为「出路要靠直填/扩容，玩家不易发现」的 UX 问题。
  根因：① 道具卡是**两段提交**——未拥有时点卡只开购买确认，须 `confirmPowerupBuy()` 才结算；我把「点了卡」当成「已施法」，于是 Δ=0 的含义从「执行了没效果」被误读成「规则封死」，而角标正写着金币价 100 / 拥有数 ×0。② 顺手用 `空格数 = 总格 − filled` 自推盘面状态并据此下结论，属 K-042 同族：探针能读的东西不该靠算。
  规避/做法：① 判「还有没有路」用现成量具 `games/beads/design/forensics/g3/g3-lib.ts::probeTrayPlace / probeRetrieve / probeDirectFill`（三族出口各一条，逐次真调公开命令、由引擎裁合法性），Node 侧单盘亚秒级；浏览器点击只用于验「点得到 / 文案对 / 热区在」。② 道具类判据必须同时拿到「命令返回 accepted」与「状态确实变化」两份证据；测试里先 `setPowerupFreeDepleted({})` 或直接给已拥有态，跳过付费门。③ 推翻自己上一轮的判定时，报告里写明**撤回原因是量具**（哪一步没提交 / 哪个公式是自推的），只写结论翻转等于没交代。
  关联：K-036（跑过 ≠ 检到）、K-042（探针不得自推公式）、K-156、K-193（存了 ≠ 看了）。
  ⚠ 同因第二例（同晚）：同一批报的「暂停面板行4 画面文案与热区整行循环错位一格」也被引擎侧否证——用 vitest 取暂停帧 RenderModel（`renderPlayFrame` → 文本指令落点 vs `pausePanelLayout()` 格矩形）逐格对拍，13 格文案与该格 `hitTest` 解出的动作全对，而渲染链本就是 id 单源（逐钮 `settingsContentLabel(button.id)`）。浏览器那轮的错因是**两套自算坐标**：点击格心按自己假设的内缩/列宽推，裁窗读文案又按另一套偏移算，两者各自错一格就读出「错位一格」。守卫用例已落 `games/beads/tests/pause-settings.test.ts`（逐格文案↔动作 + 钮序覆盖面断言）⇒ 以后此类疑点先跑格对拍再开单。

- **[判据实测取证][K-196] 想加「可解性/容量」类门禁前，先查 `levels:check` 已有的硬拦闸与已被撤回的错论，否则会造出把合法内容判红的弱门**（来源 MVP 复验批 / WXG-T-434，2026-10-27）
  现象：因 L00001 实测出「24 颗同色错位组 vs 基础托盘 12 槽」，拟给关卡装配加一条静态门 `最大同色错位连通组 ≤ 基础容量 − 1`。一查即废：`tools/scripts/sync-levels-data.mjs` 的 dev 侧溯源断言已经在拦 `pricing.cleared=false`（「可解性未证实，不可入关」）、拦 `stepsLB > steps`、拦 `time` 与 `ceil(steps × secPerStep ÷ tierK)` 不符（改了图案没重跑 bot 就红），`levels-spec §5.0.0` 是「生成期拒产 + 入关期拒收」双闸；而 `beads-bot.ts` 头注已用取证说明**静态结构量预测不了可玩性**（全错位初盘空格数为 0、连通域随玩法演化），`§3.13` 那条「容量构成步数下界 ⌈M/k⌉」更是 **WXG-T-391 明文撤回的错论**（实测单步可搬 93 颗）。我这条静态门既冗余（弱于既有 bot 实测门）又反向（会判红 9/10 张合法关，而 10 关重跑实测全部 `cleared=true`、steps/taps/time 与登记逐字段一致）。
  根因：门禁类需求天然像「补一条断言」的小活，动手冲动先于检索；而本仓的门是分散的（生成期 derange / 装配期 sync-levels-data / 运行期 BOOT / 求解器 beads-solve 各一层），不在一处列全，容易重复造。
  规避/做法：① 提「加门」前先跑三条检索：`grep` 目标脚本既有 `throw/problems` 清单、`grep` 该不变式在 `levels-spec` / `control-manifest` 的条文、`knowledge` 里查同键是否被撤回过（`git log -G` 搜旧值而非键名，判例 K-168）。② 门的强度要与**真源判据同源**：内容可解性已由 bot 逐关实测保证，再加静态代理只会给出更弱且会误杀的口径；真要补的是残差维度（本例真残差 = 「bot 有一条解路径 ≠ 玩家任意合法走法都可活」，即 no-move 可达性未被任何门覆盖，该疑点已证为假警报，且缺口已于同晚补齐：`games/beads/tests/worst-first-move.test.ts` 逐关断言「取回最大同色错位组之后，仍存在使已就位珠数 `filled − misplaced` 上升的合法命令」，10 关全绿、62ms）。③ 重跑实测做**逐字段对账**（fresh vs 登记），别只看 exit code。
  关联：K-174（同一映射两处登记必漂移）、K-156、K-037、K-168（`git log -S` 搜键名得假阴性）。
- **[判据实测取证][K-197] 宿主替身全绿 ≠ 真宿主能落盘：框架与 DOM 同名类型互相遮蔽，再加吞异常，一条存档链可以在浏览器里静默哑掉而 1928 例照绿**（来源 MVP 复验批 F4 / WXG-T-434，2026-10-27）
  现象：浏览器实测「拨设置开关后 `localStorage.setItem` 计数 0 次、localStorage/sessionStorage/cookie/IndexedDB 四面全空、刷新后设置不保留且体力回满」。当时把断点猜在 `game-settings.ts` 的 `persist(): if (!save) return;` 上游，查下来与游戏层无关：`packages/framework/src/platform/web.ts` 把 `globalThis.localStorage` 直接当框架 `Storage` 交出去，而框架接口讲 `get/set/remove/keys/clear`、DOM 只有 `getItem/setItem/removeItem/key/length` ⇒ 网页端每次写都撞 `TypeError: storage.set is not a function`，被 `JsonStorage.setString` 的 try/catch 吞成返回 `false`（控制清单「读写失败永不抛异常」），读侧同一吞法 ⇒ 永远当新档。微信侧一直是对的（`weapp.ts` 有 `WeappStorage` 包 `wx.*StorageSync`），只有 web 宿主漏了这层适配。
  根因：三层遮蔽叠在一起。① `web.ts` 里 `localStorage?: Storage` 引的是框架自己的 `Storage`（`import { type Storage } from '../core/save/storage.js'`），把 lib.dom 的同名类型顶掉 ⇒ 这处错配在编译期**不可能**报警；② 全仓用例（框架 548 + beads 1380）注入的都是 `NodePlatform.createStorage()` = `MemoryStorage`，本来就合接口，所以替身把真宿主的形状差异整个盖住；③ 吞异常的设计本意是防崩，却把「功能根本不工作」也一起防掉了。
  规避/做法：① 判「宿主相关」的缺陷，先问**用例注入的替身和被测宿主是不是同一个接口形状**；不是，则这条链的绿不覆盖真宿主（K-036 的同族）。② 落一条按**真宿主形状**（DOM 五件套）造的适配用例，改前必红（本例红讯 = `storage.set is not a function`）：`packages/framework/tests/platform/platform.test.ts`。③ 修在唯一的错配点而不是在各调用点补 try/catch：加 `DomStorage implements Storage` 适配层（与 `WeappStorage` 同族），并把 `GlobalWithDom.localStorage` 的类型改成 DOM 形状，让编译期从此站在这一边。④ 凡「失败必须静默」的错误通道，配一条**能显形**的读回口径（返回值 / 计数 / 日志），否则静默 = 无声的功能缺失。
  复验（2026-10-28，真宿主而非替身）：`build:cocos:web` 重出 `web-mobile` 产物后在浏览器实测 —— 启动即写出 `wxgame.beads.save.v1` + `wxgame.beads.meta.v1`；拨「音乐」→ 真 `localStorage` 文档里 `settings.bgmMuted` false→true，且 spy 记到 save 键 `setItem` 恰 1 次；刷新后文档仍为 true，暂停面板渲染出「音乐 关」⇒ 用户可见症状正式关单。浏览器取证另有两坑：① 面板期 `__WXG_GAME_DEBUG().screen` 仍是 `play`，判「面板开没开」要读 `phase`；② 设计坐标→客户端像素别靠眼估（本轮 CTA 眼估偏了 16px），点完拿引擎自己的调试标签（`dsn`）或截图读数回验。
  反向用法（2026-10-28，微信 mock 腿 / QA SC-WX-01）：替身也可能**比真宿主多给一个假对象** —— `packages/framework/src/adapters/cocos/bindings.ts::_fitToGameCanvas()` 的 `doc?.querySelector` 只挡 `document` 缺失，而浏览器里的 wx mock 提供了一个**没有 `querySelector` 的 `document`** ⇒ 每次 `start()` 抛 `TypeError`，而真机（无 `document`）反而永不显形。⇒ 宿主探测一律挡**方法存在性**（`typeof x?.m === 'function'`），⛔ 只挡 null。同批把「必须走宿主工厂」固化成机检：`packages/framework/tests/platform/platform.test.ts`「宿主存储契约」逐宿主跑 `createStorage()`（⛔ 直接 `new WeappStorage(wx)`，那会绕过接线），断五方法齐全 + 写入落到宿主底层；敏感性已证（web / weapp 各自退回直传 ⇒ 各自那条腿判红）。
  关联：K-036（跑过 ≠ 检到）、K-195（同晚第二例：量具假阴性把可用判成死局）、K-174（同一映射两处登记必漂移）、K-010（宿主/沙箱环境差异造成的假读数）。

- **[判据实测取证][K-198] 「三浏览器全干净」不等于真机干净：降级臂开关由资产齐不齐决定，浏览器可能从未走过真机路径**（来源 WXG-T-461 / cfc5432d，2026-10-28）
  现象：托盘珠真机缺陷（豆顶被槽底色横带盖住），但 harness canvas2d / 浏览器 web-mobile Cocos / 微信模拟器三端全部复现不了；按「静态穷尽 + 三端干净」推演无元凶，差点把缺陷归为不可解。
  根因：Cocos 真机珠渲染走 carrier（tint 图集 + Sprite 池）路径，而该路径**默认开的前提是 mask 需求集装载齐**（`TINT_MASK_GAUGE_PIN=null` ⇒ 需求 4 张；构建档包不全 ⇒ warmup `N/4` `< 4` ⇒ carrier 静默 off 回矢量臂）。浏览器构建档资产不齐 ⇒ 浏览器「干净」根本没测到真机那条腿——**验证矩阵看起来覆盖三端，实际目标路径只被真机踩过**。
  规避/做法：① 判「某路径干净」前先用日志自证**该路径真的被走过**（`[BeadsBlitCarrier] masks=N/N carrier=on|off`），静默回退（K-108 同族）会让对照实验测的是另一条臂；② 真机专属路径的 A/B 对照用**宿主开关**（启动参数 `carrier=off`）做第一刀二分——同机同包同参数，比跨端对比干净；本例一刀把病灶从「整个渲染栈」钉到 carrier tint 腿；③ 「多端干净」的证据要按端列出**实际生效的渲染臂**，不是只列「没复现」。
  关联：K-197（替身/遮蔽族）、K-108（静默回退看不出）、K-036（跑过 ≠ 检到）。

- **[判据实测取证][K-199] 真机循环贵的缺陷：单文件多臂探针 + 启动参数选臂，一轮会话钉死环节**（来源 WXG-T-461 / cfc5432d→ea1b8892，2026-10-28）
  现象：缺陷钉死在真机专属渲染腿后，内部仍有四层候选（Sprite 池序 / 图集 drawImage / `uploadData` 上传 / 合成层）；每轮真机循环 = 构建 + 出码 + 真机操作，逐层试错不可接受。
  根因：真机取证的优势是「现象现场」，劣势是「每轮成本高」；把 N 个嫌疑拆成 N 轮，等于把最贵的资源用最浪费的方式花。
  规避/做法：① **一次落齐多臂**：单文件加 `PROBE_MODE`（启动参数 `probe=1|2|3` 选臂），每臂单变量——P1 行为钳制（`setSiblingIndex` 强制本帧命令序）、P2 纯观测读回（合成后 `getImageData` 双采样打日志）、P3 行为替换（绕过嫌疑环节直贴）；② 读回采样点选**判别力最大**的位置（豆形外角 / 孔心 / 上缘 / 下缘），src 与 atlas 双份对照 ⇒ 一条日志同时切开「合成层 / drawImage 层 / 上传层」；③ 诊断件标注任务号、钉死后即撤（revert 独立成笔，历史可 cherry-pick 复用）；④ 本例战果：P1/P3 无效排除两项 + P2 `src≡atlas` 逐位一致（合成链干净）+ 槽 tile 全透明读数直指「槽底色靠矢量底 rect 承担」⇒ 两轮真机会话收敛根因（K-116 ⚠ 段）。
