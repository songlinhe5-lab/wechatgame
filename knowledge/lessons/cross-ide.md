- **[跨IDE][K-080] `kb:sync` 的「谁先跑谁归因」：无主条目会被恰好先运行的那次 sync 记进别人的 Task 号**（来源 beads 选中抬起立体感批（未挂 Task 号），2026-09-26；原登 `工具链` 片，由 WXG-T-169 沉淀批**代归位**至本片——本条讲的是并发会话的写序，不属工具链装置自身）
  现象：向 `knowledge/lessons/{criteria,process}.md` 追加两条**无行内 ID** 的条目后跑 `pnpm run kb:sync`，输出「本次新补号 0 / 写入：无」，而 `CHANGELOG.md` 里这两条落在**并发会话**的 `### WXG-T-169` 分组下——补号与归因都不是我这次运行做的，是对方那次 sync 顺手把刚落的正文一起扫走（我读到的 ID 已是它分配的）。
  根因：① `--task` 是**运行时入参**，条目正文里的「来源 …」是散文、机器不解析 ⇒ 归属跟着「谁跑」走；② `events` 的语义是「本轮变更日志」，但 `renderChangelog` 按 `event.taskId` 分组渲染成 `### WXG-T-xxx` ⇒ 读者必然把它读成归属；③ 追加正文与补号写盘之间没有任何原子性/锁。
  规避：① 追加条目后**同会话立刻**跑 `kb:sync`（先写先补号），隔一步就可能被别的会话抢先；② 确实无号可挂时，接受渲染器现成的 `### （无任务号）` 分组（`taskId: null` 是一等分支），⛔ 不得借用别人的号；③ 已串号的订正只能改 **`ledger.json::events[].taskId` / `note`**（sync 对既有 events 只做 `normalizeEvents` 保留、不重写 ⇒ 这一层改了才稳），⛔ 改 `CHANGELOG.md` 无意义（下次 sync 即覆盖）；改前先按条件过滤断言**命中恰 1 条**，≠1 即停手；④ 判归属的权威字段是 `entries[].sourceTask`（不是 event）——核对顺序：`sourceTask` → 正文来源行 → event 日志。
  判例引用：同族 K-045（并发会话共享同一份台账：那边是 `git add` 整文件被捎带，这边是生成器运行序被抢）、K-046（引用要认工作树正本）、K-058（走盘生成器只认自己的硬编码规则，不认「我以为」）、K-078（编号占用信息住在散文里 ⇒ 动作与真源不绑定，同型失效面）、K-008（同一并发会话号池问题）。

- **[跨IDE][K-087] 并发会话的「台账已落 / 代码不在工作树」不一致：下游把层集当配方真源前必须先做 patch↔现树对账**（来源 WXG-T-218，2026-09-27）
  现象：主表 T-215 行写「已落（两轮）/ beads 726/726」，而三轮改动（描边边框 + 孔边线 + 刻面内缩 0.09→0.0615→0、去 `PLATE.fill`）
  **只存在于** `temp/bead-relief-compare/wip-215-full-backup.patch`；现树 `FACET4_FACET_INSET` 仍 0.09、层集零描边、
  `assets-spec` 无 v1.5-r19（grep 全仓只在 patch 里命中）。无任何机械门响：typecheck/单测/verify 全测的是“现树那一份”。
  根因：多 IDE 共一份工作树 ⇒ 未 commit 的改动可被 `checkout`/`stash`/并行提交抹回；台账行由该会话**当时的树态**写下，
  此后无人复核（与 K-046/K-045 同族，只是漂移面从「号」换成了「交付物本体」）。
  规避：① **下游消费“代码形态”作真源的批**（本例 = 烘焙纹理是层集的编译产物，不归位就会把已判不合格的形态烘进缓存、
  每次命中都在复现），开工前先对账：`git apply --stat <备份 patch>` 列文件面 + grep 现树关键常量读数/文档版本号逐项比对，
  不一致 ⇒ 先归位或明写为 **0 号前置**，⛔ 照现树继续；② 对账结果写进台账与提案头注（不靠口头提醒）；
  ③ 本会话不代改他人单的行（只追加披露），归主理人/质检裁决；④ 发现备份 patch 比台账多一轮时，**逐轮确认终态**再落，
  ⛔ 拿最后一轮 diff 当终态（本例 patch 已到 `recheck_7`，主表只到 5/6）。
  判例引用：`production/TASKS.md` T-215 行 vs `temp/bead-relief-compare/wip-215-full-backup.patch`；同族 K-046（领号/状态要认工作树）、K-045（共享工作树的暂存原子性）、K-051（纸面推论须实测复算）。
- **[跨IDE][K-142] 「不擅自 push」的纪律会被 IDE 自动同步静默绕过；推送状态只能靠 ls-remote / reflog 取证，`git status` 永远看不出来**（来源 WXG-T-292 代收口批，2026-10-18）
  现象：会话只跑 `git commit`（11 笔），提交后台账按实写「未 push」；随后 `git ls-remote origin refs/heads/develop` 显示**远端已等于本地 HEAD** ⇒ 全部早已公开。全程 `git status` 只报“working tree clean / 领先 origin N 个提交”，看不出任何异常。
  根因：推送来自 IDE 侧自动同步（时机在每次 commit 后 30–60 s；仓内 `.githooks` 只有 pre-commit / commit-msg，`git config` 也无 push 相关项）。远端跟踪引用被 push 更新 ⇒ `git reflog show origin/develop` 留下 `update by push` 条目，但**工作区状态与“谁推的”无关** ⇒ 任何基于 `git status` 的推送判断都是猜。
  规避/做法：① 写「未 push」前两条取证必跑：**`git ls-remote <remote> <branch>`**（远端真值，别只看本地跟踪引用）+ **`git reflog show <remote>/<branch> --date=iso`**（拿 `update by push` 时间戳与 commit 时间对撞 ⇒ 直接量化“是不是自动”）；② 台账里的状态句带**核实时间**，被自动同步推翻时按事实改写、不拿旧断言交差（K-053同族：不静默删但必须订正）；③ 想让「不擅自 push」真成立，只能在 **IDE 设置侧**关自动推送——仓内拦不住（git hooks 无 push 阶段，`pre-push` 也可被 `--no-verify` 绕）；关掉后复测：随便提一笔 → 等 ≥60 s → `git rev-list --count origin/develop..HEAD` 应 **≥ 1**，为 0 即开关仍开着。
  判例引用：`memory/MEMORY.md` §Hooks（登记与复测法正本）、`production/TASKS-DETAIL.md` §WXG-T-291「推送状态」条。⚠ 追记（2026-10-19 · WXG-T-294）：用户改裁 = **保留自动推送**（10-18 的「关掉」作废）——本条技术结论不变（取证只认 ls-remote / reflog），纪律侧从「它越了我们的约束」改为「提交即入远端 ⇒ pre-commit 的门必须真绿，因为没有人会再来仓一次」；「会话不得自行 push」仍成立（开关不在仓内，agent 既不能开也不能关）；同族 K-046（状态要认工作树而非口头）、K-045（共享工作树）。
- **[跨IDE][K-160] 终端按列宽折行后的输出抄进编辑工具会夹入「词内假空格」；中文正文改完必做一次空格复核**（来源 WXG-T-349 自纠批 / 读数归 WXG-T-350，2026-10-22）
  现象：把 `grep`/`sed` 在窄终端里**已折行**的输出当 `original_text` 或直接抄进正文，换行处会被带成一个空格——中文里就变成「需␣逐笔」「在␣台账结构重构」这种词内假空格（␣ = 本条刻意不真写空格，以免本文件自身被②的复核正则命中）；写入当场不报错，直到看 diff 或渲染才发现。同型症状：拿折行输出做精确匹配⇒ `Failed to match`（实际差在换行点那个空格）。
  根因：终端按列宽折行，复制出的字符串在折点被补成分隔符；编辑/写入工具不做「可视排版 ≠ 文件字节」这层还原，⛔ 不会报警。中文本无空格 ⇒ 多出来的空格无法靠语义自动识别，人工校对又靠同一双眼睛。
  规避/做法：① 取长行原文用**读文件工具按行号取**，或 `node -e` / `sed -n 'Np'` 直接打单行，⛔ 从已折行的终端面板里逐字复制；② 中文文件落盘后对 **diff 的新增行**跑一次 `rg -n '[\p{Han}] [\p{Han}]'`（本仓 Grep 工具即 ripgrep，本机实测可命中；macOS BSD `grep -P` 不可用）；③ 复核结论必须分「本批新引入」与「历史遗留」——数新旧两侧命中条数，**相等才敢说没夹带**，⛔ 顺手改掉历史那几处（会混进无关 diff）。
  归片理由（非内容理由）：本条本属 `工具链`，但该片实测 **7740/8000 tok** 已贴顶，为一条目做标签再切（K-119 ④：自带脚本三重自证 + `TAG_TO_SHARD`/`LESSONS_SHARD_ORDER` 两处硬映射）不划算 ⇒ 按「工具面之间搬运文本」的形状归 `跨IDE` 片（与 K-142 同族：都是 IDE/终端与仓内纪律的接缝）。
  判例引用：K-142（IDE 侧动作仓内拦不住、只能换工具面取证的同族形状）、K-106（“跑了”与“检到了”分清 ⇒ 本条是“写了”与“写对了”分清）、K-051（纸面推论须实测复算）。
  追记（2026-10-22，WXG-T-353 · **同族另一头：不是多出空格，而是符号名被静默改写**）：`rg -rn <模式>` 里的 `-r` 是 **`--replace`**（既不是递归、也不是 `-n` 的一部分），于是匹配到的文本全被替换成字面 `n`——本批一次搜索把 `tierSecondsFor` / `LEVEL_TIME_MIN` 都打成 `n`，看上去像代码里真叫这个名字，直接引用这段输出就等于把假事实写进了文档。征状识别：一次搜索结果里**大量不同符号塌成同一个 token**（或行内只剩单字母），这不可能是真代码。规避：凡要从搜索输出里引用符号名/原文，必须用不带 `-r` 的写法重跑一遍再取字节（本批第二次重跑即取到真名，未据此下结论 ⇒ 风险面 0，但征状极易被当成事实）。
  追记（2026-10-23，WXG-T-354/355 · **同族第三头：不是多出空格，而是字符被静默换成形近码点 —— 且肉眼复核无效**）：本批把「逐」写成「逢」（U+9022）、「塌」写成「塔」（U+5854）、把 `≺`（U+227A）写成 `⋺`（U+22FA）、把顿号「、」（U+3001）写成片假名中点 `・`（U+30FB）；另有把「锤」（U+9524）替了「锚」（U+951A）**连发两次** —— 第一次当 `original_text` ⇒ 工具 `Failed to match`（拦得住），第二次落在已成功替换的 `new_text` 里 ⇒ **错字直接进文件**，而我肉眼校了三遍没看出来。更坏的一面：台账里那条自纠把自己写错的码点也记错了（登成 U+22BA，真身 U+22FA）⇒ 说明“知道有这类错”不等于能写对。根因：中文近形字与生僻符号在输入/采样层面属同一视觉簇，而 diff 校对靠的是同一双眼睛 ⇒ 无独立信息源；工具只要求“有差异”，不校验差异是否合法。规避/做法：① 改完对 `git diff HEAD` 的**新增行**跑一次**按码点机械扫**：零宽族 U+200B/200C/200D/FEFF/2060 + 已知近形集（逐/塔/锤…）+ 非常用符号盘点（列出非 ASCII 非常用字符及各处数，逐条判归属）；② **命中必须打印所在行与归属文件**，并区分“本批新增”与“自纠条目里的引文”（后者会自我引用 ⇒ 同一轮出现“扫描命中数 = 1”与“全文 grep = 2”并不矛盾，⛔ 拿字面计数下“零残留”结论，也⛔ 顺手改历史那几处）；③ 引用字符时写**码点**不写字形；④ 复发处置只能落成可复跑的命令（本仓已落 `tools/scripts/scan-text-distortion.mjs`：只扫 diff 新增行 + 打印归属文件 + 非常用符号盘点 + 末尾给判读口径；⛔ 未进 verify，无门禁消费者），⛔ 写成“下次注意”。

- **[跨IDE][K-162] 向 Markdown 表格追加行时拿「半截行」当追加锚 ⇒ 把相邻整行吞掉且工具不报警**（来源 WXG-T-354/355 自纠批，2026-10-23）
  现象：往 `production/TASKS.md` 主表追加一行时，`original_text` 取的是上一行开头的一段唯一前缀 ⇒ 结果两行合成一长行，**354 的行首 `| WXG-T-354 | beads·§3.7 三档时钟按档地板落码` 整段消失**，355 行尾黏上 354 的余文并多出 3 列，`check:tasks` 报「该行 8 列（应 6）」且「详情里有 `## WXG-T-355`、主表无该行」。同类失效此前已因**凭记忆**写 `original_text` 触发 6 次，本批是第 7 次。
  根因：编辑工具按字节精确匹配，只要求锚在文件内唯一，⛔ 不做“这是一整行/一个表行”的语义校验；而 Markdown 表格的格式契约恰好是“行 = 一行”，唯一前缀常落在被吞行的中段。
  规避/做法：① 追加行的锚 = **完整行**或**行尾唯一串**（末尾新增尤其安全：锚后只接正文，不可能吞行），⛔ 半截行；② 改完立刻用 `git show HEAD:<file> | sed -n '<行号>p'` 取原行、与恢复后的行做 `cmp` 逐字节比对（本机 BSD `diff` 遇 options 报错时仍会打印“成功”标记 ⇒ 取证改 `cmp`，参 K-142 的“只认机械取证”口径）；③ 恢复被吞行只做**最小断行 + 补前缀**，⛔ 重打整行长文（重打只会再错一次）；④ 结构性回归确实有机械门兜（本例 = `check:tasks` 的主表列数 / 详情节配对 / 头注计数），但“门能在下一次运行报红”不等于“本轮可以不当场自证”——台账串行会直接阻塞入库。
  判例引用：K-160（同族：写入不报警、只能靠机械扫描复现）、K-045（同一台账被并发会话写）、K-046（号/状态要认工作树而非口头）、K-051（纸面推论须实测复算）。

- **[跨IDE][K-164] 两会话在同一工作区改同一个文件 = 后写者整文件覆写，前者的改动会静默消失、`git status` 看不出来**（来源 WXG-T-351 续 / commit 4db4343、c06a137，2026-10-23）
  现象：① 本侧在 `src/config/tuning.ts` 给 `HEART_PRICE_LADDER` 加的 `@deprecated` 注释块，跑完 `framework:sync` 后**凭空消失**，而 `git status` 只显示该文件一个 `M`（看似正常）；对 `git diff` 逐 hunk 核对才发现磁盘上只剩另一会话新增的 `LEVELS_BAND_INSET` 块。② 更险的一次：索引里残留着对方提交**之前**的版本（12 件呈 `MM`），若照常 `git commit`（= 索引全集提交）会把他们已推送的工作**反向回退**。
  根因：① 两个会话都用「整文件读 → 改 → 全量写回」（脚本 or 编辑器整存）而非定点编辑 ⇒ 后写者把**自己的旧副本**一起落盘，抹掉对方刚落下的内容；② `git status` 是**路径级** dirty 视图，同文件并发改动被并成一个 `M` ⇒ 内容丢失在 status 上不可见；③ HEAD 前进后索引可能仍指向旧树（多人 `git add` 之后），此时不带路径过滤的 `commit` 提交的是**陈旧索引**。
  规避/做法：① 同文件改完**立刻** `git add` + commit，⛔ 别攒批（窗口越短越安全）；② 收尾核对一律用 **`git diff` 逐 hunk** + `git diff --cached --stat`，⛔ 只看 `git status` 就宣告「改动都在」；③ commit 前确认索引里没有他人内容；发现陈旧索引 → `git restore --staged -- .` 对齐 HEAD（**只动索引、工作区零改动**），再只 `git add` 本单文件；④ 与他人共用工作区时走**按 hunk 过滤暂存**（从 `git diff` 抽出含自己任务号的 hunk → `git apply --cached`），而非整文件暂存；⑤ pre-commit 的「多件提交逐项核对」提示（**K-045**）正是为此而设；推送取证仍按 **K-142**（`ls-remote` + reflog）。
  证据锚：commit `4db4343`（恢复被覆盖的注释块 + 只暂存本单 hunk）、`c06a137`（陈旧索引处置后再提交）、`1cda7c0`。

- **[跨IDE][K-183] 抽取型重构 = 复制：并发批改到同一函数时先集成基线再按最新原件重抽，抽后 grep 指向被搬区域的静态守卫随迁**（来源 WXG-T-420 / commit b4762884，2026-10-26）
  现象：把一段方法体「抽到新文件」本质 = 复制一份再删原件。本例把 `_syncSnapshot`（141 字段快照投影）抽到 `games/beads/src/game/beads-game/snapshot-projection.ts` 时，并发批 WXG-T-431 已把同一函数里 powerup 投影块的取值改了（`powerupFreeUses.solver = _powerups.uses.X` → `windowRestore/randomRestore/trayRestore = _powerups.freeUses('X')`）并合入 develop。若照集成前的旧副本直接 merge，**这份从旧体复制出的投影副本会反向覆盖对方已入库的改动**；而配套测试也照旧副本写 ⇒ 全测仍可能绿，反向覆盖无人报警。与 K-164「陈旧副本整文件回写抹掉他人工作」同族，只是漂移面从「文件」换到「被抽出的函数体」。
  根因：抽取即复制，副本不随源区域的并发改动自动更新；一段被同时「改内容」与「搬走」的逻辑，搬走方的副本在 merge 里静默胜出。`git status` 是路径级视图，看不出内容被反向回退（同 K-142/K-164 的取证盲区）。
  规避/做法：① **先问再抽**——动手抽取前先 `git fetch` + `git log HEAD..origin/<branch>` 比对远端；命中改动落在准备抽取的区域 ⇒ **先 `git merge --ff-only` 到远端 tip、再在最新内联体上逐行重抽**（⛔ 拿集成前旧副本改几行了事）：回退与远端重叠的已跟踪件（主类 / Cocos 镜像 / 台账），保留不重叠的新文件与编辑，ff 后在新 base 上重跑全部重连编辑与断言；② **抽后 grep 全仓「按名字 / 锚点定位被搬区域」的静态源码守卫**——本例 `stars-total-hud.test` 用 `SRC('game/beads-game.ts').indexOf('private _syncSnapshot')` 切片，本体迁走后切片落到错误区域；该守卫有一条 `toContain('starsTotal')` 正向腿**当场变红**（⛔ 若只有负向 `not.toMatch` 会假绿——正是 K-144 追记⑦「截区间门禁须加一条『区间能定位到目标』前置腿」的实证）。处置 = 把守卫的 SRC 路径 + anchor 关键字 + 闭括号锚一并**重指 `snapshot-projection.ts::projectSnapshot`**，既守住原零分配不变量（K-042 同式），又兼新文件被门禁看到的接线证明（K-106）。
  判例引用：K-164（陈旧副本回写覆盖他人工作）、K-087（下游把某层集当真源前先 patch↔现树对账）、K-042（抽走真源后原处守卫失自证 ⇒ 另配独立不变量）、K-106（跑了 ≠ 检到新文件 ⇒ 覆盖要自证）、K-144 / K-089（假绿守卫：负向腿须配正向腿 + 定位前置腿）、K-142（推送/状态只认机械取证）。
