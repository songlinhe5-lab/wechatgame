## 跨IDE

- **[跨IDE][K-007] Qoder 把 `model: inherit` 当具体模型 ID 解析**（来源 commit 2665d10，2026-09-11）
  现象：Qoder 侧 spawn SubAgent 返回 code=40506 model not found，成员未启动。
  根因：Qoder 不支持 Cursor/CodeBuddy 的 `model: inherit` 方言，解析为模型名去查询。
  规避：my-agents 正本 frontmatter **省略 model 字段**（Cursor/CodeBuddy 省略即 inherit，三平台语义一致）；跨 IDE 方言字段只在实测确认后加入正本。

- **[跨IDE][K-008] 跨 IDE 并行会话会撞任务号与 §6 版本号**（来源 WXG-T-016，2026-09-12）
  现象：CodeBuddy 独立会话把新任务编为 WXG-T-013/014，与主会话已占号冲突；Qoder 侧曾抢登 §6 v1.3。
  根因：任务号与版本号活在会话记忆里，仓库无 SSOT。
  规避：`production/TASKS.md` 台账 = 任务号唯一来源（开工先读先领号）；§6 追加前先读最新 HEAD；多平台并行期由单一会话统一落账。

- **[跨IDE][K-009] 派单范围表述必须对照冻结真源复核**（来源 WXG-T-013，2026-09-12）
  现象：主理人派单称「slow/sticky 在 MVP 范围内（concept L94）」，实现者逐字核对四份定稿证明是 Should 层，及时拦截了一次按过期摘要实现冻结外功能的事故。
  根因：转述过期会话摘要，未回查 systems-index §3 真源。
  规避：派单涉及范围/数值时，引用一律以 §3 真源现文为准；实现者收到与冻结文档冲突的指令时**先回传裁决不先动手**（本次已正确执行）。

- **[跨IDE][K-078] 跨域共用批次号（`v1.5-rN` 族）取号必须全仓扫占用，「本文件已见最大号」推不出空号**（来源 beads 视觉规格批（未挂 Task 号），2026-09-26；原登 `流程` 片，由 WXG-T-169 沉淀批**代归位**至本片——与 K-008 同族且该片越 8000 红线）
  现象：给规格补写实施记录要标批次号，按本文件正文已见的号往下取 ⇒ 首稿取 r11；而 r11–r13 早被**另一域**（音频 `bgm-main-composition`）占用、r14 被另一张单占用。这条占用事实**只写在另一个文件的头注散文里**（「`v1.5-rN` 为全工作室共用批次号、非本文件私有序列」），在本文件里无从发现。事后靠补一段「让号自查」订正为 r15。
  根因：号空间跨文件跨域共用，但**占用表住在一个具体文件的注释里**，不与「我要取号」这个动作绑定；比 K-046（只读 git 头注会拿到旧最大号）更糟——正本文档里压根没有号表。
  规避：① 取任何共用号前跑一次全仓扫（`grep -rhoE 'v1\.5-r1[0-9]' --include='*.md' --include='*.ts' games/ docs/ production/ | sort | uniq -c`），按占用表取第一个空号，⛔ 不从本文件已见号推；② 让号优于抢号、号递增不回收（沿用 K-046 口径）；③ 订正时留**自查痕迹**（「首稿误取 rNN ⇒ 因 X 改 rMM」），否则后来人视空号为漏写、又来补洞；④ 本面**无机械门**，先登记为缺口，第二次同型踩坑再建唯一性检查（不为一次性问题造门，参 K-060 的「门要有消费者」）。
  判例引用：K-046（领号认工作树，不认快照头注）、K-059（位置标签会换义 ⇒ 引用须带正文锚）、K-008（同族：并发会话撞号与版本）。

- **[跨IDE][K-080] `kb:sync` 的「谁先跑谁归因」：无主条目会被恰好先运行的那次 sync 记进别人的 Task 号**（来源 beads 选中抬起立体感批（未挂 Task 号），2026-09-26；原登 `工具链` 片，由 WXG-T-169 沉淀批**代归位**至本片——本条讲的是并发会话的写序，不属工具链装置自身）
  现象：向 `knowledge/lessons/{criteria,process}.md` 追加两条**无行内 ID** 的条目后跑 `pnpm run kb:sync`，输出「本次新补号 0 / 写入：无」，而 `CHANGELOG.md` 里这两条落在**并发会话**的 `### WXG-T-169` 分组下——补号与归因都不是我这次运行做的，是对方那次 sync 顺手把刚落的正文一起扫走（我读到的 ID 已是它分配的）。
  根因：① `--task` 是**运行时入参**，条目正文里的「来源 …」是散文、机器不解析 ⇒ 归属跟着「谁跑」走；② `events` 的语义是「本轮变更日志」，但 `renderChangelog` 按 `event.taskId` 分组渲染成 `### WXG-T-xxx` ⇒ 读者必然把它读成归属；③ 追加正文与补号写盘之间没有任何原子性/锁。
  规避：① 追加条目后**同会话立刻**跑 `kb:sync`（先写先补号），隔一步就可能被别的会话抢先；② 确实无号可挂时，接受渲染器现成的 `### （无任务号）` 分组（`taskId: null` 是一等分支），⛔ 不得借用别人的号；③ 已串号的订正只能改 **`ledger.json::events[].taskId` / `note`**（sync 对既有 events 只做 `normalizeEvents` 保留、不重写 ⇒ 这一层改了才稳），⛔ 改 `CHANGELOG.md` 无意义（下次 sync 即覆盖）；改前先按条件过滤断言**命中恰 1 条**，≠1 即停手；④ 判归属的权威字段是 `entries[].sourceTask`（不是 event）——核对顺序：`sourceTask` → 正文来源行 → event 日志。
  判例引用：同族 K-045（并发会话共享同一份台账：那边是 `git add` 整文件被捎带，这边是生成器运行序被抢）、K-046（引用要认工作树正本）、K-058（走盘生成器只认自己的硬编码规则，不认「我以为」）、K-078（编号占用信息住在散文里 ⇒ 动作与真源不绑定，同型失效面）、K-008（同一并发会话号池问题）。
