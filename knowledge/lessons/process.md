## 流程

- **[流程][K-011] 质量门复验者 ≠ 实现者**（来源 WXG-T-019，2026-09-12）
  现象：G4 复验由严守真（非实现者程基岩）独立执行，抓到 F-01 恒真断言——实现者自验 465 全绿也测不出自己写的自比较断言。
  规避：门级验证固定换人（fresh eyes）；自验（实现者）+ 复验（独立成员）双层是标配，缺一不可。

- **[流程][K-035] 文档状态列混淆「规格已写」与「代码已实现」= 可访问性假绿的温床**（来源 WXG-T-084 G4 回归 §6 / 回写裁定 WXG-T-091，2026-09-14）
  现象：`art/accessibility.md` 特性矩阵「落地状态」列标 ✅/🔶「落地」，但对应特性在 `src/**` 零命中。**四轮重犯**：① breakout `reduceMotion`（D-01）；② beads A1/A3/B2（`symbols.ts`/`bead-render.ts` 当时不存在）；③ beads A4（道具卡空白）；④ beads A2/A2b/C1/D1/E2（WXG-T-084）。
  根因：状态列把「规格任务完成」当「实现完成」——同格甚至同时出现「✅ 落地」与「随 T-085 实现」；而 G4 判据 100% 为 `[Node]` 逻辑可断言型（事件计数/公式复算），「开关存在吗 / 画面看得出吗」从来不在问句里。
  代价：beads 在「184 测试绿、完成度高」自评下交付，用户实测「完全没有可玩性」，Standard 可访问性承诺实际未兑现。
  规避（按有效性排序）：① **机械守卫**（待立项，本单未落码）：新增 `check:a11y`——矩阵每行设「代码符号锚点」列，状态含「落地」者必须在 `games/*/src/**` 命中该锚点，零命中即 FAIL（唯一能结构性阻止第 5 轮的措施）；② **状态列四值枚举**：`规格已定`/`已落码`/`已验收（附证据路径）`/`延后`，禁用裸 ✅；③ **单点裁决扩围**（ADR-0007 精神）：accessibility ↔ GDD ↔ ux-spec 的交叉承诺须指定唯一权威文件（D1/E2 冲突即因 accessibility 单方面声明、S9 冻结面板清单从未收录）。
  判例引用：`production/qa/beads/g4-regression-report.md` §6（四轮假绿谱系 + 5 条防再犯）；QA 侧已将「文档 ✅ ↔ 代码符号命中」列为 G4 固定检查组（TC-PER-09 可访问性假绿哨兵）。

- **[流程][K-036] 多项串联的门禁若「失败即短路」且「缺对象仍报绿」，它的 ✅ 不构成任何证据**（来源 WXG-T-084 §3 / WXG-T-092 §18.1，裁定立项 WXG-T-094→T-095，2026-09-15）
  现象：`verify` 以 `&&` 串 14 项 ⇒ 第 8 项失败后 9–13 项**从未执行**，而日志只指向失败项、不提示「后续门未跑」；`check:size` 只测 breakout 产物，beads 产物不存在时 `status:'skipped'` 仍让整体打 ✅ ⇒ 报告写「包体校验 OK」。
  根因：门禁被当成「一个退出码」而非「一组必须各自有结论的检查」；缺被测对象与检查通过共用同一个绿色出口。
  代价：G1 的「绿」需人工反推链路是否跑完；beads 包体红线连续两轮**无数据却看似已测**（BD-17/BD-18，均 P1）。
  规避：① 聚合脚本**逐项收集结果 + 汇总退出码**，尾部必打「未通过 / 未执行」清单；② 检查项缺对象时**显式 SKIP + WARN 计数**，禁静默通过；③ 任何引用该门的结论必须能答「这轮实际跑了哪几项」（自测脚本要包含「注入一项失败 ⇒ 后续项仍跑且总退出码非零」用例）。
  判例引用：`production/qa/beads/g4-regression-report.md` §5 BD-17/BD-18、§18.1 不升 PASS 理由 3；同族 K-030（脚本自测假绿）。
  落地（WXG-T-095，2026-09-15）：规避 ①②③ 已全部实现——`tools/scripts/verify-all.mjs` 逐项执行不短路 + 尾打 `PASS/SKIP/FAIL` 汇总与未通过清单（退出码由汇总定，`--strict` 把 SKIP 判失败）；子命令以 stdout 末次 `STATUS: OK\|SKIP\|FAIL` 自报结论（`check-bundle-size.mjs` 已接，缺产物报 SKIP 非 OK）；规避 ③ 的两条自测为 `pnpm run verify:selftest`（含「注入一项失败 ⇒ `[2/2]` 仍执行」的红→绿实测）与 `check:size:selftest`。**新口径**：`verify` EXIT=0 的含义改为「全部步骤均被跑过且无 FAIL」；但 SKIP 仍等于「没测」⇒ 引用结论时必须逐条列出，不得写成「全绿」。
  追记（2026-09-20，WXG-T-179 · **同族形态二：条件包裹断言**）：本条讲「串联短路」，此处是**把自检整段包进成功条件**——`if (der.ok) { …全部断言… }`。于是当 `der.ok === false`（错位打乱失败）时**断言一条都没跑**，脚本照旧写盘并打印「**自检：通过**」，而产物其实是**全 void 的废盘**（`--colors 2` 实测触发；根因 = 该色数下单色占比必然破 `⌊N/2⌋`）。读者看到那四个字，会以为校验发生过。**规避**：① 校验的**失败态必须显式 loud**（`if (!ok) { console.error(原因); process.exit(1); }`），主体断言放在失败分支**之后无条件执行**；② 凡「某个 ok 才校验」的写法，先自问「**ok=false 时谁在把关**」；③ 「自检通过」这句输出必须**只可能在全部断言执行后**到达（修法 = 失败分支提前 exit，末尾才 print）；④ 与 K-035（「规格已写」≠「代码已实现」）、K-060（存在性断言无判别力）同族 —— 三条是一件事的三个面：**校验缺席 / 校验无判别力 / 校验被条件吞掉**。

- **[流程][K-037]「指令流层可证」≠「屏幕层可证」：Node 探针全绿不得抬升表现层结论**（来源 WXG-T-092 §17/§18.1，裁定立项 WXG-T-094，2026-09-15）
  现象：复验把 11 项 FAIL 改判到 4 项，全部依据是 Node 侧事件/指令流断言；而 §G 20 条「玩家可感知」判据仍 3 条 ⛔（像素、色盲、真机）⇒ 「可玩性已修好」在**代码层成立、在屏幕层未被看过一眼**。
  根因：判据按「可断言性」自然收缩到逻辑层，表现层因缺取证通路（无头截图 / 滤镜 / 真机）长期无人跑，于是把「不可测」写成「未覆盖」而非「未验」。
  代价：可证面天然残缺下若判 PASS，等于用易测项冒充难测项（与 GAP-09 假绿同根）。
  规避：① 报告**逐条**标注每条判据的取证道次（`[Node]/[Harness]/[Cocos]/[Device]/[R]`），缺道次即 ⛔ 不计入通过率；② 综合结论取**最弱道次**，禁因 Node 全绿抬升；③ 把「打通取证通路」本身立项（T-099），而不是反复在易测层加断言。
  判例引用：`production/qa/beads/g4-regression-report.md` §17 逐条道次结论、§18.1 限制声明 1；K-035（同一病根的状态列版本）。

- **[流程][K-039] 报绿之后又动了源码：交付自述必须与最终状态同一时点**（来源 WXG-T-096 复核轮，2026-09-15）
  现象：会话中报「`verify` 13 PASS / 1 SKIP」为真；其后继续改 `packages/framework/src/**`（合成引擎重构）却没重跑 `framework:sync` ⇒ 独立复跑同一命令得 EXIT=1（12 处镜像漂移），QA 据此记「限制声明 ⑥：自述与实测不符」并建议重开 BD-20。排查中还一度把成因误判为「sync 会把 `{ }` 规范化为 `{}`」——读 `transformSource()` 源码 + 比对 HEAD 两侧后证伪：拷贝是逐字的，仓内本就有 `{ }` 样式件且镜像一致。
  根因：门禁结论是**时点性**证据，而「改完还引用旧绿」没有任何机制拦得住；镜像一致性靠人记得跑 sync。
  代价：跨代理复验撞在不一致状态上 ⇒ 白跑一轮取证 + 一条缺陷被建议重开（返工）。
  规避：① 每次改 `packages/framework/src/**` 后固定「`framework:sync` → `verify`」连跑，任何写进文档/台账的数字（例数、PASS 数）必须在**最后一次改动之后**重取；② ~~建议 pre-commit 增条件步~~ **已落地**：WXG-T-101 给 `.githooks/pre-commit` 加了步骤 ①⁷⁄₈（暂存含镜像源码才跑 `sync:check`，**只拦不写**——钩子改工作区不会进本次提交）；③ 指认「工具有 bug」前先读该工具源码并拿 git HEAD 两侧取证；④ **条件守卫的触发面必须等于被守护工具的实际作用面集合**，且该集合要从工具输出取证不能从脚本名推断——①⁷⁄₈ 初版只匹配框架路径，而 sync 同时镜像 `games/<game>/src/**`（一次跑报「framework 39 + game 26」）⇒ 只改玩法源码的提交能静默绕过，**一个只拦一半的守卫比没有守卫更危险（给人“已有门”的错觉）**；补漏后两类源各手工复现一次红→绿才算验收（WXG-T-098 轮发现并修）。
  判例引用：报告 §19.2、§19.5 限制声明 ⑥、§14 BD-20 行（关闭→建议重开）；同族 K-036（门禁 ✅ 的时效与口径）。

- **[流程][K-053] 冻结「语义/行为」反转（数值不变）走「反转批」固定顺序，防漏回写散落的旧裁定**（来源 WXG-T-165 / commit 3f79f6d，2026-09-18）
  现象：§3.14 裁定「回主菜单后棋盘完整保留、不惩罚」被真机反馈反转为「弃本局棋盘」，而 `STAMINA_START_COST=1` 等 §3 冻结**数值一字未动**。§3 号表不碰 ⇒ 没有任何机械门报警，但旧语义同时散落在 systems-index S 表摘要、子系统 GDD 头注、§2.2 行为子句、§8 验收判据、§9 变更记录五处；只改代码 + 测试会全绿通过，而文档仍按旧语义描述。
  根因：冻结常量表只钉**数值**，行为裁定以自然语言散写在各文档；反转是「一处改动 ↔ 多处回写」的一对多写入，漏任何一处，下一个读者就按旧语义实现。数值漂移有 `§3 真源` 兜底，语义漂移无兜底。
  做法（「反转批」顺序，勿乱序）：① **先钉语义再动笔**——「不保留进度」这类短语至少两种读法（弃棋盘 / 清解锁 / 扣心），用 AskUserQuestion 给 2–4 个选项让主理人拍板；② 代码与测试**同批**改，并把测试断言翻到旧语义的反面（旧断言 = 进度保留，新断言 = 重进即再扣次），防「实现对了、测试还在测旧世界」；③ **三文档一批**：systems-index（版本头 + S 表行回指新裁定 + changelog §6 新版本行）／子系统 GDD（版本头注 + 行为表 + §8 判据 + §9 变更记录）；④ 台账：旧任务行的该子句**改注指向反转单**（留旧裁定括注，不静默删），新任务详情节写明反转内容与动机；⑤ 数值未变时在变更记录里**显式声明「无 §3 数值漂移」**，否则读者会误查号表；⑥ 顺带清点因此变死的接口（本例 `resumeFromPause()` 唯一调用者被删）——留着会诱导后来人重新接线。
  判例引用：同族 K-052（时长常量跨「表现/玩法」两轴时纸面归属会误导）、K-050（消歧须回写**每个调用点**，不能只补一处正本）。
  追记（2026-09-19，WXG-T-164 收口批时坐实）：上面③的「三文档一批」**清单不够**——T-165 当时止于 systems-index / S9 行 / 子系统 GDD，而同一旧语义还活在 **UX 规格（流程图 + 线框注 + 启动路径表 + 决策记录四处）、一页纸概念（决策表 D 行）、`design/proposals/` 提案（MVP 分批口径）** 三处未列入清单的文件里 ⇒ 反转后的收口隔了一天，由**另一张单（T-164）收口时 grep 旧裁定短语**才描出。**做法修正**：反转批的文档面不得写死枚举，而是拿旧裁定的**特征短语**（如「保留进度不惩罚」「不重复扣心」「在途续进」）`grep -rn` 扫设 `design/` + `production/` + 代码注释全域，命中清单即回写清单；同一短语在旧版本行/变更记录里的**留档引用**属正常，不删。**另：任何单收口前都该对它的上位裁定做一次同样的复扫**——本次残留正是由收口而不是由反转本身发现的。

- **[流程][K-057] 「立项单」与「ADR 状态行」都不会被实施它们的另一张单自动收口，核销时要成对扫**（来源 WXG-T-166 核销批，2026-09-19）
  现象：一张只负责「报出前置阻塞」的立项单，阻塞被 ADR 应答、范围被另一张单（实施单）落码后，**主表行仍停在「已立项待 ADR」**；同时 ADR 头部那句「本文仍不落码 / 未裁不施工」也在施工后自动过期。两处失真互相掩盖：读者看台账以为 ADR 还没写，看 ADR 以为还没施工，而**没有任何机械门会响**（测试与 verify 全绿，因为它们只测代码）。
  根因：台账只由**领号会话自己**回填，而「完成它的那件事」发生在另一个号上；跨号回灌没有约定也没有守卫。
  做法：核销立项单时（1）写**「范围 ↔ 交付」映射表**——把当初列的每一条阻塞逐行对上「现在谁做的 + 代码/文档锚点」，对不上的就是**真未完项**（别写进核销结论）；（2）**顺手 grep 该单引用的 ADR / 上游文档状态行**，把“决策当时语”标为过期（保留裁定沿革，不删不改决策主体与正文）；（3）余项**按轨道分流挂号**（数值→§3 变更单、观感→art 轨、设备面→真机走查清单），不吹大核销单范围；（4）台账行里的旧状态字面（如“⚠ 某缺陷待修”）同批回填，否则下一轮又得重查。
  判例引用：K-053（同一“文档跟不及实现”失效家族）、K-046（领号/状态要看工作树，不看快照头注）、K-036（全绿不等于已证）。
  追记（2026-10-05，WXG-T-253）：同一失效形状也活在**上一批写的「⛔ 不加 X」禁令**里。T-252 以「无人用」为由拒绝加 `beginFrame()` 并留了升级路径；
  下一批（T-253）的实现体真需要「本帧开头收上一帧用剩的节点」⇒ **路径被触发**——若只在新单里写「加了钩子」，旧单那条拒绝就成了漂着的反证（后来人可按旧禁令把钩子拆掉）。
  做法：触发旧升级路径时，除登新单外必须**同批回到原单/原注释就地括注**（「该拒绝已被 WXG-T-0NN 触发，现形为可选钩子」），⛔ 不删原理由；代码里的 `ponytail:` 注释与台账文本要一起改，否则文档对了、注释还在说反话。

- **[流程][K-059] 用「甲/乙/丙」转述既有候选清单时必须带正文锚——字母会换义**（来源 WXG-T-167 执行批，2026-09-19）
  现象：提案文档里某问的候选是「甲=多格同屏可见／乙=逐格推进／丙=点格放大」。收口人把三候选**重排**后拿去问用户，把「逐格推进/点格放大」写成了自己的「甲」并被采纳 ⇒ 设计交付里出现「Q2=甲」这个**同号异义**引用：按提案字母读会得出完全相反的架构结论（单相机 vs 分组变换复评是否触发）。子代理读文档时才发现，并在正文补了「以正文语义为准」。
  根因：字母只是**清单内的位置标签**，不是标识符；一旦清单顺序/条数被改动（或转述者合并了两条），字母与语义的绑定就断了。裁定若只以字母回写，跨文档、跨会话不可复现——与 K-050/K-046「旧号/路径写死会漂移」同族，只是漂移的是**选项标签**而非编号。
  做法：① 求裁时**每个选项正文自带语义描述**，字母只作简短标签；② 回写裁定时一律写成「问题 = 语义（原清单字母）」双向锚（例：「Q2 = 逐格推进/点格放大（提案表乙+丙合成；表内原义甲未被采纳）」），并在文件头钉一句「引用看正文不看字母」；③ 若候选被合并/拆分，**在变更记录里显式声明字母表已重排**，否则后来人按旧表读必错。
  判例引用：K-053（先钉语义再动笔）、K-050（消歧须回写每个调用点）、K-046（引用要认工作树正本）。

- **[流程][K-105] 「改裁」不是把 DEC 正文那一行换个结论：同批必扫四节，并把旧推荐原样留作改道证据**（来源 WXG-T-251 / ADR-0030 第十一刀，2026-10-05）
  现象：一份 ADR 的推荐被后续实测数据推翻后，结论只写在读数附录（本例 §5.0.1/§5.0.3），而 §0 结论、§Decision 正文、实施批次表、§未决问题 四处仍停在旧推荐。本例已出现一次：DEC-1 正文写「采纳 丙′」而附录推荐「主选 甲′」，靠正文里一句「不一致时以 §5.0.1 为准」兜住；若没有那一句，下一会话按正文开工就会拿未过采纳门禁的载体做地基。
  根因：ADR 的推荐与裁定分处不同节，而**没有任何机械门管文档内部一致性**（verify 全绿只测代码）；且批次表是「裁前」写的，裁后每一批的射程会变（降级 / 从可选变必做 / 被提前裁定而作废）。
  做法：① 改裁同批扫**四节**：§0 结论（加修订块）/ §Decision 正文（就地标「已改裁」并写裁定理由）/ 实施批次表（逐行判「还算不算数」，本例新增 §5.2）/ §未决问题（标已裁 = 哪个选项）；② **⛔ 不删原文**：旧推荐与理由段原样保留作决策改道证据，只在旁边标作废；③ **伴随义务与裁定同写一条 DEC**（本例三条：观感一致性要新的 A/B、不得把旧路径全量重放带进生产、新链路的成本进低端机预读），否则下一会话只拿好处不担成本；④ 裁定只改「选哪条路」，**实施细节未定的不得代裁**，而是列为开工门禁登记在案；⑤ 台账与 ADR 头注都钉一句「裁定生效 ≠ 已实施」，并把开工拓扑序写出。
  判例引用：K-057（同一「文档跟不及实现」失效家族，跨号回灌）、K-059（回写裁定必带正文语义锚）、K-053（反转批：一处改动 ↔ 多处回写）。
