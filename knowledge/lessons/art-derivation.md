# lessons 分片 — 美术派生

> 标签 `美术派生`（btn-arrow pressed 态批新建）：程序化派生像素资产（状态变体裁切/缩边/AA）的调试方法与算法坑。

## 美术派生

- **[美术派生][K-121] 迭代缩边前必须先做逐列亮度剖面诊断，搞清用户所见「宽带」的真实像素构成**（来源 btn-arrow pressed 态归档 / WXG-T-268，2026-10-12）
  现象：用户投诉按钮 pressed 态两侧「宽带」，v13c–f 四轮各缩 1px 后用户反馈「完全看不到效果」。
  根因：逐轮缩边削的是暖边带**最外一行**（240→239→237→235→232），而用户所见的宽带本体是轮廓环外侧
  约 8 行缓变暖边（lum 228→239）——刀落在带的尾端，带本身没动，观感自然无变化。
  规避/做法：① 收到「太宽/有边」类反馈，先跑**逐列缘 N 行亮度剖面**（每列底缘向上数行的 lum 序列），
  定位用户所见对应哪一段像素（环槽/暖边/接触影），再决定切在哪；② 「缩 1px」类指令若连续两轮无反馈改善，
  视为裁法错误信号，换裁法而不是继续缩（v14 改切在轮廓环槽上，宽带一步变 2px 环缘）；③ 先排查用户是否在看
  旧拷贝（find + md5 证唯一新鲜产物），再怀疑算法。
- **[美术派生][K-122] 全局平滑核会把局部裁切改动跨分支传播，须按分支钳制或收紧作用域**（来源 btn-arrow pressed 态归档 / WXG-T-268，2026-10-12）
  现象：多分支轮廓（侧弧/底弧/端点弧各走不同裁切分支）中只对侧弧做 -1px 收紧，结果未参与改动的底弧列
  底缘也被带下 1px（暗影带被削亮）；另一次 9px 切线光顺把右侧环列切线拉到环槽上方，轮廓环被埋进切片。
  根因：逐列切线经统一插值＋定长窗口卷积光顺，任何一列的改动会沿窗口泄漏到邻列；邻域若属不同语义分支
  （环槽 vs 接触影），泄漏即污染。
  规避/做法：① 光顺后按分支记录**钳制数组**（如 ringcut：`edge[rc] = max(edge[rc], clamp[rc])`），
  给每分支设不可越过的下限/上限；② 局部改动限定作用列范围时，范围边界要留出**两倍窗口宽度**的隔离带，
  或验证邻分支实测值未动（重烘后逐列对照基线）；③ 均值/卷积窗口遇空列（无内容列）必须先插值填充，
  否则邻列被拉到 0 导致整列误删。
