# lessons 分片 — 美术派生

> 标签 `美术派生`（btn-arrow pressed 态批新建）：程序化派生像素资产（状态变体裁切/缩边/AA）的调试方法与算法坑。

## 美术派生

- **[美术派生][K-121] 迭代缩边前必须先做逐列亮度剖面诊断，搞清用户所见「宽带」的真实像素构成**（来源 btn-arrow pressed 态归档 / WXG-T-268，2026-10-12）
  现象：用户投诉按钮 pressed 态两侧「宽带」，v13c–f 四轮各缩 1px 后用户反馈「完全看不到效果」。
  根因：逐轮缩边削的是暖边带**最外一行**（240→239→237→235→232），而用户所见的宽带本体是轮廓环外侧
  约 8 行缓变暖边（lum 228→239）——刀落在带的尾端，带本身没动，观感自然无变化。
  规避/做法：① 收到「太宽/有边」类反馈，先跑**逐列缘 N 行亮度剖面**（每列底缘向上数行的 lum 序列），
  定位用户所见对应哪一段像素（环槽/暖边/接触影），再决定切在哪；② 「缩 1px」类指令若连续两轮无反馈改善，
  视为裁法错误信号，换裁法而不是继续缩（v14 改切在轮廓环槽上，宽带一步变 2px 环缘）；③ 先排查用户是否在看
  旧拷贝（find + md5 证唯一新鲜产物），再怀疑算法。
- **[美术派生][K-122] 全局平滑核会把局部裁切改动跨分支传播，须按分支钳制或收紧作用域**（来源 btn-arrow pressed 态归档 / WXG-T-268，2026-10-12）
  现象：多分支轮廓（侧弧/底弧/端点弧各走不同裁切分支）中只对侧弧做 -1px 收紧，结果未参与改动的底弧列
  底缘也被带下 1px（暗影带被削亮）；另一次 9px 切线光顺把右侧环列切线拉到环槽上方，轮廓环被埋进切片。
  根因：逐列切线经统一插值＋定长窗口卷积光顺，任何一列的改动会沿窗口泄漏到邻列；邻域若属不同语义分支
  （环槽 vs 接触影），泄漏即污染。
  规避/做法：① 光顺后按分支记录**钳制数组**（如 ringcut：`edge[rc] = max(edge[rc], clamp[rc])`），
  给每分支设不可越过的下限/上限；② 局部改动限定作用列范围时，范围边界要留出**两倍窗口宽度**的隔离带，
  或验证邻分支实测值未动（重烘后逐列对照基线）；③ 均值/卷积窗口遇空列（无内容列）必须先插值填充，
  否则邻列被拉到 0 导致整列误删。

- **[美术派生][K-132] 要「把已有画面画矮 N px」时，块状上移会削掉带内实体件；唯一不切穿的术式是「匀色带内删带 + 下段上移 + 末行平铺回填」**（来源 定稿底图换代·走③压矮 / 无单，2026-10-14）
  现象：想让橱窗矮 47 px，第一反应是「在立牌顶缘处切开、下半整块上移」——实算发现立牌总高只有 **99 px**（953–1052），块移 47 直接削掉它近一半。
  根因：块移的切线落在**实体件内部**，被切线穿过的那件东西就会缺一段；而「删一条水平带」改变的是**空隙**的高度，只要带内没有实体，画面里每件东西都完整，只是彼此靠近。
  规避：① 先扫**可切匀色带**（在目标横向范围内求「同一颜色 ≥90% 的连续行段」），并逐件核对带上下边界外的实体（本例带 868–952，珠拼作品底缘 864 / 立牌顶缘 953 均在带外）；② 在带内**扫缝合线**：对每个候选 y0 求「带上方末行 vs 带下方首行」的逐列差，取 (mean, 超阈列数) 最小位，别凭肉眼挑；③ 施术前先确认被切件是否**垂直**（逐行量内缘 x 是否恒定）——斜件横切必 kink，垂直件横切只留亮度台阶（本例左右柱 +1.4/+2.2，0–255 域 <1%，3× 放大目测不可见）；④ 腾出的底部用**原末行平铺回填**，前提是末行确为纯背景（先量再填）。
  配套自证：改完跑逐行 diff，**改动行最小值必须 ≥ 切口行**，否则「上方逐字节不动」不成立；交付文档里的判据读数一律从**交付件本身**复测（见 K-130/K-131 同批）。

- **[美术派生][K-133] 乘性编码资产的不变量必须写成断言；重采样的负瓣会把实体亮边甩进低 alpha 影区并被反除放大**（来源 柜内木牌定稿 B25 / WXG-T-269，2026-10-14）
  现象：定稿资产要求「牌体外纯影区 RGB ≡ 0」（乘性编码，换底才不带出原背景）。缩放前 source 满足，**缩放到 @2x 后 30 px 的 RGB = 255**，而 alpha 只有 0.027–0.090 —— 目检与「只看 alpha」的统计全都发现不了。
  根因：**LANCZOS 有负瓣**。牌体的亮边（242,195,139）被振铃到外侧 3–4 px 的预乘 RGB 里，落在本该是纯影的地方；再执行「除回 alpha」时，除数极小 ⇒ 把这点残余放大成白点。旧版一维影够不到振铃区，所以同一把尺在旧资产上读 0 px，缺陷一直被掩盖。
  规避/做法：① 把不变量落成**常驻断言脚本**，并在**缩放前 source 与缩放后交付件两个域各测一遍**（只测一个域 = 假绿）；② 修法用**实体覆盖率的同口径重采样**当门：`cov_r < 0.01` 处预乘 RGB 直接抹零 —— 这些像素本就该是 0，不动任何正确像素；③ 量「外影区」必须**离实体 3 px 以上**（`~dil(a>0.9,3) & (a>0.02)`），贴着量的话会被实体 AA 环污染（本例误读 max 147/254）；④ 本环境无 scipy，膨胀自写四向或运算即可，但 ⚠ **crop 坐标与全图坐标不可直接 `&`**（尺寸差一个 offset，混用要么 broadcast 崩要么静默错位，本仓已踩三次）。
- **[美术派生][K-134] 含「悬在实体外的影」的 9-slice 元素：切片线必须把悬影整块关进端帽，⛔ 整图横拉会把影按倍率摊平**（来源 柜内木牌随牌宽拉伸 B25 / WXG-T-269，2026-10-14）
  现象：牌宽是动态拉伸的，影层足迹只在原稿那一档牌宽上测过 ⇒ 拉伸后右下裙边错位。若按「实体 bbox」切九宫，悬在牌体外的影（牌左 349 / 牌右裙边 744 稿px）会被卷进中段跟着拉伸。
  根因：9-slice 只保证**拉伸带内**的内容可拉；实体外的投影属**不可拉区**，它的宽度由光向决定、与牌宽无关，一旦被划进拉伸带就随牌宽线性变形。
  规避/做法：① 端帽 = 牌缘 ± E（E 取 B18 口径 24 设计px），**切片线与牌体共用同一条线**，别各量各的；② 判据要**可证伪**：量「裙边伸出列数」——三段式应恒定（实测 21/21/21），整图横拉则随倍率走（15/21/32 = ×r），一条指标同时钉死两条路线；③ 纵向若影只贴在牌底，`borderTop + borderBottom = 资产高` ⇒ 中段高度 0，**牌高永不重采样**；④ 中段可拉性另测「列剖面首末差 vs 列间自然抖动 RMS」（本例 +0.011 vs 0.0043，同量级 ⇒ 可拉），别只靠肉眼看接缝。
- **[美术派生][K-135] 复用上一批的尺子：先对量纲，再把当初那份原始脚本重跑一遍取靶值**（来源 B25 复现 B18 nine_slice / WXG-T-269，2026-10-14）
  现象：复现 B18 的接缝判据得到 18/14，与「B18 交付 3/4」对不上，第一反应是尺子坏了。实际两层错：① **量纲**——B18 把牌紧框缩到高 160 设备px，B25 主流程活在 crop 高 296 域；② **靶值本身记错了**——重跑 `production/qa/menu-b18/b18-ways.py` 查明 3/4 属 W4（inpaint 正视版），W3 是 9/7，仓库内查无「W3 = 3/4」的出处。
  根因：跨批次引用时，摘要是「一个数字 + 一个名字」，丢了数字的**归属对象**与**测量域**；数字看起来单点吻合，就以为尺子可信。
  规避/做法：① 历史数字**不当基线**，回归前先跑原始脚本拿实测输出（脚本还能跑就必须跑，本仓的 QA 脚本都可离线复跑）；② 尺子自证改成**双输入**：同一把尺分别复现两个已知方案的不同读数（9/7 与 3/4），双点吻合才能同时排除「尺子错」与「参照错」；③ 换算尺寸在脚本里**写死源脚本的实际缩放值**，别假设与当前流程同域；④ 端帽/参照这类坐标，注释里写清它是**资产左上角还是实体边缘**（本例填成牌缘把整张资产推右 14 px，端帽从 116/121 错读成 130/108）。
