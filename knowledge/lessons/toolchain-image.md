- **[工具链图像][K-127] PIL `ImageDraw.floodfill` 在 `L` 模式图上静默不灌（0 像素变化、不报错）⇒ 二值补洞别用它**（来源 原型 v2 第十批 / 无单，2026-10-13）
  同一套「四角灌哨兵色 → 反解未到达区＝洞」的逻辑，在 **RGB** 图上（本仓 `cut-sprites-local.py` /
  `l4-mockup.py::cut()` 用 `(255,0,255)` 哨兵）工作正常；把图换成 `Image.fromarray(uint8 2D)`（mode `L`）、
  哨兵换成单个 int，则 `floodfill` **一个像素都不改**且**不抛异常**，表现为「掩码占比恒 1.00 / bbox 等于整块裁切窗」，
  极易被误读成「阈值选错了」而反复调阈值（本批调了三轮：244→中性度→解析圆，才回查到这里）。
  口径：① 用 `floodfill` 前**先断言它真的改过像素**（灌后 `np.unique` 里必须有哨兵值）；
  ② 单实体（盘/胶囊/字块）的补洞根本不需要连通域——**逐行/逐列 span fill**（背景无命中 ⇒ 首尾命中之间必为实体）
  是确定性、零依赖、可目视复核的替代；③ 需要真连通域时走 `cut-sprites-local.py` 那条 RGB 腿。
  代码锚：`temp/l4-proto2.py::disc_mask`（span fill 版）、`games/beads/design/ai-workflows/cut-sprites-local.py`（RGB 腿）。

- **[工具链图像][K-138] i2i 的 denoise 是「风格 ↔ 结构」单调权衡，且不承载离散状态语义 ⇒ 状态位必须程序化重画**（来源 选关弹框原型抽档批 / 无单，2026-10-18）
  现象：为选关弹框抽「参考风格」底图，同一基底（云 qwen-image-2.1-turbo s23 擦章版）+ 同一描述体提示词，本地 2.1（25 步）按 denoise 三档 × 四种子抽卡——**0.7** 结构最稳但风格几乎不动；**0.8** 四颗粒子 3 通过，种子 11 把「0★ 未解锁的彩色格」画成**带小锁的格**（状态错，不是颜色错）；**0.9** 风格变化明显，但两颗粒子都把遮罩外背景换成云纹/实景，种子 23 还丢了返回钮。反向对照：d0.3 / d0.5 相对输入的 `maxdiff>64` 像素仅 **0.4% / 0.9%** ⇒ 低档只做细修，抽不出风格；而默认档 0.65（结构锁死）拿去做「参考风格」只会复刻参考版面。
  根因：denoise 是**一个参数同时管两件事**——重画多少像素 & 保留多少结构；而「哪一格该锁」「必在件（返回钮）」「格数」这类**离散语义**在扩散模型眼里与纹理无异，高档必然随机重掷，低档必然不动。想要「风格变但语义不变」在这个参数轴上不存在。
  规避/做法：① 按**图生图类型分档**取 denoise，⛔ 不用单一默认档服务多类任务（参考风格 0.8 待定稿／形态变体 0.5／局部修改 0.3–0.5／0.65 仅兜底，正本 `games/beads/design/ai-workflows/model-matrix.md` §5.x）；② 定稿走**混合路线**：生图只出风格底，格状态由数据程序化重画（`levelselect-proto-coords.py` 的 `CELLS`），不把状态语义交给抽卡；③ 每档结论要 **≥4 颗粒子**才敢写通过率，2 颗只能出方向（本轮 0.7/0.9 各只测 2 颗，正文已按此降级）；④ 验收表**先列可数的结构硬规则**（格数、状态位、必在件），再评风格主观分——本轮第一轮只查 6 条视觉规则、漏了「必须 9 格」与「锁格底部无星」，把 12 格的输出当成合格参考，整轮打分作废重做（同 **K-044**：判定上限由判据完备性决定）。
  证据锚：`games/beads/design/ai-workflows/bench/i2i-denoise-20261017/README.md`（三档 × 种子矩阵、两次更正记录）。

- **[工具链图像][K-205] inpainting 的成败由 mask 是否「刚好覆盖」决定，膨胀没有统一安全值**（来源 WXG-T-535 / commit 4ddbfd4f，2026-11-01）
  现象：同一张 3D 写实稿、同一个擦除模型（云 `image-erase-completion`），只改 mask 外扩量就出现三种截然不同的结果——按钮 **+4px** → 原处补出一坨白黄怪物 + 一圈按钮轮廓残影；**+15px** → 补出连续木纹，肉眼无痕；铭牌文字 **+12px** → 文字确实没了，但把木牌右缘啃掉一块（膨胀越过了牌面边界跑到背景上）。另有一次不膨胀的精确 mask 擦文字，模型干脆**把文字重写成更潦草的笔画**。
  根因：无 prompt 的 inpainting 只能靠 mask 外的残留像素推断「这里原来是什么」。残留描边/投影/高光会被当成线索**续画成同类物**（欠覆盖）；越过材质边界则让模型在两种材质交界处重新解释结构（越界）。因此**成败与目标面积无关**（7.53% 的按钮外扩到位后同样干净），只与「mask 是否恰好覆盖目标且不越界」有关。
  规避/做法：① 擦除前先量**目标到所在材质边界的最小距离**，这就是该用例的膨胀上限，⛔ 不存在通用 px 值（本仓两个实例：按钮短边 190px → 15px 安全；牌面文字离牌边 <12px → 任何 >0 的膨胀都危险）；② 外扩量按「物体短边 4–8%」起步试，宁大勿小，但**一旦贴材质边界就转为精确 mask**；③ 判据必须加「**补出来的是什么**」目视门——擦掉猫后模型补出一盆绿植（语境合理但不是纯背景），只查「原物是否消失」会放过幻觉；④ 目标若是**文字**，别在擦除模型上耗——换有 prompt 的语义型模型（同片另一条），或干脆程序化覆盖。
  证据锚：`games/beads/design/ai-workflows/model-matrix-changelog.md` §7.4.2（三条覆盖边界 + 五次实测读数）；产物 `temp/erase-out/cmp2-*` / `cmp3-plate`（`temp/` 不入库）。

- **[工具链图像][K-206] SAM 类分割模型只切「物体」不切文字，纯文字目标必须换语义型模型**（来源 WXG-T-535 / commit 4ddbfd4f，2026-11-01）
  现象：要精确切出木牌上的「小猫咪」三字做擦除 mask，用 SAM3.1 `SAM3_Detect` 给紧贴字形的 bbox（365,883,505,936）→ 返回**全黑 mask（0 像素）**；把 `threshold` 从 0.5 降到 **0.2**、`refine_iterations` 从 2 提到 **4** 仍 **0 像素**。同一次会话里，同一个节点切「第1关」胶囊（0.31%）、底部按钮（5.80%）、小猫图案（1.86%）全部精确贴合圆角。
  根因：SAM 是**可提示概念分割**——它找的是「一个有边界的概念性物体」。文字笔画是同一平面上的细笔画集合，既无闭合轮廓也不构成 object，故它在框内判定「无目标」而不是「分割失败」，表现为静默返回空 mask（不报错、不告警），极易被误读成「阈值没调对」而反复调参。
  规避/做法：① 拿到 SAM mask **先断言非空**（`(mask>127).sum() > 0`）再进下游，空 mask 当显式失败处理，⛔ 不要把空 mask 传给擦除模型（会得到"什么都没发生"的假成功）；② 目标有实体轮廓（按钮/胶囊/图标/角色）→ SAM 是正解，抠图 alpha 实测 `alpha==0` 占 94–98%（真透明，云模型对比为 0.00%）；③ 目标是**文字** → 换有 prompt 的语义型模型（wan2.7 bbox + 「移除文字补成木纹」8.9s 干净），或用程序化纹理贴片；④ SAM 的文本提示也须**具体描述**：`"button"` 会误检到墙面（0.25%），`"the pink start game button with chinese characters"` 才精确命中（2.53%）。
  证据锚：`games/beads/design/ai-workflows/model-matrix-changelog.md` §7.4.3（SAM 已知边界表）；探针 `temp/sam3-run.py`（不入库）。

- **[工具链图像][K-207] 参考 UI 件的立体感可能来自方向光而非描边 ⇒ 加深色描边前先比「环均值 vs 面均值」**（来源 WXG-T-537 / commit d1ca81bf，2026-11-02）
  现象：给菜单齿轮圆牌补立体质感，首版按「1px 深棕描边 + 顶部内高光 / 底部内阴影」绘制，出图读成「塑料圆盘 + 橙圈」，与菜单里既有木牌明显不同族。回头采样基准图左箭头木牌（中心 `(66,663)` / 直径 95）**分环带与牌面两区取中位数**：环 `157/84.5/39`、牌面 `152/80/37`——**两者几乎相同**；同一圈亮侧 `228/156/90`。即参考件的立体感来自**方向光落在同一块木材上**，不是「深色边框 + 浅色面」两种颜色。
  根因：目视把「暗环」归因成描边色，实际它只是**背光侧的同色木材**。一旦按「描边」实现，环带被迫用纯色重绘 ⇒ 同时犯两个错：色相偏离材质 + 该区木纹被抹平，所以必然像塑料。
  规避/做法：① 判定前先做「环均值 vs 牌面均值」**逐通道比对**，差 <10 即判「同色木材受光」，⛔ 此时不要加深色描边；② 立体用亮度调制而非颜色替换：`gain = k × facing × sin(aπ·t)`，`facing` = 光向与法线点积（本件 `k=0.62`、`a=0.62`），内斜面同式取 `k=0.26`；③ 调制必须**乘在原始木纹像素上**（`out *= 1 + gain`），不重绘环带；④ 只保留最外 1–2% 半径的细暗轮廓（本件 `×0.45`）收边；⑤ 方向光是否成立要**机检**——左上与右侧区均值须有稳定差（本件左上 `209/157/103` vs 右侧 `188/136/83`），无差即等于没打光。
  证据锚：`games/beads/design/art/proposals/menu-3d-style-20261030/btn-gear-20261102/p-gear-btn.txt`（分层参数表 + 参考件采样读数）；脚本 `temp/m3-bevel.py` / `temp/m3-finalize.py`（`temp/` 不入库）。

- **[工具链图像][K-208] 硬边 alpha 经 LANCZOS 缩放会振铃出光晕，覆盖率高于理论圆面积 ⇒ 交付透明 PNG 前按低 α 归零**（来源 WXG-T-537 / commit d1ca81bf，2026-11-02）
  现象：92px 圆按钮的 alpha 覆盖率实测 **82.4%**，而半径 46 的圆理论占比 `π/4 = 78.5%`，高出 3.9pp（等效半径 +2.4% ≈ 1.1px）。肉眼看不出，但它会在贴回时形成一圈极淡的暗/亮边，且让「圆是否规整」的机检读数失真。
  根因：`Image.resize(..., LANCZOS)` 对**硬阶跃**的 alpha 产生过冲旁瓣，圆外一圈出现 α 1–10 的淡像素（同时也把内侧边缘略推出去）。这不是 bug 而是 LANCZOS 核的固有行为，圆盘越硬边越明显。
  规避/做法：① 交付前把 `α < 12` 直接归零（本件 82.4% → **79.8%**，余量即正常抗锯齿）；② 判据用「**alpha>0 像素占比 vs π/4**」，偏差 >2pp 即有振铃嫌疑 —— ⛔ 不要只查 `mode == 'RGBA'`，软 alpha 会让 mode 永远是 RGBA，它对这个缺陷零分辨力；③ 想更稳就在 4–8× 超采样掩码上先做线性抗锯齿（`clip((R - r + w)·255/(2w))`）再缩放，越采样率越高振铃越弱；④ 归零阈值要小于正常的边缘抗锯齿值（1px 边缘通常 α≥30），否则会把抗锯齿也削掉。
  证据锚：`games/beads/design/art/proposals/menu-3d-style-20261030/btn-gear-20261102/p-gear-btn.txt` §规格 / §校验读数；脚本 `temp/m3-finalize.py`（`temp/` 不入库）。

- **[工具链图像][K-213] 量化脚本 docstring 里的「⛔ 不再作为产出」有批次射程：跨批沿用前先查它防的是什么**（来源 WXG-T-614 / commit 867bbfa2，2026-11-11）
  现象：给三枚**单态**弹窗切图选 Cocos 投放件配方，读到 `quantize-cocos-textures.py` docstring 把 octree 注为「只用于对照、不再作为产出」，差点改用 `ship()` —— 对照体积 **246.6 / 127.6 / 111.6 KiB** vs octree **74.7 / 23.0 / 27.2 KiB**（数倍包体差）。
  根因：那条禁令出自 **BD-61 菜单按钮批**，防的是「**同族两态**（normal / pressed）被 octree 并色后按下暗边消失」；本批三件均单态，无此风险，且 T-584 / T-585 已有单态件走 octree 的先例。docstring 把「本批结论」写成了「全局禁令」。
  规避/做法：① 脚本注释里的禁令先**回溯它的来源批次与失效条件**，再判是否适用本批（同 K-096：快照不是永久事实）；② 选型跑**双配方对照 + 逐像素质量读数**（RGB mean/max、alpha 误差分布与 >8 / >32 占比），⛔ 不只比体积；③ 结论连同「为何不适用那条禁令」一起写进资产台账，下一批不必再纠结。
  证据锚：`production/qa/asset-provenance.md` §12（本批台账 + 配方口径披露）、`games/beads/design/ux/timeout-panel-spec.md` §6；关联 K-139（交付格式判据是目标运行时能不能解码）。
