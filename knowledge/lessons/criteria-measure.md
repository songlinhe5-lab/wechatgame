## 判据实测

- **[判据实测][K-126] 同一张美术在不同像素网格下量出的「设计 px」并不相同 ⇒ 跨批复用实测值前先对齐网格**（来源 原型 v2 第十批 / 无单，2026-10-13）
  同一主菜单美术存成两档：`v1-mainmenu-final.png` 1520×2736（`sx 2.027 / sy 2.051`）与
  `menu-750x1334-at2x.webp` 1500×2668（`sx=sy=2.000`）。按设计 px 量同一批元素得到**两套数字**
  （门楣梁面 246–308 vs 247–306、招牌 65–205 vs 88–212、顶栏三颗自顶 46–104 vs 31–95）——
  不是矛盾，是**多出的那 20/72 px 留白把整幅画往下推了**。前一批据此定的落位（牌位 255–293）
  恰好仍在梁面内属运气，不是校验过。口径：① 量数必须注明来自哪张图；② 非整数倍网格（`sy≠2`）的图
  **降级为构图参照**，不当事实数字来源；③ 交付规格由用户明令时（本批：UI 原型一律 750×1334@2x），
  整屏件按该尺寸出，**裁切/拼图件须在清单里标「非规格件」**，否则下一个人拿 3000 px 宽的拼图当基准。
  同族 K-123（登记违例前先确认判据对象存在）、K-122（两端同源要进门禁）。
  代码锚：`temp/l4-proto2.py`（一次性，不入库）、`design/proposals/ui-style-redesign/menu-architecture.md §5.1b-2` 第九/十批。

- **[判据实测][K-128] 在暖色浅底上抠「亮白但自带渐变」的实体：判据要用**中性度**，亮度阈值会吃掉下半个实体**（来源 原型 v2 第十批 / 无单，2026-10-13）
  白盘圆钮（(255,254,255) 顶 / (252,255,252) 底，渐变到下部才暗）坐在奶油底 (253,246,235) 上：
  亮度门 `min(r,g,b) > 244` 只圈到上半亮核，实测 Ø51 vs 真盘 Ø59（**小 8 px**），抠出来贴过去缺一块；
  换 `r − b < 9`（白盘 0–2 / 奶油底 18–22 / 暖色柔投影 18）**一条判据同时分开「底」与「投影」**，
  量得 Ø54×54 正圆。配套三条：① 归一尺寸时切圆取**短边半径 −1**（齿轮那颗自带白晕，长边会把晕吃进来 →
  缩放后一圈白边）；② 擦原位掩码必须**膨胀 ~14 px**，只擦实体像素会留下投影 ghost 环；
  ③ 搬走的钮要**合成一枚柔投影**再贴（原投影被擦掉了，不补会有贴图感）。
  代码锚：`temp/l4-proto2.py::disc_mask/disc_cut/with_shadow`；同族 K-126。

- **[判据实测][K-130] 量「某件的底缘在第几行」必须把「本体描边」与「柔投影」分成两个读数，占比型判据会系统性把投影算进本体**（来源 定稿底图换代·走③压矮 / 无单，2026-10-14）
  现象：同一颗 CTA 胶囊，用「x 窗口内非背景占比 <99%」量得底缘 y-up **68**，用「中心列仍为高饱和本体色（`r−g > 40`）」量得 **72**，差 4 px；而安全带正好是 68 ⇒ 前者报「余量 0（贴边）」、后者报「余量 +4」，同一张图两种结论。
  根因：交互件的烘焙光影是**连续衰减**的（本例描边末行 (168,98,95) → 投影四行 (235,209,197)/(226,212,201)/(233,221,209)/(241,230,218) → 背景 (248,237,225)），任何「非背景」阈值都切不出这条尾巴的终点，切点完全由阈值决定。
  规避：① 判据里写清量的是**本体**还是**含投影包络**，两个数都给，别只给一个；② 本体腿用**饱和度**（本例 `r−g`）而不是「是否等于背景」，投影腿才用背景占比；③ 安全带/碰撞类门一律按**本体**判（投影入带不判违例，但必须显式登记投影末行，否则下一个人会以为已含投影）。
  代码锚：`temp/l5-deliver.py::rim_end / shadow_end`；同族 K-126（网格口径）、K-128（中性度 vs 亮度阈值）。

- **[判据实测][K-131] 当作「后续测量基准」交付的位图必须无损编码，有损重编码会让「未改动区域逐字节相同」这条自证直接失效**（来源 定稿底图换代·走③压矮 / 无单，2026-10-14）
  现象：同一条压矮术式，无损中间件对基准实测「切口以上 maxΔ = 0 / Δ>0 像素 = 0」；落成 q82 WebP 后变 **maxΔ = 23 / 988,947 像素漂移**（1500×2668 全页，噪声集中在硬边）。
  根因：WebP/PNG 之分类比的不是「看起来一样」而是「解码后逐通道一样」；有损编码在每次交付都重采样一遍整张图，于是「我只动了下面一条带」这句话在交付件上无法自证，且代际损失会沿「底图 → 叠放 mock → 再叠放」累加。
  规避：① 区分两类产物 ——**基准件**（后续要被量、要被再叠放）走 `lossless=True`，**取证/评审拼图**（只给人眼看过一遍）继续有损，别一刀切；② 选了无损就把体积代价写进文档（本例 1052 KB vs 145 KB，且 design references 不进包体预算），免得下一个人当失误删掉；③ 若历史上已经用了有损件，**所有读数必须声明取自交付件本身**，否则文档坐标与被量的像素不是同一份。
  代码锚：`temp/l5-deliver.py`（`OUT` 无损 / `EV` q82 同文件并存，即两条通道各写一次的样板）。
