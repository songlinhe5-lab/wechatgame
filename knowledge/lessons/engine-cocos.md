## 引擎Cocos

- **[引擎Cocos][K-077] 给既有渲染路径加缩放/档位能力时，必须盘点该路径所有「绝对像素量」——凡与比例制几何同屏对照者要一起归一**（来源 WXG-T-169 收口余项 C-5 / commit c7d157d，2026-09-26）
  现象：真机报「放大时珠与背景差不多大、缩小时豆子比背景小很多」；而静息档（zoom=1）截图与全部既有测试全绿——只在非静息倍率下可感，纸面推演看不出来。
  根因：底图 tile 吃缩放后的 `snap.gridPitch`（比例制），而珠体内缩 `BEAD_DRAW_INSET = 4` 是绝对设计 px ⇒ 珠面/格距 = `(30z−8)/32z`，从 68.8% 漂到 fit 档（z≈0.6）的 52%。两类量混用无编译期/运行期报错；旧 art 裁定「保持绝对」的前提（当时全部 fit=1）已随能力上线失效。
  规避：① 上缩放前对该渲染路径 grep 一遍**绝对量**（inset / `minStroke` / 固定线宽 / 固定间隙），逐个问「它的对照物是不是比例制」；② 修法取**归一而不是加地板护栏**：`inset × outer / BEAD_CELL` —— 静息档数值逐字不变（既有 seal / 等值判据零冲击，这是能直接合入的关键），且比例天然不为 0，原拟的 `FACE_MIN` 护栏自动失效；③ 判据钉**比例不变量**（多倍率同比值，如 z=1/0.88/0.8/0.66 同一比值）而不是某档绝对值，否则防不住「偷回绝对量」；④ 同族的「可见性下限」型量（如 `minStroke`）**不属本条**——它是屏幕可读地板，归一反而错，应登记为已知钳平代价而不是跟着缩；⑤ 归一后原有观感不变量会转移（本例环带单边随缩至 ≈ 1.5 CSS px），必须**当场写清哪条读数换了承载通道**，不得拿「缩放已修」顺带宣布可辨性达标。
  判例引用：`games/beads/src/view/bead-render.ts::drawFilledBead`、`games/beads/tests/bead-render.test.ts` ③b、`assets-spec §1.10.2` C-5 裁定更替条；同族 K-035/K-040（纸面比例 ≠ 屏幕可辨，观感一律 `[待真机]`）、K-056（渲染里的视觉语言必须随语义常量派生）、K-053（旧裁定的前提条件得写在正文，否则反转时无人可发现）、K-062（同一渲染量在真机与单测上表现错开一层）。

- **[引擎Cocos][K-079] 「参数还在、通道已死」：换肤/转正会让表现层入参失去承载体，改值前先验消费者**（来源 beads 选中抬起立体感批（未挂 Task 号），2026-09-26；原登 `判据` 片，由 WXG-T-169 沉淀批**代归位**至本片——该片越 8000 红线，且本条实体是渲染层事）
  现象：用户反馈「选中珠子只是突兀地上移、没有立体感」。按旧规格的「抬起四通道」（投影偏移 / 投影变淡 / 接触面收窄 / 侧壁变长）准备调参，实读才发现四条通道**全部只住对照臂**——默认皮肤在上一轮「十层退役」转正时换成 6 图元集（1 rect + 4 polygon + 1 circle），**既无阴影层也无侧壁**，`shadowAlpha` / `contactAlpha` / `shadowDy` 这些入参在默认皮肤下没有消费方。参数卡字段、规格通道表、单测注释三套资产都还活着，盘面实际只剩「平移 + 4% 放大」两条线索。
  根因：「退役旧实现」与「换默认档」是同一动作的两面，但**只有代码跟着换**，参数与文档留在原地继续被引用；层序判据又按臂切分（旧判据整体改指对照臂），于是新臂上「通道缺失」不会让任何测试变红。属 K-035（规格已写 ≠ 代码已实现）与 K-060（文档声称有门、实际无门）的**第三形态**：不是没写、不是没门，而是**曾经有、后来没了，周边资产没跟着退役**。
  规避：① 动任何表现层参数前先做一次**消费者核对**——查该字段在**默认档实际层集**里是否被读（只看参数卡与注释必然被骗）；② 结构性换肤（改层集）必须同批把「哪些入参从此无承载体」写进函数注释，并在规格表对应行标「仅对照臂成立」，否则下一轮排查会照旧表开药；③ 要补的视觉线索优先走**与风格无关的层**（底图/格级族），既免逐风格参数化，也不占单卡图元预算（计数口径常把底图另计）；④ 观感结论一律 `[待真机]`，⛔ 不得以「比率与常数齐了」判绿。
  判例引用：`games/beads/src/view/bead-render.ts`（`FilledBeadOptions` 各通道的「无承载体」注）、`games/beads/src/view/bead-styles/facet-4.ts`、`games/beads/src/config/tuning.ts::BEAD_CARD.liftShadow*`；正本 `games/beads/design/proposals/bead-visual-style-spec.md §11.6`。同族 K-035、K-040、K-060；与本片 K-077 同域（都是「尺子/层集在变，旧资产未跟着退役」一类）。
